# 战国无双 · 布料物理（披风 / 袍子）与头发物理 — 实施计划

> **一句话**：让披风"会飘" = 用引擎自带的布料模拟（原版 231 处在用），不是我们写物理。
> 披风现在已经在甲里、**不用拆出来**；要做的是三件事：造一张低模"模拟网格"、给甲和模拟网格刷顶点色 alpha、在编辑器 Cloth Editor 里接线并 cook。
>
> **状态**：已批准（2026-09-21），**实施中** —— 管线侧（第 0~2 步）已做完，卡在人做的编辑器那一步，见 §十四。
>
> **2026-09-21 改判**：首个验证对象从「浓姬振袖」改为**织田信长披风**（用户已把披风并进甲，且披风是单张布片、比两片振袖简单）。浓姬降为第 2 个。
> **先做布料，后做头发**：布料风险低（源件自带现成的模拟网格、原版有大量先例）；头发风险高一档（原版**没有人类头发**用布料的先例，还要面对"布料 × 捏脸形变"的未知）。

## 一、结论：做四件事

| # | 做什么 | 谁做 | 做到什么程度 |
|---|---|---|---|
| 1 | **造模拟网格** `clo_taikou_nobunaga_do_a`（源件 `driver_0`，30 顶点） | 管线（Blender，现成脚本加一条出口） | 编辑器里能选中它 |
| 2 | **刷顶点色 alpha**（甲：披风顶点 = 1、其余 = 0；模拟网格：贴肩 0 → 下摆 0.44） | 管线（同一个脚本里刷） | 编辑器布料预览里布会动 |
| 3 | **Cloth Editor 接线 + cook** | **人**（编辑器，每人一次，约 10 分钟） | Publish 出来的包里布料字段齐全 |
| 4 | **装机 + 实机验收** | 现成 `install_pack.py` 链 | 走路 / 转身时披风有滞后摆动、不穿模 |

**新概念只有一个**：**模拟网格**（低模替身）。物理算在替身上，渲染网格按自己顶点色的 alpha"挂"上去跟着动。

## 二、机制（官方文档 + 本轮实测，不是推测）

| 项 | 内容 | 出处 |
|---|---|---|
| **控制方式** | 顶点色 **alpha 通道** = 该顶点能离开自己蒙皮位置多远（单位：米）。0 = 钉死不动 | 官方编辑器文档 `Editor/Resource Editors/cloth_simulation.md` |
| **两种模式** | ①**直接模拟**：渲染网格自己的顶点参与物理（适合简单拓扑、顶点少）②**映射模拟**：另做一张低模算物理，渲染网格挂上去跟 | 同上 |
| **两个网格的 alpha 含义不同** | 模拟网格的 alpha = **活动半径**（真正的物理量）；渲染网格的 alpha = **开关**（> 0 即挂到模拟网格） | 同上 |
| **命名约定** | 模拟网格名 = 渲染网格名**加前缀 `clo_`** | 原版 `aserai_robe_c` ↔ `clo_aserai_robe_c` |
| **碰撞体** | 胶囊（两端各自绑骨）。预设清单在 Native 的 `cloth_bodies.xml`，**现成就有 `cape_body` / `cloak_body` / `human_body`** | 本轮实测 |
| **手感参数** | 软硬 / 重力 / 风 / 阻尼 / 惯性 —— Native 的 `cloth_materials.xml`，编辑器里选预设 | 官方文档 |

**接线字段（本轮用 `tpaccli meshdiff` 在原版包上实测到的）**：

| 字段 | 在哪 | 原版值 |
|---|---|---|
| `ClothMetamesh` | 甲的 Metamesh | 袍子 = **非空 guid**（指向模拟网格）；披风那件 = **空** |
| `UnknownString` | 甲的 Metamesh | `human_body`（碰撞体预设名） |
| `ClothingMaterial` | **每条 LOD 各一份** | 一整组物理参数 |

**本轮新量的三个原版资产**（探针 `Debug/offline/_clo_alpha_probe.py`）：

| 资产 | alpha 分布 |
|---|---|
| `clo_aserai_robe_c`（袍子·模拟网格·725 顶点） | 下摆（z 0.44m）**0.44** → 腰（z 1.09m）**0**，近似线性；**单 LOD、单子网格** |
| `clo_female_peasant_cape_b`（披风·模拟网格·1164 顶点） | 中段最大 0.19，膝盖附近反而小（0.05）—— 按部位涂，不是纯线性 |
| `aserai_robe_c`（袍子·渲染网格·3671 顶点） | 下半身 = 1（挂）、上半身 = 0（不挂）—— **开关式** |
| `female_peasant_cape_b`（披风·渲染网格·1688 顶点） | 下半身 = 1、上沿 = 0；但它的甲 `ClothMetamesh` 是**空**的 ⇒ 它走的是**直接模拟** |

⚠️ **照抄要照对参照物**：袍子那一对（`aserai_robe_c` + `clo_aserai_robe_c`）才是**映射模式**的完整范例；披风那一对走的是直接模拟。

## 四、怎么做

### 第 0 步 · 先加一条离线验收命令（约半小时）

`tpaccli` 现在只有 `meshdiff` 能看布料字段，但它一次吐 600 行、要人工筛。加一条 **`clothinfo`**：只打 `ClothMetamesh` / `UnknownString` / 各 LOD 的 `ClothingMaterial` + 顶点色 alpha 统计。

**为什么先做它**：第 3、4 步每一步（编辑器出来对不对、装机后丢没丢）都靠它判。没有它只能靠进游戏肉眼猜。

### 第 1 步 · 造模拟网格（管线）

1. **输入**：源件 `driver_0`（30 顶点 / 40 面）
2. **变换**：用现成的逐角色变换 T（`out/srcT.json` 的 `s` 与 `z_sole`），与甲同一把尺子（否则替身和本体对不上）
3. **单网格、不出 LOD**：`build_armor.py` 有 `--no-lod`。编辑器硬性要求 **模拟网格只能有一个子网格**
4. **权重**：整体绑 `bip01_spine1_10`（与披风渲染件同骨）
5. **输出**：`tools/armor-pipeline/out/clo_taikou_nobunaga_do_a.fbx`
   （**不带贴图**：材质名直接复用渲染件的 `taikou_nobunaga_do_a`，原版模拟网格也是这么做的）
   → 它是**新资产**，交给编辑器时要放**管线落点** `AssetSources/sw2/<角色键>/` 供**手工导入**（见第 3 步）

⚠️ **硬性几何要求**：模拟网格要**贴着渲染网格、且永远不被渲染网格穿出去**（穿出去 = 碰撞错位，"腿穿甲"式）。`driver_0` 是原厂给这块布配的替身，天然满足 —— 但**要量一遍**（两边包围盒 + 逐顶点最近距离）。

### 第 2 步 · 刷顶点色 alpha（管线，两个网格一起刷）

| 刷在哪 | 怎么刷 |
|---|---|
| **甲**（渲染网格） | 披风那 4 个碎片（44+44+7+7 顶点）= **1**；其它顶点 = **0** |
| **模拟网格** | 贴肩 = **0** → 下摆 = **0.44**（照 `clo_aserai_robe_c` 的梯度） |

- **复用现成口子**：`build_armor.py` 已经在合并前用临时顶点组标"布料件"（`__cloth_drop__` / `__cloth_hang__`，合并后按组取顶点号再删组）—— 同一个口子加一种标记即可，不用新写选件逻辑。
- 🔴 **披风最顶上那圈（贴肩）必须留 0**（钉死在身上），否则整片会被重力拽跑。
- 🔴 **每一级 LOD 都要刷**：LOD 是 decimate 出来的、顶点号对不上 ⇒ 用**几何规则**算（碎片归属 + 高度），不能按顶点号抄。
- RGB 保持全白（只有 alpha 有意义；甲的材质已带 `do_not_use_vertex_color_as_occlusion`，不会被压暗）。

### 第 3 步 · 编辑器（人做一次，约 10 分钟）

1. **ModKit 开着的时候**分发（关着的时候拷 = 没拷，铁律 31）。**两种资产两种待遇**（铁律 31 的 2026-09-21 补充）：
   - **甲**（已注册资产）→ **覆盖镜像** `TifaHead2/AssetSources/armor/nobunaga/taikou_nobunaga_do_a.fbx`
   - **替身**（新资产，从没导入过）→ 🔴 **拷进镜像没用**（编辑器不会因为镜像多一个文件就注册新资产），
     必须**在 ModKit 里手工导入**：文件放**管线落点目录** ——
     **SW2 的落点是 `TifaHead2/AssetSources/sw2/<角色键>/`**（信长 = `sw2/L02_nobunaga/`），把 `out/` 这份拷进去
2. 🔴 **先验 alpha 再往下**（不用 Publish）：导入后查该资产的编译产物目录
   `tpaccli clothinfo --packdir <TifaHead2/Assets 下的产物目录> --filter taikou_nobunaga_do_a`
   —— 看是不是「甲身 0、披风 92 个 1」。全 1 = 导入器不认我们刷的 alpha → 走 §五 的退路
3. 编辑器里：甲网格 → **Cloth Editor** → Preview mesh 选甲 → 勾参与的子网格 → **Simulation mesh 选 `clo_taikou_nobunaga_do_a`** → 碰撞体选 **`cape_body`** → 布料材质（照袍子挑一个起步）→ 最大活动距离 → **Save mesh settings** → **cook**（生成 `.tcc`/`.tcm`）
4. Publish

### 第 4 步 · 装机 + 实机

- `install_pack.py` → `Taikou/AssetPackages/pack0.tpac`（**先备份**）→ 进游戏
- 判据见 §六

## 五、两道门 + 一条捷径（必须实机验，其余都是纸面）

| # | 门 | 不过怎么办 |
|---|---|---|
| 1 | ModKit 导入 FBX 时**保不保得住顶点色 alpha** | **捷径（已实测可行）**：`tpaccli` 能直接读写包里的顶点色通道（`VertexStreamData.Colors1` 是 4 通道可写）⇒ 写个离线小工具把 alpha **直接写进编译好的 `_geo.tpac`**，完全绕开导入器。代价 = 多一个工具 + 要证明"只改了 alpha"（改前改后逐字节比对） |
| 2 | **cook 出的布料数据能不能跟着 Publish 进包、再被 `install_pack` 搬进 Taikou 的 pack0、被游戏读到** | 判据 = 装机后用 `clothinfo` 看 `ClothMetamesh` / `UnknownString` 还在不在。`install_pack` 是整资产拷贝、理论上带着走，**但没有验过** |

⚠️ 我们的导入设置现在**只勾了 `Import meshes`**，顶点色要不要额外开——门 1 问的就是这个。

**备选（如果门 1、门 2 都不顺）**：给披风单独开一个子网格走**直接模拟**（原版 `female_peasant_cape_b` 就是这么做的），省掉模拟网格那一路。代价 = 要改甲的构建（多一个材质/子网格），且违背"照原版袍子办"的现成范式。

## 七、代价

| 项 | 代价 |
|---|---|
| **编辑器手工活** | 每人一次 Cloth Editor（选网格 / 选材质 / 调距离 / cook）。**只有人能做，我做不了** |
| **性能** | 随顶点数与迭代频率线性增长。披风 102 顶点 / 替身 30 顶点 = 可忽略；整件长袍要留意 |
| **部分场景不支持** | 原版论坛有案例（Sargoth 城镇场景布料失效）。**我们的日本地图场景是否支持，未测** |
| **形状由模拟决定** | 布料的最终形状是"算出来的"，与手工摆的姿态不完全一样。信长这条是**收益**（现在是一块刚体板），浓姬那条要留意 |

## 八、明确不做的事

1. **不加骨头。** Bannerlord 的 `human_skeleton` 实测**31 根骨、全是身体骨**，一根布料/头发骨都没有；仅有的 3 根 `_nub_notused` 在**头顶和两只脚尖**（父骨是头/脚趾），做不了披风链。
   ⚠️ 但"换一份骨架"是引擎支持的机制（骨架挂在 skin 上）—— **这条路本身成立、只是贵**，评估见 [§十三](#十三附备选路线骨骼物理本轮验过不推荐先做)。
2. **不把披风拆回独立装备**（它已经在甲里，布料不需要拆）。
3. **不为了布料推翻现有几何。** 已经手工摆好的形状（浓姬 / 长政 / 家康）保持不动，布料是**在它之上再加一层动效**。
4. **不动没有驱动件的 11 人**（要自己降面造替身，收益最低、工作量最大，放最后）。

## 十、头发物理（仍排最后）

与披风**同一套机制**，但多两道坎：

1. **原版没有人类头发的先例。** 原版用布料的地方里，跟头有关的是**头盔垂饰和羽饰**，马鬃马尾是**马**。人类头发一根都没有 —— **没有参照物**。
2. **布料 × 捏脸形变能不能共存，未知。** 我们的头带 **101 条脸形变通道**（捏脸滑块用的），布料数据是另一套网格数据，两者能否在同一件资产上共存，没有实测证据。
3. **头发是"多股细长几何"**（辫子），碰撞体不好做 —— 原版布料碰撞是**胶囊**，对细长分叉的辫子不一定合适。

做法：给头发单独造一张 `clo_` 模拟网格，**不动脸壳**（头发现在和脸壳是同一个网格，不能把脸壳直接扔进布料）。

### 🔴 先分清：哪些是**几何问题**、哪些是**物理问题**

**上布料不会解决几何问题。** 现在已知的头发毛病里，只有一部分是"不够飘"，其余是**形状本身就不对** —— 那要先修几何，再谈物理。

| 角色 | 现象 | 属于 | 物理能解决吗 |
|---|---|---|---|
| 明智光秀 | 发团鼓到头顶上方（源件是齐肩直发 + 背后一条到腰的长辫） | **几何** | ❌ 只会让错形状飘起来 |
| 武田信玄 | 整片红发帘罩住头（源件里那块是"红发 + 腰间红披"复合件） | **几何** | ❌ |
| 风魔小太郎 | 头下挂着一条长条（**用户确认：那是三根辫子，是设计**） | 待定 | ⚠️ 可能物理、可能几何 |
| 佐佐木小次郎 | 头下挂着一条长刃状长条 | 待定 | ⚠️ 同上 |
| 岛津义弘 | 兜没摘出来、还被放大成飞碟浮在头上 | **几何**（而且是兜，不是头发） | ❌ |
| 稻姬 | 头被拉得很细长、发丝拖很远 | 待定 | 待查 |

**⇒ 阶段十的前提是先做完几何修复**（见 [战国无双换装总纲.md](战国无双换装总纲.md) 的 T8 / T10）。

## 十三、附：备选路线——骨骼物理（本轮验过，不推荐先做）

**问题**：源件里披风本来就有自己的骨链（`nuno1_p_9_bone_103/108/113/…`，nuno = 日文"布"），能不能把这条链搬进游戏、自己写物理？

**答案：能，但不是"搬"—— 是"给这个角色换一份骨架"，成本比布料高一个数量级。**

### 硬事实（本轮逐个验过，不是推测）

| # | 事实 | 出处 |
|---|---|---|
| 1 | 骨架**全游戏共用一份** `human_skeleton`：31 根骨、全是身体骨 | 探针实测（附骨名全表） |
| 2 | 仅有的 3 根 `_nub_notused` = **头顶 + 左脚尖 + 右脚尖**（父骨是头/脚趾） | 同上 |
| 3 | 🔴 **骨架挂在 skin 上**：`skins.xml` 每条 skin 带 `skeleton="human_skeleton"`，skin 按「race × 性别 × 年龄段」选 ⇒ **可以给某一个角色单独换骨架**（信长已有自建 race `lwn_nobunaga`） | `Native/ModuleData/skins.xml` |
| 4 | **动画按骨名绑定**：骨名不匹配 = 通道落空（不动）⇒ 多出来的骨不会被原版动画影响，可以自己驱动 | 工程知识库《动画导入与UE5重定向》 |
| 5 | Monster 里的骨头字段（布娃娃、主手、头朝向、IK）**也全按骨名**，没有骨架字段 | `Native/ModuleData/monsters.xml` |
| 6 | 引擎暴露 `SetBoneLocalFrame`（能写骨的局部变换） | `TaleWorlds.Engine.dll` 二进制 |

⇒ **完整路线**：建一份「human 31 骨 + 披风链」的自建骨架 → 给信长的 skin 指过去 → 披风重新蒙皮到那几根骨 → **自己写 C#，每帧跑弹簧/verlet 写骨变换**。

### 和布料比

| 对比项 | 布料（推荐） | 骨骼物理 |
|---|---|---|
| 性质 | **配置资产**（刷 alpha + 编辑器接线） | **引擎工程**（建骨架 + 写运行时物理） |
| 代码量 | **0** | 每帧物理 + 与动画求值的写入时序（会不会被动画覆盖，未知） |
| 先例 | 原版 231 处；TW 连**马鬃**都用布料（马有尾巴骨，但**没给鬃毛加骨**） | 无先例：得自证骨架被引擎接受 / 动画真按名 / 布娃娃 / 捏脸 / 装备全不受影响 |
| 工作量 | 管线一次 + 每人 10 分钟编辑器 | 首个角色**数天起**，每加一个角色仍要重新蒙皮 |
| 观感 | 逐顶点：会褶皱、会贴身，幅度受 alpha 半径限制（原版袍子 0.44 m） | 整片摆动：幅度无上限，但**做不出布的形状**（除非骨链足够密） |

**骨骼路线唯一真正的优势**：幅度不受限，且不受"部分场景不支持布料"的影响。

**结论**：**先做布料**。实机若发现幅度不够、或我们的地图场景不支持布料，再按本节启动骨骼方案 —— 那时上表 6 条硬事实已经把路铺好了。

### 🔴 本轮新发现（3 条，都已进代码/文档）

1. **披风原本在 lod3 就整块消失**（decimate 的 collapse 把共面薄片吃光；09-20 那份包里 lod3/4/5 一片披风顶点都没有）。
   这是**布料的前置**：离远了披风直接不见，比"不飘"更出戏。修法 = `--lod-protect`（Blender 的语义实测：
   顶点组**权重越高砍得越狠** ⇒ 保护要 `invert_vertex_group=True` + 权重 1，依据脚本 `Debug/offline/_dec_test.py`）。
2. 🔴 **装机包里那件甲现在的顶点色 alpha 全是 1**（1543/1543，`clothinfo` 实测）—— 那是 ModKit 对
   「FBX 里没有顶点色」的**默认填充**。⇒ 如果导入器**不认**我们刷的 alpha，结果不是"布料不生效"，
   而是**整件甲都挂到披风替身上**（甲会跟着披风乱飘）。**所以第 3 步之前必须先验这一条**（见下）。
3. **原版参照物的精确参数**（`clothinfo` 打出来的）：袍子 `aserai_robe_c` 的 LOD0 是
   `bend=0.55 shear=0.64 damp=0.1 grav=8 airdrag=0.25`，**LOD1~5 全是默认值**
   ⇒ 编辑器的 Cloth Editor 只调 LOD0，其余 LOD 带默认参数，不影响运行。
