# 战国无双 · 袍子物理与头发物理 — 实施计划

> **一句话**：袍子和头发现在都是**刚体**（整块跟着一根骨走）。要让它们**会飘**。
> 引擎自带布料模拟，原版用了 231 处；我们要做的是**把自家资产接进去**。
>
> 🔴 **先做袍子，后做头发。** 袍子风险低（源件自带现成的模拟网格、原版有大量先例）；
> 头发风险高一档（原版**没有人类头发**用布料的先例，还要面对"布料 × 捏脸形变"的未知）。
>
> **状态**：待审批。批准前不实施。

---

## 一、结论：要做四件事

| # | 做什么 | 做到什么程度 |
|---|---|---|
| 1 | **最小验证**：只拿浓姬一个人跑通全链路 | 编辑器里能看到布在动 → 进游戏能看到 |
| 2 | **铺开袍子**：给"源件自带模拟网格"的角色做 | 每人一次编辑器操作 |
| 3 | **头发物理**：同一套机制，另做 | 排在袍子验证通过之后 |
| 4 | ~~改骨架、加头发骨~~ | **不做**（理由见 §五）|

## 二、凭什么：引擎给了什么（都已实测，不是推测）

| 项 | 内容 | 实测证据 |
|---|---|---|
| **控制方式** | 网格**顶点色 `COLOR_0` 的 alpha 通道** = 每个顶点能离开自己蒙皮位置多远。0 = 钉死不动 | 原版袍子 0~0.44；马鬃 0~1.0 |
| **模拟网格** | **映射模式**：另做一张低模来算，渲染网格挂上去跟。渲染网格自己的 alpha 当开关（>0 = 挂到模拟网格） | 原版 231 个 `clo_` 资产；渲染网格 alpha 中位数 0、最大 1 |
| **命名约定** | 模拟网格名 = 渲染网格名**前面加 `clo_`** | `aserai_robe_c` ↔ `clo_aserai_robe_c` |
| **手感参数** | 软硬 / 重力 / 风 / 阻尼 / 惯性 | `Modules/Native/ModuleData/cloth_materials.xml` |
| **碰撞体** | 胶囊（两端各自绑骨、可带权重），防止腿穿出裙摆 | `Modules/Native/ModuleData/cloth_bodies.xml` |
| **编辑器** | **Cloth Editor**：选模拟网格 + 布料材质 + 最大活动距离 + cook | 1.2.12 编辑器里字符串齐备（`AVClothEditor` / `Cloth cook` / `Enable Cloth Simulation`） |

**原版把布料用在哪**（决定我们照哪个抄）：

- 袍子 / 裙子 / 披风（`clo_aserai_robe_c`、`clo_aserai_plated_skirt` …）
- 头盔垂饰 / 羽饰（布料材质 `helmet_tail`、`feather`）
- **马鬃 / 马尾**（布料材质 `horse_mane`）
- 旗 / 军旗

**引擎还额外做了一件事**（说明布料是"活"的系统）：角色背上挂盾时，引擎会**把披风布料关掉**
（`CheckEquipmentForCapeClothSimulationStateChange` → 距离倍率设 0），免得盾和披风打架。

## 三、我们手上有什么

**源件自带现成的模拟网格 —— 这是最大的便宜。**

战无2 源模型里有 `driver_*` 网格（材质名带 `driver_`、**无 UV**、15~30 顶点），
**就是布片的低模驱动件**：包围盒和它驱动的渲染件几乎重合。

**配对判据**：按包围盒重合度把驱动件配到渲染件上 —— 在 8 个角色上验证，**8/8 全部配上**
（最低重合度 86%），且结果与人工判断一致。

| 角色 | 源件里的布片 | 现成的模拟网格 |
|---|---|---|
| 浓姬 | 两片振袖 | `driver_0` / `driver_1`（各 15 顶点）|
| 浅井长政 | 长外袍下摆 | `driver_0`（25 顶点）|
| 德川家康 | 阵羽织 | `driver_0`（25 顶点）|

**共 17 人**有驱动件：浓姬 · 幸村 · 慶次 · 信长 · 光秀 · 谦信 · 胜家 · 信玄 · 政宗 · 半藏 ·
家康 · 长政 · 左近 · 义弘 · 訚千代 · 兼续 · 小太郎。

**另外 11 人**（阿市 · 阿国 · 杂贺 · 小次郎 · 兰丸 · 秀吉 · 忠胜 · 稻姬 · 三成 · 宁宁 · 武藏）
源件里**没有**布片驱动件 —— 要做只能自己拿渲染件降面造一个。**这批放最后。**

## 四、方案

### 阶段 0 · 最小验证（**只做浓姬一个人**）

**为什么是她**：她的布片最大最显眼（两片振袖）、源件自带驱动件、形状已经修过一轮（现在是自然下垂的）。

要做的事：

1. **造模拟网格**：把 `driver_0` / `driver_1` 按现有甲的同一套骨架重定向搬过来，输出成 `clo_taikou_nouhime_do_a`。
   - ⚠️ 编辑器约束：**模拟网格必须只有一个子网格**（编辑器原话 `Simulation meshes must have single submesh`）。
   - ⚠️ 模拟网格必须**整个包在渲染网格里面**，不能顶出去（原版文档：渲染网格穿出模拟网格会出现"腿穿甲"式的碰撞错位）。
     实测两个 driver 的包围盒确实在振袖内部 —— 这条天然满足。
2. **刷顶点色 alpha**：
   - 模拟网格：**靠肩（钉死）= 0 → 靠袖口（自由）= 大**。参照原版袍子的 0~0.44。
   - 振袖网格：**凡是"要跟着飘"的顶点 = alpha 1，靠肩那圈 = 0**（这是"挂到模拟网格"的开关）。
3. **进编辑器**（人做）：导入 → 材质勾 `Vertex Layout → Skinning` → 挂贴图 →
   **Cloth Editor** 里选模拟网格 + 布料材质（照 `medium_leather` 或 `flag` 起步）+ 最大活动距离 → **cook** → Publish。
4. **装机验**：`install_pack.py` → 进游戏看。

**这一步要验的就是 §六 的两道门。门没过，后面全部不做。**

### 阶段 1 · 铺开袍子

阶段 0 通过后，按**同一个模板**给其余 16 人做。
每人固定三件事：搬驱动件 → 刷 alpha → 编辑器 cook。

**顺序按"布片有多大"排**：先做长政 / 家康（已知形状偏大），最后做本来就正常的（幸村 / 信长）。

### 阶段 2 · 头发物理

与袍子**同一套机制**，但多两道坎（见 §七）。**排在阶段 1 之后。**

做法：给头发单独造一张 `clo_` 模拟网格，**不动脸壳**。
（头发现在和脸壳是同一个网格，不能直接把脸壳扔进布料。）

### 阶段 3 · 没有驱动件的 11 人

要自己从渲染件降面造模拟网格。**收益最低、工作量最大，放最后，可做可不做。**

## 五、为什么不做"加骨头"那条路

Bannerlord 的 `human_skeleton` 实测是 **31 根骨，全是身体骨**（盆骨 / 脊椎 / 四肢 / 头），
**一根头发骨都没有**。

骨架是全游戏共用的 —— 所有装备、所有动画都按它做。**加骨 = 换骨架 = 全套动画与装备重做。**

（引擎里有 4 根名字带 `_nub_notused` 的骨，字面意思就是"没在用"；数量也撑不起一条头发链。）

**结论：不做。头发只能走布料。**

## 六、挡路的两道门（必须实机验证，其余都是纸面）

| # | 门 | 怎么验 |
|---|---|---|
| 1 | ModKit 导入 FBX 时**保不保得住顶点色 alpha** | 导入后进 Cloth Editor，看预览里布动不动 |
| 2 | Cloth Editor **cook 出的数据能不能进 Taikou 的 tpac、被游戏读到** | 装机后进游戏看 |

⚠️ 我们的导入设置现在**只勾了 `Import meshes`** —— 顶点色要不要额外开，门 1 就是问这个。

**门 1 不过** → 退路是在编辑器里手刷顶点色（编辑器有 `Paint Vertex Color` 工具），但那是纯手工、28 人做不动。

## 七、头发的额外未知（所以排在后面）

1. **原版没有人类头发的先例。** 原版用布料的地方里，跟头有关的是**头盔垂饰和羽饰**，
   马鬃马尾是**马**。人类头发一根都没有。**没有先例 = 没有参照物**。
2. **布料 × 捏脸形变能不能共存，未知。** 我们的头带 **101 条脸形变通道**（捏脸滑块用的），
   而布料数据是另一套网格数据。两者能不能在同一件资产上共存，没有实测证据。
3. **头发是"多股细长几何"**（辫子），碰撞体不好做 —— 原版布料碰撞是**胶囊**，
   对细长分叉的辫子不一定合适。

## 八、代价

| 项 | 代价 |
|---|---|
| **编辑器手工活** | 每人一次 Cloth Editor（选网格 / 选材质 / 调距离 / cook）。**只有你能做，我做不了** |
| **性能** | 随顶点数与迭代频率线性增长。袖口这种小件可控；整件长袍要留意 |
| **部分场景不支持** | 原版论坛有案例（Sargoth 城镇场景布料失效）。**我们的日本地图场景是否支持，未测** |
| **返工风险** | 布料的形状是"模拟出来的"，**和我们现在手工摆好的形状会不一样** —— 上了布料等于放弃手工摆的姿态 |

## 十、明确不做的事

1. **不改骨架、不加头发骨**（§五）。
2. **不做马的布料**（源工程升了马的贴图，但我们没有马的管线，属另一个工程）。
3. **不为了布料推翻现有几何。** 已经手工摆好的形状（浓姬 / 长政 / 家康）保持不动；
   布料是**在它之上再加一层动效**。
4. **不在脸壳上直接开布料**（头发要单独网格）。
