# 选人开局（StartAsAnyone 式）— 实施计划

> **状态：✅ 实机验证通过**（2026-09-10；编译 0 错、体检 14 绿 / 1 既有红）——选人界面正常显示、魂穿开局成功、**无卡死**。
> ⏭ **下一步：选人界面 UI 优化**（功能已通，纯外观/交互打磨）。
> **上游**：承 [时代剧本切换-验证](时代剧本切换-验证.md)（选剧本已验通）；机制参考 = `Modules/StartAsAnyone`（反编译，v1.0.1 / 1.2.12）
> **一句话**：选完剧本后接一步**选人**——先王国、再家族、再家族里的英雄；选中即用该英雄开局，**跳过整套建号捏脸**。

---

## 一、要做什么（一句话）

主菜单流程从「选剧本 → 建号捏脸」改成 **「选剧本 → 选人」**，其中选人界面留一个「自定义英雄」按钮走原来的建号。

**语义（用户裁定）**：选了某位领主 = **魂穿**——你就是他本人，**人和家当（部队/金钱/物品）一起接手**。

```
主菜单[剧本] → ① 选剧本（已有）
              → ② 加载世界（读盘屏，几秒）
              → ③ 选人【本次要做的】——世界建好后弹出（界面要读王国/家族/英雄，必须世界在先）
                    ├ 左列：王国
                    ├ 中列：该王国的家族
                    ├ 右列：该家族的英雄
                    ├ 右上：[自定义人物] → 进原建号流程（捏脸/出身/加点，一行未改）
                    └ 右下：[返回]（= 改走建号）/ [以此人开局] → 魂穿，直接进图
```

**实现形态**（实机验证）：选人界面是**挂在建号屏上的覆盖层**（`HeroSelectOverlay`），
不是自建 Screen；底下的建号屏给层当宿主、并被上层遮住——玩家只看得到选人界面。

🔴 **时点硬约束（2026-09-10 实机踩坑）**：选人界面**必须在世界建好之后**才能开——
界面要读 `Kingdom.All` / `Clan.Heroes`，而这些需要 `Campaign.Current`（世界创建期才赋值）。
在世界之前开 = `Kingdom.get_All()` 直接 **NRE**（已踩）。这正是 StartAsAnyone 把选人
放进建号流程内部的同一个原因；我们用「`OnLoadFinished` 里弹界面」达到同等效果。

## 二、机制（从 StartAsAnyone 反编译得到；我们只借机制、不用它的 GUI）

### 2.1 换玩家身份 = 一个引擎 API

```csharp
ChangePlayerCharacterAction.Apply(选中英雄);
```
引擎内部做完的事：`Game.PlayerTroop` 换成该英雄的 CharacterObject → 触发 `OnPlayerCharacterChanged` →
**`MobileParty.MainParty` 变成该英雄的部队**（人、钱、粮、装备全跟过来）→ 原主队若空则销毁。

### 2.2 光调它不够——必须补 5 件事（StartAsAnyone 实测做法）

| # | 补什么 | 为什么 |
|---|---|---|
| 1 | 记下英雄生日 → 换完后 `SetBirthDay` 还原 | 换人会重置生日（年龄变 18） |
| 2 | `Campaign.SetPropertyValue("PlayerDefaultFaction", hero.Clan)` | 玩家默认势力 |
| 3 | ~~清空主队物品栏~~ → **我们不清空** | **用户裁定（2026-09-10）：魂穿 = 人和家当一起要**。StartAsAnyone 清空是它的平衡口味，我们不跟 |
| 4 | 销毁原占位家族（`main_hero` 的 `player_faction`） | 换人后它被清空成无主，留着会出问题 |
| 5 | 相机 `ResetCamera` + `TeleportCameraToMainParty` | 否则镜头停在旧位置 |

### 2.4 跳过建号 ≠ 什么都不用做——引擎的「建号收尾」必须补

对照 `CharacterCreationState.FinalizeCharacterCreation()`（反编译实锤），**建号结束**时引擎做这些：

| 步 | 引擎做什么 | 我们怎么做 |
|---|---|---|
| 1 | `CharacterCreation.ApplyFinalEffects()`——把建号菜单里选的出身/加点写进角色 | **省略**（我们没走建号，没有这类选择） |
| 2 | `CleanAndPushState(CreateState<MapState>())`——**推入大地图** | ✅ 照做（不推 = 玩家停在空状态） |
| 3 | `PartyBase.MainParty.SetVisualAsDirty()` | ✅ 照做（换人后立绘/图标要重算） |
| 4 | `_handler?.OnCharacterCreationFinalized()` + `CurrentCharacterCreationContent.OnCharacterCreationFinalized()` | ✅ 通知内容类（里面会 ResetCamera + TeleportCameraToMainParty） |
| 5 | `CampaignEventDispatcher.Instance.OnCharacterCreationIsOver()` | ✅ 照做（其他 behavior 在听这个事件） |

> 实现 = `StartingHero.FinalizeCampaignStart()`。**只有第 1 步省**，其余一步不落——
> 省错步骤的症状是"进了图但没有 UI"或"其他 behavior 没初始化"。

### 2.3 与我们的差异（少走一半路）

StartAsAnyone 是**寄生在官方建号流程**里（反射给所有 `CharacterCreationContentBase` 子类的
`CharacterCreationStages` 打 postfix 插自己阶段 + 给 `ApplyFinalEffects` 打 postfix 做落地）。
**我们有自己控制的建号流程**（`LivingWorldCampaignGameManager`），因此：

- 选了人 → **根本不推建号界面**，在 `OnLoadFinished`（世界已建好）直接做 §2.2 那 5 件事
- 选「自定义英雄」→ 走现有 `CharacterCreationState`，**一行不改**

## 三、落地设计

### 3.1 数据流（谁把"选了谁"传下去）

```
选剧本界面点剧本 → EraCatalog.StartCampaign(era) → 世界开始加载
  → OnLoadFinished（世界已好）
      ├ 先建好「建号状态」（**不显示**）——为的是 CharacterCreationContentBase.Instance 可用
      └ 弹选人界面（盖在建号状态之上）
           ├ 点[以此人开局] → StartingHero.ApplyPending(hero)
           │     = 换人（魂穿）+ 走完引擎的建号收尾（推入大地图，见 §2.4）→ 关界面 → 进图
           └ 点[自定义人物]/[返回] → 关界面 → 建号状态 NextStage() → 原建号流程
```

### 3.2 三列取数（纯查询，可离线验）

| 列 | 取什么 | 过滤规则 |
|---|---|---|
| 王国 | `Kingdom.All` | 排除小派系（`IsMinorFaction`）；排除无据点/无人的空壳 |
| 家族 | `kingdom.Clans` | 只列**至少有一个可玩英雄**的家族 |
| 英雄 | `clan.Heroes` | **成年 · 在世 · 非俘虏 · 非小孩**（`!IsChild && IsAlive && !IsPrisoner`）；排除占位 `main_hero` |

> 为什么必须过滤英雄：选到小孩/囚犯/死人 = 开局即废档。

### 3.3 界面

- 复用已验证的自建界面三件套（`GUI/Prefabs/*.xml` + `VM` + `Screen`，范本 = `ScenarioSelectScreen`）
- 三列各一个 `ListPanel`（纵向），点左列刷新中列、点中列刷新右列（纯 VM 内部联动）
- 右上/右侧留**大图位**（立绘，先占位——与选剧本界面同款做法）
- 右下「返回」→ 回选剧本界面；左上一个「自定义英雄」按钮

## 五、要实测的三个未知点

| # | 未知 | 万一不对怎么办 |
|---|---|---|
| U1 | `OnLoadFinished` 时点上，选中英雄的**部队是否已就绪**（`ChangePlayerCharacterAction` 依赖 `hero.PartyBelongedTo`） | 退到世界创建期的 `OnNewGameCreatedPartialFollowUp`（StartAsAnyone 就是在建号末期做的，那条时点实测可行）。<br>📌 **已核实的部分**：引擎在**世界创建期**就把英雄实例化了——`HeroSpawnCampaignBehavior` 是拿 `clan.Heroes` 去建领主部队的（反编译实证），所以 `OnLoadFinished` 时**英雄一定在**；只有"部队是否已挂上"需要在 `ChangePlayerCharacterAction` 内部由 `Campaign.OnPlayerCharacterChanged()` 现算，故风险低 |

| U3 | 换人后原占位家族的清理是否有副作用 | 照抄 StartAsAnyone 的销毁序列；若报错则退化为"保留空家族"观察 |

## ✅ 实施记录（2026-09-10；含三次实机迭代的结论）

### 🔴 一句话结论（踩了三个坑才走到）

**给跳过的引擎标准流程补收尾时，两个地方必须照抄、一个地方必须自建**：
① 收尾步骤照抄 `CharacterCreationState.FinalizeCharacterCreation`（**一步不能漏**，漏一步就是静默卡死）；
② 界面宿主照抄本仓库能工作的范本（**挂到引擎现成的屏上，不自建 Screen**，否则层画不出来）；
③ "选人"这一步自建（不改主菜单列表——MCM 会崩；不寄生建号流程——`ApplyFinalEffects` 会把所选领主家族声望清零）。

### 三个坑（每个都有实机日志为证）

| # | 症状 | 根因 | 修法 |
|---|---|---|---|
| 1 | 界面**完全不可见**，但屏在栈顶 / IsActive / 层活跃 / 焦点全 True | **自建 `ScreenBase` + `PushScreen` 在这个时点画不出来**（引擎屏栈正在换代）。本仓库能工作的界面（AgentHud / IM / 相机调试）**无一例外**都是 `ScreenManager.TopScreen.AddLayer` | 改成挂层到现成屏（`HeroSelectOverlay`） |
| 2 | 点剧本后**卡在 loading** | 引擎 `GameLoadingState.OnTick` **没有"只调一次"守卫**——`_loadingFinished` 之后**每帧**调 `OnLoadFinished()`；而我在里面弹界面 = 每帧重建 = 玩家点击被下一次重建吞掉 | `OnLoadFinished` 必须**幂等**（`_heroSelectOpened` 守卫） |
| 3 | 选人成功后**卡死**（画面在、无法操作，日志停在 `scene=CampaignPaused`） | 跳过建号后自己补收尾时**漏了引擎的一步**：`UnregisterActiveStateDisableRequest`。不撤 = `GameStateManager.ActiveStateDisabledByUser` 恒真 = **地图状态永不激活** | 收尾照抄引擎 5 步（见 §2.4） |

### 还有一个"半坑"（不是 bug，是取舍）

**不预推建号状态 → 选人层没屏可挂 → 界面不出现**（坑 1 的变体）。
最终定案：**预推建号状态**（给层提供宿主），选人层盖在它上面（玩家看不到选文化界面）。
它的副作用（禁用请求）由收尾的撤销步骤处理。



### 落了什么

| 文件 | 职责 |
|---|---|
| `CampaignMode/StartingHero.cs` | 静态交接（待选英雄 StringId）+ **落地执行**（换人 5 步序列 + 相机归位） |

| `GUI/Prefabs/HeroSelect.xml` | 三列布局 + 右上「自定义英雄」+ 右下「返回/确认」 |
| `CampaignMode/{EraCatalog,ScenarioSelectScreen,LivingWorldCampaignGameManager}.cs` | 接线：选剧本 → 记时代 → 选人 → 开局分支 |

### 实施中作的两个技术订正（与设计稿的差异）

1. **`Campaign.PlayerDefaultFaction` 是 `internal` 属性**——设计稿写 `Campaign.Current.SetPropertyValue(...)` 是
   StartAsAnyone **自己写的反射扩展**（不是引擎 API）。已改为我们自己的反射写法（`SetPlayerDefaultFaction`），
   并记下为什么必须写：`Clan.PlayerClan => Campaign.Current.PlayerDefaultFaction`，不写则换人后仍指向已销毁的占位家族。
2. **「自定义英雄」与「选英雄」共用同一条启动路径**——都走 `EraCatalog.StartCampaign(eraId)`，
   差别只在**是否设了待选英雄**（设了 = 换人跳过建号；没设 = GameManager 推建号界面）。
   因此不需要两套开局代码，只需一个 `StartingHero.ClearPending()`。

| ② | ~~清空物品栏~~ → **保留**（用户裁定：魂穿 = 人和家当一起要）；村庄补给不做 | `StartingHero.Apply` 第 ④ 步 |
| ③ | 非族长的 5 个小补丁**先不做**（实测遇到再加） | — |

### 待实机验证

1. 主菜单「剧本」→ 选剧本 → **出现选人界面**（三列有内容）
2. 点王国 → 家族列跟着变；点家族 → 英雄列跟着变（默认自动选第一项）
3. 点「以此人开局」→ **不经建号**直接进图，玩家 = 所选领主（名字/家族/部队对）
4. 相机在玩家身上；F5 存档不报错
5. 回主菜单 → 剧本 → **「自定义人物」** → 走原建号流程（捏脸/出身/加点照旧）
6. 选一个小家族（如 1582 的 G 家，只有 1 名领主）也能正常开局
