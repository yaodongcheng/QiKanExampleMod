**测试夹具合同：**`begin <caseId> <goap|htn|hybrid> <seed>`只能在Debug功能显式开启且大地图可安全进入时运行；同一时间只能一个测试过程，退出原场景后才开始下一例。夹具有独立剧情状态、尝试账本和财物适配器，真实身体／Brain／移动／视线尽量走原生实现，所有测试演员标记隔离身份；效果适配器不得写正式家族／队伍／存档。普通场景、非Debug、未知案例及已有测试未结束时拒绝开始，不能为了测试偷偷覆盖正式状态。

**注入只控制输入，不提交结果。** 固定骰子通过同一检定入口消费一次；只能在真实交互达到检定时生效，日志记录目的、人物、attempt与注入来源。拒绝职责、控制权不足时不消费骰子。移动受阻夹具要有真实障碍／不可达点，不能伪造到达或只返回一个失败回调冒充原生寻路测试；回包延迟、重复事件和队列抢占通过明确测试入口产生。结束清除所有注入，任何残留视为失败。`test begin`不得为绕过“不重复掷骰”去删除同一测试过程内的账本。

**真实招募、扣款、存档与正常试玩单独验：**复制一份可正常进入511二次场景的测试存档，用正常对白操作；不使用隔离财物替身充当真实经济验收。测试文件在模块已有`Debug/offline`内，正式数据生成源不混入调试夹具。若实施阶段不能提供某个原生夹具，报告“未验”和手工复现条件，不能自动把它算通过。

## 2. 测试前准备与日志保存

1. 记录实际游戏版本、DLL文件hash／构建标识、配置版本／hash和测试时间。涉及模块生效问题时自行核本次引擎日志`Command Args:`，不以目录存在推测加载成功。
2. 正常试玩使用511二次场景，先完成当前人物事件／开场并收尾；无永久令牌、无已完成通行记录，记录初始门岗人数、同伴、金币、能力与身份。不要用修改剧情的命令跳阶段。
3. 从游戏设置关闭LLM相关功能，记录润色开关；无LLM案例须证实没有规划／决策／润色请求发出。润色案例单独开启，实际控制算法不变。
4. 在地图存一份专用测试副本，保留原档。测试结束记录未了拘捕／伤害等，重复案例用明确的同一初始副本，不能忽略上次后果。
5. 运行`status/where/gate`，正式接入后再运行`cooperate status`；保存控制台输出。玩法步骤按实施后提供的真实对白选项／人物称呼操作，不能靠内部token让玩家猜。
6. 运行时日志在模块根`Debug/StoryEngine_RuntimeLog.txt`，首次写入会覆盖前次游戏日志。**每轮结束、尤其读档重启前先复制日志**到已有`Debug/offline`内，按案例、版本、runId命名；不清空原日志制造整洁报告。

**只读取证示例（PowerShell，在模块根执行）：**

```powershell
Get-Content -LiteralPath 'Debug/StoryEngine_RuntimeLog.txt' -Encoding UTF8 -Tail 120
rg -n --fixed-strings '"run":"实际runId"' Debug/StoryEngine_RuntimeLog.txt
Copy-Item -LiteralPath 'Debug/StoryEngine_RuntimeLog.txt' -Destination 'Debug/offline/T01-session1-runtime.txt'
```

替换真实runId和唯一目标文件名，避免覆盖前例。第一次看不到新标签先核版本与入口，不能把旧日志当新实现失败／成功。读档前后日志分开保存，并用稳定业务attempt／receipt关联；运行runId和场景代次应变化。

## 3. 关键日志合同

### 3.1 每条记录必须能关联到真实对象

**决定：复用DebugLogger，在关键出口写`[Coop]`单行结构化记录，值与诊断原因使用英文。** 推荐JSON转义，不能拼接未转义台词导致多行；不记录密钥或完整LLM请求。玩家界面使用本地化自然文字，不直接显示日志。

| 字段 | 含义／要求 |
|---|---|
| `event/seq/run/sceneEpoch` | 事件、当前场景单调序号、玩法过程、场景代次；时间戳不能替代因果顺序 |
| `actor/agent/target` | 稳定身份、当前身体索引及实际对象；无Hero模板使用稳定场景身份，不借玩家ID |
| `activity/source/owner` | 本人活动、来源（新／旧／岗位／日常等）、实际身体持有编号；没有租约则明确空值 |
| `planRevision/stage/step` | 当前计划、阶段和步骤；重规划不能沿用旧修订号 |
| `request/attempt/receipt` | 请求、逻辑掷骰尝试、业务收据；没有时为null，不随日志另造编号 |
| `state/result/reason` | 当前状态、真实结果与可稳定检索的原因；成功／无解／触限／失败／取消／被打断分开 |
| `configVersion/configHash/factsVersion` | 活动固定数据及计算所用事实快照；过期结果应可核对 |
| `simTime/testMode/injection` | 游戏推进时间、是否测试、注入内容／来源；暂停期间simTime不增加 |
| `contractMode/operationId` | 小六为临时协作还是正式同伴、稳定招募／单次人情业务身份；原委托奖励与招募／人情不得共用操作身份 |

适用事件补参数：位置、目标、到位距离、同层检查、观察者与视线解释、技能／门槛／骰子、资源前后值、预留／提交、节点与CPU耗时、公共答复、文本key、消息编号、语言、展示渠道、接收资格与丢弃原因。未适用字段明确空值；完整合同由实施者维护清单，不能因为某日志“写起来麻烦”省关键证据。

### 3.3 正常链与失败链怎样判读

下列为**预期事件顺序示意，不是实测日志**。双方独立动作可交错，检查因果依赖和编号，不能要求所有线程／演员每次同一行序。

```text
随从：plan.ready → preview.shown → brain.granted → step.started(接近)
随从：step.ended(completed，真实到位) → interaction.received(守卫)
共享：roll.committed → interaction.resolved → answer.published
随从：answer.observed → 接后续步骤／调整；不知道结果之前不提前推进
守卫：goal.selected → guard.choice(留岗交谈) → 本人Brain动作
随从：opportunity.observed → speech.shown(有限信号)
玩家：gate.evaluated(全员真实视线／技巧) → player.crossed(实际跨线)
随从：获知玩家结果 → 本人会合移动 → step.ended(真实会合)
过程：run.end(success，playerCrossed=true，companionReunited=true)
```

不需要检定的普通信息请求可以没有roll；拒绝职责的分支必须没有roll。失败骰子应是`roll.committed(result=failed)`→守卫留岗拒绝→公开答复送达→随从换已登记的新方法或撤回→终态；同一attempt后续只许`attempt.reused`。调查链必须在`post.replacement_ready`之后才出现原守卫调查移动的`step.started`，且接替者仍参与门禁观察。

**硬失败判据：**未真实到位却写completed；排队动作被清却写started；拒绝后仍出现随从来源派给守卫的移动；同一attempt出现两次roll；同一receipt实际扣款两次；旧owner在新owner获准后清新动作；看不见／无法接近的守卫隔空推回玩家；没有`player.crossed`却结束为全目标成功；没有展示出口却声称玩家收到说明。任一出现即阻止该阶段交付。

## 5. 用户可复现的验收案例

**决定：表内每例均交初始条件、操作、现场预期、日志证据和反例判据。** 同一DLL分别运行GOAP、HTN和组合模式；自然试玩使用默认模式。T01～T09可由新测试夹具准备真实人物／点位与输入；经济／存档用正式玩法在副本存档操作。夹具支持清单由`test list`给出，不能把未支持案例写成已通过。

### 5.1 两条必须完整演示的链

**T01：一卫留岗牵制，真实越门与会合。**

1. 关闭LLM。在大地图执行`custom.story_probe cooperate test begin T01 hybrid 32001`；夹具准备一卫岗位交谈、可行侧路、可用同伴、约定点与隔离的成功检定输入，输出注入项。先执行`cooperate status/plan`记录基线。
2. 与同伴按正式对白约定“你去搭话，我自己找机会过去”，先查看基础说明，暂不出发时守卫位置／财物／骰子应未变化。用卡片已有开始选择或明确的执行对白出发。
3. 亲眼观察同伴走到交谈点，守卫独立回应并在职责范围内转向，仍保持真实警戒；至少一次未出现机会前，界面只表示尝试／等待。
4. 听到／看到约定信号后，玩家亲自观察并蹲行跨真实门线，按现有技巧规则裁定。不能自动走位、传送、发令牌或直接开门。
5. 玩家用约定合法消息／目击让同伴获知结果，等其真正走到会合点，查看终态与trace，保存日志，执行`cooperate test end`。

**通过：**有同版基础说明、双方独立Brain事件、实际位置／视线、玩家跨线和同伴到位证据，演出未接管玩家；终态明确两项完成。**失败：**守卫被随从直接移走、只聊天即全局失明、无跨线日志、同伴被传送会合，任一即失败。再在正式玩法测试副本上不注入骰子／状态完成同链，记录成功或真实拒绝，证实正常输入可玩。

**T02：固定失败骰子后诚实收尾，再尝试不刷新骰子。**

1. 执行`custom.story_probe cooperate test begin T02 hybrid 32002`，夹具提供合资格交涉、低于当前门槛的骰子、无新证据，并输出实际能力／门槛。准备过程不提前提交检定。
2. 下达同样协作，观察守卫拒绝且留岗；随从按当前计划说明原因并撤回，不能播成功信号或升级袭击／加价。
3. 用同一方法再下令、回问、开关详情；等待冷却后再试一次。应复用已有失败，不再消费随机输入。保存status、trace及日志。
4. 结束夹具。在T03提供已登记且本人已知的新证据，才允许另一次有独立attempt的尝试；日志列出实质变化，不是换台词造成的新ID。

**通过：**同一attempt只有一次`roll.committed`，其余是`attempt.reused`；无新条件时失败／撤回，有合法新条件时可以重新规划。**失败：**反复下令终于成功但没有新条件，或者拒绝仍驱动守卫离岗。

### 5.3 持续开发接入的具体复现顺序

**T31～T37先保存接入基线，不直接修改正式数据做夹具。** 在已有Debug测试域维护V1／V2／V3隔离内容，沿现有生成／加载／发布路径校验，记录DLL、源文件hash、目录版本与全部相关业务ID。正常内容改动另外在测试副本实机复验，不能把夹具目录当正式DesignData发布。

1. V1运行后执行`custom.story_probe cooperate catalog`、`custom.story_probe cooperate status`和`custom.story_probe cooperate trace`，保存目录、计划、实际结果与现有收据。
2. T31仅改内容源，生成V2，不改DLL。退出场景，在大地图执行`custom.story_probe reload`；按原规则再次进入，核新目录及新内容行为，纯GOAP、纯HTN和组合模式分别验。新增的是已有能力的组合，未实现的新token应被拒绝，不能作为本例通过。
3. T32先提交悬空删除版本再正确删除；记录`config.rejected`与依赖路径，并证实旧有效hash未替换。修复后再发布，证实新计划不选已删方案；旧运行版本与新版本的差别在catalog里分别可见。
4. T33在已结算业务上改文案／文件／节点次序，保留稳定业务身份；存在旧记录时提供显式收据映射。重进和引擎允许保存的时点读档，核真账目与attempt／receipt。无映射版本必须拒绝不安全重放，不能临时清账本。
5. T34让另一真实事件通过既有效果提交出口改变相关世界条件，分别观察知情／未知NPC；再变无关条件，核依赖通知及求解次数。计时以实际游戏推进为准。
6. T35／T36记录新增C#能力注册与适配的代码差异，按支持版本隔离编译；授权部署后实机重启验证。C#需重启不算JSON热重载；若尚未部署则明确程序合同通过／原生未验，不能跳过该层。
7. T37对比模型缺失前后目录覆盖表；未建模能力不得被GOAP猜到或HTN直接执行，补齐合同后再按T36验证，日志列出启用的实际模型版本。

**本组通过标准：**T31的DLL相同，T36的算法／活动执行／Brain没有玩法专用改动；两者都能看到基础计划、真实步骤和结果。T32～T35没有旧引用控制新对象、重复业务或旧合同误解释，T37没有静默假支持。覆盖表与来源日志要能直接指出下一项新机制还缺哪一环。

### 5.4 小六招募的真实玩法复验

**T38～T43用原出场小六，不能用普通Wanderer替身代表通过。** 在正式测试副本自然进入二次场景，与小六接工具委托，到杜野处按现有合法路线办妥，再回小六完成交差；`custom.story_probe status/persona`和原对话／业务日志核当前状态，不用resolve／reset制造前置。若涉及他的当前老周群戏尚未收尾，先正常处理再谈合作；原奖励与合作分别保留收据。

1. 交差结束后重新与小六交谈，应能进入新增合作话题并听到他的目的与伤手限制。分别请求临时搭话、询正式同行条件和返回其他话题；不能在工具奖励节点自动入队。
2. 临时模式先看基础计划并取消，查看`custom.story_probe cooperate status/trace`：无正式入队、无30扣款、无favor.used；再正常开始，首个真实交涉started后只消费一次人情。失败报告、归位／待接应与旧人物身份都可观察。
3. 正式模式从相同初始副本分别走已报价付30、实际免招募费魅力成功、魅力失败和容量／资金失败；记录玩家真实金币、Hero.StringId、原生职业／同伴关系／主队、receipt及话题结果。旧`MoneyPrice=40`不能成为招募价格；免费临时人物不能误算正式招募成功。
4. 正式入队后离场／重进，并在可保存时读档；再验分兵、被扣／死亡等实际不可用状态。检查原Cast与已有同伴入口只绑定原Hero的合法身体，不造另一个小六，不把远方／被扣人物拖到墙头。
5. 运行T43自然全链，分别以临时和正式关系下令，记录当时能力与骰子；同伴真实到位且双方实际获知结果才宣告会合。玩家先越门而小六仍门外时显示待接应，不能由章完成标记让他自动进城。

**必须提交的证据：**原剧情前置／奖励回执、当前事件收尾、两种关系的独立对白／悬停、30／0真实结算与原Hero入队、单次人情提交点、同伴身体去重、角色出场资格、受伤／知识边界及过门后实际收尾。缺任何一个，首版小六路线不能算交付完成。
