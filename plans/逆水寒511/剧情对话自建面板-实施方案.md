# 511 剧情对话自建面板（已实施 2026-11-19）

## 一句话

511 玩法对话改用自己的对话面板，**默认开启**；原版对话流保留，一条命令切回。

## 为什么做

问题 49：跟我们召唤出来的 NPC 谈过一次话，结束后 NPC 定在原地、不再响应任何移动；原版世界里已有的 NPC 不会。

根因在**原版对话流的生命周期**：`MissionConversationLogic.StartConversation` 开始时会
`CampaignMission.OnConversationStart` + `ForceAiBehaviorSelection`，结束再把身体还回去。
我们的 NPC 由 AgentBrain 托管，这条「还身体」的链一旦漏一步，实机就是永久钉住；
在 `EndConversation` 后处理里反复补，仍会复发。

新面板**根本不启动引擎对话流**，所以这条链不存在 —— 这是从根上绕开，不是事后修补。

## 改了以后行为上有什么不同

| | 原版对话流（vanilla） | 自建面板（custom，默认） |
|---|---|---|
| 对话引擎 | ConversationManager + 原版面板 | 我们自己的面板 |
| 对话数据 | `dialog.json`（同一份） | `dialog.json`（同一份） |
| 选项后果 / 检定 / 跳转 | 同一套 | **同一套**（调同一个函数） |
| 对话结束后 NPC | 可能定身（问题 49） | 不会被引擎动过 |
| 适用范围 | 511 对话 + 其它 | **只有 511 对话** |
| 打不开时 | — | 自动回退原版，玩家不会卡住 |

犯罪对话、原版对话（交易/招降/…）、IM 传讯**一律不变**，与本开关无关。

## 怎么切

游戏内控制台（返回文本纯英文）：

- `custom.story_probe ui` —— 看当前形态 + 面板/运行器状态
- `custom.story_probe ui vanilla` —— 切回原版对话流
- `custom.story_probe ui custom` —— 切到自建面板

运行时切换只对**下一次**对话生效（正在说的这一段不会中途换皮）。
要长期生效改 `config.json`：

```json
"StoryDialogueUi": "custom"
```

## 操作方式（面板里）

- 鼠标点选项；或按数字键 `1`~`9`
- 悬停选项 → 下方显示说明（检定依据 + 后果，铁律 43）
- 没有选项时：底部出现「继续」（NPC 还有下一句）或「离开」（说完了）
- `ESC` = 离开对话

## 复用纪律（防止两套逻辑分叉）

对话逻辑只有一份，面板只是「画出来 + 把点击转回去」：

| 动作 | 唯一实现 |
|---|---|
| 选项是否显示 | `DialogueInjector.IsTransitionVisible` |
| 选项是否可选 | `DialogueInjector.IsTransitionSelectable` |
| 选项正文 | `DialogueInjector.GetTransitionText` |
| 悬停说明 | `DialogueInjector.GetTransitionHint` |
| 选中执行（后果 + 检定 + 跳转） | `DialogueInjector.ExecutePlayerChoice` |
| 节点进入（效果 / 动作 / 表情 / 朝向 / 机位） | 节点自身的 `PrepareTurn` / `OnShown` |
| 收尾（会话效果 / 释放朝向与机位 / 清钩子） | `StoryProbeDialogue.OnConversationEnded` |

## 顺带修掉的一个真 bug（即使切回原版也受益）

`StoryProbeDialogue.ReleaseFacingActor` 原来写的是：

```csharp
if (Mission.Current != _facingMission || !CanUseTurnAgent(actor)) return;  // ← 早退，不清
actor.ClearTargetFrame();
```

也就是说：只要释放那一刻 NPC 的身体状态「看起来不该动」（战斗中 / 被打断 / 正在执行别的表演），
我们给他设的「钉在原地」站位就**留下来了**。这正好是问题 49 的实机表现。
现在改成：**只要本层真的给他写过站位，就一定清掉**。

## 验收

### 1. 面板能开

1. 进目标城 center 场景（`custom.story_probe status` 确认 active）
2. 走到剧情 NPC 面前按 F
3. 期望：左下角出现金色名字 + 黑底台词；右侧是黑底选项条
4. `custom.story_probe ui` → 应显示 `custom` + `custom-ui=active … panel=open`

### 2. 对话能走完

- 点选项 / 按数字键 → 下一句出现；带检定的选项会飘检定提示（掷点 vs 门槛）
- 有些节点没有选项 → 底部出现「继续」或「离开」
- ESC → 面板关闭

### 3. 问题 49 复验（本次改动的核心）

1. 和召唤出来的 NPC 谈完一段对话并离开
2. 看 NPC 是否继续走自己的岗位行为（不是钉在原地）
3. 若仍定身：`custom.story_probe ui vanilla` 切回原版再测一次做对照

### 4. 切回原版

`custom.story_probe ui vanilla` → 下一次对话应是原版面板。

### 5. 数据与结构图仍然一致

- `custom.story_probe dialogue tree` / `resolve <id>` / `trace` —— 与面板走的是同一份 `dialog.json`
- 离线：`python Scripts/check_story_probe.py` → `problems=0`

## 第一轮实机反馈修正（2026-11-19）

### 1. 布局不像原版 → 已改为照抄原版 prefab

原版对话 UI 的**正本在本地文件系统里**，不需要反编译猜：

- `h:\SteamLibrary\steamapps\common\Mount & Blade II Bannerlord\Modules\Native\GUI\Prefabs\Conversation\SPConversation.xml`
- `...\Conversation\ConversationItem.xml`

按它重做后的结构（与本面板一一对应）：

| 原版 | 本面板 |
|---|---|
| 底部 `VerticalContainer` → `BottomPanelsContainer`，MarginBottom 20 | 同 |
| 左：对话框 720 宽，`npc_dialogue_panel_9`，AlphaFactor 0.65，MinHeight 192，文字 `Conversation.ConversedPartyLine.Text` | 同 |
| 右：选项列表 750 宽，按钮 `ConversationItemBrush`，文字 `ConversationItem.Text`，MarginLeft 30 | 同 |
| 名字：`name_shadow_9` + `Conversation.HeaderText`，在对话框上方 | 同 |
| 继续：右下 454×80，`name_shadow_9` + `Conversation.HeaderText` 45 号 | 同 |

原版用 `DimensionSyncWidget` 让名字块高度跟着对话框走；本面板用固定 MarginBottom 252 近似（不引入额外控件类型，少一个失败点）。

### 2. 选项点不动 → 三处处置

- **删掉 `IsEnabled="@IsEnabled"` 绑定**：我们的选项恒可选，不需要它；绑定一旦解析异常会把按钮设成禁用，表现就是「看得见、点不动」。
- **层序 350 → 400**：与已实机验证「Mission 里能用鼠标点按钮」的 IM 面板同档（引擎按 order 从高到低派发输入）。
- **加输入诊断**：每 3 秒一条 `[StoryDialogueUI] diag hit=… focus=… mask=… mouse=(x,y) opts=…`；
  选项点击另有一条 `[StoryDialogueUI] click index=…`。有这条 = UI 收到了点击。

### 3. 对话时右下角交互面板没收起 → 已强制收起

原来是靠「引擎对话中 Raycast 无目标」自然收起的；自建面板不启动引擎会话，那条隐式收起不成立。
现在 `InteractionMissionView` 在对话期间：面板强制隐藏 + 交互键一律不响应。

### 4. 选项顺序反了 → 改回 `VerticalTopToBottom` 且不加 `LWN_` Id

`GUI/StackLayoutVerticalSwapPatch.cs` 只对 **Id 以 LWN 开头**的祖先做反序交换，且只在 1.4+ 编译。
所以正确写法就是**原版自己的写法**：`VerticalTopToBottom` + 不带 LWN Id。带 Id 反而会被补丁换反。
