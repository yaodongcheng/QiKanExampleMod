#### 0.2 🔴 家族侧 —— 新规则（按侍奉关系重做，2026-09-11 用户裁定）

**结论**：家族的唯一定义 = 「谁侍奉谁」。一家 = 一个家头 + 直接侍奉他、且自己不带队的人。**苗字相同 ≠ 同族，血缘 ≠ 同族。**

**规则表**（落地时逐条对应，无例外）：

| # | 情况 | 归谁 | 例（1560 实测） |
|---|---|---|---|
| R1 | **有部下**（有人直接侍奉他） | **自己开一家**（他就是家头） | 北条氏政只是氏康的直臣，但北条氏直侍奉他 → 氏政自立一家 |
| R2 | 没部下、有上司 | 并入**直接上司**的家 | 北条氏直 → 北条氏政家 |
| R3 | 没部下、没上司 | **无家**（浪人 / 无所属） | 石田三成（1560 是浪人） |
| R4 | 妻子 | 并入**丈夫**的家 | 归蝶 → 织田家 |
| R5 | 其他亲人（父/母/祖父/亲戚）**既没上司也没部下** | 并入该人的家 | 武田信虎（隐居无主）→ 武田家 |
| R6 | **势力代表兜底**：某势力该年存在、却没有任何家族挂它 | 取势力表的**代表**（`Owner_<年>`）自立一家，「组织=该势力」的无家者并入他家 | 忍者村/水军：首领是泛用 NPC，势力表已换实名替补（高坂甚内/加藤段藏/海雷丁）→ 部下在 R2 走不到家头，这里兜住 |

**为什么 R1 这么定**：一句话——**谁有人侍奉，谁就是一家之主**；「当主的家 = 自己 + 部下里不带人的那些」，所以带了人的部下自然另立一家。这正是太阁5「城主/国主有自己的家臣团」的形态。

**拆家后果（要接受的事实）**：大名家会拆成 2~6 家。1560 年北条家 → `clan_hojo_1`（氏康）/ `_2`（氏政）/ `_3`（高广）/ `_4`（氏邦）/ `_5`（氏繁）/ `_6`（纲成）。

**六个年代各算一套**（不共用一份）：

| 年代 | 1554 | 1560 | 1568 | 1575 | 1582 | 1598 |
|---|---|---|---|---|---|---|
| 存在的势力（王国） | 96 | 95 | 90 | 82 | 72 | 90 |
| 家族数 | 213 | 195 | 180 | 156 | 126 | 102 |
| 其中无王国的独立家族 | 0 | 0 | 0 | 0 | 0 | 0 |
| 有家英雄 | 857 | 866 | 838 | 786 | 704 | 522 |
| 无家者（浪人/无所属） | 180 | 171 | 199 | 251 | 333 | 515 |
| 妻子并入 / 亲人并入 | 22 / 23 | 23 / 40 | 22 / 68 | 19 / 88 | 18 / 119 | 14 / 162 |

- 理由：六份剧本快照里 **930/1304 人换过所属组织、808 人换过立场**——一套数据套六年代必错。
- 跨六年代合计 **283 个不同家族**（按 id 计；比单年代的 213~102 多，因为人会换家）。1598 家族少 = 大量人物已卒/隐居。
- 家族数与骑砍原版同量级（原版 8 文化约 100 家），274 个据点分摊得住。

**跨年代「同一个家」怎么认**（否则「织田信长 1554-1582 / 织田秀信 1598」会被拆成两个 id）：
家头同一个人 → 同一家；或两个家头是**直系血缘**（父/母链）**且从未在同一年代同时当家头**时合并，
且**按血缘距离从近到远并**（先父子、再祖孙，避免「先到先得」把孙子并到祖父那家）。
⚠️ 北条氏康与北条氏政是父子、但 1554~1582 **同时当家头**（各自有家臣团）→ **不并**，这是规则的正确结果。

**🔴 每个家族都挂进一个王国（实测六年代「无王国」= 0 家）**：
家头的「组织」只要该年存在（= 日志里该组织当年有当主）就当王国；赤松一门这类**国主家**在日志里
本身就是「当主 + 上司=无」→ 它是**自己的一个国**（赤松家 1554-1575 存在），小寺/别所（组织=赤松家）自动挂它下面。
⚠️ 旧稿「这类家落成独立家族（无王国）」**已作废**（用户裁定：国主也是「对大名负责」的一层，不该悬空）。

#### 0.6 🔴 经验（本次踩的坑，别再踩）

1. **拿英雄表的 `Kingdom_<年>` 推"有哪些势力" = 凭空造国**。实测 68 条口径差（赤松/虎屋/秋田/池田…）——英雄表记「当年跟着谁（含同族家名）」，快照记「势力槽」。**势力存在性只看 `TaikouForce.Owner_<年>` 的 `-`**。
2. **对账必须按编号 join，禁按人名**。快照的 `name` 列自己 README 就标了「勿再引用本行作权威」；按名字 join 会把明智光秀、柴田胜家都算成「芦名家」。
3. 🔴 **游戏数据在"过继/改仕"类年代边界上会错，必须查史料**（连踩两次）：上杉景虎被快照放进 1568 上杉家，实际 **1570 元龟元年**才过继；吉见正赖被标 1554 毛利家，实际 **1557** 大内灭亡后才从属。这两格登记进 `KNOWN_DEVIATIONS`——**故意与快照不一致**，白名单防被"对账"改回去。
4. **`CareerStance=首领` 不是"族长"，是"势力代表"**。家臣家族（下间/前波/七里）的成员标 `直臣`，本来就没有独立首领；"家族没有族长"是正常的。
5. **`Identity=大名` 会过度分配**：无主家的城主被标成大名 → 曾导致 9 格势力「多标为存在」（已回退）。**存在性与值要分开处理：只换值、别动标记。**
6. **同名撞车要用「归属集相交」聚类来发现**：内藤/津田/天野/加藤… 实测 65 个家族中招 → 拆出 57 个新家族。⚠️ **归属集为空的成员（女性/隐居/已故，如阿松/武田信虎）要并回最大一组**，否则被误拆。
7. **macron 规范在 `csv/ReadMe.csv` 里**（当年写的 VBA 规则原文）：`ō→oo`（**不是 `ou`**）、`ó→oo`（acute 与 macron 同等）。英雄英文名早就用 `oo`（`Katoo`/`Kyoogoku`/`Motoosa`），`check_englishname_clan_prefix.py` 的规范表也是 `oo`。
8. **生成器脚本别接 `head`**：`... --apply | head -6` 会 SIGPIPE 打断写盘，`--check` 随即报"产物不一致"。
9. **按首列去重要限定表**：对 `BaseInfo.csv` 去重会误删 459 行（它的「内置番号」天然不唯一）。
10. **改数据一律走脚本 + 备份 + 往返校验 + 幂等两跑**——本次靠这套回滚了三次（macron 转错两次、误删行一次），没有在错状态上打补丁。

**家族重建（2026-09-11 下半场续）新踩的六条**：

11. 🔴 **Python 的 `set` 迭代顺序不保证（`PYTHONHASHSEED` 随机化）→ 生成器会「每次跑出不同结果」**。
    症状：`--check` 永远红、三张表互相不一致（实测 `clan_araki_1` 的文化一次 `kinai` 一次 `nankai`）。
    **规矩**：凡 set 参与顺序（遍历、建组、取「第一个」）一律 `sorted(...)`；`Counter.most_common` 的并列要靠 `sorted(key=(-n, 名字))` 定死。**生成器不许有第二次结果不同的可能**。
12. 🔴 **合并类算法要「重验守卫」**：一轮里 A 吃掉 B 之后，A 的家头集合变了，但候选列表是吃掉之前算的 →
    另一条候选可能把「同年并存的两家」并进来（实测 `clan_oda_2` 1575 出现两个家头）。
    **两条防线**：①每轮合并时**重新验证**不变量；②生成器里加**自证断言**（「一家在任一年代只能有一个家头」）——本轮就是这条断言抓出来的。
13. 🔴 **合并/配对要按「距离」排，不能「先到先得」**：先到先得会让孙子并到祖父那家（实测长宗我部盛亲本该并元亲、却先并到了祖父国亲）。改成**按血缘距离从近到远**。
14. **外键映射要带「类型」消歧**：太阁5 的组织名里武家/商家/忍者/海贼会**同名**（`茶屋家` vs `茶屋`），
    只按名字建 `name→id` 会串。**规矩**：多类型同名时按源数据的类型列消歧（势力类型：大名家/商家/忍者众/海贼众）。
15. 🔴 **「组织/势力名」不等于「存在的势力」**：太阁5 的勢力槽每代只有 ~99 个，33 个武家（赤松/松平/池田…）
    六个年代都没有槽位——**引用一张表前先查它的「存在性列」**，否则会造出指向空王国的家族（本轮差点如此）。
16. 🔴 **「快照（decoded）」不能当权威——本轮被它带偏一次**：`era_v2/forces.csv` 有一批槽位的**名字解码失败**（显示成「无」/空），
    我据此得出「赤松没有势力槽」的结论并设计了「独立家族」方案；用户当场纠偏：**只看上级日志**。
    **规矩**：判「谁存在/谁归谁」只认**游戏运行时导出的日志**（上级日志/据点日志）；解码快照只作考古参考，
    且**引用前先查它有没有解码空洞**（空名/「无」占位、「待替换(ID N)」占位都是信号）。
17. **势力首领可能是泛用 NPC → 要一条「实名替补」规则**：忍者村/水军的头目在 DB 里常是 `六郎次`/`道闲`/`仙左卫门`
    这种**不在英雄表**的泛用槽位人。**规矩**：当主不在英雄表 → 从**同组织同年代**的成员里挑实名替补（部下多优先），
    并把「谁替了谁」打进生成报告（本轮 15 格：透波众→高坂甚内、轩猿众→加藤段藏、甲贺众→猿飞佐助…）。
18. **改名/继承类差异要用「最大那年」的形态命名**：同一家历代家头苗字不一（长尾政景→上杉景胜），
    按「第一个家头」命名会得到「长尾家」（而它在游戏里该叫上杉家）。**规矩**：取规模最大的那年的家头，并把这类家**列进报告**供人核。

### 五·补、据点表这一波做了什么（2026-09-11 沉淀）

> 一句话：**名字全部换成「游戏自己说的」，并把三条不变量焊成硬断言。**

**① 名字来源定死为两个（别再发明第三个）**

| 来源 | 用途 | 为什么是它 |
|---|---|---|
| **简体版六份剧本日志**（`Knowledge/太阁5/据点日志/<年>剧本据点.log`） | `Name_<年>` 六个年代名 | **只有它记改名**（户石城→上田城、黑川城→会津若松城）；era_v2 的 `name_official` 永远是开局名 |
| **繁体原版转储**（`太阁5_据点坐标_20260901.md`，同槽号） | 只把**真异字**并进 `Name_All` | 繁体版与简体版对同一据点会用**不同的字**，剧本（事件包）引用的是繁体名 |

- `Name_All` = 该据点**全部称呼**（六年代名 + 繁体真异字别名），`|` 分隔，**第 1 段 = 开局名**（本地化键用它）
- 繁体名进 `Name_All` 前过滤：**两边都过 opencc `t2s` 再比**，相等 = 纯繁简字形（134 条丢弃）、不等 = 真异字（**6 条**：墨股/墨俣、二股/二俣、界/堺、阪本/坂本、安芸/安艺、御著/御着）
  - ⚠️ 必须**双向**归一化：opencc 把 `篠` 转 `筿`，游戏简体写 `篠`，只转一边会把 `長篠城` 误报成真异字
- **`era_v2` 的 `name_history` 整体退役**（它的差异大半是繁体写法，且它自己另有解码错字）

**② 三条不变量（生成器硬断言 + 体检脚本双查，都做过负面测试）**

1. 同一个名字不得属于两个据点（名字 = 身份，重名即匹配歧义）
2. 同一个据点内不得重名
3. 每个 `Name_<年>` 都必须在 `Name_All` 里

**③ 名字必须写全（用户裁定）** —— 「既然是叫之町那就是之町，不然不就和冈崎城混在一起了」
