# 忍术体系 — 设计总纲（法术框架 阶段 5+）

> **状态：待审批**（2026-09-26 立，同日第二版）。**本文只有设计与阶段，不含实施** —— 审批通过前不动代码、不动数据。

## 一、结论

### 1.1 融合命题（这套东西合起来是什么）

**三套参考不是三个并列的功能，是三个时间尺度上的同一件事**：

| 尺度 | 来源 | 玩家在做什么 | 我们的独有加成 |
|---|---|---|---|
| **秒** | 龙之信条 | 蓄力 → 赌注 → 释放；被打断就白费 | 忍者**不在队列里**，位置自己找（掩体 / 侧翼 / **空中**） |
| **战** | 神界原罪 2 | 用地表**改造战场**：切阵型、连锁反应 | 战场是**几百人的规模**，地表要按战场尺度做，不是按小队尺度 |
| **役** | Noita | **装配 → 试验 → 解锁 → 再装配** | 世界**有记忆**：用过的忍术会被 NPC 记住、留下痕迹、成为证据 |

**一句话记住**：**忍术是放大器，不是替代品** —— 它不让你一个人打赢一支军队，它让你**决定这场仗在什么地方、以什么方式打**。

### 1.2 决定表

| # | 决定 | 理由（一句） |
|---|---|---|
| 1 | **四段框架一行不改** —— 新东西全加在四段**之上或之外** | 三条契约（瞄准产意图表 / 投送有生命周期 / 结算只认单次命中）当初就是为今天留的口子；改四段 = 把已验收的 6 条法术全部拖回重测 |
| 2 | **Noita 的「修正」= 对法术数据的一组增量**，解算成「有效定义」再走原管线 | 修正本质就是"改数值"，而我们的法术数据本来就是一张数值表 —— **组合不预设、全由解算得出**（"玩家自创法术"的基础） |
| 3 | 🔴 **修正不止挂投射物 —— 挂到四段的任意一段** | Noita 的修正只有"投射物"一个目标；我们的四段是四个挂点，**包括"落地留什么地表"**（Noita 没有、DOS2 独有）—— 这才是三套真正咬合的地方 |
| 4 | **承载 = 施法手环 + 宝石槽**（法印升级成手环，每槽一颗宝石；宝石按"挂哪一段"分四类） | 玩家裁定（2026-09-26）：修正靠装配获得，配装即玩法 |
| 5 | **代价 = 自建查克拉条**（上限挂在已有忍术技能等级上） | 引擎没有耐力条（已核实）；忍术技能 0~4 的数据链**已经在跑**，天然是上限来源 |
| 6 | **元素立成一等数据**（五行：火水风雷土），挂在法术 / 状态 / 地表 / 修正四处 | 地表与反应、五遁、元素修正，三者共用同一个轴；没有这层，三个功能各造一套 |
| 7 | **招式表 = 太阁5 忍术卡**（20+ 张，名字与本地化键都在库里）+ 少量火影/凡人彩蛋 | 零新造词，与世界观同源；**忍术技能等级天然是学习门槛**（294 人有值、17 人满级） |
| 8 | 🔴 **地表按战场尺度做**：条形（火墙可切阵型）+ 同类合并 + 总量上限 | 小队尺度的 4 米火圈在几百人战场里等于不存在（见 §2.2 碰撞 2） |
| 9 | 🔴 **打断分级**：轻击掉一档、硬直才全断 | 百人战场里"一击全废"会让玩家不敢用长咏唱（见 §2.2 碰撞 1） |
| 10 | **首期只做投射物修正机制**（用户裁定） | 唯一"不依赖任何其他层、且直接决定玩法深度"的一块 |

### 1.3 代价（一次说清）

| 代价 | 说明 |
|---|---|
| **四段里要补一次接口** | 起手轴现在是硬编码在两个类里的 if/else（玩家 `SpellCastInput` / NPC `SpellNpcCaster`）。要加"结印""蓄力档位"这类新起手方式，必须先把它补成「接口 + 注册表」—— **只做一次**的整理，不是返工 |
| **顺带一笔欠账** | 11 个内建法术族里**只有 4 个能用**，后 7 个引用了没注册的实现，用它们的法术会被**加载期静默跳过**（阶段 11 补齐） |
| **两处要新增存档** | 查克拉（角色数值）与手环配装（"哪颗宝石插在哪个槽"）—— 骑砍的物品**没有实例状态**，配装只能记在角色身上（方案见 §7.4） |
| **地表多两条性能纪律** | 同类合并 + 总量上限 + 每拍检查限量 —— 千人对千人战场上，几十片地表各算各的会拖垮帧率 |
| **资产工作量在后期** | 忍术实体（分身 / 替身 / 隐术）与施法动作是**内容工作**，本文只定路线，不承诺工期 |

## 二、融合：三种玩法怎么咬合

### 2.1 三个尺度怎么串起来

```
战役层（Noita 的环）   在忍者里配装：选基础术 + 插宝石 → 决定这次带什么
        ↓ 出击
战场层（DOS2 的环）    你带的术在战场上生成地表 → 地表改变敌人的行动 → 敌人反制
        ↓ 每一次施法
动作层（DD 的环）      长咏唱 → 找位置 → 赌注 → 被打断就白费 → 放出去改写战场
        ↓ 战果
战役层（世界会记得）    痕迹 / 目击者 / 记忆 → 影响下一次
```

**读法**：这三个环**互为因果**，不是三个独立系统 —— 配装决定你能造什么地表，地表决定你要站哪里、赌多久，战果又回来改变你的配装。

### 2.2 四场碰撞（天真照抄会死在哪）

| # | 撞上什么 | 天真照抄的结果 | 我们的答案 |
|---|---|---|---|
| **1** | **长咏唱 × 百人战场** | 4 秒站桩 → 挨箭、被骑兵冲 → **没人敢用** | ① **忍者不站队列**：位置自己找（掩体 / 侧翼 / 屋顶 / **空中**）② **打断分级**：轻击掉一档、硬直才全断 ③ 🔴 **前摇换射程**：前摇越长，作用距离与范围越大 —— **赌要有明确回报**，而不是"又慢又一样" |
| **2** | **小地表 × 大战场** | 4 米火圈在几百人里等于不存在 | ① **战场级尺寸**：火墙 = 几十米长的一条，**能切断阵型** ② **地表形状要有"条"**（不只是圆） ③ **同类相邻合并** + 总量上限 ④ **AI 反应分两层**：物理层白送（伤害 + 减速让阵型自然散开）；**主动避让只有我们的 NPC 能做**（挂在自家 `AgentBrain` 上，原版 AI 不会避火） |
| **3** | **无限组合 × 持久战役** | 地上随便捡宝石 → 战力崩坏、原版平衡失效 | ① **获取有门槛**（忍者里库存 / 战利品 / 师匠）② **装配有上限**（槽位 = 手环品质 + 忍术等级）③ **代价有梯度**（修正越猛查克拉越贵）④ **不做随机性**（Noita 赌运气的部分不搬） |
| **4** | **法术实体 × 千人同屏** | 几十个龙卷风乱走 → 卡、看不懂、隐形杀手 | ① **实体预算**（沿用并发上限）② **可读性铁律**：一个实体必须**一眼看懂**是什么元素、会不会动 ③ **不做隐形杀手**：看不见的范围伤害一律不要 |

### 2.3 修正挂四段 —— 我们比 Noita 多的地方

Noita 的修正只有"投射物"一个目标。我们的四段正好是**四个挂点**：

| 挂哪段 | 宝石举例 | 它改变什么 |
|---|---|---|
| **起手** | 缩短前摇 / 瞬发化 / 连放两次 / 静默施法（无声无光） | 什么时候放、以什么代价放 |
| **瞄准** | 多发 / 锁定数 +N / 目标之间跳（链） | 打谁、打几个 |
| **投送** | 追踪 / 弹跳 / 钻地 / 分裂 / **触发器** / 定时器 / 加速 | 怎么过去 |
| **结算** | 伤害 / 贯穿 / 附加状态 / 🔴 **留地表** / 范围扩大 | 到了之后发生什么 |

🔴 **"留地表"这条修正是三套参考真正的咬合点**：Noita 有材质但没有组合式地表系统，DOS2 有地表但不能装配。**我们的宝石可以把火球变成"先铺油、再点燃"**，也可以让水弹带电 —— **地表从此是可装配的**。

🔴 **触发器让组合爆炸**：命中时释放另一个术 → 玩家能配出"火球命中后原地放水弹"这类链条。**这才是"自创法术"的实际形态**（不是把已有法术改个数值）。

### 2.4 一局的形状（战场上到底在干嘛）

一场战斗的五个节拍 —— 每一拍都用到上面某一套：

| # | 节拍 | 用到什么 |
|---|---|---|
| 1 | **接敌前**：你不在阵中 —— 用隐术贴近侧翼，或升空占高度 | 位置 = 忍者的第一资源 |
| 2 | **开局**：敌方骑兵正在冲锋 → 你在冲锋路线上横一道**火墙** → 骑兵踩进去**受伤 + 减速** → **冲锋被打散** | 神界原罪的地表 + 骑砍玩家一眼就懂的价值 |
| 3 | **中局**：敌方法师浇水灭火 → 你补一发**雷** → 水面带电 → 半队人麻痹 | 元素反应（水 + 雷） |
| 4 | **危机**：弓手盯上你，咏唱到一半被击中 → **掉一档**（不是全废）→ 你用**空蟬之術**脱身 | 龙之信条的赌注 + 打断分级 |
| 5 | **收尾**：残兵溃散，**亂苦無**（多发 + 追踪宝石）清场 | Noita 的组合 |

### 2.5 战役的形状（装配环怎么转）

| 环 | 内容 |
|---|---|
| **宝石从哪来** | 忍者里的库存（用钱 / 功绩换）· 任务战利品 · 师匠传授 |
| **忍术技能怎么涨** | 对应原作修行（用而涨 / 师匠处修行）；它同时是**查克拉上限**与**学习门槛** |
| **为什么要选配装** | 查克拉有限 + 槽位有限 ⇒ **出击前必须做取舍** —— 这就是 Noita 的"改魔杖"落到我们身上的形态 |
| **在哪装配** | 战役层的"忍者里"或自宅（界面排在阶段 10，阶段 5 先用控制台验机制） |

### 2.6 有意不抄的（三个参照各自的"毒"）

| 参照 | 它的毒 | 为什么不能搬 |
|---|---|---|
| 龙之信条 | 法术同步（多人同唱一术更强）· 随从拉住仇恨 | 骑砍没有小队施法编队，也不该引入仇恨系统（会跟原版 AI 打架） |
| 神界原罪 2 | 回合制与行动点 · 地表按"等级"覆盖 | 骑砍是实时；地表的"等级"改成**尺寸与时长叠加**（大覆盖小、久覆盖短）更符合战场直觉 |
| Noita | 随机获得 + 死亡重置 · 魔杖内法术顺序 / 回绕 / 施法块 · 液体物理模拟 | 持久战役不能把战力交给运气；不做顺序机制（槽位全作用于同一个术，更好懂）；引擎不做流体，我们的地表是**贴地表现 + 逻辑**，不是真液体 |
| **通用** | **法术无双**（一个人靠法术打赢一支军队）· **隐形杀手**（看不见的范围伤害 / 无法反应的秒杀） | 忍术是放大器不是替代品；看不见的伤害 = 出戏（设计哲学①反馈明确） |

## 三、我们独有的三件事（三个参照都没有）

### 3.1 立体施法（飞行）—— 三个参照都没有的维度

- **现状**：玩家飞行与"飞行中施法"**已落地**（右键蓄力、左键放、方向取相机）。
- **融合价值**：龙之信条的法师**必须站地上**；我们能**从空中往下铺地表**（火雨、油雨），也能躲开近战 —— 这是"长咏唱"在百人战场里能活下来的**位置手段**中最强的一种（碰撞 1 的答案之一）。
- **要注意**：飞行中施法目前是"不要求装备法印"的特殊路径 + 有独立瞄准机位 ⇒ 加档位与瞄准 UI 时**这两条路要一起改**，别只改地面那条。

### 3.2 世界会记得 —— 我们真正的护城河

三个参照里，Noita 没有目击者、神界原罪没有犯罪系统、龙之信条没有持久世界。**我们两样都有**（目击者系统 + NPC 记忆 + 战役层后果）：

| 忍术 | 世界层的后果 |
|---|---|
| **隐术 / 暗杀** | 没有目击者 ⇒ **犯罪系统不触发**（隐身 = 消掉证据链，不只是画面效果） |
| **火遁** | 烧过的地面留下**焦痕**（地表表现层跨场景留存）⇒ 成为**证据**，NPC 能指认 |
| **变身 / 伪装** | 改变身份 ⇒ 混进敌方据点（与既有乔装 / 潜入机制接） |
| **任何忍术** | NPC 的 LLM 记忆会记住"那个用黑炎的忍者" ⇒ 名声与情报在世界上传播 |

🔴 **这是设计方向，不是本期承诺**：它依赖隐术（阶段 11）与战役层地表存档（阶段 12）。但它决定了这套系统的**上限** —— 忍术不只是打赢一场仗，是**改变世界状态的手段**。

### 3.3 NPC 平权：战场两侧都有忍者

- 铁律 18 要求玩家能做的 NPC 也能做 —— 敌人 NPC 忍者会**同样地**蓄力、铺地表、打断你（`SpellNpcCaster` 已落地）。
- ⇒ 战场上会出现**互相点地表**的局面：你放火，对方浇水；双方都在抢战场的地面控制权。
- AI 用**带权随机**选法术（已有）；**不会连发**、**施法期间照常走位**（已有纪律）。

## 四、总架构：四段之上加三层

```
        ┌─ 装配层（新）────────────────────────────┐
        │  基础术（一条 SpellDef）× 修正宝石（N 条）  │
        │        ↓ 解算                             │
        │  有效定义（还是同一个 SpellDef 类型）        │
        └───────────────────┬──────────────────────┘
                            ↓
   四段（已有，一行不改）：起手 → 瞄准 → 投送 → 结算
                            ↑
        ┌───────────────────┴──────────────────────┐
        │  世界层（新）：元素 · 状态 · 地表 · 反应     │  ← 结算轴往这里写
        └──────────────────────────────────────────┘
        ┌──────────────────────────────────────────┐
        │  表现层（新）：蓄力前摇 · 瞄准 UI · 查克拉条 │  ← 起手轴在这里长出来
        └──────────────────────────────────────────┘
```

**读法**：三条新线**没有一条需要改四段的实现**。装配层产出"还是那个 `SpellDef`"；世界层是结算轴多几个实现；表现层是起手轴的实现与外挂 HUD。

## 五、首期：投射物修正机制（Noita）

### 5.1 核心公式

> **有效法术 = 基础术 ⊕ 修正₁ ⊕ 修正₂ ⊕ … ⊕ 修正ₙ**

- **基础术** = 现在 `Spells.xml` 里的一行。
- **修正** = 新表里的一行：**改哪个字段、怎么改、改多少**（加 / 乘 / 覆盖 / 追加）。
- **解算** = 纯数据运算，结果**仍是同一个 `SpellDef`** ⇒ 后面四段一行不用改。
- 🔴 **组合不预设**：任何基础术 × 任何一组宝石都是合法组合，效果**算出来**、不查表 —— 这是"玩家自创法术"能成立的前提。

### 5.2 宝石按「挂哪一段」分四类（§2.3）

这不只是分类好看：**它是装配界面的组织方式**，也是玩家理解系统的入口 —— 打开手环，一眼看出"我这条术缺起手、缺投送，结算已经很猛了"。

### 5.3 数据：`Modifiers.xml`（内容包 `ModuleData/AssetRegistry/`）

| 类 | 字段（示例） | 说明 |
|---|---|---|
| **身份** | `id` / `name` / `icon` / `desc` / **`stage`（起手/瞄准/投送/结算）** | 名字走本地化（铁律 13） |
| **数值改动** | 目标字段 + 运算 + 值（`damage ×1.5` / `pierce +2` / `turn_rate = 120`） | **一张通用表**：写清"改哪个字段、怎么改、改多少"，不给每颗宝石写一段代码 |
| **行为开关** | `on_hit_cast` / `on_timer_cast` / `bounce` / `drill` / `split` / `leave_surface` | 触发需要新能力的那些（§5.5） |
| **代价** | `chakra_cost_add` | 修正越猛越贵（碰撞 3 的第 ③ 条） |

### 5.4 承载：施法手环 + 宝石槽

- **法印升级为「施法手环」** —— 现有物品 `taikou_spell_seal` 就是它，不改名、不改用途，只加"槽位"概念。
- **槽位数量** = 手环品质 + 忍术等级；**装几颗 = 能叠几层修正**。
- **宝石 = 物品**：背包里有的宝石才能装（解锁凭证），但**"哪颗装在哪个槽"不在物品上**。

🔴 **技术要点：骑砍的物品没有"实例状态"**（背包里只有"某物品 × 个数"，没有"这一把附了魔"）。三个方案，**建议取甲**：

| 方案 | 怎么存 | 代价 |
|---|---|---|
| **甲（建议）** | **配装存在角色身上**（一组"槽位 → 修正 id"），走存档机制；宝石物品是解锁凭证 | 要写存档条目（本项目已有成熟的存档三件套） |
| 乙 | 每套配装 = 一个手环物品定义 | 零存档，但组合一多就是**定义爆炸** |
| 丙 | 宝石放在物品栏，施法时扫背包 | 零存档，但玩家无法表达"我要装 3 颗中的这 2 颗" |

### 5.5 行为型修正 —— 要给四段开的口子（五条）

| 修正 | 要什么能力 | 怎么落 |
|---|---|---|
| **弹跳** | 撞到地形时**反射速度**而不是结束 | `ProjectileDelivery` 撞地形分支改（按命中法线反射，次数用光再结束） |
| **钻地** | 命中过滤**只撞人不撞地** | 同一分支：地形命中忽略（飞行距离仍算） |
| **触发器** | 命中时**在原地释放另一个法术** | 投送持有"子法术"，命中那一刻派一条新意图（复用既有 `SpellCastFlow` 入口，天然支持套娃，但**要限深**） |
| **定时器** | 飞行 N 秒后**在原地释放另一个法术** | 同上，触发条件换成计时 |
| **分裂** | 飞一段后**分成 N 发** | 投送派 N 条新意图（与"多发"同一机制，只是延迟到中途） |

### 5.6 第一批修正清单（按"要不要新代码"分组）

**A 组 · 纯数据（零新代码）**
伤害强化 · 强化暴击 · 加速 · 加重 / 失重 · 变大 / 变小 · 延长寿命 · 扩大作用半径 · **多发**（瞄准轴已支持）· **缩短前摇**（起手段）

**B 组 · 已有实现，只是以前填死在法术上（填数据即可）**
追踪（`turn_rate`）· 贯穿（`pierce`）· 天降（`start_height`）· 锁定数（`lock_max`）

**C 组 · 需要投送轴新能力（§5.5 那五条）**
弹跳 · 钻地 · 触发器 · 定时器 · 分裂

**D 组 · 等后面的层**
元素转换（阶段 7）· 附加状态（阶段 7）· **留地表**（阶段 8 —— 三套咬合的关键那颗宝石）

### 5.7 首期验收（看到什么算过）

| # | 看到什么算过 |
|---|---|
| 1 | **同一个基础术**（阴魔斩）装不同宝石 → 行为**明显不同**（三发追踪 / 一发贯穿三个 / 撞墙弹两下 / 命中炸出第二个术） |
| 2 | **四段框架的实现一行没改**（判据同阶段 2：加完新东西，旧 6 条法术行为零变化） |

| 4 | 连打 50 发（含多发与触发器**套娃**）后**实体数不涨**、帧率无肉眼可见下降 |

## 七、元素与状态（DOS2 的地基）

### 7.1 元素 = 一等数据（`Elements.xml`）

- **五行**：火 / 水 / 风 / 雷 / 土（五遁正好是这五个）；按需可加毒 / 阴 / 阳（给彩蛋法术）。
- 一行一元素：`id` / 显示名 / 颜色 / 图标 / **默认状态** / **默认地表**。
- **元素挂四处**：法术 · 状态 · 地表 · 修正（元素转换）。
- 🔴 **没有这一层，地表 / 反应 / 五遁 / 元素修正会各造一套**。

### 7.2 状态 = 数据表，不是代码分支（`Statuses.xml`）

一行一状态：`id` / 时长 / 每跳效果 / 移速乘子 / 能否行动 / 能否施法 / AI 修正 / 粒子 / 叠层规则 / 免疫标签。

| 状态 | 怎么落 | 引擎能力 |
|---|---|---|
| 燃烧 / 中毒（持续掉血） | 已有的持续伤害状态扩展成读表 | 已有（`SpellStatusManager` 现在只做这一种，且不读表） |
| **减速** | API 直给 | ✅ 已核实：`Agent.SetMaximumSpeedLimit(倍率, isMultiplier: true)`；清掉传 `(-1, false)` |
| **冻结 / 定身** | 冻结配方照抄飞行那套 | ✅ 已实机验证：`Controller = AI` + `SetIsAIPaused(true)` |
| 麻痹 / 致盲 / 沉默 | 用"能否行动 / 能否施法"这类开关表达 | 需要新写，但形态是**读表判定**，不是每状态一段代码 |
| 🔴 引擎**没有**"角色着火" | 燃烧 / 中毒 / 冻伤**全部自己实现** | 已核实：全客户端搜 `Burning` 只有 `WeaponFlags.Burning`（那是弹药属性） |

### 7.3 现状要改的（一句话）

`SpellStatusManager` 现在**只做伤害型持续伤害、不读表、无叠层、无免疫、不存档** —— 阶段 7 把它扩成**读表的状态机**。加"冻伤" = 加一行数据，代码不动。

## 八、地表与元素反应（DOS2）

### 8.1 三块东西

| 块 | 是什么 | 挂在哪 |
|---|---|---|
| **地表** | 世界上一片"会持续施加状态"的区域 | **投送轴扩展**（`place` 已实现雏形）+ 新建**世界地表登记处** |
| **扩散** | 半径随时间长大；火沿油面蔓延、水顺地形流 | 地表字段（`spread_*`） |
| **反应** | 两张地表相遇 → 查表 → 出结果 | **一张数据表 + 一个查表函数**（全新的一层） |

### 8.2 关键设计点（现在就定，免得返工）

1. **地表 = 会施加状态的一片区域**，不是"另一种伤害" —— 伤害只是状态的一种效果。
2. 🔴 **形状要有"条"**（不只是圆）：火墙是**几十米长的一条**，这是它在战场上"切断阵型"的前提（碰撞 2）。
3. **反应是数据**：`(元素A, 元素B) → 结果` 一行一条。首批：油+火=爆燃 / 水+火=蒸汽 / 水+雷=导电水面 / 冰+火=化水 / 毒+火=爆燃。
4. 🔴 **同类相邻地表合并** + **总量上限**：千人对千人的战场上，几十片火各算各的会拖垮帧率（碰撞 2）。
5. **地表强度用"尺寸 + 时长"叠加**，不用 DOS2 的等级制（更容易读懂：大覆盖小、久覆盖短）。
6. **角色身上也会反应**：湿身 + 冰冻 = 冻结，湿身 + 雷 = 麻痹（角色级反应表，与地表表分开）。
7. **表现三层叠着用**（[法术体系 §13.5](法术体系-通用施法框架.md) 已定）：**贴花**（底：焦痕 / 水渍）+ **贴地平片网格**（面：流动的火）+ **粒子**（细节：火星；"烧过留痕"零代码）。
8. 🔴 **逻辑与表现分离**：登记处**只存纯数据**；圈内谁在，用 `Mission.GetNearbyAgents` 粗筛（**一次原生调用**）、按间隔节流、两两相遇限量检查。**贵不贵取决于怎么写逻辑，不取决于用不用网格。**
9. 🔴 **存档是前提不是收尾**：战场内地表可以只活一场；**要做战役层地表（据点留火、焦痕成证据）就必须同期做存档**（§3.2 的世界记忆依赖它）。

### 8.3 验收

| # | 看到什么算过 |
|---|---|
| 1 | 火地表烧人；人走出去停烧 |
| 2 | **一道火墙能切断一队冲锋的骑兵**（受伤 + 减速 ⇒ 阵型散开） |
| 3 | 油面上放火 → **火沿油面自己蔓延开** |
| 4 | 水面上打雷 → 水面带电，站进去的人麻痹 |
| 5 | 火碰上水 → 变蒸汽、火灭（地表被消耗） |
| 6 | **四段框架与首期的修正机制一行没改** |

## 十二、风险与未验证项

| # | 风险 | 影响 | 应对 |
|---|---|---|---|
| 1 | **宝石槽没有原生容器**（物品无实例状态） | 配装方案选错 = 定义爆炸或自由度打折 | §5.4 取甲方案；实施前先做一次最小存档验证 |
| 2 | **触发器套娃失控** | 命中释放的术再带触发器 → 无限套娃 | 解算时**限深**（如最多 3 层）+ 并发上限 |
| 3 | **修正把开销放大** | 多发 × 修正 = 检查次数成倍 | 沿用纪律：0.05 秒节流 + 并发上限 + 容器复用；阶段 5 末重估 |
| 4 | **起手轴接口化会碰已验收的相位机** | 蓄力 / 引导 / 飞行手势可能被碰坏 | 补接口 = "把已有分支搬进实现"，行为不变；改完把地面手势与飞行手势各回归一次 |
| 5 | 🔴 **骑乘单位能不能被减速**（未验证） | 火墙挡骑兵（§2.4 节拍 2）是整套设计的关键演示 | `SetMaximumSpeedLimit` 对**骑马的 agent** 是否生效**未验证**；实施前一次实测定性，不行就改走"马匹受惊 / 强制下马"另一条路 |
| 6 | **原版 AI 不会避让地表** | 火墙可能拦不住敌方大部队（只有伤害与减速起作用） | 接受"物理层散开"的效果；主动避让只对我方 NPC 做（挂自家 `AgentBrain`） |
| 7 | **地表的性能与存档** | 战役层地表漏存档 = 读档后"地上的火没了" | 同类合并 + 总量上限；做战役层地表必须同期做存档 |
| 8 | **查克拉会改变原版战斗平衡** | 玩家变强 = 原版难度失效 | 只服务忍术、不影响原版武器；上限与消耗都是数据，可调 |
| 9 | **7 个未实现的族仍在被误用** | 数据写错 = 法术被静默跳过 | 阶段 11 补齐；在那之前**把"静默跳过"改成打日志告警** |
| 10 | **忍术实体是内容工作**（分身 / 假体 / 隐身） | 工期不可控 | 阶段 11 单列；能抄的照抄外部 mod 的开通链路 |

## 十三、与现有工程接线（铁律对照）

| 铁律 / 规矩 | 本设计怎么落 |
|---|---|
| **三单元架构** | 逻辑进 LWN（`Combat/`，不新开目录）；元素 / 状态 / 地表 / 反应 / 修正 / 招式 = **数据进内容包** `ModuleData/AssetRegistry/`（既有目录） |
| **四段框架** | **一行不改** —— 装配层产出"还是那个 `SpellDef`"，世界层是结算轴加实现，表现层是起手轴加实现 |
| **铁律 18 玩家/NPC 平权** | 查克拉、状态、地表、修正**对 NPC 同口径**；入口仍是 `SpellCastFlow.Cast(施法者, 法术, 起点, 方向)` |
| **铁律 13 / 20 本地化与 StringId** | 预制招式与宝石走 `LWNTextHelper` + `{=LWN_*}`；**数据表一律 StringId**；🔴 **玩家自创的法术名是玩家输入**（与 IM 聊天同类，不进语言表） |
| **铁律 22 生成物禁手改** | `Card.csv` 加"技能归属"走**改生成器重跑** |
| **铁律 5 禁止硬编码资源 ID** | 宝石 / 手环 / 网格 / 粒子一律走数据表 + 两轮查找 |
| **铁律 34 模块加载取证** | 排查"法术 / 资产为什么没生效"一律先读日志 `Command Args:` |
| **设计哲学四原则** | ①反馈明确：蓄力环 / 落点圈 / 可读的元素颜色 ②自由感：装配组合 ③任何 NPC 接得住：平权 ④信息塑造目标：地表与反应给出"下一步做什么"的线索 |
| **存档** | 查克拉 + 手环配装是新增角色级数值 ⇒ 走既有 `SaveableTypeDefiner` 三件套，并同步补新档清理（`ResetAll`） |
| **既有轮子（一律复用）** | `SpellCastFlow`（施法入口）· `SpellWorld`（引擎触点门面）· `SpellMath` / `SpellSweep` / `SpellAim`（公共件）· `AgentDamageHelper.CastBlow`（伤害）· `AgentHudMissionView`（世界→屏幕投影）· 粒子管线 · `SpringArmCameraView`（演出机位）· 目击者系统（阶段 12） |
