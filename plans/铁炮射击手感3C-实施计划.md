# 铁炮射击手感（3C）— 实施计划

> **状态：实施中**（2026-09-19 起）。🔴 **阶段 1 已完成** —— 铁炮装填已换成自制动画（实机通过），风险 R1 消解。本轮坑点、配方、TODO 全在 **§〇**。
> **目标**：把铁炮的举枪 / 瞄准 / 开火做成《荒野大镖客 2》**单发步枪**的手感。
> **三条基准**（用户裁定）：① 手感对标 **单发步枪**（一枪极重、装填漫长）② **不做 Dead Eye**，只做手感 3C ③ **自制举枪 + 装填全套动画**。
> **前置**：[太阁火器与移动大筒-实施计划.md](太阁火器与移动大筒-实施计划.md)（阶段 1+2 已落地，待实机验证）。本计划 = 它的**阶段 4**，不重复它做过的事。

> **两个词先说清楚**：
> · **3C** = 角色（Character）、相机（Camera）、操作（Control）—— 射击手感的三个组成部分。
> · **越肩** = 相机挪到角色肩膀后方（而不是吊在头顶），枪口指向看得更清楚，RDR2 瞄准时就是这个视角。

| # | 症状 | 根因 | 解法 |

| 1 | 动画导进去人趴地上、四肢乱折 | trf 写的是"相对静止姿势的**增量**"，引擎要的是**绝对局部变换** | 旋转写 `rest ∘ delta`；见 [Knowledge/骨骼动画TRF格式与增量陷阱.md](../../Knowledge/骨骼动画TRF格式与增量陷阱.md) |

## 一、结论速览

**决定：分四步做，三步是纯代码（我能独立完成），一步是动画（必须你在 ModKit 操作）。**

| 步 | 做什么 | 谁做 | 卡不卡 |
|---|---|---|---|
| **A** | 越肩瞄准相机 + 举枪变焦 | 我 | 不卡 |
| **B** | 后坐 + 命中反馈 + 枪口烟 | 我 | 不卡 |
| **C** | 精度模型 + 节奏参数表 | 我 | 不卡 |
| **D** | 四条自制动画（举枪 / 摇摆 / 装填 / 后坐） | 🔴 **你** | 卡你 |

**一句话**：RDR2 单发步枪的手感就是四件事 —— **举枪慢、身体有摇摆、一枪极重、装填漫长**。

**凭什么说能做**：这四件事里三件在骑砍里有现成旋钮（下表右列全部有反编译实证）。**唯一没有旋钮的是"装填漫长"** —— 引擎的装填时长直接等于动画时长，所以它只能靠第 D 步的动画解决。**这正是你必须自制动画的原因，动画在这条路上是骨干不是装饰。**

### 1.1 一个必须先知道的工程事实：越肩相机和引擎准星是二选一

引擎的准星显示条件里有一条 `!IsMissionScreenUsingCustomCamera()`（反编译实证）。意思是：

> **一旦我们接管相机（设 `MissionScreen.CustomCamera`），引擎自带的准星就会消失。**

所以第 A 步有两条路，代价差别很大：

| | 做法 | 准星 | 观感上限 | 风险 |
|---|---|---|---|---|
| **轻方案** | 不接管相机，每帧只 `Mission.SetCameraFrame(...)` 微调位置 + `CombatCamera.SetFovVertical(...)` 收视野 | ✅ **保留** | 中（能变焦，越肩幅度受限） | 低，可随时撤 |
| **重方案** | 接管 `CustomCamera`（复用已有的 `SpringArmCameraView`） | ❌ **消失，得自绘准星** | 高（完全自由，能抖动） | 中，要配套一套准星 HUD |

**建议：先做轻方案。** 理由：准星是射击手感的地基，能不弄丢就不弄丢；轻方案验证不了再上重方案，届时自绘准星的活本来也躲不掉。**这一步要不要走到重方案，等轻方案实机效果说话。**

## 二、RDR2 单发步枪手感 → 骑砍旋钮 对照表

每一行右列都有引擎反编译实证（2026-09-18）。

| RDR2 的手感元素 | 骑砍里对应的旋钮 | 性质 |
|---|---|---|
| 举枪慢（有明显抬枪过程） | 自制举枪动画的长度 + `blendInPeriod`；速度倍率可调 `native_parameters.xml` 的 `ready_speed_multiplier` | 动画 + 数据 |
| 举枪时相机拉近、视野收窄 | `AgentStatCalculateModel.GetMaxCameraZoom`（**虚方法，可重写**）+ `CombatCamera.SetFovVertical` 每帧覆写 | ✅ 纯代码 |
| 越肩视角 | **原版没有** → 自建（`SpringArmCameraView` 已有越肩模板 `2m_Self_Shoulder_Mid_R`） | 纯代码，见 §1.1 |
| 武器摇摆（呼吸起伏） | 自制摇摆循环动画；或每帧扰动相机 | 动画 或 纯代码 |
| 屏息稳住 | 新输入键 → 暂停摇摆 + 视野再收一点 | 纯代码 |
| 准星随状态收缩/扩散 | **引擎已有**：准星尺寸 = `74 + 精度误差 × 300` 像素，误差由引擎实时算 | ✅ 改系数即可 |
| 开火后坐（枪口上跳 + 镜头震） | 🔴 **引擎无此 API**（全 DLL 无 `Shake`）→ 每帧读-改-写相机帧自己造 | 纯代码（自造） |
| 单发 + 漫长装填 | **装填时长 = 动画时长**（`MBActionSet.GetActionAnimationDuration`）→ 做一条长动画 | 🔴 动画 |
| 命中标记（准星闪一下） | **引擎已有**：`CrosshairVM.ShowHitMarker(是否致命, 是否爆头)`，引擎自动触发 | ✅ 白送* |
| 枪声 / 枪口烟 | 枪声已有（三档）；烟待补（契约字段留空，填名字即生效） | 数据 + 少量代码 |
| 子弹会下坠 | 引擎已有火器专用空气阻力参数 `AirFrictionBullet` | ✅ 数据 |

\* 命中标记在"轻方案"下白送；若走重方案接管相机，引擎准星连同命中标记一起消失，要自绘。

## 三、分步实施

### 步骤 A：越肩瞄准相机 + 举枪变焦（3C 的 Camera）

**做什么**：玩家举枪（按住左键）时，相机切到越肩位、视野从 65° 收到约 45°；松手立刻还原。

**怎么触发**：读引擎现成的公开属性 —— `MissionMainAgentController.IsPlayerAiming`。
> 大白话：引擎自己就有一个"玩家正在瞄准吗"的开关，不用我们重新判断。它的判定是「手里是远程武器 **且** 按住左键 **且** 有攻击方向标志」。

**用到的现成东西**：
- `Camera/SpringArmCameraView.cs` —— 已写好的弹簧臂相机，有 `SetFovVertical` 和越肩机位模板
- `Core/VersionCompat.cs` —— 版本差异走这里，不裸写 `#if`

**三个要注意的**：
1. 🔴 **`SpringArmCameraView.targetAgent` 是 `public static`** —— 已经被剧本演出系统用着。两边同时写会互相覆盖 → **必须加互斥**（演出占着相机时，瞄准不接管）。
2. 🔴 **轻方案下不能碰 `CustomCamera`**，否则准星消失（§1.1）。
3. `IsPlayerAiming` 的判定含"手里是远程武器" —— 铁炮是 `WeaponClass.Crossbow`，天然满足。

**归属**：新增 `Camera/AimCameraView.cs`（`Camera/` 目录已存在），挂进 `Core/MySubModule.cs`。

---

### 步骤 B：后坐 + 命中反馈 + 枪口烟（3C 的 Control）

**做什么**：开火瞬间镜头向上顶一下再回落；命中时准星给反馈；枪口喷烟。

**怎么触发**：复用已有的 `FirearmFxLogic.OnAgentShootMissile`（开火回调已通）—— **在同一个回调里加后坐**，不新开一条监听。

| 项 | 做法 |
|---|---|
| **后坐** | 🔴 引擎没有震动 API → 自己每帧读-改-写相机帧：开火瞬间叠一个向上的俯仰偏移，再按曲线衰减回零 |
| **命中标记** | 轻方案下引擎自动给；**验证一下**（引擎的触发条件是"我打的 + 不是友伤 + 伤害>0"） |
| **枪口烟** | `FirearmFx.xml` 的 `particle` 字段现在留空 —— **填上名字即生效，代码不用动**（这是上一阶段就设计好的） |
| **枪声** | 已完成，无需改动 |

**要补的资产**：一个枪口爆发型粒子。原版全是环境型（持续烟柱），没有枪口型的 → 要么借织丰的（需 tpaccli + 编辑器重导），要么自制。

**归属**：`Combat/FirearmFxLogic.cs` 增加后坐逻辑；粒子资产在 Taikou 侧。

### 步骤 C：精度模型 + 节奏参数（手感的地基）

**这一步不改观感，改的是"打不打得中"和"举枪快不快"。不做这步，前面两步只是好看。**

**为什么必须做**：反编译实证 —— 引擎给弓弩算精度时，对**火器类（`Pistol`/`Musket`/`Cartridge`）直接跳过**（`CustomBattleAgentStatCalculateModel.UpdateAgentStats` 的 `else` 分支不给他们赋值）。所以现在的铁炮**没有精度模型**，散布行为是未定义的。

| # | 做什么 | 在哪 |
|---|---|---|
| 1 | 重写 `AgentStatCalculateModel`，给火器类补 7 个精度字段（移动惩罚 / 不稳惩罚 / 最佳稳定等待时间 / 不稳起止时间 / 旋转惩罚…） | LWN 新增 `Combat/FirearmStatCalculateModel.cs` |
| 2 | 覆写 `GetMaxCameraZoom` —— 给铁炮一个比弩大的变焦倍率 | 同上 |
| 3 | 填 `Taikou/ModuleData/native_parameters.xml`（**现在是空模板**）：举枪速度 `ready_speed_multiplier`、释放速度 `release_speed_multiplier`、瞄准旋转速度 `ranged_attack_rotation_base_speed_multiplier`、完美瞄准所需时间 `additional_time_for_perfect_ranged_ready` | Taikou 数据 |
| 4 | 微调铁炮物品数值（`accuracy` / `thrust_speed` / `speed_rating` / `missile_speed`） | `Taikou/ModuleData/taikou_items/firearms.xml` |

**⚠️ 这一步和第 D 步有耦合**：第 3 项的四个参数是"举枪多快"的总开关，但**举枪动画换了之后手感基准会变**，所以这四个数应该在动画落地之后再定稿。**先填一版能跑的，D 步做完回来复调。**

**归属**：代码进 LWN `Combat/`；参数进 Taikou（内容包 = 纯数据）。

### 步骤 D：四条自制动画（🔴 需要你操作 ModKit）

**这是唯一必须你亲手做的环节，也是周期最不可控的一环。**

| # | 动画 | 作用 | 备注 |
|---|---|---|---|
| 1 | **举枪**（进入瞄准） | 决定"举枪慢"的观感 | 长度即节奏 |
| 2 | **摇摆**（瞄准循环） | 决定"端不稳"的观感 | 循环动作，**零净位移** |
| 3 | **装填** | 🔴 **决定装填时长** | 引擎事实：装填时长 = 动画时长。想要 8 秒空窗就做 8 秒动画 |
| 4 | **后坐**（开火后枪口上跳） | 决定"一枪极重"的观感 | 可与 1 合并成带变体的组 |

**流程**：Blender 做动画 → ModKit 建 Animation Clip（GUI，无脚本路径）→ Publish 到 tpac → 我接线。

**接线方式**：走 `action_types.xml` + `action_sets.xml` + `project.mbproj`（Taikou 这两个文件现在是空占位，正好填），**播放走 C# `Agent.SetActionChannel`**。

> 🔴 **为什么不用 `item_usage_sets.xml` 挂动作**：上一阶段实机踩实 —— 内容包**不能**用自定义 `item_usage`，会 `AccessViolationException` 崩游戏（那个文件只由 Native 模块加载）。详见 [太阁火器与移动大筒-实施计划.md](太阁火器与移动大筒-实施计划.md) §12.3⑤。

**🔴 本计划最大的技术风险在这里**：不碰 `item_usage` 意味着引擎自己的弩动作（举弩 / 拉弦）**照样会播**，我们的自定义动作必须**盖住**它。可行的手段是提高动作优先级（`priority`）+ 每帧重设通道，但**"盖不盖得住"没有实证**（见 §五 R1）。**建议第 D 步开工前先做一个最小验证**：只做一条 2 秒的占位动画，验证它能不能稳定盖住弩的举枪动作。**这一条不通，四条动画都白做。**

> ✅ **2026-09-19 更新：这一整段已作废** —— 实测内容包注册的 `item_usage_sets.xml` **会被引擎读取**，
> 所以装填动作由数据层直接决定，**不存在"盖不住"的问题**。详见 **§〇**。

## 四、验收

每一步做完都要能实机看到/听到，验不过不进下一步。
