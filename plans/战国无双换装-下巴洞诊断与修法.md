## 一、结论（三条，都已实测，不再有争议）

| # | 事实 | 谁验的 |
|---|---|---|
| 1 | **头件单独看，下巴下面有个能透背景的洞**（ModKit 截图实锤：白块 = 看穿头部） | **用户截图**（决定性） |
| 2 | **头+甲拼装后没有可见的洞**——那圈脖/领几何**在甲资产里**（逐顶点比对：宁宁 41 个段内顶点 33 个精确命中 0.0000；余 8 个被混合权重挪 1~2cm，不是被删） | `_srcinprod.py` / `_hole_scan.py` |

🔴 **两条不冲突的原因**：1 量的是**头件自己**，2 量的是**头+甲拼装**。
**谁也不能拿"拼装没洞"去否认"头件有洞"**——用户在 ModKit 里打开的就是头件。争论到此为止。

**判定：用户的诉求成立且为正解** —— **头件必须自洽**（下巴下面不能透背景），
手段 = 把那圈脖/领几何**抠进头**（就是「脖子归头」该干的事，见 §三）。

## 二、验收硬标准（本轮定死，任何判据不得凌驾）

| 判据 | 口径 | 判什么 |
|---|---|---|
| **★终判** | **头件单独渲染 + 洋红背板**，取用户截图同角度（正前偏下，下巴进画面）→ **下巴正下方不得露洋红** | 头件自洽 |
| ② | `_hole_scan.py`（头+甲拼装 + 洋红背板） | 拼装后不穿模、不露洞 |
| ③ | `_srcinprod.py`（逐顶点一对一） | 几何到底在哪个资产里（**不依赖刚体假设**） |
| ④ | `check_assembly.py`（拼装闸门） | 领口那圈覆盖没覆盖（改完 `neck_args` **必须复跑**，防把领口/肩片吃进头） |
| **⑤ 新增几何的空间约束**（2026-09-20 加，防再犯） | 搬进头的顶点**必须全部**落在 `r ≤ 0.09 m`（离颈轴）、`z ∈ [1.40, 1.58]` 的柱子里 | **越界 = 不合格**。这一次的"脖子旁怪皮肤"就是越界：把斜方肌/肩（`\|x\|` 到 0.145、z 到 1.57）抠进了头 |
| **⑥ 量化尺**（2026-09-20 加，批量复验不靠肉眼） | `_chin_ray.py`：在「下颌正下方」柱体（`r ≤ 0.10`、`z ∈ [1.42,1.56]`）里撒采样点，从 **低正面 35° / 仰视 53° / 正下方 79°** 三个角度打射线，逐点跟**原版头**比 | 数字 = 「原版有几何、我们没有」的占比。**目标：三机位最差 ≤ 5%**（原版头基准 = **0%**） |

**工具位置**：都在 `Debug/offline/外观批量导入/` ——
`_chin_ray.py`（⑥ 量化尺）/ `_chin_tex.py`（带贴图、从下往上渲，肉眼终判用）/ `_chin_mark.py`（把缺的那块画成红点）/ `_hole_scan.py`（头+甲拼装 + 洋红背板）/ `_srcinprod.py`（逐顶点一对一）。

## 三、修法

### 🔴 主修（2026-09-20 更正）：**逐顶点区域裁剪**（不是"放宽 neck_args"）
- **"调宽 `neck_args`"这条路已实测证伪**：`neck_args` 是**整块连通域**判据，而战无2 的**脖子皮常与斜方肌/肩连成同一块**
  → 放宽 `r_max` 才能抠到它，但**顺带把肩那片一起拖进头**。实测宁宁：`r_max` 0.10 → 0.15 抠到 107 顶点，
  编辑器里脖子旁多出一圈**怪皮肤**，而**下颌底下的洞依旧**（抠到的位置在脖子根 z 1.46~1.57，压根不在下颌底下）。**已回退。**
- **正解 = `skin_region`（逐顶点裁剪）**：`parts_table` 那一行写
  `skin_region=dict(r=0.09, z0=1.40, z1=1.58, skin=True)` —— 只取「那根柱子里的皮肤顶点」，
  **天然不会越界**（= 验收⑤）。现成先例：稻姬（`skin_region` 修项链 V 里的胸口皮）、小太郎（领口那块布）。
  甲侧由 `build_armors.py` 用**同一份参数**剔掉同一批源顶点（头拿多少、甲正好少多少）。
- **`neck_args` 仍然有用**：只用在「脖子皮是**独立碎片**」的角色上（半藏 / 稻姬 / 左近 / 兰丸 那批的既有覆写不动）。

### 备选（不推荐单独用）：甲侧白名单去掉 `bone_10`
`build_armor.py` 的 `HEAD_SW`（头骨族白名单）= `bone_10/11 + 46~62`，而 **`bone_10` 是颈骨**。
→ 甲保留绑 `bone_10` 的碎片：洞没了，但**那圈仍在甲里** ⇒ **换装照样露**。只能当辅修。

### 🔴 三条必须知道的坑（2026-09-20 实测）
1. **甲侧 `--drop-coincident` 会删过头**：与新头去重时，它把甲**领口那圈**删了 96 顶点 → 前领口开了 **5cm** 的口，
   比修之前更糟。宁宁这轮**关掉去重**重建的甲。⇒ 要开去重必须先量「删完之后领口还剩不剩」。
2. **`build_heads.py` 的件数解析 bug**（已修）：表情段的件数原来读 `[OK] N 件（face,mouth,eye,neck）` ——
   那是**请求件位**，抠不到脖子时照样写 4 而实际只有 3 件 → `表情源 4 ≠ 目标 3` **FATAL**，
   **整个头重建失败**（宁宁复现）。已改成数 build_head 落位段的**逐件映射行**（` face  -> head_x.0 `）。
3. **有 3 个人源模型里没有脖子皮**：**家康 / 忠胜 / 长政**（高领/兜盖住，抠脖子**一个候选都没有**）。
   ⇒ 甲乙两条修法对他们**都无效**，只能**人工补一圈脖子管**（下颌壳下沿 → 领口线放样），或接受现状。

## 四、留档：第一版错在哪（防再犯）

| 错法 | 机理 |
|---|---|
| 「三角形**边长**指纹」当"面是否存在"的判据 | 边长只对**刚体**免疫；甲管线**保留美术原始蒙皮权重**（`build_armor.py:9`「wᵢ = 顶点原有的蒙皮权重，美术做的，原样保留」）→ 混合权重顶点是**多骨平均、非刚体** → 边长变 → **误报"真洞"**。旁证：`build_armor.py:45-46`「权重混合把两个旋转**平均**出来 → 一块**刚性甲片被弯进去**」 |
| 「面心最近距离（4/10/20mm）」 | 容差一变数字大变（642→301→87）= 把"被挪位"当"被删" |
| 按"挑件表归属"判"有没有救" | 归属 ≠ 资产里真有（甲管线自己也会剔碎片） |

⇒ **结论：凡"刚体不变量"类判据在甲/兜的混合权重区域一律不可用。**
`_face_provenance.py` / `_chin_audit_all.py` / `_region_audit.py` 降级为"只看趋势，不得作结论"。

## 五、执行顺序

```
① 拿 1 个人跑通闭环（建议【兼续】：洞小但肉眼可见，最省时）
   调 skin_region（§三 主修）→ build_heads.py --only <键> → build_armors.py --only <键> --force
   （⚠️ 甲那一步先**别开** --drop-coincident，见 §三 坑 1）
   → ★头件单独渲图（同角度+洋红背板）：「下巴正下方不露洋红」
   → _chin_ray.py 三机位 ≤5% → 验收⑤ 越界检查 → _hole_scan.py 拼装复验 → check_assembly.py 复跑
② 闭环通了 → 按「位置会露」排序批量推（**不是按面数**；面数≠可见度：
   兼续 8 面肉眼可见，訚千代 4 面藏在领子里）
③ 🔴 **6 个 fullhead（颅骨版）必须同步修**：秀吉 / 家康 / 兼续 / 谦信 / 忠胜 / 长政
   实机用的是 `AssetSources\head\<名>\fullhead\..._skull.*`，走的是**另一条产线**
   （`_skull_graft.py` → 搬通道 → 出贴图）。**只修基线头 = 白修。**
④ 全量复验：28 人头件单独渲图全过 + `_chin_ray.py` + `check_assembly.py` + 材质闸门
⑤ 投递：`_deliver.py`（产物 → `AssetSources\sw2\` → 镜像布局，带 md5 清单 + 时间戳守卫）
   ⚠️ 投递**必须在 ModKit 开着时**做（铁律 31：编辑器是文件监视）
```
