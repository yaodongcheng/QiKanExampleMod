## 三、本轮新查到的四个事实（它们改变了做法）

### 事实 1：一个 FBX 可以编译出多个网格（本次用不上，但记下来）

官方文档（`Knowledge/bannerlord_official_docs/Asset Management/Asset Types/asset_naming_conventions.md`）：

> All meshes imported from a single geometry file(e.g. fbx) are **grouped by their names**.

编辑器不是「一个 FBX 一个网格」，是按**名字前缀**分组的。
**本次已拍板仍走「一人一个 FBX」**（见第五节），所以这条只作记录——将来要一次导 50 个脸时它值一次导入。

### 事实 2：源模型的零件**全是无名编号** —— 现有工具的关键字/序号挑件完全失效

实测 28 个源 FBX（`Debug/offline/sw2_survey/sw2_survey.json`），零件名一律长这样：

```
model_0_submesh_6_noesis_meshnode_0006
```

没有 `head` / `eye` / `mouth` 这种字。而 `build_head.py` 的挑件靠关键字（`--pick face=head,...`）、`build_armor.py` 的选件靠**子网格序号**（`--parts body_kimono_arms`）——
**两个都不通用**：信长那次是人工看出「submesh_6 是脸」，幸村那次是人工看出「2/4/7/8/9 是甲」。
28 个模型 × 平均 13 块零件，人工认件不可行。

**⇒ 必须先造零件识别工具**（见阶段 0）。

### 事实 3：三个可程序判定的地标

| 地标 | 命中率 | 用途 |
|---|---|---|
| **眼球 = 38 顶点 / 60 面** | **27/28**（只有宫本武藏例外，他是 19v/30f 两块） | 定「眼」件，顺带定头的位置与朝向 |
| **武器件 = 材质名带 `mat_w_`** | 28/28 | 排除武器（盔甲工程已实证此法） |
| **每个模型都自带骨架**（96~142 骨） | 28/28 | 甲的重定向有绑定可用；头用不着 |

另外：**28 个模型都没有形变键**——59 条脸形通道全部要靠 `transfer_channels.py` 从蒂法那份移植过去（与萨菲罗斯同一条路）。

### 事实 4：编辑器里手配的材质**可以完全不打**

`skinfix --fullmat` 是**按材质名**（名字里含不含 mouth/eye/lash）在**发布后的包**上刷配方的，涵盖：
`VertexLayoutFlags`（含 `skinning`）、四角色 shader、`MaterialFlags`（脸/嘴/眼/睫标记）、纹理槽复制。
**⇒ 只要材质名规范（脸=裸名、其余加 `_eye`/`_mouth` 后缀，CLAUDE.md 铁律 27），编辑器里就不用逐个勾。**

唯一还没打通的一环：**材质挂哪张贴图**（`tex[0]`）——这一步现在靠编辑器里手挂。计划里给一条补丁命令补上（见阶段 2 的「材质接线」）。

### 事实 5：源模型的「一个对象」里住着**语义不同的几样东西**——取件要按骨骼分组

**先纠正一个容易走错的判断**：源模型的零件**全是碎片云**（实测：秀吉某件 736 顶点 = 66 个连通域、
归蝶某件 1241 顶点 = 86 个连通域）。PS2 时代的模型不焊顶点 —— 所以**「按连通域拆分」这条走不通**。

**真正的现象**是：一块件里混着语义不同的几样东西（逐件单独渲染实测）：

| 角色 | 件 | 里面混了什么 |
|---|---|---|
| 杂贺孙市 | 8 | 头发 **+ 长外套** |
| 武田信玄 | 10 | 红发 **+ 腰间红披** |
| 伊达政宗 | 7 | 身甲 **+ 大月牙前立** |
| 归蝶 | 6 | 身体 **+ 发髻** |
| 服部半藏 | 10 | 脸 **+ 布头罩** |
| 丰臣秀吉 | 0 | 甲 **+ 兜 + 日轮冠** |

**为什么必须处理**：换头/换甲是**整块拿走**的。整块拿 → 头发里会拖着一件外套飞到头上去。

**做法：按「碎片的主导骨骼」分组，只留目标那一组。**
碎片虽多，但每片绑在哪根骨头上是明确的——头发那几十片全绑头骨，外套那几十片绑脊柱/手臂。
判据沿用已有的那三条（主导骨骼 / 包围盒高度 / 主色），**不用新造**。

**⇒ 新增一个拆分工具**：输入源模型 + 目标（脸/头发/甲），输出「只剩目标那组碎片」的网格。

## 四、四阶段计划

### 阶段 0 —— 零件识别工具（本阶段是全部工作的前提，先做）

**要造的东西**：`identify_parts.py` —— 输入一个源 FBX，输出每块零件的「身份判定 + 依据」。

**判定依据**（三条并用，不靠肉眼）：

| 依据 | 怎么算 | 认出什么 |
|---|---|---|
| **顶点位置** | 世界坐标包围盒 + 顶点云重心 | 头（最高的那一簇）、脚、躯干 |
| **骨骼归属** | 逐顶点组的骨名 → 该件主导骨 | 脸/眼 → `head` 骨；腿 → `thigh/calf`；手 → `hand` |
| **贴图颜色** | UV 采样图集 → 主色聚类 | 肤色（脸/手）、甲色、金属色 |

**产出**：
1. 每人的一份**零件表**（CSV）：`序号, 顶点数, 材质, 主导骨, 包围盒, 主色, 判定身份, 置信度`
2. 每人的一张**接触图**（contact sheet）：每块零件单显渲染一格，带编号 —— **给人肉眼复核用**（机器判定 + 人抽查，不靠肉眼从零认）

**判据**：28 张接触图上，头和甲的零件都标对；错的人在表里手工写一行覆盖（覆盖表进 git，脚本读它）。

### ~~阶段 1 —— 修一次男头领口~~ ❌ **取消**（2026-09-14 用户裁定：以信长/幸村为先例）

**为什么取消**：原计划是照**萨菲罗斯**那套（`--fit-rim` 硬收领口 → 领口破碎 → 要照 `build_neck.py` 重铺）。
但**萨菲罗斯不是战无2 的模型**——那几条（`--fit-rim` 收领口、`--weld-seam` 合缝、`--weights-from` 抄权重）
全是给他一个人的毛病打的补丁。

**信长那版的实际构建日志**（`work/out/build_head_L02.txt`，战无2 同类源模型）：

```
  收领口：收进 4 个顶点（最大收进 16.8mm）      ← 对比萨菲罗斯：118 个顶点 / 最大 6.2cm
  没有 weld-seam，没有 weights-from
  全头包围盒 x[-0.1321,0.1302] z[1.4644,1.9502]
```

**⇒ 战无2 的头只沾 4 个顶点、1.7cm，根本不是萨菲罗斯那种领口破碎。这条不成立，删掉。**

**⇒ 本轮的模板一律取**：
- **头 → 织田信长**（`--parts face,eye,mouth` + `--pick-idx` + `--cut-mouth` + `--fit-rim`，**不加** weld-seam / weights-from）
- **甲 → 真田幸村**（`build_armor_chain.py --parts body_kimono_arms --kimono-torso-only --no-hands --r 0.0120 --r-arms 0.0160`）
- **贴图 → 信长那版**（单张图集当三张 diffuse + `_n`/`_s` 纯色，见 `make_sw2_textures.py`）

**复现验证**（2026-09-14）：信长的头用全自动流程重跑 → face **818** 面（手工 816）、eye 60、mouth 140（手工 142）、
收领口 **4 顶点 / 16.8mm**（与手工日志相同）、包围盒**逐位相同**。

### 阶段 2 —— 批量出 27 张脸

**先补一个缺口：源模型没有「嘴」件，要自动切。**

`build_head.py` 的标定需要「嘴」件（用眼↔嘴的竖直距离算缩放），而战无2 的源模型**只有脸/眼/发**，
嘴是**从脸壳上切下来的一块**——信长当年是**手工切的**（`|x|≤3.2, z∈[170.6,174.4], y<0` → 142 面），
脚本里没有这一步。27 张脸不能手工切。

**补法**：给 `build_head.py` 加 `--cut-mouth`——按几何自动切唇周：
- 嘴中心估计 = 眼球中心往下 `0.20 × 脸壳高度`（实测信长：眼 179.3、嘴 172.5、脸高 34.1 → 6.8/34.1 = 0.20）
- 切盒 = `|x| ≤ 0.25×脸宽`、`z ∈ 嘴中心 ± 0.06×脸高`、`y` 取前半
- 切出来的面独立成件（`<名>.N`），与脸/眼一起走后面的标定
- **判据**：切完渲染一张脸，嘴的位置对得上（离线看，不用开游戏）

**每人一条命令**（新增一个批量驱动，把配方固化，照 `build_head_chain.py` 的样子）：

```
① build_head.py            源模型 → 头部 FBX（4 件或 3 件，按性别）
② transfer_channels.py     59 条形变通道移植
③ make_head_textures.py    源图集 → 5 张贴图（_d/_n/_s/_eye_d/_mouth_d）
④ fbx_probe.py             关卡 1：USF=100 / UpAxis=2 / 节点零变换
⑤ （不做合集 FBX —— 已拍板走「一人一个」）
⑥ 人：ModKit 导入 → Publish      ← 人工步骤，**每人一次**（27 次）
⑦ install_pack.py          两道补丁 + 关卡 2 + 装机（每张脸一次 --filter，脚本循环）
⑧ [补] 材质接线            把 tex[0]/[2]/[4] 指到我们的贴图上（新增 tpaccli 命令）
```

**接线（XML 侧）**：
- `Taikou\ModuleData\skins.xml` 每个头加一个 `<race id="lwn_<名>">`（生成器 `Scripts/gen_taikou_*.py` 出，禁手改）
- `taikou_lords*.xml` 对应行加 `race="lwn_<名>"`（生成器里的 `SPECIAL_RACE` 表加一行）

**判据**：进游戏，28 个领主各长各的脸；随便找个路人领主 —— 脸不变（隔离成功）。

### 阶段 3 —— 批量出 27 套甲

同一个零件识别工具输出「甲件清单」→ 走现成的 `build_armor_chain.py`：

```
① build_armor.py      选件 → Y 轴镜像 → 骨架重定向 → 6 级 LOD 0..5
② build_textures.py   裁图集 + 生成 _n/_s + 重映射 UV
③ fbx_probe.py        关卡 1
④ 人：ModKit 导入 → 材质勾 Bumpmap+Skinning → Publish
⑤ Item XML：taikou_items\body_armors.xml 加一件（id/mesh/属性）
⑥ EquipmentRoster：把甲挂到对应武将身上
```

**已知欠账（第一件就挂着，第二件顺手做掉）**：上臂中段露身体 —— 需要一段程序生成的布袖（绕上臂骨的筒，权重给 `upperarm_twist_15`）。做在 `build_armor.py` 里，之后所有甲都受益。

**判据**：28 个领主穿自己的甲，走路/战斗不穿模、不撕扯。

### 阶段 3.5 —— 批量出 27 件武器（2026-09-14 用户追加）

**为什么要做**：Taikou 现在**一件日式武器都没有**——28 个领主拿的全是原版欧洲剑
（实测统计：`short_sword_t3` 343 次 / `cleaver_sword_t3` 155 次 / `pugio` 136 次 / `ridged_sabre_sword_t4` 130 次 / 圆盾 287 次）。
织丰有整套日式武器（`sho_katana_1..31` 等），但**铁则 6 规定 Taikou 与织丰零依赖**，不能引它的 id。

**做法**：战无2 每个源模型**自带该角色的武器**（零件识别工具已按材质名 `mat_w_` 标出），
像幸村甲那样把它做成资产 → 挂到物品上。

| 比甲便宜的地方 | 说明 |
|---|---|
| 不用蒙皮 | 武器是刚体，直接跟手骨走 |
| 不用 6 级 LOD | 原版武器 LOD 少，先做一个 LOD 也能跑 |
| 不用后处理补丁 | 无 morph、无脸部标记 |

**流程**：零件识别工具挑出武器件 → 导出（朝向/尺度对标原版武器）→ 贴图 → 编辑器 Publish → Item XML。

**判据**：28 个领主手里拿的是自己的武器，不是欧洲剑。
