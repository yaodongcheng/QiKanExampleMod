# 移动模式补充 —— 给铁炮换一套持枪走跑

> **状态：待实施**（2026-09-19 立）
> **一句话**：让拿着铁炮的角色站着 / 走 / 跑 / 转身时用我们自己的动画。需要 **10 条自制 clip + 6 处 XML 改动**，**零 C#**。
> **这是什么**：[铁炮射击手感3C-实施计划.md](铁炮射击手感3C-实施计划.md) 的补充。那份管**一次性动作**（举枪 / 摇摆 / 装填 / 后坐），这份管**循环动作**（站着不动 / 走 / 跑 / 转身）。

> **三个词先说清楚**：
> · **移动集** = 一张「18 个槽位 → 动作名」的表，告诉引擎「往这个方向走的时候播哪条动画」。
> · **整套移动组** = 把「走 / 跑 / 蹲走 / 蹲跑」四档各指到一个移动集。
> · **追加层** = 叠在走路动画上的躯干修正，**不属于本次要改的东西**（见 §五）。

---

## 〇、结论速览

| 问题 | 答案 |
|---|---|
| 能新增一种移动模式吗 | ❌ **不能**。人形只有 4 个模式（走 / 跑 / 蹲走 / 蹲跑），名字写死在引擎里，数据层加不了第 5 个 |
| 那这次做什么 | **给这 4 个档换外观** —— 模式不变，每个模式指向我们的新动作 |
| 要提供多少条 clip | **一个档 = 10 条**（1 idle + 9 方向）。最小可用 = 只做「走」这一档 |
| 要改几处 XML | **6 处** = 2 个新文件 + 3 处追加 + 1 处改行 |
| 要不要写 C# | ❌ **零代码** |
| 影响谁 | **所有拿着铁炮的角色**（玩家 + 全部铁炮足轻）。数据层做不到「只影响玩家一个人」 |
| 怎么回退 | 一行：`item_usage_sets.xml` 里改回 `crossbow` |

**跟装填的关系**：装填（`reload_action`）已经走通过这条数据链，本次是同一个机制的另一种用法。装填踩过的坑（新 id 零交集、逐字抄原版、mbproj 必须挂 soln 行）**条条适用**。

## 一、引擎的边界

**人形只有 4 个运动模式，且不可扩展。**

- 模式名字（`walking` / `running` / `crouch_walking` / `crouch_running`）在 native 二进制里就是这四个字面量，C# 侧只能读（`Agent.WalkMode` / `Agent.CrouchMode`）。
- 数据层能做的只有一件事：**告诉引擎「这个模式下播哪条动画」**。
- 所以「加一种移动模式」的真实含义 = **加一套移动集**。走路还是走路，只是长得不一样了。

**走 / 跑 / 蹲 由谁切**：引擎的两把开关（`EventControlFlag.Walk/Run/Crouch/Stand`），玩家或 AI 拨；另有 `monsters.xml` 里的速度阈值 `walking_speed_limit="1.8"` / `crouch_walking_speed_limit="1.3"`。**两者的配合关系未验证**（见 §七）。

## 三、要提供哪些 clip

### 3.1 一个移动集 = 18 个槽，一个都不能少

原版 103 条移动集**逐条数过，全部是满的 18 槽**（外加一个 id）。

| 类别 | 槽 | 要不要自制 |
|---|---|---|
| 静止 | `idle` | ✅ 要 |
| 9 个方向 | `forward` `backward` `left` `right` `left_back` `right_back` `left_to_right` `right_to_left` `rotate` | ✅ 要 |
| 8 个追加层 | `forward_adder` `backward_adder` `left_adder` `right_adder` `left_back_adder` `right_back_adder` `left_to_right_adder` `right_to_left_adder` | ❌ **照抄原版动作名** |

**→ 一个档 = 10 条自制 clip。**

> **追加层为什么不用做**：它们不分武器 —— 原版所有移动集共用同一条（如 `act_walk_forward_adder`），不存在 `_crossbow` 变体。槽里填原版名字即可。
>
> **18 个槽一个都不能省**：原版 103/103 全满。省了会怎样没验证过，别赌。

### 3.2 四档怎么分配

| 模式 | 建议 | 不做就指向 |
|---|---|---|
| `walking` | ✅ **做这一档** | — |
| `running` | 可选 | `run_crossbow` |
| `crouch_walking` | 不做 | `crouch_walk_crossbow` |
| `crouch_running` | 不做 | `crouch_run_crossbow` |
| `swimming` / `diving` | ❌ 不做 | `swim_unarmed` / `dive_unarmed`（原版弩用的也是 unarmed） |

**所以最小可用 = 10 条 clip**（只做「走」档，其余四档指向原版）。四档全做 = 40 条。

`left_stance`（左撇子）**不需要做**：铁炮的用法组带 `has_single_stance="true"`，只有 `False` 一份。

### 3.3 每条 clip 建的时候照抄谁

| 我们的槽 | 照抄的原版 clip |
|---|---|
| `idle` | `troop_stand_crossbow_1` |
| `forward` / `backward` / `left` / `right` | `walk_forward_crossbow` / `walk_backward_crossbow` / `walk_left_crossbow` / `walk_right_crossbow` |
| `left_back` / `right_back` | `walk_left_back_crossbow` / `walk_right_back_crossbow` |
| `left_to_right` / `right_to_left` | `walk_left_to_right_crossbow` / `walk_right_to_left_crossbow` |
| `rotate` | `turn_crossbow` |

⚠️ **动作名和 clip 名经常不同名** —— `act_idle_crossbow_1` 指向的 clip 叫 `troop_stand_crossbow_1`。**别按名字猜，照抄前先在 `action_sets.xml` 里查一遍。**

**为什么要抄元数据**：clip 的 `Blend in period` / `Blend out period` 决定「从站着到走」怎么混过去；`Bipedal movement and ik` 那一组决定脚步落地时机。**裸导 = 这两样都是空的 → 硬切 + 脚打滑。**（装填那颗雷的同款成因。）

### 3.4 减到多少算安全

| 做法 | 结果 |
|---|---|
| 只换 1~5 个方向槽，其余照抄 | ⚠️ 能跑，但**风格割裂**（前走是我们的、斜走是原版的）。**只适合验管线，不适合出货** |
| 换齐一个档的 10 条 | ✅ 出货标准 |
| 8 个追加层槽 | 永远照抄，不用自制 |

## 四、XML 配置（6 步）

全部落在 `Modules/Taikou/ModuleData/`。

### 1️⃣ 新增 `movement_sets.xml`

```xml
<movement_sets>
	<movement_set
		id="taikou_gun_walk"
		idle="act_gun_walk_idle"
		forward="act_gun_walk_forward"
		backward="act_gun_walk_backward"
		right="act_gun_walk_right"
		right_back="act_gun_walk_right_back"
		left="act_gun_walk_left"
		left_back="act_gun_walk_left_back"
		left_to_right="act_gun_walk_left_to_right"
		right_to_left="act_gun_walk_right_to_left"
		rotate="act_gun_turn"
		forward_adder="act_walk_forward_adder"
		backward_adder="act_walk_backward_adder"
		right_adder="act_walk_right_adder"
		right_back_adder="act_walk_right_back_adder"
		left_adder="act_walk_left_adder"
		left_back_adder="act_walk_left_back_adder"
		left_to_right_adder="act_walk_left_to_right_adder"
		right_to_left_adder="act_walk_right_to_left_adder" />
</movement_sets>
```

🔴 **id 必须全新。** 这张表**没有同名合并**（引擎原样直送 native），撞 id = 09-08 那次崩的形态。带 `taikou_` / `lwn_` 前缀最稳。

### 2️⃣ 新增 `full_movement_sets.xml`

```xml
<full_movement_sets>
	<full_movement_set id="taikou_gun">
		<movement_set id="taikou_gun_walk"      left_stance="False" movement_mode="walking" />
		<movement_set id="run_crossbow"         left_stance="False" movement_mode="running" />
		<movement_set id="crouch_walk_crossbow" left_stance="False" movement_mode="crouch_walking" />
		<movement_set id="crouch_run_crossbow"  left_stance="False" movement_mode="crouch_running" />
		<movement_set id="swim_unarmed"         left_stance="False" movement_mode="swimming" />
		<movement_set id="dive_unarmed"         left_stance="False" movement_mode="diving" />
	</full_movement_set>
</full_movement_sets>
```

> 这张表**引擎有同名合并**（同 id 的子节点并进第一个），用新 id 仍是纪律 —— 往原版 `crossbow` 里塞第二个 `walking`，谁生效是未定义的。
> 档位**可以缺**（原版 25 个里有 4 个缺档），但缺档时引擎怎么表现**没验证**，所以本次把六档填满、不做的指向原版。

### 3️⃣ `action_types.xml` 追加 10 行 —— 🔴 **两种声明方式不一样**

```xml
<action_types>
	<!-- 9 个方向 + 转身：裸声明，不带任何属性 -->
	<action name="act_gun_walk_forward" />
	<action name="act_gun_walk_backward" />
	<action name="act_gun_walk_left" />
	<action name="act_gun_walk_right" />
	<action name="act_gun_walk_left_back" />
	<action name="act_gun_walk_right_back" />
	<action name="act_gun_walk_left_to_right" />
	<action name="act_gun_walk_right_to_left" />
	<action name="act_gun_turn" />
	<!-- idle（移动集里的静止槽）：同样是裸声明 -->
	<action name="act_gun_walk_idle" />
</action_types>
```

**规则（原版数据实证）**：

| 动作种类 | 声明方式 | 实证 |
|---|---|---|
| 走 / 跑 / 转身（含移动集里的 `idle` 槽） | **裸声明** `<action name="X" />` | 590 / 590 条全裸 |
| 追加层 | **裸声明** | 41 / 41 条全裸 |
| **武器待机**（用法组的 `<idles>`，如 `act_idle_crossbow_1`） | 🔴 **必须带 `type="actt_idle"`** | 73 条里 71 条带 |
| 装填 | 带 `type="actt_reload"` + `action_stage` | 见 3C 计划 §〇 |

> ⚠️ **两个 idle 不是一回事**：移动集的 `idle` 槽指向 `act_walk_idle_crossbow` 这类（裸声明）；用法组的 `<idles>` 指向 `act_idle_crossbow_1`（带 `actt_idle`）。**本次只动前者**；后者要改就是 §六 的扩展项。

### 4️⃣ `action_sets.xml` 追加绑定

```xml
<action_set id="as_human_warrior" skeleton="human_skeleton" movement_system="bipedal">
	<action type="act_gun_walk_forward" animation="gun_walk_forward" />
	<!-- …其余 9 条同样式… -->
</action_set>
```

现有文件已经有 `act_gun_reload` 的绑定，**追加**即可。引擎按 id 把我们的块并进 Native 的同名块，原版几千条动作不会被挤掉。

🔴 `animation=` 填的是 **clip 名**，不是 FBX take 名、不是骨架动画名。写错 = 静默解析成 `act_none`，**没有任何报错**，只是播不出来。

### 5️⃣ `project.mbproj` 挂 2 行

```xml
<file id="soln_movement_sets"      name="ModuleData/movement_sets.xml"      type="movement_set"/>
<file id="soln_full_movement_sets" name="ModuleData/full_movement_sets.xml" type="full_movement_set"/>
```

**不挂这两行 = 两个文件从不解析。** id 名照抄 Native 的 mbproj（第 41 / 42 行）。

### 6️⃣ `item_usage_sets.xml` 改 1 行

```xml
<movement_sets>
	<movement_set id="taikou_gun" />     <!-- 原为 id="crossbow" -->
</movement_sets>
```

🔴 这里的 `<movement_set id="...">` 指的是**整套移动组**（`full_movement_set` 的 id），不是移动集 —— 原版 19 处引用全是这么对的（19/19 命中 `full_movement_set`，0 命中 `movement_sets`）。名字反直觉，别搞错。

**回退 = 这一行改回 `crossbow`。**

## 五、追加层（不用动，但得知道它是什么）

原版 `monsters.xml` 里 human 有这么一组：

```
move_adder_bone_0="spine"    move_adder_bone_4="r_clavicle"
move_adder_bone_1="spine1"   move_adder_bone_5="neck"
move_adder_bone_2="spine2"   move_adder_bone_6="head"
move_adder_bone_3="l_clavicle"
```

**7 根骨，正好等于引擎常量 `MoveAdderBoneMaxCount = 7`**，且全是脊柱链 + 锁骨 + 头颈。

→ 追加层是**只作用在脊柱链上的叠加动画**：基础走路动画驱动全身，追加层在上面加躯干修正。它们**不分武器**（只有 `act_walk_forward_adder`，没有 `_crossbow` 变体），所以本次直接沿用原版。

⚠️ 上面这句「脊柱叠加层」是基于骨表和「无武器变体」两条实证的**推断**，不是直接读到的实现。

## 六、四条纪律

1. **影响所有拿铁炮的角色** —— 玩家 + 全部铁炮足轻，跟装填一样。**只想改玩家一个人 → 数据层做不到**，得走运行时换整套动作集（LWN 侧代码），代价见 §八。
2. **女性角色大概率用不上** —— `as_human_female_warrior` 用 `base_set="as_human_warrior"` 继承，但它**明确覆盖了走跑全套**（换成 `female_walk_*`）。我们新声明的动作名它没覆盖 → **理论上会继承到我们这条**，但**没实测**。要女版就得在那个动作集里再绑一份。
3. **每条 clip 先单独验** —— `custom.do_anim act_gun_walk_forward`，命令现成，不用接任何线就能看姿势对不对。**这是最便宜的检查点。**
4. **顺序**：先 action_types + action_sets → `do_anim` 确认 10 条都能播 → 再上 movement_sets / full_movement_sets / usage → 最后实机走路看。

## 七、验收

| # | 验什么 | 怎么验 |
|---|---|---|
| 1 | 10 条动作都能播 | `custom.do_anim <动作名>` 逐条 |
| 2 | 走路的姿势换了 | 实机掏出铁炮向前走，对比改动前 |
| 3 | 🔴 **八个方向都对** | 前 / 后 / 左 / 右 / 斜向各走一遍，不该出现「前走是我们的、斜走是原版的」割裂 |
| 4 | 🔴 **脚不打滑** | 慢走时看脚有没有在地上搓 —— 打滑 = clip 的 `Bipedal movement and ik` 那组没抄 |
| 5 | 🔴 **站着不动没变呆** | idle 是我们的，且不是僵直姿势 |
| 6 | 转身正常 | 原地转圈看 `rotate` |
| 7 | 🔴 **负面测试：不带铁炮的角色不受影响** | 空手 / 拿刀走一遍，应与原版完全一致 |
| 8 | 🔴 **负面测试：收枪状态不受影响** | 铁炮收起时走路应还是原版（那走的是 `no_weapon` 那套） |
| 9 | 装填没被带坏 | 装填仍播我们的动画（回归） |

## 九、可选的前置探查（便宜，建议先做）

**ModKit 里有 `Create Override` / `Select base clip` 这个入口**，很可能是「照抄某条已有 clip 建新 clip」的官方做法。**如果 AnimationClip 这个类型允许被覆盖**，那 §三·3 的「逐条抄元数据」就能省掉 —— 建覆盖时元数据天然继承。

⚠️ 编辑器里有一句提示 `This item type can not be overriden`，说明「覆盖」是**分类型的**，动画 clip 属不属于可覆盖类型未知。**开 ModKit 时花两分钟试一下**，值。
