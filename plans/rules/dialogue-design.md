# 对话树设计原则（2026-11-13 立，用户裁定）

> **一句话**：对话是**一张话题网**，不是一条流水线。一个节点 = 对方的一次开口；一个选项 = 你**说出口**的一句话；**每个选项都要有一个专门回答它的节点**。

> 这份文档的由来：同一个毛病我犯了三次（重复自报家门 / 两种问法进同一节点 / 问句弹回菜单）。
> 所以这里不只是"怎么写好看"，而是**十条会被机器检查的硬规则**。

---

## 〇、先分清三个东西

| 东西 | 是什么 | 不是什么 |
|---|---|---|
| **节点** | **对方的一次开口**，最多两行 | 不是一段独白，不是"这一章的内容" |
| **选项** | **你说出口的那句话** | 不是按钮名，不是界面提示 |
| **跳转** | 你说完这句之后，**对方怎么回** | 不是"回到菜单"的偷懒出口 |

🔴 **选项文字就是玩家台词**。原版对话会把选项文字当作玩家角色的话念出来。
写成 `[打听] 门口那个打手……` 时，方括号里的"打听"是我加的分类标签（不念），后面才是真说的话。
⇒ 措辞必须像人话，而且必须与玩家**此刻知道什么**对得上（见规则八）。

---

## 一、十条硬规则

**规则一 · 一个节点 = 一次开口，最多两行。**
超过两行要拆——拆的办法是**让第二段由玩家追问引出**，不是机械切行再塞一句"继续"。

**规则二 · 每个选项必须指向一个专门回答它的节点。**
玩家问甲，对方答甲。答完可以给追问，但**绝不能**把甲的答案拿去回答乙。

**规则三 · 禁止两种不同问法指向同一个节点。**
同一个回答接到两种问法，第二次问就会得到一模一样的回答——读起来像对方失忆。
⇒ 要么删掉"再问"，要么给"再问"一个独立节点，内容必须是新东西。
唯一的例外是**菜单节点**（见第二节）：各种"回头再说"汇总到菜单，本来就该如此。

**规则四 · 问句不许直接弹回菜单。**
玩家问了一句，结果跳回菜单，菜单开口就是"还有事？"——**问了等于没问**。
问句必须落到实处：一个回答节点。

**规则五 · 禁止假选项。**
"继续""嗯""听他说下去"这类——玩家在上面没有做任何选择。
内容太长就**删内容**，不要拿填充句凑数。

**规则六 · 同一件事只许说一次。**
同一份信息（名字、价码、线索）在一条链里出现两次就是错。
最典型的错：开场已经"我姓周，街坊都叫老周"，下一句又问"说说你自己"，他又说一遍。

**规则七 · 同一个"只问一次"的闸门，不许被两条选项共用。**
两条都挂同一个闸门，问过一次就**两条一起消失**，"再问"那条永远是死的。
⇒ 一条选项一个闸门；再问类选项**一律不设闸门**（它本来就该一直可用）。

**规则八 · 称呼必须匹配玩家此刻知道什么。**
玩家还不知道他叫铁头时，选项只能写"门口那个打手"；知道了才能写"铁头"。
同一个阶段、同一个人，不许两种称呼。

**规则九 · 每句台词配一个能播的动作。**
动作必须在对方实际使用的动作集里（人形就是 `as_human_warrior`，见铁律四十一）。
动作与台词行数一一对应，写在 对话节点里的 `NpcActions` 字段。

**规则十一 · 菜单一次最多四个选项，其余靠条件分批放出来。**
一屏六个选项玩家会挑花眼。做法：新话题用显示条件（`Requires`）挂在"说过某句 / 拿到某物 / 完成某事"之后；
说过的旧话题用"只问一次"（`Once`）**直接不再出现**——这就是骑砍2 版的"已读变淡"（原版对话列表改不了单项颜色）。

**规则十 · 演不出来的不写。**
心理描写不写；场景里做不出来的动作不写（要写就先去把它做出来）。
旁白只允许用于**结果播报**（`（旁白，玩家）：路让开了。`）。

## 二、对话树的标准形状

```
              开场节点（对方一两句，抛出话题）
                          │
              并列选项（你挑一句，只挑一句）
        ┌─────────────┬───┴────┬─────────────┐
     回答问题甲     回答问题乙    要钱        委托
        │             │          │           │
      追问若干       追问若干    结果播报     任务说明
        └─────────────┴──────────┴───────────┘
                          │
                    菜单节点（"还有事？"）
```

### 三类节点，规矩不同

| 类型 | 例子 | 出口数 | 能不能被多种说法指向 |
|---|---|---|---|
| **回答节点** | 当铺老板答"三个月前的姑娘" | 两三个 | 绝对不行（规则三） |
| **菜单节点** | 当铺老板的"还有事？" | 五个以上 | 可以（这就是它的职责） |
| **结果节点** | 交差后给钱 | 一两个 | 绝对不行 |

### 选项的四种合法类型

| 类型 | 长什么样 | 必须做到 |
|---|---|---|
| **打听** | "三个月前，见过一个穿青布的姑娘吗？" | 落到**新信息** |
| **行动** | "这点意思，您收着。"（递钱） | 有代价（钱、物品、关系） |
| **检定** | "让开。"（威吓） | 有失败分支 |
| **收尾** | "别的先不问了。" | 允许直接回菜单 |

🔴 **"打听"不许重复**：同一个话题问第二次，除非这次对方说的是新东西，否则删掉这个选项。

## 三、写一场对话的顺序

1. **先列信息清单**：这场戏玩家必须拿到几件事？
2. **一件事 = 一个回答节点**，最多两行。
3. **每个入口选项都指向它自己的节点**：首问和再问不能共用。
4. **追问只挂在该回答节点下面**，不要提到顶层。
5. **全部汇到菜单**；菜单出口五个以上才算菜单节点。
6. **自查四问**：
   - 有没有两种问法进同一个节点？
   - 有没有问句弹回菜单？
   - 有没有同一件事说了两遍？
   - 每个选项有没有代价或新信息？

## 四、自动检查

跑 `python Scripts/check_story_probe.py`，它会抓：

| 抓什么 | 对应规则 |
|---|---|
| 节点台词超过两行 | 规则一（当前只计数，重写进行中） |
| 假选项 | 规则五 |
| 问句跳菜单 | 规则四 |
| 同一个非菜单节点被多种问法指向 | 规则三 |
| 两条选项共用同一个闸门 | 规则七 |
| 台词不是"（说话人，听话人）："格式 | —— |
| 动作播不出来 / 动作数与行数不符 | 规则九 |

**机器查不出的**：规则二、六、八、十，还有"这两句话像不像人说的"。这四条只能靠读。

## 五、我犯过的错（反例库）

| # | 错在哪 | 教训 |
|---|---|---|
| 一 | 开场自报姓名，下一节点又问一次姓名 | 同一件事只说一次 |
| 二 | 把四行节点切成两加两，中间塞"听他说下去" | 拆节点要靠追问，不能靠填充选项 |
| 三 | 首问和再问共用同一个闸门 | 两条一起消失，再问选项是死的 |
| 四 | "门口那个打手"和"门口那个铁头"进同一节点 | 称呼要匹配玩家知道多少 |
| 五 | "所以你也知道不少事？"直接跳菜单，对方回"还有事？" | 问句必须有回答 |
| 六 | 批量删选项前没备份，一次删掉四十五条问法 | **批量改结构前先备份**；改完要整条链读一遍 |

## 六、互动之前：冒泡与对话组

玩家还没开口的时候，场上是**活的**。两层，性质完全不同，规矩也不同。

### 6.1 单人冒泡（他自己在说）

一个 NPC 头顶循环冒出来的一句话，作用是**把玩家勾过去**。

| 规矩 | 内容 |
|---|---|
| 长度 | 一句话，**不超过十二个字**（头顶冒泡空间很小） |
| 间隔 | 八到二十秒一次，随机（写在 `StoryProbeTuning.json` 的 `Ambient` 段） |
| 内容 | 必须是**钩子**：吆喝、抱怨、透露有生意/有麻烦、喊人。**不是自我介绍** |
| 重复 | 同一个人**不许连着两次说同一句**；至少备两句轮换 |
| 格式 | **豁免**"（说话人，听话人）："前缀——冒泡本身就挂在人头上，加前缀是多余的 |
| 动作 | 冒泡时配的常驻动作同样受规则九约束：**必须能播** |

范本（当铺老板）：
```
"当铺还开着——死当活当都收。"        ← 吆喝，勾人
"门口那个收数的，今天又来过了。"      ← 抱怨，暗示冲突
```

### 6.2 对话组（几个 NPC 一来一回）

一段街上的戏，玩家可以**站着看**、可以**插话**、也可以**走开**。

| 规矩 | 内容 |
|---|---|
| 必须是一来一回 | 甲说 → 乙接 → 甲再答。**不许把两段独白并排摆着充数** |
| 每句仍受规则一约束 | 每次开口最多两行 |
| 谁对谁说必须清楚 | 台词键里写清对象（`（打手，老周）：钱呢？这月的。`） |
| 循环 | 一场戏演完不散场，隔一阵重新开演（同一个事件可以重播，但**台词不能接不上前一轮的情绪**） |
| 玩家能做什么 | ① 旁观：不打断，戏继续 ② 插话：落到这场戏的**接入节点**（`StoryEventDef.JoinNode`）③ 走开：戏照演 |
| 插话之后 | 允许戏暂停；玩家聊完离开，戏**回到循环**，不散场 |
| 玩家离得远 | 超过设定距离，戏不演（省性能，也不让玩家听见远处的私语） |

范本（收保护费）：
```
（打手，老周）：看什么看？没你的事。
（老周，打手）：客官，您别掺和……钱我这就给。
```

### 6.4 多人同场怎么谈

骑砍2 原版对话流**一次只有一个对手方**。多人争吵靠三件事表达：

#### 多行台词块（说话人前缀）

`NpcLine` 写成一整段带前缀的多行文本，引擎按段落显示，读起来就是"两个人当着你的面吵"：

```
thug：看什么看？没你的事。
老板：……客官，您别掺和，他喝了酒。
thug：（把柜上的秤推到地上）钱呢？
老板：（弯腰去捡）这月实在……
```

- 前缀用 `名字：`，不用引号嵌套；
- 每方**一轮最多两句**，超过就假；
- 动作写在同一行括注里，不单独占段。

#### 选边之后，焦点收敛到一个人

玩家一旦表态（帮谁 / 问谁），后续节点**只跟一个人谈**，另一个人用**一行插话**留在场：

```
thug：你他妈算哪根葱？（手已经摸到腰后）
老板：（在你身后小声）别……别在这儿动手，他真敢捅人。
```

#### 插话节点（第三人称打断）

在关键节点插一个"另一个人忍不住说话"的节点，玩家可以回应也可以不理。这是多方感最强的地方，**每个多人事件至少一个**。

### 6.3 两层怎么配合

```
玩家走近 ──▶ 冒泡（单人，勾人）
                 │ 玩家开口
                 ▼
            对话树（规则一~五）
                 │
   玩家路过时 ──▶ 对话组（群戏，可旁观可插话）
```

🔴 **冒泡和对话组不是同一件事**：冒泡是"他一个人在那儿"，对话组是"他们有来有回"。
写数据时对应两套表（常驻动作/吆喝、开场戏），**不要混用**。

## 六点五、菜单的"已读"与"渐进披露"

| 想要的效果 | 骑砍2 里怎么做 | 做不到的 |
|---|---|---|
| 说得太多记不住 | **一次性最多四个选项**，多的用显示条件压后 | —— |
| 说过的别再问 | 选项挂"只问一次"（`Once`）→ **直接消失** | 让它在列表里变灰（原生对话列表不支持单项样式） |
| 新话题随剧情解锁 | 选项挂显示条件（`Requires`），如"问过妹妹的事之后" | —— |
| 玩家想回顾说过的话 | 另设一个"再说说上次那件事"的**独立节点**（内容必须是新的） | 复读原节点（会得到一模一样的回答） |

🔴 **不要用"同一个节点被多条选项指向"来做回顾**——那就是重复问法，见规则三。

## 七、和别的规则的关系

- **铁律十二**（每个选项必须有代价或检定）：本文件的"打听"补足它的边界——打听的代价是**话题机会**，所以不许重复打听。
- **铁律四十一**（动作必须能播）：规则九的上位规则。
- **铁律二十一**（说人话）：本文件本身遵守。

- 动作挑选 → `.claude/skills/story-line-action/SKILL.md`
