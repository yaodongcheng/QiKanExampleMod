# 对话树设计原则（2026-11-13 立，用户裁定）

> **一句话**：对话是**一张话题网**，不是一条流水线。一个节点 = 对方的一次开口；一个选项 = 你**说出口**的一句话；**每个选项都要有一个专门回答它的节点**。

> 这份文档的由来：同一个毛病我犯了三次（重复自报家门 / 两种问法进同一节点 / 问句弹回菜单）。
> 所以这里不只是"怎么写好看"，而是**十条会被机器检查的硬规则**。

---

## 〇、先分清三个东西

| 东西 | 是什么 | 不是什么 |
|---|---|---|
| **节点** | **对方的一次开口**，只说一句且不硬换行 | 不是一段独白，不是"这一章的内容" |
| **选项** | **你说出口的那句话** | 不是按钮名，不是界面提示 |
| **跳转** | 你说完这句之后，**对方怎么回** | 不是"回到菜单"的偷懒出口 |

🔴 **选项文字就是玩家台词**。原版对话会把选项文字当作玩家角色的话念出来。
写成 `[打听] 门口那个打手……` 时，方括号里的"打听"是我加的分类标签（不念），后面才是真说的话。
⇒ 措辞必须像人话，而且必须与玩家**此刻知道什么**对得上（见规则八）。

---

## 一、十条硬规则

**规则一 · 一个节点只能有一句 NPC 台词，不能硬换行。**
不同句子拆不同节点；连续NPC台词用节点级`NextNode`接到下一句，玩家点击原版继续推进；有实际选择时才配置`Options`。每次互动由NPC先说开场，禁止玩家网关先开口。

**规则二 · 每个选项必须指向一个专门回答它的节点。**
玩家问甲，对方答甲。答完可以给追问，但**绝不能**把甲的答案拿去回答乙。

**规则三 · 禁止两种不同问法指向同一个节点。**
同一个回答接到两种问法，第二次问就会得到一模一样的回答——读起来像对方失忆。
⇒ 要么删掉"再问"，要么给"再问"一个独立节点，内容必须是新东西。
唯一的例外是**菜单节点**（见第二节）：各种"回头再说"汇总到菜单，本来就该如此。

**规则四 · 问句不许直接弹回菜单。**
玩家问了一句，结果跳回菜单，菜单开口就是"还有事？"——**问了等于没问**。
问句必须落到实处：一个回答节点。

**规则五 · 禁止假选项。**
"继续""嗯""听他说下去"这类——玩家在上面没有做任何选择。
内容太长就**删内容**，不要拿填充句凑数。

**规则六 · 同一件事只许说一次。**
同一份信息（名字、价码、线索）在一条链里出现两次就是错。
最典型的错：开场已经"我姓周，街坊都叫老周"，下一句又问"说说你自己"，他又说一遍。

**规则七 · 同一个"只问一次"的闸门，不许被两条选项共用。**
两条都挂同一个闸门，问过一次就**两条一起消失**，"再问"那条永远是死的。
⇒ 一条选项一个闸门；再问类选项**一律不设闸门**（它本来就该一直可用）。

**规则八 · 称呼必须匹配玩家此刻知道什么。**
玩家还不知道他叫铁头时，选项只能写"门口那个打手"；知道了才能写"铁头"。
同一个阶段、同一个人，不许两种称呼。

**规则九 · 每句台词配一个能播的动作。**
动作必须在对方实际使用的动作集里（人形就是 `as_human_warrior`，见铁律四十一）。
每个单句节点最多配一个动作，511写在唯一维护源 `Dialogues/*.dialog.json` 节点的 `LineActions` 字段，定稿直接维护。

**规则十一 · 菜单一次最多四个选项，其余靠条件分批放出来。**
一屏六个选项玩家会挑花眼。做法：新话题用显示条件（`Requires`）挂在"说过某句 / 拿到某物 / 完成某事"之后；
说过的旧话题用"只问一次"（`Once`）**直接不再出现**——这就是骑砍2 版的"已读变淡"（原版对话列表改不了单项颜色）。

**规则十 · 演不出来的不写。**
心理描写不写；场景里做不出来的动作不写（要写就先去把它做出来）。
旁白只允许用于**结果播报**（正文直接写`路让开了。`，不显示人物前缀）。

**规则十·补 · 弹窗不是对话（2026-11-13 用户裁定）。**
`InformationManager.ShowInquiry` 这类弹窗**只承载第三人称叙述**：讲发生了什么、给玩家什么信息。
- **禁止**在弹窗正文里写 NPC 台词（`（老囚，玩家）：…`）—— 没有站位、没有表情、没有镜头，念出来出戏。
- 弹窗正文**也不加 `（旁白，玩家）：` 前缀**，直接第三人物口吻写（「你醒在稻草上，后脑一片湿。」）。
- 对话正文同样禁止人物前缀；说话者、听话者用显式`Speaker`／`Listener`字段，交给原版机制切换真实角色。
- 想让 NPC 真开口 → 进场景走对话流或头顶冒泡，不要塞进弹窗。

**规则十二 · 禁止孤立不可达节点（Orphan Node）。**
JSON 里的每一个节点，都必须能从运行时合法入口（`_intro` / `_hub` / `_turnin` / `_chat` / `event_*_join` / `blocker_*`）顺着 `NextNodeOnSuccess` 或 `NextNodeOnFail` 走到。写了节点却没连上边 = 死代码、断任务。

**511正式格式：**合法入口由 `Entries[].Node` 显式登记，连续台词用节点级`NextNode`；玩家分支用`Options[].NextNode`或`Check.Success/Fail`；节点名不决定入口。只问一次用 `Requires: ["!asked:话题"]` 配 `mark` 效果；付款用 `Requires: ["gold>=金额"]` 配 `Effects`。上文旧 `Once`、下文旧 `PROBE` 和通用注入器的 `NextNodeOnSuccess/Fail` 是兼容桥术语，不能写回511正式JSON。中文审阅字段 `EntryOptionZh/TextKeyZh/PlayerKeyZh` 必须保留并与语言表一致，未知字段仍由严格解析拒绝。

**规则十三 · 禁止自指循环与中途回跳 `_intro`。**
任何选项不得跳回当前节点自身（玩家选了等于重听一遍刚才的话），也不得从对话中途跳回 `<npc>_intro`（要回到顶层一律跳 `<npc>_hub`）。

**规则十四 · 付费/塞钱选项必须配 `Requires: gold>=N` 且动作与文案一致。**
凡触发 `PROBE:pay` / `pay_to` / `bribe` / `offer_money` / `money_deal` 的选项（或其前置入口），必须挂 `gold>=N`（钱不够不出现，见 §5.5），且选项文案不能写"借钱"实则扣玩家的钱。

**规则十五 · 非终局的打听/回答节点必须给回 `_hub` 的收尾项，不许只留 `[离开]`。**
玩家问完一个问题（如问身世、问对手、问妹妹），如果不是立刻开打或过门，必须提供回 `<npc>_hub` 的选项（如 `[收住] 别的先不问了。`），不能逼玩家关窗重按 F。

## 二、对话树的标准形状

```
              开场节点（对方一两句，抛出话题）
                          │
              并列选项（你挑一句，只挑一句）
        ┌─────────────┬───┴────┬─────────────┐
     回答问题甲     回答问题乙    要钱        委托
        │             │          │           │
      追问若干       追问若干    结果播报     任务说明
        └─────────────┴──────────┴───────────┘
                          │
                    菜单节点（"还有事？"）
```

### 三类节点，规矩不同

| 类型 | 例子 | 出口数 | 能不能被多种说法指向 |
|---|---|---|---|
| **回答节点** | 当铺老板答"三个月前的姑娘" | 两三个 | 绝对不行（规则三） |
| **菜单节点** | 当铺老板的"还有事？" | 五个以上 | 可以（这就是它的职责） |
| **结果节点** | 交差后给钱 | 一两个 | 绝对不行 |

### 选项的四种合法类型

| 类型 | 长什么样 | 必须做到 |
|---|---|---|
| **打听** | "三个月前，见过一个穿青布的姑娘吗？" | 落到**新信息** |
| **行动** | "这点意思，您收着。"（递钱） | 有代价（钱、物品、关系） |
| **检定** | "让开。"（威吓） | 有失败分支 |
| **收尾** | "别的先不问了。" | 允许直接回菜单 |

🔴 **"打听"不许重复**：同一个话题问第二次，除非这次对方说的是新东西，否则删掉这个选项。

## 三、写一场对话的顺序

1. **先列信息清单**：这场戏玩家必须拿到几件事？
2. **一件事 = 一个回答节点**，只说一句且不硬换行。
3. **每个入口选项都指向它自己的节点**：首问和再问不能共用。
4. **追问只挂在该回答节点下面**，不要提到顶层。
5. **全部汇到菜单**；菜单出口五个以上才算菜单节点。
6. **自查四问**：
   - 有没有两种问法进同一个节点？
   - 有没有问句弹回菜单？
   - 有没有同一件事说了两遍？
   - 每个选项有没有代价或新信息？

## 四、自动检查

跑 `python Scripts/check_story_probe.py`，它会抓：

| 抓什么 | 对应规则 |
|---|---|
| 节点多句、硬换行或人物前缀 | 规则一（一句一节点，结构人物，硬门禁） |
| 假选项 | 规则五 |
| 问句跳菜单 | 规则四 |
| 同一个非菜单节点被多种问法指向 | 规则三 |
| 两条选项共用同一个闸门 | 规则七 |
| 说话者／听话者缺失、未知或是同一人 | 真实人物字段；禁止把身份写进正文 |
| 动作播不出来 / 动作数与行数不符 | 规则九 |

**机器查不出的**：规则二、六、八、十，还有"这两句话像不像人说的"。这四条只能靠读。

## 五、我犯过的错（反例库）

| # | 错在哪 | 教训 |
|---|---|---|
| 一 | 开场自报姓名，下一节点又问一次姓名 | 同一件事只说一次 |
| 二 | 把四行节点切成两加两，中间塞"听他说下去" | 拆节点要靠追问，不能靠填充选项 |
| 三 | 首问和再问共用同一个闸门 | 两条一起消失，再问选项是死的 |
| 四 | "门口那个打手"和"门口那个铁头"进同一节点 | 称呼要匹配玩家知道多少 |
| 五 | "所以你也知道不少事？"直接跳菜单，对方回"还有事？" | 问句必须有回答 |
| 六 | 批量删选项前没备份，一次删掉四十五条问法 | **批量改结构前先备份**；改完要整条链读一遍 |

## 六、互动之前：冒泡与对话组

玩家还没开口的时候，场上是**活的**。两层，性质完全不同，规矩也不同。

### 6.1 单人冒泡（他自己在说）

一个 NPC 头顶循环冒出来的一句话，作用是**把玩家勾过去**。

| 规矩 | 内容 |
|---|---|
| 长度 | 一句话，**不超过十二个字**（头顶冒泡空间很小） |
| 间隔 | 八到二十秒一次，随机（写在 `StoryProbeTuning.json` 的 `Ambient` 段） |
| 内容 | 必须是**钩子**：吆喝、抱怨、透露有生意/有麻烦、喊人。**不是自我介绍** |
| 重复 | 同一个人**不许连着两次说同一句**；至少备两句轮换 |
| 格式 | 正文只写台词，一律不带人物前缀；用人物字段指定真实听话者 |
| 动作 | 冒泡时配的常驻动作同样受规则九约束：**必须能播** |

范本（当铺老板）：
```
"当铺还开着——死当活当都收。"        ← 吆喝，勾人
"门口那个收数的，今天又来过了。"      ← 抱怨，暗示冲突
```

### 6.2 对话组（几个 NPC 一来一回）

一段街上的戏，玩家可以**站着看**、可以**插话**、也可以**走开**。

| 规矩 | 内容 |
|---|---|
| 必须是一来一回 | 甲说 → 乙接 → 甲再答。**不许把两段独白并排摆着充数** |
| 每句仍受规则一约束 | 每次开口只说一句且不硬换行 |
| 谁对谁说必须清楚 | 结构显式指定说话者/听话者，正文只写这一句台词 |
| 循环 | 一场戏演完不散场，隔一阵重新开演（同一个事件可以重播，但**台词不能接不上前一轮的情绪**） |
| 玩家能做什么 | ① 旁观：不打断，戏继续 ② 插话：落到这场戏的**接入节点**（`StoryEventDef.JoinNode`）③ 走开：戏照演 |
| 插话之后 | 允许戏暂停；玩家聊完离开，戏**回到循环**，不散场 |
| 玩家离得远 | 超过设定距离，戏不演（省性能，也不让玩家听见远处的私语） |

范本（收保护费，节点局部示意）：
```json
[
  {"Id":"interrupt_1","Speaker":"thug","Listener":"pawnbroker","TextKeyZh":"看什么看？","NextNode":"interrupt_2","Options":[]},
  {"Id":"interrupt_2","Speaker":"thug","Listener":"pawnbroker","TextKeyZh":"没你的事。","NextNode":"interrupt_3","Options":[]},
  {"Id":"interrupt_3","Speaker":"pawnbroker","Listener":"thug","TextKeyZh":"客官，您别掺和……钱我这就给。","Options":[]}
]
```
实际定义还须补TextKey与根字段、合法入口；人物信息独立于正文。

### 6.2.1 演出内发声的身体和视线（2026-11-16用户裁定）

实际冒泡的NPC就是这句的说话者。`StreetLife.Listener`、群组逐句`Speakers/Listeners`、`actor_say.Actor/Listener`显式指定人物，不从正文、刺激源或旁观玩家猜听话者。

发声与Brain动作并联；移动和战斗喊话不必进入`PerformanceAction`。已进入该动作的NPC实际发声后，由动作每帧持续让身体朝向听话者、视线注视听话者；听话者移动时跟随，气泡消失仍保持，直到动作退出。暂停暂时归还身体和注视，恢复重新应用；听话者死亡或被移除则结束动作，不能看向失效对象。正文无人物前缀适用于NPC对玩家和NPC对NPC。

`SpeechChannel.Say`的第一个Agent才是说话者；旧`SpeechContext.Speaker`表示触发发声的刺激源，不能拿它替代说话者或听话者。动作只接收属于自身实例且已经实际播放的台词，旧动作的迟到台词不能控制新动作。

### 6.4 多人同场怎么谈（2026-11-16用户裁定）

每人每句一个节点。正文只含台词；`Speaker`和`Listener`控制真实说话者与听话者，不能靠署名假装换人。

原版`ConversationSentence.IsSpeaker/IsListener`支持按真实Agent选择参与者；连续NPC句的输出token指向下一NPC句的输入token，由原版继续按钮推进。

511节点的`npc/questioner`绑定入口演员，实名ID必须登记在`Actors`；只有`EntryActors`可占有这份定义的入口与业务归属。玩家选项显式`Speaker=player`和`Listener`，与连续NPC边互斥。

加入第三人必须走原版参与者登记与收尾，并检查存活、捆缚、倒地、战斗及演出占用；当前句真正展示才提交该节点效果和动作。缺参与者安全结束，不能默认让入口演员代说。

### 6.3 两层怎么配合

```
玩家走近 ──▶ 冒泡（单人，勾人）
                 │ 玩家开口
                 ▼
            对话树（规则一~五）
                 │
   玩家路过时 ──▶ 对话组（群戏，可旁观可插话）
```

🔴 **冒泡和对话组不是同一件事**：冒泡是"他一个人在那儿"，对话组是"他们有来有回"。
写数据时对应两套表（常驻动作/吆喝、开场戏），**不要混用**。

## 六点五、菜单的"已读"与"渐进披露"

| 想要的效果 | 骑砍2 里怎么做 | 做不到的 |
|---|---|---|
| 说得太多记不住 | **一次性最多四个选项**，多的用显示条件压后 | —— |
| 说过的别再问 | 选项挂"只问一次"（`Once`）→ **直接消失** | 让它在列表里变灰（原生对话列表不支持单项样式） |
| 新话题随剧情解锁 | 选项挂显示条件（`Requires`），如"问过妹妹的事之后" | —— |
| 玩家想回顾说过的话 | 另设一个"再说说上次那件事"的**独立节点**（内容必须是新的） | 复读原节点（会得到一模一样的回答） |

🔴 **不要用"同一个节点被多条选项指向"来做回顾**——那就是重复问法，见规则三。

## 七、和别的规则的关系

- **铁律十二**（每个选项必须有代价或检定）：本文件的"打听"补足它的边界——打听的代价是**话题机会**，所以不许重复打听。
- **铁律四十一**（动作必须能播）：规则九的上位规则。
- **铁律二十一**（说人话）：本文件本身遵守。
- 写作流程与反例 → `.claude/skills/story-dialogue-writing/SKILL.md`
- 动作挑选 → `.claude/skills/story-line-action/SKILL.md`
