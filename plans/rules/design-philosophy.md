# 设计哲学：玩家体验四原则

> **适用场景**：设计任何新系统、新功能、新 Quest、新 NPC 交互时，必须逐条对照检查。
> **优先级**：这四条原则高于一切实现细节。设计不符合原则 → 先改设计，再写代码。
> **来源**：从村庄偷窃后续反应系统的设计评审中提炼，适用于本 mod 所有玩法设计。

---

## 原则一：互动要有明确的反馈

**核心命题**：玩家的每一个行为，都要让玩家感知到"世界因为我的行为发生了变化"。

### 检查清单

- [ ] **即时反馈**：动作执行后，有没有视觉/音效/文字上的即时响应？（如偷窃成功 → 物品入袋动画 + 音效）
- [ ] **短期反馈**：几分钟到几小时内，有没有后果信号？（如 NPC 发现东西少了 → 开始议论）
- [ ] **长期反馈**：几天到几周后，有没有连锁反应？（如村庄悬赏 → 报复部队追杀）
- [ ] **中间状态可见**：系统内部的状态变化（进度 0→1），玩家能否通过模糊信号感知？（如"村民刚开始议论"→"村长挨家挨户问话"→"听说找到线索了"）
- [ ] **负面反馈不是"无事发生"**：玩家的行为没有产生预期后果时，也应该有反馈（如冷案 → "那事儿不了了之了……"）
- [ ] **成功/失败都要有戏剧性**：不只是数值变化，要有叙事反馈（如嫁祸成功 → 看到 NPC 被抓的场景描述）

### 反例

- 玩家偷了动物离开，三周后回来村庄已经恨透了他，但中间过程完全没有通知 → 反馈断层
- 调查进度 0.0→1.0 完全在后台跑，玩家无从感知 → 中间状态不可见
- 7 天冷案，没有任何通知，`!` 标记也消失了 → 玩家困惑"然后呢？"

## 原则二：给玩家足够的自由感

**核心命题**：永远不让玩家觉得"我只能这么做"。玩家应该能选择**怎么面对**后果，而不是被后果推着走。

### 检查清单

- [ ] **至少 3 种解决路径**：任何冲突场景，提供对抗/协商/绕过三种以上路径（如对抗=武力摆平、协商=赔钱了事、绕过=嫁祸他人）
- [ ] **允许后悔**：提供补救/归还/道歉/认罪路径，不要只有"逃避"和"对抗"两条路
- [ ] **不给强制选择**：可以给压力（不处理后果会恶化），但不能剥夺选择（"你必须接这个 Quest"）
- [ ] **技能/关系影响选项**：玩家的 Roguery/Charm/Trust/声望等应该解锁不同的选项，而不是所有人看到同一套对话
- [ ] **选项有层次**：同一条路径应该有不同档次（如威胁分轻度/重度，赔钱分足额/讨价还价）
- [ ] **"什么都不做"也是一种选择**：不介入应该有自然后果，但玩家有权不介入

### 反例

- 只有赔钱/骗人/威胁/跑路四条路，没有"归还动物"或"认罪谈判" → 缺少补救路径
- Charm 辩护成功率固定 40%，跟玩家 Charm 技能和 Trust 无关 → 技能不影响选项
- 威胁只有一种结果（恶名+1→阶段3），没有轻度威胁的中间选项 → 选项无层次

## 原则三：任意相关 NPC 都要接得住

**核心命题**：系统涉及的每一个 NPC——不限于主要对话对象——在任意阶段都应有符合其身份的合理反应。NPC 的认知必须有来源可追溯。

### 检查清单

- [ ] **NPC 全覆盖**：系统涉及的 NPC 类型（主要对话者/目击者/普通村民/守卫/路人/商队/同伴）是否都有对应的反应？
- [ ] **认知可追溯**：NPC 的每条知识都能追溯到来源——亲身经历（目击）> 听人说（传闻）> 公共认知（村庄都知道）> 不知情
- [ ] **认知可能不准**：传闻可能失真，村民可能搞错嫌犯，不同 NPC 说法可能矛盾
- [ ] **无 HeroId 的普通 Agent 有兜底**：通过 Settlement/Clan 级别的公共记忆（`SettlementPublicMemory`），让无名 NPC 也能对事件有合理反应
- [ ] **反应与身份自洽**：守卫的反应 ≠ 村民的反应 ≠ 商人的反应；受害者的反应 ≠ 旁观者的反应
- [ ] **反应与关系自洽**：高 Trust 村庄对玩家的态度 ≠ 低 Trust 村庄；熟人 ≠ 陌生人
- [ ] **记忆持久化**：NPC 的记忆应通过 `SingNpcMemorySystem` 持久化，读档后认知不丢失

### 实现策略

```
NPC 对话判定流程：
  ├─ 有 HeroId？
  │   ├─ YES → 查 SingNpcMemorySystem
  │   │   ├─ DirectExperiences（亲身经历）→ "我亲眼所见"级认知
  │   │   ├─ KnownEvents（传闻）→ "听人说"级认知
  │   │   └─ 都没有 → 查公共记忆
  │   └─ NO → 查 SettlementPublicMemory / ClanPublicMemory
  │       └─ 根据 CollectiveAttitude 决定语气
  └─ 综合判定：认知内容 + 态度 + 个人诉求 → 对话内容
```

### 反例

- 整个系统只有村长（Headman）一个对话入口，目击者/普通村民/守卫全无反应
- NPC 的认知来自"系统全知"而非记忆系统，导致 NPC 知道他不该知道的事（违反叙事铁律）
- 玩家 Trust +80 的村庄和 Trust -30 的村庄，村民对偷窃嫌疑的反应完全一样

## 原则四：提供信息，塑造目标

**核心命题**：永远不让玩家处于"我不知道发生了什么，也不知道该干嘛"的状态。信息要主动触达，目标要隐晦暗示。

### 检查清单

- [ ] **多渠道触达**：重要信息通过 ≥2 个渠道传达（通知/酒馆传闻/路人搭话/同伴提醒/地图标记）
- [ ] **行动暗示**：每条通知结尾，给一句隐晦的"下一步可以做什么"的暗示（不是任务指引，而是叙事性的方向）
- [ ] **信息不丢失**：玩家离开后再回来，应该有方式回顾"当前有哪些未了结的事"
- [ ] **偷窃/违规行为有预警**：行为完成后给一条低优先级提示，让玩家有心理预期（"牲口少了，迟早会被发现"）
- [ ] **目标感塑造**：玩家不接 Quest 也应该知道"这事还有后续"，不会觉得"偷完就完了"
- [ ] **不过载**：多案件并发时，信息应该有优先级和合并机制，不要让玩家被通知淹没

### 反例

- 通知只描述了状态，没有任何"然后呢"的暗示 → 玩家读完不知道要干嘛
- 只靠酒馆传闻触达，玩家不去酒馆就完全不知道 → 渠道单一
- 偷了 5 个村庄后，没有任何方式帮玩家追踪"哪些村庄还有未了的案子" → 信息丢失
- 偷窃完成无任何提示，玩家以为"没事了"就离开 → 缺少预警

## 设计评审流程

设计任何新系统时，按以下步骤自检：

1. **画出玩家体验路径图**：至少 3 条典型路径（如对抗/协商/绕过），每条路径标注关键反馈点
2. **列出所有相关 NPC 类型**：逐一检查每个类型在每阶段的反应是否合理
3. **检查信息触达**：每个状态变化是否通过 ≥2 个渠道告知玩家
4. **问自己 KCD2 问题**：这个设计在《天国：拯救 2》里合格吗？玩家会不会出戏？
