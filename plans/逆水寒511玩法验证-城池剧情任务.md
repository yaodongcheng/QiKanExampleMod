# 市井 · 城门序章 —— 需求文档

> **状态**：**代码已实施（2026-11-12）；外部审查（2026-11-13）判「不可交付」，其 R1/R2/R3/R5 已当天修复，R4 已补交互断点，见 §〇 · 0.7**。实施记录与偏差见 §十五，实机验收按 §12。
> **一句话**：在真实城镇场景里做一段 5 分钟的序章——玩家是个进不了城的穷光蛋，靠嘴、手、拳头或钱，从城门口四家手里换来一条进城的路。
> **三个名词**：
> - **三种能力**：魅力（人际 / 身份）、技巧（偷 / 翻 / 撬 / 潜）、武力（打 / 吓 / 绑 / 扛）
> - **钱是第四手段**，不属于任何能力，只解决「钱能买的那一段」
> - **一次检定**：玩家某类属性 vs NPC 同一类属性，掷点 ≥ 门槛即成功

## 测试（先看这里）· 怎么玩 / 怎么验

> 这一节是**给你实机测试用的**，放在最前面方便查。代码状态与设计细节在后面（§〇 审查、§十五 实施记录、§十六 交接 TODO）。

> **运行环境（2026-11-13 裁定）**：本序章**只跑原版卡拉迪亚**，启动时**不挂任何世界观 mod**（不含 Taikou）。
> 九个人的外观模板、目标城（`town_ES4` 吕卡隆）全部按原版 `SandBoxCore` / `SandBox` 挑；`LivingWorldNpcs` 的 `SubModule.xml` 也只依赖原生那五个模块 + 四个前置库。

### A. 四步进游戏

```
custom.story_probe enable
custom.story_probe goto
```

1. `enable` —— **打开开关**。`config.json` 里 `StoryProbeEnabled` 默认是 `false`（故意默认关，免得影响正常游玩）。不开的话城镇菜单不会出现「入城（玩法测试）」，硬进场景日志会打 `skipped: disabled`。**只在本次游戏有效**；想永久开就改 `Modules\LivingWorldNpcs\config.json` 里那个字段。
2. `goto` —— **纯代步**，把主队瞬移到目标城的城门位置（`MobileParty.MainParty.Position2D = GatePosition`）。**不会**帮你进城；你已经在城门口的话这条可以不打。

然后：**从地图正常进城 → 城镇菜单点「入城（玩法测试）」**。

### B. 哪些城能用（不是随便哪座城）

| 条件 | 说明 |
|---|---|
| ① 目标城 = **`town_ES4`（吕卡隆 Lycaron，帝国城镇，center 场景 `empire_town_m`）** | 写在 `config.json` 的 `StoryProbeSettlementId`；运行时 `custom.story_probe city <id>` 可改 |
| ② 地点必须是 **center**（城门 / 市中） | 酒馆、领主大厅、地牢**都不加载** |
| ③ 必须从城镇菜单那一条进 | 原版「在城里逛逛」**永远不加载**序章（故意的，不是 bug） |

**换城没核过**：锚点按"守门人刷新点 + 相对玩家偏移"算，别的城有没有那个刷新点、门内点在哪儿都没验。⇒ **先只在 吕卡隆 测**。

### D. 常见"没生效"怎么判

| 看到这行 | 含义 | 怎么办 |

## 二、玩家流程

```
【第一次进城】
点「入城（玩法测试）」
  → 弹窗：你被这座城通缉，正门进不去 →【硬闯】
  → 场景里只有守门人：拦住你 → 动手 → 你必败（数值碾压）
  → 黑屏：「你被打晕，扔进了牢里。」
  → 弹窗：同监的老囚递给你一套旧衣服和一块面罩 →【换上】
  → 出狱：装备被没收，只剩这身旧衣 + 面罩（遮脸 = 不被通缉画像认出来）

【第二次进城 —— 序章正式开始】
  → 酒馆自动招一个随从（免费）→ 随从说 3 句交代目标
  → 城门口：有人正在被收保护费（头顶「!」，气泡在弹）
  → 玩家凑过去 → 事件暂停 → 自动开对话 → 插话
  → 认识四家之一 → 打听妹妹线索 → 求一样东西 → 他派一件事
  → 办完回来交差 → 拿到工具 / 学了一手
  → 用魅力 / 技巧 / 武力 / 钱过守门人
  → 走到门内 → 恢复金钱 → 序章完
```

**第一次为什么必败**：这是教学。玩家必须先亲身撞一次墙，才会去想「明着进不去，那就别明着进」——后面魅力的遮面、技巧的翻墙、武力的硬打、钱的打点才有意义。

## 三、场景与进入

### 3.1 目标城与场景

- **目标城**：默认 `town_ES4`（吕卡隆，帝国城镇，1.2.12 与 1.5.x 都有），`config.json` 可改。
- **场景**：该城 center = **`empire_town_g`**。来源：`Modules\SandBox\ModuleData\settlements.xml` → `town_comp_EN1` → `<Location id="center" scene_name="empire_town_g">`。
- **只在 center 触发**：tavern / lordshall / keep 不触发；别的城不触发。

### 3.2 进入流程（两进：第一次必败，第二次才是序章）

菜单选项「入城（玩法测试）」**默认不出现**，只在目标城且打过 `custom.story_probe.enable` 后出现；`disable` 后消失。原版「在城里逛逛」永远不加载序章。

#### 3.2.1 第一次进城：必败教学

| 步 | 发生什么 | 实现 |
|---|---|---|
| ① 弹窗 | 标题「城门」+ 4 句背景 +【硬闯】/【再想想】 | `InformationManager.ShowInquiry` |
| ② 进场 | 场景里**只有守门人**——四家、事件、目标点都不布置 | `Phase = FirstAttempt` |
| ③ 对话 | 守门人：「通行文书。」→ 你「我要进城」→ 他动手 | 原版对话流注入 |
| ④ 必败 | **强制失败**：不掷骰，直接播被击倒（`KnockoutFlow.PlayStrikeAnim`）→ 你倒地 | 不给玩家翻盘的机会 |
| ⑤ 黑屏 | 淡出 + 旁白「你被打晕，扔进了牢里。」 | MissionScreen 淡出 |

**为什么强制失败**：「打不过」如果只是数值设定，操作好的玩家仍可能赢；所以这一场的武力检定**直接判负**（`forceFail`），保证教学一定成立。

**弹窗正文**（4 句）：

```
三个月前，你妹妹进城做工，再没消息。
你一路找来，钱在路上被偷光了，身上只剩她最后一封信。
更糟的是，码头帮栽了你一桩小事——城门上挂着你的小额通缉。
正门是进不去了。城门外的几家，各有各的门路。
```

#### 3.2.2 牢里：换装束 + 面罩

黑屏之后弹第二个窗：

```
同监的老囚把一套旧衣服和一块面罩塞给你：
「想进城？先让人认不出你。」
【换上】【我再想想】
```

- 点【换上】→ **装备与钱被没收**（武器 / 甲 / 钱袋全没）→ 得到旧衣 + 面罩 → 出狱，回到城门外。
- **面罩的作用 = 遮脸**：通缉画像认不出你（`Disguised = true`），这是后面「正门走进去」的基础。
- 点【再想想】→ 留在牢里，弹窗再出现（不锁死，也不能跳过）。

#### 3.2.3 第二次进城：序章开始

| 步 | 发生什么 | 实现 |
|---|---|---|
| ① 随从 | **酒馆自动招一个随从**（免费），他从酒馆跟你出来 | 目标城酒馆里挑一个 wanderer → `AddCompanionAction`；没有可招的 → 跳过，用旁白 |
| ② 随从说话 | 站在玩家左后 1.5 m，说 3 句（间隔 2.5 秒，头顶气泡） | `SpeechChannel.Say` |
| ③ 布置场景 | 四家代表 + 6 起事件循环 + 目标点全部就位 | 完整序章 |

- **随从台词**：`就是这儿了。你妹妹三个月前进的这座城。` / `正门挂着你的通缉——硬闯等于自投罗网。` / `先跟门口这几家搭上线。帮谁，谁教你一手。`
- **强制随从**：这一次不判断「玩家有没有随从」——**没有就从酒馆招一个**，保证目标一定有人讲。
- 随从只播一次（`IntroPlayed` 存状态）；`custom.story_probe intro` 可重播；`custom.story_probe phase first|second` 可强制切阶段。

**文本键**（走 `LWNTextHelper`）：`LWN_story_intro_inquiry_title/_body/_btn_go/_btn_back` · `LWN_story_intro_line_1..3` · `LWN_story_intro_narr_1..3` · `LWN_story_jail_inquiry_body/_btn_wear`。

**触发判定**（`StoryProbeMissionBehavior.OnMissionBehaviorInitialize`）：`Enabled` 为真 → `EnterViaOption` 为真（否则直接 return）→ 当前定居点 = 目标城 → 当前地点 = center → 按 `Phase` 布置第一次（只有守门人）或第二次（完整序章）→ 消费标记。

## 四、世界：城门口的四家

**四家是城里的组织势力，不是家族。** 数据上每家可挂一个 `Clan` 当身份载体（关系 / 声望判定现成），叙事里只叫「公会 / 会 / 剧团 / 帮」。

| 势力 | 性质 | 城门口的代表 | 对应能力 | 和谁敌对 |
|---|---|---|---|---|
| **捉刀人**（友好） | 中间人 / 掮客，跑腿、找门路、写状子 | 当铺老板 | **钱 + 人脉** | 码头帮 |
| **夜行会**（中立） | 小偷 / 撬锁 / 扒窃 | 寡妇的儿子（小贼） | **技巧** | 码头帮 / 野贼 |
| **流浪剧团**（中立） | 剧团 / 舞姬，靠表演和魅力 | 寡妇（领班） | **魅力** | 码头帮 / 对台剧团 |
| **码头帮**（敌对） | 水上脚夫结成的帮派，收数 / 放贷 / 打手 | 守门人（blocker）、thug；屠户是叛逃者 | **武力** | 其余三家 |

英文 fallback：The Fixers · The Nightwalkers · The Players · The Dockhands（键 `LWN_faction_*`）。

### 4.1 帮忙换手艺

玩家求一家要东西 → 对方派一件小事（教训他的仇家）→ 办完才给。

| 你求谁 | 求什么 | 他让你做什么 | 仇家 | 完成得到 | 后果 |
|---|---|---|---|---|---|
| 当铺老板（捉刀人） | 钱 + 消息 | 收一笔欠账 | debtor（码头帮的收数） | 第纳尔 + 消息 | 捉刀人 +；debtor − |
| 儿子（夜行会） | 钩索 | 教训抢他生意的野贼 | 野贼 | 钩索 | 夜行会 +；野贼 − |
| 寡妇（流浪剧团） | 一个能进城的身份 | 砸对台的招牌 | 对台领班 | 贵族制服 + 通行文书 | 剧团 +；对台 − |
| 屠户（叛逃者） | 武器 / 教两手 | 教训砸他摊的 thug | thug | 武器 + 绳子 | 屠户 +；码头帮 − |

- **不白给**：不办事不给；可以花钱或硬闯，但那不是人情。
- **可以都帮**，也可以只帮一家；帮忙本身不检定、不花钱。
- **序章先做屠户那条**（教训 thug）：目标就在门口，武力的决斗 / 击晕 / 绑扛都现成；其余三家留接口。
- 委托形状复用 `CommissionQuest` / `CommissionData`（giver / target / reward），不跑程序化生成器。

### 4.2 每个人知道妹妹的一截

| 谁 | 他知道的 |
|---|---|
| 当铺老板 | 她当过一个镯子，还没赎（当票） |
| 寡妇 | 卖过她一张通行文书，后来有个水手把她领走 |
| 儿子 | 上个月夜里，码头帮押着个女的从后巷过去 |

**码头帮是带走她的那条线**——序章结束时把线索引到「第一张凭证」。

## 五、玩家能做什么：三种能力 + 钱

### 5.1 总表

| 手段 | 玩法 | 用什么判定 |
|---|---|---|
| **魅力** | 乔装（冒充通行 / 通缉脱险 / 冒充犯法） | Charm 对 Charm |
| **技巧** | 钩索 / 扒窃 / 撬锁 / 潜行 / 偷属性道具 | Roguery 对 Roguery |
| **武力** | 决斗 / 击晕 / 威吓 / 绑起来·扛走 | Vigor+Control 对 Vigor+Control |
| **钱** | 收买（打点 / 消息 / 酒） | **不检定**，钱够就过 |

**嘴上的事在对话里，手上的事在对话外**：
- 对话里 = 打听 / 求 / 交差 / 闲聊 / 亮身份
- 对话外 = 扒窃（扒窃条）、动手（拔刀）、绑 / 扛（动作键）、收买（钱够直接给）、乔装（换装）

### 5.2 魅力：遮面与冒充

**两件事，同一套机制（`Disguised` 旗标），用途不同**：

| 做法 | 来源 | 对付什么 | 检定 |
|---|---|---|---|
| **遮面**（旧衣 + 面罩） | 出狱时老囚给的 | 通缉画像认不出你——正门能站，守卫不会直接抓 | 魅力对拼（被盘问时） |
| **冒充**（贵族制服 + 通行文书） | 寡妇给的 | 守门人把你当成某位大人，直接让路 | 魅力对拼（他信不信） |

- **遮面是底子**：没有它，通缉状态下走正门直接被认出来；有了它才站得住门口。
- **冒充是升级**：穿贵族制服 + 通行文书（存 `DisguiseHeroId`），守门人一句「阁下」让路。
- **通缉脱险**：走别的路失败被通缉后，遮面 / 冒充都能让守卫认错人。
- **冒充犯法**（可选）：乔装状态下犯事，罪名记在「那个人」头上（`FrameSuspect` / `WorldEvent` 的 suspect 字段），你的通缉不涨。
- **失败**：被识破 → 警觉 / 被抓；可换收买或其他路。
- **后续伏笔**：被冒充的人以后会来找你（本阶段只存 `DisguiseHeroId` + 次数）。

### 5.3 技巧：五个玩法

| 玩法 | 怎么做 | 成功 | 失败 |
|---|---|---|---|
| **钩索**（主路） | 儿子给你钩索后，勾住城门上方的墙 / 梁翻过去 | 守门人没反应过来 | 钩空 → 他察觉 |
| 扒窃 | 扒窃条扒走他的武器 / 钥匙 | 他手里没家伙 | 察觉 |
| 撬锁 | 绕到侧门开锁 | 从背后过去 | 发出声响；**场景没真门就不做这条** |
| 潜行 | 蹲下趁他转头溜过去 | 没被看见 | 被看见 |
| 偷属性道具 | 扒窃条偷 NPC 背包里那件（见 §5.6） | 拿到并 +1 对应技能 | 被目击 → 犯罪 |

### 5.4 武力：四个玩法

| 玩法 | 怎么做 | 结果 |
|---|---|---|
| **决斗**（主路） | 先一次武力检定看开局（成功 = 他起手慢）→ 非致命决斗 | 赢：让路；输：可换路；**无论胜负关系 −20** |
| 击晕 | 从背后 / 趁不备放倒 | 成功倒地；失败他反击 |
| 威吓（开战前） | 亮兵器逼上前，一次武力检定 | 成功他退开（关系 −10）；失败直接开打 |
| 绑 / 扛 | 制服后用现有绑人 / 扛人把他挪开 | 武力检定；失败挣脱 / 喊人 |

### 5.5 钱：收买与零活

- 玩家**一开始 0 钱**。
- **零活**（不是委托）：跑腿 / 搬货 / 送信 / 把风，**50 第纳尔/次，1 小时冷却**。
- **能买**：守门人打点（100）、消息（几十）、酒。
- **不能买**：势力的工具 / 手艺（只换人情）、仇家的恩怨。
- 钱不够时那条选项**不注入**。

#### 5.5.1 每个人对钱的态度不一样（2026-11-13 用户裁定）

> **一句话**：**"递钱"不是万能键**。同一条动作，三种人三种结果。

| 态度 | 谁 | 当面递钱会怎样 | 怎么才收 |
|---|---|---|---|
| **厚脸皮收** `Open` | 守门人（100）· 寡妇（60）· 儿子（40） | 当着你的面点数，收得干脆 | 直接递 |
| **不当面收** `Covert` | 当铺老板（80） | **把钱推回来**：「我这铺子做的是明面上的生意」 | 改口说"**买**"——换成正经买卖，他才收 |
| **不屑** `Disdain` | 屠户 | **不接**，刀背敲案板：「我卖肉，不卖话」；**关系 −10** | 钱买不到他，只能办事 / 动手 |

- 数据在 `StoryNpcDef.Money / MoneyPrice / MoneyCovertPrice / MoneyHintKey`（一行一个人），**对话只读这张表**。
- 收下钱的人会给一句**实话**（`MoneyHint*`），并给你记一条「被拿捏」隐患；给不屑的人塞钱会掉关系。
- 门卫的**打点**同样过这道闸：只有 `Open` 的人接（`StoryProbeDialogue` 的 `bribe` 分支）。
- 验收：`custom.story_probe money` 打印九个人的态度与价码。

### 5.6 属性道具：偷东西也能涨值

- 每个 NPC 背包里一件（原版书 / 药剂 / 护符当载体，不给新资产）。
- **偷到或委托奖励**得到 → 用掉 / 装备后 **+1 对应技能**（`Hero.AddSkillXp`），不新造属性系统。
- **每件唯一**，不能刷；偷有风险（被目击 = 犯罪 / 警觉）。

| 谁 | 道具 | +1 |
|---|---|---|
| 寡妇 | 护符 / 假印 | Charm |
| 儿子 | 细钩 / 撬锁包 | Roguery |
| 屠户 | 磨刀石 / 护腕 | Vigor / OneHanded |
| 当铺老板 | 账本 | Trade / Charm |

## 六、怎么把玩家拉进来：事件 → 对话

**问题**：玩家站在城门口不会主动找人搭话——他不知道该干嘛。**解法：先出事，再搭话。**

> 本章全部发生在**第二次进城**；第一次场景里只有守门人。

### 6.1 开场 6 起事件

| # | 事件 | 谁 | 玩家 10~20 m 外看到什么 | 接入后 |
|---|---|---|---|---|
| 1 | 收保护费 | thug → 当铺老板 | 两个气泡对着弹，推搡，老板后退 | 第一次和**捉刀人**说话 |
| 2 | 砸摊 | thug → 屠户 | 肉案被掀，屠户举刀，吼声 | **武力**路入口 |
| 3 | 骂街 | 剧团领班 ↔ 对台领班 | 隔街对骂，越走越近 | **魅力**路入口 |
| 4 | 抓小偷 | 当铺老板 → 儿子 | 揪着领子，小孩挣扎 | **技巧**路入口 |
| 5 | 一个人发愁（单人） | 当铺老板 | 反复翻账本、叹气 + 头顶「!」 | 钱路 / 委托引子 |
| 6 | 一个人在收拾（单人） | 屠户 | 扶肉案、蹲下捡东西 + 头顶「!」 | 武力路 / 委托引子 |

**三条硬规则**：

1. **不推进**：事件开演后停在开头状态**自循环**——两个人一直对着吵（`act_conversation_aggressive_loop`）、气泡每 3~5 秒冒一句；单人就一直重复发愁的动作。**不会自己散场，也不会自己结束**。
2. **只有玩家介入才推进**：走近 4 m → 暂停 → 对话 → 选择 → 才收尾。
3. **同时只循环 1 起**：进场 12 秒起第一起；玩家走远（>20 m）才换下一场。

**远距离可见**：
- 循环里持续出声（`SpeechChannel.Say`，`Warning` 优先级）——10~20 m 外就能看到两个气泡反复弹。
- 动作循环播放（`ForcePlayAction`）。
- 背对着也知道：现有 `AgentHudMissionView` 的 `FarHearDistance`（30 m）会在屏幕给一行提示。
- 单人事件没对手可吵，只能靠「!」+ 反常举动吸引人。

**头顶「!」**：参与者挂标记，复用现有头顶 HUD（`AgentHudVM.HasEventMark` + `AgentHudNearby` 加一个图标位），不新建 UI；事件结束或玩家接入后消失；没轮到的人不带。

### 6.2 玩家接入

| 玩家行为 | 系统反应 |
|---|---|
| 走进 4 m | 事件**暂停**，双方看向玩家 |
| 停约 2 秒 | **自动开对话**（原版对话流） |
| 第一句 | 事件里的人冲你说一句（「看什么看」/「客人，稍等」） |
| 选项 | 【帮这边】【帮那边】【问怎么回事】【走开】 |
| 选【走开】 | 回到循环 |

**接入 = 搭话**：这就是五步关系里的第 ① 步；之后按 F 才能继续打听。不介入也不会卡——它一直循环，没有「错过」。

### 6.3 对话：走原版对话流注入，不自建面板

| 步 | 玩家做了什么 | 走哪个现有件 |
|---|---|---|
| 1 | 从事件接入，或走近按 **F** 交谈 | 原版 `StartConversation` |
| 2 | `ConversationEntryPatch` 在 `hero_main_options` 挂一个入口选项 | `DialogueInjector.InjectScript`（Gateway 模式） |
| 3 | 点进去 → 节点树（NPC 一句 + 几个玩家选项） | v2 模型：`DialogueNode` + `DialogueTransition` |
| 4 | 点选项 → 执行 → 路由到下一个节点或关窗 | `CheckType.None` / `SkillCheck` |

- **注入统一收口 `StartConversation`**：调用方只设 trigger，不自己 `InjectScript` 再 `StartConversation`（会双重注入）。
- **数据**：`ModuleData/DesignData/Dialogues/story_probe_<npc>.json`，一个 NPC 一个文件。

**选项的写法**：
- 每条就是一句玩家台词，前面带方括号标类别：`【打听】三个月前，有没有见过一个穿青布的姑娘？`
- **不显示百分比**（原版对话流不支持）：靠措辞给线索——`【试着唬他】没你的事，让开。`
- 条件不满足的选项**不注入**（不是置灰）；想说明原因，让 NPC 那句台词点一句。
- 问过的事不再注入；【离开】用原版自带。

### 6.4 五步关系

| 步 | 节点 | 玩家选项 | 什么时候注入 | 结果 |
|---|---|---|---|---|
| ① 搭话 | `<npc>_intro` | 【搭话】先问一句 | 第一次见 / 事件接入 | 自我介绍 + 态度；解锁 ② |
| ② 打听 | `<npc>_ask1..3` | 【打听】……（每人 2~3 条） | 搭过话 | 妹妹线索 / 他的三维 / 怎么过门；不检定 |
| ③ 求 | `<npc>_deal` | 【求】把东西借我 / 教我一手 | 打听够了 | 派一个委托 |
| ④ 交差 | `<npc>_turnin` | 【交差】事情办完了 | 委托已完成 | 给东西 / 教一手；关系 + |
| ⑤ 熟人 | `<npc>_chat` | 【闲聊】【还有活吗】 | 交差之后 | 口吻变热络，给钩子 |

没打听就求 → 走「拒绝」分支（「你先去问问别人」），不锁死。

### 6.6 台词规范

- **三段式**：选项标签 = 玩家想做的事（第一人称、短）· NPC 回应 = 角色口吻（一句，能听出职业和处境）· 旁白 = 世界反馈（只在大事发生时才出现）。
- **口吻定位**：

| NPC | 口吻 | 忌 |
|---|---|---|
| 当铺老板 | 客气里带账本，句句不离钱 | 文绉绉 |
| 寡妇 | 演戏的腔，刀子嘴，护短 | 骚气（她是领班，不是花魁） |
| 儿子 | 快嘴、爱吹、心虚 | 老成 |
| 屠户 | 闷、硬、话少，一次不超过两句 | 长篇大论 |
| 守门人 | 冷硬短句，不说整话 | 解释自己 |

- **同一个人两套说法**：第一次见（防着你）→ 交差后（认你）。
- **失败台词必须写**：失败不是「没事发生」，是「他记住了你」「他警觉了」。
- **键名**：`LWN_story_<npc>_<步>_<序>`，中英各一套，全走 `LWNTextHelper`。量级：6 个 NPC × 8~12 句 ≈ 70 个键。

### 6.7 NPC 主动开口

| 触发 | 说什么 |
|---|---|
| 玩家走近 3 米 | 寡妇「看戏吗？站远点也行，别挡人。」/ 儿子「嘘——」/ 守门人「站住。」 |
| 玩家掏出武器 | 守门人「收起来。」/ 屠户「在我摊子前头别动刀。」 |
| 玩家交差后 | 老板「来了？账我记着呢。」 |
| 冷却 | 每人 30 秒；走 `SpeechChannel.Say`（模板，不默认调 LLM） |

### 6.8 屏幕目标

左上角一句话，随进度换一行（不做任务栏）：

| 阶段 | 那句话 |

| 刚进场景 | 进城。城门有人拦着——问问门口这几家。 |

## 七、NPC 自己会动

### 7.1 三层行为

| 层 | 谁做 | 频率 | 玩家看到什么 |

| 常驻动作 | 每人自己 | 8~20 秒一次 | 拨账本、挥手、探头、抖腿；偶尔一句吆喝 |

### 7.4 对玩家的反应

| 触发 | 反应 | 冷却 |
|---|---|---|
| 进 3 米 | 转头看 + 一句招呼 / 警告 | 30 秒 |
| 掏出武器 | 后退半步 + 一句警告 | 10 秒 |
| 犯罪（偷 / 打） | 中断行为 → 喊人 / 逃跑（`NpcSightSystem` + 警戒） | — |
| 交差之后 | 招呼换热络版 | — |

### 7.5 技术口径

- 一个 `StreetLifeDirector`，挂在 `StoryProbeMissionBehavior.OnMissionTick` 里，不新建 MissionBehavior。
- 每人一个状态：`Idle` / `Performing` / `Talking` / `Reacting`。
- 播动作：`ForcePlayAction`，**只在站桩（`IsInStayMode`）时播**——走路 / 打架 / 对话时让位。
- 说话：`SpeechChannel.Say(..., forwardToNearby: false)`（只冒泡，不进附近频道）。
- 走位：投事件给 `AgentAIController.SendEventToAgent`，不直接碰 Brain 队列。
- **不冻结 AI**：城镇里 `SetIsAIPaused` 会把行走输入冻在最后一帧（人反而直走不停）。
- 只接管我们 spawn 的这几个人，**原版村民 / 守卫一点都不动**。
- 行为写进 `StoryProbeDefs` 的静态表（`StreetLifeDef` / `StreetSceneDef`），加一条 = 加一行。

## 八、检定

### 8.1 同类对拼

**检定 = 玩家的某类属性 vs NPC 的同一类属性**，各比各的：

| 玩家 | NPC 拿什么 | 底层数值 |
|---|---|---|
| 武力 | 武力 | Vigor + Control |
| 技巧 | 技巧 | Roguery |
| 魅力 | 魅力 | Charm |

```
chance    = playerAttr / (playerAttr + npcAttr)     玩家侧钳制 [5%, 95%]
threshold = 1 − chance                             掷点 ≥ threshold 即成功
```

**NPC 三维直接填数值**（不读随机生成的 Hero 技能，保证难度一致）；模板 NPC 按 Level 估算。

### 8.2 NPC 三维表（初值，实机再调）

| NPC | 武力 | 技巧 | 魅力 | 玩家该用什么 |
|---|---|---|---|---|
| 守门人 | 70 | 30 | 50 | 硬拼难；技巧最顺 |
| 屠户 | 70 | 50 | 30 | 打他难；骗他容易 |
| 寡妇 | 30 | 50 | 70 | 吓她容易；嘴炮难 |
| 儿子 | 30 | 70 | 30 | 偷他难；骗他容易 |
| 当铺老板 | 30 | 50 | 70 | 吓他容易 |
| 对台领班 | 30 | 50 | 70 | 偷 / 吓比嘴炮容易 |
| 野贼 | 30 | 70 | 50 | 骗他比偷他容易 |
| thug | 70 | 30 | 30 | 绑 / 骗比硬打容易 |
| debtor | 50 | 50 | 50 | 三条路差不多 |

**打听 = 把这张表的数字告诉他**：聊过之后 `check` 里显示这个 NPC 的三维，玩家自己判断走哪条路。
**钱不参与对拼**：收买不检定。

### 8.3 结果与显示

- **只有成功 / 失败**（现有检定本身就是 bool），不做大成功 / 大失败。
- 对话节点里：`CheckType.SkillCheck` → 成功 / 失败各走一个节点，两段台词都要写。
- **不显示百分比**（原版对话流限制）；要看精确数值用 `custom.story_probe check`。
- 掷完提示：「掷点 X% vs 门槛 Y% → 成功 / 失败」（铁律 17：不写成功率以外的难度措辞）。

## 十、nobody 状态

**剥夺发生在坐牢那一刻，不是进场景时**：

| 时机 | 发生什么 |
|---|---|
| 第一次进城被打倒 | 进牢：**武器 / 甲 / 钱袋全部没收**（记原始值，序章完成恢复） |
| 出狱时 | 只留**旧衣 + 面罩**（魅力线「遮面」的底子） |
| 第二次进场 | 已经是 nobody，不必再收一次 |

- **只动场景 agent 与英雄身上那套**：战役装备不销毁，记下来最后还。
- **中途存档 / 读档**：保留「已剥夺」状态。
- **通知**：出狱时一条「你身上没武器，钱袋也空了」。
- **已知限制**：不锁背包（玩家能从背包重新装备）；武力走 Peace 决斗时现有逻辑会把随从扫到一边。

### 12.1 命令（游戏内控制台）

```
custom.story_probe enable
custom.story_probe disable
custom.story_probe city town_ES4
custom.story_probe status
custom.story_probe enter
custom.story_probe intro
custom.story_probe phase first
custom.story_probe phase second
custom.story_probe where
custom.story_probe spawn
custom.story_probe check 魅力
custom.story_probe check 技巧
custom.story_probe check 武力
custom.story_probe roll 魅力 95
custom.story_probe roll 技巧 5
custom.story_probe roll 武力 50
custom.story_probe learn 魅力
custom.story_probe learn 技巧
custom.story_probe learn 武力
custom.story_probe resolve 魅力
custom.story_probe strip
custom.story_probe restore
custom.story_probe reset
custom.story_probe talk 老板
custom.story_probe goal 2
custom.story_probe life status
custom.story_probe life list
custom.story_probe life force 老板 0
custom.story_probe life scene 1
custom.story_probe life stop
custom.story_probe life resume
custom.story_probe event list
custom.story_probe event force 2
```

- 返回文本**纯英文**；首参可弃。
- `check <能力>`：打印技能 / 属性、成功率、门槛、情境；不改状态。
- `roll <能力> <0~100>`：强制下一次掷点（验成功 / 失败）。
- `learn` / `resolve`：跳过流程强制学 / 强制结算。
- `strip` / `restore`：单独测 nobody。
- `status`：阶段 / 城池 / 三门 / 关系 / 天赋点 / 隐患 / 是否剥夺 / 是否完成 / 每个 NPC 的步数。
- `where`：打印门外点 / 城门 / 目标点坐标与距离，以及用的是场景点还是兜底。
- `talk <npc>`：不走近直接开对话（验节点树）。
- `phase first|second`：强制切到第一次（必败教学）或第二次（完整序章），不用重开档。
- `goal <0~4>`：强制切屏幕目标。
- `life status|list|force|scene|stop|resume`：行为调试。
- `event list|force <1~6>`：事件调试。

### 12.2 手工验收清单

1. `enable` 后进 `town_ES4`，菜单出现「入城（玩法测试）」；点它**先弹窗**，点【再想想】不进场景。
1a. **第一次必败**：进场只看到守门人（**没有四家和事件**）；谈话后动手 → **必败倒地** → 黑屏；`phase first` 可直接复现。
1b. **牢房弹窗**：黑屏后弹「旧衣服和面罩」；点【换上】→ 出狱、装备与钱被没收、只剩旧衣 + 面罩（`status` 可见 `Disguised`）。
1c. **第二次**：再进 → **酒馆自动招到一个随从** → 随从说 3 句 → 四家与 6 起事件就位；`phase second` 可直接跳到这一阶段。
2. `where` 打印的坐标与 §3.3 一致；玩家站在门外、面向城门；换城打不出场景点时显示 `fallback` 且仍能跑。
3. 第二次进场：玩家穿旧衣 + 面罩、空手、0 钱；收到提示。
4. 原版「在城里逛逛」进场景：不加载玩法。
5. **事件**：进场 12 秒第一起开演，参与者头顶「!」，气泡每 3~5 秒一句；**不介入就一直循环、不推进、不散场**；走近 4 m 暂停并自动开对话；选【走开】回到循环。
6. **事件类型**：4 起双人（收保护费 / 砸摊 / 骂街 / 抓小偷）与 2 起单人（发愁 / 收拾）都能看到；单人只靠「!」和反常举动。
7. **对话**：按 F → 原版界面 → 入口选项 → 节点树；五步能推进；问过的不再出现；检定成功 / 失败走不同节点；屏幕目标随阶段换。
8. **自发行为**：站着不动 60 秒，能看到常驻动作与随机桥段；`life stop` 后变木头。
9. **魅力**：穿贵族制服 → 守门人误认（「阁下」）→ 让路；被识破 → 警觉；通缉状态乔装能脱险。
10. **钱**：钱够打点就过；不够那条选项不出现；留下「被拿捏」。
11. **技巧**：钩索翻过去；扒窃 / 撬锁 / 潜行各验一条；失败能换路。
12. **武力**：决斗打赢能过；打输能换路；关系 −20；击晕 / 威吓 / 绑扛各验一条。
13. **委托**：求屠户 → 教训 thug → 交差拿到武器 + 绳子；`status` 显示委托状态与关系。
14. **属性对拼**：不同 NPC 的 `check` 成功率不同；打听过之后三个数字直接显示。
15. **选路反馈**：势力关系 / 天赋点 / 结仇 / 隐患都能看到。
16. 走到门内目标点：序章完成、金钱恢复；再进不重开。
17. 存档 / 读档：阶段、步数、关系、旗标、剥夺状态保留。
18. 酒馆 / 领主大厅 / 别的城不触发；`disable` 后不触发。
19. 两个客户端各编译一次；`run_all_checks.py` 通过；新增文本无 emoji、无裸中文。

## 十四、设计原则对照

- **反馈明确**：帮忙、检定成功 / 失败、势力关系、天赋点、结仇、隐患，全部当场可见；每个选项点了都有台词回应，失败也有话说。
- **自由感**：四家可全帮；每种能力任选一条；失败能换路；打听可以跳过——直接偷 / 打 / 买也行，代价是拿不到线索和他的底。
- **NPC 接得住**：全是原版 Hero；对话 / 钩索 / 战斗都是现有系统；玩家不找他说话时他也在过日子，插话有反应。
- **信息塑造目标**：先看到出事，才去搭话；不是一上来就知道「三种能力」；屏幕角上只有一句话目标，不摆任务列表。

### 15.5 已实现但需要实机确认的三件事

1. **模板外观**：9 个 Hero 的模板 id 是按"职业像不像"挑的（`merchant_empire` / `female_dancer_empire` / `blacksmith_empire` / `veteran_caravan_guard_empire` / `civillian_template_gangster_tier1/2` / `merchant_notary_empire` / `musician_empire` / `looter`），两轮查找已在代码里；**好不好看要进场景看**。

### 15.9.0 钩索不是白给的，也不是无敌的（2026-11-13 用户追问后补）

- **来源**：不是买的。**儿子的委托奖励**——替他打发墙根抢了他钩子的野贼，交差才给绳 + 钩。玩家开局 0 钱、无武器、无钩索、无身份。
- **不是无敌**：原来只要被钩索拉过 2 m 就开门，**不管守门人看没看见**。现在加视线判定（与潜行同一套朝向点积）：
  - 他没看着你 → 翻过去了，门开；
  - 他正看着你 → 他喊人，**门不开**（落地照样被弹回门外），并记一条隐患 `hazard_climb_seen`。
- **和技巧挂钩（2026-11-13 补）**：翻墙不只是"位置对就行"——**每次腾空要掷一次技巧**（对拼守门人的 30）。
  勾住了才过去；**失手 = 钩子滑了**（播一行「什么动静？」），门不开、记 `hazard_climb_missed`，落地被弹回门外。
  一次腾空只掷一次，落地后重新计。
- **钩索不消耗**：钩子是弹药（`stack_amount=20`，打一发后被钉回 1），钩头会回收 —— 它是工具不是消耗品；
  所以限制它"不能无敌"的手段是**检定 + 视线**，不是消耗次数。
- **绳长与准度都吃技巧（2026-11-13 用户裁定）**：钩索原来的三个手感常量（射程 30 / 绳长 33 / 零散布）全部改成按 Roguery 缩放（`GrappleLogic.SkillScaling`）：

  | 技巧 | 有效射程 | 绳长上限 | 出手散布 |
  |---|---|---|---|
  | 0 | 16.5 m | 19.5 m | 7.0° |
  | 50 | 25.5 m | 28.5 m | 3.8° |
  | 100 | 34.5 m | 37.5 m | 0.6° |

  实现：`EffectiveAimRange`（射程）/ `SpreadDegrees` + `ApplySpread`（按面积均匀的圆锥采样）/ 出手时把 `_rope.MaxLength` 同步成"有效射程 + 3"。**玩家与 NPC 同一套**（Hero 读真实 Roguery，模板 NPC 读模板技能）。
  调参/验收：`custom.grapple skill`（打印当前值与本角色此刻的射程/散布）、`custom.grapple skill on|off`、`custom.grapple skill <min,max,maxDeg,minDeg>`。
- **绑走 / 扛走**也要付代价：动的是码头帮的人，记 `hazard_dragged_the_guard`。
- 于是钩索带来的是"**条件更好的三条路**"，不是"一键通关"。

### 15.9.1 玩家路径（按体验顺序走一遍）

**第 0 步 · 把玩家送到城下**
`custom.story_probe enable` → `custom.story_probe goto`（主队瞬移到 吕卡隆 城门）→ 从地图进城。

**第 1 步 · 城门菜单 → 弹窗 → 第一次进场**
1. 城镇菜单多出「入城（玩法测试）」。
2. 点它 → 弹窗（4 句背景）→【硬闯】。
3. 🔧 **出生点**：原版城镇中心的默认出生点是 `sp_player`(480,367) —— **已经在城里**；序章要求从门外来，已显式指定 `sp_outside_near_town_main_gate`(435,387)。
4. 场景里只有守门人一个剧情 NPC。往城门走：
   - 走到 3.5 m 内 → 自动开口（守门人要通行文书）；
   - 🔧 **直接绕过去**（跨过守门人 1 m 或贴近门内点）→ 当场被按倒，**不会漏掉教学**；
   - 🔧 谈过一次后走开 8 m 再回来，会**重新**自动开口（原来只触发一次）。
5. 【动手】或硬闯 → 强制倒地（不掷骰）→ 4.2 秒后任务结束。

**第 2 步 · 牢房**
- 结束 Mission 后弹「牢里」（🔧 不再要求"必须站在目标城菜单"，站地图上也照弹）。

**第 3 步 · 第二次进场（序章正式开始）**
- 再点「入城（玩法测试）」→ 直接进场景（不再弹窗）。
- 随从（酒馆/城里招一个 Wanderer）在左后 1.5 m 说 3 句（**只播一次**）。
- 四家代表 + 守门人 + 三个仇家就位；12 秒后第一起事件开演。

**第 4 步 · 门口这四家（任选其一或全做）**

| 你找谁 | 打听 | 求 → 他派什么 | 办完得到 |
|---|---|---|---|
| 当铺老板（捉刀人） | 妹妹线索 ①、守门人弱点（怕麻烦、100 打点） | 找收数人讨 120 的账 | 30 第纳尔 + 护符 + 守门人情报 |
| 寡妇（剧团） | 妹妹线索 ② | 砸对台的招牌 | 贵族行头 + 通行文书（冒充用） |

| 屠户（叛逃者） | 妹妹线索 ④ | 教训砸摊的 thug | 刀 + 绳子 |

- 没钱也能活着：跟当铺老板做零活（50 第纳尔 / 次，1 小时冷却）。
- **塞钱看人**：守门人 / 寡妇 / 儿子当面就收；**当铺老板会推回来**（得改口说"买"）；**屠户不收还会掉关系**（§5.5.1）。

**第 5 步 · 过门（六条路，任一条都通）**

| 路 | 条件 | 代价 / 风险 |
|---|---|---|
| 钱 | 身上 ≥100 第纳尔 | 钱归守门人；被拿捏（关系 −5） |
| 武力·威吓 | 武力检定（对拼守门人 70） | 成功他退开（关系 −20 + 通缉）；失败直接开打 |
| 魅力·冒充 | 有贵族行头（寡妇那条线） | 魅力检定；被识破 → 警觉 |
| 技巧·潜行 | 技巧检定 | 失败 → 他盯上你 |
| 技巧·钩索 | 有钩（儿子那条线）+ 技巧检定 | 同样的检定，代价更小 |
| 武力·决斗 | 直接动手，把他打倒在地 | 赢了门开；输了可换路 |

- 🔧 **门没开就过不去**：越过守门人或贴近门内点会被**弹回门外**（守门人喊「通行文书」）；

## 十七、场景演出脚本（2026-11-13 立，**待审批**）

> **一句话**：先定一套**原子指令**（每一条做一件最小的事），再用一张可编辑的**指令流**把它们串成"布景 → 摆人 → 玩家出场"。四拍不是写死的代码，是这串指令跑出来的结果。

### 17.1 为什么必须先有原子

现在设想的"四拍"是**写死的一段戏**：想加一个「打手一脚踢翻肉案」，就得改 `StoryProbeMissionBehavior.cs` 重新编译。

有原子指令之后，同一件事 = 台本里加两行：

```
{"at":8.0,"cmd":"actor_action","actor":"thug","action":"act_bully"},
{"at":8.0,"cmd":"prop_move","id":"butcher_block","anchor":"gate","fwd":3.0,"right":-2.0}
```

**判据**：台本里出现某件事时，代码一行都不用动。

### 17.2 原子指令表（第一版 9 条）

| 原子 | 做什么 | 参数 | 落在哪个 API | 状态 |
|---|---|---|---|---|
| `player_freeze` | 冻住玩家输入 | — | `V.SetPlayerControlFrozen(a,true)` | ✅ 现成 |
| `player_release` | 解冻 | — | 同上 `false` | ✅ 现成 |
| `camera_cut` | 切到指定机位 | 机位 id（`Camera.csv` 的行） | `CameraService.ApplyPose(...)` | ✅ 现成 |
| `camera_return` | 交还引擎相机 | — | `CameraService.Stop()` | ✅ 现成 |
| `prop_spawn` | 生成一件场景物件 | prefab / 锚点 / 偏移 / 朝向 / 缩放 | `GameEntity.Instantiate` | ✅ `custom.spawn_prefab` 验过 |
| `actor_place` | 把人瞬移到位 | 角色 / 锚点 / 偏移 / 朝向 | `TeleportToPosition` + `HoldInPlace` | ✅ 已用 |
| `actor_action` | 让他播一个动作 | 角色 / `act_*` | `AgentControlHelper.ForcePlayAction` | ✅ 已用 |
| `actor_say` | 头顶冒一句 | 角色 / 文本键 | `SpeechChannel.Say` | ✅ 现成 |
| `wait` | 等 N 秒 | 秒 | Mission tick 计时（不用 Task.Delay） | 新增·简单 |

**第一版不做**（留口）：`actor_enter`（从场外走进来）、`actor_move`、`actor_leave`、`dialogue`、`prop_move`、`fx_*`。

**加原子 = 加一个 `case`**：`StoryStageDirector` 里一个 `switch(cmd)`，一条指令一个分支，没有共用状态。

### 17.3 语义位（原子参数怎么落到场景）

台本里不写坐标，写**语义位**，运行时代码去场景里找：

| 语义位 | 场景实体 | 本场景数量 | 怎么解 |
|---|---|---|---|
| `entry` | `sp_outside_near_town_main_gate` | 1 | 直接取 |
| `gate` | `sp_guard_with_spear` | 30 | 取离入场点最近的那个 |
| `market` | `sp_merchant` | 8 | 同上 |
| `idle` | `sp_npc_idle` | 34 | 同上 |
| `argue` | `sp_npc_argue_set` | 26 | 同上 |
| `player` | 玩家开场点 | — | 直接取 |

解不到 → 退回 `player` 并**打日志报警**（不静默）。

### 17.4 台本 = 一张可编辑的指令流

**格式用 JSON，不用 CSV。** 理由：每条指令参数都不一样（布景要 prefab 和缩放，冻结什么都不要），CSV 会变成一大片空格子；而且本工程的对话树本来就是 JSON（`ModuleData/DesignData/Dialogues/*.json`），同一个目录、同一套习惯。

文件：`ModuleData/DesignData/Stage/story_probe_gate.json`

```jsonc
{ "script": "story_probe_gate", "beats": [
  { "at": 0.0, "cmd": "player_freeze" },
  { "at": 0.0, "cmd": "camera_cut", "case": "story_intro_gate" },        // 先对着城门，布景在画面外

  { "at": 0.2, "cmd": "prop_spawn", "id": "butcher_block",
    "prefab": "bd_table_c", "anchor": "gate", "fwd": 2.5, "right": -1.0, "yaw": 90, "async": true },

  { "at": 0.5, "cmd": "actor_place",  "actor": "butcher",
    "anchor": "gate", "fwd": 0.8, "facing": -1 },                        // facing=-1 面朝玩家
  { "at": 0.5, "cmd": "actor_action", "actor": "butcher", "action": "act_bartender_meat", "async": true },

  { "at": 1.5, "cmd": "camera_cut", "case": "story_intro_wide" },        // 布景完成，镜头才转过来
  { "at": 3.0, "cmd": "camera_return" },
  { "at": 3.2, "cmd": "player_release" }
] }
```

### 17.5 时序控制（照太阁那套）

| 语义 | 写法 | 用在哪 |
|---|---|---|
| **等它做完**（默认） | 不加标记 | 摆人、切镜头 |
| **不等** | `"async": true` | 布景、播动作、喊话 |
| **等一组都做完** | 挂 `"group": "x"` + `{"cmd":"sync","group":"x"}` | 九个人都摆好了再转镜头 |

**纪律**：只有明确不需要等的才标 `async`（布景/动作/镜头）；**切镜头和有玩家看的东西永远等**。

### 17.6 玩家出场这一段（用原子写出来）

| 时刻 | 指令 | 玩家看到 |
|---|---|---|
| 0.0s | `player_freeze` | 动不了 |
| 0.0s | `camera_cut story_intro_gate` | 镜头对着城门空场 |
| 0.2s | `prop_spawn ×N`（async） | **画面里看不到**（镜头背对广场） |
| 0.5s | `actor_place ×9`（async）+ `actor_action ×9`（async） | 同上 |
| 1.5s | `camera_cut story_intro_wide` | 镜头转过来，场面已经摆好 |
| 3.0s | `camera_return` | 镜头回到玩家 |
| 3.2s | `player_release` | 能动了 |

⚠️ **解冻顺序不能反**：切 Controller 会让引擎重置相机（`CameraBearing`=移动方向、`CameraElevation`=0）。必须"交还相机 → 等稳定 → 解冻"。

### 17.7 验收命令（每个原子都要能单独打）

```
custom.story_probe stage list                 // 打印台本解析结果 + 每个语义位的实际坐标
custom.story_probe stage only <行号>           // 只播某一条指令
custom.story_probe stage reload               // 重读 JSON，不重启游戏
custom.story_probe atom <原子名> <参数...>      // 单独打一个原子（调试用）
  例：custom.story_probe atom prop_spawn bd_table_c gate 2.5 -1.0
      custom.story_probe atom actor_action butcher act_bartender_meat
```

**没有 `atom` 这条，调试只能整段重演** —— 加一个物件要等 3 秒出场演完，没法用。

### 17.8 代价与风险

1. **prefab 必须是本场景已加载的**：`GameEntity.Instantiate` 对不存在的返回 null。每件都打 `[StoryStage] spawn <id> (<prefab>) ok|fail`。
2. **生成的物件不进 NavMesh**：人和玩家可能穿过去。布景不能摆在必经路上。
3. **布景不入存档**：每次进场景重新生成（这正是演出脚本要的）。
4. **出场镜头**：`Camera.csv` 现有 21 个 case 全是"对着人"的，要新增两个"看场面"的宽机位，参数得实机调。

### 17.9 不做的事

- 不做通用演出引擎（那是 `plans/scenario-campaign-mode/05-演出系统.md` 的范围）。这里只做**能跑序章这一场**的最小原子集。
- 不造新资产：布景只用本场景已加载的 `bd_table_a/b/c/d/e`、`bd_barrel_*`、`bd_cart_*`、`carpet_empire_a`。

## 十九、台词写作标准（2026-11-13 用户裁定）

> **一句话**：这是 3D 游戏，不是 AVG。**演不出来的动作不写，心理描写不写，每句话都要说清谁对谁说。**

### 19.1 三条硬规则

1. **格式**：每句台词写成 `（说话人，听话人）：文本`。
   - 玩家自己的话也是台词：`（玩家，老周）：女的，穿青布，三个月前进城。`
   - NPC 之间：`（打手，老周）：钱呢？这月的。`
   - 英文同构：`(Thug, Old Zhou): The money. This month's.`
2. **禁止心理描写**：不写「他心里一沉」「他知道自己完了」这类读者才知道的东西。
3. **禁止演不出来的动作**：写进对话的动作，必须是场景里真能播的（有动作、有道具、有演出）。
   **做不到就不写** —— 写了玩家也看不到，只会让文字显得假。

唯一的例外是**结果播报**：`（旁白，玩家）：路让开了。` —— 它不是动作描写，是给玩家的反馈。

### 19.2 这条规则带来什么后果

- 开场那几段「（他驼着背，正拨着算盘……）」全部删掉 —— 换成**真的布景与动作**（`StoryStage.json` 里生成桌子、播 `act_bartender_wipe`）。
- 原先靠旁白交代的信息，要么变成 NPC 说出来，要么交给演出，要么就不存在。
- 页面/文档里若还写着「他拨着算盘」而游戏里没这张桌子，那就是**文案撒谎**，按本规则应当删。

## 二十、台词配动作（2026-11-13 立）

> **一句话**：每句台词配一个原版动作，动作写进数据；**动作必须在该 NPC 的 action set 里**，否则播了没反应。

### 20.1 硬约束（这条是这次挖出来的大坑）

`Native/ModuleData/monsters.xml`：`<Monster id="human" action_set="as_human_warrior" …>`。
我们的剧情 NPC 全是 `human` ⇒ **只有 `as_human_warrior` 里的动作播得出来**。

实测后果：原来给 9 个人配的常驻动作里，**16/19 条播不出来** ——
`act_bartender_wipe`（抹柜台）/ `act_beggar_idle`（蹲着讨钱）/ `act_bartender_meat`（剁肉）/
`act_play_celtic_harp_stand`（弹竖琴）/ `act_bully` / `act_stealth_mission_guard_*`
全部只存在于**职业专用集**（`as_human_tavern_keeper` / `as_human_beggar` / `as_human_musician` / `as_human_hideout_bandit`）。
⇒ 已全部换成 `as_human_warrior` 里真有的对话手势。

### 20.2 数据与运行

- 正本：对话节点里的 `NpcActions` 字段
  `key → 动作数组`，**数组长度 = 这句台词的中文行数**，`""` = 这行不配动作（玩家/旁白）。
- 运行：`SayOnAgent` 播台词时，按行依次延迟 2.2 秒播动作（`StoryLineActions.PlayFor`）。
- 初稿生成器：`Scripts/gen_line_actions.py`（说话人气质定风格 + 语气定情绪）；定稿由人改 JSON。
  现有 **163 个键 / 330 条动作**，全部落在 `as_human_warrior`。

### 20.3 生效的动作库（速查）

| 类别 | 动作 |
|---|---|
| 风格 × 情绪 | `act_conversation_<aggressive\|closed\|confident\|demure\|hip>_<start\|loop\|trivial\|positive\|negative\|very_negative\|unsure>` |
| 专项 | `talk_explain` / `talk_commenting` / `talk_dunno` / `talk_crossedarms` / `talk_promise` / `threat_arm` / `threat_point` / `point_somewhere` |

### 20.4 验收

```bash
python Scripts/check_story_probe.py     # 动作是否可播 + 条数是否对齐；必须 problems=0
```

```

→ OK: ... resolves in this agent's action set (index=N)
→ NO: ... is NOT in this agent's action set (plays nothing)
```

`.claude/skills/story-line-action/SKILL.md` —— 下次要配动作时直接走它，不用重新摸。

### 4.1 当铺老板 · 老周（`pawnbroker`）

**六十岁上下，驼背，左手缺半截小指。** 早年跑过南北货，赔光了本钱，在这城门口盘下这间当铺。他不算好人——放贷收利、压价收当——但他守着一条：从不逼死人。码头帮每月来收保护费，他给了三年，账本上记得清清楚楚，一笔不落。

- **他想要**：安稳做到死，别惹事。
- **他怕**：码头帮砸摊（他见过隔壁绸缎庄被砸成什么样）。
- **他在意**：账本。他记账比记人清楚。
- **口头习惯**：先说价，再说事；爱用「童叟无欺」这种生意人的套话，但底下是精明。
- **对玩家的态度**：一开始只当是又一个穷鬼；玩家帮他收账之后，他真会拿你当半个自己人——因为三年了没人替他出过头。

### 22.2 本轮定死的几条

1. **一个节点头最多两行**；拆节点靠追问，不靠"听他说下去"这种假选项。
2. **选项文字 = 玩家说出口的话**，不是界面提示。
3. **每个选项指向专门回答它的节点**；两种问法进同一节点 = 第二次问会得到一样的回答（已清）。
4. **问句不许弹回菜单**（已清「所以你也知道不少事？→还有事？」这类）。
5. **只有一张菜单**：原来的 `*_hub`（"还有事？"）全部合并进开场节点，8 个 NPC、节点 110 → **102**。
6. **一屏最多四个无条件选项**，多的挂显示条件分批放（`Requires` / 只问一次）。
7. **主动掏钱的选项必须有叙事理由**（四家开场「递钱/塞钱」全部挂条件，不再首屏可点）。
8. **每句台词的动作写在节点自己的 `NpcActions` 上**（与行数一一对应），`StoryLineActions.json` 已删除。
9. **动作必须在该 NPC 的 action set 里**（铁律 41）：`monsters.xml` 写明人形默认 `as_human_warrior`；
   职业集（`as_human_hideout_bandit` / `as_human_musician` 等）里的动作**播不出来**——已补注册 13 条到 `as_human_warrior`。

### 22.3 页面现在的样子

- **可折叠树**：点选项才展开对方的回答，默认全收起
- **每个节点只展开一次**，再走到就是 `↩ 回到前面「还有事？」`，不再重复铺开
- **已点过的选项变淡并打 ✓**（游戏里做不到，用"只问一次"直接消失代替）
- **顶部勾选框**：默认只显示"当前能满足条件"的选项；勾上才显示被条件挡住的（半透明 + 条件徽标）
