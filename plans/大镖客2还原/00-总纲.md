## 5. 资产自动化（为什么不用 ModKit 手工导入）

- 唯一网格 **10,076 个**、贴图 **3,236 张**；ModKit 导入是「右键 → Import → 确认」，**没有批处理**，一万件 ≈ 8.3 小时纯点击。
- 三条路里选 **C. 直写 tpac**：`tools/tpactool` 是我们 fork 的 TpacTool，`makepack`（PNG → 贴图资产）已在游戏里跑通（立绘包 `lwnprof_*.tpac`）。

**现有工具链**：

| 命令 | 作用 |
|---|---|
| `tpaccli makepack` | PNG → Texture 资产包 |
| `tpaccli assetclone` | 克隆原版资产（metamesh + 材质 + 贴图）并改名 |
| `tpaccli texreplace` | 换贴图像素（支持任意尺寸、生成 mip） |
| `tpaccli meshmake` | RMDL1 网格 → Metamesh（`--lods 0,1,2,3` 出多档） |
| `tpaccli matflags` / `inspect` / `dump` | 改材质 flag / 看字段 / 导 OBJ→PNG |

**判定口径**：`tpaccli list` 资产数对得上；游戏里 `custom.spawn_prefab` 看得见、贴图对、无 `RGL CONTENT WARNING`；重跑两次字节一致。

## 6. LOD（只针对「真实城镇场景」，地图图标另算）

### 6.1 现状

- RDR2 交接包**没有 LOD 链**（每个原型只有最高精度网格）；全量按 LOD0 摆 = **3.36 亿面**。
- RDR2 自己的 `_slod` 是整片区域合并低模，不能当「一栋房子一套 LOD」用。

### 6.2 场景模型 LOD 规划

| 级别 | 距离 | 单件目标面数 | 做法 |
|---|---|---|---|
| LOD0 | 0~15 m | ~2,000 | 保留轮廓/门窗，削内部与背面 |
| LOD1 | 15~40 m | ~800 | 焊接顶点 + 减面 |
| LOD2 | 40~100 m | ~300 | 去栏杆/雨棚/招牌 |
| LOD3 | 100~250 m | ~100 | 体块 + 屋脊 |
| LOD4 | 250~600 m | 20~30 | 体块 + 屋顶 |
| LOD5 | 600~1,500 m | 6~12 | 双面片 / 交叉公告板 |
| LOD6 | >1,500 m | 2 | 单公告板 / 纯色块 |

**按 prefab 做，不按实例做**；先剔 `in_lib=0` 与 `cls=0`；单场景 LOD0 可见 ≤ 40 万面，配合 LOD1~2 ≈ 60 万面。

> 🔴 **LOD6 ≠ 大地图图标**。LOD6 是场景里"远到看不见"的保底面片；大地图图标是另一套独立资产（§7.0）。

### 6.3 引擎侧未验的一件事

骑砍 MetaMesh 每层网格带 `Lod` 序号，但**切换距离是引擎固定的**——P0 要量出"第几档在多少米切换"，再决定档位分配，不猜。

## 7. 大地图与场景

### 7.0 🔴 两套资产，别混

同一个圣丹尼斯要做**两个完全不同的模型**：

| | ① **大地图缩略模型**（Main_map 上的据点图标） | ② **真实城镇场景**（进城后的 Mission 场景） |
|---|---|---|
| 用途 | 大地图上"代表"这座城，俯视一眼认出 | 玩家走进去的实景 |
| 比例 | **1 : 29**（约 20 场景单位宽） | **1 : 1 米**（862×955 米） |
| 资产形态 | **一个 metamesh + 一张图集 = 1 次绘制** | 每栋楼一个 prefab（实例引用），带 **LOD0~6** |
| **材质** | **整城一张 4096² 图集 + 一个材质**（不是每栋楼自己的材质）—— 否则 1000+ 次绘制 | **每栋建筑用它自己的材质/贴图**（RDR2 原材质转到骑砍静态材质模板），同模型复用同材质 |
| 面数 | **≤ 40 万**（单次绘制，见 §7.0.1） | LOD0 总量 ≤ **2,500 万**（圣丹尼斯特例，见 §7.4） |
| 数量 | 44 个据点各 1 个 | 44 个场景，每个几千~上万实体 |
| 生成 | Blender 抽真实模型 → 减面 → 合并 + 图集（`Scripts/build_rdr2_city_from_blend.py`） | `tiles/*.json` → prefab + `scene.xscene` + 地形导入 |
| 现状 | 🔄 圣丹尼斯首版已出（目标 1 非阻塞） | 🔴 **目标 1 后半（先做圣丹尼斯）** |

**共同点只有来源**（同一份解包网格/贴图）。**资产绝不共用**。

**为什么不能把实景模型直接缩小**：实景模型是 **2,500 万面 / 上万件**，直接放到地图上会卡死；微缩模型必须重新减面到 **40 万面以内**。

#### 7.0.1 每个据点的微缩模型：尺寸与规模要求（给外包方看，2026-10-25 定）

**一句话**：每个据点交一个独立的微缩模型，按实景尺寸统一缩到 **1/29**、高度放大 **1.5 倍**；规模最大的圣丹尼斯和最小的夏洛蒂的家是两把尺子，其余据点都落在两者之间。

**两把尺子**

| 项 | 最大样本：圣丹尼斯（`sdn`） | 最小样本：夏洛蒂的家 = 威拉德之息（`roc`） |
|---|---|---|
| 实景占地 | 862 × 955 m（建模只取城核心 570 × 570 m） | 60 × 60 m（1 栋房） |
| 成品尺寸（实景 ÷29） | 约 20 × 20 m（实测 20.5 × 20.9） | 约 2.1 × 2.1 m → **放大到 ≥2.5 m** |
| 高度 | 以地面为 0、实景最高不超过 60 m，再整体 ×1.5（成品高约 2.9 m） | 同左 |
| 三角面（整个据点合计） | **36.6 万**，上限 40 万 | **500~2,000** |
| 贴图 | 一张 4096 × 4096（多栋楼可拼进同一张） | ≤ 2048 × 2048 |

**其余据点怎么排（都在这条线上）**

- 按「实景占地（长 × 宽）+ 建筑密度」从大到小排：越大越靠近圣丹尼斯，越小越靠近夏洛蒂的家。
- 同档规模用同一档预算，**不按据点类型一刀切**：康沃尔煤焦油厂（541 × 512 m）归类是庄园，但规模是城级，按城算。
- 比夏洛蒂的家更小的点（草皮屋 15 × 14 m）面数仍落在 500~2,000 这一档，只是放大倍数更大。

**通用规则**

1. **比例统一 1/29**：不做逐据点缩放，只有「最小成品尺寸」这一条兜底。
2. **取景**：以建成区为界，外扩不超过 50 m；不要把大片空野地纳进来（浪费面数）。
3. **最小成品尺寸**：最长边 ≥2.5 m；不到就整体放大。
4. **高度**：以地面为 0、实景最高不超过 60 m，再整体 ×1.5。
5. **三角面**：按整个据点合计，见下表。
6. **贴图**：每个据点自带；城镇 4096²，小据点 ≤2048²。
7. **选材**：用真实模型减面，允许简化，**不允许改建筑布局**；实景高 <2.5 m 或占地 <1.2 m 的小件删掉，轮船保留。
8. **认得出**：每座城开工前先定 3 个必须认出的地标（圣丹尼斯 = 教堂尖顶 / 码头 / 主街），成品要看得出来。

**分档预算（三角面）**

| 类型 | 数量 | 面数上限（整个据点合计） | 贴图 | 依据 |
|---|---|---|---|---|

### 7.4 圣丹尼斯特例（场景侧）

实测 **约 2.6 万实体 / 4,700 万面（LOD0）**，是第二名的 10 倍：

- 剩下小件按材质合并批处理；

### 7.5 场景文件怎么来（三层分开，只有地形要进编辑器）

| 层 | 格式 | 谁生成 | 引擎怎么读 |
|---|---|---|---|
| 网格 metamesh | 二进制 `.tpac` | `tpaccli` | `AssetPackages/*.tpac` 启动自动加载，**不需注册** |
| 预制体 prefab | 纯文本 XML | 脚本生成 | `Prefabs/` 目录**自动扫** |
| 场景 xscene | 纯文本 XML | 脚本生成 | `SceneObj/<场景名>/scene.xscene`；由 `settlements.xml` 的 `scene_name` 指过来 |

**生成顺序（关键）**：① 脚本生成场景骨架（含 `<terrain>` 参数）→ ② 用户在 ModKit 导地形（编辑器写出 `terrain.bin` 并回填参数）→ ③ 脚本再把实体注入 xscene（不碰 terrain）→ ④ 验收。
**原因**：编辑器保存会重写整个 xscene，先导地形后注入实体，两边互不覆盖。

#### 7.6.2 我们的方案（用户裁定：高空俯视能认出即可，体积要小）

- **真实模型 + 狠减面 + 合并成一个网格 + 一张图集**（1 次绘制）；
- 素材来源：**`continent.blend`**（98,249 个物体，物体名 = 模型哈希 `e_xxxxxxxx`，与模型库/贴图对得上）；
- 取景：世界米 x[2330,2900] y[-1450,-880]；比例 **1:29**，高度 ×1.5 夸张；
- 选件（实测依据）：
  - 剔垃圾**按模型身份**（`cablemesh` 高压线 / `road` 路面 / `glue` 地块 / `decal` / `vfx`）——**不按尺寸一刀切**（一刀切会误伤 67 个 60~120 米的大地标）；
  - 高度 < 2.5 m 丢（凳子/箱子/室内家具/矮栅栏）；
  - 水平尺寸 < 1.2 m 丢（路灯/路牌/栏杆）；
  - 轮船保留（高 5~25 m、长 5~40 m，俯视最认得出）。
- 预算：**总 ≤ 40 万面**（圣丹尼斯实测 36.6 万）；口径与逐条验收见 §7.0.1。
- LOD：LOD0 40 万 / LOD1 3 万 / LOD2 1 万 / LOD3 2.5 千（**目标值；当前 `meshmake --lods` 只是复制几何，真减面未做**）。

#### 7.6.4 交接：地图图标当前状态（2026-10-25 晚）

**目标（用户原话）**：一个完整的圣丹尼斯、低空俯视能看到城市布局与主要建筑、视觉缩小、体积小、**有贴图**。

**链路（已跑通，单轮约 4~30 分钟）**：
`continent.blend` → Blender 选件/减面/UV 重映射 → 二进制网格 → RDRL1 → `tpaccli` → prefab → 场景实体。

**参数**：
| 项 | 值 |
|---|---|
| 取景 | 世界米 x[2330,2900] y[-1450,-880]（570×570 m） |
| 比例 | 1:29；高度 ×1.5；z 用 2% 分位数当基面并钳制 0~60 m |
| 面数预算 | 40 万（实测稀疏版 36.6 万） |
| 图集 | 4096²，32×32 = **1024 格**（128²/格），城市用到 740 种贴图 |
| 选件 | 按模型名剔电线/路面/贴花；高 <0.5 m 或 footprint <0.3 m 丢；高 >120 m 丢 |

**已经踩过并修好的五个坑**（都别再踩）：
1. **共享网格只减了第一个实例** → 必须按"网格数据块"分组，先给属主单用户副本再减面（`modifier_apply` 对多用户数据直接失败，日志里是 123 条 SKIP）。
2. **图集太小**（255 格）→ 71% 物件落兜底灰格 → 扩到 1024 格。
3. **UV 没归一化** → RDR2 模型 UV 只占 0~1 的一小块，缩进格子后整栋楼采样同一个颜色（看着"没贴图"）→ 每栋楼 UV 先归一化铺满格子。
4. **z 基面被离群件带偏**（有 −179 m 的顶点）→ 用 2% 分位数 + 钳制 0~60 m。
5. **Python 逐行解析 250 MB OBJ**（十几分钟）→ Blender 直接导二进制 `MESH1`，numpy 秒级读取。

**已知未解**：Blender 的 `modifier_apply` 在个别网格上会**死锁**（CPU 归零，实测两次，分别卡在第 3,500 个物件 / 第 600 组）。当前规避 = 跳过 >2 万面的网格（原样保留）。

**下一步（建议顺序）**：
1. 跑完密集版看预览：`Debug/RD2构造相关/icon_blend/preview_render.png`；重点看**有没有贴图**（砖缝/窗框）。
2. 若 Blender 仍卡 → 放弃 Blender 减面，改**纯 numpy 顶点聚类减面**（不调 Blender ops，无死锁风险）。
3. 若要更真实的贴图 → 改成"每栋楼用自己的贴图 + 多材质"（需扩展 `tpaccli meshmake` 支持多材质），原版城镇正是这么做的。
4. 装包：`python Scripts/install_rdr2_city_icon.py --mdl Debug/RD2构造相关/icon_blend/rdr2_m_sdn.mdl --atlas Debug/RD2构造相关/icon_blend/atlas_d.png`

**内部验收（引擎侧）**：任意场景 `custom.spawn_mesh rdr2_m_sdn 30` 看得见、贴图对；大地图俯视截图无 `RGL CONTENT WARNING`；与「原版图标占位」在同相机高度 A/B，帧率 ≥90%。

**方法论教训（下次做同类任务先看这段）**：
- **先用 50~100 个物件跑通"带贴图的预览"，再放大到全量**——这次每一轮都是全量跑 10~30 分钟才发现一个本可以在小样本 1 分钟内发现的 bug。
- **每轮必须有可视化验收**（预览图），不要只看日志里的面数。
- **长任务必须有进度页**（`Scripts/build_progress.py`，浏览器 2 秒自刷新），并且时间戳要能看出"卡住"。
- **Blender 的 `modifier_apply` 不适合万级批量**：多用户报错、大网格死锁、每次调用刷全场景。

### 7.7 地图覆盖分三档（"每一栋房子都要看到"要定义清楚）

用户问过：**圣丹尼斯的经验能不能扩到全图，让说过的每一栋房子（如夏洛蒂的家）都在地图上有缩略版？**
能，但不是"逐栋摆"，要分三档：

| 档 | 范围 | 做法 | 预算 | 状态 |
|---|---|---|---|---|
| **A. 据点图标** | **44 个据点**（9 城 / 11 堡 / 11 村 / 5 营地 / 6 POI / 2 藏身处） | 每据点一个合并网格 + 图集（圣丹尼斯管线） | 城镇 ≤40 万面、村庄 0.5~2 万面；全图 44 个合计 ≤150 MB（暂定） | 圣丹尼斯在做，其余待 T10 |
| **B. 具名单点** | 夏洛蒂的家（= 威拉德之息）这类 | **它已经在 44 人名单里**（POI → 村庄），按 A 档做，图标只放 1~2 栋房、500~2,000 面 | 可忽略 | 含在 A 档 |
| **C. 全图建筑覆盖** | 18 万实例里剩下的房子 | **不逐栋摆**，改按 **2000 m 瓦片合并**：43 个瓦片各出一个"城外建筑群"低模网格 | 约 43 次绘制、**200 万面上下** | 未开始，先挑一个瓦片试点 |

**为什么不逐栋摆**：

1. **绘制次数**：地图相机一次要看全图，一个实体 = 一次绘制；几千栋独立房子直接掉帧。
2. **面数**：全图建筑 LOD0 是 3.36 亿面；就算每栋砍到 50 面，18 万栋 = 900 万面，仍太重。
3. **数据缺口**：约一半大件在解包模型库里没有网格，"每一栋"物理上做不到。
4. **交互**：不是据点的实体只是装饰——不能点、不能进；要有交互得挂 tag/组件，成本另算。

**建议顺序**：先把 A 档做完（44 个据点，含所有你点名的房子）→ 再看要不要 C 档（先做一个瓦片，看观感和帧率）。

#### C 档怎么做（"全图每一栋房子都能看到"的操作方案）

目标：18.2 万个建筑实例，地图上全都看得到缩略版。**不逐栋摆实体**，走"瓦片烘焙"：

| 步 | 做什么 | 产物 | 机器时间 |
|---|---|---|---|
| 1 | **替身网格库**：10,076 个有几何的模型各减面到 30~60 面；没几何的（约一半大件）用"同尺寸档最近模型"顶替 | 一张"模型 → 低模"映射 | 30~60 分钟（Blender 批量） |
| 2 | **按 2000 m 瓦片烘焙**：43 个瓦片，各把瓦片内实例按位置/朝向摆好、合并成一个静态网格 | 43 个 metamesh | 1~2 小时（机器） |
| 3 | **每瓦片 3 档 LOD**：LOD0 ~40k 面 / LOD1 ~12k / LOD2 ~4k | 43 × 3 档 | 同上 |
| 4 | **共用图集**：全图一张 2048²（或每瓦片一张），颜色取自原贴图 | 1~43 个 tpac | 快 |

**预算**：全图约 **240 万面 / 55 MB**；完全缩小看全图时 43 个瓦片都停在 LOD2 ≈ **17 万面**，与现在的大地图同量级。

**代价 / 风险**：
1. **一半建筑是替身**（不是真模型）——除非重新解包补几何；
2. 地图会变"满"，可能挡据点视认，需要按缩放淡出或只保留据点周边；
3. 仍是**纯装饰**：不能点、不能进；
4. 和 A 档会重叠（据点图标更精细，应该盖在瓦片层之上，或瓦片里挖掉据点范围）。

**先做试点**：挑一个 2000 m 瓦片（建议含瓦伦丁或黑水镇），量出观感 + 帧率，再决定要不要 43 个全做。

## 13. 坑与注意（接手先看）

1. **Taikou 不能与 RD2 同时加载**（都定义 `neutral_culture` / `player_faction` / `main_hero`）。
2. **ModKit 打不开 RD2**（依赖 LWN 四前置）→ 用只依赖 Native 的 `RD2Map` 沙箱。
3. **`terrain.bin` 只能由 ModKit 生成**（格式被引擎二次变换）。
4. **图层顺序 = 权重通道顺序**：`apply_rdr2_terrain.py` 整段搬 `<terrain>`，不逐项改。
5. **场景原版实体已全删**（716 个），只留 `border_min` / `border_max`。
6. **实机资产验证未做**：`custom.spawn_prefab rdr2_test_tent` 还没跑；若引擎不认手写 tpac，回 ModKit 兜底。
7. **git**：改动由用户自己提交；`Modules/RD2`、`Modules/RD2Map` 不在 LWN 仓库。
8. **C# 改动**：`if (pack == "RD2")` 只在 RD2 勾选时生效；RD2 里不放 DLL。
9. **`snow_a_d`**：真实材质名（在 Native `core.tpac`）；若 ModKit 里雪区是白板，先把雪并进 `rock`。
10. **Blender 大场景减面极慢**：`continent.blend` 有 9.8 万物体，每次 `modifier_apply` 都会全场景更新——**必须先把裁切区外的物体删掉**再逐件减面（30 分钟 → 几分钟）。
11. **blend 物体名 = 模型哈希**（`e_<hash>`），与 `assets/lib_native/index.json` 对得上；贴图/尺寸/颜色都从哈希查。
12. **地铁/电线这类"大跨度扁片"要按模型名剔**，不能按尺寸一刀切（会误伤大地标）。
