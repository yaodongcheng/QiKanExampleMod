## 4. 资产自动化（本次最关键的探索）

### 4.1 为什么不能手工导入

- 唯一网格 **10,076 个**，贴图 **3,236 张**；
- ModKit 的导入是「右键 → Import new asset → 选文件 → 确认」，**没有批处理**；
- 按每件 3 秒算，一万件 ≈ 8.3 小时纯点击，且中途崩一次要重来。

### 4.2 三条路，选第三条

| 路线 | 做法 | 判定 |
|---|---|---|
| A. 界面自动化 | 用按键脚本驱动 ModKit 点一万次 | 慢、脆、崩了难恢复；**不选** |
| B. 只自动化材质/贴图 | 网格仍手工导入 | 主要矛盾没解决；**不选** |
| **C. 直写 tpac** | 用我们自己的 `tpaccli` 生成资产包 | **选它**；风险 = 引擎是否接受手写网格，用 2 天实验定生死 |

**选 C 的底气（已经读源码确认，不是猜）**：

- `tools/tpactool` 是我们自己 fork 的 TpacTool；
- `Metamesh.WriteMetadata`、`Mesh.Write`、`VertexStreamData.WriteData`、`Material.WriteMetadata`、`Texture` 打包路径**都已实现**；
- `makepack` 已经能「PNG → 贴图资产 → tpac」并在游戏里跑通（立绘包 `lwnprof_*.tpac` 就是证据）；
- 缺的只是「RMDL1 网格 → Metamesh」这道 CLI 前端。

### 4.3 链路

```
RDR2 模型库
  assets/lib_native/<hh>/<hash>.mdl   (RMDL1：子网格 = 贴图id + 顶点/法线/UV/索引)
        │
        ├─(a) 读网格 ──────────────► tools/rdr2-pipeline/rmdl.py
        ├─(b) 生成 LOD1~3 ─────────► 减面（Blender 无头 / pymeshlab）
        │
        ▼
  tpaccli meshmake（新命令）
        ├─ 每个子网格 → 一个 Mesh（Lod=0..3）
        ├─ 每张贴图 → 一个 Texture（BC1 不透明 / BC3 带 alpha）
        ├─ 每个贴图 → 一个 Material（克隆原版静态材质模板，只换贴图 guid）
        └─ 每个模型 → 一个 Metamesh（引用上面全部）
        │
        ▼
  rdr2_core.tpac + rdr2_<地区>.tpac  →  内容包 AssetPackages/
        │
        ▼
  Prefabs/*.xml（<meta_mesh_component name="rdr2_p_<hash>"/>）
        │
        ▼
  scene.xscene（<game_entity prefab="rdr2_p_<hash>"> + 位置/旋转）
```

### 4.4 命名、GUID、包切分

- 命名：prefab `rdr2_p_<hash>`、网格 `rdr2_m_<hash>`、材质 `rdr2_mat_<贴图id>`、贴图 `rdr2_tex_<贴图id>`；可读名（`p_house_01`）只进注释与清单，不进资产 id。
- GUID：**由名字哈希确定性生成** → 重跑一遍字节一致（幂等），不会每次出新包。
- 包切分：`rdr2_core`（共用小件/材质/贴图）+ 6 个地区包，单包 200~400 MB；避免做一个 2 GB 巨包。

### 4.5 通过判据（做不到就必须换路）

1. `tpaccli list` 资产数与清单对得上；
2. 游戏内 `custom.rdr2 prefab <hash>` 生成一件建筑：**看得见、贴图对、光照正常**、日志无 `RGL CONTENT WARNING`；
3. 同一批重跑两次，产出包字节一致；
4. 一个 prefab 的 LOD0~3 在实机里能按距离切换（近处不糊、远处不卡）。

### 4.6 兜底

若引擎拒绝手写网格：退回「ModKit 界面自动化」（AutoHotkey 驱动导入），一万件 ≈ 8~14 小时无人值守。**只作为兜底，不作为首选。**

## 5. LOD（用户点名要自己处理）

### 5.1 现状

- RDR2 交接包**没有 LOD 链**：10,893 个可加载原型里，只有一个最高精度网格；
- 全量按最高精度摆进去 = **3.36 亿三角面**，任何引擎都跑不动；
- RDR2 自己的 `_slod` LOD 资产在原始解包里有一部分，但**是整片区域的合并低模**，不是「一栋房子一套 LOD」，不能直接当 prefab 的 LOD 用。

### 5.2 做法

| 级别 | 距离 | 单件目标面数 | 做法 |
|---|---|---|---|
| LOD0 | 0~15 m | ~2,000（源中位 4,928，减 60%） | 保留轮廓/门窗，优先削内部与背面 |
| LOD1 | 15~40 m | ~800 | 焊接顶点 + 减面 |
| LOD2 | 40~100 m | ~300 | 去掉栏杆/雨棚/招牌 |
| LOD3 | 100~250 m | ~100 | 简化到体块 + 屋脊 |
| 远景代理 | >250 m | 20~30 | 体块 + 屋顶；LOD4 只给大地图据点用 |

- **按 prefab 做，不按实例做**：10,076 个 prefab 各一套 LOD，实例只引用；
- **先裁再减面**：丢掉 `in_lib=0`（817 个无网格）与 `cls=0`（<1.5 m 的小件，全图 1.01 亿面）；
- **面数预算**：单场景 LOD0 可见 ≤ 40 万面，配合 LOD1~2 挤出后 ≈60 万面（与解包侧建议一致）。

### 5.3 引擎侧要确认的一件事

骑砍的 MetaMesh 每层网格带一个 `Lod` 序号，但**切换距离是引擎固定的**。P0 要拿一个原版建筑量出「第几档在多少米切换」，再决定我们的 LOD 怎么分配——**不猜**。

### 6.3 据点场景（46 个）

每个场景的固定流程：

1. **地形**：从 4 m 源数据烘一张高度图 + 7 张层权重（1024²），ModKit 导入（**唯一的人工步骤**）；
2. **实体**：从 `tiles/*.json` 取该据点范围内的实例，生成 `scene.xscene`（脚本可全自动）；
3. **出生点/标签**：从模板套（城/堡/村各一套），按「中心 + 主街 + 城门」规则摆 `sp_player` / `npc_common` / `sp_guard` 等；
4. **寻路网格**：v1 用场景属性 `nav_mesh_auto_generated=true`（引擎进场景自己算），先不做烘焙；
5. **碰撞**：v1 用体块代理（墙/地/屋顶各一个 box），不做逐三角形碰撞。

### 6.4 圣丹尼斯特例

实测：**约 2.6 万实体 / 4,700 万面（LOD0）**，是第二名的 10 倍。必须特殊处理：

- 丢掉距主街 >150 m 的 `cls=0` 小件（光这一类 = 2.08 万件 / 2,890 万面）；
- 剩下的小件按材质合并成批次网格（失去单件交互，但只是装饰）；
- 目标：**≤8,000 实体 / ≤2,500 万总面**，进场景实测帧率再调。

### 6.5 场景文件怎么来（三层分开，只有地形要进编辑器）

| 层 | 格式 | 谁生成 | 引擎怎么读 |
|---|---|---|---|
| **网格资产 metamesh** | 二进制 `.tpac` | 我们的 `tpaccli meshmake` | 模块 `AssetPackages/*.tpac` 启动时自动加载，**不需要注册** |
| **预制体 prefab** | 纯文本 XML | 脚本生成 `Prefabs/rdr2_prefabs.xml` | 模块 `Prefabs/` 目录**自动扫**（已核：Native 与 LWN 的 SubModule.xml 都没有 Prefabs 条目） |
| **场景 xscene** | 纯文本 XML | 脚本按据点生成 | `SceneObj/<场景名>/scene.xscene` 直接读；据点用 `settlements.xml` 的 `<Location scene_name="...">` 指过来，**也不需要注册** |

**三层各自的真实长相**（都是从原版核过的写法）：

```xml
<!-- ① prefab：一个模型一条，放在 Modules/Rdr2World/Prefabs/rdr2_*.xml -->
<game_entity name="rdr2_p_0xd46e4919" old_prefab_name="" mobility="1">
  <components>
    <meta_mesh_component name="rdr2_m_0xd46e4919"/>
  </components>
</game_entity>

<!-- ② 场景实例：一行一个，坐标是米，旋转是弧度（原版实测：-2.741 / 0.430 这种量级） -->
<game_entity prefab="rdr2_p_0xd46e4919">
  <transform position="243.286, 659.004, 13.782" rotation_euler="0.000, 0.000, -2.007"/>
</game_entity>

<!-- ③ 场景骨架：照抄一个原版空场景，改 terrain 参数与场景名 -->
<scene name="rdr2_val" version="2">
  <levels>…4 个 base 层，照抄…</levels>
  <environment_properties>…照抄…</environment_properties>
  <terrain enabled="true" node_dimension_x="16" node_dimension_y="16" node_size="53.000"
           min_height="…" max_height="…" …/>
  <!-- 实体由脚本追加到这里 -->
</scene>
```

**生成顺序（关键，避开编辑器覆盖）**：

1. 脚本生成**场景骨架**（含 `<terrain>` 参数，先不放实体）→ `SceneObj/<场景名>/scene.xscene`；
2. 你在 ModKit 里导入高度图 + 7 层权重（**全流程唯一的人工步骤**），保存 → 编辑器写出 `terrain.bin` 并回填 `<terrain>` 参数；
3. 脚本再把**实体清单注入** xscene（此时地形参数已定，脚本只追加实体，不碰 terrain）；
4. 进游戏验收。

**为什么不一次生成完**：编辑器保存场景时会**重写整个 xscene**（省略默认属性、重排节点）。先导地形、后注入实体，两边互不覆盖；顺序反了就得重导。

**规模参考**：一万条 prefab ≈ 1~2 MB 文本；一个城镇场景 2,000~8,000 条实例 ≈ 0.5~2 MB。都是纯文本，生成和比对都很快。

### 6.6 大地图上的据点怎么表现（参照原版 + 织丰，不用 Taikou 的做法）

**结论：每个据点 = 一个据点实体 + 2~6 个「图标网格」子节点（按街区/地标分组合并），不是一栋房子一个 prefab，也不是整城合成单个网格。**

**参照物（都核过原版文件）**：

- **原版卡拉迪亚**：`Modules/SandBox/SceneObj/Main_map/scene.xscene` 里，一个城镇是 `<game_entity name="town_EW4">`：
  - 带 `<tag name="town"/>` 和 `<script name="Town Entity Manager">`（含 Factor Color 变量）；
  - 子节点 `bo_town`（射线碰撞体）；
  - 子节点 `town_EW4_wall_l1`，里面再挂 `map_icons_empire_keep_l1` / `map_icons_empire_gatehouse_l1` 等，每个用 `<meta_mesh_component name="mi_emp_keep_1"/>`；
  - 整个城在图上只有约 5~10 个单位宽（子节点坐标 -3.2~3.4、scale 0.8~2.6）。
- **织丰**：一个据点 = `<game_entity name="castle_TOHO16" prefab="sho_map_castle_b_full">`，prefab 里带一串子节点（房屋位置在 prefab 局部坐标里，0.5~4 个单位）。

⇒ 两家的共同做法：**据点是一个「小组合」，由若干低模图标拼出轮廓**，不是一个整块网格。

| 据点类型 | 地图上的图标组合 | 面数预算 |
|---|---|---|
| 城镇 Town | 2~6 个图标（主街区 / 教堂或工厂地标 / 码头或城门） | 每个 1,000~5,000 面 |
| 城堡/庄园 Castle | 2~4 个图标（主体 / 围墙 / 角楼） | 每个 1,000~3,000 面 |
| 村庄 Village | 1~2 个图标（核心屋群） | 每个 500~2,000 面 |
| POI 单户 | 1 个图标（见 §6.7） | 200~800 面 |

**处理流程（每个据点一条命令）**：

1. **归类**：用 `settlements_world_v2.csv` 的包围盒 + `zones.json` 的 TOWN 多边形，把建筑实例归到据点；没归到任何据点的孤立建筑按 25 米聚类（§6.7）。
2. **分组**：据点内的建筑按空间位置聚成 1~6 簇（城镇按街区、城堡按「主体/围墙/角楼」、村庄只留最大一簇）。
3. **选件**：每簇只留 `in_lib=1` 且体积/高度靠前的件（城镇每簇 30~80 件、村庄 8~20 件）。
4. **减面 + 合并**：每簇减到约 300 面/件后并成**一个网格 + 一张 256² 图集**（UV 重映射）。
5. **摆放**：在据点实体下挂子节点，坐标用「世界坐标 − 据点坐标」（局部坐标，单位=地图单位）；父节点照原版带 `Town Entity Manager` 脚本。
6. **地标**：城镇额外保留 1~3 个最高/最有辨识度的建筑单独做图标（教堂塔、工厂烟囱），保证高空认得出。

**交互四件套照原版挂**：`bo_town`（射线碰撞体）/ `town_circle_decal`（黄圈）/ `gate_position` / `banner_pos`；城墙升级用 `wall_l1/l2/l3` 三个子节点（没有墙的城镇可只留 l1）。

**为什么按簇合并、不按单体**：

- 圣丹尼斯 4,900 栋建筑 = 4,900 次绘制调用，大地图直接卡死；
- 14.5:1 下每栋房子只有几个像素，单体模型纯属浪费；
- 按簇合并后每据点 2~6 次绘制，全图 46 个据点总面数 < 100 万。

**地图模型与场景模型是两套资产**：地图用「按簇合并低模 + 图集」，场景用「单体高模 + 原贴图」。不要共用。

### 6.7 单户人家与小聚落（结论：村庄，绑到最近的城堡/城镇，人口压到 1~2 户）

**结论：威拉德之息这类独屋 = 村庄（Village），绑定到最近的城堡或城镇。** 绑定只影响经济/政治归属，**地图上仍是独立点位**；关键是村里只放 1~2 栋房、1~2 个村民。

| 项 | 做法 |
|---|---|
| 据点类型 | 村庄（Village）；`bound_to` = 最近的城堡或城镇（威拉德之息 → 安尼斯堡约 850 米，或华莱士堡） |
| Hearth（村庄繁荣度） | 设最低档 **10~50**（引擎 `DailyTick` 的下限就是 10）——村民生成数量、征募量都按它算，低 hearth 就几乎没人 |
| 名流 | **显式放 1 个名流英雄**（夏洛蒂·贝尔福）：模板 `occupation=RuralNotable`，建世界期用 `HeroCreator.CreateSpecialHero` + `EnterSettlementAction.ApplyForCharacterOnly` 放进该村——这正是引擎自己生成名流的同一套调用（反编译 1.2.12 已确认） |
| 场景出生点 | `npc_common` / `npc_wait` 各只放 1~2 个；场景里只放 1~2 栋房 |
| 经济 | 不建工坊、产出极低（甚至不产）；贸易走绑定的城堡/城镇 |
| 地图图标 | 用房子本身的减面模型；**最小可见尺寸 2.5~3 单位（约 40 米）**——制图夸张，古地图也这么画；不夸张的话 0.7 单位的房子在图上等于看不见 |
| 交互四件套 | `bo_town`（碰撞体按房子大小调小）/ `town_circle_decal`（黄圈缩小）/ `gate_position` / `banner_pos` 照配 |
| 场景 | 150~300 米小场景，只放那几栋房子 + 出生点 |
| 验收 | `custom.rdr2 tp roc` 直接传送到威拉德之息：看到 1~2 栋房、能跟夏洛蒂对话 |

**哪些孤立房子要收**：第一步先收 v2 表里的 6 个 POI + 你点名的；解包侧 `towns.json` 里还有约 90 个「有名字但没进 46 人名单」的点，后续按「有官方地名 + 有网格」两个条件筛，再批量补。
