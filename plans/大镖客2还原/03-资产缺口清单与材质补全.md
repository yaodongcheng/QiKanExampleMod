## 一、材质补全：88 个缺失材质已补齐（等你验一次）

### 1.1 是怎么发现缺口的

模型导入后，编辑器每次加载会弹：

```
RGL CONTENT WARNING
Unable to find material for mesh cumb_rock_05.0
```

一次启动实测弹 **293 个**（约 3~5 分钟才清完），2026-11-10 02:20 那一轮就是弹窗期间游戏崩了。

定位办法：**TRF 是文本格式**，头部就是材质引用表：

```
rfver 4
mesh 2
j_710_r_b_bri_d08.0 0 gri_trestles_wood_03_ab     ← 网格名.序号 标志 材质名
j_710_r_b_bri_d08.1 0 gri_trestles_wood_02_ab
```

扫全部 **9,869 个 TRF**，抽出被引用的材质名 **7,293 个**，与现有材质资产对账：

| 项 | 数量 |
|---|---|
| TRF 引用的材质名 | 7,293 |
| 现有材质资产（补前） | 7,647 |
| **被引用但不存在** | **88** |
| 其中：同名贴图存在（可建正常材质） | **0** |
| 其中：连贴图都没有（只能中性兜底） | **88** |
| 其中：在 `matmap.csv` 里 | **0** |

> 结论：这 88 个材质从**贴图导出阶段就没进来**，既没有 `_tex.tpac`、也没有 matmap 行，所以只能用中性兜底。

### 1.2 怎么补的

用项目自带工具 `tpaccli editormeta --genmats3`，喂一份临时 matmap（88 行，三槽全指向已有中性贴图）：

```csv
material,albedo,normal,ma
six_cs_log_01,rdr2_white,rdr2_flat_normal,rdr2_white
...（共 88 行）
```

```powershell
tpaccli editormeta --genmats3 "<RDR2>\AssetSources\_matstage" `
  --mtlref "<RDR2>\Assets\materials\lod\fragments\adl_01_slod_ab_mtl.tpac" `
  --matmap  "<TEMP>\matmap_fallback.csv" `
  --name _x --out "<RDR2>\Assets\materials\fallback\x"
```

- 产物目录：`Assets\materials\fallback\`，**88 个 `_mtl.tpac`，38.9 KB**
- 三槽指向：albedo = `rdr2_white`（`3f480a0a…`）、normal = `rdr2_flat_normal`（`b716c6c6…`）、ma = `rdr2_white`
- 生成耗时 68 秒
