## 一、原版是怎么做的（实测，不是推测）

把 Native 全库 **7,847 个物理体**导出来量过：

| 指标 | 值 |
|---|---|
| 顶点数中位 | **32**（≈21 面） |
| 顶点数 < 100 占比 | 79.2% |
| 顶点数 < 500 占比 | 96.3% |
| 最大 | 9,686（`bo_aserai_castle_keep_a_l2_interior`） |
| 面里**四边形**占比 | **99%** ⇒ 手搭块体，不是减面（减面只出三角面） |
| 单个体积 | 中位 **4.8 KB**，全库 74.3 MB |

对照实例：

| 物件 | 碰撞体 | 视觉网格 |
|---|---|---|
| `bo_crate_a`（木箱） | **8 顶点**（一个方块） | — |
| `bo_cart`（推车） | 80 顶点 | — |
| `bo_empire_village_house_a` | **220 顶点 / 339 面** | LOD0 **13,305 面** ⇒ 碰撞体是 **2.5%** |

**结论**：原版碰撞体 = 美术手搓的低模块（方块 + 楔块 + 坡屋顶），按"够挡人"做，不追求跟建筑对齐。我们照同样预算自动生成即可。

## 二、机制：碰撞体定义在哪

| 层 | 在哪 | 内容 |
|---|---|---|
| **几何** | 模块 `AssetPackages/*.tpac` | **Physics Shape 资产**，名字以 `bo_` 开头，来源与网格同一套导入流程 |
| **绑定** | 场景或 prefab 的 XML | `<physics shape="bo_xxx" mass="1.000" override_material="wood">` + `<body_flags>` |
| **属性** | `Modules\Native\ModuleData\` | `physics_materials.xml`（摩擦/声音）、`collision_infos.xml`（碰撞特效） |

命名前缀决定导入成什么：

| 节点名 | 导入成 |
|---|---|
| `bo_xxx` | 三角面碰撞体（它自己的几何） |
| `bo_capsule_xxx` | 解析胶囊（XY 为半径、Z 为高度；XY 缩放必须相等；节点内容忽略） |
| `bo_sphere_xxx` | 解析球（节点中心即球心） |
| `bo_composite_xxx` | 复合体（子节点可为 capsule / sphere / 网格） |

三条硬事实：

1. **没有 `<physics>` = 没有碰撞**，引擎不会自动从视觉网格生成。
2. **`shape` 必须指向 `bo_` 资产** —— 原版 prefab 里非 `bo_` 开头的 shape **0 例外**。
3. **不能绕过编辑器直写 tpac**：每个 Physics Shape 除顶点/面描述外还带一份 **PhysX 烘焙数据**（`bo_crate_a` 解压 4.5 KB 里约 3 KB），Python 造不出来。

## 三、我们的生成器（已落地）

`Scripts\gen_rdr2_collision_bodies.py`：源 TRF（视觉网格，局部坐标）→ `bo_<模型名>.trf`

```
读 TRF → 顶点/面心/边中点打点 → 体素占位 → 膨胀补缝
      → 贪心盒子合并（x→y→z 扩到最大）→ 按源包围盒裁剪 → 写 TRF
```

实测三例：

| 模型 | 源网格 | 体素 | 盒子 | 碰撞体 | 原版同档 |
|---|---|---|---|---|---|
| `new_com_03_hotel_grand`（16.7×8×6 m） | 4,502 顶点 / 4,766 面 | 1.04 m | 53 | **194 顶点 / 396 面** | 220 顶点 / 339 面 ⇒ 同档 |
| `new_pie_train_43_2`（45×24×40 m） | 216,682 顶点 / 258,199 面 | 2.84 m | 82 | **253 顶点 / 588 面** | 大件 500~900 面 |
| `p_lampfactory02x`（0.8 m） | 604 顶点 / 586 面 | 0.15 m | 16 | 77 顶点 / 132 面 | `bo_crate_a` 8 顶点 |

生成耗时：25 万面的火车部件 **< 1 秒**。包围盒与源模型**逐轴一致**（裁剪已校掉膨胀外圈，此前会大出 8.5 m）。

参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--max-grid` | 16 | 体素最长边格数。**可进入的屋子调到 24~32**，否则门洞会被 1 m 体素封死 |
| `--voxel` | 自动 | 直接给体素边长（米），覆盖 max-grid |
| `--dilate` | 1 | 膨胀次数（补三角面之间的缝） |
| `--list` | — | 批量：每行一个模型名的清单 |

产物落点（新资产只放这里，铁律 36）：

```
Modules\RDR2\AssetSources\ImortReady\rdr2_collision\<类>\bo_<模型名>.trf
```

## 四、两条路线（待选，取决于导入成本）

| | **A 逐建筑一个 `bo_`** | **B 合并地块级 `bo_`** |
|---|---|---|
| 导入次数 | **517**（建筑唯一模型数） | 几十 |
| 场景 XML | 24,000 个实体各加一行 `<physics>` | 几行，或运行期 `AddPhysics` 挂 |
| 精度 | 每栋贴合 | 整块粗糙，细部丢失 |
| 修改联动 | 改一栋只重导一个 | 改一栋要重烘整块 |
| 风险 | 导入工作量大 | 生成器要加合并逻辑 |

规模参考：建筑 517（1,060 实例）、道具 1,314、车马 164、树 116；**只做建筑 = 517 个资产，存储约 12 MB**；全做约 2,000 个 / 25~30 MB（对比现有网格资产 14 GB，可忽略）。

## 七、附录：RDR2 原版碰撞体在哪（**本工程不用，留档备查**）

> **决定：不用原版 `.ybn`。** 三条理由：
> ① **格式没解析器** —— 全仓库 0 个脚本读过 `.ybn`，要先写 RAGE bounds 解析（复合 bounds → 几何 bounds → BVH）才有得用；
> ② **拿不到「一模型一碰撞」** —— 静态世界碰撞是按地图区块**合并**的（一个文件装一批物体，中位 742 KB），原版根本不按模型分文件；
> ③ **省不掉编辑器那道工序** —— 原版是 RAGE 的物理数据，没有骑砍2 要的 PhysX 烘焙段，最后仍要进编辑器重导。
> 所以走 §三 的体素盒子路线更省。

### 7.1 原版碰撞体分四类存放

| 类别 | 定义在哪 | 例子 |
|---|---|---|
| **静态世界碰撞**（建筑 / 路面 / 地形装饰） | `*_static_collision.rpf` 里的 `.ybn`，**按区块合并**，文件名是 hash | `0x10700DED.ybn` |
| **室内 / 单体建筑**（MLO） | 与模型**同名**的 `.ybn`，同包同目录 | `abe_farmhouse_int.ybn` + 高精度档 `hi@abe_farmhouse_int.ybn` |
| **动态物件**（门 / 窗帘 / 动物） | **内嵌在 `.yft` 里**，没有独立 `.ybn` | `p_door` 包：0 个 `.ybn` / 56 个 `.yft` |
| **普通静态道具 `.ydr`** | **自身不含碰撞**，碰撞烘进第一类 | — |

### 7.4 两个能省半天功夫的判据

1. **文件名的 hash 不是 `joaat(模型名)`** —— 拿 294,471 条已知名字全算过一遍，命中 **0**。别试图按模型名去找碰撞文件，静态碰撞只能按**空间位置**匹配。
2. **看文件头就能认类型**（前 8 字节）：

   ```
   ydr (drawable) : 52 53 43 38 02 1f 00 00
   yft (fragment) : 52 53 43 38 0a 1f 00 00
   ybn (bounds)   : 52 53 43 38 0f 1f 00 00
   ```
