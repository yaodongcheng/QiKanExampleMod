## 0. 背景（为什么要改）

相机现在是**跨系统通用件**（飞行 / 钩索 / 处决演出 / 对话 / 剧情都在用），但现状有三处结构问题：

1. **参数住得乱**：飞行 4 档机位参数是 `FlightCameraRig` 里的代码常量；钩索相机参数（臂长 2.8、灵敏度、锚点跟头骨系数…）硬编码在 `GrappleAimCamera`；Camera.csv 只覆盖了一半字段（缺 Lag / 运动驱动 / 锚高口径等 7 列）。
2. **两套机器抢一个资源**：跟随相机（`SpringArmCameraView`）与飞行相机（`FlightCameraRig`）各自写 `MissionScreen.CustomCamera`，**零互斥、最后写的赢**；飞行 `Exit` 还会无条件置 null（可能踩掉别人的）。
3. **调试功能放错地方**：`aimcam / aimanchor / aimlift / aimsens / lock / test` 这一套通用相机调试被放进了钩索模块。

**改造目标（一条一句话）**：所有机位 case 都成为 **Camera.csv 里的一行**；所有消费者只写"**用哪一行**"；相机逻辑收敛为**一个服务 + 一份机器**；调试命令统一到 `custom.cam`。

## 2. Camera.csv 目标表

文件：`LivingWorldNpcs\ModuleData\DesignData\Camera.csv`（**保持 GBK + CRLF + 三行表头**：①英文键 ②类型 ③中文标签；数据从第 4 行起；解析器 = `Data/DesignDataLoad.cs` 的 `CsvLoader.LoadTable`）。

### 2.1 列（16 现有冻结 + 14 新增）

现有不动：`ID`（取用句柄）· `AttachType`（一次性机位锚点选择：Player/Speaker/Listener/AnchorWorld）· `PivotX/Y/Z` · `ArmLength` · `ArmYaw/ArmPitch` · `SocketX/Y/Z` · `SelfYaw/SelfPitch/SelfRoll` · `Fov`。
（`ScriptName`（中文描述，仅人读）已于 2026-10-06 删除，见顶部偏差 7。）

新增（追加在末尾；老行缺列 = 0 = 旧行为）：

| 列 | 一句话 |
|---|---|
| `IsAnchorWorld` | 1 = 方向世界锚定（角色转身镜头不甩，飞行/钩索口径）；0 = 角色相对（演出模板口径） |
| `UseEngineEyeHeight` | 1 = 锚点用引擎公式（贴合接引擎的机位）；0 = 旧常量 1.4626 米（飞行/演出口径） |
| `LagSpeed` / `LagMaxDistance` | 弹簧跟随速率 / 拖尾上限（米）；0 = 不滞后 |
| `FovPerVz` / `ArmPerVz` / `RollPerYawRate` | 运动驱动三件套（竖直速率→FOV/臂长、角速度→侧倾）；0 = 关 |
| `Seed` | 接管瞬间方向与臂长起点：`Engine` = 照抄引擎相机（**ArmLength/Fov 填 0 = 保留引擎当时的值**）；`Row` = 方向用本行 ArmYaw/ArmPitch |
| `MouseLook` / `LookSens` / `PitchMin` / `PitchMax` | 相机自己接管"看"（每帧鼠标驱动 + 向 `CameraLook` 供方向）及其灵敏度/俯仰钳位 |
| `AnchorFollowHead` / `AnchorHeight` | 环绕点贴**动画头骨**（认得出蹲姿；含头上抬 0.10 米、6/s 平滑）或定死高度（米；≤0 = 引擎公式） |

🔴 **格式陷阱**：0/1 开关的类型行写 **`float`**，代码读 `GetFloat(...) > 0.5f`——不能写 `bool`（`bool.TryParse("1")` 为 false）、不能写 `int`（`DynamicRecord.GetFloat` 只认 float）。键/类型/数值全 ASCII；第 3 行中文保持 GBK（该行与中文列从不被代码消费）。

### 2.3 明确**不进表**的东西（边界）

| 类别 | 例子 | 为什么留代码 |
|---|---|---|
| 时序 / 玩法状态 | 进场渐变时长（飞行 0.45s / 跟随 0.35s）、拉拽的归还滑行 1.2s 与触发点 u≥0.5、超时秒数（= 拉拽时长+余量）、方向归还收敛组 | 依赖玩法进程，进表 = 每换玩法就要加一行；作 `Play/Adopt` 的**调用参数** |
| 归还策略三件套 | `writeBackLook / clearSpecial / predictReset` | 描述"引擎接下来会干什么"（会不会解冻/重置相机），不是"镜头长什么样"；作调用参数 |
| 算法内部常数 | 头骨上抬 0.10、锚点平滑 6/s、旧眼高常量、运动量上限 | 全 case 同一份，改一处全变 |
| 全局标定 / 设备偏好 | 运动驱动总增益、鼠标 X/Y 反转、飞行的接管开关 | 非单 case 参数 |

## 3. CameraService（唯一入口，新文件 `Camera/CameraService.cs`）

```csharp
// 起播（owner = 持有者标签 "flight"/"grapple"/"perf:exec_pair"）
bool Play(string caseName, Agent agent, float seconds, string owner);   // 已被别人持有 → 拒绝并记日志
bool Switch(string caseName, float blendSeconds);                       // 同 owner 换 case（= 飞行机位切换）
bool Adopt(string caseName, string owner, in CameraStage stage);        // 同 owner 换阶段，**不重播种**（钩索收编走这条）
// 一次性静态机位（演出/对话；= 原 UseCameraTemlate，会被新 Play 顶掉）
bool ApplyPose(string caseName, Agent speaker, Agent listener, Vec3 anchorWorldPos);
// 现场改（仅当前持有者）
SetArmLength / SetPivotZ / SetSocketZ / SetLook / ReleaseLook / SetMotion / SetTimeout / SetReturnPolicy
// 归还 / 收场
BeginLookReturn(seconds) / RequestHandBack(glideSeconds) / Stop()
// 查询
IsHeld / Holder / CurrentCase / IsHeldBy(owner) / TryGetBasis(out f, out r)
```

配套：`Camera/CameraCase.cs`（表行 → `SpringArmCameraParam` + 行为开关，带缓存与 `Describe`）；`CameraLook.cs` 增 `Set(provider, owner)` / `Clear(owner)`（修单槽互踩）；**此后全项目只有 CameraService 写 `CameraLook.Provider` 与 `CustomCamera`**。

**仲裁规则**：常规 `Play` 被占用 = **拒绝**；一次性机位 `ApplyPose` = **抢占**（停旧持有者 + 记日志）；只有持有者能置 `CustomCamera = null`（**修掉飞行 Exit 无条件置 null 踩别人的 bug**）。

**现有 API 处置**：`UseCameraTemlate` 签名保留（5 处演出调用点一字不动，内部转 ApplyPose）；`ApplyFollowFromEngineCamera` → `PlayEnginePose`；`ApplyFollowTemplate` → `Play`；`SetFollow*` 改名搬进服务；`TryGetFollowLook` 退役。`GrappleAimCamera` 缩成 ~60 行政策层（玩法总开关 + 何时 Play/归还 + 身体朝相机；鼠标与锚点跟头骨搬进相机模块，按 case 的 `MouseLook/AnchorFollowHead` 自动生效）。

## 4. 分阶段（每阶段独立可验收；每阶段一个独立提交）

### 阶段 0 · 清场（风险低）
删 `Camera/CameraDebuggerView.cs` + `CameraDebuggerVM.cs`、`custom.openCamDebugger` / `custom.useCameraTemplate`、`MyCommands` 的 `custom.cam_face / cam_reset`。同步：csproj 条目、`MySubModule` 注册、`StoryEngine` 里对 `CameraDebuggerView.targetAgent` 的引用。
**验收**：四条命令返回 unknown；`custom.useSpringArmCamera <模板>` 与 `custom.exec_pair 1 2 sp_lordshall` 照常。

### 阶段 1 · 数据搬家（风险中——飞行数值逐字保护）
1. `CameraCase.cs` + Camera.csv 按 §2 改；`BuildCameraParam` 读全部新列（跟随路径不再硬写 `IsAnchorWorld=false`；一次性机位路径行为冻结）。
2. `FlightCameraRig.Presets` 改为从 `fly_*` 行填充（表缺行 → 不接管 + 明确日志，**不做代码兜底**）；灵敏度/俯仰钳位改读 case。
3. `GrappleAimCamera` / `GrapplePull` 参数改读 `grapple_shot` / `grapple_pull` 行（鼠标驱动与锚点逻辑暂留原处，阶段 2 搬）。

**验收**：
- 静态：`custom.cam show fly_boost` → `arm=4.5 fov=80 lag=7.4 lagmax=10 fovvz=0.50 armvz=0.100 rollyaw=0.015`（与代码原值逐字对齐，四档全对）；
- **飞行手感回归**：飞固定路线（悬停 5s→巡航 10s→冲刺 10s→俯冲→落地），`custom.flight log on` 的 `[FlightCam]` 逐帧日志与改造前同路线对比（臂长/FOV 序列一致）；再用 `custom.flight tune cammotion 0 / camlag 0` 开关对照；
- 钩索全程（开火→接管→拉拽→落地）无跳变；对话/`exec_pair` 镜头与改前一致。

### 阶段 2 · 服务化 + 持有者仲裁（风险中）
`CameraService` 落地；跟随机器接仲裁；鼠标驱动 + 锚点跟头骨 + Provider 注册搬进相机模块；`GrapplePull.EnterCamera` 的 5 步舞 → 一次 `Adopt("grapple_pull", "grapple", stage)`；`ApplyPose` 改"抢占并停旧持有者"。
**验收**：`custom.cam play follow_engine 3` = 原黄金测试（原地切换坐标厘米级一致、画面零变化）；`custom.cam play grapple_shot 5` 不拉钩也能看开火机位；飞行/拉拽收场后 `CustomCamera` 必回 null（`custom.cam info` 在跟=0）；对抗用例：飞行中开对话/拉拽中开演出不互踩。

### 阶段 3 · 命令统一（风险低）
`custom.cam play <case> [秒]`（替代 aimcam lock/test + cam test）· `stop` · `set <case> <列> <值>`（热改内存 case，替代 aimlift/aimanchor/aimsens/aimcam<臂长> 与 flight 逐参数命令）· `show [case]` / `list`；保留 `log|stat|info|lift`。
删 GrappleCommands 的 `aimcam/aimanchor/aimlift/aimsens` case **与白名单 4 项**（⚠️ 白名单漏删/漏加就是 2026-10-05 那次静默回落事故）；钩索只留一条相机总开关 + 时序旋钮 `camret/lookret`。旧命令名一律返回"已迁移到 custom.cam …"提示。
**验收**：`custom.cam set grapple_shot arm 3.2` 实时可见；旧命令提示正确；`custom.cam list` 列出全部 case 含缺行检查。

### 阶段 4 · 合并两套 rig（风险高——飞行手感 A/B）
以跟随机器为底（已有：引擎播种、进出场渐变、超时、外部 look、归还策略、实体绑定、Adopt），把飞行的能力**搬运**进去：鼠标驱动、`SpringArmLagState`、`WithMotion`、case 间渐变（0.45s）、**写回引擎朝向的 elevation 符号校准**（跟随路径没有，直接照搬会翻俯仰）、`TryGetBasis`。拆文件：跟随机器从 MissionView 拆到 `Camera/SpringArmRig.cs`；`SpringArmCameraView` 只剩 UI/生命周期/空实体。
**安全绳**：`FlightTuning.UseMergedRig` 开关（默认 0）→ 实机 A/B 合格再切 1 → 再删旧类（两个提交，回退粒度清晰）。
**前置未知（先做对照实验）**：飞行那台相机是裸 `Camera.CreateCamera()`（无空实体）而跟随路径注释说"引擎只读实体帧"——两套表述冲突但实机都可用。合并成"一台相机 + 一个空实体"前先实测确认飞行视角不变；不一致就**只合并逻辑、保留各自相机对象**。
**验收**：飞行全流程手感 + `[FlightCam]` 日志与合并前一致；钩索/演出回归；`UseMergedRig` 两侧对照。
