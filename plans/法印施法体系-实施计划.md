# 法印施法体系 — 实施计划

> **状态：施工中** —— P0+P1 已落盘（2026-09-21，纯数据零代码），待实机验收。施工记录见 §十四。
> **一句话**：把「施法」做成**一件武器 + 一种弹药**，骑砍原生的武器/导弹机制当骨架；法术按**形态分族**，每族对应一条骑砍实现路径。
> 关联：[自定义战斗.md](../Knowledge/自定义战斗.md)（§3 打点 / §15 飞行物）· [骑砍2粒子系统.md](../Knowledge/骑砍2粒子系统.md) · 粒子工具链 [tools/particle-pipeline/](../tools/particle-pipeline/README.md) · 形态学参考 `F:\LarianModLearn\docs\dos2-skill-shapes-reference.md`

## 一、结论（先说做什么）

| # | 决定 | 依据 |
|---|---|---|
| 1 | **法印 = 一件武器物品**（`weapon_class="Crossbow"`，动作外观自建） | 引擎给「抬起→瞄准→释放→发射」完整流程 |
| 2 | **法术弹 = 一种弹药物品**，**`flying_mesh` = 法术网格** | 🔴 飞出去长什么样由**弹药**决定（原版弩矢 `bolt_bl_flying` 就是这么做的） |
| 3 | 发射后的**飞行 / 重力 / 碰撞 / 插地 / 命中 / 伤害**全部**引擎接管，零代码** | `Mission.AddCustomMissile` → native；`AirFrictionConstant` / `GetMissileCollisionPoint` / `MissileCollisionReaction` |
| 4 | 🔴 **范围伤害也是数据驱动**：弹药物品开 `weapon_flags` 的 `AffectsArea` / `AffectsAreaBig` | 原版 `mpitems.xml` 在用；`Mission.MissileAreaDamageCallback` 按 `isBigExplosion` 取半径 |
| 5 | **法术按形态分四族**（见 §二），选族 = 选工作量 | 拉瑞安 DOS2 的 15 形态经验 + 骑砍实现路径盘点 |
| 6 | 我们要写的只有 **4 件**：蓄力、开火特效、命中特效、技能层 | 见 §六 |
| 7 | 动作**完全自建**（不绑"拉弓/装填"语义），走内容包 `item_usage_sets.xml` | 本项目已实测：内容包的 `item_usage_sets.xml` 会被引擎读取（铁炮装填就是这么接的） |

**一句话概括**：我们缺的从来不是"施法框架"，而是**飞行物 + 碰撞 + 范围伤害** —— 这三件骑砍的武器系统已经做完了。我们要做的是**把法术伪装成弹药**，再按形态补"编排层"。

## 二、法术形态框架（本计划的地基）

### 2.1 四族：按「骑砍侧怎么实现」分

| 族 | 形态 | 骑砍实现 | 复用度 | 工作量 |
|---|---|---|---|---|
| **A 弹道族** | 单体弹（阴魔斩）、爆炸弹、天降弹（落雷）、连发 | **弹药物品**：`flying_mesh` + `trail_particle_name` + `missile_speed` + `AffectsArea[Big]` | 🟢 **几乎 100%** | 只配数据 + 出网格 |
| **B 区域族** | 自心圆爆发、扇形、地面雨、光环、震地、持续雷暴 | `Mission.GetNearbyEnemyAgents(Vec2, r, team, list)` 选敌（**只有俯视圆**）+ 自己按角度/高度过滤 + `AgentDamageHelper.CastBlow` 结算 + 粒子管线出特效 | 🟡 选敌/结算有轮子，**要写编排** | 中 |
| **C 位移族** | 突进、瞬移、瞬影连击 | 位移 + 位置写入（🔴 已知：X/Y 可写、**Z 写不进去**）+ 路径判定；骨架可参考 `Flight/PlayerFlightBehavior` 的状态机 | 🔴 基本自写 | 大 |
| **D 实体族** | 阻挡墙、召唤、持续光束区域 | `GameEntity`/`MetaMesh` 生成实体（范例 `TrajectoryVisualizer`/`CarrierBoard`）；召唤走 `Mission.SpawnAgent` | 🟡 轮子有 | 中大 |

**判据**：凡是"**东西会飞出去**"的 → A 族（最省）；凡是"**在某处发生**"的 → B 族；"**施法者自己动**" → C 族；"**生成一个持久物件**" → D 族。

### 2.3 与 DOS2 十五形态的对照（拉瑞安经验怎么用）

| DOS2 形态 | 骑砍族 | 说明 |
|---|---|---|
| Projectile / ProjectileStrike / Target(远程) | **A** | 直接等价；DOS2 用"投射物模板 GUID"决定视觉，我们用**弹药物品的 `flying_mesh`** —— 是同一件事（一个视觉 = 一个数据条目） |
| Shout / Cone / Quake / Dome / Rain / Storm | **B** | DOS2 靠 `AreaRadius` + `Angle` + `CycleConditions` 描述区域；骑砍没有这些字段，**要自己算**（选敌 API + 角度/高度过滤），但粒子与结算我们有轮子 |
| Rush / Jump / Teleportation / MultiStrike | **C** | DOS2 有 `TeleportTextEvent` / `StartTextEvent` 这类"动作事件"驱动位移；骑砍对应的是自己写位移 + 播动作 |
| Wall / Summon | **D** | 生成持久物件/单位 |
| Zone（激光） | **B + D** | 持续光束 = 视觉实体 + 每帧判定 |

**值得直接借用的两条拉瑞安做法**：
1. **一个视觉 = 一个数据条目**（DOS2 的"投射物模板表"）→ 我们的"每种法术弹一个弹药物品"。禁止一个弹药被多个技能乱用（DOS2 踩坑 #10：元素错配就是"火球模板"类错误的根源）。
2. **形态决定字段集**（DOS2 每个形态有必填字段清单）→ 我们给每族定一张**必填清单**（见 2.4），新法术照表填，不自由发挥。

### 2.5 施法方式（第三根轴：形态 × **施法方式** × 时机）

形态决定"法术长什么样"，**施法方式决定"玩家怎么把它放出去"** —— 两者独立，必须分开选。

| 施法方式 | 骑砍原生 | 用什么 API | 要写什么 | 适用 |
|---|---|---|---|---|
| **① 方向施法**（自由瞄准，看哪打哪） | ✅ **弓/弩原生就有** | 武器瞄准 → 引擎发射 | **零代码** | A 族全部（阴魔斩走这条） |
| **② 锁定目标施法**（先选目标再打） | ❌ 没有原生；**引擎导弹是纯弹道、不追踪** | 选目标：`Mission.RayCastForClosestAgent(eyePos, eyePos + lookDir × range, out dist, excludedAgentIndex, rayThickness)`；要部位就 `RayCastForClosestAgentsLimbs` | 选目标 + **方向解算**（含提前量预判）。注意：这只解决"瞄准"，弹出去**仍然不追踪** | A 族（瞬锁 = 自动瞄准）；想**追踪**见下面纪律 2 |
| **③ 指定范围施法**（点地面，在落点生效） | ❌ 没有落点 UI，**但射线 API 全套都在** | 取落点：`Scene.RayCastForClosestEntityOrTerrain(src, src + dir × range, out dist, out closestPoint, out collidedEntity)`；取高度/法线：`Scene.GetGroundHeightAtPosition(pos, out normal)`；粗粒度 `Scene.BoxCast` | 取落点 + **自己画落点指示圈**（骑砍没有地面瞄准 UI） | B 族（区域）+ A 族天降（雷电术①） |

**三条纪律**：
1. **施法方式不改变形态族**：同一个"落雷"形态，方向施法（朝准星打过去）与指定范围施法（点地面落点）是两种玩法，工作量差一个数量级 —— 登记表必须写清是哪一种。
2. 🔴 **追踪弹是陷阱**：引擎导弹**没有 homing**。要追踪只能自己每帧移动实体 → 等于放弃引擎的碰撞/伤害/插地（L1 复用全丢，退化成 D 族自管）。**能用"瞬锁 + 预判"就别做追踪。**
3. **落点指示圈要自己画**：可用粒子（地面 decal 类）或实体（`GameEntity` + `MetaMesh` 画个环）；也可以先不做 UI、靠准星方向粗略施放（P6 可选项）。

**首两个法术的施法方式**：阴魔斩 = **① 方向施法**（最省）；雷电术①落雷 = **③ 指定范围施法**（所以雷电术会先撞上"落点"这个新课题，见 §8.2）。

## 四、物品设计

### 4.1 法印（武器）—— 照抄 `mp_crossbow`

```xml
<Item id="lwn_spell_seal" name="{=LWN_spell_seal}Spell Seal" mesh="<法印网格>"
      Type="Crossbow" weight="1.5" value="500">
  <ItemComponent>
    <Weapon weapon_class="Crossbow"
            item_usage="<自建 usage id>"     <!-- 动作外观由它决定 -->
            ammo_class="Bolt"                 <!-- enum 不可扩，复用原版弹药类 -->
            ammo_limit="1"
            missile_speed="60"                <!-- 法术手感靠它 -->
            reload_phase_count="1"            <!-- 原版弩是 2；法印抬手即可 -->
            weapon_length="60" thrust_damage="0"
            physics_material="wood_weapon" />
  </ItemComponent>
</Item>
```

### 4.2 法术弹（弹药）—— 关键就在这几行

```xml
<Item id="lwn_spell_crescent" name="{=LWN_spell_crescent}Crescent" mesh="<袋里的样子>"
      flying_mesh="<月牙网格>"            <!-- 🔴 飞出去的样子 -->
      Type="Bolts" item_holsters="...">
  <ItemComponent>
    <Weapon weapon_class="Bolt"
            missile_speed="60"
            stack_amount="999"
            trail_particle_name="lwn_psys_crescent_trail"   <!-- 🔴 飞行拖尾 -->
            thrust_damage="60" thrust_damage_type="Cut"
            weapon_flags="AffectsArea,AffectsAreaBig" />      <!-- 🔴 范围伤害，数据驱动 -->
  </ItemComponent>
</Item>
```

**碰撞体**：异形网格的物理形状在 `ModuleData/collision_infos.xml` 里定义（原版 `burning_jar` 就是一例）—— 月牙要在这里挂一个盒/球当碰撞体。

### 4.3 动作（`item_usage_sets.xml`）

- `weapon_class` 决定**引擎行为**，`item_usage` 决定**播什么动作** → 能要「结印→推掌」而不必"拉弓"
- 需要的新动作至少 3 个：抬手/结印、蓄力保持、推出/释放
- 已有先例：本项目给火器加过 `act_gun_reload`（`action_types.xml` + `action_sets.xml` 绑定）

🔴 **前提：`item_usage_sets.xml` 必须挂进 `project.mbproj`，否则完全不加载**（2026-09-21 核实）。
内容包的 `item_usage_sets.xml` **不在 SubModule.xml 的 `<XmlNode>` 体系里**，而在 soln 体系：
只有 `project.mbproj` 里写了 `<file id="soln_item_usage_sets" name="ModuleData/item_usage_sets.xml" type="item_usage_set"/>`
引擎才会读它。不挂 = 文件是死的 = `item_usage` 指向一个不存在的 usage = native 取到无效索引 =
`AccessViolationException`（雷 122；同族坑还有 `item_holsters` 雷 136、`module_sounds`）。
范本：Taikou 的 `ModuleData/project.mbproj` 已挂 7 行 soln，铁炮的 `tk_firearm` 就是这么活的。

## 五、阶段机：需要时才抄，且是**照抄**不是发明

原版器械上有一台完整分阶段状态机（反编译实见 `RangedSiegeWeapon.cs:40`，推进在 `OnTick` :951）：

```
Idle → LoadingAmmo → Reloading ↔ ReloadingPaused        ← 装填可暂停（= 蓄力保持的原生对应物）
     → WaitingBeforeProjectileLeaving                    ← 发射前一刻（放爆发特效的钩子）
     → Shooting（AddCustomMissile 在这，:1641）→ WaitingAfterShooting → Idle
```

- **A 族（单发弹道）不需要状态机** —— 引擎流程本身就是状态机
- **只有这两类才要抄结构**：① 引导类（持续光束，需"进入/每帧/被中断"）② 多段法术（蓄力→发射→二段）
- 抄**结构**（状态枚举 + OnTick 推进 + 每状态副作用），**不是抄类**（那是带 `UsableMachine` 的器械）

### 8.2 雷电术（第二个目标，形态待定）

给三个候选，按成本排：

| 候选 | 形态族 | **施法方式** | 做法 | 成本 |
|---|---|---|---|---|
| **① 落雷**（单体天雷） | **A** | **③ 指定范围** | 取地面落点（`Scene.RayCastForClosestEntityOrTerrain`）→ 从落点上方生成一发 A 族弹（`AddCustomMissile` 自高处向下） | 最低（复用 + 一个落点函数） |
| **② 连锁闪电** | **A + 自写** | ① 方向（或② 锁定） | A 族命中后"找下一个目标再发一发"，递归 N 次 | 中（要写链式选敌） |
| **③ 雷暴**（持续落雷数秒） | **B + A** | **③ 指定范围** | 计时器每 X 秒落一发 ①，区域选敌 | 中（要写计时与区域） |
| （备选）雷环 / 电场 | **B** | 无（以自身为圆心） | 以自身为圆心的持续区域伤害 | 中 |

**建议**：先做 **①落雷**。它一次验证两件事：① A 族能不能做**非水平弹道**（从天上往下打）② **指定范围施法**（落点 + 指示圈）这套新机制。这两个结论后面 ③ 和所有天降类法术都要用。

⚠️ 注意 ① 与阴魔斩的差别：阴魔斩是"方向施法 + 水平弹道"（弓弩原生路径，最省），而落雷是"指定范围 + 垂直弹道"（要新写落点逻辑）。**所以 P6 比 P1~P5 多一个课题 —— 落点**。

**落点的最省做法**（P6 第一版）：不做指示圈 UI，直接用"准星射线打到哪就在哪落"（`Scene.RayCastForClosestEntityOrTerrain` 从眼睛往视线方向打，取 `closestPoint`）。指示圈作为 P6 的可选打磨项。

### 14.2 怎么验（一趟游戏看两个结论）

```
campaign.add_item_to_main_party SpellSeal | 1
campaign.add_item_to_main_party SpellCrescent | 40
```

🔴 **这条命令有两个坑，2026-09-21 各踩一次，反编译 1.2.12 实证**：

| # | 坑 | 实据 |
|---|---|---|
| ① | **按「显示名」查，不按 StringId** | `CampaignCheats.GetItemObject` 拿 `ItemObject.Name.ToString()` 去掉空格、忽略大小写跟输入比对；`Name` 来自 `ItemObject.Deserialize` 的 `Name = new TextObject(node.Attributes["name"].InnerText)` = **本地化后的显示名**。敲 `taikou_spell_seal` 一辈子查不到 |
| ② | **参数组用竖线 `\|` 分隔**，组内才用空格拼 | `GetSeparatedNames(strings, "\|")`。格式提示里那个 `\|` 是**语法**不是"或"。敲 `SpellSeal 1`（没竖线）→ 整串被当成**一个**名去比对 → 同样 not found |

**两个物品的显示名因此做成「中英同串的 ASCII」**（`SpellSeal` / `SpellCrescent`）——
免得中文客户端得在控制台敲中文（未必吃 IME）。这是**探针期**选择，P2 换正式网格时一并换成正经本地化名。

**踩坑时的误判方向要记牢**：报 `Item is not found` **长得像"物品没注册"**，
于是会去翻数据文件——**但这次数据从没被验到**。看到这个报错先确认"命令打对没有"，再查数据。

**分两步打，别一步到位**（这样能白拿一次变量隔离）：

1. **先纯 P0**：随便找一把**原版弩** + 装上法术弹，射一发 —— 看飞出去的是不是一个**陶罐**（而不是弩矢）。
   变了 = `flying_mesh` 生效，L1 复用路线成立。这一步只有"弹药"一个变量。
2. **再上 P1**：法印装弩槽、法术弹装弩矢槽，再射一发 —— 能装、能瞄、能发射、打中敌人掉血 = 法印 v0 成立。

两个网格都是**占位件**（弩 + 火罐），是故意的：排除"我们的资产坏了"这个变量，
形状差异又足够大，肉眼一眼可判。
