# 命令系统后续优化

> **来源**：2026-09-10 玩家实机日志复盘（随从听令把主公本人打晕）。
> **状态**：待审批，**未开工**。批准后按第四节顺序施工。
> **分工**：本文 = 修复计划（改哪里、怎么验收）；原始 badcase 记录见 [plan-badcases.md](plan-badcases.md) **BC-008**；系统设计见 [llm-goap-plan-execution.md](llm-goap-plan-execution.md)。

## 二、凭什么这么改（事故链，四步都有日志实证）

2026-09-10 20:55~20:57，玩家（朱祁心）对随从孙娴淑下令「把他打晕」，结果**自己**被打晕。证据取自玩家日志 `StoryEngine_RuntimeLog (9).txt`（行号见括注）：

1. **20:55:38 大模型指认是对的** —— 回复轮返回 `action_target = 大明卫所刀牌手#49`：站在 5 米外的那个兵，`#49` 是他在本场战斗里的唯一编号。（日志 1166 行）
2. **20:55:50 程序把一份正确计划误杀了** —— 计划轮大模型产出的也是打 `#49` 的正确计划，但计划生成后的"目标兜底检查"**拿玩家的命令原文去场上找人**；原文是"把他打晕"，里面没有人名（人名存在另一个字段里）→ 场上匹配 0 人 → 判定"场上没找到" → 扔掉计划、投出一张不成立的澄清卡：「场上没找到「大明卫所刀牌手#49」这样的人——您说的是谁？」（日志 1189-1190，明写"候选 0 个"）
3. **20:56:48 玩家被迫补话，大模型把目标认成主公** —— 玩家回"你旁边的就是"。这一轮 prompt 里没有【目标指认】段，大模型只能自己从【场景当前人员】段里认；而那段是**以主公为中心**写的（`[player] 玩家：你身旁0米`、`你东侧5米`、`面朝玩家`——孙娴淑自己被列成"你东侧6米"，可见"你"=主公），同一段 prompt 开头却写着"你是孙娴淑"——**同一个"你"字在一条 prompt 里指两个人**。大模型照字面把"你旁边的"认成"你身旁0米"那位 = 主公本人。（日志 1214，计划 `knockout → player`；日志 1213 是完整 prompt）
4. **20:57:13 没有任何守卫，照打** —— 计划校验只报了"缺超时/预案不足"这类结构警告（日志 1227-1235），三层代码里没有一处检查"目标是不是自己人" → 主公倒地（日志 1256 `act_death_fall_front`），并派生三条错误：4 名随从记忆写反（1255）、旁观者罪名判成偷窃（1258/1267/1270）、犯罪事件 `misconduct_town_south_3_3314751_1` 成立（1284）。

**因果判断**：第 2 步是**触发链起点**（没有假澄清，就不会有第 3、4 步）；第 4 步是**防线缺失**（prompt 再歪也不该真动手）；第 3 步是**prompt 视角缺陷**（即使修好第 2 步，同类指代仍会踩）；第 4 步派生的三条是**叙事污染**（已写进存档的错记忆不会自己恢复）。

## 三、逐项方案

### P0-1 目标兜底：判据从"命令原文"改成"已解析目标"

**症状**：目标就在场上，随从却说"场上没找到这个人"。

**根因**：计划生成后的兜底检查用 `_lastTargetCheckCommand`（玩家的命令原文/合并后的命令）去场上重采候选；而目标的真身（含 `#N` 编号）存在 `ResolvedTargetText` 字段里，**不在命令文本里**——命令"把他打晕"里没有任何人名 → 天然 0 候选 → 误判。

**改法**：候选查询串按优先级取——
1. `ResolvedTargetText` 非空 → **用它**（解析函数内部有 `#N` 精确解析，命中即唯一，天然区分"真人"和"编的名字"）；
2. 否则用命令文本（现状行为，保留）；
3. 换目标意图（`HasRetargetIntent`）仍走"剥掉锁定目标尾巴重采"（保留 2026-08-20 那次修复的语义，别回退）。
4. 加一条日志：`查询串 / 命中数 / 场上人数 / 判定结果（放行 or 澄清）`——本次定位全靠人工拼证据，这条日志让下次一眼可见（与 P2-7 合并做）。

**🔴 边界（别改错方向）**：0 候选**不能**一律放行——大模型编造一个不在场的名字时，仍然必须投澄清卡。用"`#N` 能否精确解析到人"来区分这两种情况。

**落点**：[ImCommandFlow.cs:493-534](../ExampleModVS/ExampleMod/ExampleMod/ImChat/ImCommandFlow.cs#L493-L534)（后置检查）· [ImCommandFlow.cs:705-752](../ExampleModVS/ExampleMod/ExampleMod/ImChat/ImCommandFlow.cs#L705-L752)（候选采集）· 参照 [ImCommandFlow.cs:330-331](../ExampleModVS/ExampleMod/ExampleMod/ImChat/ImCommandFlow.cs#L330-L331)（生成 prompt 那条路径的判据本来就是对的：用的就是 `ResolvedTargetText`）

**代价**：约 10 行 + 1 条日志。无新增配置项、无存档影响。
**风险/回归**：换目标流程（点候选 → 说"换个人"）必须仍然重采多候选；LLM 编造名字的澄清路径必须仍然触发。

**验收**：见第六节 S1（正例）/ S2（负例）。

### P0-2 执行守卫：随从不能对主公/队友动手

**症状**：随从听令把主公打晕——主公倒地 + 被禁跑禁攻 + 世界生成了一条犯罪事件。

**根因**：三层都没有"目标是不是自己人"的检查——计划校验层只查结构与词表（[PlanGrammar.cs:433](../ExampleModVS/ExampleMod/ExampleMod/Planner/PlanGrammar.cs#L433)）；执行步骤只解析目标是谁（[InlineSteps.cs:1482-1504](../ExampleModVS/ExampleMod/ExampleMod/Planner/InlineSteps.cs#L1482-L1504)）；共享的击晕管线只做判定与结算（[KnockoutFlow.cs:87-120](../ExampleModVS/ExampleMod/ExampleMod/Combat/KnockoutFlow.cs#L87-L120)）。

**改法（两层都做，缺一不可）**：
1. **计划校验层**（进执行前就拦）：`knockout` / `order_attack` 步骤的目标解析为**玩家本人**或**玩家队伍成员**时 → 丢弃该步并写进 Warnings；主链被丢空 → 整份计划拒收（给玩家一句诚实反馈，不是静默失败）。
2. **执行期层**（兜底，防绕过校验的路径）：击晕步骤构造时判目标是不是玩家本人/队伍成员 → 直接判该步失败 + **当面诚实报告**（新增两条本地化文案：「我不能对您动手」「那是自己人」）。

**🔴 需审批人拍板**：玩家明说"打我 / 把你自己打晕"要不要照办？
- **方案 A（建议）**：一律拒绝，引导到切磋玩法（现有 SPAR 路径）——击晕主公属于自杀式命令，语义上就是切磋。
- **方案 B**：改成"二次确认卡"，玩家确认后照办（保留整蛊玩法，代价是多一次点击）。

**落点**：`PlanGrammar.Validate` + `KnockoutInlineState` 构造函数；玩家可见文案进 [ModuleData/Languages](../ModuleData/Languages)（铁律 13，禁止硬编码中文）。

**代价**：小。2 处判据 + 2 条文案。
**风险/回归**：击晕路人/敌人/守卫等**正常玩法绝不能受影响**；切磋（SPAR）路径不受影响；「随从被自己人打晕」这种合法场景（同僚斗殴）也要确认不在拦截范围内。

**验收**：见第六节 S3。

### P1-3 场景清单视角错位（"你"指两个人）

**症状**：大模型把"你旁边的"认成主公本人。

**根因**：[SceneSnapshot.cs:440+](../ExampleModVS/ExampleMod/ExampleMod/Planner/SceneSnapshot.cs#L440) 渲染【场景当前人员】用的是**主公坐标**（`[player] 玩家：你身旁0米`、`你东侧5米`、`面朝玩家`；孙娴淑自己被列成"你东侧6米"就是铁证——"你"=主公），但这段被注入**发给随从**的 prompt（同一条 prompt 开头写着"你是孙娴淑"）。

**影响面**：所有"发给随从/路人"的 prompt——IM 计划轮、IM 回复轮、当面对话（respond）、闲聊动作空间。凡是需要大模型按方位/距离理解场景的地方都歪一点；"你旁边的""你身后那个"这类指代必然踩雷。

**改法两步**：
1. **止血（小改，本轮做）**：清单段首加一句坐标基准声明（"本段方位一律以主公为中心；'你'=主公"）+ 主公那一行从"你身旁0米"改成"主公（玩家本人）"（自身距离为 0 时不再落进"你身旁"分支）。
2. **正解（大改，下一轮单独做）**：渲染按**接收者视角**出方位——接收者是随从时，主公那行写"主公（朱祁心）就在你身旁0米"，其余人相对随从算方位与距离。需要给渲染函数加"观察者"参数，并逐个注入点传接收者。

**代价**：① 小（1 段模板 + 1 处分支）；② 中（渲染层 + 约 8 个注入点，回归面大）。
**🔴 纪律**：这条修好也**不能**去掉 P0-2 的守卫——prompt 出错是概率问题，守卫是确定性防线。

**验收**：见第六节 S4。

### P1-4 犯罪感知带上施暴者（记忆被写反）

**症状**：随从打晕主公后，同场景 4 名随从的记忆里被写成「主公刚刚把人打晕了（温州府附近）」——**被打的主公成了打人的那个**。

**根因**：[KnockoutFlow.cs:96](../ExampleModVS/ExampleMod/ExampleMod/Combat/KnockoutFlow.cs#L96) 无条件调用 `ReportPlayerMisconduct(罪行词)`；而该函数把施暴者**写死成主公**（[AttackTriggerMissionLogic.cs:1086](../ExampleModVS/ExampleMod/ExampleMod/Combat/AttackTriggerMissionLogic.cs#L1086) 拼「主公刚刚{罪行}」）——它的设计前提是"只有主公作案"。

**改法**：函数签名加一个"施暴者"参数（默认空 = 主公作案，文案不变；非空 = 同僚作案，用新文案「{施暴者}刚刚把主公{罪行}」）。调用点逐个核对：`KnockoutFlow.Resolve`（传 attacker）、`StealManager` 5 处（主公作案，保持默认）、`AttackTriggerMissionLogic` 内部调用。

**代价**：小~中（签名 + 2 条本地化文案 + 6 处调用点）。
**🔴 为什么优先级不低**：这条记忆会进【近期回忆】段喂给大模型——写反的记忆会让随从以后拿"主公打人"当事实说话，是**写进存档的持久污染**，越早改越好（已产生的错记忆无法自动回收，见第六节 S5 备注）。

**验收**：见第六节 S5。

---

### P1-5 罪名随事件传递（旁观者别再猜）

**症状**：主公被打晕，旁观者旁白却是"我看见孙娴淑在偷窃"，警戒因素记 `Steal`，质问台词也是偷窃台词（"你！放下！那是朱祁心的！"）。

**根因**：[AgentBrain.cs:861](../ExampleModVS/ExampleMod/ExampleMod/AI/AgentBrain.cs#L861) 用 `IsKnockedOut(受害者)` 来区分"打晕 / 斗殴 / 偷窃"，而它读的是**受害者的大脑标记**；玩家永不建脑（[AgentAIController.cs:216](../ExampleModVS/ExampleMod/ExampleMod/AI/AgentAIController.cs#L216) `if (agent.IsMainAgent) return;`）→ 恒为 false → **凡是"受害者=玩家"的犯罪，一律掉进"偷窃"分支**。
（注：[KnockoutFlow.cs:100-102](../ExampleModVS/ExampleMod/ExampleMod/Combat/KnockoutFlow.cs#L100-L102) 的注释显示这个坑以前踩过一次——事件时序版；这次是"玩家无脑"版。）

**改法**：把罪行类型**随事件传下去**——目击事件（`WitnessCrime` / `WitnessCrime_GatherOnLook`）增加一个"罪行类型"参数（打晕 / 斗殴 / 偷窃），由发送方（`KnockoutFlow.Resolve`、`StealManager`、`AttackTriggerMissionLogic`）填；大脑优先读事件参数，读不到再回退现有推断（兼容其余调用点，避免"改一处崩一片"）。

**代价**：中（事件参数是位置参数，所有目击事件的发送点/接收点要同步改）。
**风险/回归**：玩家偷窃被目击 → 仍是偷窃文案；斗殴 → 仍是斗殴文案。

**验收**：见第六节 S6。

### P2-6 计划结构缺陷自动修复（可延后）

**症状**：小模型（本次玩家用的是 `doubao-seed-2-0-mini`）常输出单预案、死预案（无跳转进入）、缺超时收尾的计划；现在只打日志警告，然后**带病执行**（日志 1227-1235）。

**改法**：计划校验器从"只警告"升级为"能补则补、不能补则拒收"——缺超时 → 补默认中止；死预案 → 丢弃；预案数不足 → 保留警告 + 可在 prompt 里追加"上次不合格项"要求重写一次（最多一次）。

**代价**：小~中。**说明**：这不是本次事故的成因，属体验打磨，可拆单。

---

### P2-7 目标解析可观测性（可延后，可与 P0-1 合并）

**改法**：目标解析的关键分叉处加确定性日志——`查询串 / 命中数 / 场上人数 / 走了哪条判据（#N 精确 / 名字 / 类型词 / 无匹配）`。

**代价**：小。

---

### 待核实的疑点（先查再定改法，可能派生新修复项）

**犯罪事件的当事方口径**：本次生成的 `misconduct_town_south_3_3314751_1`（AssaultValue=725 = 主公身价）里，**登记的行凶者是随从还是主公**？若记成主公，赔偿、对质、世界事件后续链会全错。需先查 `RecordAssaultVictim` 与事件落库时的行凶者取值，再决定是否加一项修复。

## 四、执行顺序

1. **P0-1**（断触发链——没有假澄清，就不会被逼出"你旁边的就是"）
2. **P0-2**（加确定性防线——prompt 再歪也不执行；含上面那个拍板点）
3. **P1-4**（止血记忆污染——已经写进存档的错记忆不会自己好）
4. **P1-3 ①**（视角止血，小改）
5. **待核实疑点**（查犯罪事件当事方口径）
6. **P1-5**（罪名传递，改动面中等，单独一轮回归）
7. **P1-3 ②**（视角正解，大改，单独一轮）
8. **P2-6 / P2-7**（打磨，可拆单）

**理由**：先断触发链，再加防线，最后修叙事污染——每一步都能独立验收，不互相挡。
