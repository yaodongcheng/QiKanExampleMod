## 一、起步抖动：根因与修法（✅ 代码已改，待实机确认）

**症状**：起飞后一给方向（按 W），角色朝向"抖一下"、"脸不在正前方"。

**根因**（反编译实证，不是猜的）：

| 事实 | 出处 |
|---|---|
| 摆相机用的 `Mat3.RotateAboutUp(角)`，作用在单位朝向上得到的前方 = `(−sin 角, cos 角, 0)` | `TaleWorlds.Library.Mat3` 反编译 |
| ⇒ "角" 与"方向"的换算必须是 `atan2(−x, y)`（= `Vec3.RotationZ`） | 同上 |
| 而旧代码写的是 `atan2(朝向.y, 朝向.x)` —— **两者差 90°** | `FlightCameraRig.YawDegOf`（已删） |

**后果**：接管那一帧镜头**绕角色横甩 90°**（画面上看像角色自己转了一圈）；按 W 时机身立刻对齐镜头（这一步逻辑本身是对的）⇒ **又转 90°**。用户看到的"抖一下 + 脸不在正前方"就是这两次 90° 的叠加。

**修法（已落地）**：

1. 接管相机时**直接读引擎相机此刻的视线方向**，用 `Vec3.RotationZ`（左右）/ `RotationX`（俯仰）换算 —— 镜头方向**逐度接上**，不甩不抖；机身本来就朝那个方向，按 W 也不再翻身。
   - 取不到相机帧时回落到角色朝向，**也走同一套换算**（不会再出现 90° 甩动）。
   - 顺手**删掉**那个错 90° 的换算函数（留着 = 下一个人还会踩）。
2. **机身转向加了限速**：`custom.flight tune turnrate <度/秒>`，默认 **540°/秒**（转 180° 用 0.33 秒）；**填 0 = 回到旧的"瞬时转身"**。
   - 为什么顺手加：转镜头时机身原来是"啪"地跟过去，"抖"的另一半来自这里。**做成可热调**是为了你能一个键切回旧手感对比。

**怎么验**（三条，都不用重编译）：

| # | 做什么 | 合格线 |
|---|---|---|
| 1 | 跳起来按空格起飞，**手不要碰鼠标** | 镜头不甩；看到的是**角色背面** |
| 2 | 悬停时松开所有方向键，鼠标绕圈 | 机身**定住不动**（转镜头能看各个面）—— 这条是第一轮就有的行为，别被这次改坏 |
| 3 | 按 W / 按 A ，再 `custom.flight tune turnrate 0` 重复一次 | 默认是**转过去**；turnrate=0 时恢复**瞬间到位** |

## 二、动画体系：UE 有什么 / 骑砍能给什么 / 我们怎么做

### 1. UE 那边的事实（已导出取证，不是听说）

**工程 = `SuperheroFlightAnimations`，UE 4.26，180 条飞行动画 + 20 个混合空间 + 2 个动画蓝图。**

**动画按家族分**（`A`~`E` 是**5 种风格变体**，不是 5 个方向）：

| 家族 | 条数 | 干什么 |
|---|---|---|
| `A_Flight_Idle_A..E` | 5 | 悬停待机（**唯一的真循环**，91 帧） |
| `A_Flight_Hover_Start_A..E` | 5 | 起飞 |
| `A_Flight_HoverMove_A..E` | 5 | 巡航（循环，61 帧） |
| `A_Flight_FastMove_A..E` + `_Start` | 10 | 冲刺趴姿（循环 31 帧 + 入姿） |
| `A_SuperheroLanding_A..E` | 5 | 落地 |
| `A_FM_{A..E}_Pose_U / _D / Pose` | 15 | ⚠️**增量**：`_U` 抬头 / `_D` 低头（不能直接播，见下） |
| `A_FM_{A..E}_Lean_{L,R,U,D}` | 20 | ⚠️**增量**：四个方向的倾斜 |
| `A_Flight_HoverLean_{A..E}_{L,R}_Add` | 10 | ⚠️**增量**：巡航左右倾斜 |
| `A_Flight_HoverMove_{A..E}_{F,B,L,R,U,D}_Add` | 30 | ⚠️**增量**：巡航六个方向的位移姿势 |
| `A_Flight_Dodge_{A..E}_{L,R,U,D}` | 20 + 20 蒙太奇 | 闪避（一次性动作） |

> ⚠️ **"加法"这两个字是关键**：`_Add` / `Lean_*` / `Pose_*` 那些是**增量姿势**（UE 里叠在基础动画上用的），
> 单独当普通动画播会**散架**。要用必须先合成（见下 §3）。

> 🔴🔴 **实测（推翻第一轮的一条判断）**：130 条里 **80 条是增量动画** ——
> UE 元数据 `AdditiveAnimType=AAT_LocalSpaceBase`，且**每条都写明了参照姿势**：
>
> | 增量家族 | 参照（`RefPoseSeq`） |
> |---|---|
> | `A_FM_{A..E}_Pose` / `_Pose_U` / `_Pose_D` / `_Lean_{L,R,U,D}` | `A_Flight_FastMove_{对应变体}` |
> | `A_Flight_HoverMove_{A..E}_{F,B,L,R,U,D}_Add` | `A_Flight_HoverMove_{对应变体}` |
> | `A_Flight_HoverLean_{A..E}_{L,R}_Add` | `A_Flight_HoverMove_{对应变体}` |
>
> ⇒ **第一轮方案里"`Pose_U` 是直立上升、可以直接导来当定格姿势"这句是错的**（那是"增量"被当成"姿势"看，
> 渲染出来像那么回事，但**当姿势播出来是坏的**）。好在第一轮没导它，没造成损失。
> ⇒ 这套**不能用"导进来直接播"，必须先烘焙**（§二·3 · B）。

**动画蓝图 `ABP_Player` 的结构**（已完整导出 + 逐节点解析，报告见 §附）：

- **飞行本体其实只有 3 个状态**：`待机/悬停 →（按下冲刺）→ 起飞过渡 → 巡航循环`，4 个跳转条件里 3 个是 `IsSprint`。复杂的地方**不在状态机，在叠加层**。
- 🔴 **叠加层的"强度"不是由变量控制的**：28 个叠加节点的强度**全是常量 1.0**，方向/倾斜的强弱来自**叠加层内部的混合空间**——把 `倾斜量(−1~1)`、`上下/水平速度分量(−1~1)` **直接当混合空间的轴**去采姿势。悬停状态是 **3 层叠加**（上下 / 水平 / 倾斜）摞出来的。
- **20+ 个混合空间**（每个变体一套：移动方向 / 倾斜 / 升降）——**升降那套是 1 维的，轴名就叫 `Speed`，取值 −1~+1**（实测：`−1 → _D_Add` 俯冲姿势、`+1 → _U_Add` 爬升姿势、`0 → 中性`）。**这就是你说的"以速度作参数的混合空间"**：它混的是**升降速度**
- 两个**引擎无关、可直接抄**的公式：
  - `上下/水平速度分量 = 把本地速度按 −最大速度~+最大速度 归一化到 −1~+1`（超范围钳住）
  - `倾斜量 = 平滑(角速度归一化到 −1~+1)`，平滑速度：左右用 5、俯仰用 15；角速度 = 相邻两帧速度方向的转角 ÷ 时间
- 瞄准用 `LookAt` 节点；闪避/落地走 **Montage**（一次性动作槽）
- 特效挂在动画时间轴上（`AnimNotify` / `AnimNotifyState`，详见 §三）

### 2. 骑砍2 引擎能给什么（反编译核实）

| 能力 | 接口 | 说明 |
|---|---|---|

| **交叉淡化** | 上面那个 `blendInPeriod` | ✅ 有，就是这个 |
| **播放速率** | `actionSpeed` / `SetCurrentActionSpeed` | ✅ 有（可用来做"越快动作越急"） |

| 读混合权重 | `GetActionChannelWeight` / `GetActionChannelCurrentActionWeight` | ✅ 有（只读） |
| **按参数连续混合两个姿势** | — | ❌ **没有**（没有权重 setter） |
| **加法叠加通道** | — | ❌ **没有** |

| 骨骼挂点粒子 | `MBAgentVisuals.CreateParticleSystemAttachedToBone` | ✅ 有（§三用） |

### 3. 结论：我们怎么做

| # | 决定 | 理由 |
|---|---|---|
| **A** | **速度混合 = 三档阶梯 + 交叉淡化**（悬停 / 巡航 / 冲刺），不做"连续参数混合" | 我们飞行是**定速**（巡航 9 / 冲刺 26 两个值），没有中间速度可混；引擎也没有权重接口。**等以后加了加减速**，再往阶梯里插一档（`FastMove_Start` 现成可当"加速中"） |
| **B** | **倾斜 / 爬升 / 俯冲 = 离线烘焙成绝对动画**（在 **TRF 层**合成，不用开 Blender），运行时按转向快慢切换档位 | 引擎没有加法通道（`_Add` 是增量，直接播会散架），也没有"按参数混合两个姿势"的接口。**做法照抄 UE 的思路、降级实现**：UE 是把 `倾斜量(−1~1)` 当轴在混合空间里采姿势；我们**把它量化成 3 档**（左满 / 正 / 右满），切换时交叉淡化。**倾斜量的算法照抄**（见 §二·1 的公式：角速度归一化 + 平滑；基准 ±180°/秒），而我们刚加的**转向限速**正好给这个公式提供了稳定的角速度信号 |
| **C** | **爬升 / 俯冲也走烘焙**（改：不再是"直接导 `Pose_U/_D`"） | 实测它们是**增量**（参照 `A_Flight_FastMove_A`）⇒ 直接导进来播是坏的。**改成烘"巡航 + 升降增量"**（参照姿势正好就是巡航本身，语义最干净） |
| **D** | 头随视线 = 用引擎自带的 `allow_head_movement` 标记 | UE 那边是 `LookAt` 节点；引擎有这个开关，不用自己写 IK |
| **E** | 🔴 **变体 `A~E` 要随机化**（2026-09-21 用户裁定，改掉原"只用 A"）：**每次起飞随机挑一种风格**；**俯冲结束 / 从冲刺回巡航这类"姿态归位"的时刻也重挑一次**。运行时行为 = 几行代码（开局抽一个编号，之后每次触发重抽），**代价全在导入侧**（变体是 5 条不同的 clip，要随机就得都导进来） | 观感回报最大的一条：同一套飞行每次进去长得不一样。**成本阶梯见 §二·4** |
| **F** | **闪避（Dodge 20 条 + 蒙太奇）单独立项**，本轮不动 | 它是**新玩法**（位移 + 无敌帧 + 输入），不是"打磨"，混进来会让这一轮失焦 |
| **G** | 🔴 **AI 空壳通知不要抄** | UE 里 `AnimNotify_HoverStrat` / `StartFlightTrailVFX` / `StopFlightTrailVFX` 三个"通知"**图形体是空的**（不产生任何效果），真正管拖尾的是另一个。**别照名字抄设计** |

**烘焙为什么便宜**（实现口径，写代码时照这个来）：

- 增量是**每骨一个固定的局部旋转**（那几条增量动画只有 2 帧 = 常量），
  所以"合成"= 把基础动画**每一帧**都乘上同一个旋转：`结果(第 t 帧) = 基础(第 t 帧) × (增量 × 参照首帧⁻¹)`（逐骨）。**不涉及时序、不涉及插值。**
- 🔴 **可以在 TRF 上直接做，不需要 Blender**：重定向是"每骨乘一个固定旋转 R"，
  而 `(R·增) × (R·参照)⁻¹ = R · (增 × 参照⁻¹) · R⁻¹` —— **R 会自己约掉**，
  所以"先重定向再合成" 与 "先合成再重定向" **结果一样**。⇒ 一个"读两条 TRF、写一条 TRF"的短脚本即可。
- 产物仍是 TRF，**照样走"ModKit 导入"那条路**，下游一字不改。

**② 特效分两类挂，这是 UE 自己的分法**（别只做一类）：

| 类 | 例子 | UE 怎么挂 | 我们怎么挂 |
|---|---|---|---|
| **状态驱动**（跟着状态开 / 关） | 拖尾、脚下尘土、加速光效 | 状态开关（`BPAN_SetActiveFlightVFX` 这类）——**不是**挂在时间轴上 | 跟 `PickAirAction` 的状态走：进冲刺开拖尾、退出就关 |
| **时间轴驱动**（到点触发一次） | 落地冲击、起飞爆发、闪避 | Montage 上的 `AnimNotify`，**时刻已逐条解出** | 标记表 + `GetCurrentActionProgress`（S4） |

> 🔴 **别照抄 UE 的通知名字**：`AnimNotify_HoverStrat` / `StartFlightTrailVFX` / `StopFlightTrailVFX`
> 三个在 UE 里**图形体是空的**（不产生任何效果），真正管拖尾的是另一个。**拿效果清单当依据，不拿名字当依据。**
> 另一条实测：130 条动画里**只有 15 条带通知**，全在"起手 / 过渡"上（循环本体是干净的）——
> 也就是说**循环动画上本来就没有特效**，拖尾那种持续效果只能由状态开关管（与上表一致）。

**③ 不用做贴图资产**：转出来的 XML 用的是**原版材质**（`prt_shd_fire_1` 这种）。
UE 的贴图只用来做离线预览，不进游戏 —— 这一条把工作量砍掉一大半。
（顺带：材质是按名字映射的，飞行这几个特效的名字里带 `trail` / `dust` / `glow`，**现有规则表能直接命中**，不用加规则；真遇到没命中的再补。）

### 2. 分四步做，**从最便宜的开始**

| 步 | 做什么 | 谁 | 依赖 |
|---|---|---|---|
| **S1** | **相机特效**（纯 C#，零资产）：加速瞬间 FOV 冲一下 + 轻微抖动；起飞/落地各一下 | 我 | 无 |
| **S2** | **注册冒烟测试**：把 1 个 UE 特效（建议 `NS_Flight_Hover_Start`）转成 XML → 进包注册 → 实机在游戏里看到它 | 我 + 你 | 你实机 |
| **S3** | **批量破解**：飞行 6 + 脚下尘土 5 + 落地 5 → XML → 预览页逐个看 | 我 | S2 |
| **S4** | **时间轴绑定**：一张标记表（动作 + 时间点 → 特效），每帧按 `GetCurrentActionProgress` 推进触发 | 我 | S3 |

**为什么 S2 单独一步**：内容包注册粒子 XML 这条路**从来没在实机验证过**（工具链文档里就写着这是唯一没被证明的一环）。
先拿 1 个特效验通，再批量 —— 免得 16 个特效一起上，出了问题不知道是注册坏了还是单个特效坏了。

**注册怎么做**（照 Native 的官方写法）：`Modules\Taikou\ModuleData\particle_systems_lwn_flight.xml`（平铺在 ModuleData，不新建目录）
+ `project.mbproj` 加一行 `<file id="soln_particle_systems" name="ModuleData/particle_systems_lwn_flight.xml" type="particle_system" />`。
Native 自己就把这个 id 挂了 **7 个文件**，我们只加**新名字**（`lwn_*`）= 纯追加，不覆盖原版。

**S4 的绑法（优雅在哪）**：特效清单**不进代码**，写成一张表（动作名 + 归一化时间 → 特效名 + 挂点）。
代码每帧只做一件事：`进度 = GetCurrentActionProgress(0)`，越过某个时间点就触发。
好处：调时间点、换特效、加动作**都不用重编译**；表本身就是"动画时间轴"的骑砍版本。

**照抄 UE 的时刻表**（落地蒙太奇，实测）：`0.13 秒` → 震屏 + 落地冲击特效 + 视场拉伸；尾段 `1.33~2.0 秒`「有移动输入就打断」。
起手类（起飞 / 冲刺入姿）同理，逐条在 §附 的解析报告里。

**挂点**：脚下（法阵处）用实体挂粒子（已实机验证的写法：`FirearmFxLogic`）；
拖尾用**骨骼挂点**（`CreateParticleSystemAttachedToBone`，能挂在手/脚/骨盆上）——
⚠️ 骨骼挂的粒子**没看到对应的销毁接口**，S3 时要先验一次（挂上→落地→还在不在），确认不泄漏再用。

### 3. 地面材质区分（草/沙/石各一套尘土）——**可选，排最后**

UE 按物理材质分 5 套落地特效。我们地面是地形，要"知道脚下是什么材质"得再查一次 API 能不能拿到。
**建议先不做**：先用一套通用尘土，观感已经到位；等你要"沙漠起沙、草地扬草"时再单独立项。

## 五、风险与回退

| 风险 | 处理 |
|---|---|
| 烘焙的倾斜姿势"不像"（增量合成的空间可能不对） | 先烘 1 条（巡航+左倾）在预览里看；不像就退回"不做倾斜"，其他项不受影响 |
| 注册粒子 XML 让游戏起不来 | 回退 = 删 `project.mbproj` 那一行（文件留着不生效）；做法与之前 4 次成功启用同款 |
| 骨骼挂点粒子会残留 | S3 先做"挂上→落地→再看"的一次性验证；残留就改用实体跟随（站在骨骼位置的实体） |
| 抬升/俯冲两条定格姿势接上去观感怪 | 它是**定格**不是动作（飞行没脚部着地，读起来就是"保持这个姿势在飞"）；不满意只是把 `ActClimb`/`ActDive` 填空回空 |
| 全部改动 | 代码：`turnrate 0` + 删掉相机播种那几行即可回到旧行为；资产：tpac 回滚到备份 |
