## 〇、一句话

把太阁5 的全量数据（人、家、城、组织）**按时代差异机制**铺进 **Taikou**：人/家/城/中文名对齐
**表制式 StringId**（见 §〇·补），只补真缺的；产出 = Taikou 的时代差异段 + 共享段。

**运行环境**：1.2.12（Taikou 的目标机）。

### 〇·补、🔴 与原方案最根本的差异：**没有"生成物 vs 真身"的分裂了**

原方案最痛的一点：`ShokuhoTaikouExpansionPack` 里的 753 人生成物**全部未注册 = 引擎内存里不存在**
（骑砍不自动扫 ModuleData，文件必须在 `SubModule.xml` 的 `<Xmls>` 段声明才加载），
而"真身"在织丰 mod 里 → 数据分裂成两套，要靠"沿用织丰 id + 只补缺口"来缝合。

**Taikou 下这个问题不存在**：它是我们自己的包，**铺进去的数据就是运行真身**——
`SubModule.xml` 的段注册 + 多时代 GameType 机制（已实机验证）直接生效。
⇒ **原方案的大量缝合工作（沿用仲裁/存活双口径/补充 XML 生成）简化为"按表产出 Taikou 的数据段"。**

## 一、四原则（用户 2026-08-28 裁定，本 plan 的验收依据；2026-09-11 载体改 Taikou）

1. **沿用**：**表里的 StringId 制式**（`lord_1_oda` / `clan_oda_1` / `town_CHUB11` 一类）为唯一命名基准，
   Taikou 现有占位 id（`lord_oda_nobunaga`）**改齐到表制式**（见 [07b §〇](07b-织丰表解读-StringId覆盖率.md)）
2. **按需新增**：太阁5 剧本点名、表里没有的角色 → 新增。🔴 **检查口径 = 并集**：
   `事件点名（522）∪ BaseInfo 人物全集（≈1049）`——因为 `csv/BaseInfo.csv` 基本全是太阁5 本身有的人物
   （1506 行 = 太阁5 人物底表，去重 1049），剧本数据包会拉到它的全部；只扫事件点名会漏掉
   「太阁5 有、事件近期没登场」的一大片（归一后并集 = **1127 人**：1049 + 事件独有 78）
3. **化名匹配**：同一人多名的（木下藤吉郎 = 丰臣秀吉 = 羽柴秀吉）必须先对名再谈新增
4. **最终物**：**Taikou/ModuleData/** 下的数据段能跑事件，且**正确性经检查**
