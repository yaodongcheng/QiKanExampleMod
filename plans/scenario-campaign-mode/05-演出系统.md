# 05 — 演出系统：StoryCompiler + PlaybackEngine + StoryDialogVM 升级

> **Phase 1 | 依赖：01（演出挂起队列）| 出口：预编译产物播放 + 多 agent 演出 UI + SCN_* 指令**
> 对应蓝图：§3.5 / §3.8.6 / §3.8.7。代码位置：`Scenario/Playback/` + `Scenario/Compiler/`。

## 目标

回应 StoryEngine 批评（运行时动态扫描 + 无多 agent 能力 + UI 陈旧）：**StoryCompiler 预生成**（编译期算好分幕/站位/镜头/进出场，运行时零扫描）+ **StoryEngine 执行器化**（PlaybackEngine）+ **StoryDialogVM 升级**（UI 重构接近原版对话流 + 多 agent 互动）。

## 分步实施

### Step 1 — StoryCompiler 编译产物 Schema（Scenario/Compiler/PlaybackSchema.cs）🔴 先行定义
- 预计算结构：`PlaybackScene[]`（分幕表：sceneId/参与者清单/站位分配 StageSlot/镜头序列/进出场指令展开/时间轴/选项树展开）
- 产物格式 = 纯数据（JSON），**与太阁 DSL/StoryEngine 指令分离**（编译器产出，PlaybackEngine 消费）
- Schema 先行冻结（样板 = ReadStory.cs StoryEvent 结构 + 编译产物新定义）
- 验收：Schema 文档 + 样例产物可反序列化

### Step 2 — StoryCompiler 编译器（内容包侧工具，Python/C#）
- 输入：StoryJson（太阁 DSL 翻译产物，见 08）→ 中间表示 → 编译产物
- 计算内容：分幕（场景切换点切幕）、每幕参与者清单（对话指令提取说话人）、站位分配（StageSlot：主位/客位/旁听位）、镜头序列（SpringArmCameraView 模板 + 机位按说话人）、进出场指令展开（入场/退场动画指令序列）、时间轴（Wait 时长）、选项树展开（分歧展开为选项节点）
- **导演标注覆盖层** `_director_notes.json`：人工指定某幕镜头/站位（质量可调，编译时合并）
- 验收：太阁剧本样例 → 编译产物 dump（分幕/参与者/站位/镜头齐全）

### Step 3 — PlaybackEngine（执行器化 StoryEngine）
- 运行时只顺序执行编译产物（PlaybackEngine 替代动态分析执行路径）
- 移除：`ExecutionContext.RefreshSceneScope` / `GetCurrentSceneParticipants` / `AssignSlots` 等运行时扫描逻辑（移入编译器）；保留：场景切换（`進入設施` + `_isWaitingForSceneChange`）、等待（StartWait）、阻塞语义（对话/选择）
- 保留 CommandManager 新指令注册：`SCN_SET_WORLD`（内嵌 effects → 01 ActionExecutor）/ `SCN_CUTSCENE`（过场）/ `SCN_IM`（私聊投递）/ `SCN_MEET`（SpawnHeroInFrontOfPlayer）/ `SCN_BATTLE`（程序化战斗，依赖 03）/ `SCN_FLAG` / `SCN_CHOICE_BRANCH`（IF 分支）
- 验收：预编译产物播放全流程（对话/选择/场景切换/进出场）

### Step 4 — StoryDialogVM 升级（🔴 用户裁定：UI 重构 + 多 agent）
- **UI 重构**：视觉接近原版对话流（说话人名字/头像/文本区 + 底部选项列表——玩家零学习成本）；保留复用现成组件模式（StoryOptionVM 选项/预测/置灰/悬停、继续提示、StoryTraitVM 特质）
- **多 agent 互动**：对话轮转（`對話` 指令带说话人 → UI 自动切名字/头像/镜头）、旁听者（在场未发言 agent 站立/坐下/注视）、多方表态（分歧节点多 NPC 依次发言）、镜头跟随说话人（SpringArmCameraView 模板按说话人切换）
- 🔴 **斩断旧链**：`OnDialogClosed → OnDialogueEnded → GenerateEventAsync`（无当面对话 `_memory` null 必崩）——升级时彻底移除该回调链
- 🔴 **IM confirmFight 纪律**：ATTACK/DUEL/KNOCKOUT/STEAL 确认回调**禁止**改调重制版 `Close()`（沿用 IM 面板关闭路径，铁律 16）
- UI 纪律：按 wheels.d/ui.md（GauntletLayer 摘层守卫 HasLayer+!LayerFinalized+try/catch、输入门控、手柄兼容、层序表）
- 验收：两 NPC 对话轮转（名字/头像/镜头切换）+ 旁听者站位 + 选项 → 分支；IM confirmFight 路径不受影响

### Step 5 — 过场适配（ScenarioAdapters.ShowCutscene）
- `ScenarioSceneNotificationData : SceneNotificationData`，角色槽位 `CampaignSceneNotificationHelper.CreateNotificationCharacterFromHero`
- 文本 `LWNTextHelper.BuildCompoundTextObject`（铁律 13）
- 验收：桶狭间出征/胜利过场（Phase 2 接）

## 出口验证（Phase 1）

1. StoryCompiler：太阁剧本样例 → 编译产物（分幕/站位/镜头）dump 完整
2. PlaybackEngine：预编译产物播放（对话/选择/场景切换/进出场）无运行时扫描
3. StoryDialogVM 升级：多 agent 轮转 + 旁听者 + 镜头跟随说话人；旧链已断（无 OnDialogClosed 崩溃路径）；IM confirmFight 正常
4. 无 LLM 全流程（编译产物兜底文本直出）

## 风险

- 🔴 StoryDialogVM 升级是废弃系统重制——**铁律 16**：斩断旧链 + IM confirmFight 不碰重制版 Close()（实机 11:13:37 崩溃教训）
- 编译产物 Schema 冻结顺序（先 Schema 后编译器）
- 原版对话流视觉还原（UI 重构工作量大，先做基础版：名字/头像/文本/选项）
- 镜头跟随说话人（SpringArmCameraView 模板切换）在 multi-agent 场景的性能/稳定性实测
