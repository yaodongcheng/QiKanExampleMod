## 这一步做什么（一句话）

把"看戏"这件事做好：
1. **预编译**——太阁5 剧本翻译过来的演出脚本，先在编译期算好一切（分几幕、每幕谁在场、站哪、镜头怎么切、谁什么时候进场退场），运行时只照着播——解决旧演出引擎"每次运行现算、又慢又没准"的问题
2. **播放器**——执行编译好的演出；新增一批剧情指令（放过场/发私信/让 NPC 现身/触发战斗/设旗标/分支选择）
3. **对话面板升级**——旧面板（谈判小游戏专用、已废弃）重做成**接近原版对话流的样子**（名字/头像/文字区 + 底部选项），支持**多人轮转说话**（谁说话切谁的名字头像镜头）、旁听者站位、多方表态

## 玩家视角

- 御殿会议：信长、家臣团轮番说话，镜头跟着说话人切，没说话的坐在旁边看着你；选项弹出时你可以选，也可以拔剑掀桌（不锁死输入）
- 演出流畅稳定：镜头/站位是提前排好的，不会出现"人站歪了/镜头乱切"的现场事故
- 面板看起来像原版对话（零学习成本），但能力更强（多人、旁白、带检定的选项）

## 怎么实现（四个部件）

1. **编译产物格式**（先冻结）——一场演出 = 一幕一幕：每幕的场景、参与者、站位分配、镜头序列、进出场、时间轴、选项树
2. **编译器**（内容包侧工具）——输入：太阁 DSL 翻译产物；输出：编译产物。算分幕（切场景处切幕）、提说话人、分站位（主位/客位/旁听位）、排镜头（跟随说话人）、展开进出场、排时间轴
   - **导演标注**：人工可以写一个覆盖文件，指定某幕用某镜头/某站位——质量人工可调，编译时合并
3. **播放器**（旧演出引擎改造）——只按顺序播编译产物；砍掉"运行时现算参与者/站位"的旧路径；保留场景切换/等待/阻塞
4. **对话面板升级**——UI 重构（原版对话流视觉）+ 多 agent 互动（说话人切换/旁听者/镜头跟随）+ 选项挂检定/战斗/分支
   - 🔴 **两条安全红线**：①切断旧面板的崩溃回调链（无对话时必崩的旧路径，实测踩过坑）②游戏内确认弹窗（切磋/偷窃等）继续走自己的关闭路径，不许改调新面板的关闭接口

## 分步骤清单

| 步骤 | 做什么 | 完成标志 |
|---|---|---|
| 1 | 编译产物格式（先冻结） | 格式文档 + 样例产物能解析 |
| 2 | 编译器（分幕/参与者/站位/镜头/进出场/时间轴 + 导演标注合并） | 样例剧本编译产物 dump 完整；导演标注生效 |
| 3 | 播放器（执行编译产物；新增剧情指令；砍运行时现算） | 编译产物全流程播放（对话/选择/切场景/进出场） |
| 4 | 对话面板升级（UI 重构 + 多人轮转 + 旁听者 + 镜头跟随） | 两人对话轮转正确；旁听者站位；选项→分支 |
| 5 | 过场适配（出征/胜利/死亡等章节点题画面） | 过场能放、角色槽位正确、文本走翻译表 |

## 做完怎么验收

1. 样例剧本 → 编译产物（分幕/站位/镜头齐全）→ 播放全流程无现场计算
2. 多人演出：两人轮转说话（名字/头像/镜头切换）、旁听者站位、选项分支
3. 旧崩溃链已断（无对话场景不会再崩）；确认弹窗路径不受影响
4. 没配 AI 全流程可玩（编译产物的兜底文本直出）

## 要注意的坑

- 面板升级是"废弃系统重制"——两条安全红线必须验（上面第 4 部件）
- 编译产物格式冻结顺序：先格式后编译器，不然返工
- 镜头跟随说话人在多人场景的性能/稳定性要实测
- UI 重构工作量大：先做基础版（名字/头像/文本/选项），高级效果（旁听者动画等）迭代加
