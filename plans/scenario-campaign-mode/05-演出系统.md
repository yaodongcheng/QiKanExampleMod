## 这一步做什么（一句话）

把"看戏"这件事做好：
1. **预编译**——太阁5 剧本翻译过来的演出脚本，先在编译期算好一切（分几幕、每幕谁在场、站哪、镜头怎么切、谁什么时候进场退场），运行时只照着播——解决旧演出引擎"每次运行现算、又慢又没准"的问题
2. **播放器**——执行编译好的演出；新增一批剧情指令（放过场/发私信/让 NPC 现身/触发战斗/设旗标/分支选择）
3. **对话面板升级**——旧面板（谈判小游戏专用、已废弃）重做成**接近原版对话流的样子**（名字/头像/文字区 + 底部选项），支持**多人轮转说话**（谁说话切谁的名字头像镜头）、旁听者站位、多方表态；🔴 **头像位**：骑砍2 无原生头像——AI 生成"光荣风格"头像随数据包加载（附录-角色头像生成，非前期必须，**先留占位**：无头像显示角色首字/默认图标）；🔴 **立绘叙事原则**（2026-08-25 用户裁定，附录动机）：骑砍2 建模短板——**3D 只做站位动作，2D 立绘负责人物认知与表情**（古早 RPG 仙剑四/侠客风云传式）；面板支持**立绘情绪状态切换**（怒/笑/惊/哀，数据包多情绪图，首版静态头像 + 文本情绪）

## 玩家视角

- 野战开场（大地图立绘，2026-08-25 裁定）：义元/信长立绘轮转说话（"全军止步！""窄道……有胜算了！"），战术选择弹出时你发言，选完进战役；敦盛之舞（城主间 3D）：信长独舞、归蝶/小姓在场，镜头跟着说话人切，没说话的坐在旁边看着你；选项弹出时你可以选（🔴 拔剑掀桌交互已降级为参考设计，见"玩家介入与演出封控"）
- 演出流畅稳定：镜头/站位是提前排好的，不会出现"人站歪了/镜头乱切"的现场事故
- 面板看起来像原版对话（零学习成本），但能力更强（多人、旁白、带检定的选项）

## 怎么实现（四个部件）

1. **编译产物格式**（先冻结）——一场演出 = 一幕一幕：每幕的场景、参与者、站位分配、镜头序列、进出场、时间轴、选项树
2. **编译器**（内容包侧工具）——输入：太阁 DSL 翻译产物；输出：编译产物。算分幕（切场景处切幕）、提说话人、分站位（主位/客位/旁听位）、排镜头（跟随说话人）、展开进出场、排时间轴
   - **导演标注**：人工可以写一个覆盖文件，指定某幕用某镜头/某站位——质量人工可调，编译时合并
3. **播放器**（旧演出引擎改造）——只按顺序播编译产物；砍掉"运行时现算参与者/站位"的旧路径；保留场景切换/等待/阻塞
4. **对话面板升级**——UI 重构（原版对话流视觉）+ 多 agent 互动（agent = 场景里实际站着的角色实体；剧情角色运行时映射出 agent，模板 NPC 也生成 agent；说话人切换/旁听者/镜头跟随）+ 选项挂检定/战斗/分支
   - 🔴 **两条安全红线**：①切断旧面板的崩溃回调链（无对话时必崩的旧路径，实测踩过坑）②游戏内确认弹窗（切磋/偷窃等）继续走自己的关闭路径，不许改调新面板的关闭接口

## 🔴 参与门控与单演出多机位（3D 多视角三通道，2026-08-24）

AVG 多视角（AVG = 文字冒险/视觉小说类游戏）= 每个视角各做一份完整演绎（重放）；3D 三通道（三种信息渠道：玩家在场看演出 / 玩家缺席走渠道通知 / NPC 侧世界模拟结算）= **一份演出 + 参与门控**（04 裁定）：

1. **参与门控字段**（编译产物格式增加）——每场演出带 `involved`（参与者角色引用 + 条件，如"玩家 ∈ {信长, 织田军在场者}"）：
   - 玩家满足 → 完整播放（**玩家侧才有戏**：扮演信长看布阵动员、扮演义元看休息混乱——同一份事件组按玩家身份**互斥选路**，太阁5 同款，玩家命中哪条哪条演）
   - 玩家不满足 → 跳过演出本体，只保留"渠道通知锚点"（该场发生了什么的短文案 → 走 IM/传闻/世界信号）
   - 🔴 **NPC 当事人从不演出**：NPC 侧 = 世界模拟结算（02/14），不为 NPC 运行事件演出；玩家恰好旁观在场（非当事人）时，可选看世界内真实发生（3D 红利，非机制要求）
2. **导演标注扩展**：覆盖文件可指定某场演出的"参与条件"和"缺席通知文案"
3. **播放器参与判定**：运行时按玩家身份（阵营/角色/位置）判定 → 选播放路径；判定逻辑与 02 AI 纠正 / 03 战斗的玩家阵营判定**同源**（不另起一套）
4. **不重放纪律**：同一个名场面只写 1 份演出数据（**互斥选路，玩家只命中一条，只跑一次**）；太阁5 的镜像事件（163/707 两侧各写一份）在 3D 里 = **玩家身份互斥选路，只有玩家所在侧有戏，禁止复制**

> 🔴 **脚本强制 mission 的 Esc 截断语义（2026-08-26，裁定在 01 scene hop 段）**：过场式全控下 Esc = 玩家被允许的离开通道——演出截断 = 步骤完成、脚本继续；世界结算照常（结算唯一不变），被截断演出内容走 absentNote 渠道摘要。

**问题**：NPC 演出（敦盛之舞/结盟仪式/过场）时玩家可以随意走动/拔剑/开菜单——剧本会被打断（说话人被砍、人走光、场景切走）。

**原则**：既不全锁（出戏——按钮没反应最糟，铁律 6），也不全开（剧本必崩）——**分层封控 + 打断必须被演出感知并回应**（设计哲学三：NPC 接得住）。

| 档 | 场景 | 玩家身份 | 玩家封控 | 打断处理 |
|---|---|---|---|---|
| A 关键演出 | 敦盛之舞/结盟仪式/晋升宣布 | **主公/主人**（主持人） | 软封：锁攻击/互动，允许移动 + 拔剑保留 | 拔剑 = 显式打断（拍案掀桌特权）→ NPC 惊愕 → 中止走分支 |
| | | 🔴 **家臣/列席**（被召集者） | **更严**：锁攻击/互动 + **列席位限制**（编译产物站位分配，离开席位 = 离席行为）；拔剑键不吞但 = **大不敬行为** | 🔴 **秩序维持者（守卫 NPC）第一响应**：拔剑 → 守卫上前压制（按回席位，强制移动 + 短输入锁）→ **演出继续**；重复违规/攻击守卫 → **升级 `onDisrespect`**（拿下/逐出 → 主公震怒分支，铁律 12）；离席 → 守卫引回/质询 |
| B 场景演出 | 日常对白/NPC 闲聊/战后余波 | 任意 | 不封：玩家可走动、可离开 | 离开 → 演出在 NPC 之间继续（玩家回来看到结果）；攻击 → 演出中止 + 战斗逻辑接管（NPC 正常反击） |
| C 世界内行为 | NPC 日常（无演出） | 任意 | 不封（本来开放） | — |

🔴 **封控 = 档位 × 在场身份**——同一场结盟仪式，玩家是信长（主持人，可掀桌）vs 玩家是家臣（列席，拔剑 = 大不敬）行为边界完全不同。太阁5 同款（评定间里家臣的行为限制）。

**🔴 前期 MVP（Phase 1，本次实现就是这个）**：A 档演出 = **封住玩家自由行动**（输入全锁，多 agent 轮流发言），**只有玩家说话（对话选项节点）时才弹选项**——其余时间玩家单纯观赏剧情（先验证演出链路稳定）；**秩序维持者 + 打断分支 = 已裁定不实施**（2026-08-25，见下参考设计）。

## 🔴 内核复用与台本化（StoryEngine / StageDirector 现有代码，2026-08-24）

**现有内核 = 舞台剧导演管理**（`Story/StoryEngine.cs` + `Story/StageDirector.cs`）：

- **StoryEngine = 执行器**：栈式 RunLoop（`ExecutionContext` 栈管嵌套/分歧）、阻塞/恢复（对话/等待/切场景）、进出场等待（`_movingAgentsForEntering/Leaving` + `_isWaitingForMovement_*`，演员走到位才继续）、`StartEvent` 用 `V.SetAgentAI(Agent.Main)` 收走玩家控制权（封控的现成起点！）
- **StageDirector = 舞台调度**：`StageConfig` 槽位（Gate/Chair/Guest/Accompany1/Accompany2，CSV 解析）→ `RegisterActor` → 🔴 `CalculateAllPositions` **预计算所有槽位坐标并缓存**（注释："对话开始前调用一次之后不再调用，锁死位置防闪烁"——**已是预编译思想**）→ `ShowActor/HideActor`（瞬移门口 → SetScriptedPosition 走位 → 等待到位 → FadeOut 退场）→ `ChangeActorSlot/SetActorSpecialPosition`（**"谁过程中走到什么地方"**）

🔴 **现状动态算的 4 个点（台本化要消灭的"运行时现算"）**：

| 动态算（运行时） | 台本化后 |
|---|---|
| 向前扫描脚本算"当前幕谁在场" | 编译期确定参与者，排演成指令流（幕信息内嵌） |
| 运行时分配站位 | 槽位由入场指令给定（导演排好） |
| 运行时判断谁该入场 | **显式 `actor_enter` 指令**取代 |
| 运行时偷看下一幕算谁退场 | **显式 `actor_leave` 指令**取代 |

🔴 **台本 = 可执行的指令流，不是行号索引表**（2026-08-24 用户裁定：执行到某处就是明确的入场/离场/走位指令——不用 enterAt/leaveAt 行号）：
```jsonc
// 编译产物 = 分幕指令流（ScriptNode 列表，与现有 RunLoop 逐行执行模型一致）
// 🔴 铁律 20 + 域规范：actor 引用一律 StringId 且带域前缀——Hero::lord_1_oda（剧情角色，运行时按 HeroId 映射 Agent）/ Agent::guard_oda（场景内模板 NPC，TemplateId）；cmd 用英文 token——中文只准在注释
// 🔴 多实例消歧（2026-08-25）：Agent:: 模板 NPC 可有多个实例（多个守卫/士兵）——用语义位消歧：{ "actor": "Agent::guard_oda", "at": "护卫1" }（spawn 时分配语义位并登记 StageDirector._actorMap 实例↔槽位表，运行时按 TemplateId+语义位匹配）；"at": "any" = 就近/首个；Hero:: 一对一无歧义；战场群演（几十个士兵）走氛围层不个体引用
{ "acts": [
  { "sceneId": "sho_meeting_castle_a", "nodes": [
      { "cmd": "actor_enter", "actor": "Hero::lord_1_oda", "slot": "Chair" },                            // 显式入场（触发 StageDirector.ShowActor，等走位完成）
      { "cmd": "dialogue", "speaker": "Hero::lord_1_oda", "textKey": "LWN_SCN_..." },
      { "cmd": "actor_enter", "actor": "Hero::lord_1_maeda", "slot": "Accompany1", "involved": [...] },  // 参与门控挂指令上（玩家不在 → 跳过入场，走渠道）
      { "cmd": "actor_move", "actor": "Hero::lord_1_maeda", "to": { "slot": "Guest" } },                // 中途走位（ChangeActorSlot/SetActorSpecialPosition）
      { "cmd": "dialogue", "speaker": "Hero::lord_1_maeda", "textKey": "..." },
      { "cmd": "actor_leave", "actor": "Hero::lord_1_maeda" }                                            // 显式离场（触发 HideActor）
  ] }
] }
// 🔴 现有代码的运行时 Cmd 是中文（"對話"/"對話選擇"，太阁源直译）——台本化后编译产物输出英文 token，CommandManager 加映射/兼容层（实现细节），与 01 DSL 英文 token 纪律统一
```

**台本 = 编译器排演产物**：编译器分析源剧本 → 确定每幕参与者 → **在脚本流中插入显式调度指令**（演员首次说话前插 `actor_enter`、末句后插 `actor_leave`、中途换位插 `actor_move`）——**编译期推断一次，运行期显式执行**；行号索引的脆弱性（插一行全乱）不存在，指令流自包含、可读（"信长入场→会议→利家入场禀报→走位→离场"），与现有 RunLoop 的 Cmd 执行天然一致。

### 🔴 台本的时间控制（同时做几件事 / 等大家都到位再继续，2026-08-24）

导演的台本不是一条线走到底——**一个提示点可以同时推多个动作**（并行）、**等谁到位再继续**（依赖）、**背景不用等**（异步）。我们沿用现有引擎"一条线顺序执行"的骨架，加三种等待方式（最小改动）：

| 语义 | 台本写法 | 舞台剧对应 | 现有引擎对应 |
|---|---|---|---|
| **等它完成**（默认） | 无标记 | "等演员走到位再开口" | 遇等待就停下等（✅ 已有） |
| **不用等** | `"async": true` | "灯光/音效不用等" | 发出去继续走下一行（新） |
| **等一组都完成** | `{ "cmd": "sync", "group": "entrance" }` | "等所有入场完成再开会" | 等挂同一组的"不用等"全部完成（复用现有等待机制） |

```jsonc
{ "cmd": "actor_enter", "actor": "Hero::lord_1_oda", "slot": "Chair" },   // 阻塞入场（默认）
{ "cmd": "fx_rain", "async": true },                                      // 异步：雨效与后续并行（不等）
{ "cmd": "actor_enter", "actor": "Hero::lord_1_maeda", "slot": "Accompany1", "async": true, "group": "entrance" },  // 异步入场：走位在后台
{ "cmd": "dialogue", "speaker": "Hero::lord_1_oda", "textKey": "..." },  // 对话照常进行（利家在后台走位）
{ "cmd": "sync", "group": "entrance" },                                   // 等"entrance"组的入场全部完成再继续
{ "cmd": "dialogue", "speaker": "Hero::lord_1_maeda", "textKey": "..." } // 全员到齐后的对白
```

- **并行场景**：多人同时入场（现有引擎已支持多 agent 并行走位）｜入场与对白并行（"不用等"的入场 + 对话继续）｜特效/音效/镜头与对白并行（"不用等"）
- **依赖表达**：挂同一组的"不用等"在"等一组都完成"处汇合；更复杂的"谁等谁"（依赖图）留给导演标注覆盖层（复杂编排用，基础版不做）
- **纪律**：只有明确不需要等待的才标"不用等"（特效/音效/镜头/多人入场之一）；**对白永远等**（对话流不能跳）——标错 = 演员没到就开口（穿帮）
- **执行器**：async 指令执行后不 return（继续下一行），完成回调登记进组；`sync` 阻塞时复用 `_isWaitingForMovement_*` 等待机制

### 🔴 场景内角色引用（Agent 域与多实例消歧，2026-08-25）

**台本在 Mission 执行，操作的是 Agent 实例**——但数据层写**稳定身份**（Agent 每次进场景重新生成，绝不能写进台本），运行时映射：

| 域 | 语义 | 运行时映射 | 消歧 |
|---|---|---|---|
| `Hero::lord_1_oda` | 剧情角色（Campaign 层，有 HeroObject） | 按 HeroId 映射 Mission 内 Agent（现有 `GetAgentInMission`） | 一对一无歧义 |
| `Agent::guard_oda` | 场景内模板 NPC（无 HeroObject，引用 = CharacterObject.StringId，铁律 8 平权） | 按 TemplateId 找场景实例，缺失可 spawn（03 编排） | 🔴 多实例 → **语义位消歧** |

**多实例消歧（`at` 语义位——语义位 = 站位的语义名字（"门左守卫"/"主位"），不是坐标）**：
```jsonc
{ "cmd": "actor_enter", "actor": "Agent::guard_oda", "at": "guard_1" }   // 护卫模板在"guard_1"位的实例（英文 token 语义位 id）
{ "cmd": "actor_enter", "actor": "Agent::guard_oda", "at": "any" }      // 随便一个（就近/首个）
```
- 🔴 **位 = 叙事身份**：门口左守卫 vs 殿内右守卫是**不同的叙事角色**（一个拦玩家、一个站主公身边）——不用序编号（"守卫#3 是谁？"无意义）
- **生命周期**：spawn 时分配语义位（护卫1 站门左、护卫2 站门右）→ 登记 `StageDirector._actorMap`（实例↔槽位绑定表，已有）→ 运行时按 TemplateId + 语义位查表命中唯一实例 → 坐标走场景适配（分层回退）——**全部复用既有设施，无新造机制**
- **边界**：Hero:: 一对一无歧义；战场群演（几十个士兵）走氛围层（以少代多）**不个体引用**——真要引用（"左翼旗手"）用 03 布局语义位

### 🔴 槽位系统升级：语义位 + 情景模板 + 关系式解算（2026-08-24）

**问题**：①不能写死坐标（每场景手工配 CSV 槽位 = 爆炸）②纯 LLM 判相对位置不可靠 ③固定模板（Chair/Guest/Accompany1/2）太机械 ④情景差异大（御前会议等级秩序 / 军团本阵军事位次 / 街头会面平等对位）⑤站位要不要定朝向。

**舞台剧导演的做法**：舞台分区（"左二"= 语义位置非坐标）+ 调度（"站主公左侧"= 相对关系）+ 朝向（面向说话对象）。**导演从不写坐标，写"语义 + 关系"，由系统解算**。

**三层设计**：

1. **情景模板**（数据包定义，每情景类型一套语义位集合 + 布局规则——不共用机械槽位；🔴 **语义位 id 一律英文 token**（铁律 20：标识不可本地化/改名），中文只准注释与显示层）：
```jsonc
{ "type": "court_meeting",                                  // 御前会议：等级秩序
  "anchors": { "chair": "rel_chair", "gate": "abs ..." },   // 🔴 锚点 = 场景标记（ChairTrans/TagPoint）——存在性编译期校验，缺失走降级链（见场景适配）
  "slots": [ { "id": "throne",      "rule": { "rel": "anchor:chair", "dir": "front", "dist": 0 }, "facing": "anchor:gate" },   // 主位（锚点本身），面朝门（迎客）
             { "id": "retainer_1",  "rule": { "rel": "anchor:chair", "dir": "left", "dist": 2 },  "facing": "anchor:chair" },  // 列席1：官职越高越近主位，面朝主位（对上位说话）
             { "id": "retainer_2",  "rule": { "rel": "anchor:chair", "dir": "left", "dist": 4 },  "facing": "anchor:chair" },
             { "id": "retainer_3",  "rule": { "rel": "anchor:chair", "dir": "right", "dist": 2 }, "facing": "anchor:chair" },
             { "id": "gate",        "rule": { "rel": "anchor:gate", "dir": "front", "dist": 1 },  "facing": "anchor:chair" },   // 门位，面朝主位（进门先见主）
             { "id": "guard_1",     "rule": { "rel": "anchor:gate", "dir": "left", "dist": 1.5 }, "facing": "anchor:gate" } ] } // 秩序维持者站位，面朝门（盯入口）
// 军团本阵（03 共用）：帅位 = 锚点 + 部将1-4 = 围着帅位站一圈（军职/资历均分）+ 传令位（门附近）+ 地图桌（道具位，部将绕桌围坐）
// 街头会面：对位A（玩家原位 = 锚点 player）+ 对位B（前方 2.5m 面对面）+ 随从位（左后/右后 1.5m）
```
🔴 **锚点体系与方位词（几何基础）**：
- **原点 = 语义中心，不是场景坐标**：谁最"中心"谁当原点——御前会议 = 主位（主公）、本阵 = 帅位（主将）、街头会面 = 对话双方、军议 = 地图桌（道具位）；**玩家本身可以是锚点**（rel_player 即"锚点 = 玩家"：玩家是主公时，列席就相对玩家站位）
- **方向 = 方位词 + 距离**（相对锚点朝向，不写角度）：前/后/左/右 + 四个斜角（数据里写 front/back/left/right 等英文 token）+ 距离（米）——换算 = 从锚点朝向出发，按方向转、按距离偏移；"围一圈" = 绕锚点圆周均分（环形列座/围坐）
- **语义位全集（8 类功能位，模板按需选用）**：权力位（主位/帅位）｜列席位（列席1-N，官职序）｜对位（对位A/B 面对面）｜从属位（随从/护卫——🔴 秩序维持者站位！）｜功能位（门位/传令位/报告位）｜旁听位（旁观）｜道具位（地图桌/案几，绕物排列）｜特殊位（TagPoint 导演标记）
2. **分配器（按确定规则排，不靠 LLM 猜）**：角色 → 语义位——御前会议 = 按官职排序（17 功勋链：家老近主位、足轻远；座次按官职等级排）；本阵 = 按军职/资历围着帅位站；街头 = 对话双方面对面。🔴 **LLM 只做"情景变体选择"**（密谈近位 vs 正式列席——数据包预定义变体，第一版不做）
3. **换算（语义位 → 场景里的实际坐标）**：锚点坐标 = 现有 StageConfig 解析（每场景只配锚点）；语义位 = 锚点 + 相对偏移 + NavMesh 吸附（NavMesh = 角色可走的地面网格，吸附 = 把目标点贴到最近的可站立位置；复用 `GetRandomNavMeshPoint`/`BuildWorldFrameFromLocalPose`）；🔴 **朝向 = 关系式（面向谁，不写角度）**：🔴 **`facing` 是每个语义位自带的默认朝向字段**（内嵌在 slot 里：`{ "id": "guard_1", "rule": ..., "facing": "anchor:gate" }`——"这个位上的角色默认面向谁"：列席面朝主位、护卫面朝门；**不设独立 facing 表**——位与朝向天然一体，新增位不会漏朝向）

🔴 **运行时朝向动态（facing 是静态底座，运行中随对话/指令变，2026-08-25）**：

| 时机 | 朝向规则 |
|---|---|
| 入场 / 走位完成 | 该位模板 facing（静态默认） |
| 对话节点 | 说话者与对话对象**互看**（面对面）；🔴 模板可声明 `lookAtSpeaker: true/false`——御前会议 = true（上位说话全员注视，等级秩序）/ 旁听位 = false（保持自己 facing） |
| `face` 指令（对话挂 face / 独立指令） | 显式指定（面向观众/门/某物）——覆盖一切，直到被下一条规则重置 |
| actor_move 走位后 | 重置为该位 facing |

- **默认规则**：对话时**说话者与对话对象互看，其余人保持模板 facing**——不是全员齐刷刷转头（机械感）；`lookAtSpeaker` 是模板级开关
- 现有引擎对应：入场看人已有（`Agent.Main.SetLookAgent`）；对话互看 = Agent LookAt 机制（原版对话流双方互看现成）

### 🔴 场景适配（语义位 → 场景实例，自动化解算最后一步，2026-08-24）

**问题**：语义位是抽象的（"主位左侧 2 米"），场景是具体的——目标点可能**在墙里**（NavMesh 不可达/穿模）、**坐席不够**（模板 5 列席、场景 3 椅）。不能脱离场景聊站位，也不能手工逐场景验证。

**自动化 = 分层回退**：

```
第 1 层：场景标记位（TagPoint/ChairTrans——设计者指定）        ← 最准，直接用
   🔴 锚点存在性校验：模板引用的锚点（chair/gate）∈ 场景标记清单（编译期查 TagPoint/ChairTrans 记录）；**缺失 → 降级链**：该锚点用玩家位 / 场景中心 / 门兜底，适配表记录回退结果（台本校验脚本同步查锚点引用，缺失 = 错误）
第 2 层：模板规则位（方位词 + 距离）→ 自动适配：
   ├─ 撞墙就缩短距离：目标点在墙里 → 沿方向逐步缩短（2m→1.5m→1m→0.8m）直到能站
   ├─ 方向被挡就换方向：正左被挡 → 试左前/正前/右前…（逐个试）
   └─ 落在家具里 → 同上重试
第 3 层：降级位：列席 → 站席；旁听 → 角落（软位可降级）
第 4 层：兜底：门位站着（门总是可达）
```

- **硬位 vs 软位**：模板语义位分硬位（必须有：主位/对位）和软位（可降级：列席/旁听可站）；场景数据标注坐席容量（如"本场景列席容量 3"）→ 分配器按官职截断：**高官坐、低官站**（御前会议礼仪本就如此，非 bug）
- **🔴 预先算好，玩的时候只查表**：场景清单固定 → 模板 × 场景预计算"场景适配表"（每语义位：命中位/回退结果/降级标记），找位置的探测开销编译期一次做掉，**运行时零探测只查表**；`rel_player` 动态位跟随玩家运行时算
- 🔴 **03/05 共用"布局探测层"**：找路探测 + 撞墙缩短 + 换方向 + 家具检查是通用工具（03 营地布局同源问题），不各写一套
- 调试：`custom.scene_probe <sceneId> <templateId>` dump 每个语义位的适配结果（命中/回退/降级）——12 A4 验收用

### 🔴 台本校验脚本（离线检查，保证演出品质，2026-08-25）

**背景**：台本 = 离线生成的交付物（编译期产出 → 打包 → 玩家运行）——不能靠玩家现场发现问题，需要 Python 脚本在产出/发布前检查台本是否合理。与 01 事件 validator 并列（各管各的：01 管事件/DSL 层，本脚本管演绎台本/演出层），**引用合法性共用人物池/场景/本地化清单**。

**检查三层**：

**① 语法/引用层**（与 01 validator 同源检查）：
- cmd ∈ 指令表；actor/speaker ∈ 人物池（Hero::/Agent:: 域 + StringId + **无中文**，铁律 20）；slot/at ∈ 情景模板语义位清单；act → animId ∈ 动作清单（05 动作能力模型）；sceneId ∈ 场景清单；textKey ∈ 本地化文件

**② 时序/在场层（演出品质核心）**：
- **说话人必须先入场**（dialogue 前有 actor_enter）；**离场后不能再说话**
- sync 组闭合（等一个从没发起的组 = 错误）；**演出结尾无未完成的"不用等"**（人还在路上演出就结束 = 穿帮）
- 入场前无动作/走位（人没到位就做动作）；camera target 当前在场
- **对白永远"等它完成"**（async 的 dialogue = 错误——对话流不能跳）

**③ 品质/能力层**：
- 动作 × 角色能力（骨骼兼容：human_child 排除；装备要求）；姿态链可解（坐着做不了站姿动作——编译器应已插前置，校验兜底）
- choice 写槽后存在对应 if 块（演绎剧本与骨架同构检查，01 #17）；fx_* 特效/音效 ID 存在
- 分配器可解：角色在模板里有语义位可分配、坐席容量不超（超 = 降级记录在案，**警告非错误**——高官坐低官站是合法降级）

**运行时机**：08 编译台本产物后 + **发布前必跑**（12 流程）；错误 = 阻断发布；警告 = 建议（与 01 validator.py 同报告格式：文件/行号/问题/建议）
**脚本位置**：内容包工具链（与 validator.py 并列；引用合法性检查共用人物池清单）

**台本对应**：`actor_enter` 的 `slot` = 语义位 id（"主位"/"列席1"/"对位A"），解算是机制——台本仍显式（导演排演定"利家→列席1"），坐标与朝向由系统解。**槽位不写死、不 LLM 猜、不机械、情景自适应、朝向关系式**。

**保留 vs 替换**：StageDirector 槽位系统 + 坐标预计算缓存 ✅ 保留升级（槽位分配从运行时 `AssignSlots` 改为台本给定）；StoryEngine 栈式执行/阻塞恢复/移动等待骨架 ✅ 保留（播放器 = 按台本执行）；被替换的只有"现算"逻辑（扫描/分配/进出场判断）→ 编译期静态化（StoryCompiler 把 `GetCurrentSceneParticipants`/`AssignSlots`/进出场判断逻辑搬到编译期跑一遍，产物即台本）。**运行时零扫描、零现算**——`RefreshSceneScope` 只查台本幕表，不再向前扫脚本。

## 🔴 战斗演出（战斗中的剧情演绎，2026-08-24）

**问题**：已有演出都是和平场景；战斗中的剧情（本能寺信长见光秀）怎么演——**把玩家从战斗切走 = 破坏战斗体验**（切场景回来战斗感觉全无）。

**舞台剧的三招**：①**以少代多**（千军万马 = 近处几个兵 + 战鼓 + 烟雾）②**编舞 + 停顿**（打几回合 → 定格/慢动作 → 对白 → 再打）③**Tableau 定格瞬间**（全场静止、灯光聚焦、两人对视、独白）。

**映射 = 软接管，不切场景**：

| 介入强度 | 机制 | 现有轮子 |
|---|---|---|
| **软介入** | 慢动作（子弹时间）+ 镜头特写 + 独白——战斗继续但节奏被打断 | ✅ wheels.d/stealth.md 子弹时间 + SpringArmCameraView |
| **硬介入** | 战斗暂停（时间冻结）+ 演出 + 恢复 | Mission 时间控制（待验证） |
| **叙事介入** | 不暂停——对白走战斗喊话/IM | ✅ SpeechChannel 战斗喊话 |

**战场氛围层（03 扩展，以少代多）**：近处几个敌兵（可打/可无视）+ 远处的火/烟/喊杀声 = 环境粒子 + 持续声景 + 雾——03 已有"雨夜/黄昏/火光"氛围数据指定，扩展**持续声景（喊杀/火声）与火粒子（本能寺大火）**为环境层。

**Tableau 瞬间**（本能寺例）：信长在着火的城楼 → 氛围层（大火 + 烟 + 喊杀声景）→ 光秀现身 → **慢动作 + 镜头对切 + 独白**（"光秀……你吗！"）→ 恢复战斗或演出介入选择。

**台本新增指令**：`battle_pause`（硬介入暂停）/ `slowmo`（软介入慢动作）/ `tableau`（慢动作 + 镜头对切 + 对白组合）/ `fx_fire`（氛围层）——挂阻塞（默认等完成）/ async（不用等）/ sync 组（等一组都完成）三态。

**纪律**：软介入优先（保留战斗手感）；硬介入只用于关键瞬间（Tableau）；🔴 **战斗演出不改变战斗结算**（击杀/战败仍走 03 逻辑，演出只是"节奏打断"）。

## 🔴 镜头语言与角色动作（表演层，2026-08-25）

**缺什么**：镜头给谁、是否特写（景别）、每一步的角色动作——台本目前只有对话/调度指令，没有表演层。

**镜头指令 `camera`**（电影/舞台导演镜头语言）：

| 字段 | 语义 | 默认 |
|---|---|---|
| `target` | 镜头对准谁：`speaker`（说话人）/ actor 引用 / 锚点（主位/门）/ 环境（火/城楼） | speaker（现有隐式"镜头跟说话人"显式化） |
| `shot` | 景别：`closeup` 特写 / `medium` 中景 / `wide` 全景 / `over_shoulder` 过肩 | medium |

- 🔴 **景别 = 情感距离**：特写 = 独白/对峙/Tableau（本能寺"光秀……你吗！"必须特写）、中景 = 会议对话、全景 = 环境/大军/着火城楼
- 现有 `UseCameraTemlate`（`xm_Any_Side45_Far_R`）= 机位模板，景别作为显式字段叠加；导演标注可覆盖
- 纪律：默认中景跟说话人——不必每行写 camera；关键节点（Tableau/对峙/独白）显式写

**角色动作指令 `actor_action`**（每步的表演——"边说边做"是舞台剧常态）：

```jsonc
{ "cmd": "actor_action", "actor": "Hero::lord_1_oda", "act": "stand_up", "async": true },  // 说话前站起（不阻塞）
{ "cmd": "dialogue", "speaker": "Hero::lord_1_oda", "textKey": "...",
  "camera": { "shot": "closeup" },                                        // 特写
  "action": { "actor": "Hero::lord_1_maeda", "act": "bow" } }             // 利家同时鞠躬（对白节点挂动作）
```

| 动作类 | 例 |
|---|---|
| 姿态 | sit / stand_up / kneel（坐/立/跪） |
| 礼仪 | bow 鞠躬 / salute 拱手军礼 |
| 情绪 | slam_table 拍案 / draw_sword 拔刀（🔴 连接"拔剑=打断"：演出中角色主动拔刀 = 表演动作）/ throw_cup 掷杯 |
| 位移 | step_forward 上前（actor_move 已有） |
| 道具 | raise_cup 举杯 / hand_over 递物（动态道具） |

- 动作库 = 数据包定义（动作名 → SetPose/ForcePlayAction 动画组合，复用 wheels.d/stealth.md 击晕机制 / agent.md ForcePlayAction），核心只做指令机制（worldview 铁律）
- 纪律：动作是表演节点（需要才写），默认纯对话；动作与对白并行用 `async`（边说边做）

### 🔴 动作能力模型（动作库来源：角色当前能执行哪些原版动作，2026-08-25）

**来源 = 骑砍2 原版动画全集**：`MBActionSet.GetNumberOfActionSets()` + `GetActionSetWithIndex(i)` 可全量枚举（MySubModule.DumpAllActions 已有实现，`LivingWorldNpcs_Actions_Dump.txt` 导出先例）——🔴 **编译期导出"动作清单"**（动作库数据包参考 + validator 校验用）。

**🔴 关键洞察：切集方案使"动作集包含"不再是限制**——AgentControlHelper.ForcePlayAction 已有完整管线（`MBActionSet.GetActionSet("as_human_warrior")` → `FillAnimationSystemData` → `SetActionSet` 切集 → `SetActionChannel` 播 → `RestoreActionSetAsync` 还原；注释"as_human_warrior 是所有人类动作的根"、已 war 跳过切集避免 AccessViolation 竞态）——**村民也能播武士动画**（临时切集）。真正的限制只剩三层：

| 判定层 | 内容 | 时机 |
|---|---|---|
| 动画存在性 | 语义动作 animId ∈ 动作清单（MBActionSet 枚举） | ✅ 编译期静态校验（validator） |
| 骨骼兼容 | human_child 骨骼差异（击晕文档已踩）——动作定义标 `bones` 白名单排除 | 数据包 + 运行时 |
| 装备/姿态 | draw_sword 需武器在手（查 agent.Equipment）；坐姿先站起（动作链：坐→站→鞠躬） | 运行时 |

**语义动作定义（数据包）**：`{ "act": "bow", "animId": "...", "preferredSet": "as_human_warrior", "bones": ["human","human_warrior"], "requires": { "weapon": "any" }, "pose": "standing", "fallback": ["近似动作", "台词表现"] }`
- 运行时能力查询：`AgentActionValidator.CanPlay(agent, act)` = 动画存在（编译期已验）∧ 骨骼兼容 ∧ 装备满足 ∧ 姿态链可解
- 🔴 **降级链**：不可播 → 近似动作（bow→低头）→ 台词表现（旁白"他微微欠身"）→ 跳过（纯对话）——演出永不因动作缺失卡死
- 调试：`custom.anim_check <heroId> <act>`——查角色当前能力（action_set/骨骼/装备 → 语义动作可行性）
