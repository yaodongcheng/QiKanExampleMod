## 这一步做什么（一句话）

把"看戏"这件事做好：
1. **预编译**——太阁5 剧本翻译过来的演出脚本，先在编译期算好一切（分几幕、每幕谁在场、站哪、镜头怎么切、谁什么时候进场退场），运行时只照着播——解决旧演出引擎"每次运行现算、又慢又没准"的问题
2. **播放器**——执行编译好的演出；新增一批剧情指令（放过场/发私信/让 NPC 现身/触发战斗/设旗标/分支选择）
3. **对话面板升级**——旧面板（谈判小游戏专用、已废弃）重做成**接近原版对话流的样子**（名字/头像/文字区 + 底部选项），支持**多人轮转说话**（谁说话切谁的名字头像镜头）、旁听者站位、多方表态

## 玩家视角

- 御殿会议：信长、家臣团轮番说话，镜头跟着说话人切，没说话的坐在旁边看着你；选项弹出时你可以选，也可以拔剑掀桌——**拔剑 = 显式打断**（A 档软封下唯一保留的介入键），演出感知并回应（家臣惊愕、会议中止、进入战斗分支，见"玩家介入与演出封控"）
- 演出流畅稳定：镜头/站位是提前排好的，不会出现"人站歪了/镜头乱切"的现场事故
- 面板看起来像原版对话（零学习成本），但能力更强（多人、旁白、带检定的选项）

## 怎么实现（四个部件）

1. **编译产物格式**（先冻结）——一场演出 = 一幕一幕：每幕的场景、参与者、站位分配、镜头序列、进出场、时间轴、选项树
2. **编译器**（内容包侧工具）——输入：太阁 DSL 翻译产物；输出：编译产物。算分幕（切场景处切幕）、提说话人、分站位（主位/客位/旁听位）、排镜头（跟随说话人）、展开进出场、排时间轴
   - **导演标注**：人工可以写一个覆盖文件，指定某幕用某镜头/某站位——质量人工可调，编译时合并
3. **播放器**（旧演出引擎改造）——只按顺序播编译产物；砍掉"运行时现算参与者/站位"的旧路径；保留场景切换/等待/阻塞
4. **对话面板升级**——UI 重构（原版对话流视觉）+ 多 agent 互动（说话人切换/旁听者/镜头跟随）+ 选项挂检定/战斗/分支
   - 🔴 **两条安全红线**：①切断旧面板的崩溃回调链（无对话时必崩的旧路径，实测踩过坑）②游戏内确认弹窗（切磋/偷窃等）继续走自己的关闭路径，不许改调新面板的关闭接口

## 🔴 参与门控与单演出多机位（3D 多视角三通道，2026-08-24）

AVG 多视角 = 每视角一份完整演绎（重放）；3D 三通道 = **一份演出 + 参与门控**（04 裁定）：

1. **参与门控字段**（编译产物格式增加）——每场演出带 `involved`（参与者角色引用 + 条件，如"玩家 ∈ {信长, 织田军在场者}"）：
   - 玩家满足 → 完整播放（**玩家侧才有戏**：扮演信长看布阵动员、扮演义元看休息混乱——同一份事件组按玩家身份**互斥选路**，太阁5 同款，玩家命中哪条哪条演）
   - 玩家不满足 → 跳过演出本体，只保留"渠道通知锚点"（该场发生了什么的短文案 → 走 IM/传闻/世界信号）
   - 🔴 **NPC 当事人从不演出**：NPC 侧 = 世界模拟结算（02/14），不为 NPC 运行事件演出；玩家恰好旁观在场（非当事人）时，可选看世界内真实发生（3D 红利，非机制要求）
2. **导演标注扩展**：覆盖文件可指定某场演出的"参与条件"和"缺席通知文案"
3. **播放器参与判定**：运行时按玩家身份（阵营/角色/位置）判定 → 选播放路径；判定逻辑与 02 AI 纠正 / 03 战斗的玩家阵营判定**同源**（不另起一套）
4. **不重放纪律**：同一个名场面只写 1 份演出数据（**互斥选路，玩家只命中一条，只跑一次**）；太阁5 的镜像事件（163/707 两侧各写一份）在 3D 里 = **玩家身份互斥选路，只有玩家所在侧有戏，禁止复制**

## 🔴 玩家介入与演出封控（2026-08-24：NPC 演出时玩家能不能动？分层模型）

**问题**：NPC 演出（御殿会议/结盟仪式/过场）时玩家可以随意走动/拔剑/开菜单——剧本会被打断（说话人被砍、人走光、场景切走）。

**原则**：既不全锁（出戏——按钮没反应最糟，铁律 6），也不全开（剧本必崩）——**分层封控 + 打断必须被演出感知并回应**（设计哲学三：NPC 接得住）。

| 档 | 场景 | 玩家身份 | 玩家封控 | 打断处理 |
|---|---|---|---|---|
| A 关键演出 | 御殿会议/敦盛之舞/结盟仪式/晋升宣布 | **主公/主人**（主持人） | 软封：锁攻击/互动，允许移动 + 拔剑保留 | 拔剑 = 显式打断（拍案掀桌特权）→ NPC 惊愕 → 中止走分支 |
| | | 🔴 **家臣/列席**（被召集者） | **更严**：锁攻击/互动 + **列席位限制**（编译产物站位分配，离开席位 = 离席行为）；拔剑键不吞但 = **大不敬行为** | 🔴 **秩序维持者（守卫 NPC）第一响应**：拔剑 → 守卫上前压制（按回席位，强制移动 + 短输入锁）→ **演出继续**；重复违规/攻击守卫 → **升级 `onDisrespect`**（拿下/逐出 → 主公震怒分支，铁律 12）；离席 → 守卫引回/质询 |
| B 场景演出 | 日常对白/NPC 闲聊/战后余波 | 任意 | 不封：玩家可走动、可离开 | 离开 → 演出在 NPC 之间继续（玩家回来看到结果）；攻击 → 演出中止 + 战斗逻辑接管（NPC 正常反击） |
| C 世界内行为 | NPC 日常（无演出） | 任意 | 不封（本来开放） | — |

🔴 **封控 = 档位 × 在场身份**——同一场御殿会议，玩家是信长（主持人，可掀桌）vs 玩家是家臣（列席，拔剑 = 大不敬）行为边界完全不同。太阁5 同款（评定间里家臣的行为限制）。

**🔴 前期 MVP（Phase 1）**：A 档先按常规过场处理——多 agent 对话流控制玩家（每个人轮流发言），输入全锁、**玩家单纯观赏剧情**（先验证演出链路稳定，守卫/打断交互后置）；**秩序维持者 + 打断分支 = 完整形态（Phase 2+，随 09 剧本）**。

**实现要点**：
1. 封控 = 输入掩码（复用 SetInputRestrictions，IM 面板已有）；🔴 **演出结束必须重置掩码**（wheels.d/ui.md 教训：`_lastCompactMask` 残留导致下次打开输入限制被跳过）
2. **A 档按身份保留介入键**：主公档 = 拔剑键保留为显式打断（拍案特权）；家臣档 = 拔剑键不吞但**定义为大不敬行为**（触发 `onDisrespect` 后果分支，非轻打断）——防止"玩家狂按没反应"（出戏）
3. 打断分支进 01 事件：perform 可挂 `onInterrupt`（中止演出 + 分支 flag，与 choice 分支同构）；🔴 家臣大不敬走 `onDisrespect` 变体（主公震怒 → 斥责/处罚/处刑/战斗，按 17 官职/关系权重裁），效果 when 门控接分支
4. 演出结束恢复：输入掩码恢复 + NPC 归位（站位数据编译产物已有，重放位置即可）
5. 大地图演出（campaign 层，无玩家 Agent）：模态暂停（复用 UiFullScreenHelper/模态门控轮子），玩家离开 = 演出继续（不阻断世界）
6. **封控 = 档位 × 在场身份**（编译产物 `involved` 带身份标记）：站位分配即封控边界（主位/列席位/旁听位——家臣列席位外移动 = 离席行为）；🔴 **发言权限联动 17 功勋**：御殿会议可发言/可提议 = 官职解锁（家老可提议、足轻组头旁听）
7. **秩序维持者 = 场景守卫 NPC**（剧本演员表/03 编排，如织田卫兵）："按回去" = AgentControlHelper 强制移动（回席位）+ SetInputRestrictions 短锁（复用 wheels.d/agent.md 移动分派 + ui.md 掩码轮子）；**主公档守卫不干预**（拍案特权保留）；守卫被打 = 守卫反击/告警 → 升级 `onDisrespect`；守卫也服务 B 档（日常场景的城卫维持治安，同一机制）

## 🔴 内核复用与台本化（StoryEngine / StageDirector 现有代码，2026-08-24）

**现有内核 = 舞台剧导演管理**（`Story/StoryEngine.cs` + `Story/StageDirector.cs`）：

- **StoryEngine = 执行器**：栈式 RunLoop（`ExecutionContext` 栈管嵌套/分歧）、阻塞/恢复（对话/等待/切场景）、进出场等待（`_movingAgentsForEntering/Leaving` + `_isWaitingForMovement_*`，演员走到位才继续）、`StartEvent` 用 `V.SetAgentAI(Agent.Main)` 收走玩家控制权（封控的现成起点！）
- **StageDirector = 舞台调度**：`StageConfig` 槽位（Gate/Chair/Guest/Accompany1/Accompany2，CSV 解析）→ `RegisterActor` → 🔴 `CalculateAllPositions` **预计算所有槽位坐标并缓存**（注释："对话开始前调用一次之后不再调用，锁死位置防闪烁"——**已是预编译思想**）→ `ShowActor/HideActor`（瞬移门口 → SetScriptedPosition 走位 → 等待到位 → FadeOut 退场）→ `ChangeActorSlot/SetActorSpecialPosition`（**"谁过程中走到什么地方"**）

🔴 **现状动态算的 4 个点（台本化要消灭的"运行时现算"）**：

| 动态算（运行时） | 位置 | 台本化后 |
|---|---|---|
| 向前扫描脚本算"当前幕谁在场" | `ExecutionContext.RefreshSceneScope` → `GetCurrentSceneParticipants(Script, Index, ...)` | 编译期确定参与者，排演成指令流（幕信息内嵌） |
| 运行时分配站位 | `PrepareActors` → `VisualCommands.AssignSlots()` | 槽位由入场指令给定（导演排好） |
| 运行时判断谁该入场 | `CheckActorEntering`（`info.FirstLineIndex == ctx.Index` 扫描首次出场行） | **显式 `actor_enter` 指令**取代 |
| 运行时偷看下一幕算谁退场 | `CheckActorLeaving`（peek 下一幕 participants） | **显式 `actor_leave` 指令**取代 |

🔴 **台本 = 可执行的指令流，不是行号索引表**（2026-08-24 用户裁定：执行到某处就是明确的入场/离场/走位指令——不用 enterAt/leaveAt 行号）：
```jsonc
// 编译产物 = 分幕指令流（ScriptNode 列表，与现有 RunLoop 逐行执行模型一致）
// 🔴 铁律 20：actor 引用一律 StringId，cmd 用英文 token（与 01 DSL token 纪律一致）——中文只准在注释
{ "acts": [
  { "sceneId": "sho_meeting_castle_a", "nodes": [
      { "cmd": "actor_enter", "actor": "Hero::lord_1_oda", "slot": "Chair" },                            // 显式入场（触发 StageDirector.ShowActor，等走位完成）
      { "cmd": "dialogue", "speaker": "Hero::lord_1_oda", "textKey": "LWN_SCN_..." },
      { "cmd": "actor_enter", "actor": "Hero::lord_1_maeda", "slot": "Accompany1", "involved": [...] },  // 参与门控挂指令上（玩家不在 → 跳过入场，走渠道）
      { "cmd": "actor_move", "actor": "Hero::lord_1_maeda", "to": { "slot": "Guest" } },                // 中途走位（ChangeActorSlot/SetActorSpecialPosition）
      { "cmd": "dialogue", "speaker": "Hero::lord_1_maeda", "textKey": "..." },
      { "cmd": "actor_leave", "actor": "Hero::lord_1_maeda" }                                            // 显式离场（触发 HideActor）
  ] }
] }
// 🔴 现有代码的运行时 Cmd 是中文（"對話"/"對話選擇"，太阁源直译）——台本化后编译产物输出英文 token，CommandManager 加映射/兼容层（实现细节），与 01 DSL 英文 token 纪律统一
```

**台本 = 编译器排演产物**：编译器分析源剧本 → 确定每幕参与者 → **在脚本流中插入显式调度指令**（演员首次说话前插 `actor_enter`、末句后插 `actor_leave`、中途换位插 `actor_move`）——**编译期推断一次，运行期显式执行**；行号索引的脆弱性（插一行全乱）不存在，指令流自包含、可读（"信长入场→会议→利家入场禀报→走位→离场"），与现有 RunLoop 的 Cmd 执行天然一致。

### 🔴 台本时序语义（舞台剧导演式：并行 cue + 同步屏障，2026-08-24）

导演的台本不是单线程流水线——cue 点可以同时推多个动作（并行）、"等谁到位再继续"（依赖）、"背景不用等"（异步）。映射到现有 RunLoop 单流水线 = **顺序流 + 三态指令**（最小改动）：

| 语义 | 台本写法 | 舞台剧对应 | 现有引擎对应 |
|---|---|---|---|
| **阻塞**（默认） | 无标记 | "等演员走到位再开口" | RunLoop 遇阻塞 return 等待（✅ 已有） |
| **异步** | `"async": true` | "灯光/音效不用等" | 执行后不 return，继续下一行（新） |
| **同步屏障** | `{ "cmd": "sync", "group": "entrance" }` | "等所有入场完成再开会" | 等 async 组全部完成（复用 `_isWaitingForMovement` 机制） |

```jsonc
{ "cmd": "actor_enter", "actor": "Hero::lord_1_oda", "slot": "Chair" },   // 阻塞入场（默认）
{ "cmd": "fx_rain", "async": true },                                      // 异步：雨效与后续并行（不等）
{ "cmd": "actor_enter", "actor": "Hero::lord_1_maeda", "slot": "Accompany1", "async": true, "group": "entrance" },  // 异步入场：走位在后台
{ "cmd": "dialogue", "speaker": "Hero::lord_1_oda", "textKey": "..." },  // 对话照常进行（利家在后台走位）
{ "cmd": "sync", "group": "entrance" },                                   // 同步屏障：等 entrance 组全部到位再继续
{ "cmd": "dialogue", "speaker": "Hero::lord_1_maeda", "textKey": "..." } // 全员到齐后的对白
```

- **并行场景**：多人同时入场（现有 `_movingAgentsForEntering` 已支持多 agent 并行）｜入场与对白并行（async 入场 + 对话继续）｜特效/音效/镜头与对白并行（async）
- **依赖表达**：async 组 + sync 屏障 = "等前面指令完成"；cue 编号（`id`/`waitFor` 依赖图）留给导演标注覆盖层（复杂编排用，基础版不做）
- **纪律**：只有明确不需要等待的才标 async（特效/音效/镜头/多人入场之一）；**对白永远阻塞**（对话流不能跳）——async 误用 = 演员没到就开口（穿帮）
- **执行器**：async 指令执行后不 return（继续下一行），完成回调登记进组；`sync` 阻塞时复用 `_isWaitingForMovement_*` 等待机制

### 🔴 槽位系统升级：语义位 + 情景模板 + 关系式解算（2026-08-24）

**问题**：①不能写死坐标（每场景手工配 CSV 槽位 = 爆炸）②纯 LLM 判相对位置不可靠 ③固定模板（Chair/Guest/Accompany1/2）太机械 ④情景差异大（御前会议等级秩序 / 军团本阵军事位次 / 街头会面平等对位）⑤slot 要不要带方向。

**舞台剧导演的做法**：舞台分区（"左二"= 语义位置非坐标）+ Blocking（"站主公左侧"= 相对关系）+ Facing（朝向说话对象 = 关系函数）。**导演从不写坐标，写"语义 + 关系"，由系统解算**。

**三层设计**：

1. **情景模板**（数据包定义，每情景类型一套语义位集合 + 布局规则——不共用机械槽位）：
```jsonc
{ "type": "court_meeting",                                  // 御前会议：等级秩序
  "anchors": { "chair": "rel_chair", "gate": "abs ..." },   // 🔴 每场景只配 2 锚点（主位/门），量少稳定
  "slots": [ { "id": "主位",  "rule": { "rel": "anchor:chair", "dir": "front", "dist": 0 } },  // 锚点本身
             { "id": "列席1", "rule": { "rel": "anchor:chair", "dir": "left", "dist": 2 } },   // 官职越高越近主位
             { "id": "列席2", "rule": { "rel": "anchor:chair", "dir": "left", "dist": 4 } },
             { "id": "列席3", "rule": { "rel": "anchor:chair", "dir": "right", "dist": 2 } },
             { "id": "门位",  "rule": { "rel": "anchor:gate", "dir": "front", "dist": 1 } },
             { "id": "护卫1", "rule": { "rel": "anchor:gate", "dir": "left", "dist": 1.5 } } ], // 秩序维持者站位
  "facing": "列席面向主位；护卫面向门" }
// 军团本阵（03 共用）：帅位 = 锚点 + 部将1-4 = circle around 帅位（军职/资历均分）+ 传令位（门附近）+ 地图桌（道具位，部将绕桌 circle）
// 街头会面：对位A（玩家原位 = 锚点 player）+ 对位B（front 2.5m 面对面）+ 随从位（back_left/back_right 1.5m）
```
🔴 **锚点体系与方位词（几何基础）**：
- **原点 = 语义中心，不是场景坐标**：谁最"中心"谁当原点——御前会议 = 主位（主公）、本阵 = 帅位（主将）、街头会面 = 对话双方、军议 = 地图桌（道具位）；**玩家本身可以是锚点**（rel_player：玩家是主公时列席相对玩家排）
- **方向 = 8 扇区方位词 + 距离**（相对锚点朝向，不写角度）：`front/back/left/right/front_left/front_right/back_left/back_right` + `dist` 米——解算 = 锚点朝向按扇区旋转 + 距离偏移；`circle` = 绕锚点圆周均分（环列/围坐）
- **语义位全集（8 类功能位，模板按需选用）**：权力位（主位/帅位）｜列席位（列席1-N，官职序）｜对位（对位A/B 面对面）｜从属位（随从/护卫——🔴 秩序维持者站位！）｜功能位（门位/传令位/报告位）｜旁听位（旁观）｜道具位（地图桌/案几，绕物排列）｜特殊位（TagPoint 导演标记）
2. **分配器（确定性函数，不靠 LLM）**：角色 → 语义位——御前会议 = 官职排序（17 功勋链：家老近主位、足轻远；座次 = 等级函数）；本阵 = 军职/资历环列；街头 = 对话双方面对面。🔴 **LLM 只做"情景变体选择"**（密谈近位 vs 正式列席——数据包预定义变体，第一版不做）
3. **解算（语义位 → 世界坐标）**：锚点坐标 = 现有 StageConfig 解析（每场景只配锚点）；语义位 = 锚点 + 相对偏移 + NavMesh 吸附（复用 `GetRandomNavMeshPoint`/`BuildWorldFrameFromLocalPose`）；🔴 **朝向 = 关系式（面向谁，非角度）**：站位指向"面向锚点"（列席→主位）/ 说话对象（对话指令可带 `"face": "speaker"`/`"face": "chair"`，默认面向说话者），解算时算方向角；导演标注可覆盖（面向观众/门）

### 🔴 场景适配（语义位 → 场景实例，自动化解算最后一步，2026-08-24）

**问题**：语义位是抽象的（"主位左侧 2 米"），场景是具体的——目标点可能**在墙里**（NavMesh 不可达/穿模）、**坐席不够**（模板 5 列席、场景 3 椅）。不能脱离场景聊站位，也不能手工逐场景验证。

**自动化 = 分层回退**：

```
第 1 层：场景标记位（TagPoint/ChairTrans——设计者指定）        ← 最准，直接用
第 2 层：模板规则位（方位词 + 距离）→ 自动适配：
   ├─ 距离松弛：目标点在墙里 → 沿方向逐步缩短（2m→1.5m→1m→0.8m）直到 NavMesh 可达
   ├─ 扇区旋转：正左被挡 → 试左前/正前/右前…（8 扇区逐个试）
   └─ 穿模检查：落在家具/桌子里 → 同上重试
第 3 层：降级位：列席 → 站席；旁听 → 角落（软位可降级）
第 4 层：兜底：门位站着（门总是可达）
```

- **硬位 vs 软位**：模板语义位分硬位（必须有：主位/对位）和软位（可降级：列席/旁听可站）；场景数据标注坐席容量（如"本场景列席容量 3"）→ 分配器按官职截断：**高官坐、低官站**（御前会议礼仪本就如此，非 bug）
- **🔴 编译期预适配 + 运行时查表**：场景清单固定 → 模板 × 场景预计算"场景适配表"（每语义位：命中位/回退结果/降级标记），探测开销编译期一次做掉，**运行时零探测只查表**；`rel_player` 动态位跟随玩家运行时算
- 🔴 **03/05 共用"布局探测层"**：NavMesh 探测 + 距离松弛 + 扇区旋转 + 穿模检查是通用工具（03 营地布局同源问题），不各写一套
- 调试：`custom.scene_probe <sceneId> <templateId>` dump 每个语义位的适配结果（命中/回退/降级）——12 A4 验收用

**台本对应**：`actor_enter` 的 `slot` = 语义位 id（"主位"/"列席1"/"对位A"），解算是机制——台本仍显式（导演排演定"利家→列席1"），坐标与朝向由系统解。**槽位不写死、不 LLM 猜、不机械、情景自适应、朝向关系式**。

**保留 vs 替换**：StageDirector 槽位系统 + 坐标预计算缓存 ✅ 保留升级（槽位分配从运行时 `AssignSlots` 改为台本给定）；StoryEngine 栈式执行/阻塞恢复/移动等待骨架 ✅ 保留（播放器 = 按台本执行）；被替换的只有"现算"逻辑（扫描/分配/进出场判断）→ 编译期静态化（StoryCompiler 把 `GetCurrentSceneParticipants`/`AssignSlots`/进出场判断逻辑搬到编译期跑一遍，产物即台本）。**运行时零扫描、零现算**——`RefreshSceneScope` 只查台本幕表，不再向前扫脚本。

## 做完怎么验收

> 🔴 分拆验证（12 总纲 A4）：`custom.playback_dump <compiledId>`（编译产物完整性，播放零扫描）→ `custom.playback_play <compiledId>`（多 agent 轮转/旁听/旧链已断）；拼装验收 = 12 Phase 1。分拆全绿前不拼装。

1. 样例剧本 → 编译产物（分幕/站位/镜头齐全）→ 播放全流程无现场计算
2. 多人演出：两人轮转说话（名字/头像/镜头切换）、旁听者站位、选项分支
3. 旧崩溃链已断（无对话场景不会再崩）；确认弹窗路径不受影响
4. 没配 AI 全流程可玩（编译产物的兜底文本直出）
5. 🔴 参与门控（12 分拆矩阵 A4 扩展）：同一演出——玩家在场 = 完整播放 + 机位随玩家侧；缺席 = 跳过演出 + 渠道通知锚点；单演出双机位样例（桶狭间布阵/休息，09 名场面 #3）验证通过

## 要注意的坑

- 面板升级是"废弃系统重制"——两条安全红线必须验（上面第 4 部件）
- 编译产物格式冻结顺序：先格式后编译器，不然返工
- 镜头跟随说话人在多人场景的性能/稳定性要实测
- UI 重构工作量大：先做基础版（名字/头像/文本/选项），高级效果（旁听者动画等）迭代加
