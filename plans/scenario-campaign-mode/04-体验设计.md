# 04 — 体验设计：主命系统 + 叙事层级 + 强度谱系

> **Phase 1 | 依赖：01（Quest 载体复用 ScenarioQuest）| 出口：主命派发走通 + 强度谱系执行**
> 对应蓝图：§3.8（3.8.1/3.8.2/3.8.4/3.8.5）。代码位置：`Scenario/Orders/`。

## 目标

玩家 3A 体验：**间隙期**（不事件时玩什么）有目标感（主命）+ 世界推进感（背景，见 02）；**事件触发**分级触达（通知→IM→Quest 引导）；**演出期**亲历且禁止纯点点点（强度谱系 L1-L7，Quest 化推进为核心）。

## 分步实施

### Step 1 — 主命系统（Scenario/Orders/ScenarioOrderDirector.cs）
- 数据：剧本 `orders` 表（主命池：攻城/防守/讨伐/护送/领地治理/外交，按阶段 + 势力关系解锁，来源 = 当前主公 actor）
- 派发：剧本节拍（周/月）由 ScenarioDirector 调起，向玩家派发 1-2 条主命（太阁式）
- 形态：主命 = ScenarioQuest 阶段任务（JournalLog 目标 + TrackedObjects 地图标记 + 报酬 + 期限）；拒绝有代价（关系/剧本推进滞后——设计哲学：给压力不剥夺选择）
- 主命是"可选推进器"：接 → 加速剧本走向（攻城成功 → 触发条件提前）；不接 → 等时间窗/条件自然成熟（自由感）
- 验收：演示剧本定义主命池 → 节拍派发 → 接/拒两条路径走通（任务面板可见）

### Step 2 — Quest 结合（ScenarioQuest : QuestBase）
- 每个剧本阶段 = 一个 `StoryModeQuestBase` 子类实例（仿 CommissionQuest 自动创建、不可失败）
- JournalLog 剧情日志（当前阶段目标 + 历史脉络）——玩家任务面板随时看"我在剧本哪里、下一步做什么"
- TrackedObjects 地图标记（今川大军位置/京都/目标 NPC）
- 阶段推进 = `CompleteQuestWithSuccess` 完成当前 + 创建下一阶段（onPlayerChoice 分支不同子类）；剧本完结五通道收束
- 主命（Step 1）复用同一 Quest 载体
- 验收：任务面板阶段日志 + 地图标记 + 阶段切换

### Step 3 — 强度谱系执行（ScenarioIntensity.cs）
- 数据：事件/节点标 `intensity`（L1-L7）；转化管线自动分配（08），人工可调
- 执行分派器：L1 通知横幅（InformationManager/SceneNotification 轻量）→ L2 IM 私聊（ImChatManager）→ L3 Quest 化推进（Step 2 + TrackedObjects 指路）→ L4 原版对话流 + Persuasion 检定 → L5 演出面板（依赖 05 StoryDialogVM 升级版）→ L6 程序化战斗（依赖 03）→ L7 操作型节点（检定/限时）
- 🔴 **Quest 化推进纪律**：关键剧情节点优先走 L3（玩家亲自前往目标 NPC 触发），禁止全部 AVG 切场景
- 验收：演示剧本节点按 intensity 走对应通道（L3 可亲自位移触发）

### Step 4 — 叙事层级（campaign 层载体）
- 🔴 **大地图交互**（三国志式"军团头上人物说话"的骑砍2 实现）：地图上军团 party 可靠近互动（MapEncounterDialogState 既有 + 靠近触发 IM/对话流）；发言走 IM/冒泡
- 通知横幅（大事发生）；IM 私聊（人物立场/密谋铺垫）；Quest 引导（下一步去哪）
- campaign 层给"信息与目标"，mission 层给"亲历与情感"
- 验收：靠近被锁定军团 → 触发对话/IM；通知横幅在大事件触发

## 出口验证（Phase 1）

1. 主命：节拍派发 → 任务面板可见 → 接（推进剧本）/拒（代价）双路径
2. 强度谱系：L1/L2/L3/L4 通道走通（L5 依赖 05 完成后接）
3. Quest 化推进：玩家亲自前往目标 NPC → 触发下一节点
4. 大地图交互：靠近军团 → 对话/IM 触发

## 风险

- 主命与既有委托/任务系统并发（MCM 开关降频，见 11）
- 主命期限与剧本时间窗冲突（主命失败不应破坏剧本主链——失败只影响奖励/关系）
- 强度谱系 L5 依赖 05 的 StoryDialogVM 升级（串行依赖，先出 L1-L4）
