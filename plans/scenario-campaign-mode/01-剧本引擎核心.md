# 01 — 剧本引擎骨架

> 阶段：Phase 0 ｜ 依赖：无 ｜ 完成后：控制台能驱动一个卡拉迪亚演示剧本全流程，进度能存读档

## 这一步做什么（一句话）

造最基础的地基：**一份剧本数据（有哪些事件、什么条件触发、触发了做什么）→ 每天检查 → 条件满足就触发 → 记下"已发生过"**。先用卡拉迪亚两个王国的演示剧本验证整条管线，不碰任何日本战国内容。

## 玩家视角

现阶段玩家看不见东西（这是地基）。验证靠控制台调试指令：手动开始剧本、手动改条件、看事件按预期触发、存档读档不丢进度。

## 怎么实现（六个部件，对应下面的步骤）

1. **剧本长什么样**（数据格式）——一份剧本 = JSON：角色表 + 时代 + 事件列表 + 结局列表。每个事件 = "触发条件"（比如"尾张城在织田家手里"）+ "效果"（比如"宣战/发通知"）
2. **读入剧本**——启动时从数据文件夹读全部剧本；坏文件不崩，跳过并记日志
3. **记住进度**（存档）——当前在哪个事件、哪些已触发、哪些分支旗标 → 存进存档
4. **每天检查**（调度）——每天扫一遍未触发事件，条件满足就触发；玩家正在战斗/演出时，演出类效果先挂起，世界状态类效果立即执行
5. **条件怎么判断**——一整套"小问题"：这座城归谁？这人活着吗？这人在哪个势力？两家在打仗吗？过了多少天？某旗标设了吗？每个问题答不上来就安全返回"否"并记日志（不能崩）
6. **效果怎么执行**——一整套"动作"：设旗标 / 宣战 / 停战 / 换城主 / 杀角色…。本期先实现不依赖其他系统的（旗标/宣战/停战/换城主），其余留桩（打日志假装成功，不崩），后续阶段逐个接上

## 分步骤清单

| 步骤 | 做什么 | 完成标志 |
|---|---|---|
| 1 | **定数据格式**（剧本 JSON 长什么样）——先冻结再写代码，样板参考现有演出脚本的读取方式 | 样例剧本能解析成数据对象 |
| 2 | **读入剧本**——启动时加载，坏文件不崩 | 控制台能列出已加载剧本 |
| 3 | **进度存档**——进度存进存档 + 新档时清空（防串档，这是必守红线） | 存读档后进度不丢；新档无残留 |
| 4 | **每日调度**——每天扫条件、按优先级触发；演出挂起队列 | 改条件后事件按预期触发；战斗期间触发不崩 |
| 5 | **条件原语全家桶**——上面第 5 点那套"小问题" | 演示剧本用到的条件全部可测 |
| 6 | **效果执行器**——上面第 6 点那套"动作"（依赖别的系统的先留桩） | 旗标/宣战/停战/换城主实际生效；桩动作只打日志不崩 |
| 7 | **角色解析**——剧本里写的角色名怎么找到游戏里的真人：先查预设 ID 列表，查不到再按名字特征遍历兜底（红线 2）；找不到的按剧本要求决定是禁用剧本还是以后补造 | 命中日志正常；缺失角色不崩 |
| 8 | **控制台调试指令**——列出剧本/开始剧本/强制触发某事件/设旗标/中止/看内部状态 | 演示全流程可控制台驱动 |
| 9 | **演示剧本 demo_border_war**——卡拉迪亚两个王国的边境战争：开档宣战 → 条件触发 → 事件链 → 结局 | 新档跑通全流程 |

## 做完怎么验收

1. 新档 → 控制台开始演示剧本 → 手动改条件（设旗标/宣战）→ 事件触发 → 效果生效（能观察到宣战/停战/换城）→ 日志齐全
2. 存档 → 读档 → 进度保持（事件指针/旗标/已触发集合）
3. 坏剧本文件 / 找不到角色 / 战斗中触发 → 都不崩（红线 4）
4. 代码里搜"织丰/日本战国/太阁/主公" → 零命中（红线 1）

## 要注意的坑

- **格式必须先冻结再写读取代码**——不然改一次格式改一堆代码
- **每天全量扫条件有性能成本**——条件结果缓存 + 每个事件设检查上限；剧本多了再优化
- **留桩的动作日志要醒目**（"此动作未实现"），不然调试时以为真生效了
