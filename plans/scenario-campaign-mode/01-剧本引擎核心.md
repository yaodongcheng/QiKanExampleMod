# 01 — 剧本引擎骨架

> 阶段：Phase 0 ｜ 依赖：无 ｜ 完成后：控制台能驱动一个卡拉迪亚演示剧本全流程，进度能存读档

## 这一步做什么（一句话）

造最基础的地基：**一份剧本数据（有哪些事件、什么条件触发、触发了做什么）→ 按各事件声明的触发时机检查 → 条件满足就触发 → 记下"已发生过"**。先用卡拉迪亚两个王国的演示剧本验证整条管线，不碰任何日本战国内容。

## 玩家视角

现阶段玩家看不见东西（这是地基）。验证靠控制台调试指令：手动开始剧本、手动改条件、看事件按预期触发、存档读档不丢进度。

## 怎么实现（六个部件，对应下面的步骤）

1. **剧本长什么样**（数据格式）——一份剧本 = JSON：角色表 + 时代 + 事件列表 + 结局列表。每个事件 = "触发条件"（比如"尾张城在织田家手里"）+ "效果"（比如"宣战/发通知"）
2. **读入剧本**——启动时从数据文件夹读全部剧本；坏文件不崩，跳过并记日志
3. **记住进度**（存档）——当前在哪个事件、哪些已触发、哪些分支旗标 → 存进存档
4. **按声明触发**（调度）——每个事件 JSON 自己声明触发时机（`trigger` 字段，取值 ∈ 16 trigger 注册表），调度器按声明时机检查、条件满足就触发；玩家正在战斗/演出时，演出类效果先挂起，世界状态类效果立即执行
5. **条件怎么判断**（每个事件 JSON 自带的 `condition` 表达式）——触发时机到了，就求值该事件自己的 DSL 条件表达式（如 `and( (Settlement::town_CHUB11.owner) == (Clan::clan_oda_1), exists(Hero::lord_1_imagawa) )`，语法见下方正式格式）；表达式能问的"小问题"来自属性/谓词注册表（16）：这座城归谁？这人活着吗？这人在哪个势力？两家在打仗吗？过了多少天？**现在是哪一年**（绝对年份 = 开局基准年 + 流逝年，供 14 历史时间轴用）？某旗标设了吗？表达式里某个问题答不上来就按"否"处理并记日志（不能崩）
6. **效果怎么执行**——一整套"动作"：设旗标 / 宣战 / 停战 / 换城主 / 杀角色…。本期先实现不依赖其他系统的（旗标/宣战/停战/换城主），其余留桩（打日志假装成功，不崩），后续阶段逐个接上

### 🔴 正式格式（DSL）——mod 解析用，2026-08-24 约定（v2 文本表达式）

> 剧本数据（14/09/10/15 的 timeline 和事件）里的条件和效果**必须用正式格式**，mod 才能解析。自然语言只准出现在注释和文档里，不准出现在 mod 读的数据里。**本小节是 DSL 的权威定义，Step 1 冻结 Schema 时同步定稿。**
> 🔴 **完整注册表（域/属性/谓词/动作全表 + 代入槽 + 太阁映射）= [16-DSL注册表全表.md](16-DSL注册表全表.md)**——本小节管"语法规则/类型纪律/安全兜底"，16 管"有什么可写"；表外用法 = 回填 16 + 扩展本小节注册表。
> 🔴 **结构决策 v2（2026-08-24）**：**条件 = 文本表达式语法**（符合语言习惯，人和 LLM 都好读好写；太阁5 的 2594 个事件是现成语法范本，转化 1:1；项目 StoryEngine 的"對話/分歧"中文指令已有先例）。**效果 = JSON 命令**。**语法 token 用英文（题材无关、避免全角符号解析坑）。🔴 引用必须用游戏内稳定 ID（StringId）——不能用显示名/中文名**（显示名是本地化产物：不同语言不同名、且名字可被改名（聚落改岐阜/角色改名），拿名字做标识运行时匹配不稳；中文只准出现在注释或可选别名 refs，加载期解析成 ID，运行时无中文参与）。

**条件表达式（文本）**：

```
表达式 = 逻辑组合 or 比较 or 谓词 or 🔴 裸引用（真值判断）
  比较：  (引用) 操作符 (引用|字面量)      例：(Settlement::town_CHUB11.owner) == (Clan::clan_oda_1)
  谓词：  函数形式，直接布尔结果         例：exists(Hero::lord_1_imagawa) / atWar(Faction::Kingdom.oda, Faction::Kingdom.imagawa)
  🔴 裸引用： (布尔属性引用) 直接作叶子 = 真值判断   例：(Hero::X.alive) —— 太阁 `調查:(人物::X.死亡標誌)` 形态
  逻辑：  and(表达式, 表达式, ...) / or(...) / not(表达式)
  操作符：==  !=  >  >=  <  <=
  字面量：数字 / 字符串 / true / false

引用 = 域::ID[.属性]     // 只用于"单值属性"（归属/首领/存活/年份…），参与比较
  🔴 符号分工（2026-08-26 明确，防实现混淆）：`::` = 域↔对象分隔符（域 = 类型标识 → 查询器/值类型）；`.` = 对象↔属性访问符（属性 ∈ 每域白名单 → 静态类型判定）；全局属性无对象，直接 `域::属性`（`(Time::year)`）。与太阁5 `人物::X.所屬大名家` 同构，翻译时位置原样保留
实现者注：以下为加载期实现裁定，审核人无需验证细节。

  🔴 `.` 拆解规则（实现裁定，剧本作者无需理解）：**域:: 后的 `.` 是否拆属性由该域属性白名单静态决定**——①域无属性白名单（Faction）→ `::` 后整体为 StringId（含点，如 `Kingdom.oda`）；②域有白名单 → 按 `.` 拆，后半段必须 ∈ 白名单（`Settlement::X.owner`），后半段不在白名单且整串命中已知 ID 清单 → 整体作 ID（加载期两轮策略校验）；歧义无法静态判定 → 加载报错禁用剧本
  域（引擎注册，英文 token，题材无关）：Time / Settlement / Hero / Clan / Faction / 🔴 Event / Flag
  ID（游戏内 StringId，两轮策略查找：预设 ID → predicate 兜底，铁律 5）：
     如 town_CHUB11 / lord_1_oda / clan_oda_1 / Kingdom.oda
  属性（每域白名单，英文，见下表）——🔴 必须是单值；"关系"不进属性（见谓词表）

🔴 值类型（由 域.属性 静态决定——不是运行时才知道）：
  数字    ：Time::year / Time::day
  势力引用：Settlement::X.owner / Clan::X.kingdom
  家族引用：Settlement::X.clan / Hero::X.clan
  角色引用：Clan::X.leader
  布尔    ：Flag::X / Hero::X.alive
🔴 比较纪律（左右必须同类型）：
  == / != ：同型才能比（引用对同型引用 / 引用对同型字面量，如布尔对 true、数字对 1560）
  > >= < <=：仅数字
  类型不匹配 → validator 报错 + 加载报错禁用剧本（静态可判定，当场拦住，不是运行时才发现）
```

🔴 **谓词表（关系判断，带参函数，直接布尔——与属性区分：属性是单值、谓词是关系）**：

| 谓词 | 参数 | 语义 | 示例 |
|---|---|---|---|
| exists | 引用 | 对象存在 | `exists(Hero::lord_1_imagawa)` |
| atWar | a, b（势力引用） | a 与 b 交战 | `atWar(Faction::Kingdom.oda, Faction::Kingdom.imagawa)` |
| （后续按需扩展：isNeighbor / isAllied / hasRelation …）| | 新谓词 = 注册表加行 + 实现 | |

| 域 | 属性白名单（单值） | 示例 |
|---|---|---|
| Time | year / day | `(Time::year) >= 1562`（year = 开局基准年 + 流逝年） |
| Settlement | owner（归属势力）/ clan（归属家族）/ position | `(Settlement::town_CHUB11.owner) == (Clan::clan_oda_1)` |
| Hero | alive / clan（所属家族）/ party（所在部队）/ position | `(Hero::lord_1_imagawa.clan) == (Clan::clan_imagawa_1)` |
| Clan | kingdom（所属势力）/ leader | `(Clan::clan_oda_1.leader) == (Hero::lord_1_oda)` |
| Faction | （无单值属性——关系走谓词）| |
| 🔴 Event | done（bool，🔴 调度器自动记录——事件已触发并完成，作者不写） | `(Event::okehazama_opening.done) == true`（顺序依赖写法） |
| Flag | 值（bool）——🔴 只留跨事件持久自定义标记（战斗结算结果等） | `(Flag::okehazama_imagawa_killed) == true` |

**可选别名 refs（剧本文件顶部，人性化糖，加载期解析成 ID）**：
- 中文别名 → StringId 的目录表：`"refs": { "清洲": "town_CHUB11", "今川义元": "lord_1_imagawa", "织田家": "clan_oda_1" }`
- 表达式里可用别名（`(Settlement::清洲.owner)`），**加载时一次性解析成 StringId，运行时全部是 ID**——本地化无关
- 别名没定义的引用 = 直接按 StringId 解析（默认纪律：写 ID；别名是可选糖）

```jsonc
// 事件触发条件示例（condition 字段）——太阁5 原文 `調查:(據點::發生據點)!=(據點::那覇之町)` 转化而来（ID 版，注释说明可读性）：
"condition": "and( (Time::year) >= 1560,                              // 年份到了
              (Settlement::town_CHUB11.owner) == (Clan::clan_oda_1), // 清洲归织田家
              exists(Hero::lord_1_imagawa),                          // 今川义元存在
              (Hero::lord_1_imagawa.clan) == (Clan::clan_imagawa_1), // 义元在今川家
              atWar(Faction::Kingdom.oda, Faction::Kingdom.imagawa), // 织田今川交战
              not( (Flag::okehazama_started) == true ) )"            // not 组合子语法示例；🔴 防重复不写 not(Flag)——调度器自动记 Event::done（三层纪律）
// 🔴 安全兜底（铁律 1）：引用求值失败（对象缺失/StringId 查不到）→ null → 参与任何比较返回 false
// 未知域/未知属性/未知谓词/语法不合法 → 加载时报错并禁用该剧本（不是静默 false）
// 🔴 类型纪律：比较两边必须是同类型（属性对属性/属性对字面量）；关系判断一律走谓词函数，禁止把关系写成属性
```

**🔴 事件结构 = condition + script（线性演出脚本）。决定：事件级条件字段叫 `condition`（对应太阁5「發生條件」）；步骤级门控叫 `when`（事件一层是门、步骤一层是门）**：

- 每个事件 = `condition`（条件）+ `script`（**线性序列：演出步骤与世界效果交错**——太阁5 正是如此，對話和效果命令混排；玩家"看到"事件发生过程，效果在演出适当时刻执行）
- 🔴 **骨架与内容分离（2026-08-24 用户裁定）**：事件 JSON 只放**骨架**（短：条件 + 效果 + 选择 + 过场/演绎引用）；**长对话等演出内容一律进独立演绎剧本**（StoryJson，05 StoryCompiler 编译），事件用一行 `perform` 步骤引用（`playbackId`）——**对话可能很长，但 condition 和 effect 不会很长**
- **演出强度按事件重要度选**（04 强度谱系呼应）：轻事件 = inquiry 弹窗说明 + 几个 effect；中 = cutscene 过场；重 = perform 引用多 agent 演绎剧本 + 效果交错

**script 步骤类型表（05 注册，本表为索引）**：

| 步骤 | 语义 | 强度 | 内容位置 | 🔴 执行语义（2026-08-25 补） |
|---|---|---|---|---|
| 🔴 perform | 引用演绎剧本（`playbackId` = 05 编译产物 ID）——多 agent 长对白/镜头/旁白都在剧本里 | 重 | 演绎剧本（StoryJson） | 🔴 阻塞：演出演完才执行下一步 |
| inquiry | 弹窗说明（标题/正文/按钮——轻量事件主载体） | 轻 | 骨架（文本 key） | 阻塞 |
| cutscene | 过场（SceneNotification） | 中 | 骨架（sceneId+textKey） | 阻塞 |
| im_message | 单条私信/消息（campaign 层，参数 channel/actor/textKey；09b 在用名，2026-08-26 统一登记 = 本步骤类型表 + CSV 命令行动作行） | 轻 | 骨架（textKey） | 🔴 默认异步（后台发送不阻塞；需确认送达才显式标同步） |
| effect | 世界效果（action ∈ 16a-DSL翻译总表.csv 命令区动作行）；🔴 可选 `when` 条件（门控——IF 分支的效果侧） | — | 骨架 | 同步（立即执行，落世界） |
| wait / bgm / se | 节奏/音乐音效 | — | 骨架（或演绎剧本） | wait 阻塞 / bgm·se 异步 |
| scene_enter | 场景切换 | 重 | 骨架 | 阻塞 |
| 🔴 choice | **玩家选择（2026-08-24 修正：choice 是演绎的一部分——玩家在演出中感受到的节点）**：在**演绎剧本内**（对白流中某处弹出选择），选项带 `effect`（🔴 2026-08-25：分支选择默认 `ctx_set` 写 Ctx 命名槽——事件内局部；跨事件持久才用 `set_flag`）与 `goto`（分支台词线）；IF 分支 = 选项 effect 设值 + 事件骨架效果步骤 `when` 门控 | 重 | 🔴 演绎剧本内 | 阻塞（随演出流） |

> 🔴 **script 默认执行语义 = 同步顺序**：上一步完成才执行下一步（perform 演完 → 才轮到下一个 effect）。需要并行的步骤显式标 `"async": true`（im 后台发送、bgm/se 音效、多人入场之一）。台本层（05 编译产物）另有 async/sync 组三态——骨架层只分同步/异步两态，不引入组。

### 🔴 事件触发时机 / 重复性 / 优先级（2026-08-26 增补——TK5 四段完整落位，数据驱动）

> 太阁5 事件头字段 = `屬性` / `發生契機` / `發生條件` / `執行` 四样（实测 2594 事件头字段只有这四样）。转化后**四段全部落 JSON 字段**——🔴 触发时机禁止只写注释：谁在什么时候检查脚本必须由数据决定（09b 教训 2026-08-26）。

| TK5 头字段 | JSON 字段 | 必填 | 说明 |
|---|---|---|---|
| 發生契機 | `trigger` | ✅ 必填 | 值 ∈ trigger 注册表（trigger = 触发时机：进据点/开会/每天…；值见 16 §二）；引擎按注册表挂监听，**trigger 触发时只遍历挂名事件** |
| 屬性:一次/多次 | `once` | 默认 true | true = 触发完成移出扫描集；false = 可重复（每次契機 + 条件满足都再触发） |
| 屬性:…｜弱 | `priority` | 默认 normal | 互斥选路优先级：`weak` < `normal`；**多个 normal 同时满足 = 按文件声明顺序，第一个触发，其余本轮跳过**（见下调度模型） |
| 發生條件 | `condition` | ✅ | 条件表达式（已有） |
| 執行 | `script` | ✅ | 步骤序列（已有） |

**trigger 值表（token 注册权威）= 16 §二**——2026-08-26 单所有权，本文件不再维护（词表统计口径以 16 为准：主人公據點子集 632/211；全量复跑 = 16「复跑」节命令）：

🔴 **触发时运行环境 = 演出能力边界（2026-08-26 引擎语义验证）**：trigger 触发时玩家所处运行环境决定可用的演出形态——

| trigger 族 | 触发时环境 | 可用的演出形态 |

**调度模型**：
- 引擎按 trigger 注册表挂监听；trigger 触发时只遍历挂在自己名下的事件（不是全量扫描——daily 每日检查只是其中一个 trigger）
- 🔴 **互斥选路**（太阁5 同款，实测同契機组规模：據點畫面表示後(主人公據點) 632 个事件、室內畫面表示後(主人公據點,自宅) 211 个、評定開始時 134 个）：同 trigger 的挂名事件按 `priority`（weak < normal）分层，**层内按文件声明顺序**（见下），从第一层开始逐事件检查 condition——**第一个 condition 满足的触发，其余本轮全部跳过**——一次时机只演一个事件。**多个 normal 同时满足 = 文件声明顺序在前者触发**；normal 全部不满足时才检查 weak 层（weak 层内同样按文件声明顺序）
- 🔴 **文件声明顺序 = 调度器的确定性排序依据**：同 trigger 挂名列表按事件 JSON 在剧本文件中的**声明先后**注册（加载序），**禁止依赖字典序/事件 id 排序/运行时顺序**；作者调整同契機事件的先后关系 = 调整文件中的声明位置（同 priority 时声明在前 = 优先触发）。🔴 **弱语义**：本轮只要有任意非弱事件触发（无论演出是否被玩家打断/中止），弱事件一律跳过；只有非弱事件全部不满足时才轮到弱事件——`屬性:一次｜弱`（如 ECF00000_159 旅人通报）就是"锦上添花"事件，被常规事件挤掉是正常现象，不能因此认为漏演
- once 语义：触发完成 → 移出扫描集；多次事件留在扫描集（`Event::X.done` = "至少触发过一次"，对多次事件语义不变）
- 🔴 **事件合并纪律**：一个事件 = 一个 trigger。跨契機的多个 TK5 事件折叠进一个 mod 事件时（如 09b 事件 1 合并 EFF0C300_160/161/162 三契機），trigger = 首个契機，其余契機 → 步骤内 when 闸（特例，需人工确认——宁可拆事件）

**纪律**：
- 14/09/10/15 的 timeline/事件定义里，pre/post 等**人读概要**旁边必须指向正式条件（事件定义里的 `condition`/`effects` 用 DSL 写）
- 太阁5 条件（`調查:(據點::發生據點)!=(據點::那覇之町)`）**由 08 转化管线翻译成本格式**：去掉"調查:"前缀 + 域映射（據點→Settlement、人物→Hero、狀況::年→Time::year）+ **名称归一（那覇之町 → StringId，角色匹配表/城池归一表直接产出）** + 操作符照搬——引擎不解析太阁5 格式
- 新增域/属性/操作符/动作 = 注册表加一行 + 实现；未注册的引用/操作符/动作 → 加载报错并禁用该剧本
- 语法 token（Time/Settlement/set_flag 等）为**英文，题材无关**；🔴 **引用一律 StringId（本地化无关）**；🔴 **对象引用统一带域前缀**（`Hero::lord_1_oda` / `Clan::clan_oda_1` / `Settlement::town_CHUB11` / 🔴 `Agent::guard_oda`（场景内模板 NPC，CharacterObject.StringId，铁律 8 平权）——DSL 条件、台本 actor/speaker、数据包引用、refs 别名解析结果一律；**域前缀 = 类型标识，是 validator 池查找的依据，字段语义（如 actor 已定是角色）不替代它**；**Hero:: = 剧情角色（Campaign 层，运行时按 HeroId 映射 Mission 内 Agent）vs Agent:: = 场景内角色（无 HeroObject，按 TemplateId 找场景实例，缺失可 spawn）**，2026-08-25 裁定）；中文只出现在注释 / refs 别名（加载期解析）/ 数据包；织丰/日本战国等题材字串只准出现在数据包（worldview 铁律）
- 🔴 **事件只发生一次、结算唯一、演绎按参与裁剪**（3D 多视角三通道，2026-08-24，详 04/05）：同一历史节点的 effect（结算）全局只执行一次；perform 引用的演绎剧本带参与门控——玩家在参与者列表 → 现场演出，不在 → 跳过演出（世界内照常发生），信息走渠道（IM/世界信号）；**禁止为每个视角各写一份结算或完整演出**（AVG 重放范式：结算重复 = 改两次世界，演出重复 = 成本爆炸且出戏）
- 🔴 **状态表达三层纪律（2026-08-25）**：①事件执行过/事件间顺序依赖 → `Event::<id>.done`（🔴 调度器自动记录 + 全局存档，作者不写；condition 里**不需要** `not(Flag::xx)` 防重复——调度器只扫未触发事件）②分支选择 → `Ctx::` 命名槽（choice 的 `ctx_set` 写入、同事件步骤 `when` 门控读，事件内局部）③世界状态 → 游戏本体属性/谓词优先（`Hero.alive` / `Settlement.owner` / `atWar`）；`Flag::` 只留跨事件持久自定义标记（战斗结算结果等）。注册表见 16。**分支选择跨事件要读 = 升级 Flag/Variable，禁止跨事件读 Ctx**
- 🔴 **玩家打断演出 = 事件分支**（05 封控分级，2026-08-24；🔴 **2026-08-25 已裁定不实施——剧本演出 = 过场式全控，本节降级为参考设计备查**）：A 档关键演出玩家拔剑/攻击 = 显式打断入口 → perform 走 `onInterrupt`（中止演出 + 分支 flag，与 choice 分支同构，效果 when 门控接分支）；演出封控期间玩家介入必须有 NPC 回应（禁止无反应）

## 要注意的坑

- **格式必须先冻结再写读取代码**——不然改一次格式改一堆代码
- **每天全量扫条件有性能成本**——条件结果缓存 + 每个事件设检查上限；剧本多了再优化
- **留桩的动作日志要醒目**（"此动作未实现"），不然调试时以为真生效了
