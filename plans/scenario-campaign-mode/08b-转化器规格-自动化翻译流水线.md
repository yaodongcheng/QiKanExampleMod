## 十二、🔴 踩坑实录与机械翻译纪律（2026-08-27 桶狭间试点全量）

> 每条 = 一次实机踩坑（用户抓包或自审发现）→ 已固化为脚本纪律。**新事件/新题材翻译前先过这十二条**。

1. **条件必须逐条对上 TK5 原文（用户裁定）**——「注释说 25 条、JSON 只写 5 条」是 LLM 手抄的必然结果；机械翻译 = 逐条查 16a CSV，表外标 `🔴待注册` 不猜译（§2.4）。**表外 = 回填 16 后重跑，禁止「注释摘要 + JSON 简化」两条腿**
2. **指令名必须落 JSON 第一字段（用户裁定）**——演绎剧本 lines 每行 `cmd` ∈ 05 指令流权威（`dialogue`/`narrator`/`choice`）；骨架 script 每步 `step` ∈ 01 步骤表。**禁止靠字段推断类型**（曾用 speaker 存在与否推断对话，被用户抓包）。`對話`→`dialogue`+speaker+listener；`自語`→`narrator`+speaker（内心独白归属）；`旁白`→`narrator`（上帝视角）；`選擇`→`choice`
3. **對話 双参数全语义化（用户裁定）**——`對話:(說話人,對象)` 的 param1=speaker、param2=listener **都要结构化落字段**（`"listener"`），禁止只收 speaker 让对象靠注释反推（stage_inject 的沉默观众位直接从 listener 字段推导）
4. **代入 = 局部变量赋值，不是静态展开（用户裁定）**——`代入人物Ｄ:(旅人)` → 骨架 `ctx_set` 动作（slot=`hero_D`，value=翻译引用）；后续引用 → `Ctx::hero_D`（16 §一 Ctx 三档）。**唯一例外：條件块内代入 = 静态展开**（条件求值无执行流可跑 ctx_set——EFF0C300_159 的 據點Ｂ=織田本城 案例）。槽名全 ASCII（人物Ｄ→hero_D、城Ａ→settlement_A、據點Ａ→place_A、ａ→var_a、忍者衆Ａ→ninja_A）
5. **中文/emoji 禁止进 ID（用户裁定）**——占位 ID 必须英文 ASCII 合法 StringId 形态（`Hero::tk5_dosan`/`Agent::tk5_traveler`/`Settlement::tk5_narumi`），配 report「占位 ID 映射表」（占位 → 中文名/语义 → 07 审核全局替换）。漏网 fallback = 确定性 hash ID（`tk5_uXXXXXX`）+ 登记中文名。**`🔴待07` 只允许出现在注释/清单，不允许出现在引用位置**
6. **i18n key 必须全局唯一（铁律 13 落脚本）**——t_counter 是事件级计数，key 必须带事件号前缀（`LWN_SCN_okehazama_EFF0C300_159_7`）；裸序号跨事件必撞（实机：`_7` 撞 22 次）
7. **文本变量占位符语义化（用户裁定）**——TK5 变量 → TextObject 占位符 key 从角色 ID 派生（`(今川義元)`→`{IMAGAWA.NAME}`），风格同引擎内置 `{PLAYER.NAME}`；**TextObject key 只收大写字母/数字/下划线/点**（`::` 和小写不合法——不能写 `{Hero::lord_1_imagawa.name}`）。注入表（report「文本变量注入表」）仍记录 类型+源角色
8. **称呼属性体系（用户裁定，全语料扫描 2026-08-27）**：圆括号仅两种——`(X.姓)`→`{X.FIRSTNAME}`（**姓 = FirstName**，骑砍2 FirstName 显示在前，日本名姓在前）、`(X.名)`→`{X.LASTNAME}`（显示在后）；花括号三种——`{X.名前}`→`{X.NAME}`（全名）、`{X.姓名}`→`{X.FULLNAME}`（姓+名组合，运行时拼接注入）、`{X.代名詞}`→槽人称；人称 `{一人稱}`→`{SELF_PRONOUN}`/`{二人稱}`→`{OTHER_PRONOUN}`/`{二人稱名前}`→`{OTHER_PRONOUN_NAME}`；`{未知NN}`→`{UNKNOWN_NN}`（唯一需人工语义裁决类，~1500 次全语料）；槽显示 `<城Ａ>`→`{SLOT_A.NAME}`、`<ａ>`→`{SLOT_A.VALUE}`、`<年>`→`{TIME.YEAR}`、`<月>`→`{TIME.MONTH}`。**禁止自造属性词**（曾把 姓 写成 CLAN 被用户纠正）
9. **源重复拷贝自动去重**——TK5 源大量整块重复拷贝（EFF0C300_159 条件块 4 组 OＲ = 2 组重复、性别变体文本逐字相同）；条件翻译顶层去重（顺序敏感保留首个）。**执行块内的重复拷贝照翻**（可能是机位变体，非纯重复）
10. **循环/容器必须完整语义保留，禁止降级（2026-08-27 用户裁定修订）**——`循環:{...}` → `loop` 步骤（body 递归，运行时对容器逐元素执行）；`脫出模塊` → `break`；容器命令（設定/篩選/排除/排序/選擇/清理）→ `container_*` 步骤（参数按序语义化：domain/attr/value/slot/mode）。**实机教训**：曾把循环"线性展开一次"、容器标 `🔴待注册`——用户裁定「翻译必须原原本本保留意思，指令不足 = 检查 16a CSV 回填 + 实现，不准自作主张删减」。166 案例：`循環:{容器選擇→脫出模塊→人物登用→容器清理}` → `loop{container_pick → break → spawn_hero → container_clear}`（完整语义，0 效果 → 全语义）。**顺带发现 CSV 参数列漏项**：`人物登用` 源实参 3 个 `(人物Ｅ,直臣,德川家康)`（actor/status/clan），CSV 原只有 (actor, clan)——已回填
18. **🔴 完整语义优先铁律（2026-08-27 用户裁定，最高优先级）**——翻译器**必须完整保留 TK5 语义**：循环就是循环、容器就是容器、参数就是参数。**指令/谓词/域不足 = 检查 16a CSV 是否漏了 → 回填（tools/gen_registry_tables.py / build_registry_csv.py 重跑）+ 01/16 注册 + 引擎实现**；「标 🔴待注册 推给 agent」只允许用于**真正表外且确认不是 CSV 漏项**的词条（流程：先 grep CSV 确认无此词 → 才标待注册并记录「已查证表外」）。**禁止**：把已注册命令降级成 note、把参数丢成 src、把循环展开成一次、把容器当静态展开——「结构在效果待补」不是设计，是欠账
19. **🔴 「原文 → 翻译」注释纪律（2026-08-27 用户裁定，四连抓包后固化）**——每个翻译后的内容必须**紧贴其源原文注释**，正文保持纯翻译：
   - **正文 = 纯翻译后内容**（引擎消费的数据）；TK5 源原文一律进注释（`// 源：` / `// [N]` / `// T#`）——**禁止把 src 当 JSON 字段**（曾把 `"src": "ＢＧＭ變更:..."` 塞进正文，用户抓包；引擎调试要源行 = 编译产物阶段注入，源文件不背）
   - **注释位置 = 紧贴对应字段正上方**（字段级：id←事件块头 `事件:事件X{`、trigger/facility←發生契機、once/priority←屬性；条件级：`[N] 調查原文 → DSL` 逐条**严格在 condition 字段正上方**；步骤级：`// 源：`；演出行级：`// T#`）——**禁止堆在 JSON 对象开头**（曾把 39 条 [N] 堆在 `{` 前，用户抓包）
   - **每条原文只出现一次**——禁止「顶部整块原文 + 字段级注释」两处拷贝（两处拷贝 = 「注释和 JSON 对不上」的温床；已删顶部整块，触发/条件原文只存在于字段级注释与 [N] 对照）
   - **覆盖全字段**：id/trigger/once/priority/facility/condition/script 每步/story 每行——**任何翻译内容没有紧贴源注释 = 欠账**（用户抓包：只补 condition 是「代表性 vs 个别」问题，必须统一规则全字段覆盖）

### 🔴 loop 执行模型（2026-08-27 全量数据定稿）

> 全量扫描：TK5 1,823 个循環块，命令 100% 为机制操作（容器選擇/清理/脫出模塊 每块标配 + 更新 1,103/人物解雇 440/城主解任 396/人物登用 69/武將死亡 17/代入），**零演出命令、零等待**。

- **执行模型 = 同步批量执行**：`loop` 步骤一帧内跑完所有轮次，**不需要暂停/续跑机制**（玩家不介入）
- **Ctx 轮次语义**：每轮 body 执行前 `container_pick` 覆盖槽（如 `Ctx::hero_E`）→ body 内引用 = 当轮元素；容器空（pick 失败）或显式 `break`（脫出模塊）→ 循环终止
- **validator 防御检查**：`loop` body 内**禁止演出类步骤**（dialogue/choice/perform/scene_enter）——全量数据证明合法循环不含演出，违规 = 翻译或题材 bug（阻断打包）
- **容器域（Container）** = 运行时集合：`container_set`（按类别初始化）→ `container_filter`（叠加条件）→ `container_sort` → `container_pick`（取元素到 Ctx 槽）/ `container_clear`（移除）；引擎实现 = 内存集合 + 世界查询填充（01 调度器/执行器注册）
11. **stage_inject 注释恢复必须用 cmd 字段判断**——恢复 T# 注释的配对条件曾用 `"narrator" in ln`，v4 改 `cmd: "narrator"` 后旁白行配对错位、T# 全丢（覆盖率 22/22 掉到 15/22）；**凡是「加载-改写-写回」的二次处理脚本，必须自证注释/锚点不丢**
12. **全角字符禁止进任何 key/ID**——全角 Ａ-Ｅ/ａ-ｚ 在槽名、占位符、ID 里一律转 ASCII（`ninja_Ａ`→`ninja_A`、`SLOT_Ｃ`→`SLOT_C`）；validator 应加全角检查
13. **解析器块结构：开块 append 一次、闭合只出栈**——实机：块头 append 到父/root + 闭合又 append 一次 = 每个块翻倍（EFF0C300_159 树里 4 个 OＲ 变 16 个）；闭合行 `}//塊名` 只 pop 不 append。**解析器写完先跑「源块数 vs 树块数」自证**
14. **CSV 侧名按主体域取段**——16a CSV 属性侧名是 `Hero.clan / Settlement.clan` 这种多域共用格式：翻译必须按「域::主体」的域取对应段（人物::X → `.clan`、城::X → `.clan`），**禁止整段侧名拼进 DSL**（实机：`(Hero::X.Hero.clan / Settlement.clan)` 错拼）；域不匹配（大名家.本城 vs Hero.home）→ `🔴待注册` 不硬拼
15. **分支语义三件套（分歧配对/最近一次调查/机位取反）**——①`分歧:(N)` 语义 = 引用**最近一次 調查**（pending_cond 保留到被覆盖，不消费即清——EFF0C300_159 主流程 分歧:(0) 与尾部守城 分歧:(1) 共用同一调查）；②相邻 分歧:(1)/分歧:(0) 配对成 if/else（顺序 [0块,1块] 时 then 条件取反）；③`主人公分歧:(其他)` = 已见机位取反（`not(A) and not(B)`）；④not 嵌套化简（`not(not(X))`→X）
16. **effect 参数语义化（CSV 参数列权威）**——世界结算命令（武將死亡/城主變更/家督讓位…）参数按 16a CSV「参数」列映射成字段（`kill_hero actor`/`set_owner settlement+clan`/`teleport party+pos`…）；TK5 参数**不带域前缀**（`武將死亡:(今川義元)`）→ 按参数名推断域翻译（actor→人物→`Hero::lord_1_imagawa`）；参数逗号切分（`(A,B)` 多参数）；参数溢出 → `🔴待注册` 标注。**禁止只落 src 原文丢参数**
17. **代入槽参数解析**——槽名在命令名里（`代入人物Ｄ:(旅人)` → cmd=`代入人物Ｄ`、参数=值），**不是参数列表第二项**；`代入ｃ:(狀況::年)` 单参数（曾误判 len>=2 导致 89 条假待注册）

### 🔴 称呼决策规则（{二人稱名前} 运行时，用户 2026-08-27 裁定：称呼取决于双方地位差）

> 全语料扫描（2026-08-27）：`{一人稱名前}` **0 次不存在**；`{二人稱名前}` 1,863 次，说话人→对象模式 = **低位→高位占绝对多数**（人物Ｂ→主人公 180、忍者→主人公 131、人物Ａ→主人公 120、小姓→主人公 54、人物Ｂ→上杉謙信 57、福島正則→德川家康 22），少量平级（主人公→人物Ａ 50、人物Ａ→人物Ｅ 平级）。

## 〇、结论先行（决定清单）

1. **决定：翻译自动化 = 两个 py 脚本 + 一个校验闭环 + agent 只做收尾审核**，不再让 LLM 逐句手抄（09b 教训：自称 55 行全落点实际漏 15+ 行；注释 25 条条件 JSON 只写 5 条——LLM 手抄不可校验、不可回放）
2. **决定：机械翻译严格查 16a-DSL翻译总表.csv，表外词条一律标 `🔴待注册` 输出，禁止猜译**（理由：猜译 = LLM 幻觉换了个形态，问题照旧；表外 = 回填 16 注册表后重跑，见 §五）
3. **决定：生成 JSON 放新子文件夹 `plans/scenario-campaign-mode/story_event_json/`**（理由：独立产物独立目录，与手写 plan 文档分离；开发期在 plan 目录内便于审核，定稿后整体迁移补充包 ModuleData，裁定 24）
4. **决定：初版按「源事件 1:1」生成**——一个 TK5 事件 = 一个事件 JSON + 若干演绎剧本 JSON（按演出单元拆分）；多契機合并/机位拆线（09b 先例）是设计判断，留给 agent 审核阶段（§六）
5. **决定：每行原文自动写进 JSON 行注释并自动编 T# 锚点**（理由：源行就是解析器读进来的，注释由程序生成——铁律 7「每一行必须有对应」从源头成立，不靠人工数 T 号）
6. **决定：09b/09c 手工产物保留为「审核参照答案」**，不是废弃——agent 审核时对照它的机位归属/合并决策/软化裁定，机械初版是素材，参照物是终态
7. **决定：旧脚本（TK52Json5.py / TK52Json_SpiltFile_v2.py）只批判继承**——继承词法/块解析/平衡括号思路，废弃它的输出格式（太阁5 中间 JSON）与丢原文做法，见 §七

## 二、步骤 1 规格：`tk5_to_json.py`

### 2.1 输入

- `--events` 事件号清单（带前缀，如 `EFF0C300_159`；支持从 09b 视角归属表读入）
- `--source` TK5 合并源文件（默认 `Knowledge/太阁事件包/TK5AllEvents_merged.txt`）
- `--registry` 翻译表（默认 `16a-DSL翻译总表.csv`）
- `--maps` 归一表目录（角色/城池 StringId 映射，来源 = taikou_final_v9_inference.xlsx + 07 织丰 XML + 匹配报告）
- `--out` 输出目录（默认 `plans/scenario-campaign-mode/story_event_json/`）

### 2.2 解析器（批判继承旧脚本）

| 旧脚本做法 | 继承/批判 | 我们怎么做 |
|---|---|---|
| 正则删 `//.*` 注释再解析 | ❌ 批判：原文被丢，T# 锚点无处可锚 | **不删行**：每行保留原文 + 行号，注释由原文自动生成 |
| 字符流 tokenizer（`{` `}` `\n` 切块） | ✅ 继承思路 | 同思路，但**必须处理 `//size=xxx` 块尾注释与 `}//块名` 闭合标记**（源格式实测，旧脚本未处理会误判） |
| `\(.*?\)` 非贪婪取参 | ❌ 批判：嵌套括号截断（v1 的 bug）| 平衡括号提取（v2 的 `_extract_balanced_params` 思路，✅ 继承） |
| 输出「太阁5 中间 JSON」（cmd 保持原名） | ❌ 批判：等于没翻译，还得再译一遍 | **直接输出 01 DSL 事件 JSON**（查表在解析时完成） |
| `[[文本]]` 里 `{}` 替换 `%%LEFT%%` | ✅ 继承（防块解析器误判）| 同思路，还原时写回原文注释 |
| 性别变体（`分歧:(1)`/`分歧:(0)` 双行） | ⚠️ 未处理 | 识别「相邻两 分歧 块内容逐字相同仅性别词不同」模式 → 合并为一行 lines[] + 性别变体注释（09b 先例 `T2/T2'`） |

### 2.3 事件头翻译（發生契機/屬性 → JSON 字段）

- `屬性:一次` → `"once": true`；`屬性:多次` → `"once": false`；`｜弱` → `"priority": "weak"`（08 §二规则，实测分布已确认）
- `發生契機:X(参数)` → `"trigger"` 值 = 查 08 时机对照表（settlement_enter/house_enter+facility/field_battle_*/siege_battle_*/council_start/daily 兜底），**表外时机输出 `🔴待注册` 清单**（禁止自造 trigger token，README 纪律 8）
- `facility` 参数（自宅/評定間/城主間…）→ `"facility"` 字段（01 facility 注册表 v1）

### 2.4 條件翻译（發生條件 → condition DSL）——🔴 本文件核心

规则（严格按 01 + 16a CSV）：

1. **逐条查表**：每条 `調查:(...)` 用 CSV「太阁原词」列查「我们侧名/实现用法」列：
   - 域映射：`人物`→`Hero::`、`大名家`→`Clan::`、`城`/`據點`→`Settlement::`、`狀況`→`Time::`、`事件標誌`→`Flag::`、`國`→`Settlement.region` 等
   - 属性映射：`存在`→`exists(域::X)` 谓词、`死亡標誌`→`(Hero::X.alive)`、`所屬大名家`→`(Hero::X.clan)`、`城主`→`(Settlement::X.owner)`、`外交同盟`→`isAllied(Faction::a, Faction::b)`、`鄰接大名家`→`isNeighbor(...)`、`事件参加可能`→`(Hero::X.available)`、`評定期間標誌`→（17 注册后落，当前标 🔴待17）等
   - 值映射：角色名/城名 → StringId（查归一表；**查不到 → `🔴待07` 占位 + 清单**，铁律 20 禁止显示名）；`真偽::真/偽` → `true/false`；枚举值（`身份::城主`）→ 16 §四枚举 token（表外 → 🔴待注册）
2. **结构保持**：`ＡＮＤ調查` 嵌套 → `and(...)`、`ＯＲ調查` → `or(...)`——**括号结构 1:1，禁止拍平**（08 纪律：拍平 = 漏条件 = 静默语义错误）
3. **代入槽**（`代入據點Ａ:(大名家::今川義元.本城)` 后引用 `據點::據點Ａ`）：初版按 08 纪律**静态直译**（把槽值直接展开成具体 StringId）；展开不了的（`主人公據點` 等运行时值）→ 写成 `Ctx::` 引用 + `🔴待Ctx` 标注（Ctx = Phase 1 必交，README 裁定 18）
4. **表外条目纪律（🔴）**：CSV 查不到的词 = **不猜**。输出 `// 🔴待注册: 太阁原词「X」` 标记到 condition 注释 + 汇总到待注册清单（§五流程），**条件本身照抄原文进注释**（保证 25 条条件每条都有注释对应——解决 09b「注释 25 条 JSON 5 条」问题的机制设计）
5. **防重复不生成**：`not(Flag)` 等防重复写法不生成（01 三层纪律：调度器自动记 `Event::<id>.done`）；事件顺序依赖 → 自动生成 `(Event::<源内事件引用>.done) == true`（源内 `事件::N` 引用 → 带前缀事件号）
6. **输出 condition 表达式**：单条 = 直接表达式；多条 = `and(...)` 包裹；全表外 = 空 condition + 全量待注册清单（宁缺勿错，agent 审核阶段人工补）

### 2.5 執行翻译（→ script 骨架 + 演绎剧本 lines[]）

按 08 两层拆解（表现层/结算层/流程控制）：

| 源命令 | 落位 | 说明 |
|---|---|---|
| `對話:(說話人,對象)[[文本]]` / `自語` / `旁白` | 演绎剧本 `lines[]`（speaker/narrator + textKey + 行注释 T#+原文） | 说话人查归一表（`人物::` / `主人公` → `Hero::MainHero` / 模板角色 → `Agent::`+🔴待07）；**本地化 key 自动分配** `LWN_SCN_<剧本>_n` 顺序号，生成 i18n XML 骨架（中文值 = 原文自动填入，英文 fallback = `🔴待翻译` 占位） |
| `ＢＧＭ變更` / `ＳＥ開始` | 演绎剧本对应字段（05 注册表）或注释标注 | 表外 → 🔴待注册 |
| `進入設施:(X)` / `離開設施:` | 骨架 `scene_enter` / `scene_exit` 步骤（01 起点环境+中途切换） | 成对出现（08 纪律：进设施演 3D 段、出来回 campaign） |
| `代入` 系列（代入人物Ａ/城Ａ/ａ…） | Ctx 静态展开或 `ctx_set` 步骤 | 同 2.4-3 |
| `調查:` 行（執行内） | 对应 `when` 门控或 if 条件 | 同条件翻译规则 |
| `分歧:(N)`（按值分支） | 演绎剧本 choice + 骨架 `if ((Ctx::<槽>) == "值")` 路由（08 裸分歧规则） | 选项序 = TK5 索引序，值用可读语义词（`"accept"`/`"reject"`），禁止数字索引 |
| `場合別` / `場合分歧` | 骨架 `if` 块（1:1 嵌套结构，08 纪律） | 禁止拍平 |
| `主人公別` / `主人公分歧:(X)` | 机位选路：`if ((Hero::MainHero) == (Hero::lord_X))` | 含对白 → 演绎剧本机位块；纯效果 → 串行 if |
| 结算类命令（武將死亡/勢力滅亡/城主變更/宣戰/改名/軍團指令…） | 骨架 `effect` 步骤（查 CSV 命令区） | 结算唯一纪律：同语义结算只生成一处（跨事件引用时自动标注「结算在 X 事件」） |
| `選擇:[[…]][[…]]` | 演绎剧本 choice 节点 | 选项文本进 i18n |
| 机制行（士气更新/義理更新等无演出价值的） | 不落 lines[]，**在 JSON 注释标 `🔴机制行 → 承接系统`**（删行不行，铁律 7） | 承接系统 = 02/03/13/14/17 按 CSV 分组 |

**演出单元拆分规则（初版机械默认）**：一个源事件的执行块按「`進入設施`/`離開設施` + `主人公分歧` 机位块」切成若干演出单元 → 每个单元 = 一个演绎剧本 JSON（playbackId = `<剧本>_<事件>_<段序>`）；agent 审核阶段再合并/命名（09b 参照物：159 → first_audience + departure 两个演绎剧本）。

### 2.6 输出清单（每事件）

- `story_event_json/<剧本>/events/<事件号>.json` — 事件骨架（id/trigger/facility/once/priority/condition/script + 行注释）
- `story_event_json/<剧本>/story/<playbackId>.json` — 演绎剧本（初版 = lines[] + textKey + T# 注释；stage 字段留待步骤 2）
- `story_event_json/<剧本>/i18n/std_scn_<剧本>.xml` — 本地化骨架（中文自动填原文，英文 fallback 🔴待翻译，铁律 13）
- `story_event_json/<剧本>/report_<事件号>.txt` — 覆盖报告（源行总数 / 落点行数 / 待注册清单 / 表外清单）

### 2.7 校验（脚本内置）

- 内嵌 `verify_tk5_coverage.py` 解析逻辑：**演出行 100% 覆盖是硬断言**（每行都是生成的，跑不绿 = 生成器 bug，阻断输出）
- 行数声明自动生成（不存在「手数 T 号数错」）
- 待注册清单 ≠ 空 = [WARN] 提示（不阻断，agent 审核阶段裁决）

## 三、步骤 2 规格：`stage_inject.py`

> 输入：步骤 1 的演绎剧本 JSON。职责：把「谁、何时、在哪个位置」的舞台管理写进 JSON——05 源格式补充字段（actor_enter/actor_move/actor_leave/present，README 纪律 7 补注）的机械推导。

### 3.1 推导规则

| 数据来源 | 推导结果 |
|---|---|
| lines[] 说话人全集（Hero::/Agent::） | `actors` 清单（每演员一行；说话人无对应实体 = 🔴待07 占位） |
| 演出单元起点（perform 开始） | 开场即在场演员 → `"present": true`；其余 → 首条说话行前插 `actor_enter` |
| `進入設施`/`離開設施` 对应行 | 中途入场/离场 → `actor_enter` / `actor_leave` 指令（05 源格式字段） |
| 对话顺序中说话人位置语义 | `actor_move` 走位（说话人上前/归位——05 推导规则：发言者移动到主位、发言完退回） |
| 演出单元机位（主人公分歧块） | 机位门控 `when`（`(Hero::MainHero) == (Hero::lord_X)`），非本机位演员剪裁 |

### 3.2 槽位分配

- 参考实现 = `ExampleModVS/ExampleMod/ExampleMod/Story/StageDirector.cs` 的 StageSlot 语义（Chair 主席/Guest 贵宾/Accompany 陪席）→ 映射 05 语义槽（throne 主位/side 侧位/gate 门位）
- 机械默认：**首个说话人 = 主位（throne）**，对话对象/次高频说话人 = 侧位/门位；机械分配只是初值，agent 审核阶段按名场面语义调整（09b 参照物：first_audience 的 actors 表）
- 场景（sceneId）：初版 = 按演出形态查 05/07 场景清单，查不到 → `🔴待07` 占位 + 兜底场景注释

### 3.3 输出

- 第二版演绎剧本 JSON（覆盖写 `story_event_json/<剧本>/story/*.json`）：actors 齐全 + 舞台指令字段 + 机位门控
- 舞台管理是 mod 必要补充（verify_tk5_coverage.py 文档声明「只查源→mod 方向，不检查 mod 多出来的内容」）——**不参与覆盖校验**，参与 05 编译器校验（字段 ∈ 05 注册表）

## 四、步骤 3：校验闭环（角色反转）

- `verify_tk5_coverage.py` 对生成产物跑：**理论上必然全绿**（演出行全部生成）——它的角色从「抓漏」变「回归护栏」

## 五、表外条目处理流程（🔴 v2：表外 = 生成器缺陷，禁止产出待注册，2026-08-27 用户裁定）

```
翻译器遇到 CSV 表外词 → ❌ 不可能发生（两道闸）：
  ① 生成期自检（build_registry_csv.py）：全语料 (域,属性)/(域,值)/带参调用/命令 必须全部可解析，
     表外 = exit(1) + 列清单（回填 gen_registry_tables.py 映射/规则 → 重跑）
  ② 翻译器 fail-fast（tk5_to_json.py）：CSV 查不到 = RegistryGapError 抛异常终止，禁止产出 🔴待注册
        ↓
agent 对「有主占位」逐条裁决（report 待注册清单 = StringId 级，非词条级）：
  ① 回填 16 注册表（gen_registry_tables.py 映射字典）→ 重跑 build_registry_csv.py → 重跑步骤 1
  ② 标 🔴待07（织丰 ID 未核）/ 🔴待17（评定系统未做）等真实占位——占位对象可查、有主
  ③ 设计上确实不要（如流派域 = ❌ 放弃，CSV 已有例）→ 标注弃用理由
```

裁决结果 = 审核记录（`story_event_json/审核记录.md`），禁止「静默猜译」「静默丢弃」两种出口。
