## 一、机械翻译纪律（27 条）

> 每条都是一次实机踩坑（用户抓包或自审发现）→ 已固化成脚本行为。**翻新事件、换新题材之前先过一遍这 23 条**，这是本文件最有用的部分。

1. **条件必须逐条对上 TK5 原文**（用户裁定）——「注释说 25 条、JSON 只写 5 条」是手抄的必然结果。机械翻译 = 逐条查 16a CSV（§3.4），查不到就停机（§六）。**禁止「注释写摘要、JSON 写简化版」两条腿走路**。
2. **指令名必须落 JSON 第一字段**（用户裁定）——演绎剧本每行 `cmd` ∈ 05 指令流权威（`dialogue` / `narrator` / `choice`），骨架每步 `step` ∈ 01 步骤表。**禁止靠别的字段在不在来推断这行是什么**（曾用「有没有 speaker」推断是不是对白，被抓包）。🔴 **v6 命名分层（2026-08-30 定）**：CSV 侧名 = 翻译层（say / monologue / narrate / choice——**查表识别用**）；05 形态词 = 表现层（dialogue / narrator / choice——**产物落盘用**）。两个层不混：台词管线 = "CSV 侧名命中台词集合 → 输出 05 形态词"。**禁止产出 CSV 侧名当 lines cmd，禁止产出 05 词当骨架 step**（选材：对话→say 识别→dialogue 落盘；本句尾的「對話→dialogue」只是 05 侧语义示意，以实测产物为准）。
3. **對話 的两个参数都要落字段**（用户裁定）——`對話:(說話人,對象)` 的 param1=speaker、param2=listener 都结构化落盘，禁止只收 speaker、让「对谁说」靠注释反推。舞台注入靠 listener 字段推导沉默观众位（§四）。
4. **代入 = 局部变量赋值，不是静态展开**（用户裁定）——🔴 **v6 修订**：`代入人物Ｄ:(旅人)` → 动作名 = CSV 侧名 `assign_ctx`（原稿写 ctx_set，CSV 权威 = assign_ctx / assign_var / assign_slot），槽名 = CSV 参数列 `slot=` 预设（`hero_d`，以 CSV 为准，不再脚本推断），值 = pos1 翻译 → `Ctx::hero_d`（16 §一 Ctx 三档）。**唯一例外：条件块里的代入要静态展开**——条件求值时没有执行流可以跑 assign_ctx（EFF0C300_159 的「據點Ｂ = 織田本城」即此例）。槽名大小写：CSV 参数列字形 = `hero_d`（d 小写）；旧产物 `hero_D` 大写，v6 重跑后以 CSV 统一。
5. **中文和 emoji 禁止进 ID**（用户裁定）——占位 ID 必须是合法 StringId 形态（`Hero::tk5_dosan` / `Agent::tk5_traveler` / `Settlement::tk5_city_083`），配一张「占位 ID → 中文名」对照表进报告，供 07 审核时全局替换。🔴 **v6 修订（2026-08-30 零兜底纪律）**：**"兜底 fallback = 确定性哈希 ID" 作废**——哈希 = 把数据缺口伪装成翻译成功，禁止；查无实体 = 生成器闭包登记占位（`tk5_city_NNN`/`TK5_ONLY_HERO`）+ 报告点名（§9/§21 先例），翻译器侧零兜底（§15.1.5）。**「🔴待07」只允许出现在注释和清单里，不允许出现在引用位置**。
6. **本地化键必须全局唯一**（铁律 13 的脚本落地）——行计数器是事件内的，键必须带事件号前缀（`LWN_SCN_okehazama_EFF0C300_159_7`）。裸序号跨事件必撞（实机：`_7` 撞了 22 次）。

### loop 的执行模型（2026-08-27 全量数据定稿）

> 全量扫描：TK5 共 1823 个循環块，块里的命令 100% 是机制操作（容器選擇/清理/脫出模塊 每块标配，加上 更新 1103 次、人物解雇 440、城主解任 396、人物登用 69、武將死亡 17、代入若干），**没有一条演出命令、没有一次等待**。

- **执行模型 = 同步批量跑完**：`loop` 一帧内跑完所有轮次，不需要暂停/续跑机制（玩家不介入）。
- **每轮的上下文**：每轮进 body 之前 `container_pick` 覆盖槽（如 `Ctx::hero_E`），body 里的引用 = 当轮那个元素；容器空（pick 失败）或显式 `break`（脫出模塊）→ 循环结束。
- **validator 要拦的**：`loop` body 里**禁止出现演出类步骤**（dialogue / choice / perform / scene_enter）——全量数据证明合法循环不含演出，出现了就是翻译或题材出了 bug，直接阻断打包。
- **容器域** = 运行时集合：`container_set`（按类别初始化）→ `container_filter`（叠条件）→ `container_sort` → `container_pick`（取一个进 Ctx 槽）/ `container_clear`（清空）；引擎侧 = 内存集合 + 世界查询填充（01 调度器/执行器注册）。

## 三、步骤 1 规格：`tk5_to_json.py`

### 3.1 输入

- `--events` 事件号清单（带前缀，如 `EFF0C300_159`）
- `--scenario` 剧本名（决定输出子目录与本地化键前缀）
- `--source` TK5 合并源（默认 `Knowledge/太阁事件包/TK5AllEvents_merged.txt`）
- `--registry` 翻译总表（默认 `16a-DSL翻译总表.csv`）
- 实体归一表：直接 import `tools/entity_maps.py`（§九 的生成物，不再走命令行参数）
- `--out` 输出目录（默认 `story_event_json/`）

### 3.2 解析器（批判继承旧脚本）

| 旧脚本做法 | 结论 | 我们怎么做 |
|---|---|---|
| 正则删 `//.*` 注释再解析 | ❌ 批判：原文被丢，T# 无处可锚 | **不删行**：每行留原文 + 行号，注释由原文自动生成 |
| 字符流 tokenizer（按 `{`、`}`、换行切块） | ✅ 继承思路 | 同思路，但**必须处理 `//size=xxx` 块尾注释和 `}//块名` 闭合标记**（源格式实测，旧脚本没处理会误判） |
| 非贪婪正则取括号参数 | ❌ 批判：嵌套括号被截断（v1 的 bug） | 平衡括号提取（继承 v2 的 `_extract_balanced_params` 思路） |
| 输出「太阁5 中间 JSON」（cmd 保持原名） | ❌ 批判：等于没翻译，还得再译一遍 | **直接输出 01 DSL**，查表在解析时完成 |
| `[[文本]]` 里的花括号先替换成占位再还原 | ✅ 继承（防块解析器误判） | 同思路，还原时写回原文注释 |
| 性别变体（相邻 分歧:(1)/分歧:(0) 双行） | ⚠️ 旧脚本没处理 | 识别「相邻两块逐字相同、只差性别词」→ 合并成一行 + 性别 when 门控 |

### 3.3 事件头（發生契機 / 屬性 → JSON 字段）

- `屬性:一次` → `"once": true`；`屬性:多次` → `false`；`｜弱` → `"priority": "weak"`。🔴 **v6 修订**：不管 if 判断，值查枚举值区「事件屬性」域（一次→once 等）。
- `發生契機:X(参数)` → `"trigger"`，值查 16a 枚举值区「觸發」域（`室內畫面表示後→Trigger::house_enter` 等 22 条 T2）；**契约第二参数（自宅/評定間/城主間…）→ `"facility"`，值查「設施」域（38 条 `Facility::*`）**——🔴 v6 前脚本用 TRIGGER_MAP 硬编码字典、facility 中文原样（A6），v6 后两处都走表。**08-转化管线 的触发时机对照表（md）降级为"说明文"**（它列了"在骑砍2 哪个事件点注册监听"这一信息，16a 没有——属实现说明非翻译知识）；表外时机 = 停机报缺，禁止自造 trigger（README 纪律 8）。

### 3.4 条件翻译（發生條件 → condition DSL）——本脚本的核心

1. **逐条查表**：每条 `調查:(...)` 拿「太阁原词」列查「我们侧名 / 实现锚点」列：
   - 域：`人物`→`Hero::`、`大名家`→`Clan::`、`城`/`據點`→`Settlement::`、`狀況`→`Time::`、`事件標誌`→`Flag::`、`國`→`Settlement.region`。
   - 属性：`存在`→`exists(...)`、`死亡標誌`→`(Hero::X.alive)`、`所屬大名家`→`(Hero::X.clan)`、`城主`→`(Settlement::X.owner)`、`外交同盟`→`isAllied(...)`、`鄰接大名家`→`isNeighbor(...)`、`事件参加可能`→`(Hero::X.available)`。
   - 值：角色名/城名 → StringId（查 §九 归一表）；`真偽::真/偽` → `true/false`；枚举值（`身份::城主`）→ 16 §四 枚举 token。
2. **结构 1:1 保持**：`ＡＮＤ調查` → `and(...)`、`ＯＲ調查` → `or(...)`，**禁止拍平**（拍平 = 漏条件 = 静默语义错）。
3. **代入槽**：见纪律 4（条件块内静态展开，执行块内 assign_ctx——CSV 侧名，v6 修订）。
4. **查不到就停机**：见 §六。
5. **防重复条件不生成**：`not(Flag)` 这类防重复写法不落（01 三层纪律：调度器自动记 `Event::<id>.done`）；事件顺序依赖 → 自动生成 `(Event::<前置事件号>.done) == true`。
6. **输出**：单条 = 直接表达式；多条 = `and(...)` 包裹。

### 3.5 执行翻译（→ script 骨架 + 演绎剧本 lines[]）

> 🔴 **v6 起本表只解释"翻译语义"，不再描述"脚本内硬编码怎么写"**——翻译实现 = 查 16a 命令区（§十五 S2）：每行"源命令"查 CSV 得侧名/参数列/档/载体，按参数列翻译参数。本表保留是因为它说明参数列里各词条的语义；**凡本表出现的落位词与 CSV 侧名不同，以 CSV 侧名为准**（如 `對話`=CSV 侧名 `say`，演绎剧本里由台词管线输出 05 形态词 `dialogue`——查表识别用 CSV 名、落产物用 05 名，两层不混）。

| 源命令 | v6 后的翻译链 | 说明 |
|---|---|---|
| `對話` / `自語` / `旁白` | 查表得 `say` / `monologue` / `narrate`（台词侧名集合）→ 台词管线 → 演绎剧本 `lines[]`（cmd=`dialogue`/`narrator`+speaker+listener+textKey+T#） | 说话人查归一表；本地化键自动分配（`LWN_SCN_<剧本>_<事件号>_<序>`），同时写 i18n XML（中文 = 原文，英文 fallback 待翻译） |

## 六、查不到怎么办（🔴 v2：查不到 = 生成器缺陷，2026-08-27 用户裁定）

**两道闸，把「表外」堵在产物之前**：

1. **生成期自检**（`build_registry_csv.py`）：全语料的 (域,属性) / (域,值) / 带参调用 / 命令 必须全部可解析，有表外就 `exit(1)` 并列清单 → 回填 `gen_registry_tables.py` 的映射与规则 → 重跑。
2. **翻译器停机**（`tk5_to_json.py`）：CSV 查不到 = 抛 `RegistryGapError` 终止，**禁止产出「🔴待注册」凑数**。

**所以报告里剩下的「未结清」不是表外词条，而是三类有主的缺口**——每条都指向一个明确的补法：

| 类别 | 桶狭间当前 | 什么意思 | 怎么结清 |
|---|---|---|---|

## 八、与 16b 落点裁定表怎么对接

**一句话：16a 告诉翻译器「这个词翻成什么」，16b 告诉它「这个词将来由谁实现、存哪儿」。翻译器两样都读，但只把后者写进报告，不写进 JSON。**

翻译器实际消费 16a 的 13 列里的这几列：

| 列 | 翻译器拿它干什么 |
|---|---|
| 类别 / 所属域 / 太阁原词 | 查表主键（三元组）——同一个词在不同域里是不同的东西 |
| 我们侧名 | 直接拼进 DSL 的 token（`Hero.clan` → `(Hero::X.clan)`） |
| 参数 | 结算命令的参数位 → 字段名映射（纪律 16）；参数位不够就记未结清 |
| 值类型 | 决定值怎么写（布尔 → true/false、数字 → 裸数、枚举 → token、对象 → StringId） |
| **档** | 只进报告分档统计，不进 JSON |
| **载体 / 存档键** | 只进报告的「落仓清单」，告诉实现方这个字段将来存哪个仓 |
| **实现锚点** | 只进报告，告诉实现方读写落在哪个模块 |

**四档在运行时分别是什么行为**（16b 权威，翻译器只是转述）：

| 档 | 含义 | 运行时 | 桶狭间用到 |
|---|---|---|---|
| T1 | 引擎直取 | 直接读写骑砍原生字段 | 25 |
| T2 | 引擎改造 | 走引擎，但要本 mod 补一层（如 loop、facility 进出） | 21 |
| T3 | 本 mod 新造 | 落外置仓 / 13主命 / 17功勋 等，本 mod 自己实现读写 | 35 |
| T3-预留 | 可解析、可落仓、**行为空执行** + `[Scenario][TODO]` 日志 | 存得下读得出，动作本期不做 | 1（所屬海賊衆） |
| T0 | 降级 | 只作注释保留，不生成步骤 | 0 |

**落仓清单**（本剧本要存档的字段，报告自动汇总）：`lwn_scn_attr` 29 个、`lwn_scn_state` 6 个、`13` 2 个、`17` 4 个。这张清单就是 11-存档与配置 的输入——存档键必须在 11 的登记表里写清「存在哪」和「新档怎么清」，`fill_registry.py` 自检⑥ 会卡。

## 九、名字 → StringId 的对照表从哪来（`gen_entity_maps.py`）

## 十五、v6 数据驱动重构（2026-08-30 用户裁定——当前任务，按本节执行）

> 一句话：**翻译脚本停止"认识命令"，改成"查表"。** 16a CSV 自带全部翻译知识；脚本只做两件事——解析 TK5 语法、查表翻译；查不到 = 报错停机 + 缺口报告（agent 回填映射表收敛到零）。**CSV = 翻译知识唯一事实源，脚本禁止复制第二条。**

### 15.1 为什么（背景三句话）

1. 现状 tk5_to_json.py 是**枚举式翻译器**：翻译知识（命令→动作名→参数形态）写死在脚本里（`_WORLD_EFFECTS` 字典、933 行表现指令表、容器 op 字典、slot_cname 推断），绕开了 16a。
2. 后果：16a 修得再全脚本也不读（表有 `ＢＧＭ變更→bgm_change`，脚本硬编码成 note）；表外**永远不报错**（硬编码兜底）→ 产物带病：312 个 note、23 个 `🔴 02 army_gather` 式假 action、容器参数中文原样。
3. 新架构 = 本文件 §〇-2 与 §六"**查不到=生成器缺陷→停机→回填**"宗旨的真正落地（之前被硬编码短路了）。换题材（三国演义） = 换 CSV + 实体表，脚本零改动。

### 15.1.5 🔴 双信源架构（翻译总表可信的前提，重写工作的第一原则）

**TK5 事件里的 token 分两类，各有一个查表信源，互不越界：**

| 信源 | 内容 | 权威文件 | 可信前提 |
|---|---|---|---|
| **A：翻译总表** | TK5 事件里**除具名实体外的一切名词**——命令 / 域 / 属性 / 函数 / 枚举值 / 语法 / 文本变量 / 域值 | `16a-DSL翻译总表.csv`（生成物） | `build_registry_csv.py` 的**全语料闭包自检**（六道，不绿 exit(1)）：`Knowledge/太阁事件包/TK5AllEvents_merged.txt`（2594 事件）里所有非实体名词必须全被认领——**所以"查不到 = 表不全 = 生成器缺陷 = 回填 `gen_registry_tables.py` 重跑，禁止在脚本里兜底** |
| **B：实体 ID 表** | TK5 事件里的**具名实体**（人名/城名/家族/势力/据点的 StringId） | `Knowledge/骑砍2织丰角色ID对应/` 的诸多表格（`骑砍2太阁Mod表.xlsx` 等）→ `gen_entity_maps.py` → `tools/entity_maps.py`（生成物，MISSING_IN_XML / TK5_ONLY_HERO 报告点名） | 此表由织丰数据源生成（§九），实体找不到 = 07 数据包欠账（报告点名，**不算翻译器表外**） |

**选择规则（数据驱动，禁止硬编码）**：翻译器对每个 token 先看它的**值类型/类别标注**（标注来自 CSV 参数列/值类型列/域值区，不是脚本判断）——标注 = `具名实体`/`模板NPC` → 信源 B；标注 = `枚举`/`域值`/`资源`/`文本变量`/`数字`/`真偽` → 信源 A。**脚本永远不写"哪个中文名去哪查"，只按标注分流**——这就是硬编码与数据驱动的分界线：硬编码 = "我知道ＢＧＭ變更要查枚举值区"；数据驱动 = "参数列写了 pos0=ＢＧＭ 枚举 → 查枚举值区"。区分错误（参数列标注写错/漏标）→ 报"标注问题"→ 回填 CSV 参数列，同样不猜。

**🔴 零兜底纪律（2026-08-30 用户裁定——最高优先级）**：**翻译器内禁止出现任何形式的兜底/fallback/占位替换**——防的是"翻译静默降级"：产物带病但脚本不报错（正是 BGM note/哈希占位/FALLBACK_MAP 走过的错）。规则：

1. **查无 = 中止**：翻译器查 信源 A（16a）或 信源 B（entity_maps）任何一表查无该词条/实体 → `RegistryGapError` **停机并报错**（报：什么词条/哪个实体/源第几行/查的哪个信源/建议回填哪个生成器哪个区）——**绝不生成占位、绝不哈希、绝不注记"→XX承接"**。
2. **修复闭环**：报错 → agent 按报错优化生成器（`gen_registry_tables.py` = 信源 A / `gen_entity_maps.py` = 信源 B）→ 重跑 CSV/映射 → 重跑翻译 → 直到零表外。**翻译器自身的失败模式只有一种 = 报错停机**。
3. **占位 ID 是生成器的产物，不是翻译器的兜底**：信源 B 生成器对"太阁有、织丰无"的实体（4 町/3 配角/8 城）**闭包登记**——输出登记型占位 ID（`tk5_city_NNN`/`TK5_ONLY_HERO`）+ 报告点名（08b 纪律 21/§九 批准过的做法）；翻译器查表**永远命中**（表是闭包）。**禁止**生成器用哈希/静默值——那等于把"数据缺口"伪装成"翻译成功"（纪律 25 精神：空转报绿同样禁止）。
4. **层边界（不混）**：零兜底 = **翻译/生成侧**（本文件全部脚本：tk5_to_json / stage_inject / gen_* / verify）；**运行时降级**（游戏内铁律 1 防崩：条件求值失败→假、称呼查→默认敬称、LLM 不可用→模板）是另一层纪律，不动——差别只在"数据作者是开发侧 agent（可修复、必须拦截）vs 玩家（防崩、可降级）"。

**代码形态**：翻译器内两个查询器平级：`Registry`（信源 A）与 `EntityMaps`（信源 B，现有 `translate_ref/translate_subject/speaker_of` 已用）。**新代码禁止出现"某命令专属的取参逻辑"**——一切取参走参数列解析 → 类型标注 → 对应信源。
