## 这一步做什么（一句话）

给**有主公**的玩家身份（家臣）一条数值化渐进成长线：**功勋（Merit）→ 季度评定 → 晋升 → 官职效果**——与剧本推进的事件跃迁线（家臣→家督→霸主）正交（用户 2026-08-24 拍板：第一版只做家臣线，大名支配力线后续 plan）。

## 一、核心概念

### 1. 功勋 Merit

- **定义**：主公视角的贡献累计。与骑砍2 声望（天下名望）**语义分离——独立数值，禁止与 Renown 互算/混用**（防"打野刷声望也能升官"的荒谬）
- **激活条件**：`Hero.identity` 为家臣类（枚举 token 数据包定义，如 `retainer`）才有此线；大名/浪人身份无此线（浪人先仕官——第一版仕官 = 剧本事件驱动，自由仕官后续 plan）
- 🔴 **按主公维度记账**：功勋记在"（角色, 主公）"对下；**换主公（跳槽/独立）清零重来**（防跳槽刷功勋，符合太阁5）
- **纯累计制**（太阁5 模式）：晋升**不消耗**功勋，只增不减（负面来源除外：拒绝主命/事件惩罚）
- 存档：per-hero SyncData（卡域先例，16 Card），`ResetAllCampaignState()` 同步补（横切纪律 5）

### 2. 晋升链 RankLadder（🔴 数据包定义，核心零日战字串）

```jsonc
// 织田家示例（数据包；titleId 用英文 token，显示名/称呼走本地化）
{ "meritLadder": [
  { "titleId": "rank_ashigaru",     "titleName": "足轻",     "threshold": 0,   "salary": 100,  "unlocks": [] },
  { "titleId": "rank_kumigashira",  "titleName": "足轻组头",  "threshold": 100, "salary": 200,  "unlocks": ["quest_type_campaign"] },
  { "titleId": "rank_samurai_taisho","titleName": "侍大将",   "threshold": 300, "salary": 400,  "unlocks": ["quest_type_campaign", "quest_type_diplomacy"] },
  { "titleId": "rank_busho",        "titleName": "部将",     "threshold": 500, "salary": 700,  "unlocks": ["quest_type_fief"] },
  { "titleId": "rank_karou",        "titleName": "家老",     "threshold": 800, "salary": 1000, "unlocks": ["quest_type_fief", "quest_type_war"] },
  { "titleId": "rank_castle_lord",  "titleName": "城主",     "threshold": 1200,"salary": 1500, "unlocks": ["quest_type_fief", "quest_type_war", "propose_council"] }
]}
```

- 核心只定义模型：**有序阶梯（titleId / 阈值 / 俸禄 / 解锁项）**，内容全在数据包
- 阶梯最高级之后 = 剧本推进线接管（跃迁家督/霸主，06/14），功勋线自然结束

### 3. 评定 Review（季度评定会，太阁5 的灵魂）

- **周期**：季度初（骑砍2 一年 84 天，月 = 7 天，1/4/7/10 月 = 季度）
- **触发**：**功勋已达下一级阈值才触发晋升评定**（`canPromote` 谓词，见第三节）——例行评定（不晋升）第一版不做，**省演出防疲劳**；俸禄静默季度结算
- **实现 = 标准 DSL 事件**（01 格式）：

```jsonc
// 季度评定事件（引擎核心通用模板；数据包配阶梯后直接可用）
{
  "id": "merit_review_generic",
  "when": "and( (Time::month) == 1,                // 季度初
                canPromote(Ctx::主人公),            // 🔴 功勋 ≥ 阶梯中当前官职的下一级阈值（新谓词，16 注册）
                (Ctx::主人公.identity) == retainer,  // 身份枚举 token（数据包定义）
                not( (Flag::reviewed_this_quarter) == true ) )",  // 防重复（flag 季度初统一清）
  "script": [
    { "step": "perform", "playbackId": "review_promotion" },   // 评定演出（05 编译）：主公当众宣布 + 家臣祝贺 IM
    { "step": "effect", "action": "promote", "actor": "Ctx::主人公" }   // 晋升：官职+1、俸禄表更新（阶梯查询）
  ]
}
```

- 演出要点（05）：评定会场景（御殿列席）→ 主公点名 → 当众宣布新官职 → IM 祝贺刷屏——**晋升是仪式，不是弹窗**

### 4. 官职效果（三合一，才不空洞）

| 效果 | 内容 | 实现 |
|---|---|---|
| **俸禄** | 季度发俸（按当前官职查阶梯）；**金钱 = 特殊物品，走 AgentControlHelper 铁律 4** | 季度结算引擎自动发（Grant 单边"世界"来源，null 虚空标注） |
| **权限解锁（软性）** | 主命类型解锁（13 QuestDef 加 `minTitle` 门槛：当上侍大将才接"带兵出征"类主命）、治理权（城主解锁"治理封地"类）、提议权（家老可提议军议事项） | 🔴 **只用解锁不用禁止**——不碰原版带兵公式（声望制）、不锁死自由行动（设计哲学：自由感） |
| **称呼** | NPC 对话开场/IM 引用按官职称呼（"XX大人"）；数据包称呼表（titleId → 称呼模板），任意 NPC 接得住（铁律 8） | 现有对话/IM 称呼语料管线 |
| **事件门控** | `merit`/`title` 域（16 已注册）进事件 `when`：功勋不够 → 主公不委以重任 → 历史事件推迟/换人 | 与 14 drift 衔接（玩家可控变量） |

## 二、功勋来源（🔴 纪律：必须"为主公做事"才涨，自由行动不涨）

| 来源 | 场景 | 数值 | 负面反馈 |
|---|---|---|---|
| 完成主命 | 13 QuestDef 报酬项加 `merit` | 数据包按难度 | 拒绝/超时 → 扣功勋 + 关系（04 反馈纪律） |
| 战斗/讨伐 | 03 battle 结算钩子（玩家参战 + 胜） | 数据包 | 战败不扣（第一版） |
| 剧本事件 | DSL `grant_merit`（含负值） | 事件表定 | 事件选择负分支 |
| 献金 | 与主公对话入口（送钱） | 每 X 金 = Y 功勋（数据包），**季度上限**（防买穿） | — |

- 献金走**铁律 4 Transfer 纪律**（玩家扣、主公收，守恒）
- 功勋变动播报（+X 功勋 通知/面板），负面变动也播报（反馈纪律）

## 三、DSL 增补（16 注册表同步）

| 类别 | 条目 | 参数 | 语义 | 状态 |
|---|---|---|---|---|
| 域 | `Hero.merit`（数字）/ `Hero.title`（枚举） | — | 已在 16 数据包扩展层注册（16 L106/L109），直接可用 | ✅ 已有 |
| 谓词 | `canPromote(Hero::X)` | hero | X 的功勋 ≥ 阶梯中 X 当前官职的下一级阈值（X 无官职 = 第 0 级；已最高级 = false） | 注册表加行（17 实现） |
| 动作 | `grant_merit` | actor, value | 功勋增减（负值 = 扣） | 17 |
| 动作 | `set_title` | actor, titleId | 直接设官职（主公特封/剧本用） | 17 |
| 动作 | `promote` | actor | 按晋升链升一级（评定事件用；阶梯查询数据包） | 17 |

- 🔴 **动作统一管理**（16 第五节注记精神）：三个动作挂 WorldActionExecutor 共享执行层（Scenario 层入口）；Agent 决策层（ActionRegistry）第一版无对应——功勋是剧本/主命/结算系统写，不是 Agent 决策动作
- validator 同步：canPromote 谓词 + 三动作进注册表检查清单（01 静态检查 #2）

## 四、与剧本推进的衔接（双线正交）

- **功勋线 = 数值渐进**（同一身份内部爬升，间隙期主节奏）；**剧本推进线 = 事件跃迁**（身份质变，06/14）
- **衔接点**：① 晋升链最高级 → 剧本推进接管（跃迁）② `merit`/`title` 可作剧本事件门控（14 drift 的玩家可控变量：功勋高 → 主公早委以重任 → 历史事件提前触发）
- **换主公**（跳槽/独立/主公死亡）：功勋清零（新主公重新积累）；身份变大名 → 功勋线结束（成长 = 原版声望 + 剧本推进，支配力线后续 plan）

## 五、体验展示（04 第六节呼应：成长必须看得见）

- **面板**：功勋值 / 当前官职 / 下一级阈值 / 俸禄（常驻可见）
- **晋升演出**：05 评定会 + IM 祝贺——晋升是仪式感事件，不是数值通知
- **称呼升级**：NPC 称呼随官职变化（对话开场可见）
- **门控预告**：主命池按官职解锁时明示"侍大将可接"（事前信息，设计哲学：信息塑造目标）

## 做完怎么验收

1. 家臣身份玩家全链路：做主命 → 功勋涨（播报+面板）→ 季度评定演出 → 晋升 → 俸禄/主命池/称呼变化
2. 纯累计制：晋升不扣功勋；**换主公清零**；大名身份无此线（面板隐藏）
3. 防刷：自由行动不涨功勋；献金季度上限生效
4. 面板随时可见：功勋/当前官职/下一级阈值/俸禄
5. 门控生效：剧本事件 when 引用 merit/title 正确求值（高功勋触发"委以重任"分支）

## 要注意的坑

- **声望 vs 功勋混用**：独立数值，禁止互相换算（语义不同：天下名望 vs 主公信任）
- **换主公不重置**：按主公维度记账，跳槽/独立清零
- **官职只解锁不禁**：不碰原版带兵公式、不锁自由行动（自由感；带兵上限是软引导不是硬限制）
- **评定演出疲劳**：只晋升才演出，例行俸禄静默结算
- **日战官职名零核心**：阶梯/称呼全数据包（worldview 铁律 grep 验收）
- **存档纪律**：merit/title SyncData + ResetAllCampaignState 同步（漏了 = 读档回退/重置残留）
- **铁律 4**：俸禄 = Grant 单边（null 虚空）；献金 = Transfer 守恒（玩家扣、主公加）
- **validator**：canPromote/三动作进注册表清单，未注册引用 = 加载报错禁用剧本（01 纪律）
