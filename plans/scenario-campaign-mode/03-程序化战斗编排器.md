> 通过后改为 ✅ 已审核（日期）+ 记录意见。

## 这一步做什么（一句话）

**不手工搭战场，也不写演出脚本**：一场战役 = 一段关卡数据，引擎按数据**一次并联布设**整个战场（场景/天气/双方兵力/站位/装饰/初始状态/叙事钩子），之后交给引擎实时模拟，钩子触发（主将死→溃散）时写战果旗标。**新战役 = 写关卡数据，零美术工作**。

## 🔴 定位：关卡编辑器，不是演出脚本（2026-08-26 用户裁定）

03 与 09b 是**两个范式**，共用一套执行模型的错觉会导致设计错位：

| | 09b 演绎剧本 | 03 战斗编排 |
|---|---|---|
| 本质 | 时间顺序的动态演出 | **关卡编辑（并联瞬时完成）** |
| 来源 | TK5 原文直译（原文行完整性铁律，见 README） | **无太阁5 对应行可译**——太阁5 战斗是棋盘，没有战场布设概念；关卡 = 作者/AI 按剧本语境创作 |
| 执行模型 | lines[] 逐行顺序执行（上一行完成才下一行） | 布设一次算好、所有元素**同时就位**（并联），之后引擎实时模拟，无"逐行演出" |
| 驱动 | 翻译驱动（每行有原文锚点） | **语境驱动**（关卡要回答"这场战斗在剧本里该是什么样"） |
| 动词 | 说/看/走（演出动作） | 摆/生成/挂（布设动作） |
| 写作纪律 | 原文行完整性（能翻译就翻译） | **约束下的创作**（无原文可依，但受注册表约束，见 §7） |

> 🔴 **扩展性（2026-08-26 用户裁定：03 是通用引擎件，禁止被剧本绑架）**——本文件是 LWN 核心引擎的关卡编辑子系统，**桶狭间/本能寺只是第一个使用实例（Phase 1 演示）**。三权分离：引擎（本文件）只定义通用机制（字段/原型/布局函数/波次类型/主题/管线），题材内容（日式营地素材/中原营寨/卡拉迪亚战场）全部在数据包（织丰/三国/未来包，07 素材表按包组织）——**任何剧本 = 选 archetype + 覆盖参数，不写引擎代码**。铁律：文档主体出现的剧本实例只作示例，禁止实例冒充定义。

## 玩家视角

> （以下为 Phase 1 演示实例——03 的通用性见上"扩展性"；实例之外的能力见 §0a 原型注册表）

- 桶狭间：雨夜，今川义元的营地在场地中央（帐篷圈 + 篝火），义元在营中央被卫队围着，正沉睡——你带着少量兵力从雨夜侧翼摸进来。砍死义元 → 整个营地炸营，敌军四处溃逃，战斗自动判你胜
- 本能寺：城堡里分阶段逐波——大门→回廊→大殿→本堂，光秀军一波波涌进来，你且战且退，火光越来越旺
- 你感受到的"剧情"（主将在哪、从哪偷袭、什么时候崩溃）全是关卡数据参数——程序化不等于平庸

## 数据格式（§0 字段冻结——权威定义，validator 依据）

> 🔴 **样本 = 09b §四 三份真实预设**（okehazama_raid/frontal/marune）——**第一个使用实例的实样**，本表为通用定义回灌冻结。新增字段 = 回填本表 + 实例更新，validator 按本表检查（铁律：注册表外 token 禁止落 JSON）。

| 字段 | 类型 | 默认值 | 语义 | 示例 |
|---|---|---|---|---|
| `presetId` | string | 必填 | 关卡唯一 ID，事件 `battle` 动作引用 | `okehazama_raid` |
| `archetype` | string | 必填 | **关卡原型**（§0a 注册表）——继承原型默认值（布局函数/装饰主题/状态模板/钩子模板），本预设只写覆盖字段；**新剧本 = 选原型 + 覆盖，零重写** | `night_camp_raid` |
| `nameKey` | string | 必填 | 本地化 key（铁律 13） | `LWN_SCN_okz_battle_raid` |
| `scene` | string[] | 必填 | 场景候选列表，**依次尝试、缺失换下一个**（铁律 5 两轮策略） | `["🔴待07织丰平原战场","scn_plain_01"]` |
| `weather` | object | 晴昼 | rain/fog/time 三项 | `{"rain":true,"fog":true,"time":"night_0230"}` |
| `layout` | object | 必填 | 布局函数调用：`{"fn":"<注册函数>","params":{...}}`，参数表见 §1 | `{"fn":"ring_camp","params":{...}}` |
| `sides` | Side[] | 必填 | 参战方：`{side:"<阵营StringId>", state:"sleeping"/"alert", troops:[{templateId,count}]}` | 见 09b §四 |
| `outskirts` | object | 无 | 🔴 氛围外圈（以少代多）：ringRadius/presence/soundscape/routFx——**不生成可打 agent**，给"数万大军"体感 | `{"ringRadius":60,"presence":["torch_rows","banners"],"soundscape":"camp_noise_far","routFx":[...]}` |
| `spawnChaos` | bool | false | 初始状态变体（夜袭时义元惊起、半数守卫清醒），事件侧传入 | `true` |
| `deco` | string[] | 无 | 场景部件摆放清单（ID ∈ 07 素材表） | `["tent_x6","campfire_x4","torch_x8"]` |
| `atmosphere` | object | 无 | 声景/粒子环境：soundscape/fx | `{"soundscape":"rain_night","fx":["rain","fog"]}` |
| `hook` | object | 无 | 叙事钩子：killLeader（见 §5）/battleChoices（战斗内选项，IF 挂点，effect 写跨事件 Flag） | 见 09b §四 |
| `aftermath` | object | scenario_owned | 战后结算模式——剧情战结算走事件 resolution，**官方结算（俘虏/声望）不自动发生** | `{"mode":"scenario_owned"}` |
| `waves` | WaveBlock[] | 无 | 分阶段波次，**每波独立布设块，语法按 tag 选**，见 §4 | 见 §4 |

> **§0a 关卡原型（archetype）注册表——扩展性的核心机制**：
> - 原型 = 一组默认值（布局函数 + 装饰主题 + 初始状态模板 + 钩子模板 + 场景需求类型），预设引用原型后只写差异字段（默认值继承，类似模板继承，新剧本零重写）
> - 原型注册表（引擎侧只登记"名 → 默认值组"；题材默认值来自数据包素材表，按时代包组织）：
>
> | 原型 | 布局函数 | 装饰主题 | 初始状态 | 钩子模板 | 场景需求 | 首个实例 |
> |---|---|---|---|---|---|---|
> | `night_camp_raid` 夜袭营寨 | ring_camp | 营地 | 守方 sleeping | killLeader→溃散 | 平地/营地 | 桶狭间 raid |
> | `field_battle` 会战 | volley_line | 战场 | 双方 alert | killLeader→溃散 | 平原 | 桶狭间 frontal |
> | `siege_battle` 攻城 | siege_lite | 城防 | 守方 alert | 夺门/溃散 | 城战 | 桶狭间 marune |
> | （后续注册：伏击/水战/守城/突围…） | 注册新函数 | 注册新主题 | — | — | — | 三国/权游剧本等 |
>
> - 🔴 **新剧本的战斗需求 = 注册新原型/新布局函数/新波次类型，不在剧本侧各写布设逻辑**——引擎零改动，数据包加注册（铁律 18 平权精神；题材内容零进入核心，世界观纪律）

## 🔴 技术本质：动态场景生成（2026-08-26 用户裁定——03 是完整的场景生成子系统，不是"改改天气"）

关卡布设 ≠ 参数化微调现成场景。要做的事：**摆建筑/房子/gameentity + 定 agent 初始位置 + 设 agent 动态信息与 AI 归属**——对应引擎两条现成管线（反编译验证 v1.5.1，签名见下）+ 素材盘点 + 布局算法，三条线全是工程：

**管线 A（物件管线）——摆建筑/房子/装饰**：
- `GameEntity.Instantiate(Scene, prefabName, MatrixFrame, callScriptCallbacks)`——按位置+朝向实例化 prefab（内部 = CreateFromPrefabWithInitialFrameAndRestOffset，**支持 restOffset 落地高度修正**——摆帐篷/篝火对齐地面）
- `GameEntity.PrefabExists(name)`——运行时查 prefab 存在性（铁律 5 两轮策略：预设 ID 列表 → 存在性兜底）
- `GameEntity.CreateEmptyDynamic(Scene)`——动态实体（氛围物/无碰撞物，**不参与静态 navmesh，规避寻路冲突**）
- 工程内容：① **prefab 盘点**（原版为主——引擎侧底线；织丰/三国等时代包素材由数据包自备，产出 = 07 素材表按包组织：帐篷/篝火/栅栏/灯笼/攻城器械/火把…每个的 prefab 名/尺寸/碰撞体/地面修正）② 摆放封装（位置 → 地面法线对齐/朝向/缩放/restOffset，铁律 18 共享管线）③ 碰撞与 navmesh 策略（可摆物 vs 氛围物两类）

**管线 B（agent 管线）——生成部队 + AI 归属**：
- `Mission.GetAgentBuildDataToSpawnTroop(origin, isPlayerSide, hasFormation, spawnWithHorse, isReinforcement, formationTroopCount, formationTroopIndex, initialPosition, initialDirection, bannerItem, formationClass)`——🔴 **带初始位置/朝向/编队的部队生成：布局函数的位置清单直接喂进来**
- `Mission.SpawnTroop(...)` / `Mission.SpawnAgent(AgentBuildData)`——完整生成
- 工程内容：阵营 → Team 归属（Mission.Teams）、兵种 → CharacterObject 两轮策略（铁律 5）、装备由 CharacterObject 决定、沉睡冻结（实测项 2 裁决）、主将 Hero 关联（06 角色池）、AI 归属 = Team + FormationClass + 冻结状态

**🔴 A/B 路线决策（场景库盘点先行）**：
- **路线 A（轻）**：场景库（原版 + 各时代包）里有合适的现成场景（营地/战场/城战）→ 参数化微调（天气/刷点/兵力）——省，优先走
- **路线 B（重）**：没有合适场景 → 任意基础场景 + 管线 A 程序化搭景（营寨/列阵/攻城——正是 ring_camp/volley_line 存在的意义）——**03 的完整形态，底线能力**
- 决策方式：分步骤第 1 步场景库盘点，剧本实例需要的场景类型 vs 场景库有无，盘点结论决定 A/B 比例；**搭景不可行时 03 退化为"场景库匹配 + 参数化"路线，archetype 机制仍成立**

## 怎么实现（七个部件）

1. **布局函数注册表（§1）**——纯数学算位置，叙事核心。每个函数 = 一个注册项（参数 → 位置清单），新布局 = 注册一行，不在业务层各写；**注册即用：任何剧本可引用任何已注册函数，禁止剧本侧复制算法**（铁律 18）

| 函数 | 参数 | 输出 | 算法要点 | 首个实例 |
|---|---|---|---|---|
| `ring_camp` | `center`(Hero StringId) / `guardRing`{template,radius,count} / `tentCircle`{radius,count} / `entry`(方向) | 位置清单：主将位/卫队环/帐篷圈/入口 | 主将圆心；卫队圆周均分；帐篷外圈均分；入口 = 指定方向对侧 | 桶狭间 raid |
| `volley_line` | `width`/`ranks` | 两军列阵线 | 宽度均分、排数、对阵间距（数值由实机调） | 桶狭间 frontal |
| `siege_lite` | `gate`/`defenders` | 攻防布设 | 城门 + 守军分布 | 桶狭间 marune |
| （后续注册） | 伏击圈（三面合围+开口）/侧翼阵/城头布防… | — | 三国伏击/守城/突围等按需注册 | — |

2. **生成士兵（§2，管线 B 工程化）**——按位置清单生成双方 agent：`GetAgentBuildDataToSpawnTroop`（位置/朝向/编队直接喂布局函数输出）→ `SpawnTroop`；`templateId` 按铁律 5 两轮策略解析（预设 ID 列表 → predicate 兜底）；阵营 → Team 归属；`state:"sleeping"` = 敌人 AI 冻结、玩家靠近才激活——**冻结实现 = 实测项 2 裁决**（反编译验证后二选一，结论写回本文档）；主将 = `Hero::xxx` 引用（§0 layout.center / hook.killLeader.leader），从角色池取

3. **摆装饰（§3，管线 A 工程化）**——`deco` 清单 = 07 素材表实体（盘点产出：prefab 名/尺寸/碰撞/地面修正），`GameEntity.Instantiate(prefab, frame)` 摆放（restOffset 落地）；**场景部件运行时摆放可用性 = 实测项 1**，不行按降级决策树走（见坑点）；氛围物走 `CreateEmptyDynamic`（不碰 navmesh）

4. **分阶段波次（§4，动态布设）**——🔴 **每波 = 一个独立布设块，语法按 tag 选，不强求统一 schema**（攻城突破 / 室内推进 / 决战的布设参数天然不同）：
   - 数据形状：`waves: [{ "tag": "<波次类型注册表>", "trigger": "<前波全灭/时间/玩家推进位置>", ...各自字段 }]`
   - **波次类型注册表（通用，不写剧本名）**：`breach` 攻城突破 / `interior` 室内推进 / `climax` 决战——**本能寺是第一个实例**；新波次类型 = 注册新 tag，字段随类型独立定义
   - 每 tag 的字段在 10 本能寺写作时填实（🔴 10 是第一个消费者——写 10 时把 tag 字段补全进注册表，不是给 10 定制）
   - 机制：逐波生成（复用 §2 生成管线），前波布设不影响后波

5. **叙事钩子（§5）**——`hook.killLeader`：主将死 → `panicked_rout`（近处敌军四面溃逃 = 引擎原生士气机制 + 外圈氛围溃散 routFx）+ 自动判胜 → 写 `flags.killed`（**跨事件持久 Flag，事件 resolution 读**，flag 名 = 预设内声明）；`battleChoices` = 战斗内选项（IF 挂点，effect 写 Flag）——**溃散实现 = 实测项 3**（"一键溃敌"用哪个指令反编译验证后定）

6. **选场景 + 环境（§6）**——`scene` 候选列表依次尝试（缺失换兜底）；天气/氛围（雨夜/黄昏/火光）数据指定；**氛围层扩展（05 战斗演出联动）**：持续声景 + 火粒子（本能寺大火）为环境层数据指定——供 05 Tableau 名场面战斗演出使用（outskirts 就是给它的素材）

7. **🔴 创作纪律（§7，2026-08-26 用户裁定：03 是创作不是翻译）**——关卡没有 TK5 原文可依，写作受四条约束：
   1. **语境一致（不限题材）**：关卡必须回应剧本语境（时间/天气/兵力对比/叙事钩子）——桶狭间雨夜偷袭 vs 正面迎击是两个不同关卡设计（同例：三国伏击 vs 会战），禁止"通用大战场"敷衍
   2. **注册表约束**：templateId / deco / scene / flag 全部 ∈ 注册表（16 已知 ID 清单 + 07 素材表），禁止自造（铁律 20）
   3. **战果语义明确**：hook.flags 写什么、哪个事件读（09b resolution），validator 检查引用成立
   4. **【玩家看到】注释纪律**：与 09b 同款——预设数据里【玩家看到】注释描述玩家实际所见（08 纪律第 2 条：注释描述的动作必须落 JSON 字段）

## 要注意的坑

- 🔴 **工程量声明（2026-08-26）**：本部件是完整子系统（素材盘点 + 两条管线封装 + 布局算法 + AI 状态控制），不是轻量功能——12 分拆测试矩阵给它完整档位（A5 全流程），禁止按"加个天气参数"的规模排期
- **场景部件运行时摆放是否可用 = 实测项 1**——不行按降级决策树：只放火光氛围（fire fx + 声景），不堆设计
- 🔴 **navmesh 冲突（2026-08-26）**：动态摆的物件若带静态碰撞会挡路——agent 寻路卡死/绕路；策略 = 可摆物（战术位：栅栏/拒马）与氛围物（CreateEmptyDynamic 无碰撞）分两类，摆放前检查场景 navmesh 可用区域
- **prefab 盘点工作量（2026-08-26）**：原版+织丰可摆 prefab 数百个，每个要记 prefab 名/尺寸/碰撞/落地修正——盘点表是 07 素材表的实体，盘点先行（分步骤 1），禁止"边做边查"
- 引擎版本差异：开战斗场景的接口在 1.5.1 是新管道，老版本另一套 → 走版本兼容层（详见 12）
- 沉睡冻结 = 实测项 2：反编译验证两种做法的可行性与副作用（AI 冻结 vs 位置驻留），二选一写回文档
- 溃散实现 = 实测项 3："一键溃敌"具体指令反编译验证后定（引擎士气机制/SetFleeing 类指令），禁止凭名字猜
- 🔴 **波次禁止强造统一 schema**（2026-08-26）：大门/回廊/大殿每波布设参数天然不同——每波独立布设块 + tag 选语法，统一化 = 过度设计
- 🔴 **关卡是创作不是翻译**（2026-08-26）：无 TK5 原文可依 ≠ 自由发挥——模板/素材/flag 全部注册表约束，validator 拦截
- 🔴 **开场演出阶段（intro）= 增强项（2026-08-25 裁定降级）**：桶狭间野战开场主案 = 大地图立绘演绎（05「大地图演出形态」，进战斗前播，本文件无需 intro 阶段）；Mission 内开场演出 = 增强版——待 05 Mission 内播放支持后，预设 JSON 再加 `intro` 阶段（敌我 AI 冻结 → 播对白 → 解除冻结开战），**不在 Phase 1 实施清单内**
- 自定义战斗的战后结算（俘虏/声望）不自动发生——剧情战自己写结算，要官方结算走官方遭遇链路（两条路都测）
