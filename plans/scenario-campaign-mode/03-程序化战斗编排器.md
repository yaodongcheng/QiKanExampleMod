# 03 — 程序化战斗编排器（Procedural Battle Director）

> **Phase 1 骨架 / Phase 2 全量 | 依赖：01, 07(素材表) | 出口：演示战斗（原版场景 + 程序化营寨 + 主将死 Panic 溃散）**
> 对应蓝图：§四（4.1/4.2/4.3/4.4）。代码位置：`Scenario/Battle/`。

## 目标

通用"战斗演出编排"系统：剧本 JSON 声明编排参数 → 代码程序化生成整个 mission（场景/装饰/agent 位置/AI 逻辑/阵营/阶段/叙事钩子）。**新战役 = 写 JSON，零美术工作**（用户裁定：程序化生成但要符合叙事）。

## 分步实施

### Step 1 — 编排参数模型（BattlePreset.cs）
- JSON 反序列化：`sceneIds[]`（两轮策略）/ `atmosphere` / `layout`（type + 参数）/ `forces`（defender/attacker：troopIds/counts/general）/ `initialState`（sleeping/alert）/ `phases[]`（阶段表）/ `narrative`（generalKilled/onEnd）
- 对齐 01 的 ScenarioEffect 参数约定（`battle_mission` 效果的 payload）
- 验收：编排 JSON 反序列化 + 缺字段默认值

### Step 2 — 布局函数库（BattleLayouts.cs）🔴 叙事表达核心
- 纯数学计算：`camp_raid`（环形营寨：center/radius/tents/campfires/guards/generalAtCenter）/ `square`（方阵）/ `column`（队列）/ `outposts`（哨站链）/ `entry_side`（突入方向）
- 输出：位置清单（主将位/卫队位/装饰位/入口位）——`List<(EntityType, Vec3)>`
- 每个布局 = `函数(center, radius, counts) → 位置清单`
- 验收：布局函数单测（console dump 位置清单：主将在圆心、卫队环形、入口在对侧）

### Step 3 — 程序化 Spawn（ProceduralSpawnLogic.cs : MissionLogic）
- 按布局清单 `Mission.SpawnAgent(AgentBuildData(...).InitialPosition(frame))` 放置全部 agent
- 所属阵营（Team 分配，`BattleSideEnum`）+ 主将（`CustomBattleCombatant.General`）
- 兵种经 ActorResolver 两轮解析（07 素材表 troopIds）
- 初始被动（`initialState: sleeping`）：敌人 AI 冻结（行为禁用），玩家接近/触发点激活（参考 `StealthPatrolPointMissionLogic` 思路，程序化实现）
- 验收：演示战斗——原版场景 spawn 位置正确 + 沉睡态敌人不动，玩家接近后激活

### Step 4 — 程序化装饰（ProceduralDecorLogic.cs : MissionLogic）
- `Mission.CreateMissionObjectFromPrefab(prefab, MatrixFrame)` 摆装饰（营帐/篝火/火把粒子/栅栏）
- 素材表 = 07 盘点的 prefab 清单（铁律 5 两轮策略）
- 🔴 prefab 有效性实测（Phase 1 第一件事）：`Mission.CreateMissionObjectFromPrefab("campfire", ...)` 是否生效；不可用 → 降级"只放粒子 + Atmosphere 氛围"
- 验收：营地场景摆出帐篷圈 + 篝火（粒子 + 灯光）

### Step 5 — 分阶段波次（PhaseWaveLogic.cs : MissionLogic）
- 阶段表（JSON）：每阶段敌人位置（布局函数）/数量/兵种 → 程序化生成
- 推进：前阶段清空/触发 → 下阶段生成（叙事阶段推进）；替代 `HideoutPhasedMissionController` 的场景实体依赖（不依赖场景出生点组实体）
- 验收：三阶段波次（如 大门→回廊→大殿）逐波激活

### Step 6 — 叙事钩子（NarrativeBattleLogic.cs : MissionLogic）
- 主将死 → 溃散：`OnAgentRemoved` 检测 `affectedAgent == 敌方 Team.GeneralAgent` → 敌方全员 `CommonAIComponent.Panic()`（官方 `mission.flee_enemies` 同款）→ `BattleEndLogic` 自动判 EnemyRetreated
- 战斗内事件点：`SCN_CHOICE_BRANCH` 挂接（玩家选择 → flag）
- 战果写 flag：`battle_won/lost`（`MissionEnded` 钩子）→ 01 条件求值分流
- 验收：击杀主将 → 敌军全员 Panic → 胜利判定 → flag 写入 → 事件链分流

### Step 7 — 场景选择（BattleScenes.cs）
- 两轮策略：剧本 `sceneIds` → 织丰 `sho_battle_*`/`sho_castle_map_*` → 原版 `mp_battle_map_*`/`scn_*` 兜底
- 参考织丰 `sho_sp_battle_scenes.xml`（地形索引→场景映射 31 条目）的选场数据模型
- mission 打开：`MissionState.OpenNew` + `CustomBattleCombatant` + `CustomBattleMissionSpawnHandler.InitWithSinglePhase`（v1.5.1 管道）；或 `EncounterManager.StartPartyEncounter` 走官方全链（要战俘/声望时）
- 验收：指定场景加载成功；场景缺失 → 兜底场景不崩

### Step 8 — 环境（Atmosphere + 火焰）
- 雨夜：`AtmosphereOnCampaign` = `TOD_photo_02_30_rainy_night` 预设（凌晨 2:30 大雨浓雾）
- 火焰：`ParticleSystem.CreateParticleSystemAttachedToEntity("fire_big"...)` + `AmbientColor` 橙红 + 夜 atmosphere；`FireSpreadLogic` 按 MissionTime 递增 `SetRuntimeEmissionRateMultiplier` + 火区可选伤害（🔴 引擎无燃烧蔓延机制，氛围级）
- 验收：演示战斗雨夜可见；本能寺大火氛围（Phase 3）

## 出口验证（Phase 1）

1. 演示战斗（原版场景）：程序化营寨（帐篷圈 + 篝火粒子 + 主将中央 + 卫队环形）→ 沉睡初始态 → 击杀主将 → 敌军 Panic 溃散 → 胜利 → flag 写入
2. 雨夜 Atmosphere 生效；prefab 有效性实测结论记录
3. 无 LLM 全流程可玩（对话走预写树/冒泡直出）

## 风险

- **CreateMissionObjectFromPrefab 可用性**（Phase 1 第一实测项）：不可用 → 装饰降级"粒子 + 氛围"
- v1.5.1 mission 管道（MissionState.OpenNew 体系）`#if MB2_GE_150` 隔离；1.4.x 旧体系另核
- CustomBattleCombatant 的战后结算（俘虏/声望）——剧情战走自写 MissionEnded，官方全链路径另测
- 沉睡初始态的 AI 冻结实现细节（IsAIEnabled vs 行为禁用）实测
