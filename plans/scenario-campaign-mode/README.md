## 🔴 剧本内容写作纪律（2026-08-25 踩坑教训：自造 tone/look_away 字段与动作名）

> 任何剧本文件/演绎剧本/事件 JSON 的写作与审查，先过这七条——注册表外的 token 一律禁止落 JSON。

1. **一切 token 先查注册表再写**：域/属性/谓词/动作 ∈ 16 注册表；演绎剧本指令（actor_action/face/camera/choice/async 等）∈ 05；`act` 值 ∈ 05 动作库注册表（`act → animId` 数据包定义，编译期校验 MBActionSet 枚举）；sceneId/playbackId/textKey ∈ 对应清单。**注册表外 = 禁止落 JSON**（validator 会阻断，但写的时候就该查，不是等 validator）
2. **注释描述的可执行动作必须落 JSON 字段**（`actor_action` 独立指令 / 对话节点 `action` / `face` 朝向 / `camera` 镜头），且字段值必须注册过；注释只留情绪/语气/动机提示——【玩家看到】注释描述了动作而 JSON 没有对应字段 = 欠账
3. **禁止无机制消费方的字段**（如 tone——骑砍2 无角色语音）
4. **写剧本前先看 16 注册表 + 05 动作能力模型 + 本文件 DSL 要点**；不确定的动作 → 标注"动作库待注册"或注释化，不假装能执行
5. **台词来源三态（2026-08-25 强化——用户裁定：默认原汁原味翻译，零发挥）**：🔴 **能翻译就翻译，别自己发挥**——台词是历史的（太阁5 原文），不是作者的（文笔）；【原文】= 太阁5 原句（可回查 `Knowledge/太阁事件包/TK5AllEvents_merged.txt`——**单一合并文件，事件号带文件名前缀**，搜 `事件:事件EFF0C300_159{` 定位，编号 = `文件名_事件ID`）；【原文改编】= 仅允许称谓/报告者/场景的最小适配；【演绎补写】= **实在没办法才用**（如太阁5 的 AVG 表现部分骑砍2 确实表现不了），且必须标注；🔴 **禁止无标注的编造台词，禁止为了"剧情丰满"加戏**
6. 🔴 **旁白/宣告的呈现载体（2026-08-25）**：史官腔旁白、世界宣告 = `inquiry` 弹窗（01 步骤，原版 quest 通知样式）——**禁止改编成角色台词**（角色说上帝视角的话 = 叙事纪律违规；旁白→角色的"原文改编"只允许人话转述，不允许史官腔整段搬）
7. 🔴 **TK5 原文行完整性铁律（2026-08-26 用户裁定——09b 事件 0 重写教训）**：构造任何太阁事件 JSON（事件 JSON + 演绎剧本 JSON），源事件（`TK5AllEvents_merged.txt` 按 `文件名_事件ID` 定位）的**每一行都必须存在对应，不得违背**：
   - **执行（演出行）**：源事件每一句演出文本 = 演绎剧本 `lines[]` 中一行，该行注释直接写 TK5 原文（`// T#【说话人】"原文"`，T# = 引用锚点）——**禁止省略、转述、合并多行、丢弃任何一句**（性别变体并排写在同一注释）；确实无法落地的行（机制行/BGM 等）也要在 JSON 注释中标明由哪个步骤/系统承接，标 `🔴待XX` 占位可以，**删行不行**
   - **触发/条件**：源事件头部的触发时机与条件，写在事件 JSON `trigger` 字段（∈ 01/16 注册表）与 `condition` 上方注释块（原文 + mod 落点说明），逐条对应
   - **表现注记**（性别变体/镜头/动作/机位 gate）以括号跟在原文注释后，不另起【玩家看到】转述——"原文 → 表现"同屏对照
