## 这一步做什么（一句话）

织丰 mod 提供日本战国的一切（地图、40 势力、848 城、日式兵种装备、上百日式场景），且它的 DLL 与 1.5.1 **静态兼容**（反编译实测）。所以：**织丰作为前置依赖模块正常加载，我们的剧本层嵌入织丰战役**——玩家先装织丰 + 我们的 mod，主菜单多一个"历史剧本战役"入口，进战国世界跑剧本引擎（事件/时间轴/演出/主命）。织丰的世界与玩法保持原样，剧本引擎附加在其上。

## 玩家视角

- 玩家装两个 mod：织丰（前置依赖）+ 我们（剧本层）
- 主菜单多一个"历史剧本战役"入口（织丰原入口保留，两个入口共存）
- 选剧本进世界：40 个日本势力、848 座城、日式兵种装备、日式场景全在，织丰的港口/寺庙/决斗等玩法也在
- 年代不锁死 1568（织丰原版锁死 1568 开局）——由剧本决定（桶狭间 1560 / 本能寺 1582）

## 怎么实现

### 方案 A（推荐）：依赖织丰 DLL，嵌入剧本层

**实现载体：`ShokuhoTaikouExpansionPack` 补充包**（独立 mod，`Modules/` 下与 LivingWorldNpcs 平级；同一 VSCode/Claude Code 工作区，**独立 git 仓库、独立打包**；发布依赖 = 织丰 + LivingWorldNpcs + StartAsAnyone + 本包。骨架已建：SubModule.xml / csproj / 空壳 MySubModule，审核通过前禁止实施逻辑）。

四个部件：

1. **真机可用性验证（前置关卡）**——织丰完整解压进 1.5.1 启用跑一次：①DLL 能否加载（主菜单出现织丰入口）②数据文件是否正常（进织丰新档看世界/城/人物）③存档是否正常。**这一关不过 → 直接切方案 B**
2. **兼容层**（补充包，解决"dependency conflict"报错）——反编译实锤的加载机制：
   - 报错根因：游戏 `AssemblyLoader.LoadFrom` 在 .NET Core 分支遍历织丰引用，用**相对文件名**从游戏 bin 找第三方 DLL（0Harmony 2.2.2 / ButterLib / UIExtenderEx / MCMv5 / Serilog / ColorMinePortable 等 8 个），而它们都在各模块 bin → `LoadedWithErrors` → 弹窗（文案统一为"dependency conflict"，与版本无关）
   - 解法（两步，都在织丰加载前完成）：①补充包 `SubModule.xml` 声明 `<ModulesToLoadAfterThis><Module Id="Shokuho"/></ModulesToLoadAfterThis>`（游戏内拓扑排序把我们排在织丰之前；启动器顺序用 `<DependedModuleMetadata order="LoadBeforeThis"/>`）②`OnSubModuleLoad` 里补丁 `AssemblyLoader.LoadFrom`（相对名 → 织丰 bin / 各模块 bin 兜底）+ 绝对路径预加载织丰 bin 的 0Harmony 2.2.2（强名版本精确匹配，供引用解析）
   - 🔴 兼容层 DLL **禁止引用 LivingWorldNpcs.dll**（AssemblyRef 存在即触发同样的引用循环报错；剧本层如需引用 LWN，按实测拆两个 DLL）
3. **共存性验证**——织丰行为与我们的引擎同场跑：织丰的士兵晋升/外交行为/扩张主义 AI 驱动世界自然演化，我们的剧本引擎按剧本纠正历史走向（02 战略 AI 纠正器管这个）；织丰 138 个补丁是否改写核心结算（战斗/围城/数据加载）——逐个核对冲突面，有冲突的记入 02/14 的兼容处理
4. **嵌入层**（补充包的剧本层，审核通过后实施）——
   - 剧本入口：`AddInitialStateOption` 注册"历史剧本战役"（织丰的 `ClearStateOptions` 在它的 OnSubModuleLoad 执行，我们加载在它之后，入口共存）
   - 战役启动：复用织丰战役容器（`ShokuhoCampaignGameManager`/`ShokuhoCampaign`，数据加载开关天然匹配织丰数据零改动）；剧本初始化时**覆盖织丰的时间锁**（反射写 `CampaignStartTime` 为剧本年代 1560/1582——织丰自己也是这么写的，同一手法）
   - 剧本注入：`OnGameStart`/`OnCampaignStart` 阶段向 campaign 注入剧本行为（时间轴/事件调度/演出/主命），剧本引擎的全部机制挂在织丰战役之上
   - 角色创建：**剧本入口走我们自己的流程**（06 的 ASO/StartAsAnyone，扮演历史人物），不进织丰的角色创建 UI
5. **素材表落地 + 接线验证**——织丰场景/部件盘点产出素材表（供 03 编排器）；"尾张城归织田家"等剧本条件能命中织丰对象

**方案 A 明确不做**：不打包织丰任何资源（场景/模型/贴图/数据文件零拷贝），织丰的一切仍由织丰 mod 提供。

### 方案 B（回退）：克隆注册层（原 07 计划）

织丰 DLL 或数据在 1.5.1 真机不可用时启用：不加载织丰 DLL，只加载织丰的数据文件，我们自己写壳注册"战国战役"入口（数据加载开关匹配织丰战役名，零改动加载数据；规则只挑与战斗/剧本相关的；明确放弃抽卡/海战/港口/寺庙/决斗/内嵌外交）。
**方案 B 的资源归属纪律**：数据全部标注来源（织丰 mod + 作者），随包附织丰许可说明；发布前与用户确认授权方式。**方案 B 是回退不是默认**。

### 版本验证矩阵（"只支持 1.2.12"的说法不成立）

| 原说法（旧 07 裁定） | 实测结果 |
|---|---|
| 引用了 1.5.1 已删除的程序集 | ❌ 45 个引用程序集**全部存在**（SandBox/StoryMode/LinQuick/PSAI 均在） |
| 一批接口签名变了 | ❌ MBSubModuleBase 全部 9 个 override 点签名一致；Module 状态选项三件套、`ManagedParameters.Initialize(string)`、`InitialStateOption` 构造、`MBObjectManager.LoadXML`（含织丰补丁 4 参匹配）、`GetMergedXmlForManaged`、`MapEventParty.OnTroopKilled`、`SandBoxManager.SandBoxMissionManager`、`CampaignData.CampaignStartTime`、`SaveableField/Property/TypeDefiner` **全部存活且兼容** |
| 1.3.0 迁移 .NET 6 导致不兼容 | ❌ **1.2.12 的 runtimeconfig 也是 `tfm: net6.0`**——两版本同一套 .NET 6 运行时（mono 目录是打包残留）；织丰 .NET Framework 4.8 编译，mscorlib 引用被 .NET Core 兼容转发，1.2.12 能跑即证明 |
| 第三方库版本冲突 | ❌ 1.2.12 与 1.5.1 环境 ButterLib 2.10.4 / UIExtenderEx 2.13.2 / MCM 5.11.4 / 0Harmony 2.4.2 **完全相同**，织丰引用的旧版本在 1.2.12 已通过 |

**结论**：织丰"只支持 1.2.12"更可能是作者声明（SubModule.xml 依赖版本面），而非技术硬限。**静态层面与 1.5.1 完全兼容——这是方案 A 的前提**。

### 行为注册机制（方案 A 可行性的关键反编译结论）

- 织丰的 `AddBehaviors`（19 个行为：士兵晋升/征募/抽卡/寺庙/决斗/书籍/Diplomacy 全家桶等）在 `OnGameLoaded`/`OnCampaignStart` **无条件执行，不区分 GameType**——任何 Campaign 启动都会带上织丰全部行为
- 织丰的 `OnSubModuleLoad` 无条件清原版入口 + 锁时间 + PatchAll——这些只在织丰 DLL 被加载时发生，我们无法用配置关闭，但可以"共存"（后注册入口 + 启动时覆盖时间）
- 织丰的 `OnGameStart` 只对 `ShokuhoCampaign`（它的 GameType）做定制（注册 Port/DuelLocation/Temple 对象）——复用织丰战役容器时这些自动就位；若走自己的 GameManager 需要手动补注册

### 待真机验证（步骤 1/2 的内容）

- 🔴 织丰 DLL 在 1.5.1 真机加载（静态兼容 ≠ 运行时一定过，深层 API/运行时细节未覆盖）
- 🔴 织丰数据文件在 1.5.1 正常加载（XML/场景/文化数据跨版本稳定是预期，未验证不算数）
- 🔴 138 补丁对核心结算的改写是否影响剧本引擎（战斗编排/事件结算）
- 🔴 织丰行为 × 剧本引擎并存（晋升/外交/扩张主义驱动 vs 历史走向约束）

## 要注意的坑（全工程最高风险）

- 织丰 DLL/数据在 1.5.1 的真机兼容性是**方案 A 的生死前提**，步骤 1 必须先做；不过 → 切方案 B（此时克隆注册层 + 资源归属纪律走方案 B 段）
- 织丰世界数据是 **1568 快照**（角色年龄/势力版图按 1568 摆）——1560 桶狭间开局时世界状态与历史不符，由 06 时代重置（表驱动选择性激活：活着/未出生/已死三态）处理，与谁加载数据无关
- 织丰时间锁与剧本年代冲突：剧本启动时覆盖 `CampaignStartTime`（织丰同款反射手法），覆盖后织丰行为按新时间运行，**每日结算/出生死亡等依赖时间的行为要回归测试**
- 剧本入口走我们自己的角色创建（06 的 ASO/StartAsAnyone），**不进织丰角色创建 UI**——否则扮演历史人物被织丰的自定义捏人流程干扰
- 织丰存档与我们剧本状态共存：织丰 SaveableField/TypeDefiner 会参与我们的存档，新增剧本存档字段注意 ID 冲突（存读档测试）
- 回退路线（方案 B）：织丰数据标注来源 + 许可说明 + 用户确认授权；代价是官方开局选择器不可用，用设置菜单代替
