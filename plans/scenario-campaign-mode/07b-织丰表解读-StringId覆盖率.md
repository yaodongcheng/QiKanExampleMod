## 一、结论

**可以开工，这张表够用。**

- 太阁全量事件里点名的对象共 **923 个**，织丰表能查到 **758 个 → 82.1%**。
- 查不到的 165 个**基本不是「表缺数据」**，而是四类可预期情况：太阁独有角色（要发占位）、组织（在另一张表里）、写法差异（要配别名）、解析伪影（数字乱码）。
- **桶狭间剧本已经 100% 落地**：22 个事件全部翻译通过，全场只剩 6 个占位据点，且每个都带了「事件该在地图哪一带发生」的锚点。

**唯一需要人工补的东西**：一张「太阁地方名 ↔ 织丰文化区」的对照表（9 行），和一列「组织名 → StringId」（31 行）。两件都是**填表**，不是找数据。

## 四、三个最容易看错的地方

### 4.1 `IsShokuho = 0` 不是缺数据，是「这条没启用」

- Kingdom：`IsShokuho=1` 的 39 条，模块 XML 里**全部存在**；`=0` 的 96 条，XML 里**一条都没有**。
- Clan：`=1` 的 221 条全有，`=0` 的 384 条全无。
- **所以**：此前记的「95 个势力在 XML 里查不到 = 数据缺口」是误读。那 96 条是织丰做好但没在本版本启用的预备数据，要用就把开关打开，不用从头造。

### 4.2 `MatchSettlement` 和 `NearSettlement` 是两回事，混用会出事

| 列 | 条数 | 含义 | 怎么用 |
|---|---:|---|---|
| MatchSettlement | 99 | 骑砍地图上**就是这座城** | 直接用它的 StringId |
| NearSettlement | 81 | 骑砍地图上**没有这座城**，只给了最近的一座 | 发 `tk5_city_NNN` 占位 + 把 near 记成锚点 |

**混用的后果**：太阁「鸣海城」的 near 是「那古野」——这是两座不同的城。当成同一个用，桶狭间的鸣海城攻防会打到那古野去。
**例外**：near 其实就是同城异写（清洲/清须、河越/川越、石山本愿寺/大坂御坊），这些走白名单直接用真 ID。

### 4.3 三个会认错人的 ID

| 你以为 | 实际是 | 正确的 ID |
|---|---|---|
| `lord_1_saito_dosan` = 斋藤道三 | **太原雪斋** | 斋藤道三 = `lord_1_saitoo_doosan` |
| 德川家康在织田家 | 1560 年是**今川家陪臣** | `lord_1_tokugawa` / `clan_tokugawa_1`，Kingdom_1560 = 今川 |
| 丰臣秀吉 | 1560 年叫**木下藤吉郎** | 按年份列取名，别用后世名查 |

**另外**：20 个 ID 带非 ASCII 字符（Hero 4 个带连字符 `lord_1_minami-hime`、Clan 16 个带长音符 `clan_saitō_1`）。长音符在基本平面内，不触发铁律 14（禁 emoji），生成器自检已豁免，不用处理。

## 五、真正要补的东西（4 项，都是填表不是找数据）

| # | 缺什么 | 现状 | 谁来补 | 工作量 |
|---|---|---|---|---|
| 1 | **地方名对照表** | 太阁用现代地方名（近畿/关东/中国/四国/九州/东北/甲信/东海/北陆），织丰 Culture 表用古代八道（畿内/关东/山阳/南海/西海/奥羽/东山/东海/北陆）。**两边都有数据，只是叫法不同**，直接对上的只有 3 个 | 人工写 9 行对照 | 十分钟 |
| 2 | **组织 StringId** | 31 个组织（忍者众/商家/海贼众）在 Kingdom 表里没有条目 → 现在发哈希占位。但 **ForceTaikou 表 204 条 100% 覆盖了这 31 个，还带了类型分类**，只是没有 StringId 这一列 | 给 ForceTaikou 补一列 ID | 一小时 |
| 3 | **8 座无锚点的城** | 既没 Match 也没 Near，占位了但不知道摆在地图哪 | 07 数据包连位置一起定 | 需要查史料 |
| 4 | **太阁独有角色** | 服部小平太、毛利新介、簗田政纲（桶狭间关键配角）繁简双查都不在表里，现走 `TK5_ONLY_HERO` 占位 | 07 数据包补 Hero XML | 每人一条 XML |

**不用补的**：卡/流派/物品/官位官职——这几族在太阁里是独立系统，织丰表本就不管，按 16b 裁定走 T3 外置仓自己存，不需要对照表。

## 六、两条旧结论作废

写在别处的这两条说法被数据推翻，已同步更正到 `08b` §九：

1. ~~「织丰表完全没有分区/令制国数据」~~ → **有**。CityTaikou 的 `Area` 列有 62 个分区，Culture 表有 9 个文化大区。缺的只是对照关系（§五-1），不是数据。
2. ~~「37 个组织是数据缺口」~~ → **不是**。ForceTaikou 表 100% 覆盖，缺的只是 StringId 这一列（§五-2）。

另有一条**证据不成立、不采信**：此前记录的「xlsx 的 Clan.Kingdom 与活 XML 的 `super_faction` 在 154 个家族上不一致」——实扫 `Shokuho/ModuleData/spclans/*.xml`，带 `super_faction` 属性的家族**为 0 个**，这个属性根本不在活 XML 里，原结论无法复现。
