## 〇、🔴 先解决：表 ID ↔ Taikou 模块 ID 的对齐

| | 织田信长 |

  （当前只有 3 个英雄 + 2 个据点，**分钟级**；拖到 T4 再改要动几百处）

## 四、三个最容易看错的地方

### 4.1 `IsShokuho` 列 = 织丰时代的遗留（Taikou 下无意义）

- 原义：`IsShokuho=1` 表示"这条在织丰模块里已启用"；`=0` 是织丰做好但没启用的预备数据
  （Kingdom `=1` 39 条 / `=0` 96 条；Clan `=1` 221 条 / `=0` 384 条）。
- 🔴 **Taikou 下这一列不再有判别力**：Taikou 是我们自己的包，**没有"启用开关"这回事**——
  哪些对象在世界里，由该时代的差异段（`spkingdoms_<年份>.xml` 等）决定。
- **所以**：实施时**不看该列**，看**该时代的段里有没有这条**。列本身保留（表的原始数据，别删）。

### 4.2 `MatchSettlement` 和 `NearSettlement` 是两回事，混用会出事

| 列 | 条数 | 含义 | 怎么用 |
|---|---:|---|---|
| MatchSettlement | 99 | 骑砍地图上**就是这座城** | 直接用它的 StringId |
| NearSettlement | 81 | 骑砍地图上**没有这座城**，只给了最近的一座 | 发 `tk5_city_NNN` 占位 + 把 near 记成锚点 |

**混用的后果**：太阁「鸣海城」的 near 是「那古野」——这是两座不同的城。当成同一个用，桶狭间的鸣海城攻防会打到那古野去。
**例外**：near 其实就是同城异写（清洲/清须、河越/川越、石山本愿寺/大坂御坊），这些走白名单直接用真 ID。

### 4.3 三个会认错人的 ID

| 你以为 | 实际是 | 正确的 ID |
|---|---|---|
| `lord_1_saito_dosan` = 斋藤道三 | **太原雪斋** | 斋藤道三 = `lord_1_saitoo_doosan` |
| 德川家康在织田家 | 1560 年是**今川家陪臣** | `lord_1_tokugawa` / `clan_tokugawa_1`，Kingdom_1560 = 今川 |
| 丰臣秀吉 | 1560 年叫**木下藤吉郎** | 按年份列取名，别用后世名查 |

**另外**：20 个 ID 带非 ASCII 字符（Hero 4 个带连字符 `lord_1_minami-hime`、Clan 16 个带长音符 `clan_saitō_1`）。长音符在基本平面内，不触发铁律 14（禁 emoji），生成器自检已豁免，不用处理。

## 六、两条旧结论作废

写在别处的这两条说法被数据推翻，已同步更正到 `08b` §九：

1. ~~「织丰表完全没有分区/令制国数据」~~ → **有**。CityTaikou 的 `Area` 列有 62 个分区，Culture 表有 9 个文化大区。缺的只是对照关系（§五-1），不是数据。
2. ~~「37 个组织是数据缺口」~~ → **不是**。ForceTaikou 表 100% 覆盖，缺的只是 StringId 这一列（§五-2）。

另有一条**证据不成立、不采信**：此前记录的「xlsx 的 Clan.Kingdom 与活 XML 的 `super_faction` 在 154 个家族上不一致」——当时实扫织丰 `spclans/*.xml`，带 `super_faction` 属性的家族**为 0 个**，这个属性根本不在那份 XML 里，原结论无法复现。（🔴 2026-09-11 注：**Taikou 的 spclans 是带 `super_faction` 的**，本结论不适用于 Taikou——实施时以 Taikou 为准重核。）
