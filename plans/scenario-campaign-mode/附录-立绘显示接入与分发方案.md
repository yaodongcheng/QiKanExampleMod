### 方案 A：内容包 tpac（ShokuhoTaikouExpansionPack）

产出（全在内容包内）：

```
AssetPackages/lwnprof_bustup.tpac      # 1292 张 512×768 bustup（DXT5）
AssetPackages/lwnprof_mini.tpac        # 1292 张 256×256 minihead
AssetPackages/lwnprof_emobustup.tpac   # 68 张（17 卡 × 4 情绪）
AssetPackages/lwnprof_emomini.tpac     # 68 张
GUI/LWProfilesSpriteData.xml           # 4 category + ~2720 SpritePart + ~2720 GenericSprite
ModuleData/AssetRegistry/ProfileStages.csv    # 运行时权威清单：StringId,stage,tkid,bustupSprite,miniheadSprite
ModuleData/AssetRegistry/ProfileEmotion.csv   # tkid,emotion,bustupSprite,miniheadSprite
```

- 资源名：texture = `{Category}_{N}`（N 1-based）；sprite = `lwnprof_bustup_{tkid}` / `lwnprof_mini_{tkid}` / `lwnprof_emobustup_{tkid}_{emo}` / `lwnprof_emomini_{tkid}_{emo}`。
- **4 个 category 均不加 `<AlwaysLoad/>`**（防启动全量预载 600MB+）。
- 体积：原始 DXT5 ≈ 623MB（bustup 384KB×1360 + mini 64KB×1360）；tpac 数据段带 LZ4HC 压缩，预计落盘 350-450MB。

工具改动（tools/face-pipeline/tpactool）：

- `inspect` 命令：打印 tpac 内 texture 全字段 → 对织丰 pack6 提取**逐字段模板常量表**（Flags=[dont_degrade,dont_delay_loading]、SystemFlags=[has_alpha]、`Source=""` 等）。
- `makepack --manifest <json> --template <packdir> --out <dir>`：PNG（BigGustave）→ 内嵌 `Bc3Encoder.cs`（stb_dxt 移植 ~300 行；**4 色模式**禁 3 色+黑透掩——防半透明硬边缘黑边；字节序 = BC4 alpha 块 8B 在前 + 色块 8B 在后；无 NuGet 依赖）→ 组装 asset（模板字段 + 确定性 GUID = 名字 hash，段 OwnerGuid 同值）→ 逐 category Save。
- 拆 4 包而非单包（Save 全量重写，拆包便于重建/定位；织丰 pack0-6 先例）。

生成器（ArtSource/scripts/ 新增 `build_profile_pack.py`，生成物纪律：改脚本重跑，禁手改产物）：

1. 读 ProfileImage/ + emotion/ 图、ProfileImage.csv（tkid↔StringId↔路径）。
2. 读 TaikouHero.csv「立绘阶段」列 JSON（stage/tkid/emotion/ref）→ 阶段权威数据（零新增人工表）。
3. 产出运行时清单（ModuleData/AssetRegistry/ 两 csv）+ manifest.json（tkid→sheet index、sprite 名、尺寸、路径）。
4. 产出 GUI/LWProfilesSpriteData.xml（零注释、全子元素、每卡必须 SpriteSheetSize、GenericSprite——规则表复用 plans/custom-png-import-guide.md）。
5. 断言：tkid↔SheetID 唯一、emo∈{happy,angry,sad,surprised}、emotion 目录 68 vs 69 不一致即报错、引用文件全存在。Knowledge 旧备份原位不动。
6. **去重规则（用户裁定）**：StringId 不去重——多阶段并存，每角色每阶段一行（无阶段者单行、stage 空串）。

### 方案 B：LWN 通用 Sprite 流程（新代码 2 文件，入主工程 ExampleModVS/ExampleMod/ExampleMod/）

`GUI/SpriteAssetsManager.cs`（内存管理核心）：

- `Sprite GetSpriteOrNull(name)`（静态字典直查，零分配）/ `bool EnsureLoaded(Sprite)`（按 part.SheetID PartialLoadAtIndex；category 首次 InitializePartialLoad）/ `Sprite GetOrLoad(name)`（失败 → null + `[SpriteAssets]` 日志）。
- **LRU**：按**字节**分桶（bustup 桶 ~12 张 / minihead 桶 ~64 张——聊天列表 20-40 行窗口，容量太小会抖）；驱逐 = PartialUnloadAtIndex；**驱逐延迟 2 帧** + 只逐当前帧未被引用条目（防"渲染半截没了"黑块）。
- **生命周期防御**：category 引用每次现取（`UIResourceManager.GetSpriteCategory`，不缓存——兼容调试模式热重载 Reload 换对象）；Ensure 前查 `IsLoaded && SpriteSheets.Count >= sheetID`，不满足（跨场景/读档引擎卸载后）→ 重新 InitializePartialLoad；全 try/catch → null 降级（铁律 1）。
- 版本兼容：`#if MB2_GE_140` 走 partial API；老版本回退 = 整 category Load()/Unload()（功能可用，粒度粗）。**实施第一步**：反编译 Modules/1.4.6DLL、1.3.15DLL、1.2.12DLL 的 SpriteCategory 确认签名区间。

`Data/PortraitRegistry.cs`（内容包清单读取器，纯通用零文化内容）：

- 契约：扫 `ModuleHelper.GetModules()` 所有模块 `ModuleData/AssetRegistry/*.csv`（列名大小写敏感：ProfileStages.csv → StringId,stage,tkid,bustupSprite,miniheadSprite；ProfileEmotion.csv → tkid,emotion,bustupSprite,miniheadSprite）。解析全防御，文件缺失 → 空目录 + debug 日志（铁律 1）。
- API：`GetStagePortraits(stringId) → IReadOnlyList<StagePortrait>{Stage,Tkid,BustupSpriteName,MiniheadSpriteName}`（stage 升序）/ `GetEmotionSpriteName(tkid, emotion, isBustup)`。
- 懒加载（首次查询才扫模块+读 CSV；静态构造器禁碰引擎 API）；CSV 用 `Microsoft.VisualBasic.FileIO.TextFieldParser`（现有 CsvLoader 是两行表头格式不能复用；TextFieldParser 处理 BOM+CRLF）。
- **无任何日本战国/织丰/太阁字串**（铁律 3：阶段名如"若君"在数据文件，不进代码/注释/日志）。

接入挂点（IM 头像位 / 多 agent 面板）**本阶段不做**——交付以上 API，接入时形态 = `icon.Sprite = SpriteAssetsManager.GetOrLoad(...)`（先例 GUI/SecretLetterButtonInjector.cs:275）。

## 🔴 算法参数定版（2026-08-30 v18——用户验收；改动需用户点头）

| 环节 | 参数 | 依据 |
|---|---|---|
| 抠图模型 | **u2net**（`alpha_matting=False`，无 matting） | isnet 丢部件（深甲×深背景，987/16 实证缺臂）→ 对比 u2net/birefnet：u2net 完整率最高、边缘干净、0.2-0.9s/张；birefnet 有 halo + 24s/张 |
| 立绘布局 | place()：紧贴 bbox 裁切 → 512×768 等比、水平居中、贴底 | P5 布局（2026-08-28 用户裁定，勿动） |
| minihead 尺寸锚 | **mediapipe FaceMesh 头长（额顶点 10 → 下巴 152 距离）× 2.2** | 头长不受表情影响（瞪眼/低头只动眼眉嘴）：1154 四情绪波动 3.8% vs 眼距 25-50%——表情无关的稳定尺度；脸占画面 ≈ 45% |
| minihead 水平锚 | **左右眼中心 x = 画面 52%**（窗口左右平移，头部尺寸不变） | 2026-08-30 用户裁定（左右眼坐标是最终判定量；52% 为脸朝向侧留白微调） |
| minihead 垂直锚 | 眼基线（双眼中点 y） | 稳定（眼基线一致） |
| 锚链层级 | 0 = FaceMesh 眼锚（头长+眼心52%）→ 1 = blaze FaceDetection（mesh 失败，side=脸框×2.1）→ 2 = alpha 皮肤带（HSV×YCrCb×最大连通域，side=带高×2.4）→ 3 = 上中区启发（必审） | 层 1/2 修 14 sad（mesh/cv2 双失败但 blaze 命中 0.72）；层 2 三闸防金橙盔甲混入 |

## 四、经验复盘（踩坑记录——新会话别重踩）

1. **抠图模型选型要有对比实验**：isnet 丢部件（深甲×深背景，987/16 实证缺臂）；matting 产雾（79 张灰雾）；plain 对 dark 弱；**u2net 胜出**（完整+干净+快）。三条对比都要跑，别凭感觉。
2. **minihead 不要从抠图标裁**（用户裁定：用原图）——抠图后人物贴底居中、上部全是透明，裁出来必是大空白 + 脸小。
3. **锚基准要"表情无关"**：眼距被瞪眼/俯仰撑大（波动 25-50%）→ 头长（3.8-15%）；**水平最终判据 = 左右眼 x**（用户指定口径，机器可算，别自造"中部感"）。
4. **层级变量赋值 bug**：cv2/启发分支不设 level → 全 0 假信号 → meta 不可信。**审计信号先自测真伪**（拿已知问题图对账）。
5. **皮肤掩膜域要三闸**（HSV × YCrCb × 最大连通域）：单闸把金橙盔甲/亮片当皮肤 → 框爆/拖飞。
6. **窗口/候选窗大小 & 位移门**：太宽（±0.9side）会把肩颈手框进来，最大连通块变肩膀 → 拖飞；收窄 + 位移门（±8%）+ 裁剪 clamp。
7. **机器"level0"不等于合格**：14 sad 出现过 mesh 假阳性；face_ratio 域对惊讶脸失效（12%/2% 误报）。**机器数字是佐证，视觉/用户是终裁**。
8. **读图模型的不可靠性（我，2026-08-30 教训）**：多轮把"脸偏左"读成"偏右"、方向/占比描述错误、还会"顺着用户说"。**结论：我的读图结论不作数——判定以机器数值 + 用户肉眼为准**（此条已写入 CLAUDE.md 计划纪律？→ 未，可考虑）。⚠️ 用户裁定：必须逐张读图（不缩略、不抽样）；我照做，但判语仅作参考。
9. **生成物分寸**：TaikouHero/ProfileImage.csv = 生成物（脚本禁手改，改脚本重跑）；内容表（persona）用户裁定方案 B = 放进主表"手写区"（git 已提交作安全网）。
10. **"搬运"语义错误**：把「生成 → 搬运进补充包」做成"复制留底"（Portraits/ 603MB 副本）——用户裁定：**图就放 ProfileImage 原位，发布 = 打包 tpac**。计划文档误导性描述必须及时更正（用户点名"这不是我想要的"）。
