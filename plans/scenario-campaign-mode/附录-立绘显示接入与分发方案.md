## 一、一句话结论

**显示接入 = TPAC 主路（引擎原生资源包），PNG+Harmony 回退链路降级为兜底（探针失败才走，并为未来网络加载预留）。** 生产端不变：两条路共用我们已产出的 PNG 源图，谁走通都不浪费。

先行一步的必做项只有一个：**UI 纹理 TPAC 探针包（1 张立绘 + 1 张头像，半天封顶）**——它是 TPAC 路线唯一的未验证点，探针结果决定主路走向。

## 二、决策记录（2026-08-29 用户裁定，勿走回头路）

| # | 裁定 | 理由（一句） |
|---|---|---|
| 1 | **头像提前分开存，不做运行时裁脸** | 运行时 C# 侧无 mediapipe，定位精确度回退；且出包前人人可审（64 张/板拼图）。代价 ≈ +100MB 包体，可接受 |
| 2 | **TPAC 转正为第一候选** | 主要场景 = 本地已备好的图（用户已澄清网络非主场景）；TPAC 在性能（显存 4 倍差距）、官方按需加载、零补丁依赖、alpha 无争议上系统性占优 |
| 3 | **PNG 链路 = 兜底 + 网络预埋** | 唯一独有收益 = URL→字节→纹理的网络加载与单图热更（非主场景，保留为未来选项）；代价 = LWN 核心要写补丁 + alpha 未验证（T4） |
| 4 | **裁切规则定稿（见立绘流水线附录「头像提取规则」小节）** | 信长 6 档对比实测：顶部以发髻/盔帽↔天空相切处为顶（+3% 天空隙）、下颚 +0.18 脸框高、脸中心横移 6%（左多右少） |

## 三、TPAC 主路接入步骤

### 3.1 前置：UI 纹理探针包（必做，半天封顶）

| 项 | 内容 |
|---|---|
| 做什么 | 2 张图：512×768 立绘（信长已有）+ 256×256 头像 → texconv 转 BC3 DDS → tpac 打包 → 游戏内 SpriteCategory 命中/显示/alpha 验证 |
| 为什么必做 | face 管线验证的是「替换既有资源字段」（3D 材质）；立绘是**全新资源名** `SpriteSheets\{Category}\{Category}_1`，tpaccli 能否「克隆模板 + 改名新增对象」未经实测 |
| 模板来源 | 原生 UI 纹理对象（GS_UI 族）作骨架拷字段；具体以 `TpacToolCLI/Program.cs`（MakeFace/ParseDds）实测为准；五个坑手册见 [Knowledge/tpac资源替换打包指南.md](../../Knowledge/tpac资源替换打包指南.md) |
| 判定标准 | ✅ 探针通过 = 游戏内正常显示 + alpha 正确 + 资源名命中（探针法：纯色可判命中率）→ 走 §3.2；❌ 失败（如 tpaccli 拒绝新资源名）→ 走 §四 |

### 3.2 TPAC 落地（探针通过后）

| 项 | 规格 |
|---|---|
| 纹理格式 | texconv → **BC3_UNORM**（BC1 只有 1bit alpha，头发丝会崩；BGRA8 无压缩 = 1.6GB，不可取）；mip 数与字段一致（抓「三处一致」坑） |
| tpac 资源名 | `SpriteSheets\taikou_portraits\taikou_portraits_1` / `SpriteSheets\taikou_avatars\taikou_avatars_1`——必须对上 `SpriteCategory.LoadTexture` 的请求名（模板为 `SpriteSheets\{Category}\{Category}_{N}`） |
| 打包粒度 | 一张 tpac 装全部 1066 张（单次 IO，最省）；打包脚本 = texconv 批处理 + tpaccli，工具全在 `tools/face-pipeline/` |
| SpriteData XML | 脚本生成（铁律 22：**禁止手改生成物**）；两档 category：头像 `AlwaysLoad="true"`（全载 ≈68MB 显存），立绘 `AlwaysLoad="false"` + 需要时手动 `cat.Load(ctx, depot)`（同屏 2~4 张） |
| 文件名 / Sprite 名 | 全为骑砍 StringId（铁律 20）：`taikou_portrait_{StringId}` / `taikou_avatar_{StringId}`；身份模板 = `tpl_{TK5编号}`；中文只存在于中间产物 |
| 落地 mod | ShokuhoTaikouExpansionPack（题材素材零进核心，README 裁定 24）；LWN 侧零改动、零补丁 |

### 3.3 准入锁定

- 立绘必须已通过数字双闸（脸 ≥0.030 / 肩轴 ≤-0.15）或镜像救援（RESCUED）；FAIL/NOT_RESCUED 不打包。
- 头像必须与最终立绘同向（RESCUED 用镜像版派生）。

## 四、PNG 兜底路线（仅探针失败时启用）

| 步 | 内容 |
|---|---|
| 1 | **T4 alpha 验证（必须先跑）**：1 张 PNG → 现有链路（PNG→BMP→引擎）看 alpha 是否保留；丢失则改「内存字节直建纹理」（LockBits 取 BGRA，绕过 BMP 文件）——这是唯一可能推翻方案的验证点 |
| 2 | 写 `Patch_TextureLoadFallback.cs`（落 LWN 核心，通用轮子）：加载失败 → 搜 `GUI/SpriteParts/{name}.png/.dds` → 转换 → 缓存（`.bmp.cache`）；补丁检索序 `dds(BC3) → png`，为转 TPAC/网络预埋接口 |
| 3 | 显存策略：头像全预载 ≈273MB（BGRA8）可接受；立绘按需；同槽位 SpriteData 由脚本生成 |

## 五、分发（待裁定 #5 的建议答案）

**独立「立绘资源包」子 mod（可选装）**，不作为主 mod 必装内容——立绘是可选素材，玩家可省 400MB；更新不必重发主 mod。不入 git，走发布 zip / Nexus 附件 / 网盘。
