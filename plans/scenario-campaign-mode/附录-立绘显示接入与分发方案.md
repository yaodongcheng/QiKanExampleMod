## 〇、叙事动机（三文同源，2026-08-25 用户裁定）

🔴 **骑砍2 角色建模是短板**：模型丑陋、换皮即 NPC。参考仙剑四/侠客风云传的叙事法：
- **3D 角色只做基本站位动作**（舞台）；**人物认知与表情交给 2D 立绘**（面孔）——两通道分离：3D = 舞台，2D = 面孔
- 玩家对"这个人是谁、什么气质、什么表情"的认知来自**光荣风格立绘**（太阁5 认知惯性）
- 构成立绘系统的**必要性**：这是人物认知主通道（非可选），虽然载体是内容包工作

**推论**：谁在说话 → 谁的头像/立绘上屏（对话面板/IM/多 agent 演出面板）；情绪由立绘状态 + 文本表达。

**显示挂点（原《角色头像生成》场景）**：①大地图 IM 聊天（消息行头像位）②05 多 agent 对话面板（谁说话切谁）——**引擎侧先留占位**（无头像显示首字/默认图标，不崩）——StoryVM 改造由用户另行 plan（挂起）。

## 一、最终目标（人话）

玩家在游戏里与该 NPC 对话/查看人物信息时，能看到：**半透明立绘（bustup）+ 方形小头像（minihead）**，且每张卡有唯一的"身份证号"（tkid）对应文件，换形象（多卡换脸）无缝。

## 🔴 算法参数定版（2026-08-30 v18——用户验收；改动需用户点头）

| 环节 | 参数 | 依据 |
|---|---|---|
| 抠图模型 | **u2net**（`alpha_matting=False`，无 matting） | isnet 丢部件（深甲×深背景，987/16 实证缺臂）→ 对比 u2net/birefnet：u2net 完整率最高、边缘干净、0.2-0.9s/张；birefnet 有 halo + 24s/张 |
| 立绘布局 | place()：紧贴 bbox 裁切 → 512×768 等比、水平居中、贴底 | P5 布局（2026-08-28 用户裁定，勿动） |
| minihead 尺寸锚 | **mediapipe FaceMesh 头长（额顶点 10 → 下巴 152 距离）× 2.2** | 头长不受表情影响（瞪眼/低头只动眼眉嘴）：1154 四情绪波动 3.8% vs 眼距 25-50%——表情无关的稳定尺度；脸占画面 ≈ 45% |
| minihead 水平锚 | **左右眼中心 x = 画面 52%**（窗口左右平移，头部尺寸不变） | 2026-08-30 用户裁定（左右眼坐标是最终判定量；52% 为脸朝向侧留白微调） |
| minihead 垂直锚 | 眼基线（双眼中点 y） | 稳定（眼基线一致） |
| 锚链层级 | 0 = FaceMesh 眼锚（头长+眼心52%）→ 1 = blaze FaceDetection（mesh 失败，side=脸框×2.1）→ 2 = alpha 皮肤带（HSV×YCrCb×最大连通域，side=带高×2.4）→ 3 = 上中区启发（必审） | 层 1/2 修 14 sad（mesh/cv2 双失败但 blaze 命中 0.72）；层 2 三闸防金橙盔甲混入 |
| 锚层记录 | 每张 minihead 记 `anchor_level`（主表 `ProfileImage/minihead_meta.csv` / emotion `…/emotion/minihead_meta.csv`）；**level ≥1 = 必审清单** | 机器数字先行 |
| QA 标准（用户定稿，判定主体 = **Claude 视觉模型逐张读图**——不得缩略整屏、不得抽样跳过） | 每条小头像判三闸：①**肢体完整/表情清晰**（眼睛可读、无缺臂/破洞）②**面部居中**（脸在画框水平中线 ±8%、脸部上方留白 ≈ 脸高 15-25%；**机器口径 = 左右眼中心 52%±6%**）③**同人脸一致性**（同一 StringId 的全部小头像——多情绪 AND 多卡——脸部占屏比例 ±5% 内、相对位置 ±8% 内，姿态可注记不得越界） | 2026-08-30 用户裁定：读图闸不可跳过；机器（锚层/眼距）仅复核佐证，**判定权在视觉模型**；判定写 `_review/qa_*.csv` 落盘 |

**已知容忍**：脸占比基准因画风略差（光秀瘦脸 40% vs 秀吉 52%——内容属性）；表情/姿态造成垂直位移 ±5-8%；降级锚（level≥1）卡无眼锚可平移，位置由源图决定（18 张超界清单见 §五）。

## 四、经验复盘（踩坑记录——新会话别重踩）

1. **抠图模型选型要有对比实验**：isnet 丢部件（深甲×深背景，987/16 实证缺臂）；matting 产雾（79 张灰雾）；plain 对 dark 弱；**u2net 胜出**（完整+干净+快）。三条对比都要跑，别凭感觉。
2. **minihead 不要从抠图标裁**（用户裁定：用原图）——抠图后人物贴底居中、上部全是透明，裁出来必是大空白 + 脸小。
3. **锚基准要"表情无关"**：眼距被瞪眼/俯仰撑大（波动 25-50%）→ 头长（3.8-15%）；**水平最终判据 = 左右眼 x**（用户指定口径，机器可算，别自造"中部感"）。
4. **层级变量赋值 bug**：cv2/启发分支不设 level → 全 0 假信号 → meta 不可信。**审计信号先自测真伪**（拿已知问题图对账）。
5. **皮肤掩膜域要三闸**（HSV × YCrCb × 最大连通域）：单闸把金橙盔甲/亮片当皮肤 → 框爆/拖飞。
6. **窗口/候选窗大小 & 位移门**：太宽（±0.9side）会把肩颈手框进来，最大连通块变肩膀 → 拖飞；收窄 + 位移门（±8%）+ 裁剪 clamp。
7. **机器"level0"不等于合格**：14 sad 出现过 mesh 假阳性；face_ratio 域对惊讶脸失效（12%/2% 误报）。**机器数字是佐证，视觉/用户是终裁**。
8. **读图模型的不可靠性（我，2026-08-30 教训）**：多轮把"脸偏左"读成"偏右"、方向/占比描述错误、还会"顺着用户说"。**结论：我的读图结论不作数——判定以机器数值 + 用户肉眼为准**（此条已写入 CLAUDE.md 计划纪律？→ 未，可考虑）。⚠️ 用户裁定：必须逐张读图（不缩略、不抽样）；我照做，但判语仅作参考。
9. **生成物分寸**：TaikouHero/ProfileImage.csv = 生成物（脚本禁手改，改脚本重跑）；内容表（persona）用户裁定方案 B = 放进主表"手写区"（git 已提交作安全网）。
10. **"搬运"语义错误**：把「生成 → 搬运进补充包」做成"复制留底"（Portraits/ 603MB 副本）——用户裁定：**图就放 ProfileImage 原位，发布 = 打包 tpac**。计划文档误导性描述必须及时更正（用户点名"这不是我想要的"）。
