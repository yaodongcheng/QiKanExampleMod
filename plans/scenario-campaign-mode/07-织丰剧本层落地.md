## 这一步做什么（一句话）

织丰在 1.2.12 原生可跑，所以这一步 = **把剧本引擎挂到织丰战役上**：玩家装织丰 + 我们（补充包），主菜单多一个"历史剧本战役"入口（织丰原入口共存），进战国世界跑剧本引擎（事件/时间轴/演出/主命）。织丰的世界与玩法保持原样，剧本引擎附加在其上。

## 玩家视角

- 玩家装两个 mod：织丰（前置依赖）+ 我们（剧本层）
- 主菜单多一个"历史剧本战役"入口（织丰原入口保留，两个入口共存）
- 选剧本进世界：40 个日本势力、848 座城、日式兵种装备、日式场景全在，织丰的港口/寺庙/决斗等玩法也在
- 年代不锁死 1568（织丰原版锁死 1568 开局）——由剧本决定（桶狭间 1560 / 本能寺 1582）

**实现载体：`ShokuhoTaikouExpansionPack` 补充包**（独立 mod，`Modules/` 下与 LivingWorldNpcs 平级；同一 VSCode/Claude Code 工作区，**独立 git 仓库、独立打包**；发布依赖 = 织丰 + LivingWorldNpcs + StartAsAnyone + 本包）。

- 🔴 **内容归属**：**所有剧本文件（DSL 剧本/演绎剧本/编译产物/本地化）+ 补充 XML 数据包（人物/城池/势力等）全部在本包内开发产出**；LivingWorldNpcs 只承担功能机制（worldview 铁律：核心零日战字串）
- 🔴 **版本要求：必须 1.2.12**（2026-08-25 裁定：织丰在 1.2.12 **原生可运行**；1.5.1 **硬不兼容**——验证过程见 [附录-织丰验证与兼容层历史.md](附录-织丰验证与兼容层历史.md)）——本包剧本层 + 织丰**只在 1.2.12 客户端运行**，1.5.1 及以上不做

## 明确要做（四块）

### 1. 共存性验证（织丰行为 × 剧本引擎冲突面核对）

织丰 138 个 Harmony 补丁（Harmony = 骑砍 mod 常用的代码修改库，补丁 = 直接改写原版行为的钩子；战斗结算/围城 AI/数据加载等）+ 19 个行为（晋升/征募/抽卡/寺庙/决斗/书籍/外交类系统（Diplomacy 系列插件））与剧本引擎同场运行，**需要剧本引擎在场才有意义**（01-06 审核后做）：

- 138 个补丁对核心结算的改写（战斗/围城/LoadXML）是否影响剧本引擎（战斗编排/事件结算）——逐个核对冲突面
- 织丰行为 × 剧本引擎并存：晋升/外交/扩张主义驱动世界自然演化 vs 剧本引擎按剧本纠正历史走向（02 战略 AI 纠正器管这个）
- 产出**冲突清单**，有冲突的记入 02/14 的兼容处理

### 2. 嵌入层（剧本层核心）

- **剧本入口**：`AddInitialStateOption` 注册"历史剧本战役"（织丰的 `ClearStateOptions` 在它的 OnSubModuleLoad 执行——OnSubModuleLoad = mod 加载启动阶段，我们加载在它之后，入口共存）
- **战役启动**：复用织丰战役容器（`ShokuhoCampaignGameManager`/`ShokuhoCampaign`，数据加载开关天然匹配织丰数据零改动）；剧本初始化时**覆盖织丰的时间锁**（反射写 `CampaignStartTime` 为剧本年代 1560/1582——织丰自己也是这么写的，同一手法）
- **剧本注入**：`OnGameStart`/`OnCampaignStart` 阶段向 campaign 注入剧本行为（时间轴/事件调度/演出/主命），剧本引擎的全部机制挂在织丰战役之上
- **角色创建**：剧本入口走我们自己的流程（06 的 ASO/StartAsAnyone，扮演历史人物），**不进织丰的角色创建 UI**

**设计依据**（织丰行为注册机制，反编译结论，2026-08-25）：

- 织丰的 `AddBehaviors`（19 个行为）在 `OnGameLoaded`/`OnCampaignStart` **无条件执行，不区分 GameType**——任何 Campaign 启动都会带上织丰全部行为
- 织丰的 `OnSubModuleLoad` 无条件清原版入口 + 锁时间 + PatchAll——共存策略：后注册入口 + 启动时覆盖时间
- 织丰的 `OnGameStart` 只对 `ShokuhoCampaign`（它的 GameType）做定制（注册 Port/DuelLocation/Temple 对象）——复用织丰战役容器时这些自动就位

### 3. 素材表落地

织丰场景/部件盘点产出素材表（供 03 编排器用）：场景预制件（大筒/竹栅栏/弹药箱/篝火/竹束盾/城门/推拉门等 28 个编辑器脚本）、日式兵种装备、火粒子/氛围；**关键 ID 确认**（信长/京都等剧本引用对象）。

### 4. 接线验证

剧本条件能命中织丰对象："尾张城归织田家"等条件查得出来；剧本事件在织丰世界正常触发；演出/主命跑通。

## 要注意的坑

- **依赖 01-06 审核**：共存性/嵌入层都需要剧本引擎在场，01-06 未通过前禁止实施
- 织丰世界数据是 **1568 快照**（角色年龄/势力版图按 1568 摆）——1560 桶狭间开局时世界状态与历史不符，由 06 时代重置（表驱动选择性激活：活着/未出生/已死三态）处理，与谁加载数据无关
- 织丰时间锁与剧本年代冲突：剧本启动时覆盖 `CampaignStartTime`（织丰同款反射手法），覆盖后织丰行为按新时间运行，**每日结算/出生死亡等依赖时间的行为要回归测试**
- 剧本入口走我们自己的角色创建（06 的 ASO/StartAsAnyone），**不进织丰角色创建 UI**——否则扮演历史人物被织丰的自定义捏人流程干扰
- 织丰存档与我们剧本状态共存：织丰 SaveableField/TypeDefiner 会参与我们的存档，新增剧本存档字段注意 ID 冲突（存读档测试）
