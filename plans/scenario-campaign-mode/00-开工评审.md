## 一、结论（v2）

**决定：第一步 = 端到端最小闭环——拿真实生成物（桶狭间 21 个事件）验证「能加载、能触发、能按 05 演绎」，为此改造已有 StoryEngine 管线。其他 plan（01/02/06/17…）全部后话。**

理由只有一句话：**生成物从未被任何游戏代码读取过**。"76 行覆盖全绿"只证明生成端自洽（太阁原文没丢、翻译没猜），不证明执行端能跑——而从 JSON 数据到游戏画面之间，**一件代码都不存在**。

### 为什么 v1 被判错（三条硬证据）

1. **现有管线吃的是另一套格式，和生成物结构对不上**：

   | 维度 | 已有管线（ExampleMod StoryEngine） | 生成物（story_event_json/okehazama） |
   |---|---|---|
   | 数据文件 | `ModuleData/StoryJson/*.json` = `List<StoryEvent>` | `events.jsonc`（单对象骨架）+ `story/*.jsonc`（演绎分件，文件头注明"机械翻译产物"） |
   | 指令语法 | **中文 Cmd**：`對話`/`分歧`/`代入ａ`/`變量賦值`…（CommandManager.cs:27-52 注册表） | **英文 token**：`dialogue`/`choice`/`narrator`/`effect`/`perform`… |
   | 角色引用 | ScriptNode 里裸中文名/params 字符串 | `Hero::lord_1_imagawa_katsumoto` 域前缀 + StringId（铁律 20） |
   | 条件 | `type:调查` + left/operator/right 字段 | `condition: "and(exists(...), ...)"` **DSL 文本表达式字符串**，求值器不存在 |
   | 文本 | node.Text 直接写中文 | **textKey → i18n XML**（铁律 13），文本里还有 `{PH_N}` 占位符需要运行时注入 |
   | 门控 | 无 | 行级 `when` DSL 表达式（05 源格式纪律 1） |

2. **整条「数据 → 画面」链路上缺 4 件代码，全只有文档**：①生成物加载器（StoryDataLoader 读不动 events.jsonc，字段名都不同）②DSL 求值器（condition/when 是字符串表达式，01 只写了语法没写代码）③StoryCompiler（05 步骤 2，把 lines[] 编成台本指令流——**0 行代码**）④播放器改造（05 步骤 3，现有 RunLoop/Stack 骨架保留但动得最深）。

3. **现有管线正是 05 要消灭的对象**：`GetCurrentSceneParticipants`（ReadStory 侧运行时向前扫描算"谁在场"）、`AssignSlots`、`CheckActorLeaving` 偷看下一幕——05 裁定全部移入编译期（05 "🔴 现状动态算的 4 个点"表）。所以第一步不是写新引擎，是**改造已有引擎**，让它从"运行时现算"变成"按编译器产出的台本播"——这本来就是 05 的 Phase 1。

### 验证可执行性时当场就能暴露的真问题（示例，执行侧验证返哺生成侧）

这些是在通读生成物时发现的，说明"跑一遍"值回票价（全跑通后另出验证报告清单）：

- 🔴 **生成器 bug（疑）**：EFF06E00_159_seg1 里 T23/T25 的 `when` 写成 `and(..., (Ctx::choice) == "opt0", (Ctx::choice) == "opt1")`——两个分支条件 AND 在一起**恒假**，对应台词永远不播。这正是执行侧验证才能照出来的病（生成端自检只查"行数对齐"，不查"逻辑可达"）。
- 🔴 **`{PH_N}` 占位符注入**：i18n 文本含 `{PH_N}`（208 条注入表，审记 §八），运行时没人注入 = 屏幕上直接显示 "{PH_1}" 穿帮。首版最小注入（玩家名/已注册 Hero 名），其余降级写死注释。
- 🔴 **`note` 步骤（BGM/SE/机制行）**：events.jsonc script[] 里大量 `{"step":"note","note":"🔴 ＢＧＭ變更 表现指令 → 05 承接"}`——执行器必须先能"跳过不崩"，能承接的再承接。
- 🔴 **演出形态待终裁**：159 两种分件 form = `menu_dialogue`，但事件 trigger 是 `house_enter`（室内画面）——机械默认的形态表与 trigger 是否匹配本来就留了 agent 复核（审记 §五.3）。
- 🔴 **`🔴待注册`/`🔴待07` 占位**：condition/effect 里还有待注册实体（如 `Clan::🔴待07今川氏真`）——执行器对未知 ID 必须"跳过并记日志"不崩（iron 1），但验证报告要逐条分清：执行器的锅 vs 数据包的锅 vs 生成器的锅。
