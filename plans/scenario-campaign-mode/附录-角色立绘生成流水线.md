## 三、生图服务实测能力（2026-08-28 全部实跑验证）

**端点**：`https://ai.leihuo.netease.com/v1/images/generations`，模型 `doubao-seedream-5-0-260128`。

| 能力 | 结论 | 说明 |
|---|---|---|
| 出图 | ✅ 可用 | 单张 13~35 秒 |
| **最小尺寸** | 🔴 **必须 ≥ 3,686,400 像素** | `1024x1024` 直接报 400。这是硬门槛 |
| 竖构图 | ✅ | `1568x2352`（2:3）实测通过，即最省钱的 2:3 档 |
| **参考图（图生图）** | ✅ **支持**，传 `image` 字段 | 🔴 **必须传 base64**：传外网 URL 会失败（火山服务器下载不到境外图片，实测超时报错）。支持传多张（数组） |
| **透明背景** | ❌ **不支持** | `background:"transparent"` 参数被无视，永远返回 JPEG。**必须本地抠图** |
| **水印** | ⚠️ 默认右下角有「AI生成」字样 | 传 `watermark:false` 可去掉，**实测有效，批量跑必须带** |
| 固定随机种子 `seed` | ✅ 接受 | 用于复现同一张图 |
| 一次出多张 `n` | ❌ 无效 | 传 `n:2` 仍只返回 1 张，要多张就多请求几次 |
| 返回格式 | JPEG（URL 或 base64 二选一） | URL **只活 24 小时**，必须立刻下载存盘 |

### 花多少钱（实测测量，非估算）

网关有账单接口 `/v1/dashboard/billing/usage`。连跑 3 张 `1440x2560`，前后读账单：

```
账单增量 9.0414 ÷ 3 张 = 3.0138 每张
```

按 OpenAI 惯例这个数的单位是**美分** → **约 $0.030/张 ≈ ¥0.22/张**。

| 场景 | 张数 | 预计花费 |
|---|---|---|
| 三人试跑（每人 4 版对比） | 12 | ¥3 |
| 全量一人一张 | 1049 | **¥230** |
| 全量 + 失败重跑 + 部分人出 2 张挑（按 1.6 倍算） | 1678 | **¥370** |
| 若将来每人再加 4 张情绪图（怒/笑/惊/哀） | 5245 | ¥1150 |

✅ **已复测（2026-08-28 试跑 12 张）**：账单 105281.6824 → 105317.848，12 张成功，**单价 3.0138/张，与首次测量分毫不差**。成本模型可信，上表数字不用改。

单张 15~35 秒。串行 1049 张 = **5~10 小时**；开 4 路并发 = **1.5~2.5 小时**。并发上限先用 2 路试探网关限流，没报 429 再往上加。

## 四、第一步：爬参考图（只爬，不生成）

### 爬哪里

| 源 | 用途 | 版权 |
|---|---|---|
| **日文维基百科** | 按日文名查词条，取词条内全部图片 | 江户时代肖像画，公有领域 |
| **维基共享资源（Commons）** | 按罗马音 + 日文名搜图，取 `Category:Portraits` 相关 | 同上 |

🔴 **明确不爬光荣（KOEI）的游戏立绘**。理由：那是有版权的商业美术资产，拿它当参考图等于直接复制别人的画。风格靠提示词描述即可——「光荣风格」是画风，不是具体某张图。

### 三个必须处理的坑

1. **旧字体 → 新字体**。表里写的是繁体/旧字体（`前波吉繼`／`稻葉一鐵`／`北條幻庵`），维基用新字体（`前波吉継`／`稲葉一鉄`／`北条幻庵`）。**不做字体归一，白白丢掉一批本来查得到的人**。做一张旧新字体对照表，查不到时用归一后的名字再查一次。
2. **别名**。表里是史料本名，通俗名不同——`木下秀吉` = 丰臣秀吉，`真田信繁` = 真田幸村。查不到时用通俗名再查一次，别名表手工维护（几十条，都是名人）。
3. **主图未必是人像**。织田信长词条主图是花押（签名符号），另有家纹、城池照片、墓碑。**必须筛**：网关上有视觉模型（`doubao-seed-1-6-vision-250815`），把候选图丢给它问一句「这是一张人物肖像画吗」，是就留，不是就扔。一次判图几分钱，1000 张不到 ¥50。

### 产出

```
ShokuhoTaikouExpansionPack/ArtSource/refs/{骑砍StringId}/
    ref_1.jpg  ref_2.jpg ...      # 通过筛选的肖像图
    meta.json                      # 来源 URL / 授权 / 判图结论 / 抓取日期
ShokuhoTaikouExpansionPack/ArtSource/refs/_index.csv   # 1049 人 × 参考图张数，一眼看覆盖率
```

**必须记来源和授权**——将来发布 mod 要交代素材出处。

### 网络注意（本机实测的坑）

curl 走 Windows schannel 会因为**证书吊销检查**连不上外网（报 `CRYPT_E_NO_REVOCATION_CHECK`，表现为所有网站 HTTP 000，看着像断网）。加 `--ssl-no-revoke` 即可。Python 的 `requests`/`urllib` 用自带证书，不受影响——**爬虫用 Python 写，绕开这个坑**。

## 五、第二步：立绘规格

### 分辨率怎么定

| 环节 | 尺寸 | 为什么 |
|---|---|---|
| **生成** | **1568 × 2352**（2:3） | 服务最小 368 万像素门槛下，2:3 竖构图最省钱的一档 |
| **成品入包** | 🔴 **512 × 768**（2:3） | 立绘贴左下角，只占屏宽约 1/4~1/3。1920×1080 下实际显示宽约 480~520 像素，512 正好是 1:1 像素，再大就是白扛体积（2026-08-28 用户裁定：横向最多 512） |
| **头像派生** | 256 × 256 | 从立绘裁脸，对齐 [附录-角色头像生成](附录-角色头像生成.md) 已定的头像尺寸，不重复生成 |

🔴 **成品分辨率是后处理参数，随时可批量改，不用重跑图**。原图（1568×2352）永久留底——将来真上了 4K 屏觉得糊，一条命令从原图重出 1024×1536，**不用重新调用 API、不额外花钱**。

**磁盘预算**：512×768 PNG 约 300~450 KB/张 × 1049 ≈ **350~450 MB**。数据包体积不再是问题。

**显存不用担心**：立绘按需加载（`AlwaysLoad="false"`），同屏最多 2~4 张，24 MB 以内。

### 构图怎么定（立绘贴在屏幕左下角）

1. **人物朝右**：3/4 侧身，脸和视线朝右前方——朝向屏幕中央，也就是朝向对话框和玩家注意力所在。朝左等于背对整个画面。
2. ~~**主体在画布偏右**：人物中轴放在画布横向 55%~62%~~ 🔴 **2026-08-28 试跑推翻**：512 宽的画布里人物已占满，没有右移空间，强推只会浪费像素。改为**紧贴人物裁切**，「脸偏右」交给画面内朝向（见 §十四 P5）。
3. **取景到腰**：半身像，头顶留白约 8%，下沿切在腰~胯之间。不做全身——脚会被屏幕底边切掉，白花像素。
4. **背景纯色幕布**：单一平涂色，无渐变无阴影无纹理（抠图要用）。
5. **画面里不许有**：文字、边框、签名、印章、水印、装饰花纹。

## 六、第三步：提示词怎么拼

提示词 = **模板 + 表格字段填空**，不是每人手写。四层拼起来：

| 层 | 内容 | 来源 |
|---|---|---|
| **风格层**（全人固定） | 光荣《太阁立志传》《信长之野望》武将立绘画风；日式厚涂 + 淡彩，笔触克制；历史正剧质感；**不要动漫萌化、不要写实照片、不要赛博/奇幻** | 写死在模板里 |
| **人物层**（每人不同） | 年龄（剧本年份 − 生年）· 性别 · 身份决定的服饰等级（大名/家老/侍大将/足轻组头/浪人/忍者/僧侣/商人/公家）· 家族主色 · 文化 · 性情气质（性情/精神/主义/行动四列 → 表情与神态）· 统率武力智谋（→ 披甲武将 还是 素袍文官，体格胖瘦）· 武具偏好（刀/枪/弓/铁炮） | `TaikouHero` 表字段 + `Clan` 表家纹主色 |
| **构图层**（全人固定） | 上一节的 5 条构图规则，逐条写成提示词 | 写死在模板里 |
| **参考层**（有图的人才有） | 传 base64 参考图 + 「参考此历史肖像的面部特征、发型、胡须形制，重绘为上述画风」 | 第一步爬到的图 |

**身份 → 服饰**的映射表要单独维护（大名穿什么、足轻组头穿什么、浪人穿什么），这是把表格数据翻成画面的关键一步，也是最需要人肉调的部分。

🔴 **提示词模板是唯一事实源**（铁律 22）：想改画风就改模板重跑，**禁止手 P 图片**。

## 七、第四步：抠成透明 PNG

服务不给透明背景，只能自己抠。四步：

1. **生成时就铺纯色幕布**：提示词里指定一个人物身上基本不会出现的色（如中性蓝绿 `#3A5F4B`），要求平涂、无阴影、无渐变。
2. **抠图**：
   - **主路 `rembg`**（`isnet-general-use` 模型），需要 `pip install rembg` + 下载约 180 MB 模型。头发丝、薄纱羽织这类半透明边缘明显更干净。
   - **兜底纯色键控**（OpenCV，本机已装，零额外依赖）。幕布够纯时够用，边缘略糙。
   - 两条都跑，谁的结果好用谁——用「抠完剩余像素占比」和「边缘锯齿度」两个数自动判。
3. **去色溢 + 羽化**：擦掉边缘沾上的幕布绿，alpha 边缘羽化 1 像素，避免贴到深色背景上出现绿边硬壳。
4. **对齐画布**：按内容包围盒裁切 → 按人物高度归一（占画布高 94%）→ 缩放到 **512×768**，贴底对齐。**不再做中轴平移**（§十四 P5）。

### 自动质检（不合格的自动重跑，不用人眼看一千张）

| 检查 | 判定 |
|---|---|
| 透明像素占比 | < 15% 或 > 75% → 判失败（背景没抠掉 / 人物被抠没了） |
| ~~人物中轴位置~~ | 已作废（§十四 P5）；改判**朝向**：视觉模型判「人物面朝画面左还是右」，朝左判失败 |
| 是否有脸 | OpenCV 人脸检测 0 个 → 判失败 |
| 画面是否有文字 | 视觉模型判一句 → 有字判失败 |
| 头顶是否被切 | 内容包围盒顶边贴到画布顶 → 判失败 |

失败的自动换 seed 重跑，最多 3 次；3 次还不过的进 `_manual/` 目录，人工看。

### 产出

```
ShokuhoTaikouExpansionPack/ArtSource/raw/{StringId}_seed{n}.jpg              # 原始出图，永久留底
ShokuhoTaikouExpansionPack/GUI/SpriteParts/taikou_portrait_{StringId}.png     # 成品 512×768 透明
ShokuhoTaikouExpansionPack/GUI/SpriteParts/taikou_avatar_{StringId}.png       # 派生 256×256 头像
ShokuhoTaikouExpansionPack/ArtSource/build_log.csv                           # 每人：用了哪张参考图 / seed / 质检结论 / 重跑次数
```

**文件名用骑砍 StringId**（铁律 20），不用中文名——改名和多语言下不会错位。

## 九、第六步：批量跑

- **顺序**：先跑剧本里有戏份的角色（桶狭间 / 本能寺人物表，约 100~150 人）→ 再跑各家大名家老 → 最后跑足轻组头和浪人。**先出的先能用**，不用等全跑完。

## 十一、风险

| 风险 | 后果 | 怎么办 |
|---|---|---|
| 1000 张图画风不统一（AI 天然漂移） | 立绘拼在一起像大杂烩，破坏沉浸感（铁律 6） | 风格层提示词逐字固定不变；每 100 张抽 5 张人眼比对；漂了就锁 seed 范围重跑该批 |
| 七成角色没参考图，长相全靠模型编 | 同一家族的人可能长得毫无关系 | 家族主色 + 家纹元素写进提示词做视觉纽带；父子关系（表里有 `FatherName`）在提示词里点明「面部特征承袭其父」 |
| 女性角色仅 40 人，且史料画像更少 | 40 人可能全靠编 | 单独一套女性提示词模板（打扫/小袖/眉墨/发型按身份分档），单独审一轮 |
| `rembg` 装不上（需下载 180 MB 模型） | 只能用纯色键控，边缘变糙 | 提示词把幕布纯度要求写死；实在不行接受略糙边缘，立绘贴左下角边缘不显眼 |

### 试跑暴露的 5 个真问题（都必须改，改完重跑）

| # | 问题 | 证据 | 怎么修 |
|---|---|---|---|
| **P1** | **朝向不听话**。要求「面朝画面右前方」，12 张里真正朝右的只有少数，多数是正面或朝左 | 信长 A 朝左、B/C 正面，只有 D 朝右 | 朝向提到提示词最前面单独成句 + 负面词加「禁止朝向画面左侧、禁止正面平视」；仍不稳就出图后用视觉模型判朝向，判错的自动重跑 |
| **P2** | **参考图权重失控**。真田 C/D 直接把江户古画临摹了 —— 变成盘腿坐姿的老年僧俗像，画风也从光荣立绘塌回古画 | `preview/lord_1_sanada_9_ABCD.jpg` 的 C、D 两格 | 参考图措辞改成「**仅参考面部骨相与胡须发型，姿势构图服饰一律按本提示词，不得沿用参考图的姿态与画风**」；仍塌就降低参考图使用面（只在有清晰面部特写时才传） |
| **P3** | **取景比例不统一**。A 版人物小而远，B/C/D 近而大 —— 1000 张摆一起会很乱（铁律 6） | 信长 A vs B 的人物占画面比例差一倍 | 构图层写死「头顶到腰的距离占画面高度 X%」这类可量化描述；后处理按人物包围盒统一归一（已实现，见 `matte_rembg.py` 的 `place`）。🔴 **提示词里的 X 还没定**——T2 要先在三人身上试 65% / 75% 两档，挑一档写死 |
| **P4** | **背景不是纯色平涂**，普遍带暗角和渐变 | 信长 C 明显四角压暗 | 这是键控失败的根因之一。**主路改用 rembg（AI 分割），不依赖背景纯度**；背景纯色要求降级为「有更好，没有也能抠」 |
| **P5** | **「人物中轴放在画布 58%」这条规则本身是错的** | 12 张成品实测中轴全在 0.52~0.55，卡死。原因：人物裁切后已占满 512 宽，物理上没有右移空间 | 🔴 **规则作废**。改成：PNG **紧贴人物裁切、不留无用透明边**（512 宽全部给人物，不浪费像素）；「脸偏右」由**画面内朝向**（P1）实现，不由画布内平移实现。屏幕上的位置由 UI 摆放决定 |

### 抠图为什么必须用 rembg

兜底的纯色键控在浅色背景上一看就露馅：**秀吉的黑金羽织下半截被抠成了筛子，信长的黑羽织变半透明**。原因是幕布色偏暗、又带渐变，和黑色衣物的色距不够。`preview/matte_qc.jpg` 下半排（浅底）能直接看到破洞。

→ **rembg（`isnet-general-use`）已装好**（`pip install rembg onnxruntime`，onnxruntime 1.20.1），脚本 `ArtSource/matte_rembg.py` 已写好**且已按 P5 改完**（紧贴裁切、居中贴底、新增破洞质检），**待跑 = T1**。纯色键控降级为「rembg 跑不动时的应急」。
