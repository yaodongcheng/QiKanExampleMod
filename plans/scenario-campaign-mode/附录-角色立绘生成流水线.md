## 三、生图服务实测能力（2026-08-28 全部实跑验证）

**端点**：`https://ai.leihuo.netease.com/v1/images/generations`，模型 `doubao-seedream-5-0-260128`。

| 能力 | 结论 | 说明 |
|---|---|---|
| 出图 | ✅ 可用 | 单张 13~35 秒 |
| **最小尺寸** | 🔴 **必须 ≥ 3,686,400 像素** | `1024x1024` 直接报 400。这是硬门槛 |
| 竖构图 | ✅ | `1568x2352`（2:3）实测通过，即最省钱的 2:3 档 |
| **参考图（图生图）** | ✅ **支持**，传 `image` 字段 | 🔴 **必须传 base64**：传外网 URL 会失败（火山服务器下载不到境外图片，实测超时报错）。支持传多张（数组） |
| **透明背景** | ❌ **不支持** | `background:"transparent"` 参数被无视，永远返回 JPEG。**必须本地抠图** |
| **水印** | ⚠️ 默认右下角有「AI生成」字样 | 传 `watermark:false` 可去掉，**实测有效，批量跑必须带** |
| 固定随机种子 `seed` | ✅ 接受 | 用于复现同一张图 |
| 一次出多张 `n` | ❌ 无效 | 传 `n:2` 仍只返回 1 张，要多张就多请求几次 |
| 返回格式 | JPEG（URL 或 base64 二选一） | URL **只活 24 小时**，必须立刻下载存盘 |

🔴 用户最终裁定：**需要光荣游戏图的特征**（非商业使用、只取特征不直接使用原图）——但**图不进生成 API**。管线：

2. **视觉提炼（Claude 视觉读图）**：看光荣图 → 提炼长相/须发/神情/标志装束要点（如幸村 = 鹿角兜盔+六文钱纹+赤红具足）→ 写进主源「外观描述_光荣」列（`update_appearance.py` 维护）。
3. **生成器注入**：描述进 prompt 人物层——图**绝不传给 Seedream**（img2img 是整图临摹机制，P2 教训；且非商用引用边界也更稳妥）。
4. **覆盖面策略**：剧本有戏份的人物（桶狭间/本能寺约 100~150 人）优先，有光荣形象的就爬+提炼；其余人物描述列为空 = 走纯属性驱动——这不是缺陷，很多足轻组头历史上来就没有画像（§二 结论不变）。

5. 🔴 **新角色立绘生成 SOP（2026-08-28 用户裁定后的最终方法）**——遇到新角色按此七步走：
   1. **定位**：主源 CSV/BaseInfo 找该角色 → 在本机太阁5 BUSTUP 解包库 `E:/taikou5/TaikouImage/BUSTUP/{编号_姓名}/000.dds` 找图（工具字符表命名 = `编号_姓名`，含 1292 人）；
   2. **多形象 ID 纪律**：搜目录里同名全部 ID（实例：信长 195/1154、幸村 361/1162），**选与年龄规则最匹配的形象**；众说纷纭就用多形象做对比联跑（多花 ¥0.22×n）；
   3. **转 PNG**（PIL，512×624 RGBA）；
   4. **R 版 img2img**：TK5 原图当底稿 base64 传入 `image` 参数 + 现行提示词模板（现代厚涂 CG 风格/半身朝右风暴背景/REF_HINT 强制"仅借长相造型、姿态构图画风光影一律重绘、禁临摹"）；**img2img 用 gpt-image-2**（/images/edits + `images:[{"image_url":datauri}]`，¥0.40/张——2026-08-28 终评转正）。🔴 **底稿朝向与目标不符时（原稿脸朝左，如 1057 訚千代）先水平翻转底稿再传**——gpt2 会继承底稿朝向；
   5. **数字双闸判定（2026-08-28 定稿，禁肉眼/禁 pose）**：每张出图后必过两道数字闸：
      ①**脸**（mediapipe face mesh：鼻 x − 双眼中点 x ≥ 0.030 = 脸清晰朝右；该测向与用户判断三次一致，可靠）
      ②**肩带比**（抠图 alpha 后人物顶 40% 区域左半/右半像素比 ∈ **[1.05, 1.65]** = 自然侧身；用户标定样本：阿市 1.10 ✅ / 幸村 1.49 ✅ / 信长 0.73 ❌ / 訚千代 0.95 ❌ / 秀吉 1.93 ❌——两头越界都是"拧巴"）
      任一不过 = 换 seed 重跑（≤3 次停上报）。**作废**：肉眼方向判读（本会话镜像误读 N 次，全部读反）+ mediapipe pose 肩判（半身/肩甲遮挡检不出）；
   6. **回写**：达标后把形象要点提炼进「外观描述_光荣」列（`update_appearance.py`）→ 主源 CSV；
   7. **流转**：raw 留底 → T1 rembg 抠图 → 512×768 成品 + 256×256 头像（比例待裁定 21）。
   **失败兜底**：无 TK5 形象的角色（虚构/无名配角）→ 走纯 E 版（描述驱动）+ 家族主色/父子纽带。

## 五、第二步：立绘规格

### 分辨率怎么定

| 环节 | 尺寸 | 为什么 |
|---|---|---|
| **生成** | **1568 × 2352**（2:3） | 服务最小 368 万像素门槛下，2:3 竖构图最省钱的一档 |
| **成品入包** | 🔴 **512 × 768**（2:3） | 立绘贴左下角，只占屏宽约 1/4~1/3。1920×1080 下实际显示宽约 480~520 像素，512 正好是 1:1 像素，再大就是白扛体积（2026-08-28 用户裁定：横向最多 512） |
| **头像派生** | 256 × 256 | 从立绘裁脸，对齐 [附录-角色头像生成](附录-角色头像生成.md) 已定的头像尺寸，不重复生成 |

🔴 **成品分辨率是后处理参数，随时可批量改，不用重跑图**。原图（1568×2352）永久留底——将来真上了 4K 屏觉得糊，一条命令从原图重出 1024×1536，**不用重新调用 API、不额外花钱**。

### 头像提取规则（2026-08-29 用户裁定定稿，样本=信长）

**决定：头像 = 从原图 raw 全分辨率自动定位头部 → 方形裁切 → 256×256，零人工**（比从 512×768 立绘裁更清晰；裁切框以「发髻/头盔与天空相切处为顶、完整下巴+领口起始为底、左侧比右侧多留空间」为骨架）。

定位链（从优到兜底）：
1. **mediapipe face bbox**（`verify_pose.judge['face_bbox']`，顶部已外扩 0.75 脸高盖发髻/盔帽——判向时顺带产出，零额外成本）✅ 实测命中（赤井直正/信长）
2. OpenCV Haar 正脸 → 还原成方形（3/4 侧脸检率低，仅回退）
3. 构图比例兜底（提示词铁律：头占高 24~28%、头顶留白 8% → 头带 y∈[0.10, 0.36]）

裁切几何参数（`ArtSource/make_avatars.py` 常量，2026-08-29 信长 6 档对比后拍板）：

| 参数 | 值 | 语义 |
|---|---|---|
| `TOP_SKY` | 0.03 | 顶部天空隙（相对脸框高）——以发髻/盔帽与天空相切处为顶 + 3% 天空，**头发/头盔不被截断** |
| `CHIN` | **0.18** | 下颚下方留量（相对脸框高）——完整下巴 + 领口起始；**0.30 被否（下方留太多）**，0.10 嫌贴底 |
| `LEFT_BIAS` | 0.06 | 脸中心横移（相对边长）——**左侧比右侧多留空间**；0.12 偏多被否（人物贴边太紧） |
| `MIN_H` | 1.20 | 框高下限（相对脸框高），兜住宽发型/盔帽 |
| 方形边 | `max(MIN_H×脸框高, 顶→底跨度)` | 顶=发髻顶+天空隙，底=下颚+0.18 脸框高 |

产出：`GUI/SpriteParts/taikou_avatar_{StringId}.png`（身份模板 = `taikou_avatar_tpl_{编号}.png`）+ 每 64 一张深底审核拼图 `preview/avatars_*.jpg`（人眼复核）。镜像救援（RESCUED）用镜像版做头像——**脸与最终立绘同向**。


**磁盘预算**：512×768 PNG 约 300~450 KB/张 × 1049 ≈ **350~450 MB**。数据包体积不再是问题。

**显存不用担心**：立绘按需加载（`AlwaysLoad="false"`），同屏最多 2~4 张，24 MB 以内。

### 构图怎么定（立绘贴在屏幕左下角）

1. **人物朝右**：3/4 侧身，脸和视线朝右前方——朝向屏幕中央，也就是朝向对话框和玩家注意力所在。朝左等于背对整个画面。
2. ~~**主体在画布偏右**：人物中轴放在画布横向 55%~62%~~ 🔴 **2026-08-28 试跑推翻**：512 宽的画布里人物已占满，没有右移空间，强推只会浪费像素。改为**紧贴人物裁切**，「脸偏右」交给画面内朝向（见 §十四 P5）。
3. **取景到腰**：半身像，头顶留白约 8%，下沿切在腰~胯之间。不做全身——脚会被屏幕底边切掉，白花像素。
4. **背景纯色幕布**：单一平涂色，无渐变无阴影无纹理（抠图要用）。
5. **画面里不许有**：文字、边框、签名、印章、水印、装饰花纹。

## 六、第三步：提示词怎么拼

提示词 = **模板 + 表格字段填空**，不是每人手写。四层拼起来：

## 七、第四步：抠成透明 PNG

服务不给透明背景，只能自己抠。四步：

1. **生成时就铺纯色幕布**：提示词里指定一个人物身上基本不会出现的色（如中性蓝绿 `#3A5F4B`），要求平涂、无阴影、无渐变。
2. **抠图**：
   - **主路 `rembg`**（`isnet-general-use` 模型），需要 `pip install rembg` + 下载约 180 MB 模型。头发丝、薄纱羽织这类半透明边缘明显更干净。
   - **兜底纯色键控**（OpenCV，本机已装，零额外依赖）。幕布够纯时够用，边缘略糙。
   - 两条都跑，谁的结果好用谁——用「抠完剩余像素占比」和「边缘锯齿度」两个数自动判。
3. **去色溢 + 羽化**：擦掉边缘沾上的幕布绿，alpha 边缘羽化 1 像素，避免贴到深色背景上出现绿边硬壳。
4. **对齐画布**：按内容包围盒裁切 → 按人物高度归一（占画布高 94%）→ 缩放到 **512×768**，贴底对齐。**不再做中轴平移**（§十四 P5）。

### 自动质检（不合格的自动重跑，不用人眼看一千张）

| 检查 | 判定 |
|---|---|
| 透明像素占比 | < 15% 或 > 75% → 判失败（背景没抠掉 / 人物被抠没了） |
| ~~人物中轴位置~~ | 已作废（§十四 P5）；改判**朝向**：视觉模型判「人物面朝画面左还是右」，朝左判失败 |
| 是否有脸 | OpenCV 人脸检测 0 个 → 判失败 |

## 十一、风险

| 风险 | 后果 | 怎么办 |
|---|---|---|
| 1000 张图画风不统一（AI 天然漂移） | 立绘拼在一起像大杂烩，破坏沉浸感（铁律 6） | 风格层提示词逐字固定不变；每 100 张抽 5 张人眼比对；漂了就锁 seed 范围重跑该批 |
| 七成角色没参考图，长相全靠模型编 | 同一家族的人可能长得毫无关系 | 家族主色 + 家纹元素写进提示词做视觉纽带；父子关系（表里有 `FatherName`）在提示词里点明「面部特征承袭其父」 |
| 女性角色仅 40 人，且史料画像更少 | 40 人可能全靠编 | 单独一套女性提示词模板（打扫/小袖/眉墨/发型按身份分档），单独审一轮 |
| `rembg` 装不上（需下载 180 MB 模型） | 只能用纯色键控，边缘变糙 | 提示词把幕布纯度要求写死；实在不行接受略糙边缘，立绘贴左下角边缘不显眼 |
| PNG 导入链路的**透明通道未验证** | 抠好的透明图进游戏可能变成不透明或黑边 | 🔴 **进第六步之前必须先验一张**：现有链路是 PNG→BMP→引擎（[custom-png-import-guide.md](../custom-png-import-guide.md)），而 .NET 存的 BMP 是否保留 alpha **没验过**。不透明就要改导入链路（改存 BITMAPV5 头，或直接从内存建纹理）。**这是唯一可能推翻整个方案的技术点，必须最先验** |
| 网关限流 / 模型下线 | 批量跑到一半断 | 断点续跑已覆盖；模型下线可切 `doubao-seedream-4-5-251128` 或 `gemini-3-pro-image`（同网关，已确认在列） |

### 🔴 接续要点：Py 判左右的方式（新会话直接照抄，勿用肉眼）

**文件 A：`ArtSource/verify_pose.py`（脸判向，已验证可靠）**
- 用 mediapipe **face mesh**（0.10.14 经典版，`pip install mediapipe==0.10.14`；1.x 无 solutions 勿用）
- 方案：`frx = nose(landmark[1].x) − (eye_l[33].x + eye_r[263].x)/2`；`frx ≥ 0.030` = 脸清晰朝画面右（RIGHT）；±0.012 内 = FRONT
- 🔴 读图必须走 `np.fromfile + cv2.imdecode`（cv2.imread 对中文路径返回空，会静默判 FAIL——实战踩过）
- 漏检回退：图上采样 1.6 倍再判；仍 None → 打印 None（不要算 PASS）
- 已废弃：mediapipe **pose** 肩判（半身/肩甲遮挡不可靠）、肉眼方向（本会话镜像误读 N 次）

**文件 B：肩带比（剪影法，唯一可靠肩判）——待从临时脚本提炼进 `matte_rembg.py`**
- 输入：抠图后 512×768 alpha（rembg isnet-general-use + alpha_matting，参数见 matte_rembg.py）
- 算法：
  1. 人物包围盒（alpha>25 的 bbox）；`H = bbox高`
  2. 取上半身带 `a[top : top+0.40H]`
  3. `左半像素数 =(上半身带 y 全部行, x < W/2) 的 alpha>25 计数`；右半对称
  4. `肩带比 = 左半/右半像素数`；**∈ [1.05, 1.65] 通过**（用户标定：阿市1.10✅ 幸村1.49✅ 信长0.73❌ 訚千代0.95❌ 秀吉1.93❌）
- 判定循环：生成一张 → matte → 脸闸+肩带闸 → 任一不过换 seed ≤3
- 生图调用：`gen_portrait.generate`（MODEL 取自 `api_config.json`，gpt-image-2 自动走 `/images/edits` + `images:[{"image_url": datauri}]`，返回 b64）
- 底稿方向预处理：**只对"底稿脸明显朝左"才镜像**（用 verify_pose 先测底稿，别用手眼）；实测 1057 訚千代/517 秀吉均为 FRONT/微左，无需镜像（先前镜像属误操作）
