## 这一步做什么（一句话）

把历史题材的内容变成我们引擎能解析的剧本文件，走**两条路，出同一种东西**：

- **太阁5**：它有现成的事件文件——分剧本文件 169 个（`Knowledge/太阁事件包/EVENT_TW/`）：触发时机、条件、台词、剧情指令都分好了；合并读取 = `TK5AllEvents_merged.txt`（2594 个唯一事件号，编号 = 文件名_事件ID）。**但文件是老格式，改不了，只能照着翻译。**
- **三国演义（以及以后任何题材）**：没有现成事件文件，只有原文。**直接按我们的格式写，不需要先翻译成太阁5 的格式。**

🔴 **产物归属（用户 2026-08-25 模块职责划分裁定，README 裁定 24）**：本管线产出的所有东西（剧本/人物表/城池映射/编译产物/翻译文件）**全部进 ShokuhoTaikouExpansionPack 补充包**；LWN 只提供通用工具（事件解析器/映射器/校验脚本），题材内容零进入核心。

## 🔴 一个决定：三国不先翻译成太阁5 的格式（2026-08-25 用户裁定）

上一版设计是"先把三国原文提取成太阁5 式的事件文件，再走太阁5 那条翻译路"。这个中间步骤是多余的——而且**对一切只有文字的素材都成立**：三国演义、同人小说（信长协奏曲）、轻小说……它们本来就不是太阁5 的事件格式，也不可能都硬转成太阁格式：

- 太阁5 要走翻译，**不只是因为格式旧**：它的脚本结构（trigger 触发 / condition 条件 / perform 演出 / effect 效果，四段分开）本身就有合理性和参考价值——**我们的 01 DSL（condition 条件 + script 步骤）就是从它演化来的**（01 结构决策：太阁5 事件是现成语法范本；16 对照总表：DSL 必须能表达太阁5 全集）。所以太阁5 是**设计参考范本**，翻译它只是因为引擎不能直接执行它的文件（客观事实，不是它不好）。三国、同人小说没有事件结构可参考，只有文字，从零提取**直接写目标格式就是一步到位**；中间格式（先转成太阁格式）对它们毫无意义——硬转等于先学一套旧词表再翻译一遍
- 剧本格式（01 DSL）本来就是按"人和 AI 都好看好写"设计的，提取的人/LLM 直接用它
- 中文名字有官方现成的处理办法：剧本文件顶部放一张对照表（refs，比如 `"曹操": "lord_xxx"`），加载时自动换成游戏 ID。**不需要另造一种"先写中文名"的中间文件**

记一条备忘：将来要是又碰到**别人给的、改不了的剧本文件**（比如太阁6 的事件文件、别的 mod 的剧本），照太阁5 这条路建一张对照表翻译就行；**小说原文永远直接写，不加中间步骤。**

### 🔴 事件优先级规则

同一个 trigger 挂多个事件时，一次时机只演一个——**互斥选路规则见 01**（一次时机只演一个 / priority 分层 / 弱语义 / 文件声明顺序；README 裁定 22，太阁5 同款）。本文件只留转化视角的一条：

- **`屬性` 转化**（🔴 2026-08-26 增补——实测全量分布：一次 2146 + 一次｜弱 256；多次 163 + 多次｜弱 29）：`屬性:一次` → `once: true`（默认）；`屬性:多次` → `once: false`（可重复触发，每次契機+条件满足都演）；`｜弱` → `priority: "weak"`。**"没触发过"的标记、时间窗、前置事件等全部并进 condition 条件**——防重复由调度器自动处理（事件执行过 = 调度器自动记 `Event::<id>.done`，01 三层纪律），Flag 只留跨事件自定义标记
- 角色名 → 游戏 ID：用你之前的匹配表（`taikou_final_v9_inference.xlsx`，信长/光秀已精确匹配）+ 07 织丰 XML。匹配报告统计过 594 个无匹配（2025-12 快照），**但补充包后续已经补过一批**（`ModuleData/Shokuho/heroes.xml`：753 个 Hero 定义等，旧 TaikouContent 时代产物；SubModule.xml 未注册、待 07 审核）——核对以匹配报告为底稿（`Knowledge/太阁5/骑砍2织丰角色ID对应/匹配报告_带候选项.txt`），补全覆盖到的直接用，没覆盖到的才标"缺失"交给 06 补造
- 城池名 → 游戏 ID：用 Taikou5City 映射表 + 07 织丰 XML。实在对不上的就近找一座城顶替（数据里标记，可随时改）

**③ 指令对照**（太阁5 四段里的 **perform 段 + effect 段**）——太阁5 的命令怎么换，16a-DSL翻译总表.csv 命令行已经按组给全了，**但翻译前先做一次拆解**：

> 🔴 **先拆两层（perform 表现层 / effect 结算层，2026-08-25 用户裁定）**：太阁5 的一段剧情指令是表现和结算**混排**的（对话到一半触发"武将死亡"），翻译时按时间轴拆开：
> - **表现层**——玩家看得到的（對話/變名對話/BGM/圖片/登場退場）→ 全进 05 演绎剧本（StoryJson），事件文件里只留一个"播放这段"的引用（perform 步骤）
> - **结算层**——世界真的发生的事（武將死亡/勢力滅亡/城主變更/宣戰/改名）→ 翻译成 01 动作（effect 步骤），在演出进行到该发生的时刻执行（01：演出与效果交错，**不是演完再结算**）
> - 🔴 **世界结算唯一**（README 裁定 22）：结算动作全局只执行一次；玩家不在场时演出跳过，结算照常

拆完之后按四类落位：

- **表现层指令**（對話/變名對話/BGM/圖片）→ 05 演绎剧本（StoryJson），长对白进演绎剧本，事件文件里只留一个"播放这段"的引用——**不是照着念**
- **结算层指令**（武將死亡/勢力滅亡/城主變更/宣戰/改名/軍團指令）→ 01 动作注册表（16a CSV 命令区）；表外动作 = 回填生成字典（ACTIONS/MOD_NATIVE）+ 重跑再实现（軍團指令这类挂 02，按 CSV 分组）
- **流程控制指令**（調查/分歧/場合分歧/更新）→ 变成 01 的条件和 script 步骤——这是事件的结构，不算表现也不算结算
- 🔴 **場合分歧/主人公分歧 翻译规则（2026-08-26，01 if 步骤）**：块结构 **1:1 → 01 骨架 `if` 步骤**（`then`/`else`），**禁止拍平成多条 when**——拍平 = 漏 when = 静默语义错误（validator 查不出），嵌套 = 结构错误（括号不配对，静态可查），而翻译是 Agent 干的，结构照抄最不容易错（09b 漏行教训同族）。按块内容分四类：
  ①**纯效果块** → 骨架 `if` 步骤（kiyasu 示例为范本）
  ②**块含对白/自语** → 分支整体进演绎剧本（🔴 if 块，与骨架同构——choice 写 Ctx 槽 + 后续 if 路由，2026-08-26 goto 已移除）
  ③**块含世界结算**（武將死亡/宣戰/城主變更…）→ 结算唯一纪律不变（if 只是选路，结算只落一次）
  ④**`場合別`/单命令条件** → 保留 when 门控（非块结构，不引入 if）
  配套：场景内进出设施（`進入設施`→scene_enter / `離開設施`→scene_exit）按 01「起点环境 + 中途切换」段翻译——进设施演 3D 段、出来回 campaign，成对出现，3A 读条代价能缩则缩
- 🔴 **裸 `分歧:(N)` 语法 = 按值分支（2026-08-26——频次 19,424，全语料最高频流程命令，绝大多数是选择结果路由）**：
  ```
  TK5：選擇:[[請教他]][[拒絕]]   ← 玩家选择，留下选项索引
       分歧:(1){ 拒絕线 }         ← 分歧:(N) 按索引分线（N = 选项序）
       分歧:(0){ 请教线 }
  我们：演绎剧本 choice（选项按 TK5 顺序，effect = ctx_set 写 Ctx 命名槽，值用可读语义词）
       骨架 if ((Ctx::<槽>) == "值")   ← kiyasu 范本，同构 TK5 的 分歧:(N)
  ```
  ①`選擇` → choice 节点（演绎剧本内）；**选项 effect = `ctx_set` 写 Ctx 命名槽，值用可读语义词**（`"accept"`/`"reject"`）——**禁止用数字索引当值**（魔法数字可读性差，改选项顺序 = 全链跟着改）
  ②`分歧:(N)` → `if ((Ctx::<槽>) == "值")` 路由（骨架与演绎剧本同构）；分支含对白 → 走上面规则②进演绎剧本 if 块
  ③变体：`分歧` 的值也可来自前面 `更新` 设的变量——按 16 §一 三档作用域归档（事件内 → Ctx；跨事件 → Variable/GlobalSlot），再以 if 路由
  ④纪律：选项顺序 = TK5 索引顺序，禁止乱序；选择结果跨事件要读 → 升 Flag/Variable（01/16 纪律，09b 教训）
- 🔴 **主人公系判定写法（2026-08-26，主人公 = `Hero::MainHero`，16 §一裁定）**——不是专有步骤，是条件写法：

# 第二条路：小说原文（直接写）

> 🔴 **前提：必须有一个成熟世界观 mod 做底，小说不能凭空导入**——人物、城池、地形、角色基建全都要有落点：
> - 权游 mod → 冰与火之歌；衣谷三国 mod → 三国演义；织丰 mod → 太阁5 + 信长协奏曲（同人小说）
> - 没有世界观 mod 的背景，提取出来的人物/城池没处安放（refs 表没东西可映射、validator 引用检查全挂），导入无意义
> - 源 A（太阁5 翻译）其实也是这个前提的隐式版本——太阁5 之所以能跑，正是因为织丰这个成熟 mod 提供了战国世界和匹配表

> 这条路是给**没有现成事件文件的题材**准备的（三国演义/后汉书/权游原著/**同人小说如信长协奏曲**）——把小说/史书/同人文原文**直接写成我们的剧本**，写完就能被引擎读，不用再翻译。

## 1. 写出来的东西长什么样

直接就是 01 格式的剧本：

- 条件直接用剧本格式的语法写；人名/城名先写中文（曹操/洛阳），**文件顶部放一张对照表（refs）声明它们对应哪个游戏 ID**——加载时自动换成 ID
- 台词：长对白直接写成 05 的演绎剧本（StoryJson），事件文件里只留"播放这段"的引用——和太阁5 那条路出口完全一样
- 🔴 **每段台词都要能回查原文**：事件注释里标"哪回/哪段"。这既是防 AI 编台词，也是人工抽查的依据
- 时机：直接写成引擎能解析的样子（每日型（daily）= 年份/日期条件；进据点型 = 位置条件 + 注释"以后挂检查点"；事件链内 = script 步骤）——没有太阁5 词表那一层

```jsonc
// 三国演义第一回 → 直接写成的剧本（示意）
{ "id": "huangjin_revolt",                     // 事件 ID
  "refs": { "张角": "lord_huangjin_zhangjue", "刘焉": "lord_han_liuyan",
            "洛阳": "town_luoyang" },           // 对照表：中文名 → 游戏 ID
  "condition": "and( (Time::year) >= 184,           // 中平元年（以演义为准）；防重复由调度器承担（01 三层纪律）",
  "script": [
    { "step": "perform", "playbackId": "huangjin_proclaim" },   // 台词在演绎剧本里
    { "step": "effect", "action": "spawn_clan", "clanId": "clan_huangjin", "leader": "Hero::lord_huangjin_zhangjue" },
    { "step": "effect", "action": "declare_war", "a": "Faction::Kingdom.han", "b": "Faction::Kingdom.huangjin" }
  ] }
// 演绎剧本 StoryJson/huangjin_proclaim.json 里：张角喊"苍天已死，黄天当立！"（第一回原文摘录）
// 来源锚点：第一回·宴桃园豪杰三结义
```

## 2. 提取流程（五步）

0. **确认世界观落点（前提检查）**——选好前置世界观 mod（织丰/衣谷三国/权游…），盘点它的已知 ID（人物/城池/文化，07 素材表式的盘点），评估素材世界能不能装下：装得下才开工；装不下的部分就近映射/顶替（标记）；整体装不下的题材放弃，别硬提
1. **把原文切成段落**——按回目/纪传切，每段标上年份（演义里有纪年直接取，没有的按上下文推，标"推定"）。**时间线乱的素材（穿越/平行世界/回忆插叙——信长协奏曲这种）按素材自己讲的顺序整理，标好出处，别强行对照史实**。得到一张段落表（段号 + 年份 + 原文）
2. **从段落里挑事件**——一段剧情提炼成一个"事件候选"：谁、在哪、什么时候、起因、经过、结果、能摘的台词。**一个事件可以跨好几回，一回也可以出好几个事件**；不推进剧情的段落（景物/闲笔）跳过。得到候选表（人提 + AI 帮忙）
3. **把候选写成剧本**（AI 写初稿，人抽查）——按上面的样子写成 01 剧本 + 演绎剧本。**台词必须来自原文**，写不出原文没有的台词；真要加戏，必须标记"演绎补写"，放进演绎剧本而不是事件本身。抽查：首版每批 100% 人工过一遍，熟练后定比例（建议 ≥30%），重点看时机合不合理、条件有没有把故事讲对、台词是不是原文的
4. **跑校验**——走 01 的 validator：语法对不对、用到的词在不在注册表、引用的名字在不在对照表里、flag 有没有人设置、本地化 key 全不全……错误必须修，警告人工确认

|---|---|---|
| 0 | 确认世界观落点（前置 mod 盘点 + 素材世界装得下评估）| 落点评估记录；装不下项已标记 |
| 1 | 选章节（先提名场面，不做全本——对标太阁"先提桶狭间/本能寺"）| 章节清单 + 段落表 |

## 4. 这条路容易踩的坑

- **AI 会编台词**——台词必须能回查原文段落，编的台词显式标记"演绎补写"，不进事件本身
- **纪年会错位**——演义纪年 vs 史实纪年不同是常态，**以素材为准**，标好来源，别替素材纠偏（那是 14 走向约束的活）
- **同人小说的剧情本来就是改写历史**（信长协奏曲 = 穿越改变世界线）——**这正是现成的 IF 线素材**（本工程支持 IF 线，README 裁定 3），提取时照单全收，别按史实"纠回正轨"
- **别自创词**——提取碰到剧本格式表里没有的写法（比如战争规模/多势力混战）→ 回填 16 注册表（01 的纪律），不许自创
- **对照表要跟着长**——校验靠 refs 对照表和人物表，第 4 步的表要跟着第 1-3 步同步做，别最后补

# 第三件事：剧本里提到的人/城/势力，游戏里得有定义

前面两条路产出的是"剧本说了什么"——但剧本每引用一个对象（曹操、洛阳、汉室），游戏里都要有对应的静态定义（角色、城池、文化、家族、王国），不然引擎解析时查不到，剧本就跑不起来。这些定义通常由**前置题材 mod** 提供：织丰 mod 提供战国的人物城池，衣谷三国提供三国的。**前置 mod 覆盖不全的部分，在补充包里补 XML 数据**（补充包的 `ModuleData/Shokuho/` 下已有 heroes/settlements/spcultures/spkingdoms/clans 的 XML 样例，照这个形态做）。

## 怎么补（四步）

1. **盘点缺口**——剧本引用了哪些对象，对照前置 mod 已有的定义，列出缺口清单。这就是 07 §3 素材表"关键 ID 确认（信长/京都等剧本引用对象）"做的事——**每接一个题材，第一步先做这份盘点**，别等剧本写完了才发现缺人缺城
2. **分类补全**（每种对象处理办法不一样）：
   - **人物**：优先把剧本角色映射到前置 mod 已有的人；真没有的才补（写补充 heroes.xml）。临时出场的小角色也可以靠运行时补造（06），不一定要静态定义
   - **城池**：⚠️ **地图上没有的位置补不出来**——城池必须有前置 mod 地图上的实际位置，光写 XML 只能补"城内组件/归属/文化"，补不出一个不存在的城。mod 里没有这座城 = 就近映射已有城顶替（归一表里标记，可随时改）
   - **文化/家族/王国**：可以补（spcultures/clans/spkingdoms），但补出来的东西**引用链不能断**——家族成员得是已有角色、王国得挂已有文化、文化的兵种得是已有兵种模板，一环悬空全链崩
3. **补完跑加载校验**——XML 里引用的每个对象都得能解析（铁律 5 的两轮策略），**反向引用也要查**（有没有别的东西引用了你补的对象但指向悬空）；🔴 **最终以游戏启动加载为准**——补的数据参与引擎加载，悬空引用 = **整个游戏起不来**（不是跳过那个对象），本地加载验证过才算完
4. **登记进"已知 ID 清单"**——validator 的引用检查（01 检查项 3）认这份清单：前置 mod 的 + 我们补的，补一个登记一个，validator 才有得查

## 纪律

- 🔴 **补全是交叉引用图，不是零散加文件（2026-08-25 用户警告）**——人物 ↔ 家族 ↔ 王国 ↔ 文化互相引用（Hero 的 faction/所属、Clan 的 leader/成员、Kingdom 的 ruler/文化、Culture 的兵种模板），**人物关系（父/母/配偶/子女）也在这张网里**。**缺一个节点 = 整个游戏起不来**（引擎加载时按 ID 解析，悬空引用 = 模块加载失败，不是跳过那个对象）。所以补全必须**成组补**（一个家族连带它的成员/领地/文化一起落，别零敲碎打）、**整图验证**（不光查"我引用的存在"，还要查"引用我的存在"——补了个 Hero 当某 Clan 的 leader，那 Clan 必须真在），**自造节点越少越好**（能用前置 mod 已有节点的绝不自造，自造一个就多一个链接头）
- 🔴 **前置 mod 已有的东西绝不重复定义**——重复 = ID 冲突/覆盖打架，引用铁律 5：先查已有，再决定补
- 🔴 **零资源搬运**——补的是"没有的"，不复制前置 mod 的素材（补充包铁律 2）；场景/兵种/装备等美术资源同理：能复用前置 mod 的绝不自造
- 补全产物 = 补充包 ModuleData 下的 XML + SubModule.xml 注册，**不进 LWN 核心**（裁定 24）
