## 这一步做什么（一句话）

我们有现成的剧本库：**太阁立志传5 的 2594 个事件**（已经在 `Knowledge/太阁事件包/` 里，是结构化的：触发时机、条件、台词、剧情脚本），还有你之前做的角色匹配表。这条管线把它们翻译成我们引擎的格式——**不用从零写剧本，重点是"翻译"和"适配"**。

翻译四件事：①事件（触发时机/条件/效果/台词）②人物（太阁5 角色名 → 织丰游戏内角色 ID）③城池（太阁5 城池名 → 织丰城）④对话演出（太阁5 的指令 → 我们演出引擎的指令 → 预编译产物）。

🔴 **产物归属（用户 2026-08-25 模块职责划分裁定）**：本管线全部产物（剧本/人物表/城池映射/编译产物/翻译文件）**进 ShokuhoTaikouExpansionPack 补充包**；LWN 只提供通用转化工具框架（解析器/映射器），题材数据零进入核心。

## 玩家视角

（玩家看不见这条管线，它决定剧本内容从哪来）——桶狭间/本能寺的剧情文本、人物关系、事件链条，绝大多数直接来自太阁5 原版剧本，而不是人工重写。

## 怎么实现（六个部件）

1. **事件解析**——读太阁5 事件文件（JSON 结构现成），先只提取桶狭间/本能寺相关的事件子集（2594 个不全转，按章节提）
2. **三张翻译表**（太阁5 的世界 → 骑砍2 的世界）：
   - 触发时机：太阁5 的"发生时机"（进据点时/战斗结束时/评定时/每月结算时…）→ 我们引擎的检查时机（对应骑砍2 的事件：进聚落/战斗结束/评议会/每日结算…）
   - 条件：太阁5 的条件（年/月/某人生死/某人在哪/某城归属…）→ **01 DSL（文本表达式）**：去掉"調查:"前缀 + 域映射（據點→据点、人物→人物、狀況::年→时间::年）+ 名称归一（那覇之町→逻辑名，映射表生成）+ 操作符照搬——太阁5 的 `調查:(據點::發生據點)!=(據點::那覇之町)` 翻译为 `(据点::发生据点) != (据点::那霸町)`（引擎不解析太阁5 格式）
   - 指令：太阁5 的剧情指令（换 BGM/分歧/代入人物/对话/登场退场…）→ 我们演出引擎的指令
3. **角色归一**——直接用你之前的匹配成果（`taikou_final_v9_inference.xlsx`：太阁5 角色 → 织丰 ID 的对照表，信长/光秀已精确匹配）：生成剧本人物表；没匹配上的（约四成）标"缺失则补造"，由 06 补造
4. **城池归一**——太阁5 城池表 → 织丰城映射（你之前的 Taikou5City 表）；实在对不上的就近找一座城顶替（数据里标记，可随时改）
5. **对话翻译 + 预编译**——太阁5 对话指令 → 演出引擎指令（翻译不是直读）→ 走 05 的编译器出预编译产物；每段剧情自动标"轻重等级"（哪些看字、哪些亲自跑图、哪些亲自打），人工抽查校正
6. **本地化**——所有台词走翻译表（引擎机制），产出中文翻译文件
7. 🔴 **产物校验**——每次产物产出后跑 **validator 自检查**（01「自检查脚本」）：语法/注册表/引用 ID（已知清单）/refs/flag 一致性/事件间引用/本地化 key/资源引用/剧本结构；错误阻断、警告提示；**发布前必跑**

## 要注意的坑

- 2594 个事件量大——先按章节提子集，不做全量
- 太阁5 的"时机"语义和骑砍2 不完全一样，触发点映射要人工核对
- 匹配表中文列是旧编码，读取时要转码
- 没匹配上的角色太多（约 594 人）——首版只补剧本关键角色，不是全员
- 轻重等级自动分配要抽查（AI 分的不一定准）
