## Context（为什么做）

现在有**两套各写各的临时实现**：

| 现有 | 做法 | 问题 |
|---|---|---|
| 扛人 `Combat/GrappleCarry.cs` | 每帧把被扛者 `TeleportToPosition` 到扛人者脚下，抬升/相对位移靠被扛者 clip 的根骨轨 | 目标瞬间被拽到发起者身上；动作结束两人重叠；逻辑位置与看到的位置始终差一截 |
| 处决 `custom.exec_pair`（`Debug/MyCommands.cs`） | 把目标摆到"玩家正前方 2 米"再同帧播两条 clip | 2 米是拍脑袋的测试值，不是动画首帧的真实相对站位；结束后受击方弹回站立 |

两条都不可复用，且都没有"结束时把最终位置交给 agent"的规则。本轮把它们统一成一套通用双人动作体系。

## 一、核心模型（四条铁律）

1. **角色固定**：`attacker`（发起者）+ `defender`（目标）。发起者负责走到站位；目标只做锚点，**起手那一帧原地不动**（挂接期间由运行时按相对位置每帧摆位，这是跟随，不是起手瞬移）。
2. **首帧站位是数据**：配对动画的第一帧自带相对站位，离线量出来写进配对表（`stance`：右/前/朝向）。运行时按数据摆位，**禁止再把两人坐标设成一样**。
3. **任何双人动作都只有两个参与者**：
   - `attach="none"`：一次性（处决）。
   - `attach="persistent"`：持续性挂接（扛人 / 人挂坐骑）。
   - **坐骑也是一个参与者**：把 NPC 放到坐骑上 = 一对「坐骑 ↔ NPC」的双人动作（坐骑当 `attacker`/锚点，NPC 当 `defender`）。坐骑侧 `play="none"`，只提供位置与朝向。
   - **交接（handoff）**：从「玩家 ↔ NPC 扛人」过渡到「坐骑 ↔ NPC」时，旧 pair 的 attacker（玩家）演完放下就退场，defender 原样转交给新 pair。**交接那一瞬有第三者，交接完成后仍然是两个人。**
   - **玩家与 NPC 完全平权**：任一侧都可以是玩家（发起者 / 被扛者 / 被放到坐骑上的人），代码里没有 `Agent.Main` 分支；差异只在控制租约（冻结/解冻/还相机/action_set）。
4. **位移只认一个来源**（见第四节）：
   - 一次性直线位移 → 用 clip 的 `displacement` 字段（引擎自己推 agent）。
   - 循环/挂接 → **绝不开 `displace_position`**，相对位置靠 clip 根轨，agent 位置由运行时摆。
   - 结束只提交 **X/Y + 朝向**；**Z 永远不提交**（agent 的 Z 写不进去，竖直只能靠 clip 根轨）。

## 二、数据表 `ModuleData/DesignData/PairActions.csv`

**用 CSV，不用 XML。** 这是一张"一行一个双人动作"的扁平设计表，和 `Camera.csv` 同类；项目已有运行期 CSV 读取器（`Data/DesignDataLoad.cs` 的 `CsvLoader.LoadTable`，范本 `Camera.csv`），不需要再写一套 XML 解析器。

**格式 = `Camera.csv` 的四行头**（🔴 不是 `Knowledge/.../csv/` 的两行头，那是离线表）：
1. 英文列名
2. 类型（`string` / `float` / `bool` / `list`）
3. 中文注释（装载器跳过，给人看）
4. 数据行

**约定**（2026-10-19 精简：63 列 → **14 列**）：
- **只留运行时真的会读的**：能由 clip 元数据 / 适配器 / 全局常量决定的，一律不进表。
- 两侧同值的合并成一列：`EnterEvent` / `ExitEvent` / `Motion`。
- 侧别只留"播什么"：`Attacker_Play` / `Defender_Play` 写 `machine:状态机名` 或 `action:动作名`，空 = 不播。
- 布尔写 `True` / `False`；值里禁止半角逗号。
- `ID` = 唯一键；表里没有的 id = 明确失败（`custom.pair verify` 报错），不做代码兜底。
- 动作名/状态机名不在装载期解析；运行时 `Begin` 再判 `ActionIndexCache.Create(...).Index <= 0`。
- 🔴 **适配器找行 = 按它自己拥有的状态机名**（`FindByMachines("carry", "bind")`）——**不搞 Role / 第二套 ID**；同一状态机组只能有一行。
- 🔴 **`HandoffTo` / `HandoffOn` = 交接配置**（不是结束策略）：`HandoffOn` 是触发动作名（如 `put-on-mount` = 【放上马背】），`HandoffTo` 是后继 pair id；交接时调用方从本行读这两列，从后继行读 `EnterEvent`/`ExitEvent`/`Stance_*` 作为参数——**触发、目标、姿态全在数据里**。
- 🔴 **不再进表的**（统一用全局默认 / 适配器 / clip 元数据）：`Approach_*` 调参、`Playback_*`、`Disp*/Commit*`、`Attach_Target/Offset*`、`End_Commit/Correct*/Right/Forward/Tolerance/ReleaseAI`、`Interrupt_On`、`Camera_*`、`Stance_Source/Stance_Verified`、`YawSource`、`Initiator/Anchor`（合并成 `Start`）、`Requires`（**前置条件归适配器/入口**，不在表里放 token 白名单）。

### 列（14）

| 列 | 类型 | 含义 |
|---|---|---|
| `ID` | string | 唯一键 |
| `Start` | string | `preposition`（发起者先走到站位，默认）/ `handoff`（只能由另一个 pair 交接启动） |
| `Stance_Right` / `Stance_Forward` / `Stance_Direction` | float | defender 相对 attacker：右（+X）/ 前（+Y）/ **水平面方向**（度，0=同向，180=面对面）。🔴 **没有 Z 列**：默认两人同处一个水平面；竖直由地面/clip 根骨轨负责 |
| `Attacker_Play` / `Defender_Play` | string | 空 / `machine:状态机名` / `action:动作名` |
| `EnterEvent` / `ExitEvent` | string | 两侧共用的进出时刻名（如 `carry-trigger` / `put-trigger`；交接/取下也读后继行的这两个） |
| `Motion` | string | 两侧共用：`engine`（一次性 clip 带根运动）/ `none`（原地 / 持续挂接） |
| `Attach_Mode` | string | `none` / `persistent` |
| `End_Policy` | string | `release` / `kill_defender` / `ragdoll_defender` / `hold`（**最终处置**：还控制 / 处死 / 布娃娃 / 保持） |
| `HandoffTo` | string | **交接目标**（后继 pair id）；空 = 不能交接 |
| `HandoffOn` | string | **交接触发动作名**（如 `put-on-mount` = 【放上马背】）；与 `HandoffTo` 成对 |

### 三条样例

| 列 | `grapple_carry` | `mounted_on_mount` | `execution02` |
|---|---|---|---|
| `Start` | preposition | handoff | preposition |
| `Stance_Right` / `Stance_Forward` / `Stance_Direction` | 0 / 0 / 0（重烘后 -0.735167 / 0.084623 / 0） | 0 / -0.55 / 0 | 0 / 3.70 / 180 |
| `Attacker_Play` | machine:carry | — | action:act_execution02 |
| `Defender_Play` | machine:bind | — | machine:executed |
| `EnterEvent` / `ExitEvent` | carry-trigger / put-trigger | horse-trigger / put-trigger | exec-hit / exec-rise |
| `Motion` | none | none | engine |
| `Attach_Mode` | persistent | persistent | none |
| `End_Policy` | release | release | release |
| `HandoffTo` / `HandoffOn` | mounted_on_mount / put-on-mount | — / — | — / — |

> `grapple_carry` 的 `Stance_*` 来自装机包 `lwn_core.tpac` 的 `tpaccli animpos`（lift 首帧 `(-0.735167, 0.084623)`）。
> 🔴 **当前实施阶段 CSV 里先写 0 / 0**（复现旧的"两人坐标重合 + clip 自带偏移"）；重烘 4 条 clip 后再改成上面这对值。
> `mounted_on_mount` 的 `-0.55` = 现有 `GrappleCarry.HorseBackOffset` 默认值，尚未过接触尺子（实机校准后直接改表）。
> `execution02` 的 `3.70` 是候选值，必须用 `pair_stance.py --mode contact` + 实机接触帧定稿。
>
> 🔴 **`mounted_on_mount` 两侧 `Play` 空是故意的**：坐骑跑自己的移动动画；人的 `马背` 状态由 `bind.xml`（`GrappleBind`）驱动。
> 本 pair 只做**挂接摆位**（`Attach_Mode=persistent`），交接/取下用它的 `EnterEvent`/`ExitEvent`。
> 角色：**attacker = 坐骑（锚点/参考系）· defender = 被放上去的人（被摆位/被挂接）**。
>
> 🔴 **`execution02` 的 defender 走 `machine:executed`**：状态机 `executed.xml` = 受击 → **躺地循环** → 起身。
> **交互演完 pair 立即解散**（攻击方与受害者都不再被它占用）；受害者转入 `AgentStatus`（状态名 `downed`）继续躺着。
> `custom.status end` = 播放 `ExitEvent`（起身）后放人；`custom.status kill` = **跳过起身、直接补刀**。
> `躺地`/`起身` 目前指向被绑套件的占位 clip（`binded_lay_loop` / `binded_lay_end`），等专用 clip 出来只改 `action_sets.xml`。

> `Stance_Right/Forward` 是 **defender 相对 attacker**。发起者的目标点 = `defender.Position − R(attackerYaw) × stance`。`Stance_Direction` 同时决定 defender 起播时被转到哪：`attackerYaw + stance.direction`。
>
> 🔴 **站位只在水平面上**：`Right/Forward/Direction` 三个量决定"站哪、朝哪"；没有 Z 列。默认两人同处一个水平面，竖直由地面解算与 clip 根骨轨负责。
>
> 关键连续性：发起者到位后，`attacker.Position + R × stance` **恰好等于 defender 原来的位置** ⇒ 起手那一刻被扛者原地不动；之后每帧跟着发起者走。

### 阶段机

```
Idle → PrePosition → Align → Starting → Playing / Attached → (Handoff) → Ending → Idle
```

| 阶段 | 做什么 | 失败/中断 |
|---|---|---|
| **PrePosition** | 算发起者目标点；玩家：冻结控制 + 按 `playerSpeed` 插值滑过去；NPC：`SetScriptedPosition` 寻路 | 距目标点 > `maxDistance` → 拒绝并提示还差几米；超时/取消/目标消失 → 归还控制 |
| **Align** | 精确贴到目标点、`SetMovementDirection` 摆朝向、停交互 | 目标死亡/锚点转动过大 → 中止 |
| **Starting** | **先把两侧动作全部解析并校验**，再在同一个 C# 调用里连续写两侧（中间不 await、不插帧） | 任一侧失败 → 另一侧立刻清通道，整对中止 |
| **Playing** | 一次性：只读进度、处理中断；`motion=clip` 时每帧连续推 | 超时/死亡/上马/对话 → 中止 |
| **Attached** | 每帧摆位 + 两侧状态机 Tick；`RequestStop` 先演退出 clip | `bind_lost`/任一方消失 → 硬收 |
| **Handoff** | defender + 租约原子转交给后继 pair（坐骑）；旧 attacker 演完退场 | 后继 pair 校验失败 → 退回 `Ending`（release） |
| **Ending** | 提交 X/Y/朝向、执行 `end.policy`、归还 lease | 任一步失败只记日志，不阻断其余收尾 |

### 四条实现纪律

1. **控制权是借的**：`PairControlLease` 只记"我拿走的"（玩家控制器 / NPC AI 暂停 / 脚本移动 / action_set / 通道 0 / 交互 / 相机角度），结束时只归还自己那份。`GrappleBind` 已经冻住的人，pair **不得解冻**。
2. **玩家自动小步要还相机**：`V.SetPlayerControlFrozen` / 解冻会让引擎把 `CameraBearing` 重置成移动方向、俯仰清零。冻结前记下角度，解冻后用现成的 `SpringArmRig.WriteBackLookToEngine(yawDeg, pitchDeg)` 写回，避免镜头跳。
3. **同帧且只同帧**：两侧 `Play` 必须在同一方法内完成；动作名先判 `act_none`，NPC 侧时长按 `as_human_warrior` 查。
4. **一人一配**：全局 `Agent → PairActionInstance` 表；已在别的 pair / 击晕 / 对话 / 决斗 / 骑马中 → 返回 `busy`，不硬启动。

### 交接（handoff）

- 一个 pair 在挂接期间可以把 defender 交给后继 pair：`RequestHandoff(successorId, newAttacker)`。
  🔴 **`successorId` 来自本行的 `HandoffTo`**（数据），不是代码里写死的；`RequestHandoff` 只接受这个 id。
  "扛起"平时仍是 `End_Policy=release`（直接放下），放上马背是玩家另外触发的一条动作。
- 交接时序（扛人 → 放上坐骑）：
  1. 旧 pair：attacker 播本行 `ExitEvent`（放下）；defender 的 `bind.xml` 播**后继行 `EnterEvent`**（如 `horse-trigger`）。
  2. **同一帧**创建后继 pair（attacker = 坐骑，defender = 同一个人），**控制租约原样转移**，不经过"释放再接管"。
  3. 旧 pair 的 attacker 演完出机后从 pair 退场；后继 pair 继续每帧把 defender 摆在坐骑上。
- 交接后是**一对「坐骑 ↔ 人」的普通双人动作**：`stance` 就是"人相对坐骑"的右/前/方向，没有坐骑专用字段。
- 取下来（`dismount`）：后继 pair 结束，defender 回到坐骑旁地面并播**后继行 `ExitEvent`**（如 `put-trigger`），然后归还控制。
- 坐骑当 attacker 时 `play="none"`，不播动画；它的位置/朝向每帧现读（`ForwardOf(mount, mount:true)`，优先 `GetMovementDirection`）。
- 坐骑原骑手不受影响：defender 只是视觉上摆在后部，不注册成 `MountAgent`；两者碰撞用 clip flag `disable_agent_agent_collisions` 处理。
- 玩家当 defender 时同样适用：租约把"玩家控制器冻结/相机角度"一起转交，取下来时归还。

### 与现有代码的关系

- `GrappleCarry`：`Begin` 保留钩索侧校验（被绑、站着、≤3m）和武器收还；站位/同帧起播/挂接/结束提交交给 pair 运行时。`AttachCarried` 的每帧摆位移进 `PairActionInstance`。**马背走后继 pair 的 handoff**（目标 = 本行 `HandoffTo`，事件 = 后继行 `EnterEvent`/`ExitEvent`）；`GrappleCarry` 只保留触发入口、坐骑解析、距离校验，摆位交给 pair。
- `custom.exec_pair`：保留命令名和相机参数；**必须带 `pair=<id>`**（代码里不写死动作 id），内部走 `PairAction` 同一条运行时。
- `GrappleBind`：仍拥有 `bind.xml` 的 Tick；pair 只按时刻 token `Force`，不重复 Tick。

## 四、位移与结束修正（防重叠）

| 类型 | `displace_position` | TRF 水平根轨 | 代码每帧推 | 结束提交 | Z |
|---|---|---|---|---|---|
| 一次性 · 引擎位移（推荐） | 开，填 `(X,Y,0)+endProgress` | 保留（只用来量值） | 不推 | 引擎已推完；只做相对位置/朝向校验 | 不提交 |
| 一次性 · 代码推（兜底） | 关 | **必须为 0**（in-place 版） | 按 `commitRight/Forward` 连续推 | 连续推就是提交，不再瞬移 | 不提交 |
| 持续挂接 | **必须关** | 保留（站姿→肩上的相对姿态） | 不推 | 退出 clip 末帧回站姿；有残差才贴回锚点 | 不提交 |

**关键结论：处决结束不重叠，靠的是播放过程中引擎把 agent 推到终点，不是结束时瞬移。** 先做一次 5 分钟实验（第六节步 0）确认引擎开位移时会不会把根轨也算一遍；若双份，改用 in-place 版 clip。

**末帧竖直会弹回**（旧问题，已由"后处置态"解决）：`executed02` 末帧 z≈−0.698（倒地），以前 clip 一结束人就站回原地；
现在 `execution02` 的 defender 走 `machine:executed`，演完进 **躺地循环**，不会弹回。
🔴 **这段躺地不归 pair**：交互演完 pair 立即解散，躺地循环 + 控制权交给 `AgentStatus`（状态名 `downed`）——
`custom.status end` 让它起身，`custom.status kill` 直接补刀。这样处决完一个人可以马上处决下一个。
🔴 **`End_Policy` 与 `ExitEvent` 是两件事**：`ExitEvent` = 离场时播哪个动画接缝（放下/起身）；
`End_Policy` = 离场后怎么处置（`release` 还控制 / `kill_defender` 直接死，**跳过 ExitEvent** / `hold` 保持）。

## 十、经验与坑点（2026-10-22 沉淀）

> 全部是实机踩出来的。按「症状 → 根因 → 固化成什么」写，以后写同类系统照着抄。

### 1. Mission 级行为的 `Current` 必须设在 `OnCreated`

- **症状**：命令报 `PairActionLogic not mounted` / `pair state` 恒为空，但同场景 `custom.pair list` 一切正常。
- **根因**：引擎顺序是「先给**已在列表里**的行为调 `OnBehaviorInitialize`，**之后**才调各 SubModule 的 `OnMissionBehaviorInitialize`」；我们是在后者里 `AddMissionBehavior` 挂上的，而 `AddMissionBehavior` **只调 `OnCreated`** ⇒ 这类行为**永远拿不到 `OnBehaviorInitialize`**。
- **做法**：`Current = this` 写进 `OnCreated()`；`OnBehaviorInitialize()` 里再设一次只当冗余。
- **先例**：`GrappleLogic`（2026-10-03）→ 本轮 `PairActionLogic` / `AgentStatus` 又踩了一次。

### 2. 双人动作演完就解散，后处置态归「角色状态」

- **规则**：`PairAction` 只描述**两个人之间的交互**；演完 pair 释放双方。之后人还躺着（倒地），是**他一个人的状态**。
- **两半分工，少一半都出问题**：

| 职责 | 归谁 | 为什么 |
|---|---|---|
| 姿势驱动（每帧 Tick 状态机） | Mission 级 `AgentStatus` | 战斗场景 `AgentBrain.Tick` 整体早退，脑驱动不了姿势 |
| 位置 / 朝向 / 控制权按住 | 同上 | 同上 |
| 脑占位（拒事件 / 拒清队列 / 拒参战） | `IAtomicAction`：`StatusHoldAction` | 脑只认自己的动作队列；否则被打会爬起来打架、外部清队列会把躺着的放走 |

- **命令分开**：pair 演完 `custom.pair state` = `none active`；状态用 `custom.status state|end|kill`。
- **参照物**：被捆的人 = `GrappleBind`（姿势）+ `BoundAction`（脑占位），同一套分工。

### 3. 交接后收尾别「连坐」

- **症状**：把扛着的人放上马背，玩家上马一走，人从马背上掉下来、被绳子拖在地上。
- **根因**：`GrappleCarry.Tick` 里「旧 pair 结束 ⇒ 整条扛人结束 ⇒ `HardStop`」，而 `HardStop` 会**把后继的「坐骑↔人」pair 一起 Abort**。
- **规则**：交接类流程先确认「**现在谁拥有这个人**」，再收旧的一侧；旧 pair 演完只代表**发起者退场**，不是整条链路结束。
- **落地**：`GrappleCarry.Tick` 的 `OnHorse` 分支 —— 只有 `MountPair == null || IsDone` 才收摊；旧 pair 结束只做「还武器 + 玩家自由」。

### 4. 交互面板：一个行 id = 一个动作

- **症状**：长按界面显示【放上马背】，松手实际把人**放下**了。
- **根因**：扛人四件事（扛起 / 放下 / 放上马背 / 从马背拿下）**共用 `LiftCarried` 一个 id**，执行时再按「当时的世界状态」反推该做哪件事；长按有 0.5 秒窗口，窗口内焦点一变（马出准星 / 目标倒下 / 走近），行被重算成【放下】⇒ 松手执行了【放下】。
- **规则**：
  1. **每个动作一个独立 id**；执行入口只做自己那件事，校验不过就**报原因**，绝不换成另一个动作。
  2. **按住期间锁行**：显示文案、目标（如 `_lastHorseOffer`）全部冻结在按下那一刻，松开后解除。
- **判据**：按住 G 晃视角，行文案不应变化；日志里 `[Interact] <id>` 应与画面一致。

### 5. 交互统一留痕

- `ExecuteInteraction` 入口打一行：`[Interact] <id> | focus=... | ropeHeld=... | carrying=...`。
- 用处：直接拿到「按的是哪个 id / 当时瞄着谁」，不用再靠各系统的行为日志倒推。
- 只覆盖**本 mod 的交互面板**；原版原生交互不经过这里。

### 6. 复位/暂停类 API 的"自打脸"要算进复核

- 实测 `HoldTarget` 里先 `SetIsAIPaused(true)`、再设 `Controller = None`，**后者会把 paused 清掉** ⇒ 复核日志每 0.5 秒都报「AI冻结=False」，但那是**自己写的顺序造成的**，不代表有外部系统在抢。
- **做法**：复核读到的"被还原"先排除自己的写入顺序；排除不掉才去找外部来源。
