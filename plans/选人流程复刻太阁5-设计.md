## 一、要复刻的流程（太阁5 原样）

```
主菜单[剧本] → ① 选剧本（已有，加一个「推荐」按钮）
                 ├ 点剧本名 → ② 选人列表（现有三列：王国/家族/人物）
                 └ 点[推荐] → ②' **该时代的 5 位推荐人物**（列表形态同 ②，只是内容变）
                                ↓ 点某个人名
                         ③ **角色详情页**（新增）——立绘 + 基本情报 + 能力 + 技能 + 列传
                                ├ [决定] → 真正加载世界 + 魂穿该角色
                                └ [返回] → 回 ②
```

**关键变化**：现在点人名是"直接开局"；改成"**先看详情 → 再决定**"（太阁5 就是两步）。

## 二、三个页面的形态（照截图拆解）

### 2.1 选剧本页（已有，只需加一个按钮）

太阁5 原版是：左列剧本按钮 + 右侧大图 + 底部「推荐」按钮。
**我们要加的 = 底部那个「推荐」**（点了进推荐人列表）。

### 2.2 选人列表（已有，形态基本一致）

太阁5 每行 = `头像 | 姓名 / 年龄 | 型（武士型故事…）| 目标描述（两行）`。
我们要调整的：
- 每行补 **头像（minihead）** 与 **型别标签**
- 型别与目标描述 = **推荐人专属**（普通人物没有"型"这一说，可留空或显示身份）

### 2.3 角色详情页（新增，本次主体）

| 区块 | 内容 | 数据来源 |
|---|---|---|
| 左上 | 姓名（大字） | `TaikouHero.CNName` |
| 左下 | **立绘（半身像）** | `ProfileImage.bustup` |
| 右一：**基本情报** | 官位 / 所属 / 据点 / 上司 / 俸禄 / 名声 / 恶名 / 武士功勋 / 忍者功勋 / 水军功勋 / 所属流派 / 武艺师父 / 装备武器 / 装备防具 | 太阁5 字段（部分需映射，见 §六） |
| 右二：**能力情报** | 统率 / 武力 / 政务 / 智谋 / 魅力（五维，条形图 + 数值） | `CommandValue` / `ForceValue` / `GovernValue` / `WisdomValue` / `CharmValue` |
| 右下：**技能情报** | **16 项技能**（足轻/骑马/火枪/水军/弓术/武艺/军学/忍术/建筑/开垦/矿山/算术/礼法/辩才/茶道/医术） | **16 个 `*Skill` 字段**（已核实：`SoldierSkill`/`MountSkill`/`GunSkill`/`NavySkill`/`ArcherSkill`/`CombatSkill`/`MilitarySkill`/`NinjaSkill`/`BuildSkill`/`FarmSkill`/`MineSkill`/`ArthmeticSkill`/`EtiquetteSkill`/`DebateSkill`/`TeaSkill`/`MedicalSkill`） |
| 底部 | 生卒年（`1536～1598`）+ **列传文本**（多行） | `BirthYear`/`DieYear` + 列传——🔴 **列传不在 TaikouHero.csv 里**（已核实 129 列无列传/介绍字段），在太阁5 的 `tg5msg` 文本包里，需另解 |
| 右下角 | `[返回]` `[决定]` | — |

## 三、🎨 UI 版式设计（三个页面的具体长相）

> 原则：**照太阁5 的版式复刻**（本工程的总目标是"还原太阁5"，UI 也是还原的一部分）。
> 下表数值按 1600×900 基准写，实现时按 `ScreenManager.UsableArea` 自适应。

### 3.1 选剧本页 —— 只加一个按钮

太阁5 版式：左列剧本按钮 / 右侧大图 / **底部居中「推荐」**（金色尖头 + 文字）。
现有界面已有前两者，**只补底部那个按钮**（居中、宽 ~260、高 ~54，与「返回」同款 Brush）。

### 3.2 选人列表（推荐人列表同款版式）

太阁5 每行 = 一条横向大按钮（宽 ~800、高 ~92），内部四栏：

```
┌────────────────────────────────────────────────────────────────┐
│ ┌────┐  姓名（大字）            ┌──────────┐                    │
│ │头像│  25岁（小字）            │ 武士型故事│  目标描述第一行      │
│ └────┘                          └──────────┘  目标描述第二行      │
└────────────────────────────────────────────────────────────────┘
   ~88px          ~200px              ~150px          ~330px
```

- **整行是一个 `ButtonWidget`**（`Command.Click` → 开详情页），`Command.HoverBegin` → 行高亮
- 头像 = `minihead` 小头像（数据已有，见 §六·待定 3）；无图时画占位方框
- **型别标签**（武士型故事…）= 带边框的小方块，**推荐人专属**；普通人物显示身份（大名/家主/领主）
- 目标描述 = 两行小字，**推荐人专属**；普通人物留空

**尺寸（1600×900 基准）**：

| 件 | 尺寸 | 备注 |
|---|---|---|
| 左栏 | 宽 ~460，整列左对齐 | 姓名块 高 56 / 立绘 高 ~300 / 生平块 余下 |
| 右栏 | 宽 ~900，三块竖排 | 基本情报 高 ~240 / 能力情报 高 ~150 / 技能情报 余下 |

**技能用"点"还是"数字"**：太阁5 原版是**图标 + 星级**；我们没有那套图标 →
**先用「技能名 + 数值」两列**（图标等美术资产到位再换），或简单用 `●●●○○` 表示档位（**待拍板**）。

### 3.4 交互与状态

| 交互 | 行为 |
|---|---|
| 选人列表：悬停某行 | 该行高亮（`IsSelected` 描边），不影响其它 |
| 选人列表：点某行 | **打开详情页**（不再直接开局） |
| 详情页：`[决定]` | 调现有 `StartingHero.ApplyPending` → 魂穿开局（**开局代码一行不动**） |
| 详情页：`[返回]` | 回选人列表（保留刚才的选中态） |
| 推荐人列表：`[返回]` | 回选剧本页 |

### 3.5 实现形态：**一个覆盖层，两个 prefab 互切**

现在选人界面是 `HeroSelectOverlay`（单一 prefab）。加详情页有两种做法：

| 做法 | 说明 | 取舍 |
|---|---|---|
| **A. 双 prefab 互切**（推荐） | 覆盖层持有两个 prefab（`HeroSelect.xml` / `HeroDetail.xml`），按状态 `LoadMovie` 切换 | ✅ 只占一个层，不涉及层序/焦点问题；✅ 与现有实现同构，改动小 |
| B. 再叠一层 | 详情页另开一层盖在选人层上 | ❌ 之前已经踩过层序/时点的坑，能不加层就不加 |

**推荐 A**：`HeroSelectOverlay` 内部记一个 `ViewState`（List / Detail），切状态时换 prefab + 换 VM 数据。

## 五、🔴 太阁的属性/技能怎么和骑砍2 结合（本设计的核心问题）

> 不解决这个，详情页就只是"一屏好看的数字"——玩家看完进去发现人物跟数字对不上。
> **结论：能映射的全部真正映射进骑砍2 数值（进游戏就带着这个能力），没有对应物的才退化为展示。**

### 5.1 两边的量表（反编译实锤）

| | 太阁5 | 骑砍2 | 写入手段 |
|---|---|---|---|
| 主属性 | 5 维，**0–100** | 6 项（力/控/耐/狡/社/智），**0–10**（`MaxAttribute`） | `Hero.SetAttributeValueInternal`——**internal，需反射**，且被硬钳制到 [0,10] |
| 技能 | 16 项，**0–100** | 18 项（单手/双手/长柄/弓/弩/投掷/骑术/跑动/铁匠/战术/侦察/流氓/统御/魅力/交易/管理/医术/工程），**0–300**（`MaxSkillValue`） | `Hero.SetSkillValue`——**public，无钳制** ✓ |

### 5.2 属性映射（5 维 → 6 属性）

**换算 = 除 10**（太阁 96 智谋 → 骑砍 9~10 智力，接近上限，与"史实军师"的定位相称）。

| 太阁 5 维 | → 骑砍2 属性 | 理由 |
|---|---|---|
| 统率 Command | **统御 Leadership** | 带兵/士气，1:1 |
| 武力 Force | **活力 Vigor** | 近战身体能力（活力含单手/双手/长柄） |
| 政务 Govern | **耐力 Endurance** + **社交 Social** | 内政=管理实务+交涉，两个都占（各取一半） |
| 智谋 Wisdom | **狡诈 Cunning** + **智力 Intelligence** | 算计/医术/工程分别归这两项 |
| 魅力 Charm | **社交 Social** | 1:1（与政务叠加） |
| （无来源） | **控制 Control** | 由**弓术技能**推导（弓术高 = 控制高），否则该属性永远 0 |

⚠️ 换算后取整并**钳到 [0,10]**（引擎本来就钳，我们主动钳以免日志误导）。

### 5.3 技能映射（16 项 → 骑砍2 18 项）

**换算 = 乘 3**（0–100 → 0–300 满量纲）。**只映射有对应物的**：

| 太阁技能 | → 骑砍2 技能 | 备注 |
|---|---|---|
| 足轻 SoldierSkill | **单手 OneHanded** | |
| 骑马 MountSkill | **骑术 Riding** | |
| 火枪 GunSkill | **弩 Crossbow** | ⚠️ 骑砍2 **无火枪**；我们的世界目前也没有火器 → 映射到弩是"名义映射"（数值在，实际用不上）。**或**改为不映射、只展示（待拍板） |
| 弓术 ArcherSkill | **弓 Bow** | |
| 武艺 CombatSkill | **双手 TwoHanded** | 太阁"武艺"= 剑术，骑砍2 双手最贴近 |
| 军学 MilitarySkill | **战术 Tactics** | |
| 建筑 BuildSkill | **工程 Engineering** | |
| 开垦 FarmSkill | **管理 Steward** | 经营/产出 |
| 算术 ArthmeticSkill | **交易 Trade** | |
| 辩才 DebateSkill | **魅力 Charm** | 说服/交涉 |
| 医术 MedicalSkill | **医术 Medicine** | 1:1 |
| 礼法 EtiquetteSkill | **统御 Leadership** | 太阁"礼法"影响交涉与仕官，骑砍2 最接近的是统御 |
| 水军 NavySkill | ❌ 无对应 | 骑砍2 **没有海战** → 只展示 |
| 忍术 NinjaSkill | ❌ 无对应 | 骑砍2 无忍术；**流氓 Roguery** 语义差太远（那是犯罪/偷窃），**不硬凑** → 只展示 |
| 矿山 MineSkill | ❌ 无对应 | 骑砍2 无矿业 → 只展示（或并入工程？**待拍板**） |
| 茶道 TeaSkill | ❌ 无对应 | 纯文化 → 只展示 |

⇒ **12 项真映射 / 4 项只展示**（水军·忍术·矿山·茶道）。

### 5.4 什么时候写进去（关键：**创建英雄时**，不是选中时）

太阁5 是"选谁 = 以谁的能力开始"，我们同理——但**不能等玩家点「决定」那一刻才写**：

| 方案 | 说明 | 取舍 |
|---|---|---|
| **A. 打进模板**（推荐） | 生成期把映射值写进该英雄的 `NPCCharacter` 模板（骑砍2 的角色能力本来就在模板里） | ✅ 数据优先（铁律精神）：能生成期做的别留运行期；✅ 不需要反射写属性；✅ AI 的领主也**天然**带着这个能力（世界更真实） |
| B. 运行期写 | 选人后反射写属性 + 写技能 | 简单，但**只有玩家有**、别的领主还是默认值 → 世界观不一致 |

**推荐 A**：由生成器从 `TaikouHero.csv` 产出"英雄模板的属性/技能块"。
✅ **可行性已核实**：`NPCCharacter` **本来就支持逐角色能力块**——官方各模块实测有 **3707 个** `NPCCharacter` 带 `<skills>` 子块
（不是只能挂共享 `skill_template`）。我们现有的英雄用的是 `skill_template="SkillSet.…"`（共享模板），
改成逐角色 `<skills>` 即可，格式官方有大量现成样例可抄。
⚠️ 但 1117 人 × 16 技能的模板量很大 → **分期**（见 §八·步 5）。

### 5.5 一个必须正面回答的平衡问题

**如果只给玩家所选角色写高数值、别人不变 → 玩家碾压**（太阁5 里信长本就是最强的，太阁玩家也认这个设定，但骑砍2 的 AI 会打不过）。

**解法 = 全员映射**（不是只映射玩家那个）：所有可扮演英雄的模板都按 CSV 映射 →
**强弱关系与原作一致**，而不是"玩家凭空变强"。这也正好是方案 A 的天然结果。

### 5.6 详情页要展示"两套数"

玩家看到的是太阁 5 维/16 技能（原汁原味），但**实际生效的是映射后的骑砍2 数值**。
→ 建议：**主区显示太阁数值**（复刻感），**另加一行小字**说明映射（如「已转译为骑砍能力：统御 9 / 单手 240 …」），
让玩家知道"这些数字是真的会生效的"，而不是装饰。

## 五·补、🔴 **英雄 id 与数据源的对应**（实施前必须先解决——否则详情页取不到数据）

### 问题（已实测）

详情页的数据（五维/16 技能/生卒/立绘）全在 `TaikouHero.csv`，要靠 **英雄 id 查表**。但两边对不上：

| | 织田信长 |
|---|---|
| **我们现在的 id** | `lord_oda_nobunaga` |
| **CSV 的 `ID` 列** | `lord_1_oda`（生 1534 / 卒 1582，史实一致；`CNName` = 织田信长） |

CSV 是**织丰制式**（`lord_1_oda`），我们的 id 是当时随手起的简写。**全量数据（T4）进来时才会自然对齐**，现在是占位期。

### 两个选择

| 方案 | 做法 | 代价 |
|---|---|---|
| **A. 把现有英雄 id 改成 CSV 制式**（推荐） | `lord_oda_nobunaga` → `lord_1_oda`；同步改据点/家族/王国的 `owner` 引用 | 一次性改动（当前只有 3 个英雄）；**早点对齐，T4 全量进来时零摩擦**；符合铁律 20（StringId 用游戏内制式） |
| B. 建一张"我们的 id ↔ CSV id"映射表 | 新增 `hero_id_map.csv` | 快，但**多一张要维护的表**（T4 全量进来后作废） |

> 推荐 **A**：现在只有 3 个英雄，改起来是分钟级；**拖到 T4 再改就要动几百处引用**。

### 数据怎么进游戏（实施细节，按数据优先原则）

🔴 **C# 不解析 CSV**——CSV 是人维护的源，运行期读它 = 每次启动解析 + 格式漂移风险。
按本项目惯例（生成物 + 铁律 22）走生成器：

```
TaikouHero.csv（源，人维护）
   → Scripts/gen_taikou_hero_profiles.py（生成器）
   → Taikou/ModuleData/taikou_hero_profiles.xml（生成物，键=英雄 id，值=五维/16技能/生卒/型别/目标）
   → 运行期：MBObjectManager 读（或直接读 XML）→ HeroDetailVM 消费
```

- **按英雄 id 建索引**：`lord_1_oda` → `{五维…, 技能…, 生卒…}`
- 生成器顺带做**完整性自检**（每行字段齐全、数值在 0–100、id 唯一）——与现有 checker 同风格
- **立绘不在这份 XML 里**（是图片资产，走 SpriteAssetsManager + PortraitRegistry；**已就位**，见 §六·待定 3）
- **列传同样另路**（在 tg5msg，解出后再并进这份 XML 或单独一份）

### 没有数据的英雄怎么办（必须处理的边界）

现有英雄是**占位**（`lord_g` 这种），CSV 里查不到。**详情页必须能优雅处理"查无此人"**：

- 该英雄无 CSV 记录 → **只显示从世界数据能读到的**（姓名/所属/据点/装备/生卒/五域声望），
  **太阁专属面板（五维/16 技能/立绘/列传）显示占位**并标注「暂无史料」
- 理由：短期占位期必然遇到；长期（全量数据到位后）每个可扮演英雄都应有 CSV 记录，这种情况自然消失

## 十、流程改造：把「选时代 + 选人」提到建世界**之前**（2026-09-11 用户裁定）

### 10.1 一句话

现在要**先干等一个长 loading，loading 完才弹选人**；改成**先选完人，再 loading**——loading 变成「加载我选好的这一局」。

### 10.2 现状为什么是反的

不是界面做不出来，是**数据依赖**：选人界面读的是**活世界对象**
（`HeroSelectData.cs:20` 的 `Kingdom.All`、`:40` 的 `kingdom.Clans`），世界没建好读 = NRE。
所以只能等世界建完再弹。**而主菜单阶段的界面机制早就跑通了**——选剧本界面就是主菜单阶段的自建 Screen，已实机通过。

### 10.3 破法：把选人数据整体搬到静态层

今天做的画像表已经把**大半搬完了**（五维/16 技能/生卒/立绘全是静态表）。再补一张**选人目录**，选人界面/详情页就**完全不碰 `Campaign.Current`**。

| 选人界面要的 | 现在的来源 | 改后来源 |
|---|---|---|
| 王国有哪些 | `Kingdom.All`（活世界） | 目录 `<Realm>` |
| 家族有哪些 | `kingdom.Clans`（活世界） | 目录 `<House>`（带 realm 归属） |
| 某家族有哪些英雄 | `clan.Heroes`（活世界） | 目录 `<Lord>`（带 house 归属） |
| 英雄显示名 | 活世界 `Hero.Name` | 目录 `name`（本地化键，沿用现有 `TAIKOU_hero_*`） |

| 立绘 | ✅ 已是静态（ProfileStages.csv） | 不变 |

**自检（生成期，不通过就 exit 1）**：① 目录 id 集合 == heroes 文件 id 集合 ② 每个 `house` 的 `realm` 必须存在 ③ 每个 `Lord` 的 `house` 必须存在 ④ identity 值必须在 key 表里。

### 10.5 新流程

```

   ├ 点剧本名 → 选人（主菜单阶段的新 Screen：三列树 / 详情页）──┐

```

- 世界建好后：**有选中英雄 → 直接落地进图**；**没选（自定义）→ 走建号流程**（现状不变）

**阶段卡的语义**：`stage` 列是**主题/称号**自由文本（信长「上洛」/「若君」、秀吉「羽柴」/「藤吉郎」/「秀吉」/「太阁」、
半蔵「侍」/「忍」、九鬼「海」/「将」），**数据里没有「哪张对应哪一年」的字段**。

🔴 **由此发现并修掉一个真 bug**：木下藤吉郎的**第 1 张卡是「羽柴」**——那是他改名**之后**的形象，
1560 开局用它等于让 24 岁的秀吉顶着中年的脸。

**修法 = 后缀匹配**（生成器里做，LWN 不认识任何 stage 词）：
该时代人名以某张卡的 `stage` 结尾 → 用那张。
- 1560「木下藤吉郎」→ 后缀命中「藤吉郎」✅（唯一）
- 1582「羽柴秀吉」→ 后缀命中「秀吉」✅（唯一；「羽柴」是前缀不是后缀）
- 其余 6 位领主（信长/柴田/半蔵/九鬼/纳屋/柳生）无命中 → **回落第 1 张**（不猜）

**为什么不用更激进的规则**：宁可用默认卡，也不要把一套**没有数据依据**的年代映射编出来。
要精确，得给 `ProfileStages.csv` 的 `stage` 补一列年代/序（数据侧决定，见下）。

**待定（要用户拍板）**：
- a. 详情页展示该角色的**多张阶段卡**（44 人受益）——需 UI 形态设计
- b. **情绪立绘接进对话/IM 头像**——资产与轮子都现成，缺的只是接线
- c. 给立绘表的 `stage` **补年代列**——补了就能精确按年代取卡，比后缀匹配可靠得多
