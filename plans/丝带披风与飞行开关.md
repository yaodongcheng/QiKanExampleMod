# 丝带披风 · 飞行开关（方案）

> 状态：**待审批**（2026-10-09 立）
> 一句话：给玩家做一条超长丝带披风，**走披风装备槽**；**穿着才能飞，脱了就飞不了**。

---

## 一、定下来的事（用户 2026-10-09 裁定）

| # | 决定 |
|---|---|
| 1 | 形态 = **单条超长丝带**（颈后一条，约 3 米） |
| 2 | 开关 = **披风即唯一开关**，Mod 选项里的 Flight 总闸删掉 |
| 3 | 获取 = **商店可买 + 战利品可掉** |

---

## 二、为什么走披风槽（三条已核实的事实）

1. **槽位现成** —— `EquipmentIndex.Cape = 9`（反编译确认）。原版有 **91 件**披风类物品，定义在
   `Modules\SandBoxCore\ModuleData\items\shoulder_armors.xml`。

2. **原版披风自带布料模拟** —— 用 tpaccli 实测原版 `battania_cloak_furr` 的结果：

   ```
   ClothMetamesh = clo_battania_cloak_furr   ← 低模替身在算物理
   UnknownString = "human_body"              ← 碰撞胶囊
   meshFlags     = [uses_cloth_simulation]
   ```

   ⇒ **不用自己写物理、不用绑骨**，引擎原生能力。

3. **不改骨架** —— 骑砍骨架全游戏共用一份（`human_skeleton`，31 根身体骨）。
   想给丝带加自己的骨链 = 给这个角色换骨架 = 每人一套，
   成本高一个数量级（[战国无双换装总纲](战国无双换装总纲.md) §4.18.7 已论证并否决）。
   **布料的"钉死区"本身就是绑定**：顶点色 alpha = 0 的顶点被钉在骨骼上，alpha > 0 的才被模拟。

> 参考：织丰（Shokuho）已经在用同一套系统 —— `cloth_bodies.xml` 里有 `sho_kashimono`（旗指物）、
> `sho_monk_cape`、`sho_jinbaori` 等 12 套日本风格布件。

## 三、做的顺序（三步，每步能单独验收）

### 阶段 1 —— 门控 + 物品（零建模，当天可验）

**为什么先做**：把「装备当开关」和「布料在我们的场景里到底生不生效」这两件事**先证伪**，再投建模钱。
网格**先借原版 `battania_cloak`**，不建任何新资产。

| 谁 | 做什么 | 判据 |
|---|---|---|
| 我 | 物品定义 `lwn_ribbon_cloak`（新建 `ModuleData\items\ribbon.xml`，网格先借原版） | 进游戏能装备上 |
| 我 | 飞行门控改读披风槽（共 5 处，见 §五） | — |
| 我 | 中英文两条本地化键 | — |
| **用户** | 编译 + 实机 | 穿披风能飞、脱了不能飞 |
| **用户** | 🔴 **顺手验场景**：战场 / 城镇 / 日本大地图里，看原版披风的布料**动不动** | **这条不过，整条线要换方案** |

### 阶段 2 —— 自建丝带网格

| 谁 | 做什么 | 判据 |
|---|---|---|
| 我 | Blender 建丝带 → 放 `Modules\LivingWorldNpcs\AssetSources\ImortReady\丝带\` | 规格见 §四 |
| **用户** | 编辑器 Import → **Cloth Editor**：勾 `Use cloth` + 碰撞体 `cape_body` + 材质预设 `flag` → Save mesh settings → Publish | 预览里**只有丝带动、身体纹丝不动** |
| 我 | 物品 `mesh=` 换成新网格 + 最小装机 | `tpaccli clothinfo` 出 `UnknownString="cape_body"`，且 alpha 非零数 = 丝带顶点数 |

### 阶段 3 —— 获取途径

`is_merchandise` + `culture` + `value` → 进商店货架与战利品池。
文化先定 `Culture.neutral_culture`（**原版与 Taikou 两侧都有定义**，是唯一跨世界安全的选择）。

## 四、网格规格（我照这个建）

| 项 | 值 | 为什么 |
|---|---|---|
| 位置 | 颈后垂下，顶端一圈贴颈 | 用户定的"绑到脖子" |
| 长度 | 3 m | 用户定的"超长" |
| 宽度 | 根 18 cm → 末端 30 cm | 末端稍展开，飘起来有面 |
| 分段 | 长 40 段 × 宽 5 段 ≈ 250 顶点 | 原版披风 LOD0 是 1854 顶点，这个很省 |
| 骨绑定 | **全片绑 `neck`** | 骨骼只负责"钉在哪"，摆动交给布料 |
| 顶点色 alpha | 顶端一圈 = 0（钉死）→ 末端 ≈ 2.5 | 单位是米 = 该顶点能离开骨骼位置多远 |
| 顶点色 RGB | 全白 | 只有 alpha 有意义 |
| 双面 | 🔴 **必须补背面** | 单面薄片 = 反面看不见；战无 2 工程有现成做法 |
| LOD | 先做**单 LOD** | 原版披风只有 LOD0 带布料标记、LOD1 往后是刚性；丝带顶点少，单 LOD 最省心 |

**碰撞体为什么用 `cape_body`**：它已含 `spine / spine1 / spine2 / 双锁骨 / 双上臂 / 双前臂 / 双大腿 / 双小腿`
**全套**，长丝带垂过腿时有东西挡——比只有躯干的 `cloak_body` 合适。

**材质预设先 `flag`**（原版披风的标准手感）。
想要参考图那种**往上卷**的效果，改用 `feather` —— 它的重力是 **−10（负的，往上飘）**。

**Cloth Editor 里 Simulation mesh 留空**（= 直接模拟）。
两种模式二选一：留空 = 网格自己算（上表 alpha 就是活动半径）；选替身 = 低模算、渲染件跟着动。
丝带才 ~250 顶点，走直接模拟最省事（战无 2 的信长披风就是这么跑通的）。

## 六、验收指令

沿用现有 `custom.flight` 命令族（[FlightCommands.cs](ExampleModVS/ExampleMod/ExampleMod/CampaignMode/Tools/FlightCommands.cs)），新增三个子命令：

| 命令 | 干什么 |
|---|---|
| `custom.flight` | 状态行加一条 `ribbon: worn (lwn_ribbon_cloak)` / `ribbon: none` |

文案纯英文、首参可弃（现有命令族已守这两条）。

## 七、风险与退路

| 风险 | 什么时候知道 | 退路 |
|---|---|---|
| 🔴 **场景不支持布料** | **阶段 1**（看原版披风动不动） | 退成刚性丝带（不带布料），靠角色动作带 —— 观感打折但仍可用 |
| 🔴 **飞行中布料不模拟** | 阶段 2 | 飞行时角色被冻结（`Controller=AI` + 暂停），布料是否照常算**没验过**；若不算，退成"起飞瞬间锁姿态"或刚性件 |
| 长丝带穿模 | 阶段 2（alpha 活动半径给大了会穿身体） | 缩小活动半径上限 / 缩短 / 给 `cape_body` 补胶囊 |
| 远处 LOD 僵成一根棍 | 阶段 2 | 单 LOD（顶点少，不需要分级） |

> 原版论坛有实测案例：**部分场景布料整个失效**（Sargoth 城镇）。
> 我们的日本地图与战场场景从没测过 —— 这是**头号风险，也是阶段 1 存在的全部理由**。

## 八、明确不做

- **不新建 race、不改骨架** —— 成本高一个数量级，且布料已经能解决摆动。
- **不给 NPC 加飞行** —— 飞行仍是玩家专属；披风本身任何角色都能穿（不拦）。
- **不做多条丝带分叉** —— 用户选了单条。
