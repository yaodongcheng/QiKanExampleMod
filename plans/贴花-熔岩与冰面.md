## 一、结论先行（审批就这几条）

1. **熔岩有两条驱动路线，用哪个由材质决定**（都不需要改 shader）：
   - **A. C# 每帧推 UV**（默认，任何 decal shader 都吃）
   - **B. 引擎自走**：材质勾上 `use_texture_sweep`，走 `uv += VA2.xy × 引擎全局时间 × 0.1`，
     C# 只在召唤时写一次 VA2 ⇒ **零每帧开销**。但**只有 `deferred_blood_terrain` 这一个贴花 shader 读这个 flag**。
   - 命令上分：`custom.decal_fx lava`（A）/ `custom.decal_fx lava sweep`（B）。
2. **阴魔斩的材质不能直接拿来用**：它确实靠 `use_texture_sweep` 流动（`lwn_yinmo_crescent` 的
   `shaderFlags` 里就有这条），但它是**网格 shader**（`pbr_standart` 族）—— 挂到 `decal_mesh` 上
   会被当普通网格画成一个**大立方体**，贴花的投影根本不发生。它证明的是"这个 flag 在游戏里是通的"。
3. 🔴 **B 模式自带诊断价值**：若召唤出来是**静止的**，就说明材质挂的不是那条 shader
   （普通 `decal` shader 根本不读 VA2）—— 一眼分辨材质对不对。
4. **A 模式的原理**：贴花 shader 自身没有任何时间项（`g_time_var` 在 decal 路径里压根没被用）；
   材质那三个动画 flag 里 `use_animated_texture_coords` 贴花也确实吃不到
   （`flagDefs.rsh` 里有它，但读它的只有 pbr_standart 那几支）。所以 A 只能代码驱动。
5. **能无限循环流动，是因为采样器是「重复」不是「夹取」**（引擎根签名 `s5` 实证），配合四边无缝的贴图，UV 推到 1.0 回绕时看不出接缝。
6. 🔴 **滚动的贴图保不住羽化边**——足迹边界映射到的纹素位置每帧都在变，"永远落在羽化区"数学上不成立。所以熔岩的两张贴图被刻意做成**四边接近无痕色**（发光层冷区压成纯黑、结壳层改成白底暗缝），硬边只在"裂缝恰好扫过边界"那一小段才看得见。
7. **结冰水面是静态的**，不受上面那条限制：形状和羽化直接烘进贴图，边界干净。
8. **代价**：熔岩没有"整片黑岩板"的观感（那会让边界切出一圈明显的暗方框），只有"暗裂缝 + 亮熔浆"的裂地效果。
9. **本轮不做**：熔岩的"形状不动 + 纹理流动"（需换 shader，见 §六 进阶；形状遮罩贴图已备好）。

### 结冰水面的结构（2026-09-29 二改）

| 层 | 滚不滚 | 贴图怎么写 |
|---|---|---|
| 冰体层（Modulate） | 静止 | RGB = **淡蓝白的冰面**（薄处透出暗水 / 裂缝暗线 / 靠边更白），alpha = 水洼形状 |
| 反光层（AddAlpha） | 静止 | 黑底 + 裂缝亮线 + 冰缘高光 + 零星闪光（**克制**，加多了会打爆成白纸） |

🔴 **第一版的错**：把中心压到 0.10 的深黑、边上堆一圈白霜 ⇒ 读出来是"**一个黑窟窿 + 一圈白边**"，
不是冰（用户反馈"没有那种结冰的感觉"）。结冰的观感主体是**整片淡蓝白的冰**，
暗水只是"冰薄的地方隐隐透出来"的配角。

### 🔴 熔岩的结构（2026-09-29 定稿，改过三轮）

**物理关系**：**岩壳是静止的（裂开就不动了），流动的是岩壳底下那层岩浆，只能从缝里看见。**

| 层 | 滚不滚 | 贴图怎么写 |
|---|---|---|
| 岩浆层（AddAlpha） | **滚动**（C# 每帧推 VA1） | **全铺满**的无缝岩浆，**没有形状** —— 形状由岩壳的 alpha 挖出来 |
| 岩壳层（Modulate） | **静止** | RGB = 玄武岩；**alpha = 1 岩板 / 0 裂缝**；足迹外沿还要渐隐（做软边） |

- **绘制顺序**：岩浆必须排第一（先画、被岩壳盖住）。prefab 里两个子节点的**先后就是依据**——
  上一轮实测已确认引擎按子节点顺序画（当时 crust 在前、glow 在后，看到的就是那个顺序的结果）。
- **尺寸配合**：岩浆层缩到 **0.86×**，让它的方边落在岩壳的实心区（岩壳实心到 d=0.44，岩浆边在 d=0.43）内，
  否则岩浆自己的方边会从岩壳的羽化区露出来（一圈橙光）。改岩壳羽化宽度时要同步改。
- **哪层不滚由 C# 按子节点名判定**：名字含 `crust`/`rock`/`water` 的层钉住不动。
- **附带收益**：岩壳静止 ⇒ 它的贴图边缘羽化不会漂 ⇒ **足迹外沿终于是软边**
  （滚动层做不到这件事：羽化位置每帧都在变，硬边是数学必然）。

**其余字段一个字都别动**（shader = `decal`、三个 material flag、八个 shaderFlag、alphaTest = 0、Factor 1 Color = `255,255,255,255`）。
逐字段对照（2026-09-29 从发布包 dump 实证）：

```
flags        = [no_depth_test, no_modify_depth_buffer, cull_front_faces]
shader       = 8490623a-1a2b-4f08-9864-de052ab207c2   (decal)
shaderFlags  = [use_specular, use_albedo, use_normalmap, use_ambient_occlusion,
                render_on_terrain, render_on_objects, render_on_grass, hardlight_blend]
alphaTest    = 0
blend        = add_alpha（发光层） / modulate（压暗层）
```

## 四、验收（照着做，逐条对）

| # | 操作 | 预期 |
|---|---|---|
| 1 | 进任意城镇场景，`custom.decal_fx lava` | 眼前地面出现约 8×8 米的**发光裂纹地面**，裂纹缓慢斜向流动 |

## 五、万一不对，先看这里

| 症状 | 最可能的原因 |
|---|---|
| 贴花**完全看不见** | ① `Taikou/Assets` 没改名（遮蔽了 AssetPackages，见 §三③）② 材质 Blend 选错（发光层必须是 `add_alpha`）③ prefab 不在启动模块列表里 |
| **不流动** | 材质不是 decal shader（标准 shader 会把 `decal_mesh` 当普通网格画，直接看到一个大立方体）；或 `custom.decal_fx speed` 是 0 |
| 熔岩**边界有一圈硬方框** | 正常现象但**不该明显**。若明显：说明贴图四角没落在无痕色（重跑生成器看校验行的"四角 RGBA 均值"：发光层应≈全黑、结壳层应偏白） |
| 熔岩**边界硬**（岩板 vs 原地面的直线分界） | **目前是设计如此**（整块不透明才能整块变岩板）。要软化就得让结壳层**不滚动**（不滚动才能在贴图边缘做羽化）—— 那需要给 C# 加"这一层不推 UV"的开关，暂未做 |
| 熔岩**太暗**（发光被吃掉） | 两层绘制顺序反了——把 prefab 里 `_glow` 和 `_crust` 两个子节点**调换顺序**（结壳必须在前） |
| 冰面**看着像白斑** | 说明两个材质的 Blend 反了（水体该 `modulate`、冰霜该 `add_alpha`） |
| 尺寸看着是预期的**两倍** | 换到 1.5.x 客户端了。1.5.x 的 shader 少一行 `* 2`，同一份 scale 出来的足迹是 1.2.12 的两倍（见下） |
| 熔岩**不流动**（C# 驱动模式） | `custom.decal_fx` 看状态行：显示 `C#(VA1)` 说明命令侧在推；那就查材质是不是 decal shader |
| 熔岩**不流动**（sweep 模式） | **说明材质挂的不是读 `use_texture_sweep` 的贴花 shader** —— 去 ModKit 把 Shader 换成血渍 terrain 那条（§六） |
| 冰面和熔岩**同时召**会互相顶掉 | 设计如此：`custom.decal_fx` 每次召唤会先收掉上一批（引擎没有"删单张"的 API，只能隐藏） |

🔴 **1.2.12 与 1.5.x 的尺寸口径不同**（反编译实证，已记进 prefab 注释）：
本项目实机跑 1.2.12，`Scale X/Y` 直接等于**米数**；1.5.x 的 `deferred_decal.rsh` 把投影体积的
`* 2` 那行去掉了，同一份 scale 出来是**两倍大**。跨版本时 scale 要砍半。

## 六、进阶（先不做，等这个版本验收通过后再议）

**目标**：让熔岩既有**不动的圆形羽化形状**、又能**纹理流动**（现在的版本只能二选一）。

**路子**：`deferred_blood_terrain` 这个 shader（`Shaders/Sources/deferred_blood_terrain.rsh`）
里有一条 `USE_AREAMAP` 分支，它的遮罩采样用的是 **`decal_tex_coord`（未滚动的足迹 UV）**、
而颜色采样用的是 **`atlassed_texture_coord`（可滚动的 UV）** —— 这是目前找到的**唯一**
能让"静态形状 + 动态纹理"并存的口子。而且它还有 `USE_TEXTURE_SWEEP` 分支
（`atlassed_texture_coord += VA2.xy × g_time_var × 0.1`），若能选中这个 shader，
**流动连 C# 都不用写**。

**已经备好的料**：`lwn_decal_lava_area_d.png` 就是给这条路的静态形状遮罩（羽化圆潭）。

**为什么没直接做**：这个 shader 能不能在 Material Editor 的 shader 下拉里选到、它的混合模式
在 Mission 里表现如何，都还没验。**低成本试法**：在 ModKit 里建一个材质、Shader 选
`deferred_blood_terrain`（下拉里可能叫 `blood_terrain` 或类似名）、开 `use_texture_sweep`
（要形状不动再开 `use_areamap`）、DiffuseMap 挂 `_flow_d`、第二张贴图挂 `_area_d`，
编辑器里直接看（ModKit 所见 = 游戏所见）。然后 `custom.decal_fx lava sweep` 实机复核。

🔴 **换 shader 会同时改两件事，别只看流动**：

| | `decal`（现在用的） | `deferred_blood_terrain`（进阶那条） |
|---|---|---|
| 投影体积判定 | 1.2.12 里带 `* 2` ⇒ 足迹 = **1 × scale 米** | 无 `* 2` ⇒ 足迹 = **2 × scale 米** |
| 流动来源 | 无（要靠 C# 推 VA1） | `VA2.xy × 引擎时间 × 0.1`（自走） |

⇒ 换过去之后**同样的 scale 会大一圈**，尺寸参数要减半；`argument`（VA1）仍保持 `1,1,0,0` 不动。
另外这条 shader 是**自己算光照的前向 decal**（内部 `compute_lighting` / `apply_advanced_fog`），
出来的明暗观感会和现在这条不同，两层材质的 Blend 可能要重试一遍。

## 七、本轮的纪律沉淀（已回写知识文档）

- 🔴 **`use_texture_sweep` 是**可以勾的材质 flag（不是编译期开关）—— 实证 = 阴魔斩的
  `lwn_yinmo_crescent` 材质 `shaderFlags` 里就有它、实机在流动。**别再断言"贴花吃不到动画 flag"**：
  准确说法是 **`use_animated_texture_coords` 贴花吃不到**，而 `deferred_blood_terrain`
  （贴花族）读 `use_texture_sweep`。
- 两条 sweep 实现的参数口径不同，别混：网格族 `pbr_standart` 用 **VA1.xy** × `g_time_var` × 1.64；
  贴花族 `deferred_blood_terrain` 用 **VA2.xy** × `g_time_var` × 0.1。
- **网格 shader ≠ 贴花 shader**：材质挂错族，`decal_mesh` 会被当普通网格画成一个大立方体（投影不发生）。
- 贴花 shader **没有时间项**；采样器是 **WRAP**（能无缝循环滚动）。
- 滚动贴图 ⇒ **羽化边保不住**（数学上不成立）⇒ 边界只能靠"贴图在边界处本来就接近无痕色"来藏。
- **无痕色必须乘进形状遮罩**：给"压暗层"整张图染冷调会把形状外也染上 ⇒ 切出方框
  （本轮第一版就是这么错的，校验行四角实测 `(230,245,255)` 而非纯白）。
- 生成器必须**回读校验四角**（无痕色）+ **接缝/内部差值比**（无缝判据），别靠肉眼看。
- 美术先过一遍**离线合成预览**（`_preview_decal_lava_ice.py`）再进 ModKit，省一轮往返。
