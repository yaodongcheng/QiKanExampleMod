## 一、结论速览

**决定：两样东西共用一套「火器表现」结构，但形态不同，分三条做。**

| | 铁炮 | 大筒 |
|---|---|---|
| 形态 | 单兵武器（`Type="Crossbow"` 的物品） | 场上的炮（场景实体 + 原版器械逻辑） |
| 模型 | ✅ **已有**（杂贺孙一的种子岛铁炮） | 借织丰的 `sho_ozutsu_siege` |
| 动作 | ✅ **原版弩**（和织丰一致，实证见 §二） | 原版器械的推/装填动作 |
| 开火表现 | 枪声三档 + 枪口烟（LWN 写代码） | 炮声三档 + 炮口烟（同一条管线） |
| 谁用 | 武将 + 铁炮队兵种 | 大筒队兵种操作 |
| 一期做到 | 完全做完 | 静态炮（能架、能开火、不移动） |

**明确不做**（一期）：
1. 大筒推着走（二期，`plan` v1 §B2 的技术方案保留）
2. 自制装填动画（用原版弩的拉弦动作）
3. 手持大筒、舰炮

## 三、优雅的结构（核心设计）

**一句话：火器的「开火表现」只实现一次 —— 一份数据表 + 一条代码管线，铁炮和大筒共用；以后加新火器只加一行数据，不改代码。**

### 3.1 数据侧：一份契约

`Taikou/ModuleData/AssetRegistry/FirearmFx.xml`（新建，Taikou 填值）：

```xml
<FirearmFx>
  <!-- 一行 = 一种火器口径。keys 都是世界观无关的（LWN 不认识"铁炮"两个字） -->
  <Profile ammoClass="Cartridge"
           near="tk_teppo_fire_near" mid="tk_teppo_fire_mid" far="tk_teppo_fire_far"
           particle="tk_smoke_teppo" nearDist="22" farDist="75" />
  <!-- 大筒（口径阶段 3 定；下面 Musket 是 WeaponClass 枚举的真值，不是自造字符串） -->
  <Profile ammoClass="Musket"
           near="tk_ozutsu_fire_near" mid="tk_ozutsu_fire_mid" far="tk_ozutsu_fire_far"
           particle="" nearDist="30" farDist="110" />
</FirearmFx>
```

⚠️ `ammoClass` **必须是 `WeaponClass` 枚举的真值**（枚举全表：`Arrow` `Bolt` `Cartridge` `Bow` `Crossbow` `Stone` `Boulder` `Javelin` `Pistol` `Musket` …）——
写一个不存在的名字 = 该 Profile 永不命中（查表是按枚举名匹配的）。

- `ammoClass` = **引擎枚举 `WeaponClass` 的名字**（不是我们发明的字符串）→ 火器身份由「它射什么弹」决定，铁炮和大筒天然区分开
- `near`/`mid`/`far` = 音效名，`particle` = 粒子名，全是**内容包自己定义**的字符串，LWN 只当名字用
- `nearDist`/`farDist` = 距离分档（米）：小于 `nearDist` 用近档，大于 `farDist` 用远档，中间用中档

**为什么按 `ammoClass` 分档**：铁炮物品、大筒的弹药物品都有这个字段，是两者唯一的公共身份标识；以后加火箭 / 霰弹只加一行 `<Profile>`。

### 3.2 代码侧：一条管线

`LWN .../Combat/FirearmFxRegistry.cs`（新建）：读上面那份 XML。写法照抄 `CampaignMode/HeroCatalogRegistry.cs`（扫全模块 → 懒加载 → 坏数据只记日志不抛）。

`LWN .../Combat/FirearmFxLogic.cs`（新建，`MissionLogic`）：挂 `OnAgentShootMissile`：
1. 看射手手里武器的 `PrimaryWeapon.AmmoClass`
2. 表里查不到 → **直接返回**（普通弓弩不受影响）
3. 查到 → 按射手到玩家的距离选档 → 播音效 + 在枪口位置生成粒子

**大筒走同一条表**：大筒炮射出的弹也带 `ammo_class`，同一条管线覆盖，不写第二套。

### 3.3 三个必须避开的坑（v1 结论，仍然有效）

**坑 1：火器标记用 `Cartridge`，不要用 `Bolt`**
织丰的判断是「`ItemType == Crossbow` 且 `AmmoClass == Bolt` 就播枪声」—— 在内容包场景下会误判：**原版弩兵开火时这两个条件同样成立**，会播成铁炮声。织丰自己碰不到（它全库没有普通弩），Taikou 会碰到。
→ 铁炮的 `ammo_class` 写 `Cartridge`（原版全库零占用，已核实）。

**坑 2：音效名不能硬编码进 LWN**
织丰把 `teppo_fire_patch_close` 写死在 C# 字段里。LWN 里出现这种字串直接违反铁律 3（通用 mod 不得出现世界观词汇）。
→ LWN 只认档位（近/中/远），名字从 `FirearmFx.xml` 读。**解析必须容错**：内容包没装 / 名字拼错 / 音效文件缺失 → 跳过播音，不能崩。

**坑 3：弹速写在枪上，不是弹药上**
引擎取的是**手持武器**的弹速（`GetModifiedMissileSpeedForCurrentUsage()`，拿的是枪占的槽位）。织丰在弹药上写 500、CA_BloodSmoke 写 10 —— 两者都不生效。
→ `missile_speed` 写在铁炮物品的 `<Weapon>` 上（现有杂贺那把已写 600，正确）。

### 12.3 实施中发现的 4 件事（都已处理）

**① `item_usage_sets.xml` 由引擎按文件名自动加载，但体检脚本不认识它**

首跑报 `[ERROR] item_usage_sets.xml 有定义但没有任何段加载它`。
实证：Native 与 Shokuho 的 SubModule.xml **都没注册它**，而原版弓弩 usage、织丰火枪 usage 都正常工作
→ 它属引擎惯例文件（同 `action_sets` / `action_types`）。已补进 checker 的 `CONVENTIONAL_FILES`。

**② 远程武器不能带盾 —— 带盾则武器 usage 被引擎跳过（射不出去）**

弓 / 弩 / 火器的 usage set 都带 `requires_no_shield`；原版全库**没有一个带盾的弩兵**。
而身份默认装备里"大名/国主/城主/家老/部将"都带盾 —— 杂贺孙一（1582 身份 = 家老）就因此变成"拿着枪射不出"。
→ 生成器加规则：**填了「弹药」列（= 远程武器）就丢弃盾**。目前只影响杂贺（稻姬用弓、本来无盾）。

**③ 织丰的口径分配（反编译实证）：`Bolt`(13) = 铁炮、`Cartridge`(14) = 大筒**

`ShokuhoGunSoundLogic.OnAgentShootMissile` 里写死 `AmmoClass == 13 → 铁炮声 / == 14 → 大筒声`。
→ 印证 §3.3 坑 1：织丰铁炮用的正是 Bolt，Taikou 照抄会把原版弩兵一起认成火器；改用 Cartridge 是对的。
**推论**：阶段 3 的大筒要**另选一个没被占用的口径**（候选 `Musket` / `Pistol`，都是枚举真值）。

**④ 原版没有枪口爆发型粒子**

原版 XML 引用过的粒子全是环境型（持续烟柱，如 `psys_burnt_wood_smoke`）；织丰的 `smoke_musket` 是自制的。
→ 契约 `particle` 一期留空（只播枪声，不报错）。二期补粒子时**只填名字、代码不动**。

**⑤ 🔴 内容包不能用自定义 `item_usage` —— 会崩（2026-09-16 实机踩实，已修）**

**症状**：掏出铁炮瞬间 `System.AccessViolationException`（`MissionState.TickMission`，托管栈丢失，日志戛然而止）。

**根因**：铁炮的 `item_usage` 写成了自定义名 `tk_firearm`，而 `item_usage_sets.xml` **只由 Native 模块加载**
—— 引擎硬编码，那个字符串只存在于 `TaleWorlds.Native.dll`（托管层没有对应 XmlName，
内容包在 SubModule.xml 里也注册不了）。⇒ 该 usage 运行时**不存在** → 掏出武器时 native 取到无效索引 → AV。

**判据（引擎日志，一行定生死）**：`opening .../Modules/Native/ModuleData/item_usage_sets.xml`
**只会出现 Native 一条**；内容包那个文件从头到尾不会被打开。

**教训**：`check_module_registration.py` 早就把这个文件报成「孤儿数据文件（写了但运行时不存在）」，
我拿「Native / Shokuho 都没注册它」当反证把它驳回了。
→ **驳回一条检查之前，必须先证明被检查的东西真的生效**；"别人也没注册"推不出"它会自动加载"。
该检查的白名单已回退，并在代码注释里锁死（`item_usage_sets` / `monster_usage_sets` 永不加回）。

**修法**：`item_usage` 一律用**原版名**（铁炮 = `crossbow`，与织丰的火枪动作本来就一致 —— 见 §二）。
以后真要做火枪专用动作，走 C# `Agent.SetActionChannel` 播自定义 clip
（[Knowledge/动画导入与UE5重定向…](../../Knowledge/动画导入与UE5重定向_引擎能力与实现路径.md) §6 已探明），**不要再碰 `item_usage`**。

**⑥ 内容包的音效走 `project.mbproj` 的 soln 体系 —— 不在 SubModule 的 XmlNode 体系里（2026-09-16 实机，已修）**

**症状**：铁炮能掏能射，但只有引擎默认的弩声。LWN 日志直指要害：
`[FirearmFx] 音效 'tk_teppo_fire_near' 查不到 —— 该档静音`。

**根因**：`module_sounds.xml` 与 `skins.xml` 同属 `ModuleData/project.mbproj` 的 `<file id="soln_*">` 体系 ——
**mbproj 里不挂那一行 = 文件完全不加载**。Taikou 的 mbproj 原先只挂了 `soln_soundtrack` + `soln_skins`
（2026-09-08 为躲 soln 合并冲突而精简），所以那份文件里的 **48 个音效（40 个 BGM + 8 组火器）一直是死的**。
判据：引擎日志 `opening .../Taikou/ModuleData/<文件>` 的清单里**没有 module_sounds.xml**。

**修法**：mbproj 加一行
`<file id="soln_module_sound" name="ModuleData/module_sounds.xml" type="module_sound"/>`（照 Native 自己的写法）。

**为什么不会重演 09-08 那次崩**（同 soln id 合并出重复定义 → KeyNotFoundException）：
本文件的 48 个音效名与 Native 的**零交集**（Native 实际只定义 3 条 `example/...`）→ 合并是**纯追加**，不冲突。

**⑦ 🔴 火器命中敌人必崩 —— 引擎技能映射表漏了它自己定义的火器类（2026-09-16 实机，已打补丁）**

**症状**：掏枪、开枪、枪声都正常，**子弹打中人的一瞬间** `NullReferenceException`。

**根因**：`WeaponComponentData.GetRelevantSkillFromWeaponClass` 的 switch 覆盖了弓/弩/投掷/单手/双手/长杆/盾，
**唯独没有 `Cartridge` / `Musket` / `Pistol`** → 落到 `return null`；而 `DefaultSkillLevelingManager.OnCombatHit`
拿它**无 null 守卫**直接 `AddSkillXp` → `CalculateLearningRate` 里 `skill.CharacterAttribute` 炸。
🔴 命中时传进来的是**弹药**的 WeaponComponentData —— 所以触发条件是**弹药**写 Cartridge
（织丰 / CA_BloodSmoke 的**铁炮弹药都写 Bolt**，因此都没暴露这条；织丰的大筒用 Cartridge，那条路它自己大概也没测过）。

**修法**：`LWN Core/FirearmSkillMappingPatch.cs` —— Postfix **只在 `__result == null` 且是那三个火器类**时
补 `DefaultSkills.Crossbow`（引擎没有火器专属技能，弩技能是唯一同类）。原版既有映射**逐字节不变**。

**为什么不用数据绕过**（弹药改回 Bolt）：那会丢掉「火器 vs 普通弩」的**唯一非世界观判据** ——
内容包里的原版弩兵开火会被一并误判成火器（§3.3 坑 1 花的功夫全废）。
这是**引擎遗漏**（同类的 `GetItemTypeFromWeaponClass` 里这三个类都有），补它是修 bug、不是绕限制。

**版本**：四版本参考 DLL（1.2.12 / 1.3.15 / 1.4.6 / 1.5.1）反编译 —— 方法全在、映射表全都没补。
**退役条件**：官方把这三个类补进映射表之日（届时补丁因 `__result != null` 自动 no-op）。
