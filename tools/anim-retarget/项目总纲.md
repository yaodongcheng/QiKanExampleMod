### 二、🔴 未解决：浮空病（详见 `plans/rules/wheels.d/assets.md` §15.3c）

> 🔴 **责任定性（别误读）**：**源动画是好的** —— 实测源侧脚底 `0.000`（贴地）。
> 这个浮空是**我们重定向/导出这一环造出来的 bug**（导出器把 bind pose 写歪），**不是素材问题**。

- **现象**：一部分动画（越不站姿越明显）在查看器/实机里**整体浮空** —— 实测脚底 `0.124`（普通施法）/ `0.275`（蹲着瞄的 `SpellChannel1_Up/Mid/Mid1/Down`）。
- **机制**：**FBX 导出器把「导出那一刻的姿势」写成 bind pose**。那句"导出前清 pose"保护**没用** —— 导出器自己会触发求值把姿势装回来（实测：清零后读 `0.9145` ✅，再求值一次变 `0.6645` ❌）。
- **试过一个修法并失败**：清 pose 之后再摘掉 action → **姿态通道整个没了（动画冻结成 T 字）+ 丢了对象级位移**，已彻底回退（代码 + 72 条产物 + 交付目录全还原）。
- **下一步方向（未动）**：**改 `fbx_to_trf.py` 的旋转参照** —— 引擎是按**官方骨架的 rest** 读 TRF 旋转的，而脚本现在用的是**输入 FBX 自己的 rest**（恰是被写歪的那个）。换成官方骨架，且**完全不碰导出的动画/位移通道**。先验一条 clip 再铺开。

### 三、🔴🔴 验收纪律（本轮最大的教训：假绿）

**判据必须两条一起过，缺一条就会误判**：

| 判据 | 工具 | 阈值 |
|---|---|---|
| ① 关节有没有在动 | `check_glb_anim.py` | 最大转角 **100~180°**（≈0 = 冻结/搬运失败） |
| ② 脚底高不高 | `check_glb_feet.py` | **≈0.0** |

只量脚底会**假绿**：动画冻结在绑定姿势时，脚底天然就是 `0`（本轮就是这么被坑的，用户当场抓到）。

## 1. 标准流程（唯一产线）

```
input/source/<来源>/                    源动画（只读）
        │
        ▼ ① 重定向 + ModKit 规格导出 + TRF      ← 一条命令，三者同时产出
   python pipeline/run_retarget.py --rig <骨架对> --clip <动作名> --name <输出名>
        │
        ├──▶ output/fbx/<name>.fbx     中间产物（28 骨 / 只骨架 / Z-up / cm / 根名 human_skeleton_notused）
        └──▶ output/trf/<name>.trf  ★ 最终交付物
                                     （语义：旋转 = 绝对局部变换；平移 = 相对静止姿势的增量。
                                       两条不一样，写反的后果见 §6 硬约束 5。）
        │
        ▼ ② 自检（脚本自动打印，必须看）
   CHECK_OK   绝对公式 vs Blender pose 矩阵 < 0.5°      ← 例：0.0396°
   CHECK_POS  位置轨首帧 ≈ 0（纯增量）                 ← 若量级是米（~0.86）说明误用绝对语义，产物作废
        │
        ▼ ③ ModKit 导入
   填 Source 1 / Source 2 = 该 TRF 的帧范围（如导出 1–41 就填 1 / 41），Duration > 0
   报错 "pos ipo[2,42] does not fit sources 0.00 and 0.00" 就是这个没填，不是 TRF 写错
        │
        ▼ ④ 预览（可选）
   output/glb/  ──复制──▶  viewer/datasets/<数据集>/assets/  ──▶  viewer/serve.py
```

### 一条命令示例

```bash
# SW2 线（源 glTF）
python pipeline/run_retarget.py --rig sw2_gunner --clip p006 --name sw2_gunner_p006_alig

# UE 线（源 FBX）
python pipeline/run_retarget.py --rig ue_mannequin --clip 010_01 --name ue_010_01

# 🆕 带位移的一次性动作（处决/冲锋/翻滚）：位移烘进骨盆位置轨（Root 变体 + --pelvis src）
python pipeline/run_retarget.py --rig ue_mannequin --clip GhostSamurai_Execution02 \
  --name gs_execution02_root --pelvis src \
  --animdir "input/source/ue_mannequin/clips_exec/GhostSamurai_katana/Mannequin/Animation/Apose/Execution/Root"

# 只看命令不执行
python pipeline/run_retarget.py --rig sw2_gunner --clip p006 --dry-run
```

> **`--pelvis` 三档（UE 线）**：`ground`=逐帧贴地、**丢弃源水平位移**（默认，原地动作）｜
> `src`=**保留源根位移的水平分量** + 逐帧贴地（带位移动作）｜`none`=不写位移轨（飞行/离地）。
> 🔴 源侧有水平位移却用 `ground` 时脚本会**主动告警**（以前是静默丢弃 → 实机"演完瞬移回原点"）。
> 位移进 TRF 只是上游；**引擎侧怎么让角色真被带走**见
> [Knowledge/动画带位移_RootMotion与代码推位移.md](../../Knowledge/动画带位移_RootMotion与代码推位移.md)。

**算法结论（已定稿）**：`--pose align`（世界增量 + 逐骨静止对齐 `A⁻¹`）是**唯一交付模式**，也是默认值。
`delta` / `absolute` 仅作对照，产物已归档 `_legacy/algorithm_archive/`，**不要交付或接入**。

## 3. 脚本分层约定

**新增一个源骨架 = 只加一个 `pipeline/rigs/<名>/` 目录，通用层不动。**

| 层 | 位置 | 放什么 | 判断标准 |
|---|---|---|---|
| 通用层 | `pipeline/common/` | TRF 导出、GLB 烘焙、骨架体检、质量校验、UE 导出、无头截图 | **与"哪套骨架"无关**，换骨架照样用 |
| 骨架专有层 | `pipeline/rigs/<rig>/` | `map.json`（骨映射/帧变换/单位）+ `retarget.py`（重定向算法） | **差异只此一份**，不含流程逻辑 |
| 目标规格 | `pipeline/rigs/bannerlord_target.json` | 骑砍 28 骨序、根名、轴向、单位、ModKit 导出参数 | 目标骨架的唯一事实来源 |
| 调度层 | `pipeline/run_retarget.py` | 选 rig → 组命令 → 跑 blender → 校验产物归位 | 不含算法、不含映射 |

**路径约定**：所有脚本用自动定位的项目根，**禁止硬编码绝对路径**：

```python
PROJECT_ROOT = _project_root(os.path.dirname(os.path.abspath(__file__)))  # 向上找含 pipeline/ 与 input/ 的目录
```

已新增一个源骨架时，只需在 `run_retarget.py` 的 `RIGS` 注册表加一条：

```python
"<新骨架名>": {
    "script": "pipeline/rigs/<新骨架名>/retarget.py",
    "map":    "pipeline/rigs/<新骨架名>/map.json",
    "source_kind": "fbx",          # 或 gltf
    "clip_arg": "--clip",          # 该脚本的动作名参数
    "desc": "…→骑砍2",
},
```

## 4. 通用查看器（只有一个）

```bash
cd viewer && python serve.py      # 自动找端口并打开浏览器
```

- 数据集通过 `viewer/datasets/index.json` 注册，页面**左上角下拉切换**，也可用 URL：`viewer.html?ds=ue_slim`
- 一个数据集 = 一个目录：`dataset.json`（描述）+ `assets/`（GLB/glTF）+ 可选的 `manifest.json`（clips 元数据）
- **`viewer.html` 里没有任何写死的文件名**，全部来自 `dataset.json`
- **逐帧定位（2026-09-22）**：底部「进度 / 帧」拉杆 —— **暂停后拖动即定位到某一帧**（1 格 = 1 帧 @30fps，
  拖动会自动暂停；拉杆聚焦后 `←/→` 微调 1 帧）；播放中拉杆自动跟随播放轴，暂停时不会被回写。
  URL 也可直达：`viewer.html?ds=ue_slim&clip=002_01&frame=17`（`?frame=N` 会同时暂停）

### dataset.json 关键字段

| 字段 | 作用 |
|---|---|
| `sides.src` / `sides.dst` | 左（源）/ 右（目标）两侧配置：`label` `color` `rotY` `slot` `footBones` `files[]` |
| `files[].url` | **相对 dataset.json 所在目录**（viewer 会自动加前缀） |
| `files[].mode` | `ground`（逐帧贴地）/ `src`（跟随源骨盆位移），用于双模式数据集自动切换 |
| `clipsFile` | 指向 clips 元数据文件（含 `clips`/`groups`/`P0`/`P1`），用于三级筛选 |
| `sides.*.stripPositionTracks` | 裁掉全部 `.position` 轨道（预览时不体现位移，仅看姿态） |
| 旋转侧根位移反向补偿 | **自动生效**：一侧 `rotY≈π` 时，其根位移会被翻转，viewer 自动对未旋转侧做水平反向，保证两人并排（见硬约束 13） |
| `sides.*.rootFixY` + `rootBone` | **根骨静止位移补偿**：某些源 glTF（如 SW2）导出的根位移是"髋空间增量"、丢掉了静止位移，直接播会整体下沉；按此字段在 group 层补回 |
| `sides.*.rootFixY` + `rootBone` | **根骨静止位移补偿**：某些源 glTF（如 SW2）导出的根位移是"髋空间增量"、丢掉了静止位移，直接播会整体下沉；按此字段在 group 层补回 |
| `sides.*.facingBones` | `[左踝, 左趾, 右踝, 右趾]`，供几何求【正面】用（**默认口径是头/眼线**，见硬约束 18；此字段是回退/校验） |
| `sides.*.freezeRootH` | 把根骨 `position` 轨的**水平分量归零**（竖直保留）。用于「就地比姿态」 |
| `sides.*.freezeRootRe` | `freezeRootH` 的**自定义匹配正则**。⚠️ 根位移有时挂在**骨架对象节点**上（如 `GhostSamurai_Execution02.position`）而不是 `pelvis`，此时默认正则匹配不到，要写 `"GhostSamurai_"` 之类 |
| `sides.*.pairAnchor` | **★ 成对动画「只对齐首帧」**：`{anchor, pelvisBone, gap, mode}`。切 clip 时**只算一次**平移量（先摆→量本侧骨盆落点→按差值补正的**闭环**），把本侧首帧骨盆放到锚点首帧骨盆的**正后方/正前方** `gap` 米；`mode` 缺省时按 clip 名自动判定：**`Ambush*` → `behind`（背后偷袭，两人同向）；`Execution*` → `front`（面对面，rotY 差 180°）**。算完立即停手，之后位移全交给动画自己的 root motion |
| `pairs` | **每个成对动作独立的 8 个参数**：`{ "<clip名>": { src:[x,y,z,t], dst:[x,y,z,t] } }`。x/y/z = group 世界坐标（米），`null` = 用 `pairAnchor` 自动值；t = 起点偏移（秒，正=跳过开头，负=首帧等待）。面板可见即改，**自动存 localStorage**；点「保存到 dataset.json」经 `serve.py` 的 `POST /api/save-pairs` 落盘并留备份 |
| `sides.*.clipStart` | （历史）成对动画的 head start。**现已全部归 0** —— 实测用户手调后认为"两侧延迟都设 0 最好，只有各 pair 的 Z 初始差不同" |

> **成对动画（处决/伏击）的正确摆法**：只在 `src` 上加 `pairAnchor{anchor:"dst", gap:1.5}`，`mode` 交给 clip 名自动判定。
> **不要再手调 `offsetX/offsetZ`**，也不要逐帧跟随（受击方中途倒地转身会把攻击方"锚"到别处）。
> 位移若出现"倒退/两人走散"，那是成对 clip 各自的 root motion 问题，与站位对齐无关（见硬约束 16）。

> **成对动画 = 一个「动画组」**：`sides.dst.fixedClipReplace` 存在时，查看器列表**只列攻击方那条**
> （`Executed*`/`Ambushed*` 不单列），选中即两侧各播自己的配对 clip。列表显示中文组名（伏击 01 / 处决 03）+ 站位标注。

> **额外展示侧**：`src`/`dst` 之外的第三侧（如 `ref` = 重定向前的 UE 源）会**自动跟随攻击方播同一条 clip**，
> 用来并排对比"重定向前 vs 后"。

> 无 clips 元数据的数据集会自动隐藏三级筛选器、改用 GLB 中的 clip 名列表 —— 新旧数据集都能用同一个查看器。

### 5.1 UE 源导出（把素材包变成 `input/`）

```bash
BM_OUT_DIR=<输出目录> BM_ANIM_FILTER=<子串过滤,;分隔>   <UE编辑器> <工程.uproject> -run=pythonscript   -script="<项目>/pipeline/common/export_ue_fbx.py" -unattended -nosplash -nullrhi -stdout
```

| 情况 | 做法 |
|---|---|
| 工程自带 `.uproject` | 直接用（3583=**UE5.0** / SuperheroFlight=**UE4.26**） |
| **素材包没有 `.uproject`** | 把它的内容目录挂到已有工程的 `Content/` 下，**路径必须匹配 uasset 内部的 `/Game/...` 路径** |
| 编辑器别搞混 | UE4 → `UE4Editor.exe`，UE5 → `UnrealEditor.exe` |
| 结果别只看 stdout | 读 `<BM_OUT_DIR>/export_trace.log`（stdout 会被引擎噪音淹没） |
| 过滤是**子串**匹配 | 会多带同前缀（`Anim_JU_in_PL` 带出 `_land`/`_fall_loop`）；多带可接受、少带不可接受 |
| **变体子目录必须区分** | 同一资产名在 `Inplace/` `Root/` `Sample/` 下各有一份，**扁平输出会互相覆盖**（实测 69 条导出只剩 23 个文件）→ 脚本已按父目录加 `__Inplace` 后缀 |
| **Git Bash 会改写 `/Game/...`** | MSYS 路径转换把过滤器变成 `C:/.../git-bash-binary/Game/...` → 过滤器失效。**必须加 `MSYS_NO_PATHCONV=1`** |

**实例（GhostSamurai，无 uproject）**：uasset 内部路径为 `/Game/GhostSamurai_katana/Mannequin/...`
→ 复制到 `SuperheroFlightAnimations/Content/GhostSamurai_katana/Mannequin/` 即被识别（4.21 资产由 4.26 自动升级）。

### 5.2 UE 导出的 4 个坑（本会话实测）

| 坑 | 现象 | 修法 |
|---|---|---|
| **Git Bash 改写 `/Game/...`** | 过滤器被 MSYS 转成 `C:/.../git-bash-binary/Game/...` → 失效 | 命令前加 **`MSYS_NO_PATHCONV=1`** |
| **UE5 AssetRegistry 未扫描** | `get_all_assets()` 返回 0（mySekiro/UE5.3 实测） | 先 `scan_paths_synchronous(["/Game"], True, True)` + `wait_for_completion()` |
| **UE5 类名是 `TopLevelAssetPath`** | `"AnimSequence" in str(asset_class)` 匹配失败 | 取 `asset_class.asset_name`（兜底再 `rsplit(".",1)[-1]`） |
| **大批量导出静默丢文件** | trace 报"成功 2874"，实际只落 780 个 | **分批**（`BM_MAX_N`），每批 ≤150 验证；或分批 filter |
| **`ue retarget.py` 原本硬编码贴地** | 飞行动画被强行拉到地面（骨架压到 0.329） | 已加 `--pelvis ground\|none`，**飞行/离地必须用 `none`** |

## 6. 硬约束（踩过的坑，逐条对号）

| # | 约束 | 违反后果 |
|---|---|---|
| 1 | **骨数必须 = 28** | Blender `add_leaf_bones` 默认 True，会补 5 根 `_end` → 33 骨，ModKit 直接拒 |
| 2 | 根节点名 = `human_skeleton_notused` | 与引擎内置 `human_skeleton` 冲突 |
| 3 | 只导骨架（`object_types={'ARMATURE'}`） | 动画文件混进 mesh，导入报错/膨胀 |
| 4 | Z-up + cm | 动画朝向错 / 幅度差 100 倍 |
| 4b | 导出 `scale_length` 必须 = **1.0** | 设 0.01 会让 FBX 比官方小 **100 倍**（实测：0.015 vs 1.575） |
| 5 | 🔴 **TRF 两条轨道的语义不一样**：旋转 = **绝对局部变换**；平移 = **相对静止姿势的纯增量**（`rest_rot @ loc`，**不叠加** `rest.translation`） | 旋转写成增量 → 实机"人趴地上、四肢乱折"（看首帧逐骨角度是否整齐全 0，不看 `CHECK_POS`）；平移写成绝对 → **人整体被抬高约 6cm**（看 `CHECK_POS` 首帧是否 ≈0.86） |
| 6 | **骨序 = 唯一契约**（TRF 不存骨名） | 从错位那根起全错（33 骨版从第 5 块起就废） |
| 7 | TRF 位移块只写 `bones[0]` | 位移错位 |
| 8 | 导入 FBX 会改 `scene.render.fps`（→24） | 时长膨胀 3.4%~25%（"慢半拍"）→ 导入后立刻设回 |
| 9 | ModKit `Source 1 / Source 2` = TRF 帧范围 | 报错 pos ipo does not fit sources 0.00 and 0.00 |
| 10 | 查看器加载源 glTF 若重定向后已无 `.position` 轨道，勿做每帧累加补偿 | 角色飞走 → 用 group 级一次性补偿（`rootFixY`） |
| 11 | **`--pelvis src` 的位移必须在世界空间算完再转回 base 空间**（`base.matrix_world.inverted() @ (...)`) | 直接赋给 `pb.matrix` 会因两侧 base 的 `matrix_world` 缩放不同（Mannequin_src=0.01 / human_lod_4=1.0）差 100 倍 |
| 12 | **单位换算用 `rig_span(base)/rig_span(SA)`，但竖直护栏必须按换算前的物理量判断** | 否则 off.z 被放大 100 倍后恒 >1.5m，71/71 帧全被清零、竖直位移整个丢失 |
| **13** | **viewer 里用 `group.rotation.y` 对齐朝向时，会连根位移一起翻转 180°** | 两侧位移反向 → 一个冲进画面、一个冲出画面（"一前一后"）。需对被旋转侧做根位移水平反向补偿 —— 但**仅当另一侧确实被 `rotY≈π` 旋转时**；成对数据集两侧 `rotY` 都是 0，旧条件会**两侧同时翻转**，把整对的相对位移镜像掉 |
| **14** | **角色「正面朝向」必须用【几何关系】推算，不能用骨骼的局部轴** —— 早期用 `脚踝→脚尖` / `clavicle_l→r` 的位置差求方向 | 实测：骨盆局部 `+Y` 在 UE 源里是 **+54.5°**、真实正面 **−127°**，**差 180°**；同一根骨在骑砍2 资产里又反过来。局部轴约定不可信 |
| **15** | UE 导出的 FBX **变体子目录必须区分**（`Inplace`/`Root`/`Sample` 同名资产） | 扁平输出互相覆盖（实测 69 条只剩 23 个文件）→ 脚本改为**保留完整相对路径** |
| **16** | **成对动画的根位移【方向不可信】**：逐帧实测，角色位移方向与自身朝向差 **~143°**（近似反向）；且**末帧骨盆共同收敛到原点**，说明两个 clip 共用同一参考点、位移是"从 UE 关卡原始站位走到共享点" | 直接拿它当站位 → 伏击方站到受击方**正面**。横向站位必须由几何关系算，不能用根位移 |
| **17** | **成对动画站位【只对齐首帧】**：算一次平移就停手。**既不要逐帧跟随**（受击方倒地转身 60~113° 会把攻击方甩到侧前方），**也不要冻结根位移**（那会把两人自己的走位一起冻死） | 逐帧跟随 → 攻击方绕着受击方转；冻结根位移 → 两人一动不动、动画失去位移 |
| **18** | ⭐ **正前方 = 头（两眼之间的垂线）**，不是骨盆/肩线的垂线。实现见 §8.4：绑定姿态标定 `head` 局部前向 + 运行时 `head.matrixWorld × 该向量`（`facingOf(L,'head')`，默认口径） | 拿肩线/骨盆当正面 → 躯干一拧（Ambush04 首帧躯干 38°、t=0.43 拧到 109°，而头一直 ~89°）朝向就算歪，成对站位/背后判定全错 |
| **21** | **成对动画的「同步」＝对齐有效动作窗口，不是改速率**：两条 clip 时长不同（实测 2.333s vs 3.333s）但**必须各自原速**；受击方起手前有一段「死时间」（实测 **0.10~0.61s**，攻击方只有 **0.00~0.14s**），用 `clipStart` 给受击方一个 head start，把两侧的**有效动作窗口起点**对齐到同一时刻。窗口起点用「骨骼逐帧位移能量 >15% 峰值的第一帧」离线实测 | ① 用相位锁定按时长比缩放 → 受击方事件整体提前（Ambush04 被压 **1.429×**，「攻击者还没发力、受击者就先倒下」）；② 什么都不做 → 受击方起手前空等一段。**判据：成对动画数据集（含 `fixedClipReplace`/`pairAnchor`）必须禁用相位锁定** |
| **19** | **看"页面没更新"先怀疑缓存**：用 `python -m http.server` 起的服务**不带 `Cache-Control`**，`viewer.html` 会一直用旧版；必须用项目自带 `serve.py`（发 `no-store`），或强制刷新 | 新功能"看不到"，误判成功能没做出来 |
| **20** | **无头截图别用 `--virtual-time-budget` + `--dump-dom`**（有竞态，同一命令时灵时不灵）；改用 **CDP**：`--remote-debugging-port` → `Runtime.evaluate` 轮询就绪 + 读 `#probeout` → `Page.captureScreenshot` | 截图忽有忽无、画面全黑，据此得出错误结论 |

| **22** | **查看器播放轴：clip 播完必须【冻结末帧】，不能让 mixer 自己回卷** | 成对动画两条 clip 时长不等（如 `Execution02` 3.33s vs `Executed02` 4.17s）。短的那条一旦回卷，就会在对方还在演的时候**反复重播自己的开头** → 看起来"身体扭成一团"。实现：`setActTime()` 到末尾即 `act.paused=true` 并钳住时间 |
| **23** | **Blender 5.x 是 slotted action**：跨骨架搬运 action 会**丢掉挂在【骨架对象】上的动画** | 这批 UE `Root` FBX 的**根位移挂在骨架对象**上（`ARM_OBJ.loc`，不是 `pelvis`）。直接 `ad.action = act` 不绑 slot → 根位移整段丢失。必须 `ad.action_slot = act.slots[0]`，NLA 还要绑 `strip.action_slot`。**最稳做法：不跨骨架搬，让每个 clip 用它自带动画的骨架单独烘 GLB** |
| **24** | **给 `Mannequin_src.fbx` 的网格重绑骨架时，`matrix_parent_inverse` 不能用 `armature.matrix_world.inverted()`** | 该骨架挂在一个 **scale=0.01 的空物体**下 → 求逆得 **100** → 网格世界缩放从 0.01 变成 1 → **蒙皮结果放大 165 倍**（实测网格 bbox 高 27493，应 166）。正解：`Matrix.Identity(4)`（两套骨架世界缩放本来就都是 0.01） |

## 8. 调试方法论（本会话沉淀 · 比具体坑更值钱）

> 提炼自"一个现象查了三层原因"+"方向算了十几次"的实战。

### 8.1 判断产物对不对，先量**官方同类文件**做基准
| 基准 | 值 |
|---|---|
| 官方 `human_lod_4.fbx` 骨架高 | **1.575**（米制） |
| 我们的产物 | 1.492 → 同量级 ✅ |
| 曾出现 | **0.015** → 一眼看出小 100 倍（硬约束 4b） |

### 8.2 跨单位比较，一律换**无量纲比值**
两侧 GLB 一个 cm 一个 m，直接比 `dy` 会得出**错误**结论。用 `位移/身高`（与 viewer 归一化口径一致）：
```
源侧 471.854 / 165.516 = 2.8508
目标侧 4.517 /   1.575 = 2.8669   ← 吻合 0.6% ✅
```

### 8.3 一个现象常常是**多层原因叠加**
"位置对不上"实测拆出三层，每层单独修只能把症状**换一个**：只修空间换算→竖直位移丢失；再修单位/护栏→走向相反；全修完→才对齐。
> **别满足于"症状变了"，要确认"症状消失了"。**

### 8.4 ⭐ **求方向用几何推算，不要读骨骼的局部轴**
本次最大的坑：我用**骨盆局部 +Y 轴**（+54.5°）当"正面朝向"，而**真实正面是 −127°**——**差 180°**（骨盆 +Y 其实指向**背后**）。
**正确做法**：
```
正面 = normalize( 脚踝→脚尖 )        # 最直接（人站立时脚尖朝前）
      或 由 clavicle_l→r / thigh_l→r 的连线取垂直方向
```
> 骨骼的**局部轴约定是制作时随手定的**，不可信；**左右对称骨骼的空间位置关系才是客观的**。

🆕 **补两个实测坑（2026-09-19）**：

| 坑 | 实测 |
|---|---|
| **源侧 / 目标侧的朝向数字不能混用** | 同一句"正面朝向"，骑砍2 模型 = **−Z（θ=+90°）**，UE 源 = **θ≈−127°**。差 180° = `Rot(Z,180°)` 帧变换。README 里那个 `−127°` **是源侧数字**，照搬到 viewer 里必然差 180° |
| **同一根骨的局部 +Y 在两套资产里含义相反** | 骑砍2 `bl_*.glb`：骨盆局部 +Y → (0,0,−1) = **正面**；UE `ue_*.glb`：骨盆局部 +Y → (0,0.004,−1)，而真实正面是 (−0.62,+0.78) → **背后**。所以「骨盆 +Y = 背后」这个结论**只对 UE 源成立**，别当通用规律 |
| **面向求法要选稳的** | `脚踝→脚尖` 在**倒地/被拖**时会乱转（实测伏击末帧 54°→86°）。求"谁在谁背后"这类**稳定朝向**时，用 `up × (clavicle_r − clavicle_l)`；`脚踝→脚尖` 留作校验 |
| **⭐ 正前方的权威口径 = 头（两眼之间的垂线），不是骨盆/肩线** | Ambush04 首帧三口径实测：**眼线 88.8° / 88.2°（两人只差 0.6°）**、肩线垂线 38.1° / 42.9°（差 4.8°）、脚尖 51.6° / 54.1°（差 2.5°）。攻击方**躯干会拧到 109° 而头部始终保持 ~89°**（盯着正前方出刀）→ 拿肩线/骨盆当正面必然算歪。<br>实现：绑定姿态下用几何正面（脚踝→脚尖）标定出 `head` 骨骼**局部空间的前向向量**，运行时取 `head.matrixWorld × 该向量`（`facingOf(L,'head')`，现为默认口径） |

## 11. TRF 出厂验收 & ModKit 填值（2026-09-24 立 —— 一批坏件的教训沉淀）

> **背景**：2026-09-24 查出 09-20 那批 TRF（施法/处决/伏击共 140 条）的位移轨是**绝对语义**，
> 导进游戏会把角色**整体抬高约 1m**；而**那批坏件在查看器里看着完全正常**（查看器走 FBX 世界姿态路径，
> 天生把这个病抹掉）。**教训 = TRF 出厂必须过闸门，且判据不能靠肉眼看看器。**

### 11.1 出厂闸门：`check_trf_pos.py`

```bash
python pipeline/common/check_trf_pos.py <TRF目录或.trf文件...>
```
- **判据**：位置轨**首帧 |分量| > 0.30** 报警。正常动作自身的骨盆位移可到 ~0.15（引导起手 0.14）；病征量级是 **0.79~0.91**。
- 退出码 1 = 有坏件 → **可直接当流水线闸门**。`_` 前缀的归档目录自动跳过。
- 实测：`output/trf` 212 条里抓出 140 条（全在 09-20 那个窗口；09-21 之后的批次干净）。

### 11.2 第二种病：`check_fbx_bindpose.py`

```bash
blender -b --factory-startup --python pipeline/common/check_fbx_bindpose.py -- <a.fbx> ...
```
- **症状**：重出 TRF 后首帧不是 0，而是 **+0.71~+0.83 且每条数值不同**（**不是** 11.1 那个"整批同一个常数"）。
- **病根**：**FBX 的绑定姿势被烘成了躺姿**（骨盆静止高度实测 `0.024`，正常站姿是 `0.849`）⇒ 量出的增量天生带常数偏移。
- **判据**：**首帧 − 绑定姿势 ≠ 0**（好件是 `0.0000`）。
- 🔴 **改 TRF 治不好** —— 得**按官方骨架重做 FBX 的静止姿势**再重出（施法/处决那批 2026-09-24 就是这么修完的）。

### 11.3 判预览真假：`check_glb_feet.py`

```bash
blender -b --factory-startup --python pipeline/common/check_glb_feet.py -- <a.glb> [--clip 名字]
```
- 离线复算「查看器眼里的脚底高度」（复刻 viewer 的归一化规则），**不需要浏览器**。
- 🔴 **查看器会掩盖 11.2 那种病**（FBX 世界姿态路径与静姿无关）⇒ **别拿"查看器里看着对"当验收依据**。
- 要判"游戏里长什么样"，只能走 **TRF 直读烘焙**那条路或本脚本；范本数据集 **`viewer/datasets/ue_exec_trf/`**
  （同一条 clip 两条烘焙路径并排：左 FBX / 右 TRF，自带对照 —— 同 GLB 里修过的那条是 0.068、没修的是 0.8）。

### 11.4 ModKit 填值：`trf_root_travel.py` + `make_import_sheet.py`

TRF 导进 ModKit 后，clip 的 **`Source 1` / `Source 2` / `Duration` 默认是 0**，**必须手填**（否则动画不播，
报错 `pos ipo[2,42] does not fit sources 0.00 and 0.00`）；**带位移的还要填 `displacement` 向量 + `endProgress`**
（引擎不认 TRF 自带的位移轨 —— 详见 §7.2 T17）。

```bash
# 一条量：算出该填的 (X,Y,0) 与 endProgress
python pipeline/common/trf_root_travel.py --trf "<xxx.trf>"
# 整批出表（duration / Source1 / Source2 / displacement X·Y / endProgress 一列不少）
python pipeline/common/make_import_sheet.py        # → output/modkit_import_sheet.csv
```

- **口径**：`source1/source2` = 该 TRF 的帧号范围（不是 0..N）｜`duration` = 帧数 ÷ 30｜
  `displacement` = 角色本地水平面、单位**米**（**+X 右手侧 / +Y 正前方 / Z 恒 0**）、`endProgress` 0.4~1.0。
- **可信度**：拿装机验证过的 `Execution02`/`Executed02` 对过账，量出的值与文档记录**逐位吻合**。
- ⚠️ 工具会同时报**轨迹直线度**：引擎只认直线位移，中途拐弯的条填单向量是**近似**（实机 22 条里 17 条如此，
  原版自己也有这情况）。
