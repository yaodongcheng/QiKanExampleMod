# 路径索引（重组前后对照）· 文档引用自检说明

> 生成：2026-09-19 · 背景：本目录在 2026-09-19 做过一次**工程化重组**（引入 `input/ pipeline/ output/ viewer/ docs/ _legacy/` 分层）。
> 重组把文件搬得很干净，**但文档里的路径没同步改** → 一度出现 **60 处引用失效**（照文档走会扑空 = 经验打折）。

## 4. 归档查看器为什么"跑不起来"

重组把各查看器的 `assets/*.glb` 统一收到了 `output/glb/<数据集>/`（活跃查看器用 `viewer/datasets/<数据集>/assets/`），
所以 `_legacy/old_viewers/*/assets/` 是空的 —— 归档快照保留的是**页面代码**，不是可运行实例。

## 5. 自检（重组后 / 交接前必跑）

```bash

python pipeline/common/check_doc_links.py --all   # 连 _legacy 一起查（归档的过期引用可忽略）
python pipeline/common/fix_doc_paths.py --dry     # 预览"旧路径→新路径"要改哪些（不写盘）
python pipeline/common/fix_doc_paths.py           # 执行，改前自动备份到 _legacy/path_fix_backup_<时间>
```

## 6. 这次踩到的两个教训

1. **重组目录 ≠ 只搬文件**：必须同步改文档引用，否则经验"看不见等于没有"。本次 60 处失效引用就是这么来的。
2. **批量改文档的脚本要能自证安全**：
   - 只替换「正则识别出的整段 token」，绝不做子串替换（否则 `out/` 会污染 `output/`）；
   - 改前备份、改后跑校验器；
   - **本次我第一版补丁脚本把 `pipeline/common/check_doc_links.py` 写成了 0 字节** —— 教训是：改文件前先备份、写完后要 `stat` 一下确认大小非 0。脚本现已按此约定实现（见 §5）。
