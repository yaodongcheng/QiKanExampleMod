## 0. 三个问题的答案（速览）

| 问题 | 结论 | 证据 |
|---|---|---|
| **Q1 多人能不能分别映射到不同骨骼** | ✅ **能**（人有可分辨的间距时） | A 镜 121/121 帧稳定检出 2 人；同一批帧重定向出 **两份独立 FBX+TRF**，均 `verify_modkit_fbx` **PASS（28 骨）** |

## 1. 为什么这次是"进阶"——单人链路的三条隐含前提

`docs/图视频转骨骼动画_机制与落地.md` 那条链路能跑通，靠的是三个**没有被写出来的前提**：

1. **画面里只有一个人** —— `mp.solutions.pose` 内部只保留**置信度最高**的那一个，第二个人直接消失；
2. **相机锁死** —— `world` 关键点是"该人髋中心"的局部系，相机一动，画面里的位移就混进相机运动；
3. **没有道具** —— 整条链路只输出 28 根骨头，场景里别的物体不在语义里。

本次要做的，就是把这三条各自破掉：

| 破掉的前提 | 本次的解法 |
|---|---|
| 单人 | **顶下（top-down）多人**：整帧跑一次 → 把人抹掉 → 再跑（复现官方 `num_poses>1` 的内部机制）+ 多目标跟踪 |
| 锁机位 | **镜头切分 + 跨镜重识别**：硬切处封存轨迹，用外观签名把新镜头里的人接回旧身份 |
| 无道具 | **前景 − 人 = 道具** + 道具轨迹 + **在持握部位的局部系里求偏移**（刚体假设 ⇒ 中位数去噪） |

## 3. Q1 多人 → 多骨骼

### 3.1 方法：抹除迭代（复现官方 `num_poses>1` 的内部机制）

`mp.solutions.pose` 只吐一个人，但它的**探测器本身就支持多框**——只是图里只取了 top-1。
于是我们自己做那个"取 N 次"的循环：

```python
for k in range(max_people):
    r = pose.process(work)                  # ① 整帧跑一次，拿到一个人
    if 检不出 / 太弱: break 或 抹掉继续
    norm, world = r 的关键点
    m = person_mask(norm)                   # ② 用关键点扩出这个人的身体掩码
    work[m] = 周围背景色                     # ③ 把他从画面里抹掉
# ④ 重复 ⇒ 第二个人浮出来
```

+ **逐帧多目标跟踪**：代价 = `0.65×(1−IoU) + 0.35×(归一化质心距离)`，匈牙利求解；
  轨迹连续 `max_missed` 帧没匹配上就判消失。
+ **同镜断轨缝合**：遮挡/漏检让同一个人断成几截，按"**外观相似 + 位置连续**"接回。
+ **轨迹引导的局部重检**：把某人的 bbox 裁出来单独再跑一次（顶下框架的标准补救）。
+ **插值补洞**：缝合后的轨迹内部漏检帧线性插值，并逐帧标 `interp: true` 交给下游。

### 3.2 实测结果

```
A 镜（0~120 帧）：121/121 帧稳定检出 2 人
  S0_T0  髋中点 x≈24（画面左）  衣服主色 = 蓝
  S0_T1  髋中点 x≈78（画面右）  衣服主色 = 红
```

> **独立数值旁证**（不依赖姿态模型）：直接数画面里的强色像素——
> A 镜每一帧都是"蓝 ≈7% @ x=23 + 红 ≈8% @ x=79"，两人**同时存在**；
> B 镜是"蓝 2.2% @ x=51 + 红 4~6% 从 x=34 走到 x=10 后消失 + 绿 0.7% @ x=73"。
> 这与跟踪结果逐条吻合 ⇒ **跟踪没错**。

**端到端产出两份独立骨骼**（同一批 121 帧、两个不同的人）：

| 产物 | 来源身份 | FBX 体检 |
|---|---|---|
| `output/fbx/mp_blue_shotA.fbx` + `.trf` | S0_T0（蓝） | **PASS** 28 骨 / 根名 `human_skeleton_notused` / 无叶骨 / 无 mesh |
| `output/fbx/mp_red_shotA.fbx` + `.trf` | S0_T1（红） | **PASS** 同上 |

两条链路都打印了 `CHECK_OK 0.056°`（解算与 Blender 姿态矩阵一致）与
`CHECK_POS 首帧=0`（位置轨纯增量语义正确）。

复现：
```bash
python pipeline/tools/vid2pose_multi.py --in input/source/multi_person/multishot2.mp4 \
    --out input/source/multi_person/multishot2_multi.json --export --fps 24 --max-people 4
python pipeline/run_retarget.py --rig pose_mediapipe --clip "multishot2_multi__S0_T0_s0" \
    --name mp_blue_shotA --animdir input/source/multi_person --pelvis ground
```

### 3.3 🔴 失败模式（**实测踩到，必须知道**）

> **BlazePose 的探测器在"多人紧贴重叠"时会整帧返回 None。**

素材 B 镜中段（第 128~145 帧）三个人**几乎叠在一起**，`pose_detection` 直接检不到人 ——
而**画面本身完全正常**（视觉复核：亮度 144~147、std≈55、无模糊无重影，三个人清晰可见）。
表现为：`per-frame 人数` 从 3 掉到 0，一条轨迹被切成两截。

**补救（已实现，部分有效）**：
- 低置信度的人**不能整帧放弃**（原来一旦第一个人可见度低就 `break`，导致整帧 0 人）⇒ 改成"抹掉他继续找"；
- 轨迹引导的**局部裁剪重检**（裁到单人 bbox → 目标占满画面 → 探测成功率上升）；
- 仍拿不到就**同镜缝合 + 插值补洞**，并把补的帧标成 `interp=true`。

**本次实测**：445 个观测帧里靠缝合+插值补回 84 帧（约 15%），全部带标记。
**更彻底的解法**（本机没有、留作升级路径）：换一个更强的人体检测器（YOLO 系权重）做候选框，
或改用带 `num_poses` 的 `.task` 权重 —— 两者都需要能下载权重。

## 4. Q2 换镜 → 前后镜头的人对应谁

### 4.1 方法

**① 硬切检测**（两条判据同时满足，防误切）：
```
灰度帧间差 > max(0.10, 中位数 + 8×MAD)   且   HSV 直方图相关性 < 0.75
```

**② 跨镜重识别（ReID）**：镜头切了就**封存**所有轨迹，新镜头重新建轨迹，
再用**外观签名**往前面所有镜头的"身份池"里匹配（匈牙利 + 阈值）：

| 特征 | 权重 | 为什么 |
|---|---|---|
| **躯干 ROI 的色调直方图**（按饱和度加权，30 bin） | 0.55 | 直方图对**换镜后的曝光变化**鲁棒（均值色会被整体亮度带偏） |
| 腿部 ROI 的色调直方图 | 0.25 | 上衣/裤子不同色时也能区分 |
| 体型比例（肩宽/髋宽、躯干/腿长、肩宽/躯干长） | 0.20 | 与相机无关，补色相特征的盲区 |

**③ 进出场判定**：
- 一条轨迹**中途消失且之后再没出现** → `exit_mid_shot`（离场）；
- 一条轨迹**匹配不上任何旧身份** → `enter_shot`（新入场）；
- 身份池保留历史身份 ⇒ "出去的人又回来了"也能接回。

### 4.2 实测结果（本 case 全部命中）

```
切镜    : 1 个硬切点 = 第 121 帧     ← 与拼接边界帧号完全一致 ✅

身份    : 3 个（= 素材里真实的 3 个角色）
  S0_T0  跨 2 镜 / 242 帧  [镜0 0-120] + [镜1 121-241]    ← 蓝衣，A/B 镜都是他
  S0_T1  跨 2 镜 / 183 帧  [镜0 0-120] + [镜1 123-184]    ← 红衣，B 镜走到 184 帧离场
  S1_T3  跨 1 镜 / 119 帧  [镜1 123-241]                   ← 绿衣，只在 B 镜，判为新入场

跨镜匹配: S1_T2 → S0_T0（0.768）｜ S1_T4 → S0_T1（0.579）
事件    : exit_mid_shot S0_T1 @帧184 ｜ enter_shot S1_T3 @帧123
```

### 4.3 🔴 阈值怎么定才不是拍脑袋

把**所有身份两两**的相似度都算出来，看分布：

| 配对 | 相似度 |
|---|---|
| 蓝(A镜) × 蓝(B镜) | **0.768** ← 正配 |
| 红(A镜) × 红(B镜) | **0.378** ← 正配（红衣在 B 镜已走到画面边缘，躯干 ROI 被裁掉一部分，特征退化） |
| 蓝 × 红、蓝 × 绿、红 × 绿、…… | **全部 ≤ 0.160** ← 错配 |

⇒ **正配最低 0.378、错配最高 0.160，中间留了 0.22 的宽间隔**，阈值取 **0.30** 落在中间。
这比"默认 0.45"能多救回红衣那条（0.378），而且离错配线还有一倍余量。
**结论：ReID 阈值必须用本素材的相似度分布来标定，不能抄默认值。**

### 4.4 与色相特征的解耦

红衣在 B 镜已经走到画面边缘，外观特征退化到 0.378 —— 这是这套**经典特征 ReID 的真实上限**。
如果素材里两个人穿同色衣服，这一招会直接失效；那时只能引入真正的 ReID 权重（本机拉不到）。

## 5. Q3 道具提取 + 挂接点解算

### 5.1 方法（三步）

**① 道具 = 前景 − 人**
- 前景 = 当前帧 vs **背景模型** 的差（阈值化 + 形态学开闭）；
- 人 = `selfie_segmentation`（内置模型，精确人体轮廓）∪ 关键点胶囊，再膨胀；
- 道具 = 连通域，按面积过滤。

**② 道具跟踪**：连通域按"质心最近 + 面积相近"跨帧连成轨迹。

**③ 挂接点解算（最值钱的一步）**
对每一帧找"离道具最近的身体末端点"（腕/手/头/胸），距离 < 门限 ⇒ 判这一帧**被该部位持握**；
然后在**该部位自身的局部系**里表示道具质心：
```
u = normalize(腕 − 肘)            # 前臂方向
v = perp(u)                       # 前臂法向
offset = ( (p_prop − p_wrist)·u , (p_prop − p_wrist)·v ) / 人体像素高
```
> **为什么这样算**：**刚性持有的道具，它在这个局部系里的偏移是常量**。
> 于是对所有"被持握"的帧取**中位数**即可把逐帧噪声抵消 —— 这就是"挂接点"的物理含义。
> 输出里同时给 `offset_std`：**它小 ⇒ 确实刚性挂接（结论可信）；它大 ⇒ 只是"靠近"没"挂住"**。

### 5.2 实测结果

```
A 镜：P0_0  帧43-120（78 帧）  面积0.0082  颜色[206,190,175] = 发光球
       挂接 S0_T0.r_hand，持握率 41%，偏移中位 [0.108, -0.073]，标准差 [0.080, 0.179]
B 镜：0 条
```

**视觉复核（诊断图 + 叠加图）**：
- 球**没生成**的帧（f0~f40）：无框 ✅ 不误报；
- 球**生成后在空中/手掌前方**（f60 / f80 / f100）：**黄框 + 红点全部准确套在发光球上** ✅；
- 球**被双手捧在胸前**（f130~f240）：**0/7 命中** ❌。

> 那个"持握率 41%、标准差 0.18"其实**是正确的物理**：A 镜这个球是被**推掷**出去的，
> 只有一部分帧被手拿着，其余帧在自由飞行 ⇒ 高 std 恰恰说明"它不是一个刚性挂接的武器"。

### 5.3 🔴 两个根因（都定位到了，都很有价值）

**(a) 贴身持握 ⇒ 道具被人体掩码吃掉。**
B 镜里球一直**贴着胸、被双手捧着**，完全落在人体轮廓内部 ⇒ `前景 − 人` 把它当"人"一起减掉了。

→ 已实现的补救：**用它在"裸露期"（A 镜）的像素统计出外观签名，再去 B 镜里按签名搜同款**。
  **但实测它锁到了错误目标**：发光球是亮白偏灰 `[206,190,175]`，而 UE 小白人的**头和手本身就是亮灰色**，
  颜色几乎不可分 ⇒ 签名续接 121/121 帧全中、但全锁在**绿衣角色的头/手**上。
  **这是"道具与被摄体同色"的固有歧义**，不是实现 bug。⇒ 该功能标记为 `--carry`（**实验性，默认关闭**）。

**(b) 静态镜头下，普通"时间中位数背景"会把角色烤进背景。**
这是更隐蔽、也更通用的一条：
B 镜三个人**基本站着不动** ⇒ 某个像素在 >50% 的帧里都是"人" ⇒ **中位数把角色自己当成了背景**。
后果：球与背景的差 ≈ 0，**怎么调阈值都拿不到**（实测命中 0/121）。

→ 已实现补救：**带人体掩码的时间中位数背景**（逐像素只在"该像素不属于任何人"的帧上取中位数，
  按行分块算避免整段堆内存）。换上去之后 A 镜的道具从"4 条混杂轨迹"变成"1 条干净的球轨迹"。

### 5.4 现状与升级路径

| 形态 | 现状 |
|---|---|
| 道具在**空中 / 手掌前方 / 伸出轮廓** | ✅ 能提，能跟踪，能解挂接点 |
| 道具**贴身持握 / 被双手捧住** | ❌ 会被人掩码吞掉；签名续接对"道具与人体同色"会误锁 |
| 相机在动的镜头 | ❌ 未做全局运动补偿（工具会打印"背景不稳"告警） |

升级路径（按性价比排序）：
1. **模板匹配 / 相关滤波**：把裸露期的道具裁成模板，后续帧做归一化互相关（比均值色强得多，能区分"球"与"灰手"）；
2. **专用的"手部包围盒"先验**：只在双腕构成的凸包内部找道具（贴着手的道具必然在这个区域里）；
3. **接一个小的目标检测/分割权重**（需要能下权重，本机不行）；
4. **相机运动补偿**：ORB + RANSAC 单应估计全局运动，再算残差前景（运动镜头必需）。

## 6. 这轮新踩的坑（都带实测证据）

| # | 坑 | 现象 | 修法 |
|---|---|---|---|
| 1 | **低置信度的人会连累整帧** | 一个人半出画 ⇒ 可见度均值被拉低 ⇒ 原来 `break` 掉整帧 ⇒ 25 帧"整帧 0 人"，轨迹断成两截 | 低置信度的人**抹掉继续找**，只有连 bbox 都立不住才停 |
| 2 | **断轨外推把位置判据撑爆** | 缝合时用"单帧位移 × 断帧数"外推，30 帧能放大成几个身位 ⇒ 本该合并的轨迹永远过不了位置判据 | 外推**限步**（`min(dt,4)`，单帧位移先 clip） |
| 3 | **内置 `hash()` 不能给身份上色** | Python 字符串 hash 每进程随机（`PYTHONHASHSEED`），不同身份会撞成同色 | 换确定性 `zlib.crc32` |
| 4 | **`cv2.imwrite` 在中文路径静默失败** | 返回 False，不抛异常，图就是没落盘 | 一律 `imencode` + `tofile`（沿用 `vid2pose` 的 `imread_utf8` 约定） |
| 5 | **只用关键点胶囊当人体掩码不够** | 衣服/头发比骨架宽 ⇒ 红衣角色走动时**整件衣服**被当成道具（占画面 7.5%） | 叠加 `selfie_segmentation` 精确轮廓 |
| 6 | **静态镜头下普通中位数背景会把角色烤进去** | 人站着不动 ⇒ 中位数背景里就有这个人 ⇒ 他身上/手上的道具与背景差 ≈ 0，**永远检不到** | **带人体掩码的时间中位数背景**（只在非人像素上取中位数） |
| 7 | **"顶下"顺序不能反** | 先补漏检帧再缝合，补检没有长轨迹可依附 ⇒ 白补 | **先缝合、再补检、再插值** |
| 8 | **视觉模型的"小图逐格判读"会看错** | 它把 A 镜的"双人同框"读成"单人轮流出现" | 用**独立数值判据**（强色像素占比 + 重心 x）交叉验证；视觉结论不单独作为定论 |

## 10. 能力边界（上线前先读）

| 能做 | 不能做 / 要注意 |
|---|---|
| 单人可分辨间距下的多人（实测 3 人稳定） | **紧贴重叠**会让 BlazePose 探测整帧失败（§3.3），靠缝合+插值兜，会标 `interp` |
| 硬切换镜检测 + 跨镜身份对应 | **渐变转场 / 运动镜头**不适用（硬切判据是"突变"） |
| 同色衣服以外的人靠色调直方图 ReID | **两人同色衣服**会失效，需要真正的 ReID 权重 |
| 伸出轮廓的道具提取 + 刚性挂接偏移 | **贴身持握**的道具会被人体掩码吞掉（§5.3a） |
| 全局位移 | ❌ 仍不做（`world` 是髋中心局部系；多人的**相对站位**可从 `norm` + 人高近似推，绝对位置要相机标定） |
| twist / 手型 | ❌ 目标骨架限制，与单人链路一致 |

> 验收纪律沿用本仓：**先看叠加图确认"检出对不对"，再去看骨骼**；
> 数值判据与视觉判据**两条一起过**（视觉判小图会看错，数值看不出穿模）。

## 11. 新案例：成对交互动画「背后点穴 → 应声倒地」（视频 → 查看器）

> 需求：跟查看器里 `ue_exec_pair`（处决/伏击 11 组）同类，但**没有现成动作资产**，
> 只有一段视频，要一路做到能在查看器里看。
> 真身：`input/source/dianxue_pair/` ｜ 数据集：`viewer/datasets/pose_dianxue_pair/`
> 新增工具：`pipeline/tools/root_z_from_image.py`

### 11.1 链路

```
Seedance 生成（锁机位 · 侧 60° · 两角色衣色强区分：深青 + 浅灰）
  → vid2pose_multi.py            多人提取（2 身份 / 241 帧 / 仅 21 帧插值）
  → run_retarget.py ×2           各自解算成骑砍2 28 骨（FBX+TRF，体检均 PASS）
  → root_z_from_image.py         ★ 补「倒地下沉」的根位移（见 11.3）
  → glb_pack_retargeted.py       两条动画打进一个 GLB
  → viewer/datasets/pose_dianxue_pair/  dataset.json 声明 sides + pairs
```

查看器 URL：`viewer.html?ds=pose_dianxue_pair`

### 11.2 提取结果（数值验收）

| 项 | 结果 |
|---|---|
| 多人分离 | 2 个身份，**241/239 帧全程跟踪**，插值补洞仅 21 帧 |
| **手够到没有** | 攻击者腕 → 受击者头/肩中点：**0.08~0.21**（按人体高归一化）⇒ **确实够到并接触** |
| 受击者是否真躺下 | 人体像素高 **0.72 → 0.08**、髋中点 y 0.493 → 0.842 ⇒ 真的躺平了 |
| 朝向 | 两人中位 yaw 均 ≈ **−90°**、逐帧 0 突跳 ⇒ 两人**朝向一致**（侧对镜头），没有左右判反 |

### 11.3 🔴 本 case 暴露的**新缺口**：倒地下沉是"根位移"，被现有链路吃掉了

`pose_mediapipe` 链路**只搬关节角度、不做全局位移**（`world` 天生是髋中心局部系）。
这在跑步/挥拳这类原地动作上没问题，但**倒地会被直接吃掉**：
受击者明明趴在地上，解出来的动画是"身体在髋高 ≈0.9 m 水平躺着"——**悬在半空**。

> 为什么不能填到 `displacement` 槽？骑砍2 的 AnimationClip `displacement` **只吃水平分量**
> （原版 333 条实测 Z 恒为 0，见 `pipeline/common/trf_root_travel.py`）。
> 所以下沉**只能写进根骨位置轨** —— 这也正是本仓 `_ground_trf`（压脚底）走的那条路。

**新增 `pipeline/tools/root_z_from_image.py`**（自标定单目估高，不需要相机参数）：

```
ground = 全片所有可见关键点的最大 y（最低点；人倒地时身体贴地 ⇒ 该值就是地面线）
h(f)   = ground − 髋中点y(f)                髋中点离地高度（归一化）
scale  = stand_h / h(0)                      米/单位（用"站立时髋高 stand_h=0.90m"自标定）
dz(f)  = h(f)·scale − h(0)·scale             加到 TRF 根骨位置轨 Z 上
```

**两条护栏**：
1. **落差判据**：髋最高到最低的落差 < `--min-hip-drop`（默认 0.15 m）就**判为非倒地、不动 TRF**。
   实测本 case：受击者落差 **0.893 m** ⇒ 执行；攻击者落差 **0.036 m** ⇒ **被护栏拦下，TRF 一字未改**。
2. **幂等**：在 TRF 旁写 sidecar `<trf>.rootz.json` 记录这次加的曲线，重跑时**先减掉上次的再加新的**。

### 11.4 查看器接入（照 `ue_exec_pair` 的约定）

- **一个 GLB 两条动画**：`viewer/datasets/pose_dianxue_pair/assets/dianxue_pair.glb`（含 `dianxue_attack` / `dianxue_victim`），
  两侧各用**不同的 file id** 指向同一个 url（`dx_atk` / `dx_vic`）—— 同一 id 会被 `loaded` 覆盖成同一个实例，两人会重叠。
- `sides.src`：`pairAnchor {anchor:"dst", pelvisBone:"pelvis", gap:0.80, mode:"behind"}` + `fixedClip:"dianxue_attack"`
- `sides.dst`：`fixedClipReplace [["dianxue_attack","dianxue_victim"]]`（自动配对，且把受击方那条从列表里隐藏）
- 两侧都开 `freezeRootH`（把根位移的**水平**分量归零，**保留竖直**）—— 我们的下沉在竖直上，正是要保的。
- `pairs`：`{"dianxue_attack": {"src":[null,null,null,0], "dst":[null,null,null,0]}}`（8 参数的落点，留给后续手调）

> **gap 怎么定**：点穴要贴到人，不能照抄 execute 的 1.5 m。实测取 **0.80 m** 时，
> 查看器里手正好落在受击者后背上（验收图 t=4.4~7.0 s 可见接触）。

### 11.5 查看器验收（无头截图 + 视觉复核）

| 判据 | 结果 |
|---|---|
| 前后关系 | **俯视图证实一前一后**（不是并排）；青=后方点穴者、橙=前方受击者 |
| 动作时序 | 站立 → 伸手按住后背 → 受击者前倾 → **t=9.6 s 完全躺平在地** |
| 悬空 / 穿地 | **无**（下沉补偿生效） |
| 躯干穿模 / 扭曲 / 朝向反 | 无 |
| FBX 体检 | 两份均 **PASS**（28 骨 / 根名 / 无叶骨 / 无 mesh） |

### 11.6 🔴 又踩一个坑：查看器的 `?t=` 是**秒**，不是归一化比例

第一次验收我传的 t 依次为 0.0、0.5、0.75、1.0，结果**四格画面几乎一模一样**，
差点误判成"动画没绑上 / 关键帧没写"。实际原因：`seekToTime(t)` 收的是**秒**，
而这条动画有 10 秒 —— 0~1.0 全落在第一秒里，姿势当然一样。
⇒ 改成 `t=0 / 2.6 / 4.4 / 5.6 / 7.0 / 9.6` 才看到完整过程。

**排查心法**：无头截图"多帧一个样"时，先怀疑**取时/取帧参数的单位与口径**，
再去怀疑动画本身。这类误判成本很高（会去翻绑定、翻关键帧）。

## 12. 点穴案例的迭代记录（**节奏问题的正确解法是"切"，不是"重新生成"**）

用户反馈：10 秒太拖、前面全是废时间、还有抽搐。这一轮试了 4 版，结论很硬：

### 12.1 四版素材的实测时间线（都量过）

| 版本 | 时长 | 实测内容 | 结论 |
|---|---|---|---|
| v1（首版 10s） | 10.04s | f0–48 站着发呆(2s) → **f48–80 伸手推进**(腕到后颈 0.44→**0.08 真接触**) → f80–160 按住 → f160–196 反应+倒地 → f196–240 躺尸(1.8s) | **动作内容最全**，但两头都是废时间 + 抽搐 |
| v2（压到 4s） | 4.04s | 开场手已伸在颈后(**看不到"戳"**) → **f15–51 整段冻结 1.5s** → f51–69 塌倒 → f69–96 躺尸 1.1s | 抽搐没了，但"戳"看不见、仍有冻帧 |
| v3（写死"从垂手开始戳"） | 4.04s | **动作全挤在前 0.5s** → 剩下 **3.5s 躺尸** | 更差，弃用 |
| **v1 切片（交付版）** | **3.87s** | f45–100(伸手+接触) + f160–196(反应+倒地) | ✅ **保留真接触，切掉两头废时间** |

> **核心结论：生成模型对"快节奏"的控制不可靠（试了 3 次，节奏一次比一次不可控）。
> 与其反复抽卡，不如承认素材的"动作段"是好的，用 `select_frames.py` 把废时间段切掉。**
> 切之前**必须验证切点两侧姿态连续** —— 判据是"逐关键点归一化位置差"：
> 实测本 case 接缝最大差 **0.05 身位**（≈8 cm，在肘上）⇒ 肉眼基本看不出（**视觉模型说"明显后倾"，是过度解读**）。

### 12.2 🔴 本轮最贵的 bug：**塌缩帧把整条动画的根压歪了**

**现象**：查看器里受击者**开局就躺在地上**，8 帧姿态几乎不变 —— 看起来像"动画没做"。

**根因链**（查了很久）：
```
BlazePose 在受击者被攻击者遮挡的 f45~f49 吐出「置信度不低、但整个人塌成一坨」的姿势
   （头+0.06 / 髋-0.01 / 踝-0.07，整个人只有 0.13 m 高，正常 1.7 m）
        ↓ 这些废帧正好落在轨迹的**开头**
        ↓ run_retarget 的 _ground_trf 用**首帧**FK 量脚底 → 量出"脚底在 1.32 m 高"
        ↓ 于是把【整条 4 秒动画】沿世界 Z 压下去 1.32 m
结果：受击者从头到尾贴在地上，"倒地"这个动作被压没了
```

**修法**（`vid2pose_multi.py` 新增 `sanitize_tracks`）：把「人体跨度塌缩」的帧判无效，
用相邻好帧插值并标 `interp`。

以下是**三个我实际踩过的写法错误**，每个都让护栏失效：

| 错误写法 | 为什么失效 |
|---|---|
| 量 `norm`（图像归一化）的髋宽 | norm 的宽窄只反映"人在画面哪/多大"，世界尺度塌缩时它**一点不变** |
| 量 `world` 的**髋宽/肩宽** | `pose_world_landmarks` 是**按人体自身尺度归一化**的 —— 姿势再怎么塌，髋宽照样 ≈0.25 m |
| 护栏放在**平滑之前** | 原始值 0.8x 没触发阈值，savgol 平滑后掉到 0.70，**坏帧反而是最终产物里的** |
| 护栏放在**检测阶段** | 坏帧可能是**局部裁剪重检**或**断轨缝合**补出来的，检测阶段过滤会被这两步绕过 |

**✅ 正确写法**：量 **`world` 的【人体包围盒对角线】**（站立/躺地都 ≈1.6~1.8 m，塌缩时只剩 0.1~0.7 m），
用**相对(60%中位) + 绝对(<0.95 m) 双阈值**，并且**放在平滑之后的最终轨迹上**。

### 12.3 交付版验收

| 判据 | 结果 |
|---|---|
| t=0 起点 | **两人都站立**（不是躺着的）✅ |

| 受击者 | t=1.9~2.35 僵直 → t=2.7 膝软起倒 → t=3.8 **躺平在地** ✅ |
| 悬空/穿地/跳帧/朝向反 | 无 ✅ |
| 总时长 | **3.87 秒**（原 10 秒） |
| 视觉复核结论 | **"整体判定：通过"** |

## 13. 「花式葵花点穴手」：**生成做不到，改为手 K 关键帧**

### 13.1 为什么放弃生成

需求从"背后点一下"升级成"**花式的**葵花点穴手"（绕手备势 → 并指双击 → 瞬间定格 → 直挺挺倒地）。
又试了一版把编排写死的提示词（v4），实测：

| 期望节拍 | v4 实际 |
|---|---|
| ① 绕手备势（划圈） | ❌ 手举到肩就直接停住 |
| ② 并指双击 | ❌ 手在肩上一按 **2.7 秒** |
| ③ 瞬间定格 | ❌ 无 |
| ④ 直挺挺前倒 | ⚠️ 终态对，过程断档 |

**五版生成 + 两轮提示词工程，四拍编排一次都没出现。**
结论：**生成模型能给你"一个动作"，给不了"一套编排"。** 编排必须自己写。

### 13.2 手 K 的做法：**不写骨骼，写关键点**

本项目已有一条成熟解算链（`rigs/pose_mediapipe`：把 33 个 3D 关键点"瞄准"成骑砍2 28 骨）。
所以只要**造出 33 个关键点的逐帧轨迹**，下游（解算 / TRF / 倒地根位移 / GLB / 查看器）**一行都不用改**。

新增 `pipeline/tools/author_dianxue_pair.py`：
- 内部统一用**骨架系**（X=角色右手侧、Y=正前方、Z=上、原点=双髋中点），写文件前转 MediaPipe。
- 姿势用**手写的解剖学静止姿势**当基底，再逐帧施加：
  - `set_arm(侧, 腕目标)`：**两骨 IK**，只要给"手该在哪"，肘自动解出来。
  - `bend_upper(yaw, pitch)`：上半身整体扭转 + 前倾 —— **这是"身法"的来源**。
  - `rigid_about(pivot, axis, deg)`：把**所有**关键点整体刚性旋转（不做任何关节弯曲）⇒ 这就是"木板式倒地"。
- 编排（24fps / 96 帧 = 4.0 秒）：
  ```
  攻击者  绕手备势(6-26帧) → 蓄势 → 双击(37帧高 / 46帧低) → 收势亮相(56帧后保持)
  受击者  站立 → 绷直定格(36-40) → 定住(40-48) → 木板式前倒(48-70) → 躺平
  ```
- **下沉量直接由编排给出**（`root_z_m`），不用再从画面估 ⇒ 给 `root_z_from_image.py` 加了"若有 root_z_m 就直接用"的分支。

### 13.3 🔴 这一轮踩到的"设计"坑（比代码坑更值钱）

| # | 坑 | 说明 |
|---|---|---|
| 1 | **圈画错了平面** | 第一版把"绕手"的圈画在**左右方向**的平面上；相机在**侧面 60°**，这个方向被透视压扁，**画面上根本看不见**。改成画在**前后-上下**平面并把半径加到 0.30 m，侧面才看得清。**编排必须先想"相机从哪看"。** |
| 2 | **只动手臂 = "抬手指了个方向"** | 手臂动作再大，躯干不跟，观感就不像武打。加上上半身扭转 ±30° 之后"以身为轴"的感觉才出来。 |
| 3 | **另一只手不能当观众** | 左臂全程贴腿 ⇒ 观感是"单臂机器人"。加了：绕手时**护在胸前**、戳击时**往后引**（对拉）、亮相时**对称张开**。 |
| 4 | **"亮相"不是"手放胸前"** | 第一版收势只是把手放在胸前，跟垂手差不多、等于没有。必须**手抬到肩高以上 + 肘往外上方张**才是定格造型。 |
| 5 | **两戳要一高一低** | 两个目标点几乎重合 ⇒ 看起来是同一个动作放了两遍。改成"上戳后颈、下戳肩胛"，高度差拉开。 |

### 13.4 ⚠️ 骨架的硬限制：**剑指做不了**

骑砍2 每只手只有 **1 根静态手指骨**（`map.json` 里 `*_finger0` 是 `keep_rest`）。
所以**食指+中指并拢的"剑指"手型表达不出来** —— 这不是实现问题，是目标骨架的限制。
"花式"只能靠**手臂/手腕的编排**（绕圈、双击、收势）+ **躯干身法** + **受击者的定格与木板倒**来传达。

### 13.5 验收数据（从 GLB 里直接读骨骼轨道，不靠肉眼）

| 轨道 | 最大幅度 | 说明 |
|---|---|---|
| `r_foretwist`（右前臂） | **173.8°** | 绕手一整圈 ✓ |
| `r_upperarm_twist` | **97.3°** | 抬臂外张 ✓ |
| `l_foretwist`（左前臂） | **135.3°** | 左手护手/对拉 ✓ |
| `l_upperarm_twist` | **88.8°** | ✓ |
| `l/r_clavicle` | **44.0°** | 肩带参与 ✓ |
| `pelvis` | **17.0°** | 躯干扭转传导到根骨 ✓ |

> **教训：验收"动作幅度"要读骨骼轨道，别只靠静态截图 + 视觉模型。**
> 这一轮视觉模型连续两次说"左手全程贴腿不动"，而 GLB 里 `l_foretwist` 明明摆动了 135°。
> 静态关键帧抽样会漏掉"中间过程"，视觉模型对小图也容易误读。

## 14. 照着参考剧照拆动作：白展堂「葵花点穴手」

> 用户一句"你自己去找武林外传里面白展堂点穴的图自己去学"，把问题点透了：
> **我一直在"凭感觉编"，没有找过参考。** 拆完参考才发现，我自己编的和真的「葵花点穴手」差得很远。

### 14.1 参考图与拆解方法

- 搜图 → 下载 7 张剧照到 `input/source/dianxue_ref/`（拼图：`output/verify/dianxue_pair/_白展堂点穴参考.png`）
- 交给视觉模型**按身体部位逐条拆**（不要描述"这是谁"，要拆成"手型/手臂/躯干/步型/另一只手"这种可照做的描述）

### 14.2 拆出来的 7 条（**和我"凭感觉编"的差别很大**）

| # | 参考里的事实 | 我原来的做法 | 改成 |
|---|---|---|---|
| 1 | **剑指**：食指+中指并拢伸出，其余三指收握进掌心 | 没写手型 | 骑砍2 每手只有 **1 根静态手指骨 → 做不了**（硬限制），但**手臂走势必须照剑指来**：直臂、指尖朝前 |
| 2 | 出手那条手臂**完全伸直、肘锁死**，肩到指尖一条干净直线 | IK 解出来是**弯肘** | 腕目标设在**可达距离之外** ⇒ IK 直接拉成直臂（实测臂长 0.582 / 全长 0.60） |
| 3 | 高度**齐肩到齐胸，不举过头** | 手落在齐胸（比肩低 0.176 m） | 把目标方向抬到**手落在肩高**（实测差 5 mm） |
| 4 | 躯干 **3/4 侧身 + 拧腰** | 有但不够 | 肩线拧到 **33°** |
| 5 | **空着的手低放/略向后** —— 不要和出手的手对称张开 | 我做成**双手对称张开**（错） | 改回非对称：左手在 **(-0.30,-0.22,-0.13)**（低 + 后引） |
| 6 | 脚下**轻弓步/虚步**，双脚不并排 | **腿完全没动** | 加虚步：右脚尖 +0.46 / 左脚尖 −0.09（前后差 0.55 m） |
| 7 | 整体是「**定格亮相**」：contact 帧要 **HOLD 住** | 戳完就收 | 出手后**完全定住 21 帧 = 0.875 秒** |

> ⭐ **第 7 条最关键**：**"花式"不是靠绕圈，是靠"出手后定住给人看"。**
> 我前一版花了大力气做"绕手划圈"，而真正的招牌是"**摆住那个造型**"。

### 14.3 数据验收（不靠肉眼）

| 判据 | 实测 | 符合参考 |
|---|---|---|
| 臂长（肩→腕） | **0.582 m**（全长 0.60） | ✅ 直臂 |
| 手 vs 肩高 | 差 **0.005 m** | ✅ 齐肩 |

### 14.4 🔴 又一条方法论教训：**验收要看侧面机位**

默认机位是 3/4 侧后方，**虚步、直臂、拧腰这三条在默认机位下几乎看不出来** ——
视觉模型因此在默认机位下只给 **2/5 分**（"没虚步、没拧腰、手臂是弯的"），
而数值明明全都在。换成 **`&view=side` 侧面机位**再验，同一版立刻变成 **3.5/5**（五项里四项到位）。

**结论：验收"步型/臂线/身法"必须用侧面机位；默认 3/4 机位只适合看整体关系。**

### 14.5 还差的一条：手型

参考的招牌是"食指中指并拢齐肩平推"，骑砍2 骨架做不出指型 —— 这是目标骨架的硬限制。
补了一个可做的细节：**接触瞬间手腕过冲 2 帧再回弹**（"点"的那一下），
否则动作读起来像"推掌"而不是"点穴"。
