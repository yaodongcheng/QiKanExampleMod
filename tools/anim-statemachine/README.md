## 一、怎么用

| 你要做的事 | 怎么做 |
|---|---|
| **改状态机** | 双击 **`statemachine_editor.html`** → 顶栏 **「打开 XML…」** 选 `ModuleData/statemachines/flight.xml` → 改 → **「保存」**（或 **Ctrl+S**）→ 重启游戏生效（**不用重编译、不用手粘文件**） |
| 保存会写到哪 | 写到**你打开的那一份**（顶栏药丸写着文件名）。没打开过文件时，「保存」自动退化成「另存为…」 |
| 换一份 / 存新的 | 「打开 XML…」换一份；「另存为…」换名字或换目录（之后「保存」就写新的那份） |
| **回退 / 改错了** | 页面上 **Ctrl+Z** 撤销；**写坏的那一版**去 **git** 里找（那份 xml 是仓库文件） |
| 加/改状态、边、容器（状态机结构） | 同上。**要 Chrome / Edge**（页面用的是浏览器的「直接读写文件」接口）；换别的浏览器就用不了，页面上会提示 |
| 改了生成器代码 | 跑下面的命令，一条都不能省 |
| **删节点 / 删边** | 选中它按 **Delete**。删状态 / 容器会**级联**带走相关的边 —— 删错 Ctrl+Z 回来 |
| **新建状态** | 画布空白处右键 → 「新建状态」。🔴 **在哪个页面建，就放进你正看着的那个容器**（菜单上会写「放进「X」」）：容器页 ⇒ 进那个容器；**状态页** ⇒ 进那个状态所在的容器、并**切到那一页**（不然你在当前页根本看不见它）；总览 ⇒ 顶层（不属于任何容器，比如 `超人落地` 那种衔接状态）。**粘贴状态**同一条规则 |
| **改「循环 / 一次性」** | 状态面板顶部的 **单选开关**。一次性**不写时长** —— 长度由 **clip 自己带**（引擎给 0~1 播放进度），重导 clip 换帧数也不用改配置 |
| **把几个状态收成一个子容器** | 容器页里点 **「＋ 新建子容器」**（新容器就装在当前容器里）——🔴 **你会留在当前页**、新盒子**当场就在画面里**（它在内容区**右侧**，已自动取景，不用去找）。再把状态拖进那个盒子 / 从「加入成员」里选。🔴 也可以直接把一个**已有的容器**拖到另一个容器盒上 = 变成它的子容器（**会防环**）。成员列表里 **🗂** 标的就是子容器 |
| **把一个状态 / 子容器「塞进」容器** | 三条路：① **直接拖**那个状态节点 / 容器盒，丢到目标容器盒上松手（判据 = 光标在盒里 **或** 被拖元素的中心在盒里）；② 右键状态 / 容器盒 → **「移进容器…」** → 选目标（还可以「移出容器（变成顶层）」）；③ 选中容器 → 右侧面板 **「加入成员」** 下拉。
| **边的「剩余多少」条件** | 阈值填**百分比**（0~100），落盘成 `anim-rem-pct="20"`。**不填秒数** |
| **切页 / 镜头** | 顶栏的 tab 点一下切页：**每页各自记一份镜头**（切回总览直接回到你离开时的取景，不会顶着别的页的缩放）。第一次打开某页会自动「适应视图」—— 所以新建出来的子容器**立刻看得见** |
| **线为什么一会儿实一会儿虚** | 画布**左下角有常驻图例**（以前没有，被问过）—— 三种线**各有含义，而且都写了"怎么设"**：<br>· **实线** = 普通边（**每个 tick** 判一次 · 约 60 次/秒；条件写 按键 / 谓词 / 动画）<br>· **点线** = **事件驱动**（状态机不求值，C# 在"起飞 / 落地"那一刻强行走）—— **条件选「游戏事件」**<br>· **虚线** = **演完才进**（一次性动作播完才过去，状态机自己的门）—— **勾边上的「演完才进」** |
| **「演完才进」和「动画 · 剩余 %」是一回事吗** | **是同一个思路**（用户 2026-09-27 定调）：都是"**快播完了才进**"—— 留一点余量，让下一条**在通道还没空的时候**接上。<br>· **要"播完就进下一个"** ⇒ 条件选「**动画播放情况**」+ 填数字（如 `15` = 剩 15% 就命中）。**动画条件只有这一种写法**（`anim="finished"` 已删 —— 它等于"剩余 + 一个隐含余量"，两套词汇只会让人纠结）。<br>· **勾「演完才进」** = **门，不是触发**：只表示"别打断这个一次性动作"，**条件仍要成立**（两者是**与**）。它的"演完"判据 = 剩余 ≤ 根节点 `finish-margin`（默认 15%）。<br>🔴 **为什么必须留余量**：`SetActionChannel` 传的是 `blendOutPeriodToNoAnim: 0` ⇒ **clip 一播完，0 号通道当场空掉**（引擎回到走跑 / 默认姿势），而状态机只能**下一个 tick** 才发现 ⇒ ① 掉几帧默认姿势 ② **随后的交叉淡化是从"默认姿势"开始的**（整段过渡变形）。写 `0` 就会踩这个坑。<br>🔴 事件边上的「演完才进」**不起作用**（状态机整条跳过事件边）⇒ 面板把它标成"事件边用不到"并禁掉 |

| **同屏分不清哪个 Entry** | 容器页那个 Entry 盒标题写的是 **`Entry · <容器名>`** —— 它属于**你当前所在的容器**，和右侧面板里"你点选的那个盒子"的属性是两回事（实测踩过：看着像"子容器1 的入口怎么是 hovermove"）。
| **⚠ 入口状态被搬进子容器之后** | 父容器的 `entry` **立刻失效** —— 装载器要求 entry 必须是**本容器的直接成员**（不满足 ⇒ 报错 ⇒ **整台不注册**）。编辑器的校验会直接告诉你**改成谁**；图上 Entry 那行也会写成 `⚠ 子容器1 → hovermove`，解释"线为什么指到子容器盒"。| **容器的入口 entry** | 容器页里从 **Entry 右侧绿点**拉线，落到**本容器的成员**上（状态节点 **或子容器盒**都行）⇒ 进这个容器就落到它；也可以选容器后用面板的「入口状态 entry」下拉。🔴 入口可以指向**子容器**（装载期会继续往下递归到它自己的入口）。
| **「游戏事件」是什么**（原叫"相位"） | 用户 2026-09-27 改名：「你一直在说相位我无法理解，本质上就是监听到了某些特殊事件吧」⇒ 界面上/文档里一律叫**游戏事件**（XML 里是 `event="true"`，旧名 `phase` 会**响亮报错**）。<br>它就是**条件里的一项**（下拉第 4 项），和"按着什么键 / 动画剩余 % / 命名谓词"**并列** —— 区别只是：前三项由**状态机每个 tick** 判，这一项**由 C# 在事件那一刻强行走**（起飞 = 空中按空格；落地 = 板顶触地）。<br>🔴 **C# 只认这两种接缝，代码里没有任何状态名**：<br>· `机外 → 某状态`（**进机**）⇒ 起飞时 Force 进它（装载器硬校验：必须是事件边）<br>· `某状态 → 机外` 且写了 `anim-rem-pct`（**出机声明**）⇒ 它的 **`from` = 撞地后 Force 的落地动作**、**`anim-rem-pct` = 剩多少交还引擎**（**这两个数据是真的**；🔴 这条边**不必**是事件边 —— 那句"剩 N% 出机"由状态机判也行，撞地后 C# 会 Hold 住状态机）<br>· 其余事件边的 `when=`（起飞 / 落地时刻）**只是文档** —— C# 不读它（下拉里用人话置顶） |

> 引擎侧的装载与校验在 `ExampleModVS/.../Animation/AnimMachineLoader.cs`：XML 有问题就**整台不注册**、
> 把全部问题一次报到日志。设计原则、踩坑记录、待办全在 **[plans/动画状态机-XML化与编辑器.md](../../plans/动画状态机-XML化与编辑器.md)**。

## 二、直接读写文件（2026-09-27 起）

**只有三个按钮**：**打开 XML…**（Ctrl+O）· **保存**（Ctrl+S）· **另存为…**，外加顶栏一颗药丸写着"现在打开的是哪一份"。

| 事 | 说明 |
|---|---|
| **前提** | 用 **Chrome / Edge** 双击打开页面（`file://` 上这套 API **实测可用**，见下表）。别的浏览器 / 隐私模式 ⇒ 页面会直接告诉你要换浏览器（**没有别的保存途径了** —— 用户 2026-09-27 把"导出 → 粘贴"那条老路也删了） |
| **打开** | 系统文件对话框里选一份状态机 xml ⇒ 页面上就是它。**载入会把 `DATA`（"恢复成文件里的样子"的目标 + 导出模板 + 黄条比对对象）一起换成那份文件** —— 不换的话"读的是 A、恢复回 B、黄条拿 C 比"三处全错 |
| **保存** | 覆盖回**你打开的那一份**，**不再弹任何东西**（就是"点保存直接覆盖"）。⚠ **打开**文件时浏览器会问一次"要不要允许修改该文件"—— 那是**浏览器的权限弹窗**（`showOpenFilePicker` 给的句柄默认只读，而浏览器不肯给永久写入权），我们特意放在**打开那一刻**问掉，**不留到保存**（用户实测：留到保存 = "改完就想存"的节骨眼上蹦对话框） |
| **另存为** | 换名字 / 换目录；成功后"当前文件"变成新的那份，以后「保存」就写它 |
| **没打开文件时按保存** | 自动退化成「另存为…」（不会静默什么都不做）；默认名字给的是**上次存的那一份** |
| **重开页面之后** | 🔴 **文件句柄不能跨会话**（浏览器不给，我们也**没做句柄持久化** —— 用户裁定不要"记住目录"那套）⇒ 刷新后页面**有内容、但"没握住文件"**：顶栏药丸会写成「**未打开（上次存到 flight.xml）**」，黄条也会说清"这一页还没握住文件"。想继续按「保存」直接覆盖 ⇒ 先点一次「打开 XML…」选回那份（浏览器会记住上次的目录，两次点击） |
| **取消对话框** | = 正常操作，**什么都不发生、不报错**（`fsErr()` 里 `AbortError` 返回空串 ⇒ 不弹提示） |
| **故意不做** | 目录 / 句柄持久化 / 备份 / 冲突检测 —— 那份 xml 在 **git** 里，历史与回退交给 git（用户 2026-09-27 裁定：只要"最简单的加载 / 保存 / 另存为"） |

### 🔴 这张表是"造它的时候踩出来的"，改之前先读

| 坑 | 事实 |
|---|---|
| `file://` 到底能不能用 | **能**。判据不是"函数在不在"（那只能说明接口存在），而是**真手势下调一次看返回什么**：返回 `AbortError`（用户取消）= **对话框真的弹了**；返回 `SecurityError` 才是被源/平台挡了。 |
| 只读句柄 | `showOpenFilePicker` 给的句柄**不能直接写**（`createWritable()` 抛 `NotAllowedError`）⇒ 要先 `requestPermission({mode:'readwrite'})`（**必须有用户手势**，所以只能在点击里调）。`showSaveFilePicker` 的句柄可以直接写。 |
| 无头浏览器测不了 | 原生对话框点不了（picker 直接抛 AbortError）⇒ 自检里把 picker 换成**内存文件系统桩**（`drive_pages.mjs` 的 `FSA_STUB`）。🔴 **桩的忠实度决定能抓到什么**：桩里的"打开"必须给**只读**句柄，否则那条真实路径（也是唯一会弹授权对话框的路径）永远测不到。 |
| 截图里的状态污染 | `CLEAR`（删 localStorage）**不够** —— 页面**启动时已经把旧草稿读进内存**了，第一次跑 24 号图就顶着旧草稿的边 + 一条假报错。要回"文件里的样子"必须再走一次 `btn-reset`（见 `shoot_pages.py` 的 `CLEAN`）。 |

## 三、四条命令（在本目录下跑）

```bash
python gen_statemachine_editor.py     # 重生成 statemachine_editor.html
python check_pages.py                 # ① 语法：抠出页面里的 JS 喂 node --check
python shoot_pages.py                 # ② 画面：无头 Chrome 出 26 张图到 out/_shots/
node   drive_pages.mjs                # ③ 交互：CDP 打真实鼠标 / 键盘输入，148 项断言
```

> 🔴 **改生成器时的两条硬纪律**（都踩过）：
> ① **生成物里脚本块不能出现字面 `<!--` / `-->`** —— HTML 规范里 `<script>` 内出现 `<!--` 会切进"脚本转义"状态：
>    浏览器与 `node --check` 照规范处理（**页面照跑**），但 **VSCode 的 HTML 语言服务会解析错位**，
>    在脚本尾部报一片 `Argument expression expected` **假错误**（用户截图来问过）。
>    做法：嵌进去的 JSON 里，小于号 / 大于号写成 **JSON 的 unicode 转义**（反斜杠 + `u003C` / 反斜杠 + `u003E`，
>    运行期值一字不变）；源码里的字符串/正则拼出来；**注释里也别写那个序列**。
>    验收：脚本块内 `<!--` 与 `-->` 计数都为 0（`check_pages.py` 已经自动查这条）。见 CLAUDE.md 铁律 37。
> ② **改完必须重跑四条命令**（生成器 → 语法 → 画面 → 交互）；页面是**生成物**，手改会被下次生成覆盖。

**三道自检分工（缺一道就有一类 bug 抓不到）**：

| 工具 | 抓什么 | 为什么不能省 |
|---|---|---|
| `check_pages.py` | **JS 语法错** | 模板里一个转义写错 ⇒ 整段 `<script>` 不跑 ⇒ 页面"能显示但全是静态壳"，**肉眼完全看不出来** |
| `shoot_pages.py` | **渲染错** | 语法没错但标签压字 / 连线指向空气 / 菜单没弹 —— 只有看图才知道 |
| `drive_pages.mjs` | **交互错** | 🔴 实战教训：双击进容器/进状态**全废**（`ev.detail` 在 pointerdown 恒为 0），截图 100% 看不出，真输入一按就现原形。**F 组**（文件读写）还额外要求**桩要忠实** —— 见上表 |

## 五、🔴 五条纪律（踩出来的）

1. **生成物禁止手改**（铁律 22）—— 改页面 = 改生成器 → 重跑。手改 = 与生成器分叉，下次重跑即丢。
2. **改完生成器必跑三道自检**（`check_pages.py` → `shoot_pages.py` → `drive_pages.mjs`）。
   页面是 10 万字节的内联 JS + 内联 SVG，改一处看着没事、实际整页废掉是常态。
3. **编辑器启动时 `localStorage` 的草稿会压过 XML**。现在会弹显眼黄条说明差异（这是被用户抓到"怎么还有 magicIdle"之后补的），
   但改结构后请先点「用 XML 覆盖草稿」，否则你改的是浏览器里的旧副本。
   🟢 **只差布局（节点位置 / 缩放）不弹黄条** —— 页面启动时自己会 `save()` 一次（`fit()` 落盘），
   以前这会让"每一次打开都提示你在看草稿"，明明一个字都没改。
4. **自检带副作用的清理必须无条件正确**。某条断言失败后它的 `edges.pop()` 照样跑 ⇒ 把一条真边弹掉 ⇒
   之后所有"边数应为 N"的断言全部错位。建边类测试统一「记基线 + 截断恢复」。
5. **几何类断言前面必须先把当前页框进画面**。`drive_pages.mjs` 里有个 `frame()` 就是干这个的：
   用例会把节点拖到世界坐标任意处（⑫ 甚至拖到 `x<0`），不 `fit()` 的话 `centerOf()` 拿到的屏幕坐标
   **落在画面外**，鼠标事件全打空 —— 表现为"右键弹的是画布菜单""拖端口建不出边"（本次 4 条用例就是这么挂的）。
   同理，**回总览要写 `setActive(0)` 而不是 `active=0`**（后者不还原镜头）。
6. 🔴 **夹具不许写死状态名 / 容器名，抓取点也不许拿"元素外接框中心"**（2026-09-27 两次实测）：
   - 用户在编辑器里会**改名 / 删状态**（他删掉 4 个直立压弯/俯仰 ⇒ **一次打挂 11 条用例**）。
     ⇒ 夹具一律**从当前 DATA 现挑**（`G2/G2M/G3/G3M` 那组助手），别指着空气。
   - **残留的状态节点会盖住容器盒**，而 `pointerdown` 的分支顺序是 **节点优先于容器**
     ⇒ 拖下去抓到的是那个节点，容器 `gpos` 当然"没变"（㉚c 长期被当成"既有不明故障"，根因就是它）。
     ⇒ 抓盒子用 **`boxGrabPoint()`**：逐点验到"这一点确实命中这个盒子"再拖。
7. 🔴 **改带中文的文件（尤其 `ModuleData/statemachines/*.xml`）绝对不要用 PowerShell 文本往返**（2026-09-27 实锤）：
   PS 5.1 的 `Get-Content -Raw` **默认按 GBK 读** UTF-8 字节 ⇒ 中文全乱，再 `Set-Content -Encoding utf8` 写回 =
   **双重编码**（不可逆 —— GBK 解不出的字节已经变成 `?`）。**改就用 Edit 工具**。
   **万一写坏了**：生成物 `statemachine_editor.html` 里烘着**整份 XML 原文**（`DATA.rawXml`，导出时靠它
   只替换三段、保留文件头注释）⇒ 用 `json.JSONDecoder().raw_decode` 取出来写回即可逐字还原
   （本次就是这么救回来的；比"反解双重编码"可靠，那个是有损的）。
