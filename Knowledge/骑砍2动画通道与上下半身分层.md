## 一、结论先行（三句话）

1. **引擎有三层，从下到上：通道 0（底层，全身）→ 通道 1（上层，默认整骨覆盖下层）→ 移动层（`movement_sets.xml` 那套，管腿）。**
2. **原版"边走边挥刀腿照走"不是靠通道分层**，是靠**移动层**在管腿 —— 所以**人一被冻住（飞行/坐姿/器械），移动层停了，通道 1 的动作就会连腿一起演**。
3. **想让"腿归 A、上身归 B"：A（姿势那条）放通道 0 并在 **clip 元数据**里勾 `enforce_lowerbody`；B（上层动作）放通道 1、什么都别勾。**
   🔴 **flag 必须写进资源包（clip 元数据）** —— 运行时用 `SetActionChannel` 的 `additionalFlags` 传，引擎不认（实测三次全无反应）。

## 二、三层模型（含证据）

| 层 | 谁在写 | 管什么 | 证据 |
|---|---|---|---|
| **移动层** | 引擎（`movement_sets.xml` / `full_movement_sets.xml`，按速度选方向） | **腿**（全身走路动画的上半身会被上层盖掉） | 地面挥手：手在挥、**腿照走** |
| **通道 1** | 我们 / 原版（喊命令、欢呼、嘲讽、器械装填、挥刀） | 默认**整骨覆盖通道 0** | 状态探针：`ch0 w=1.00` + `ch1 w=1.00` 同时存在时，**腿跟通道 1** |
| **通道 0** | 我们（飞行姿势）/ 引擎（idle 等） | 全程在播、权重满满，但**被通道 1 压** | 同上：写回通道 0（含 prio=60）**盖不过**通道 1 |

**已排除的错解**（别再试）：

| 错解 | 为什么错 |
|---|---|
| "通道 1 是上身层，只影响上身" | 人冻住时它连腿一起演；"上身"效果来自移动层，不是通道的遮罩 |
| "提高优先级就能保住腿" | clip `Priority` 0→30 实机无任何变化；`prio=60` 同样无变化 |
| "通道 0 被通道 1 清掉了，补写回去就行" | 状态探针证明 `ch0` 全程 `w=1.00`、**从没被清** —— "守通道 0"是治不存在的病 |
| "运行时也能传 flag" | `custom.anim_ch … lowerbody` / `all` 三次实测**零反应**；写进 clip 元数据立刻生效 |

## 三、两条 flag 的真实语义（原版用量反推 + 实机验证）

| flag | 原话（官方文档） | **实测行为** | 原版谁在用 |
|---|---|---|---|
| `enforce_lowerbody` | *Prevents previous channel and movement animations to be played during this animation* | **"我的下半身归我"** —— 加在**下层**动画上 ⇒ 上层动作抢不走它的腿 ✅ 本工程结案手段 | **355 条**：坐着喝酒（`anim_sit_idle_*`）、吧台服务、蹲下… |
| `enforce_all` | *Valid for channel 0 only. Prevents channel 1 and movement animations…* | **"谁都别动我"** —— 加在下层 ⇒ 上层动作**整个不显示**（实机：全身动作都不生效） | **510 条**：同类固定姿势动画 |

> 读数口径：`enforce_lowerbody` 只在**"姿势类"**动画上有意义（它要保护自己的腿）；
> 加在**上层动作**上是"我也要腿"——方向相反，别加错。

## 四、怎么正确管理上下半身动作（代码侧规则）

| 需求 | 正确做法 |
|---|---|
| 腿保持某个姿势（飞行、坐姿、器械），上身做别的 | **姿势动画**放**通道 0** + clip 元数据勾 `enforce_lowerbody`；**上层动作**放**通道 1**、不勾任何 lowerbody 类 flag |
| 上层动作怎么播 | `SetActionChannel(1, idx, ignorePriority: true, additionalFlags: 0, blendInPeriod: 0.12f, blendOutPeriodToNoAnim: 0f)`；循环的靠 clip 自带 `cyclic` 或传 `anf_cyclic` |
| 什么时候收回 | 播完 / 取消 / 换武器 ⇒ 通道 1 置 `act_none`（上身交还底层动画） |
| 地面上要不要这套 | **不用** —— 地面腿归移动层，天然分离；这套只解决"人不动/被冻住"的场景 |
| ❌ 别做 | 别指望"写回通道 0"抢腿、别指望优先级、别在运行时传 flag、别把 lowerbody 类 flag 加在上层动作上 |

**本工程现役配置（范本）**：

| clip | 通道 | clip 元数据 | 备注 |
|---|---|---|---|
| `flight_idle_a` 等 20 条 `flight_*` | 0 | `cyclic`（循环类）+ **`enforce_lowerbody`** | 全部 20 条都带 ⇒ 悬停/巡航/压弯/俯仰/闪避/起降都不丢腿 |
| `magic_idle` / `magic_projectile_spell`（施法手势） | 1 | `cyclic, allow_head_movement` / `allow_head_movement` | **不带** lowerbody 类 flag |

## 五、给 ModKit 的动画属性填写指引

**在哪填**：ModKit → 资源浏览器 → 选 Animation clip → 右侧属性面板（Fields / Flags 列表）。

| 字段 | 怎么填 | 依据 |
|---|---|---|
| **Priority** | 照原版同类填（本工程实测**与分层无关**，可不纠结；手势类填 2 即可） | §二"已排除" |
| **Right hand pose / Left hand pose** | 照原版同类（我们导入的手势 = `3 / 4`） | §A4：不填则动作"收下了、时长读得到、就是不播" |
| **Blend out period** | `0.5`（手势类） | 同上 |
| **Blend in period** | 照原版（`0.3`） | — |
| **Flags → `allow_head_movement`** | 勾（要头能跟着看方向就勾） | 同上 |
| **Flags → `cyclic`** | 循环动作勾 | — |
| 🔴 **Flags → `enforce_lowerbody`** | **姿势类底层动画必须勾**（飞行 20 条全部）；**上层动作绝对不勾** | §三 |
| **Flags → `enforce_all`** | 只在"这条动画期间谁都别动"时勾（会让上层动作整个不显示） | §三 |

**发布 → 交付包时的二次校验（必做）**：

1. **别假设工程里的设置进了包** —— 引擎运行期读的是 **AssetPackages 里的 clip 资产**（元数据就在包里）；
   工程 → Publish → 改名的链路任一环漏了，实机就是"元数据是旧的"。
2. **旁路改包（`tpaccli clipprio` / `clipflags`）只在交付包上，工程里没有** ⇒ 下次在 ModKit 重编/发布会**覆盖掉**。
   **永久做法 = 在 ModKit 面板里勾上/填好**；赶时间才用旁路改包。

## 六、发布包二次校验：工具与命令

```bash
CLI=<repo>/tools/tpactool/TpacToolCLI/bin/Release/net9.0/tpaccli.exe

# ① 逐条核对元数据（Flags / Priority / Duration / ClipUsages / displacement）
"$CLI" clipinfo --packdir <模块>/AssetPackages [--filter flight_]

# ② 与"期望清单"对账：哪些 clip 必须带 enforce_lowerbody / cyclic / allow_head_movement
"$CLI" clipinfo --packdir <模块>/AssetPackages | grep -B4 enforce_lowerbody

# ③ 改元数据（只改目标字节，其余一个不碰）
"$CLI" clipprio  --packdir <目录> --filter <clip> --prio 0            --out <独立目录>
"$CLI" clipflags --packdir <目录> --filter <clip> --add enforce_lowerbody [--remove enforce_all] --out <独立目录>

# ④ 离线量"这条动画动了哪些骨"（挑素材 / 判断"腿在不在动"）
"$CLI" animbones --packdir <目录> --filter <clip>     # 单条详表（逐骨 旋转/位移）
"$CLI" animbones --packdir <目录> --all               # 全量一行一条（筛"腿不动"的动画）
```

**纪律（都是踩出来的）**：

1. 🔴 **`--out` 出到独立目录，再用 PowerShell `Copy-Item` 拷回交付包**；
   `--inplace` **实测会失败**（源包被读句柄占着，`Save` 抛异常，静默没写进去的观感）——
   而且 **Bash 侧写的产物宿主可能看不见**（沙箱视图分叉），交付/装游戏一律走 PowerShell。
2. 🔴 **改完必须回读验证**：工具自带（`items/guid 一致` + 目标字段回读）；人工再加一道
   **前后 `clipinfo` diff —— 只应出现目标行变化**（例：加 flag 时 diff 只该有 `Flags` 行）。
   判据示例（本次）：包只长了 `20 × 15` 字节、diff 里只有 20 行 `Flags`。
3. **改前自校验**：工具会把"字节流里读到的值"与"对象模型解析出的值"对一遍，不一致就拒绝改 —— 这是防止偏移算错把包改坏的最后一道闸。
4. **实机抽验一条命令**（改完包后）：飞行悬停 `custom.anim_ch 1 act_command_unarmed cyclic` ⇒ 手在挥 + 腿保持飞行姿势。

## 七、运行时诊断速查

| 想要 | 命令 | 看点 |
|---|---|---|
| 两条通道此刻在演什么 | `custom.anim_state 1` | `ch0['动作' idx=… w=… curW=… prog=… prio=…]`；`w` = 通道权重 |
| 按通道手验一条动作 | `custom.anim_ch <通道> <动作> [noforce] [cyclic] [lowerbody] [all] [prio=NN]` | 返回里 `setIdx` 与 `anim_state` 的 `idx` 对齐 ⇒ 这条动作确实在通道里 |
| 某动作对应哪条 clip / 哪些 flag | `tpaccli clipinfo --filter <clip 名>` | Flags / Priority / Duration / SkeletonAnim |
| 这条动画动了哪些骨 | `tpaccli animbones --filter <clip 名>` | 逐骨旋转角/位移；`LEGS: win=… full=…` |

⚠️ **控制台的 flag 参数不可信**（引擎不读）—— 只当"设进通道"用，别拿它验 flag 语义。

### 两条诊断命令的**定位区别**（别混用，它们不可互换）

| | `custom.do_anim <动作> [agentId]` | `custom.anim_ch [通道] <动作> [agentId\|nearest] [noforce] [prio=NN] [flag…]` |
|---|---|---|
| **通道** | **固定 0（全身）**，没得选 | **参数指定**（默认 **1** = 上身叠加层） |
| **调用风格** | 🔴 **原版风格**：`ignorePriority: false` + `blendInPeriod: -0.2`（用 clip 自带的混合） | 🔴 **强制塞**：`ignorePriority: true`（默认）+ `blendInPeriod: 0.12` |
| **拿它干什么** | ① 复现"**引擎自己会怎么播**"（比较基线）② 查"这条动作注册了吗 / 时长多少"（`duration=0.00s` = 没绑上）③ 手验全身动作 | ① 手验**通道 1 叠加**（`do_anim` 到不了通道 1）② 看两条通道现状（返回里带 `ch0[…] ch1[…]`）③ 传 `noforce` 临时切回原版风格 |
| **注意** | 参数较少、行为最接近引擎 | `anim_ch 0 <动作>` **≠** `do_anim <动作>` —— 同一条动作、同一个"通道 0"，**优先级与混合参数都不同**，表现可能不一样；**要比行为就固定用同一条命令** |

**一句话决策**：**判"引擎自己的行为" → `do_anim`；判"我要强行叠加进某条通道" → `anim_ch`。**

> 📌 遗留（无关大局，记录在案）：2026-09-25 那一轮所有"写回通道 0"用的都是 `anim_ch`（强制塞），
> **原版风格的 `custom.do_anim act_fly_idle` 从没在飞行中试过**。后来由 `enforce_lowerbody` 直接结案，
> 所以这条对照没补 —— 若以后又碰到"写通道 0 没反应"，先补这一发再下结论。

## 八、一句话备忘（给下次的自己）

- **"上下半身分离"= 让腿归移动层，或让底层姿势用 `enforce_lowerbody` 把腿抢住**；不是通道的遮罩。
- **我们导入的动画，元数据一律照原版填**（Priority / 手姿势 / blend / flags），**flag 必须进包**。
- **改包 → 出独立目录 → PowerShell 拷回 → clipinfo 前后 diff → 实机一条命令**。
