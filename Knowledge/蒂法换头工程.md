## 2. 关键机制事实（全部实证过）

| 事实 | 证据/来源 |
|---|---|
| FaceKey（128 hex）↔ `KeyWeights[320]`，编码/解码在**C++ 引擎层**（`MBBodyProperties.GetParamsFromKey / ProduceNumericKeyWithParams` → `MBAPI.IMBFaceGen`，无 C# 实现） | 反编译 MountAndBlade.dll 22320 行段 |
| CharacterObject **没有** BodyProperties 属性；某角色的脸 = `charObj.BodyPropertyRange.BodyPropertyMin`（定脸 NPC 的 min==max；随机范围脸才 min≠max） | 反编译 Core 2380-2490 + 编译期报错验证 |
| `KeyWeights[i]` ↔ 该 skin 的 **deform_keys 列表第 i 个（0 基）**。铁证：`KeyWeights[59]=weight 值`、`[60]=build 值`（dump 实测 0.5355/0.5015 精确命中 `StaticBodyProperties.WeightKeyNo=59 / BuildKeyNo=60` 常量） | skins.xml 男/女块各 63 key（顺序一致） |
| 63 键结构：**idx 0..58 = 脸形键**；59=weight 60=build 61=height 62=age（身体键，无网格位移语义） | 两 skin 块导出对照 |
| `deform_key.key_time_point` = **FBX morph 通道名 `KeyTime_{N}`**（xxFemale 子件各带 102 通道 = 基础+扩展） | FBX 导入 shape_keys 名单 |
| KeyWeights w → morph 实际值 = `key_min + w×(key_max−key_min)`。**直灌 w（0..1）会爆脸**，线性映射（B 型）正常 | 多轮渲染对照（暴脸 vs 瓜子脸） |
| KeyWeights 是 **15 档量化**（0, 1/15…1，观察值 0.1333·n）——观察，非结论 | dump 值分布 |
| 游戏脸贴图（白肤+五官）= FaceGen 合成层，源在**私有 `Bannerlord.gts`（103MB）解不出**；`IMBFaceGen` 也无贴图导出 API → Blender 侧只能用素材包 diffuse | 脸部系统分析 §三 + 接口清单 |
| 游戏进程内解码命令 `custom.dump_facekey`（MyCommands.cs）：BodyProperties 原文 + KeyWeights[320] + tattoo，写 `Debug/StoryEngine_RuntimeLog.txt`，**已实测（主角"坎纳尔"）** | 本工程实测 |

## 3. Blender 侧管线（headless bpy）— 坑与修法

- **TWT FBX 导入**：Blender 5.2 导入器对 TWT 的 morph 无 FullWeights 断言崩溃 → **内存级补丁**（不落盘改安装文件）：读 `io_scene_fbx/import_fbx.py` 源码 → assert 换 warning → `exec(compile(...), real_mod.__dict__)`。脚本模板 `%TEMP%\bpy_tifa_transfer2.py`。
- **脸对齐**：头壳两特征点（头部质心点 + 头顶质心）归一化，尺度比 `ratio`（Tifa/xxFemale ≈ 1.238）。
- **通道位移场移植**（把 xxFemale 的 59 个脸形通道搬到 Tifa 拓扑）：每个通道 ±0.3 世界位移 → **KDTree 3 近邻加权** → Tifa 顶点。× **1 近邻=硬贴=脸部起皱；3 近邻=平顺**（用户实测抓到皱纹并修复）。
- **mesh 烘焙**：世界矩阵（`obj.matrix_world @ v.co`）+ **绕 Z 180°**（Tifa 原脸朝 −Y，引擎侧 +Y）；附件（眼球/眉/睫/眼影/嘴）全部同样烘焙，再统一挂空节点。
- **Shape key 在 Object 上**：`obj.shape_key_add(...)`（不是 `obj.data.shape_key_add`——编译期报错的坑）。
- 默认 morph 值 = **0（蒂法原脸）**，通道只作"能力"；要塑形再灌 `min+w(max−min)`。

## 10.6 ★★★ 三个决定性坑（本次全踩过，务必先查）

**坑 1（"mod 不生效"的真根因）：`SubModule.xml` 的 `<Xmls>` 一旦显式列清单，引擎只加载清单内文件。**
- 现象：游戏日志里 `opening .../TifaHead/ModuleData/items.xml` 等 8 个都开了，**唯独没有 `skins.xml`** → xslt 不执行 → 女头不变。
- 对照：`xxFemaleHead`（能工作的同类 mod）与 `Native` 的 `<Xmls>` 都是**空的/不含 Skins**，引擎走默认扫描 → 读到 `skins.xml`。
- 修复：`<Xmls></Xmls>` 清空 → 修复后日志出现 `opening ..\..\Modules\TifaHead/ModuleData/skins.xml` ✅（实证）。

**坑 2：`project.mbproj` 要用 `<file .../>` 形式，不是 `<Module .../>`。**
- `Native` / `xxFemaleHead` 用 `<file id="soln_skins" name="ModuleData/skins.xml" type="skin" />`；1.5.2 编辑器生成的默认模板是 `<Module .../>`。已统一改为 `<file>`。

**坑 3：空壳 `skins.xml` 必须干净，不能留 `<replace_this_with_actual_nodes/>` 占位符。**
- 编辑器默认模板会写这个占位元素；`xxFemaleHead` / `ShokuhoTaikouExpansionPack` 的空壳都是纯 `<skins></skins>`。已改。

> **方法论沉淀（可复用）**：遇到"改名/配置类 mod 不生效"，**先去游戏日志搜 `opening <模块>/ModuleData/xxx.xml`，看引擎到底加载了哪些文件**；再拿"能工作的同类 mod"逐文件对照（本次靠 `xxFemaleHead` 定位）。

## 11.2 三个根因（本轮硬结论，全部实测确证）

### 根因 A：🔴 FBX 必须带骨架 —— 不带，编辑器就把脸网格的元数据全算错

编辑器在**导入时按 FBX 内容自动计算**这些字段：

| 字段 | 无骨架的 FBX（v3） | 带骨架的 FBX（v4/v5） | xxFemale 参考 |
|---|---|---|---|
| `SkinDataSize` | **0** | = 顶点位置数 ✅ | 同 |
| `UnknownInt2`（该网格用到的骨骼数） | **0** | **28** ✅ | **28（完全一致）** |
| `VertexStreamData`（运行时 GPU 顶点流） | 有但内容错 | ✅ 齐全、Uv1/Uv2 非零 | 同 |
| 骨骼绑定 | 全 0 | **B1=13 全非零** ✅ | 13 |

**算错的后果**：引擎拿"声明 0 根骨"的网格去绑 `human_skeleton` → 越界 →
wEditor 版**断言** `face_generator.cpp:864 Expression: non-tested code execution!`；
release 版断言被编译掉 → 继续跑读到非法内存 → **native AccessViolation**（栈顶 `AgentVisuals.AddSkinMeshesToEntity`）。

**这就是为什么前 8 轮打补丁都失败**：一直在**替编辑器伪造它本该自己算的数据**，补一个冒一个。
**正解 = 把 FBX 的输入规格做对（带骨架），让编辑器自己算。**

### 根因 B：`Assets/` 是编辑器的半成品，引擎却优先读它

引擎挑资产目录是**按固定顺序取第一个存在的**：`Assets` → `AssetPackages` → `DsAssetPackages` → `EmAssetPackages` → …
而 `Assets/` 里是**编译中间产物**：**没有 `VertexStreamData`**、贴图只有 `TextureImportSettingsData`（导入设置）**没有像素**。

实测段类型对照（`tpaccli segs`）：

| | `Assets/`（编辑器工程） | `AssetPackages/pack0.tpac`（发布包） |
|---|---|---|
| `MeshEditData` | 6 | 6 |
| **`VertexStreamData`** | **0** ❌ | **6** ✅ |
| 贴图 | `TextureImportSettingsData` + `TextureSourceInfoData` | **`TexturePixelData`** ✅ |

→ 跑游戏前必须让 `Assets` **不叫这个名字**（改名 `Assets_disabled`）。见 §11.6 的 bat。

### 根因 C：`skins.xslt` 里三处改写的**条数**必须对齐参照物

脸部贴图合成在 `AddSkinMeshes` 里**按索引取** `face_textures[i]`（索引来自角色 BodyProperties），条数不足 → 越界。

| 项 | 原版 woman | xxFemale | 我们（曾写错） | **现在** |
|---|---|---|---|---|
| `face_textures` | 4 条 | **5 条**（tags 2,2,3,4,5） | **1 条** ❌ | **5 条**（照 xxFemale） |
| `mouth_textures` | 5 条 | 不动 | **1 条** ❌ | **不动**（原版 5 条） |
| `eyebrow_meshes` | 5 条 | 1 条 | **清空成 0 条** ❌ | **不动**（原版 5 条） |
| `deform_keys` / `constraints` | 63 / 2 | 同 | 抄自 xxFemale（与原版逐位一致） | 不变 |

## 11.3 骨架绑定的关键数据（可复用，别再摸一遍）

## 11.5 本轮踩的新坑（9 条）

1. 🔴 **`Mesh.VertexKeyCount` = 引擎分配 morph 缓冲的键数**。装了 101 帧却声明 59（或 0）→ 缓冲越界 → native 崩。补帧必须**同步**它。xxFemale = 101。
2. 🔴 **`Mesh.MaterialFlags` 是脸部角色标记**，词表只有 4 个值：`face_base_mesh` / `face_mouth_mesh` / `face_eye_mesh` / `face_eyelash_mesh`。原版与 xxFemale 的 **Lod0 脸部件各带其一，LOD 层为空**。全空 → 生成器认不出脸。
3. 🔴 **`Mesh.UnknownInt2` = 该网格用到的骨骼数**（`B1~B4` 去重）。**编辑器导入带骨架的 FBX 时会自己算对（=28）——绝不能用公式覆盖**（按去重数推出来是 2，错的，早期补丁踩过）。
4. 🔴 **`TpacTool.Lib` 的 `VertexStreamData.WriteData` 原本读写不对称**：读端按 sizes 表读、不读计数前缀，写端却写 4 字节计数 → **任何重写顶点流的操作都会把数据整体错位**（骨骼/UV 全毁）。已修（新增 `WriteStructArrayNoCount`）。`roundtrip` 命令只比 item 数和 guid、不比数据，所以一直没暴露。
5. 🔴 **ExternalLoader 的"原始字节直写"陷阱**：就地改 `MeshEditData`/`VertexStreamData` 的内容**不会被写回**——必须**新建 loader 顶替原数据段**（范本 `ReplaceTex.cs`）。另外改 `Mesh` 记录字段（如 `VertexKeyCount`/`SkinDataSize`）必须 `meta.RawMeta = null`。
6. 🔴 **原版头部四个角色各有各的 shader，不能统一刷**：脸 `8c88213c` / 嘴 `cea0b671` / 眼 `71740d5e` / 睫 `a578e7cc`。统一刷成脸部配方 → 引擎给眼/睫去编译脸部着色器 → 崩在 `compile_shader`。纹理槽也各不同（脸/眼需要 tex[1]/[3]，嘴/睫原生就没有）。
7. 🔴 **ModKit Publish 会清空 `AssetPackages/`** —— 放在里面的 4 个 `.bak` 备份被清掉了。**备份放模块外。**
8. 🔴 **ModKit Publish 的目标目录 = "父目录"**：选到模块里 → 得到 `Modules\TifaHead\TifaHead\`（**140MB 嵌套**，§10.4 已记过一次，本轮原样复发）。**固定发到模块外的 `_tifa_publish\`，再只把 `pack0.tpac` 拷进来。**
9. 🔴 **编辑器工程 `Assets/` 残缺（缺 `*_geo.tpac`）→ 导入直接失败**：报 `Unable to import file: Unable to copy ... to Assets folder`。成因是 Publish 目标选错时把 `Assets/` 清掉了一部分，工程处于"材质都在、几何没了"的自相矛盾态。**修法 = 换一个全新模块重做工程**（本轮建了 `TifaHead2`）。

## 12.1 一句话结论

## 12.3 根因链（两处叠加，各自独立）

**根因 1：FBX 节点上挂了 `scale = [100,100,100]`，被编辑器烘进顶点。**

```
Model bip01_notused    scale=[100,100,100]  rot=[-90,0,0]
Model head_tifa_a.0    scale=[100,100,100]  rot=[-90,0,0]   ← 网格节点也带 100 倍
```

来源 = `bind_skeleton_v5.py` 第 3 步：为了让骨架头骨（Blender 导入后 z=0.0157）追上网格（z=1.466），把**整个骨架对象乘了 k≈99.77 倍**再 `transform_apply`。缩放虽然烘进了骨架数据，但**网格对象跟着父级带上了 100 倍节点缩放**，导出时原样写进 FBX。

**根因 2：FBX 声明 `UpAxis = 1`（Y 朝上），引擎额外做一次 Y-up→Z-up 转换。**

| | 我们的 v5 | TpacTool 导出器写的（社区验证过的规格） |
|---|---|---|
| `UnitScaleFactor` | **1.0**（1 单位 = 1 厘米） | **100**（1 单位 = 1 米） |
| `UpAxis` | **1**（Y 朝上） | **2**（Z 朝上） |
| 节点缩放 | **100** | 全 1 |

**叠加算式（逐位对得上，不是推测）**：
```
节点变换烘进顶点 → rot[-90°X] 把 Z-up 转成 Y-up，再 ×100
引擎按 UpAxis=1 又转一次 → (x,y,z) → (x, z, −y)
净效果 = (100x, −100y, −100z)   ← 实测值完全吻合
```

**关键判据**：文件里节点已经转过一次，引擎又转一次 = **转了两遍 = 绕 X 翻 180°**。Blender 导出若声明 `axis_up='Y'`，引擎还会再转；声明 `axis_up='Z'` 才是"只转一次"。

## 12.6 附带确认的机制事实（以后别再摸一遍）

- **tpac 里没有绑定矩阵**。网格只存「每顶点骨索引 + 权重」（`BoneIndices` / `BoneWeights`），`Mesh` 记录里只有 `SkinDataSize` 和 `UnknownInt2`（用到的骨骼数）。
- **绑定矩阵来自骨架资源本身**（`human_skeleton` 的静止姿态）。运行时 = `Σ wᵢ × 骨骼当前世界矩阵 × inverse(骨骼静止世界矩阵) × 顶点`。
- **静止姿态下 `骨骼世界 × inverse(骨骼静止) = 单位矩阵` → 顶点渲染在自己写的坐标上。**
  → **推论（本工程的核心判据）**：**引擎不对头做任何"对齐到脖子"的修正**。头的位置 100% 由顶点坐标决定 —— 所以「头在不在脖子上」等价于「顶点坐标对不对」，可以直接离线量。
- `TpacTool.Lib` 的 `AbstractModelExporter.IgnoreScale`：**human / horse 骨架**导出时把骨骼 `RestFrame` 的 `M44` 强制设 1（丢弃骨架里带的缩放分量）。说明官方人形骨架的 rest frame 里确实带缩放分量，本工程若自己做工具链要注意。

## 12.10 第四轮（同日续）：头能跟骨架动了，但位置/大小不对 —— 两个新根因

### 根因 D：编辑器工程里材质的 `Vertex Layout` 缺 `Skinning` → 网格完全不被蒙皮

**症状**：Model Viewer 里把 `head_tifa_a` 挂到 Human 的 Head 槽，头**位置大小都对，但完全不跟动画**（身体动、头钉在原地）。对照实验：换成原版 `head_female_a` 同样的槽位**会跟着动** → 证明 viewer 确实会蒙皮，是我们的网格没被蒙皮。

**证据**：编辑器原始产出 vs 能跑的 v5 包 —— `mat.VertexLayoutFlags` 前者只有 `[bumpmap]`，后者是 `[bumpmap, skinning, doubleuv]`。

**`Skinning` 是引擎构建顶点声明时"读不读骨骼权重"的开关。没有它 → 按无蒙皮渲染。**

**根因**：`TifaHead2` 是 §11.5 那轮"Assets 残缺 → 换全新模块重做工程"时新建的**空工程**，旧 `TifaHead` 工程里手工配好的材质设置**从没搬过来**；§10.5 记的"照抄 xxFemale 配方"在新工程里没重做。

**修法**：编辑器里逐个材质勾 Vertex Layout（完整表见 §12.10 下表）——**这是正轨，改完 Publish 出来的包才是干净的**；`skinfix --fullmat` 只是事后补丁。

| 材质 | Vertex Layout |
|---|---|
| `head_tifa_a`（脸） | Bump Map + **Skinning** + Double UV |
| `head_tifa_a_mouth` | Bump Map + **Skinning** |
| `head_tifa_a_eye` | Bump Map + **Skinning** + Skinning Precise |
| `head_tifa_a_lash` / `_shadow` / `_brow` | Bump Map + **Skinning** |

### 根因 E：头的位置和大小都错 —— 丢了 `ratio` 缩放因子

**标定基准 = 原版 `head_female_a`**（实测 bbox 与参照 mod `head_xxfemale_a` 完全一致，可信）：

| 特征 | 原版 head_female_a | 修复前 head_tifa_a | 差 |
|---|---|---|---|
| 嘴中心 z | **1.6067** | 1.5142 | +0.0925 |
| 眼中心 z | **1.6795** | 1.5730 | +0.1065 |
| 眼→嘴间距 | 0.0728 | 0.0588 | **比值 0.808 → 放大 1.238** |

**1.238 正是 §3 记录的 `ratio`（Tifa/xxFemale ≈ 1.238）—— 该因子在某轮往返里丢了。**

**修法**（`bind_skeleton_v7.py`）：绕头壳包围盒中心放大 1.238，再平移让「眼睛」落到原版位置。
三锚点同时命中即为合格：**眼 1.6795 ✓ / 嘴 1.6067 ✓ / 头顶 1.8030（原版 1.8019）✓**。

### 🔴 本轮踩的两个脚本坑（都会让产出"看起来对、实际是坏的"）

1. **改顶点时漏了 `ob.data.vertices`** —— 带 shape key 的网格若只改 `key_blocks[i].data`，**导出器读的是 `mesh.vertices`，改动不生效**。表现：脸壳留在原地、嘴和眼珠飞上去 10cm。
   **正确写法**：改 `ob.data.vertices`（基础几何）+ **跳过块 0** 只改 `key_blocks[1:]`（形态键增量）——块 0 与 `mesh.vertices` 是同一份数据，两边都写 = 变换做两遍。
2. **`ob.bound_box` 是缓存，改完顶点不刷新** —— 自检若用它，会报出**过期坐标**，本轮被它骗了两次（一次误判"没改"、一次误判"改了"）。
   **自检一律逐顶点算**（`ob.matrix_world @ v.co`）。

# 13. 🔴 换头工程的可复用知识清单（跨工程通用，下次做任何 FBX→骑砍2 资产先看这节）

## 13.1 引擎导入 FBX 的换算规则（实测确立，非推测）

**引擎拿到 FBX 后做两件事**：
1. **把所有 Model 节点的变换（缩放/旋转/平移）烘进顶点**
2. **按文件声明的 `UpAxis` 再做一次轴转换**：`UpAxis=1`(Y) → 引擎做 `(x,y,z)→(x, z, −y)`；`UpAxis=2`(Z) → 不做

🔴 **文件里节点已经转过一次、引擎又转一次 = 转两遍 = 绕 X 翻 180°**（脸朝后、翻到地面以下）。

**结论：只有一套导出规格是安全的**（= TpacTool 导出器的规格，社区验证过能进游戏）：

```
UpAxis=2  FrontAxis=1  FrontAxisSign=-1  CoordAxis=0  CoordAxisSign=1  UnitScaleFactor=100
所有网格 Model 节点：零缩放、零旋转、零平移
```

**Blender 导出参数（实测对照 5×5 组矩阵得出，与 §10.3 旧记录冲突——以本节为准）**：

| 参数 | ❌ 错 | ✅ 对 | 错的后果 |
|---|---|---|---|
| `apply_scale_options` | `FBX_SCALE_NONE` | **`FBX_SCALE_UNITS`** | 把「1 米=100 厘米」烘成节点 `scale=100` + 声明 USF=1 → 顶点放大 100 倍 |
| `axis_forward` | `'-Y'` | **`'Y'`**（配 `axis_up='Z'`） | 同时写出 `CoordAxisSign=-1` + 节点 `rot=[0,0,180]` → 脸朝后 |
| 场景单位 | 不设 | **导出前重设** `unit_settings.scale_length = 1.0` | 🔴 **Blender 的 FBX 导入器会按文件里的 UnitScaleFactor 改写场景单位**（官方骨架声明厘米 → 场景被改成 0.01）。必须在**所有导入之后、导出之前**重设一次 |

## 13.2 引擎凭什么决定"这个网格要蒙皮"

三个条件缺一不可，都是**编辑器侧配置**（不是二进制能补的）：

| 条件 | 位置 | 缺失后果 |
|---|---|---|
| `VertexLayoutFlags` 含 **`skinning`** | **材质**上 | 按无蒙皮网格渲染 → 网格钉死在绑定姿势、**完全不跟骨架动** |
| `SkinDataSize > 0` + `BoneIndices`/`BoneWeights` | 网格 + 顶点流 | native 越界（AccessViolation） |
| `MaterialFlags` = `face_base_mesh`/`face_mouth_mesh`/`face_eye_mesh`/`face_eyelash_mesh` | 网格（仅 Lod0 脸部件） | 脸部生成器认不出脸 |

🔴 **第一条最容易漏**：它是材质属性，FBX 不携带 → 换新工程/重导入后**必须重新在编辑器里勾**。症状极具迷惑性：**头的大小位置全对，就是不跟动画**。

## 13.3 tpac 里没有绑定矩阵 → 位置可纯离线判定

tpac 网格只存「每顶点骨索引 + 权重」；**绑定矩阵来自骨架资源（`human_skeleton`）的静止姿态**。
静止姿态下 `骨骼世界 × inverse(骨骼静止) = 单位矩阵` → **顶点就渲染在自己写的坐标上**。

**推论**：引擎不做任何"对齐到脖子"的修正。**"头在不在脖子上"完全等价于"顶点坐标对不对"，可以离线量，不用开游戏。**

## 13.4 编辑器编译后必跑的两道补丁（见 §12.8）

```

```

### 🔴🔴 补帧语义：`VertexFrame.Positions` 是【绝对位置】，不是位移（2026-09-13 实机踩到）

**症状**：进游戏捏脸界面，**面部持续下坠**（视觉上脸往身体里/往下掉），**而眼球位置正常**。

**根因**：`morphfix` 早期版本补缺失帧时填 `new Vector4[n]`（全 0）。在"绝对位置"语义下，
**全 0 = 把整块网格拉向原点** —— 权重一起来，脸壳就往原点塌。
**眼球不掉是因为眼球子网格不参与 morph 混合**（不设形态键权重），所以只有脸掉。

**铁证**（`morphinfo` 的 `[MORPH]` 诊断行）：
```
正常包 帧0（Basis，语义上应"不形变"）: (0.032,0.11,1.595) (0.022,0.141,1.605) ...
基础网格 Positions                 : (0.032,0.11,1.595) (0.023,0.141,1.605) ...   差 0.0002
xxFemale（能跑）帧0 = 基础网格位置，差 0；末帧 = (-0.031,0.136,1.679)  ← 头部坐标量级
```
⇒ **「不形变」的正确填法 = 复制基础网格的位置**（`data.Positions`）与基础法线（`data.Vertices[i].Normal`）。

**已修**：`MorphFix.Fix` 改为填基础位置；并新增**坏帧检测**（整帧全零 → 判为坏帧并重写），
所以对已打坏的包**重跑一次 `morphfix` 即可修复**（幂等，修好后重跑不再命中）。
`morphinfo` 同步加了两样诊断：`[MORPH]` 帧数据采样 + **🔴坏帧(全零) 计数**。

⚠️ **包体会因此从 9MB 涨到 26MB**（零帧几乎不占空间，真实坐标占）——正常，不是坏了。
参照头 xxFemale 的包是 32MB，量级一致。

🔴 **FBX 重导入会把编辑器里手工配的材质设置全部刷回 FBX 默认值**（shader/flags/blend/alphaTest/VertexLayout/纹理槽全丢）。"材质是独立资产、同名会复用"这个判断是**错的**。

## 13.7 🔴 自建头部的四条硬规格（2026-09-13 实机验证通过后总结，缺一条就出怪相）

### ① 子网格必须是 **4 件、顺序 脸→嘴→眼→睫**

引擎给脸部件分配贴图**按子网格的位置算，不看 `MaterialFlags`**（我们曾把 flags 全设对也没用）。
多出来的部件（眼影/眉毛/额外附件）会落在"认识范围"之外 → **回落到脸皮材质** → 眼球、嘴、眉全糊上脸的贴图。
- 判据：多一个子网格、或眼的序号不是第 3 → 必出问题。原版 `head_female_a` 与参照 mod `xxFemaleHead` 都是 4 件同序。
- 眉毛不属于这 4 件——原版的眉毛走皮肤定义的 `eyebrow_meshes` 独立件（要 3D 眉毛就得单独做资产）。

### ② 附属件（嘴/眼/睫）**必须带形变通道**，否则脸动它不动

脸的 59 条形变通道是**位移场**（单条最大 ±2cm）；脸壳会被角色脸形参数拉动，**附属件若没有形变数据就钉在原地**。
症状极有辨识度：**眼球跑到眼眶上方、眉毛与画上去的眉影错开、鼻子比"底下的脸"更凸**；编辑器预览（basis）永远看不到。
- 做法：按**最近邻 3 点反距离加权**，把脸壳的位移场搬到附属件顶点（1 近邻会起皱）。
- 判据：编译后附属件不该是"全帧静止"。参照 mod 的嘴/眼/睫各有 53~65 帧带形变。

### ③ 形状键必须是 **Basis → 占位键 → KeyTime_1…59 的数字顺序**

编辑器**按位置**把非 Basis 键编成帧 0,1,2…（名字里的编号不影响帧号），而皮肤 `deform_keys` 用 `key_time_point=N` 取帧 N。
- **必须有一个占位键顶在帧 0**，后面的通道才落在帧 1..59 ✓
- **占位键不能是零位移**：FBX 会把零位移通道压成 1 个顶点，编辑器可能跳过 → 又错位。给 0.1mm 微位移即可（皮肤里没有 `key_time_point=0` 的条目，这帧永不启用）
- 诊断工具：`morphinfo` 的「逐帧位移签名」对 `fbx_probe.py` 的 `KeyTime_N` 包围盒 —— 帧 1 应是纯 X（脸宽）、帧 2 应是纯 Y（脸深），一眼可判

### ④ 标定的参照物要选"**源模型或同类可用资产**"，别拿不对位的件当基准

- 反例（本工程踩了）：拿原版 `head_female_a` 的**扁平眼贴片**当我方**完整眼球球体**的对位基准 → 眼球被硬拉回去 1cm 并缩小 14% → 编辑器里看就是"眼球陷进眼窝"。
- 正解：**用源模型自身反解变换**（源 head 包围盒 → 我方 head 包围盒 = 绕 x 翻转 + 等比缩放 + 平移），把源里各配件折算过来当目标。
- 🔴 **必须留一个"锚点件"验证换算**：挑一件**没被动过**的配件（本工程是"嘴"），折算出来的目标应与它当前值吻合 → 换算正确，那么**偏离的那几件就是被错改的**。

# 16. 2026-09-13 深夜（第九轮）：脸部件贴图按【顺序/数量】认，不按 MaterialFlags（★最新）

## 16.1 一句话结论

打完补丁后**症状不变**（眼球仍贴着脸皮、整张脸像糊了层皮）→ 说明病根不在材质设置。
实测定论：**引擎给脸部件分配贴图是按子网格的【顺序 / 数量】，不是按子网格上的 `MaterialFlags`。**

| | 子网格构成 | 结果 |
|---|---|---|
| 原版 `head_female_a` | **4 件**：脸→嘴→**眼**→**睫** | ✅ 正常 |
| 参照 mod `xxFemaleHead` | **4 件**：`.002.0~3` 同上顺序（嘴还是原版 242 顶点的嘴） | ✅ 实机可用 |
| **我们** | **6 件**：脸→嘴→**睫→眼影→眼→眉**（眼排第 5） | ❌ 眼/嘴/眉糊脸皮 |

**机制**：引擎按位置把"第 3 件当眼、第 4 件当睫"；我们第 3 件是睫、第 5 件才是眼 → 眼与眉落到**超范围**，回落到"脸皮材质" → 眼球/嘴/眉全部渲染脸的贴图。

## 16.2 铁证（两条，可复查）

1. **眼球上的"小脸"与包里的脸皮贴图同源**：`tpaccli dump` 抠出的 `head_tifa_a_d.png` 是一整张蒂法脸（1024²），实机截图眼球上那张小脸的构图与它逐处对应。→ 眼球确在采样脸皮贴图，不是别的东西。
2. **`MaterialFlags` 已经设对却没用**：`metaparts` 列出当前包 —— 眼=`face_eye_mesh`、睫=`face_eyelash_mesh`、嘴=`face_mouth_mesh`、脸=`face_base_mesh`（§12.8 的补丁打过），症状依旧 → flags 不是分配依据。

## 17.5 🔴 追加实证：形状键【没有 Basis + 顺序乱】——`deform_keys` 取错了通道

**工具**：`morphinfo` 新增「逐帧位移签名（前 8 帧，mm）」——把每帧与基础网格的差算成包围盒，
拿去和 `fbx_probe.py` 打出的各 `KeyTime_N` 几何包围盒**对号**，就能看出"帧 i 实际装的是哪条通道"。

**实测对照**：

| | 帧 0 | 帧 1 | 帧 2 | 帧 3 |
|---|---|---|---|---|
| **xxFemale（正确）** | **零位移 = Basis** ✅ | x±8.9mm（脸宽） | y+8.2mm（脸深） | 混合 |
| **我们** | x±16.3mm = **KeyTime_1** ❌ | y+15.2mm = **KeyTime_2** | = **KeyTime_10** | = KeyTime_3 |

**两个缺陷**：

1. **没有 Basis 帧** → 所有通道整体往前挪一格：皮肤的 `deform_key(key_time_point=N)` 取到的是第 N+1 条通道（拉"脸宽"实际改"脸深"），最后一条 `key_time_point=59` 直接落空。
2. 🔴 **顺序是乱的**：FBX 里通道排列 = `KeyTime_1, 2, 10, 3, 4, 5, 6, 7, 12, 13, 53, 52, 56, 47, 22, 24, 25, 26, 23, 17, 19, 18, 14, 15, 20, 21, 16, 48 …`，
   而**编译出的帧顺序 = FBX 里的排列顺序**（帧 2 = KeyTime_10、帧 3 = KeyTime_3 已逐条验证）→ **绝大多数通道对不上号**，角色的脸形键驱动的是一堆错位的位移场。

**成因**：`KeyTime_*` 形状键不是本仓库任何脚本创建的——它们是导入 xxFemale 的 FBX 时带进来的，
当年那次"通道位移场移植"脚本留在 `%TEMP%`（§3 记过，**已失传**），形状键按当时的迭代顺序追加，于是乱序且无 Basis。
**⇒ v9 必须由脚本重建形状键顺序**（Basis 打头、KeyTime_1..59 数字序），不能再依赖这个失传脚本的产物。

### 🔴 P2 · 捏脸参数还原（让角色用"蒂法原脸"）

**问题**：骑砍2 的脸形参数（`BodyProperties` 那串 128 hex `key`，内含 320 个权重）会**驱动我们网格的 59 条形变通道**
→ **任何非 0 的脸形权重都会把蒂法的脸拉变形**。玩家在捏脸界面随便选一个脸，看到的就不是蒂法原脸。

**事实（已核实）**
- 权重是 **4 bit 一档**（15 级量化），脸的 59 个权重 = 下标 `0..58`；`59/60/61/62` = weight/build/height/age，**只影响身体、不动脸的网格**。
- `age` 不会让脸变老：成品包里材质 `tex[1]` 已设成与 `tex[0]` **同一张图**（md5 级同 guid，已核对）。
- **全 0 key = 100% 原脸**（依据：`BodyProperties.Default` 在源码里就是 8 个 ulong 全 0；权重 0 = 该通道不参与 = 网格基础形状 = 蒂法的脸）。
- 实测样本 `key="0015F80E…"`：切成 8 个 ulong 后 **KeyPart1~5 都有数据** → **不是原脸**（KeyPart6/7 全 0、KeyPart8 只有低位，属正常——皮肤只有 63 个形变键，63 档往后本来就空）。

**现成材料**
- 解码已通：`custom.dump_facekey`（[MyCommands.cs:2860](../../ExampleModVS/ExampleMod/ExampleMod/Debug/MyCommands.cs#L2860)）→ `MBBodyProperties.GetParamsFromKey` → 320 权重逐条写 `Debug/StoryEngine_RuntimeLog.txt`
- 编码 API **已反编译核实存在**：`MBBodyProperties.ProduceNumericKeyWithParams(FaceGenerationParams, bool earsAreHidden, bool mouthIsHidden, ref BodyProperties)`
  （另有 `ProduceNumericKeyWithDefaultValues(ref BodyProperties, bool, bool, int race, int gender, int age)` 可拿默认脸做对照）

**步骤**
1. 加 `custom.zero_face`：读主角 `BodyProperties` → 解码 → **`KeyWeights[0..58] = 0`**（59~62 原样保留）→ 重新编码 → 写回主角 → 打印改前/改后 59 个权重
2. 加 `custom.set_face_key <128hex>`：直接套用一串 key（存满意的脸 / 复制给 NPC）
3. 编译 → 游戏内跑 `custom.dump_facekey` 先看当前真实权重（可能只有几个歪，微调即可）

**验收**：全 0 key 上身 → 角色脸回到基础形状（= 与 Blender 里 basis 状态渲染一致）；`DumpFaceKey` 回读 59 个权重全 = 0.0000。

**已知坑**
- 🔴 **改完别再去捏脸界面动脸形拉杆** —— 一动就又拉歪（除非你要那个变形）。
- ⚠️ `weight`/`build` 只影响身体：把身体调胖调瘦，头仍是蒂法的 → 比例可能不搭，这是取舍不是 bug。
- 编辑器/捏脸预览里看到的是**被参数变形后的脸**，不是 basis；判断"是不是原脸"要认权重不认肉眼。

## 20.2 先搞懂：骑砍2 的脖子到底长在哪

**结论：脖子不是身体给的，是「头」给的。**

- 身体 `body_female_a` 在胸口开了个**大 V 领口**。射线实测轮廓：正前降到 `z=1.407`、肩侧升到 `z=1.506`、背后 `z=1.472`。
  这是**真的洞**——从前胸打射线会穿到后背内壁（第一击是背面）。
- 原版头 `head_female_a` 自带「**颈 + 胸兜**」，它的**外沿与身体领口逐点重合**（`(0, +0.1006, 1.4066)` 两边都有）
  → 原版就是靠这段几何把洞盖住的。参照 mod xxFemale 照抄这套。
- 我们之前只有头 → **缺 4.1cm 脖子，外加整个 V 领口没人盖**。

## 20.3 做法（三块）

| 件 | 来源 | 关键点 |
|---|---|---|
| **脖子** | 蒂法源模型 `body` 自带的脖子 | 源→我们空间换算后裁到 `z=1.522`；**同一模型自带，形状/肤色天然接她的头** |
| **领口** | **按实测的身体领口轮廓现铺**（不抄原版几何） | **三次 Hermite 曲线**：起点切向取脖子壁、终点切向取身体表面 → 两端相切 = C1 连续，数学上不折棱 |
| **权重** | 从原版 `head_female_a` 最近点抄（3 近邻反距离加权） | 头→颈→脊→锁骨 平滑过渡，共 8 根骨；权重和恒 =1、零权重顶点 0 |

领口外沿往身体里埋 7mm —— 保证两条曲面**确实相交**（交线 = 干净接缝），不留悬空边。

## 20.4 🔴 十一个坑（下次做新头模一定会再遇到）

> 分两类：**几何类**（看得见）与**管线类**（不报错、更阴）。

### 几何类

1. 🔴🔴 **源→我们的变换含 y 镜像**（`our_y = −S·src_y + …`，行列式为负）→ 从源 body 搬过来的脖子**整份面朝向全反**。
   **症状**：实机背面剔除后脖子是个洞（编辑器里是一道缝）。**修法**：搬过来之后整份 `bmesh.ops.reverse_faces`。
2. 🔴 **下沿环不能按角度重排**。按角度排序 = 把「角度相邻」当「网格相邻」→ 领口的面接不到相邻顶点上，留下一圈断边（实测 19 条）。
   **修法**：保持边界环**原始顺序**；角度只用来查领口轮廓。
3. 🔴 **直线放样必折棱**（两端都不与表面相切，调环数/抹平/外凸都只是减轻）。
   **修法**：三次 Hermite，两端取真实表面切向。**切向长度用 0.5×弦长**（太大过冲插进身体 → 口沿漏缝，实测）。
4. **头壳底口（源模型自带的开口）若有一小段露在脖子外面**，从外面能看进头壳内部。
   **修法**：把露出来的那些底口顶点收进脖子体内 3mm（它们本来就被脖子挡着）。
5. **剪切锯齿**：按 `z` 裁脖子会留 **16mm 锯齿**，不抹平的话领口一圈是波浪的。抹平 6 次；领口环数 **12** 够用。

### 管线类（都不报错）

6. 🔴 **多余 UV 层**：脖子来自蒂法 body，**自带 2 套身体 UV 一起并进来** → FBX 里 3 套 UV；
   脸材质带 `doubleuv` = 引擎会去读**第 2 套** → 新增面读到垃圾坐标（编辑器里领口糊出怪花纹）。
   **修法**：并进脸壳后**删到只剩 1 套**。
7. **UV 撞车**：脸的 UV 用到 `v ≥ 0.2666`，脖子 UV 若超过它就蹭到下巴。**修法**：脖子 UV 上限压到 `0.247`。
8. 🔴 **custom split normals**：源模型/网格带自定义法线，**bmesh 新加的面拿不到正确法线** →
   导出后编辑器里是**一格一格的面片**（实机同样）。**修法**：用「按顶点平滑」的法线
   `normals_split_custom_set_from_vertices` 重设一遍（源本来就 8742/8742 全平滑，无副作用）。
9. **导出顺序**：`render_preview` 会替换材质 → **导出前跑预览 = FBX 里脸壳材质名变成 `texprep`**。**修法**：导出必须在预览之前。
10. **参考物混进导出**：量领口用的身体 OBJ 被 `use_selection=False` 一起导出（FBX 里混进 `body_female_a.lod1~5`）。**修法**：导出前清掉非交付物。
11. 🔴 **`install_pack.py` 的 `stage_dir()` 会 `rmtree`**：它在 morphfix 写完之后被调用 = **把刚生成的包删掉**（抛 `FileNotFoundError`）。
    skinfix 那步同样中招，只是有 fallback → **静默跳过皮肤补丁**（更阴）。**修法**：清空只用于「给外部工具腾输出目录」，产物目录单独处理。

## 20.5 诊断方法（比「烧一次实机」快得多）

| 方法 | 判据 |
|---|---|
| **接缝射线体检** | 沿领口一圈逐角度逐高度，从外侧朝中轴打射线，看**整条射线上有没有「正面可渲染」的命中**<br>🔴 **只看第一击会误判**：第一击是背面、后面还有正面 = 没洞（我在这上面栽过一次，虚报 3008 个「洞」） |
| **品红背景 + 背面剔除**渲染 | 背景设成品红、材质设成纯色、开背面剔除 → **露品红 = 真洞** |
| **对照原版** | 原版头+身体走**同一套判据**，**同为 0 才算同档**（不能只看绝对值） |
| **权重体检** | 权重和恒 =1.000000、零权重顶点 =0（有的话那些顶点会被拉到原点） |
| **法线体检** | 逐面算法线 · 径向 >0（朝外）；朝内的面在实机背面剔除后就是洞 |
