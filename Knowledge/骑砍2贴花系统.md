## 🔴🔴 2026-10-06 定案：形状由贴图 alpha 决定 —— 开关是材质的 `alpha_test` shader flag

> **一句话**：B 路（`decal_mesh`）上，**贴图 alpha 能定形状**，但必须同时满足两条，缺一不可：
> ① 材质 shaderFlags 里有 **`alpha_test`**；② 材质的 **`alphaTest` 值 > 0**（原版用 `0.024`，ModKit 里填 `6`）。

### 实机四格（同一个灰图探针：73% 灰 + 正中 27% 圆洞 alpha=0）

| 材质 | 贴图 | `alpha_test` | `alphaTest` | 右片（B 路）实机 |
|---|---|---|---|---|
| `lwn_manual_gray_mod_alphatest150_dds` | DDS | ✅ | 0.588 | **圆洞透出地面** ✓ |
| `lwn_manual_gray_mod_alphatest150` | **PNG** | ✅ | 0.588 | **圆洞透出地面** ✓ |
| `lwn_manual_gray_mod_dds` | DDS | ✅ | 0 | 黑洞（圆洞被 RGB=0 覆盖） |
| `lwn_manual_gray_mod` | PNG | ✅ | 0 | 黑洞 |

**两条推论**：
1. 🔴 **贴图是 PNG 还是 DDS 完全无关** —— 逐格表现一致。两种导入方式落地都是 **DXT5 + alpha 活着**
   （`tpaccli dump --format dds` 读头实测：1024²、10 mip、FourCC=`DXT5`、alpha 0~255 分布完好）。
   ⇒ **「必须用 DDS 才能导入」是错的**。
2. 🔴 **`alphaTest = 0` 等于没开** —— `clip(alpha − 0)` 一个像素都不裁
   （HLSL `clip` 只在值 `< 0` 时丢弃，等于 0 不丢）。

### 源码链（为什么是这两条）

```
decal.rs（入口，像素着色器）:61        apply_alpha_test(In, pp_modifiable.early_alpha_value);
  └ deferred_decal.rsh:209-223        early_alpha_value = 1.0
                                      → × g_mesh_factor_color.a        (材质 Factor 的 alpha)
                                      → × diffuse_texture_color.a      ← 贴图 alpha，被下面这个 flag 门控
                                        if (!HAS_MATERIAL_FLAG(g_mf_do_not_use_alpha))
  └ shared_pixel_functions.rsh:502    apply_alpha_test_impl: if (ALPHA_TEST) clip(alpha_val - g_alpha_ref);
  └ flagDefs.rsh:92                   #ifndef ALPHA_TEST → #define ALPHA_TEST 0   ← 默认关，靠 shader flag 打开
  └ definitions_helper_macros.rsh:335 #define g_alpha_ref (g_permeshf_vargroup1.y) ← 材质 alphaTest 数值走这
```

⚠️ **`apply_alpha_test` 的调用在【入口 .rs】里，不在 `.rsh` 里** —— 五个 decal 入口
（`decal.rs:61` / `decal_gbuffer.rs:62` / `decal_overdraw.rs:64` / `deferred_decal.rs:98` / `deferred_decal_gbuffer.rs:99`）
**每一个都调了**。只 grep `deferred_decal.rsh` 会得出「decal 没有 alpha test 代码」的**错结论**
（本文档 2026-10-01 那条就是这么来的，**已作废**）。

### 另外两条同族 flag（别再踩）

| shader flag | 作用 | 原版证据 |
|---|---|---|
| `do_not_use_alpha` | **一开，贴图 alpha 在第一行就被丢掉**（上面那个 `if`） | `ashes_decal` 带着它 |
| `use_mask_texture` | 改用 **tex[1] 当软遮罩**（`early_alpha_value = sample_diffuse2_texture(...).a`，**是真混合、可羽化**，不是硬裁） | `decal_moss_a` 带着它 + tex[1] 挂了遮罩图 |

**⇒ 要"任意形状"用 `alpha_test`（硬裁、无羽化）；要"羽化边"得走 `use_mask_texture`（未实测）。**

### 工具：ModKit 面板里**看不到** `alpha_test` 这个勾选项

⇒ 离线写进材质元数据（2026-10-06 新建）：

```
tpaccli matflags --packdir <目录> --filter <材质名> --add alpha_test
```

字节级只重建 `ShaderMaterialFlags` 那一小段，其余字节原样；`AssetPackage.Save` 对元数据是
**RawMeta 优先直写 + 自动重算偏移**，所以变长插入安全（同 `clipflags` 的手法，见 [tools/tpactool](../../tools/tpactool)）。
⚠️ **每次 Publish 都会冲掉** —— 重发布后要再跑一次。

### 路线 A（`Decal` 组件）配自定义材质 = **什么都不出**（2026-10-06 再证一次）

四个材质（PNG / DDS × 阈值 0 / 0.588）走 `Decal.CreateDecal()` → `SetMaterial` → `AddComponent`
→ `Scene.AddDecalInstance(decal, "editor_set", true)`，**全部空白**。
机制：引擎拿**材质 tex[0] 的贴图名**查 `decal_textures_<当前场景组>.xml`，查不到 ⇒ 整条丢弃；
**它从不采样材质自己的贴图**（`decal_atlas_texture` 只被 `shared_decal_functions.rsh` ×7 / `gbuffer_functions.rsh` ×1 采样，
`decal.rs` / `deferred_decal.rsh` 里 **0 次**）。
⇒ **换 DDS、加 `alpha_test`、调阈值，都改不了 A 路的结果。**

⚠️ 引擎对运行时贴花被丢弃是**静默的**（native 全库只有粒子那条 `Can not find decal material %s`），**没有日志可查** ⇒ 判据只能靠眼睛。
⚠️ `AddDecalInstance` 那最后一句**不能省**（社区教程的 snippet 常漏；官方 MapCursor / 攻城器械圆圈两处都有）。
⚠️ 1.2.12 **没有** `Scene.RemoveDecalInstance`（1.5.x 才加）⇒ A 路清理只能 `Scene.ClearDecals()`。

## 🔴🔴 2026-10-06 定案（续）：贴花怎么「慢慢消失」—— 溶解的数学与贴图配方

> 这一节是**实机调通之后**把原理反推出来的：所有结论都能离线算出来、且与实机一致。
> 成品生成器：[`tools/decal-pipeline/scripts/gen_decal_shape.py`](../tools/decal-pipeline/scripts/gen_decal_shape.py)（说明见 [tools/decal-pipeline/README.md](../tools/decal-pipeline/README.md)）

### 一、规则（一切推导的起点）

```
像素被画出来  ⟺  贴图该点的 alpha  ≥  阈值 ÷ factor.a
                                      └──────┬──────┘
                                        "有效阈值"
```

- **阈值** = 材质 `alphaTest`（固定值）
- **factor.a** = 我们每帧写的 `Mesh.Color` 的 alpha（1 → 0）
- ⇒ **淡出 = 有效阈值从「阈值」一路扫到 ∞**，扫过贴图的 alpha 值

### 二、三条设计法则（算出来的，不是拍的）

**法则 1 —— 阈值同时管两件事，且互相拉扯**（8 位量化的倒数效应）

`有效阈值 = 阈值 ÷ factor.a` 是倒数 ⇒ 阈值越小，"形状快没了"那一段越被挤在最后几个字节里。

| 阈值 | 满亮时覆盖 | 尾段档位数 | 每步停留 | 观感 |
|---|---|---|---|---|
| 0.0235 | ~95% | **3 档** | 228 ms | ❌ 看得见跳档 |
| 0.1 | 90% | 12 档 | 69 ms | 勉强 |
| **0.2** | **80%** | **23 档** | **35 ms** | ✅ 推荐 |
| 0.3 | 70% | 30 档 | 29 ms | ✅ 但覆盖更小 |

**法则 2 —— 补偿曲线：让「有效阈值」线性推进**

`factor.a` 如果线性降，有效阈值就走倒数（前 95% 时间几乎不动、最后一下暴走）。
反解出让它**线性**上升的写法（已实现在 `SurfaceDecalFx.SetColor`，**只作用于 alpha 那一路**，RGB 乘法保持线性）：

```csharp
kAlpha = 阈值 / (阈值 + (1 − 阈值) × (1 − a))     // a = 权重 × 寿命因子（线性 1→0）
```

**法则 3 —— 贴图的 alpha 随半径要成「抛物面」，不是直线**

可见**面积 ∝ 半径²**。要让面积**线性**缩小（观感才均匀），必须 `半径 ∝ √(1−p)`，反解出：

```
alpha(r) = 1 − (1 − 阈值) × (r / 半径)²          ← 抛物面
```

- ✔ 面积随淡出**严格线性**（实测 77.6% → 49.0% → 29.3% → 9.6%，与线性理论吻合到 0.5%）
- ✔ **附带白赚**：抛物面按阈值归一化后，**形状边缘的 alpha 恰好等于阈值**（卡在裁剪线上）
  ⇒ **满亮时是完整的形状**。直线坡做不到这点（边缘 alpha=0，一上来就被啃掉 `阈值` 那一圈）
- ✘ 直线坡 ⇒ 面积按 `(1−T)²` 缩：前半程猛掉、后半程磨蹭

### 三、守恒律：**平台 alpha = 整块跳**（躲不掉）

alpha **同一个值**的像素必然**同时过线** ⇒ 只能整块消失，不可能分批。
⇒ 「能缩掉的行程」与「满亮时不被啃掉多少」**是同一个数**（都由坡覆盖多大范围决定）。
⇒ 唯一出路 = **让贴图没有平台** —— 抛物面天然满足（alpha=1 只有圆心一个点）。

### 四、坡要按「形状轮廓」算，不能按「画框边框」算

| 距离基准 | 结果 |
|---|---|
| **形状轮廓**（对轮廓做距离变换） | 可见边界永远是「轮廓内缩一圈」⇒ ✅ **锯齿轮廓保留** |
| 画框边框 | 可见边界变成坡的等高线（圆角方框）⇒ ❌ **形状轮廓被抹平** |

（前者代价：侵蚀深度 = 阈值 × 形状内切半径 —— 所以**痕迹要先放大到铺满画幅**，
否则会在一个小痕迹里缩，看着像"一小坨在缩小"而不是"整个方框往内收"。）

### 五、🔴 引擎**没有**真 alpha 混合（2026-10-06 验完）

`modulate` / `add_alpha` / `factor` **都不消费输出的 alpha** —— `factor` 实机结果：外圈照样画出来（黑框）、也没有渐变。
⇒ **单层 `decal_mesh` 做不到「真透明度淡出」**（整体变淡那种）。
⇒ **加法层（`add_alpha`）不存在这个问题**：它的浓淡走 **RGB 乘法**（乘到 0 = 加 0 = 看不见），天生平滑 ✓ 只是它替代不了地面。
⇒ 要「满幅 + 真淡出」只剩一条路：**粒子**（原版火焰地面 = 粒子出火苗 + 贴花出焦痕）。

### 六、成品配方（实机通过：覆盖 99% × 面积线性 × 轮廓不规则）

```
半径 R(θ) = ρ₀ × (1 + 0.10 × (0.55·sin3θ + 0.30·sin7θ + 0.15·sin11θ))   # ±10% 起伏，不是正圆
alpha(r)  = clip(1 − (1 − 阈值) × (r / R(θ))², 0, 1)                     # 抛物面
RGB       = 焦痕纹理铺满整幅（否则圆内是纯色圆盘，不像痕迹）
阈值      = 0.2（与抛物面归一化用的值一致）
```

实测（阈值 0.2）：**满亮直径 99% / 面积 77.6%**（内切圆理论 78.5%），淡出全程面积线性递减。

### 九、🔴 `modulate` = **替换**（不是乘法）—— 实机证伪 + 由此定下的设计分工

**判据（一发定死）**：给 `modulate` 层挂一张**纯白**贴图（形状内也白）+ `alpha_test` 裁掉形状外，
把它推到 factor = 1（本意是"无痕"）—— **画面直接变成一块白板**。

- 若是乘法：白 × 地面 = 地面 ⇒ 应该**毫无变化** ✗
- 实际是**贴图值被原样盖上去** ⇒ **替换** ✓

⚠️ **有个会骗人的假证据**（我据此误判过一轮）：贴花会把**地面法线**（从深度图算出来）写进 G-buffer，
所以**即使反照率被整片替换，画面上的砖缝/地形起伏依然看得见** —— 那是**光照结构，不是反照率** ✗
拿"细节还在不在"判乘法/替换会得出**相反的结论**。

**⇒ 替换语义的三条推论**：

1. **贴图值没有"无痕"档**：白就盖成白、黑就盖成黑
2. **唯一"不生效"的方式 = 根本不画**（靠 `alpha_test` 裁）
3. **推 RGB 只会把"盖上去的颜色"推向黑**，推不出"回到底面"
   ⇒ **替换型地表不能靠 factor 淡出**，只能靠**裁剪**（形状从边缘往内收 = §二 法则 3 的抛物面配方）

**⇒ 由此定下的设计分工（2026-10-06 用户裁定）**：

| 场景 | 做法 |
|---|---|
| **常规地表痕迹**（焦痕 / 结冰 / 水渍 / 岩浆）| **单层 `modulate` + 抛物面坡** —— **颜色丰富度直接画在一张贴图里**（中心火红 + 外圈焦黑 = 一张图的事），不需要叠层 |
| **多层过渡**（如火焰 ↔ 冰面的交叉淡化）| 🔴 **不能用加法层叠**（亮度叠加：N 片叠一处 ⇒ 亮度 = N 倍 ⇒ 大片地表必然过曝 ✗，2026-09-29 实测）<br>✅ **改走「两层 `modulate` 溶解式交叉」**（**提案，未验**）：两层都用替换、各自用 `alpha_test` 收/放形状 —— A 的阈值往上推（从边缘烧退）、B 的阈值往下放（从边缘冻进）<br>· **两层都是替换 ⇒ 互不叠加亮度** ✓（这正是加法层做不到的）<br>· **形状变化 = 自然的"烧过去/冻过来"**，比整体变色更像那么回事<br>· 抛物面配方直接复用（只是两层阈值反向走）<br>· ⚠️ **要补代码**：现在 `Tick` 是**统一驱动所有层**的，过渡需要**层级反向**驱动 |

> 🔴 **别再用"乘一层白/黑贴图 + 推 factor"去给地表做淡出** —— 那条路已证伪（替换语义下 factor 到 1 还是贴着贴图色）。

### 十、🔴 地表「过渡」（冰面被火焰从一侧吃掉）—— 互补高度场 + 一个数推分界线

**已实机验证**（2026-10-07）：`custom.surface transition lwn_decal_lava_crust lwn_decal_ice_water 5 4 10`
= 冰面上一条火线扫过、最后整块变成火焰地面 ✓

**机制**：贴图的 alpha 就是一张**高度场 f**（亮=1=先进方 A 的地盘、暗=0=后退方 B 的地盘）。
**分界线 = f 的等高线（水位线）** ⇒ **形状离线烘焙、位置运行期一个数就推**。

```
f           = 任意二维高度场（线性扫掠 / 径向 / 手绘不规则前线 —— 形状完全自由）
A（先进方）  : alpha = f          RGB = A 的颜色
B（后退方）  : alpha = 1 − f      RGB = B 的颜色          ← 必须【精确互补】
运行期       : A 的 factor.a = 阈值 ÷ L      B 的 factor.a = 阈值 ÷ (1 − L)
              （还是"有效阈值 = 阈值 ÷ factor.a"那条老关系，这次用它推【分界线位置】）
```

- ⇒ A 显示 `{f ≥ L}`、B 显示 `{f ≤ L}` ⇒ **既不重叠也不留缝** ✓
- ⇒ **两层绘制区域不重叠 ⇒ 绘制顺序无关** ✓✓（"多层顺序不可控"那条老坑直接绕过去了）
- 生成器：[`tools/decal-pipeline/scripts/gen_transition_pair.py`](../tools/decal-pipeline/scripts/gen_transition_pair.py)（`--方向 we/ew/ns/sn`）
- 命令：`custom.surface transition <先进方材质> <后退方材质> <距离> [半径] [秒]`

#### 🔴 三个坑（2026-10-07 一口气全踩了一遍，按踩到的顺序）

| # | 坑 | 症状 | 修法 |
|---|---|---|---|
| ① | **互补公式写歪** | 末尾留一道**窄边** | B 必须**精确** = `1 − A`。⚠️ 加了"下限修正"的 `1 − f + lo` 化简后**跟 A 一模一样** ✗（"alpha 恰好=1"那一小条会活下来） |
| ② | **贴图 RGB 的透明区是黑的** | 火区边缘一条**黑带**；冰区看着像"没盖住" | 用**距离变换**把待填像素指向**最近的不透明像素**、抄它的 RGB。<br>⚠️ **别用中位色** —— 岩浆图的中位色是**暗的**（大部分是暗岩、亮的才是裂缝），填出来整张还是暗的 ✗ |
| ③ | **阈值与 alpha 区间不配套** | 两边**速率不一致**、冰退到哪火没补上、**露地面** | 见下（这条最隐蔽）|

**③ 详解 —— 8 位量化会破坏互补**：

```
有效阈值 = 阈值 ÷ (字节值 / 255)        字节值 = round(255 × factor.a)  ← 两层各自独立取整
要求 有效阈值A + 有效阈值B = 1，但取整误差让这个和很难正好等于 1
⇒ 阈值越小，误差被放得越大：
     阈值 0.01 → 末尾冰的字节该是 2.55 取整成 3 → 实际有效阈值 0.85（该 1.0）✗ 偏差 0.15
     阈值 0.2  → 末尾冰的字节 51            → 实际有效阈值 1.00 ✓            偏差 0.003
```
⇒ **配方：阈值 0.2 + alpha 区间 `[0.2, 0.8]`**
（下限 = 阈值 ⇒ 水位推到 0 时先进方能**盖满**；上限 < 1 ⇒ 水位推到 1 时后退方能被**裁干净**）

> 🔴 **通用教训**：**阈值不是越小越好** —— 它必须和 alpha 的**取值范围配套**设计。
> "公式全对、跑起来就是不对"时，**先算一遍量化后的实际值**（本例就是被 8 位取整吃掉的）。

⚠️ **判某版本有没有某个 API，必须反编译该版本自己的 DLL** —— 本项目在此栽过：
我从 Steam 主目录（1.5.x）反编译看到 `ITerrainEdit`，误当成 1.2.12 的能力写进了计划。

**⇒ 1.2.12 上唯一可用的贴花路径 = `decal_mesh` + `add_alpha`。但加法有两个致命伤：**

| 致命伤 | 说明 |
|---|---|
| **① 越叠越亮，无上限** | N 片叠一处 ⇒ 亮度 = N × 单片；大片地表必然多片拼 ⇒ **每处拼接都过曝**（不只是"过渡带"的问题）|
| **② 不能替代地面** | 地面原本的颜色/纹理**始终在下面** ⇒ 只能做"罩一层光"，做不到"这处地面**变成了**火/水/冰" |

**⇒ 结论：加法做不出「地表」，只能做「光效」（火苗 / 余烬 / 雷电 / 毒光）。**

**旁证**：原版骑砍自己的火焰地面 = **粒子出火苗 + 贴花出焦痕** —— 它也没用贴花做"地表"。

**想要真地表**（能**替换地面**、而不是罩一层光）⇒ ✅ **有一条已验证成立的路：`modulate` 满幅地表（2026-10-01 实机三条）**

| 验证 | 结果 |
|---|---|
| `lwn_decal_lava_glow`（decal shader + **modulate** + 全不透明**可平铺**贴图） | 地块被**整块替换成岩浆** ✓ |
| 两片 `strip … 4 0`（**刚好挨着**） | **几乎没有接缝** ✓ ← 关键 |
| `strip … 4 10`（重叠 10%） | **有痕** ✗ ⇒ **必须按格刚好挨着、不许重叠** |

**做法**：贴图**可平铺** + 方块**按 1 米格精确排布（0% 重叠）** = 地形刷。
**代价**：① 无淡入淡出（modulate 不消费 alpha ⇒ 地表"啪"地出现/消失）② 边界**只能方形** ③ 重叠出痕。
**已排除**：换**非 decal shader**（`_metallic` 版）**不贴地** ✗ —— 必须是 decal 那支 `8490623a-…`。
**另一条（未验）**：`brush_decal` —— 它的 alpha 是**程序化圆形衰减**，若也贴地则能补上"圆形边界"。

（`ITerrainEdit`（1.5.x）那条依然是最完整的方案：天然 lerp + 能替代地面，但要换版本。）

## 🔴 收尾结论：贴花只做**一层**（2026-09-29 用户裁定）

> **多层叠加已验证为死路，不要再试。** 任何地表效果 = **一层贴花、一个材质、一张贴图。**

> ⚠️ **2026-09-30 补（读源码后）**：本节下面那条"**alpha 不影响形状**"已有解释 ——
> 是材质 flag **`do_not_use_alpha`** 开着，不是引擎不看 alpha；另外发现引擎自带一支
> **程序化圆形 + 世界坐标采样**的笔刷 shader（`brush_decal`），以及 `deferred_decal` 的**软遮罩**与
> **Factor alpha 调透明度**。**先读 [§八·补二](#八补二-三支贴花-shader-的源码实证2026-09-30) 再按本节结论办事。**

**为什么多层不行**（三条都是实机撞出来的，不是推测）：

1. **绘制顺序不受控** —— 而两层叠加的结果是**顺序相关**的（一层"覆盖"、一层"加法"，谁先谁后画面完全不同）。
   实机先后看到过三种状态：只有上层、上层被下层盖死、下层整片盖在最上面。
   prefab 里子节点的先后 **不能**决定绘制顺序（改过、无效）。
2. **`Modulate` 的行为至今没有稳定模型** —— 同一份材质配置，白底贴图出"整块变白"、暗底贴图出
   "压暗后仍看得见地面纹理"，两种观测**无法用同一个公式解释**。它到底是不是乘法、看不看 alpha，都没定论。
3. **形状机制只有硬裁**（`Alpha Test`）—— 硬裁**没有羽化**；想羽化只能把形状画进 RGB，
   而那只在**加法**层成立，加法又压不暗。

⇒ 三条限制叠在一起，"静态形状 + 动态内容 + 能压暗"这套组合在这个引擎里**没有可靠的实现路径**。

### ✅ 单层的唯一可靠配方（实机验通过）

| 项 | 值 |
|---|---|
| 层数 | **1** |
| 混合 | **`AddAlpha`** |
| 贴图 | **形状画在 RGB**，底色**纯黑**（黑 = 加 0 = 无痕）⇒ 可任意羽化 |
| 透明处 | **RGBA 四通道一起归零**（用户裁定，2026-09-29） |
| 只能做 | **往地面上加东西**：发光、霜、水光、火星 |
| 做不了 | **压暗 / 替换地面**（焦黑、深水底）—— 加法只能提亮 |
| 要动 | C# 每帧推 `VA1`（见 §七·补），贴图必须**四边无缝**（采样器是 WRAP） |

**先例**：`lwn_decal_scorch_d`（上一轮验通）、`lwn_decal_ice_sheet_v4_d` + `lwn_decal_ice_glint_v3_d`（两个独立的单层，各自成立）。

**⚠️ 单层的固有代价**：**"形状不动 + 内容在动"做不到** —— 形状和内容在同一张贴图里，滚动就一起滚。
要流动就得接受"整张图一起滚"；要形状钉住就得放弃流动。

### 留下的可复用件（都还在，单层照样用）

- `Debug/offline/_gen_decal_lava_ice.py` —— 无缝贴图生成器（周期性 Voronoi + 可平铺噪声）
- `Debug/offline/_preview_decal_lava_ice.py` —— 离线"上地模拟"预览，出图前先自己看一眼
- `CampaignMode/Tools/DecalFxCommands.cs` —— `custom.decal_fx`：召唤 + 每帧推 UV + 速度锁档
- 知识：采样器 **WRAP**（能循环滚）· 贴花 shader **无时间项** · `Alpha Test` 刻度是 **0..255**（原版"开"= **6**）

### 1.4 为什么「不在表里 = 空白且不报错」

`gbuffer_functions.rsh` 的贴花主路径：

```hlsl
float2 tc_d = get_atlassed_decal_texture_tc(tc_init, d_atlas_uv_d, atlas_uv);
if (any(tc_d)) { decal_d = decal_atlas_texture.SampleLevel(linear_clamp_sampler, tc_d, 3); }
// 否则 decal_d 保持 0 → alpha 0 → 什么都不画
```

名字查不到 ⇒ `d_atlas_uv_d` 全零 ⇒ `tc_d` 全零 ⇒ 采样被跳过 ⇒ 不可见。
**一个自然、无声、极难排查的失败模式。**

`DecalParams` 结构体（`definitions_shader_structs.rsh:203`）把两级 UV 说死了：

```hlsl
float4 atlas_uv;      // scale_x, scale_y, offset_x, offset_y   ← 这就是 VA1
float4 d_atlas_uv_d;  // diffuse 在大图里的矩形 ← 来自表的 atlas_pos
float4 d_atlas_uv_s;
float4 d_atlas_uv_n;
```

`decal_textures_*.xml` 每条都有 `is_dynamic`。**游戏本体和编辑器的 `TaleWorlds.Native.dll` 里都搜不到这个串**
（运行时要读的话会和 `atlas_pos` 一样留一个字符串）⇒ 它是构建期图集打包工具的记账标记，运行时无关。

## 二、路线 B：网格路（`decal_mesh` + 任意 decal 材质）

### 2.1 `decal_mesh` 是什么

**引擎内置的一个现成立方体网格**（native 内置网格名单里和 `skybox`/`blob_shadow`/`__unit_xz_mesh__` 并列）。
导出的 obj 实证：8 个顶点在 ±1、6 个面 12 个三角形、每面完整 0..1 UV。

- **有效投影体积 = 物体空间 `[-0.5, 0.5]³`**（1×1×1 米 × 实体缩放，中心在实体原点）
- 代理网格是 `[-1,1]³` = **故意放大 2 倍**，保证斜视/斜坡也不缺角

### 2.2 投影怎么工作（**跟网格形状无关**）

`deferred_decal.rsh` 的像素阶段：

```hlsl
// 1. 用屏幕坐标读【场景深度图】
float pixel_depth = sample_texture_level(depth_texture, linear_sampler, tc.xy, 0).x;
// 2. 反算该像素上【真实表面】的世界坐标（不是网格自己的位置）
float4 pixel_pos_in_ws = float4(get_ws_position_at_gbuffer(pixel_depth, tc), 1);
float4 pixel_pos_in_os = mul(g_world_inverse, pixel_pos_in_ws);
// 3. 换到贴花物体空间，落在有效体积外直接丢弃
pixel_pos_in_os.xyz *= 2;
if (any(abs(pixel_pos_in_os.xyz) != saturate(pixel_pos_in_os.xyz))) clip(-1);
// 4. 贴图坐标 = 物体空间的 XY
float2 decal_tex_coord = pixel_pos_in_os.xy * 0.5 + 0.5;
```

人话：**画的是地面，不是网格**。每个像素去问深度图"这里真实表面在哪"，把贴图贴在**那个表面**上。
贴图沿实体**自身的 Z 轴**往下投（第 4 步只取 XY）⇒ **不需要旋转**。

> 官方编辑器文档原话："Their projection geometries are cubes and they are projected in the Z direction."

native 里有专用渲染 pass：**`Forward Decal Meshes`**（紧跟 Alpha Blended Forward Meshes）。

### 2.3 🔴 尺寸与摆位规则

| 项 | 含义 |
|---|---|
| **实体 Position** | 贴花中心。放地上就是把原点放在地面高度 |
| **Scale X/Y** | 贴花在地面上的**实际尺寸（米）** —— `3.0` ⇒ 3×3 米 |
| **Scale Z** | **竖直厚度**。原版 `props_testing.xml` 的 `_decal` 给 **0.022**（2 厘米，薄片，不糊到人/石头上）。地面起伏大就加大 |
| **rotation_euler** | 只转 Z 调朝向即可（Z 轴本来就是竖直的） |
| **VA1（`argument`）** | `1.000, 1.000, 0.000, 0.000` = 整张贴图铺满。它是**贴图内子矩形**，不是大图矩形 |
| **`factor`** | 染色 + 透明度（打包色，ARGB）。原版 `_decal` 用 `4279315788`；不透明白 = `4294967295` |

### 2.4 🔴 prefab 里 scale 必须写在**子节点**上

`GameEntity.Instantiate(scene, name, frame)` 传进去的 frame **会覆盖根节点的 transform**
（根上写 position/scale 一律无效，实测症状 = "召唤了还是原样"）。**子节点不受影响**。
范本：`Modules/LivingWorldNpcs/Prefabs/spell_rasengan.xml`（2026-09-27 实测记下的）。

### 2.5 实机状态（2026-09-29）

- ✅ **投影成立**：`decal_mesh` + decal 材质在城镇石砖地面上**服帖贴合地形**，无几何体、无平面
- ✅ **自绘贴图全程打通**（用户实机验通）：自己画的 PNG → 导入 → decal 材质 → `decal_mesh` →
  **出不规则、有羽化边的地面发光贴花**
- ✅ **贴图规则查明**：形状画在 **RGB**，空处填该 Blend 的**空色**（§四）
- ✅ **ModKit 所见 = 游戏所见**（用户实测）⇒ 调贴花**不用重启游戏**，编辑器里迭代
- ⚠️ **贴花受场景光照影响**（albedo 进 G-buffer 后被场景光照明）——「夜里也亮」要靠 `Emission`（未验）或粒子
- 曾经的"整块硬边矩形"已解释：那是「RGB 没有空色的贴图」，两种 Blend 都会整块染色

## 四、🔴 贴花贴图怎么画

> 🔴🔴 **2026-09-29 实机更正（推翻本节原来的"无痕色"表）**：原来写「Modulate = 地面 × RGB，空色 = 纯白」——
> **是错的**。实机证据：一块「浅色底、alpha 全 255」的结壳贴图配 `modulate`，
> 出来是**脚下石砖整个变白**（砖缝还在 —— 说明只换了 albedo，没换几何/光照）。
> 乘法做不出"变亮"，所以 **`modulate` 不是乘法**。
>
> **校正后的模型（当前采用）**：

| Blend | 公式 | 「什么都不发生」怎么写 | 只能做 |
|---|---|---|---|
| **`Modulate`** | **覆盖 / 替换反照率**（贴图 alpha **不参与混合**） | 没有办法"什么都不做"——**必须靠 Alpha Test 裁掉不要的像素** | 把足迹换成一张表面 |
| **`AddAlpha`** | 地面 **+** 贴图 RGB | **RGB = 纯黑** | 提亮（加法） |

### 4.0b 🔴🔴 形状要靠 `Alpha Test`，不是靠 alpha 混合（2026-09-29 实机定位）

- shader 里的机制是**硬裁**不是混合：`apply_alpha_test_simple` = `if (ALPHA_TEST) clip(alpha_val - g_alpha_ref);`
- 🔴 **材质 `Alpha Test = 0` 时整个裁剪被跳过** —— 贴图 alpha 算得再对也没人用。
  实机症状：`modulate` 层把**整个方形足迹**铺满（裂缝看不见、水洼变成一个大方框）。
- **开启值 = `0.024`**：原版贴花材质里 `alphaTest` 只有两个取值 —— `0`（32 个）和 `0.024`（5 个）。
  0.024 就是"启用裁剪"的档位（阈值近似"只丢掉完全透明的像素"）。
- ⚠️ **因为是硬裁，贴图 alpha 要做成二值**（0 / 1）。平滑衰减按 0.024 裁出来只剩一条发丝细线
  （例：`alpha = 1 - exp(-edge/w)` 在阈值附近只有极窄一条）。要"有宽度的缝"就写成布尔带。
- ⚠️ **硬裁做不出羽化边**。想要边界不呆板，只能把轮廓做成**不规则**的（用低频噪声定轮廓），
  或者接受硬边。加性层不受此限（它的形状在 RGB 里，黑=无痕，可以任意羽化）。

**⇒ 形状一律画在 `alpha` 里并做成二值；RGB 只放「要覆盖/叠加上去的颜色」。**
羽化 = alpha 的渐变。这条对两层都成立，也是**唯一**能做出"形状边缘不带硬方框"的写法。

- ⚠️ **旧表的来源**：它是对着"品红 + 二值 alpha"那次实验归纳的（当时看到整块品红 ⇒ 判 alpha 不门控）。
  那次的 alpha 很可能在导入环节就没了（`png_for_editor.py` 会丢 alpha，见 §4.1），
  所以**别拿那次结论当准**。§七 本来也注明过"Modulate + 白底"那条**只有数学校验、没实机跑过**。
- ⚠️ 本节第一版还写"贴花足迹是整个方块，形状要留在贴图内圈" —— 在**新写法下不必要**：
  alpha=0 就是完全无痕，形状可以画到贴图边缘。
- ⚠️ **贴花受场景光照影响**（albedo 进 G-buffer 后被场景光照明）—— 想要"夜里也亮"得靠
  `Emission`（Vector Argument 2 的 x 分量，**未验**），或改用**粒子**：
  原版火焰地面就是「粒子出火苗 + 贴花出焦痕」两层

**规格**：`RGBA` · 只写 `IHDR/IDAT/IEND`（不带 `sRGB/gAMA/cHRM/eXIf/pHYs` 附加块）· 尺寸 1024² 实测可用 ·
**必须带 alpha 通道**（形状靠它）。
生成器：`Debug/offline/_gen_decal_maps.py`（四种结构一起出 + 剥块 + 回读校验）。

### 4.0 实测记录（按**新模型**重读；结论都改过了）

| 做法 | 当时的判读 | 新模型下的正确读法 |
|---|---|---|
| 品红铺满 + 二值 alpha，配 `Modulate` | 整块饱和品红 ⇒ "alpha 不门控" | 也可能是**那次 alpha 没活到运行时**；不能据此判 alpha 无用（见 §4.1） |
| 同一张，配 `AddAlpha` | 整块淡品红 | 加法 ✓ 与"RGB 直接加"一致 |
| RGB = 形状 + **黑底**、alpha = 形状，配 `AddAlpha` | ✅ **出形状的暖色发光贴花**（用户实机验通） | 仍成立 ✓（黑底 = 加 0） |
| 原版血材质 `blood_terrain_decal_3` 挂 `decal_mesh` | 一整片红矩形 —— "没有空色概念" | **正是"反照率被替换"**：RGB 全图同一个红 ⇒ 整块变红 ✓ 印证新模型 |
| 🔴 **本轮（2026-09-29）**：浅色底 + alpha 全 255 的结壳图，配 `Modulate` | —— | **脚下石砖整块变白、砖缝还在** ⇒ `modulate` 是**按 alpha 混向贴图色**，不是乘法 |

### 4.1 ⚠️ 工具坑：`png_for_editor.py` 会**丢掉 alpha**

[`tools/face-pipeline/scripts/png_for_editor.py`](../tools/face-pipeline/scripts/png_for_editor.py)
是给**不透明贴图**写的，第 15 行注释明写「8bit RGB（丢掉 alpha）」。`AddAlpha` 型贴花靠 alpha 吃饭，
过它 = 形状信息被删（`Modulate` 型不受影响，因为它本来就不看 alpha）。

它要解决的坑是真的（Blender 的 PNG 带 `sRGB/gAMA/cHRM/eXIf/pHYs` 附加块 → 编辑器连源图带产物一起删），
**但该丢的是附加块，不是 alpha**。需要的是「保留 alpha、同样只写 IHDR/IDAT/IEND」。
现成范本：`Debug/offline/_gen_decal_maps.py`（两种贴图一起出 + 剥块 + 回读校验）。

### 4.1b ⚠️ 用 Pillow 缩放带 alpha 的 PNG 会把**透明区的 RGB 抹成黑色**

2026-09-29 实测（Pillow 12.3.0）：

```
原图角落:                RGB=(255,255,255)  A=0    ✓
LANCZOS/BILINEAR/BICUBIC 缩放后: RGB=(0,0,0)      A=0    ✗ RGB 被清零
NEAREST 缩放后:          RGB=(255,255,255)        A=0    ✓
```

**为什么这是坑**：`Modulate` 用的是 **RGB**，透明区的 RGB 一旦变黑 ⇒ 乘 0 ⇒ **整块足迹被压成纯黑方块**
（就是本项目反复撞的那个"矩形"症状）。**做预览图、缩图、拼图时都会中招。**

**规避**：① 要缩放就先把 alpha 合成了再缩（无 alpha 的图不会被清）② 或用 `Image.NEAREST`
③ 或者干脆别缩，用全尺寸。**生成产物本身不受影响** —— 只要别让 Pillow 去 resize 它。

**判据**：读回 PNG 的四角，`RGB` 必须是该模式的**无痕色**（Modulate=255 / AddAlpha=0）。

### 4.2 粒子贴图不能复用来做贴花

粒子那套（`lwn_yinmo_*`、`lwn_prt_*`）是给 `particle_shading` 加法发光做的，天生「RGB 暗、无 alpha」——
直接拿来配 `Modulate` 就是整块压黑，配 `AddAlpha` 只剩亮点。**必须按 §四 的规则重画。**

## 五、装包与进游戏（内容包流程）

### 5.1 三段链路

```
编辑器 Publish  →  Modules/Publish/<模块>/AssetPackages/pack0.tpac
                →  改名拷进  Modules/LivingWorldNpcs/AssetPackages/lwn_core.tpac（先备份旧的）
                →  重启游戏
```

🔴 **别把 Publish 目标直接指到 `Taikou\AssetPackages`** —— 那个目录会被 Publish 清空。
🔴 **每次改完都要重搬**，否则游戏读的还是旧的。

**搬运前先核对新包是旧包的超集**（`tpaccli list` 两个包对比资产名，缺失必须为 0）。范本：2026-09-29 那次新包 94 项 / 旧包 93 项 / 缺失 0。

### 5.2 🔴 陷阱：`Assets/` 会把 `AssetPackages/` 整个遮蔽

引擎在模块目录下找资产目录，按**有序清单取第一个存在的**：
`Assets` → `AssetPackages` → `DsAssetPackages` → `EmAssetPackages` → `AssetsBackups` → `AssetSources`。

- 编辑器会重建 `Assets/`（里面是**中间产物**：贴图**只有导入设置没有像素**，`_tex.tpac` 才几百字节）
- 一旦 `Assets/` 存在，刚发布的 `AssetPackages/*.tpac` **一个字节都不会被读**
- 症状：材质读得到（`_mtl.tpac` 是完整的）、**贴图却是空的** —— 极像"材质配错"

**判据（一眼看穿）**：引擎日志里该模块那行 ——
`Loading packages $BASE/Modules/<模块>/AssetPackages...` ✅ 应为这个；
写着 `.../Assets...` ❌ 就是踩了。

**修法**：跑该模块的 `to_game_mode.bat`（`Assets` → `Assets_disabled`）。要回编辑器跑 `to_editor_mode.bat`。
⚠️ ModKit 会重建 `Assets/` ⇒ **此坑会复发**。

### 5.3 prefab 放哪 + 怎么召唤

- prefab XML 放 **`Modules/<模块>/Prefabs/*.xml`**（引擎自动扫描，不需要登记）
- **必须放在游戏 `_MODULES_` 启动列表里的模块**（用 `Taikou`，不是 `LwnAnim`）
- 召唤：`custom.spawn_prefab <prefab名> [距离米]` —— 放在玩家脚下、面前 N 米
- 🔴 **`custom.decal` 验不了路线 B**：它走 `Decal.CreateDecal()` + `AddDecalInstance` = 路线 A（图集），
  用它验自绘贴图**必然空白**，会让你误判

## 七·补、🔴 贴花怎么「动起来」（2026-09-29 补，含对旧结论的更正）

**结论（两条路，用哪个由材质决定）**：

| | A. C# 每帧推 VA1 | B. 引擎自走 |
|---|---|---|
| 怎么做 | `Mesh.SetVectorArgument(1,1,ox,oy)` 每帧改偏移 | 材质勾 `use_texture_sweep`，shader 里 `uv += VA2.xy × g_time_var × 0.1` |
| 需要什么 | 任何 decal shader 都吃 | **只有 `deferred_blood_terrain` 这一个贴花 shader 读它** |
| 代价 | 每帧几条贴花写 4 个 float（可忽略） | 零每帧开销；C# 只在召唤时写一次 VA2 |

- 🔴 **更正**：本文档/wheels 曾写"贴花吃不到动画 flag"—— **不准确**。准确说法是：
  **`use_animated_texture_coords` 贴花吃不到**（`flagDefs.rsh` 里有它，但读它的只有 pbr_standart 那几支），
  而 **`use_texture_sweep` 是可以勾的材质 flag**，贴花族的 `deferred_blood_terrain` 就读它。
  实证 = 阴魔斩 `lwn_yinmo_crescent` 材质 `shaderFlags` 里有它、实机在流动。
- 🔴 **两条 sweep 的参数口径不同，别混**：网格族 `pbr_standart` 用 **VA1.xy**（`tex_coord -= VA1.xy * g_time_var * 1.64`）；
  贴花族 `deferred_blood_terrain` 用 **VA2.xy**（`+= VA2.xy * g_time_var * 0.1`）。
- 🔴 **网格 shader ≠ 贴花 shader**：材质挂错族，`decal_mesh` 被当普通网格画成一个大立方体（投影不发生）。
- 🔴 **`g_time_var`** = `g_perscene_f_group3.x`（引擎每场景的全局时间，自己走）。除这两条 sweep 外，
  decal 路径里**没有任何时间项**（`deferred_decal.rsh` 里唯一用到它的那行是注释掉的 brush 分支）。
- ✅ **采样器是 WRAP**：引擎根签名 `s5`（= `anisotropic_sampler`，贴花 diffuse 用的就是它）明写
  `TEXTURE_ADDRESS_WRAP`（`Shaders/Sources/root_signature.rsh`）⇒ **无缝贴图能无限循环滚动**，offset 推到 1.0 回绕无接缝。
- 🔴 **硬约束：滚动的贴图保不住羽化边**。足迹边界映射到的纹素位置每帧都在变，

- 🔴 **`deferred_blood_terrain` 还有个 `USE_AREAMAP` 分支**：遮罩采样用的是
  **`decal_tex_coord`（未滚动的足迹 UV）**、颜色用的是 `atlassed_texture_coord`（可滚动）——
  这是目前找到的**唯一**能让"静态羽化形状 + 动态纹理"并存的口子。

## 八·补、贴花**做不到**的两件事（2026-09-29 用户提出，记为后续方向，尚未实现）

### 1. 贴花是**纯视觉** —— 它不产生几何，踩不到

贴花改的只是**地面那一层的反照率**：引擎每像素去问深度图"这里真实表面在哪"，
然后把贴图贴在**那个已有表面**上（§2.2）。所以：

- 玩家踩的**始终是地形本体**，贴花既不是实体、也没有碰撞体；
- 想要"能站上去的表面"（用户原话：**像一块木板那样能走**），那**必须另加一个带碰撞体的实体**——
  并且记住项目的既有结论：**碰撞走 `body_name` 的物理形状，不走视觉网格**（见 wheels.d/assets.md 武器那节）；
- 那就不再是"贴花"了，而是"实体面 + 贴花做视觉"的组合。

**顺着的游戏性延伸**（比视觉更值钱，也更容易被忽略）：
- 踩进**熔岩**该不该扣血 / 着火？（贴花现在完全无害）
- **冰面**该不该打滑？（会滑的地面 = 玩法，不是贴图）
- ⇒ 把这两个效果从"贴图"升级成"玩法"，入口都在**碰撞体 + 每帧查询**，不在贴图。

### 2. 纯加法层做不出「冰」，只做得出「雪」

实测（2026-09-29）：冰面用 `AddAlpha` 出图后，观感是**雪**不是冰。原因是加法层的物理限制：

| 冰的辨识度靠什么 | 加法层能给吗 |
|---|---|
| **镜面/高光**（反光才是"冰"） | ❌ 加法只提亮，打不出高光 |
| **半透深度**（底下透出更暗的水/泥） | ❌ 加法只能往上加光，压不暗 |
| 冷白 | ✅ |

⇒ 结果就是"均匀淡蓝白 + 软边" = **雪的视觉定义**。要改成冰，按优先级：
1. **给材质挂 Specular Map**（`use_specular` 这个 shaderFlag 已有、但**第二张贴图槽空着**）—— 高光一出来，冰和雪立刻分开；
2. **底色压下去、拉开明暗对比**（暗底 + 局部亮）= **需要一个"能压暗"的层** ⇒ 与熔岩卡在同一件事上；
3. 裂缝画直画锐（现在的偏软）。
   🔴 注意 2 依赖 `Modulate` 层，而该层的形状机制在 1.2.12 上是**硬裁**（`Alpha Test`），
   硬裁**没有羽化**——冰的软边和"压暗"目前是**互相冲突**的两个需求，要在 shader 层面解（见下）。

### 3. 真正通吃的解法（未做）

`deferred_blood_terrain` 这个贴花 shader 同时带 `USE_AREAMAP`（遮罩按**未滚动的足迹 UV**采样、
是真混合不是硬裁）和 `USE_TEXTURE_SWEEP`（引擎自走 UV）。它能一次解决本页列出的多数冲突：
形状可羽化 + 色彩层可滚动 + 不必靠 `Alpha Test`。
**代价**：它的投影体积判定没有 1.2.12 那行 `* 2`（同 scale 大一圈），且自己算光照、观感不同。
详见 [plans/贴花-熔岩与冰面.md](../plans/贴花-熔岩与冰面.md) 的进阶节。

## 八·补二、🔴 三支贴花 shader 的源码实证（2026-09-30）

> 来源：**直接读 shader 源码**（`<游戏根>/Shaders/Sources/`，1.2.12 客户端）+ 材质 flag 定义表
> （`definitions_helper_macros.rsh` 的 Material Flags 段）。这一轮把前面几条"观测归纳"换成了源码事实，
> **并且解释了 §四 那个"两种 Blend 下 alpha 都不影响形状"的谜团**。

### 1. 🔴 `do_not_use_alpha` 才是"alpha 失效"的真因（不是引擎不看 alpha）

`deferred_decal.rsh:199-203`（贴花主 shader —— 我们用的 `decal` 材质就是这一支）：

```hlsl
early_alpha_value *= g_mesh_factor_color.a;                        // ① Factor 的 alpha
if(!HAS_MATERIAL_FLAG(g_mf_do_not_use_alpha))                      // ② 这个 flag 一开
    early_alpha_value *= diffuse_texture_color.a;                  //    贴图 alpha 整个被跳过
```

- **材质 flag `do_not_use_alpha` = bit 0**（`g_mf_do_not_use_alpha = 0x00000001`）。
- 它一开，**贴图 alpha 完全不参与**。我们那些材质是从原版 `blood_terrain_decal_3` 另存来的，
  **很可能带着这个 flag** ⇒ 于是"alpha 怎么画都没用"。
- ⇒ **要用 alpha 形状，第一件事是关掉这个 flag**（在材质编辑器的 Material Flags 里找）。
- 本条的推论：§四 那句"**形状只能画在 RGB 里，alpha 只需和 RGB 同步为空**"**只在该 flag 开着时成立**，
  不是引擎的普遍行为。**先查 flag，再谈 alpha 有没有用。**

### 2. 🔴 Factor 的 alpha = **每片贴花的透明度**

同一行 `early_alpha_value *= g_mesh_factor_color.a` ——
`Material.SetFactor1(ARGB)` 的 **A 通道**就是这一片的整体不透明度。
⇒ **每片贴花可以单独调浓淡**（这是"权重"的载体：同一处叠两片不同类型，靠各自的 alpha 做交叉淡入）。

### 3. 🔴 `deferred_decal` 也有**软遮罩**（不只有 `deferred_blood_terrain`）

```hlsl
if(bool(USE_MASK_TEXTURE))            // shader flag（flagDefs.rsh:196）
{
    early_alpha_value = sample_diffuse2_texture(atlassed_texture_coord).a;   // 第二张贴图当遮罩
    clip(early_alpha_value - 0.001f);                                        // 只裁掉完全透明的
}
```
- 这是**软**遮罩（不是硬裁）：alpha 值会乘进输出 —— **羽化形状可做**。
- 遮罩和漫反射**共用同一套 UV**（同一个 `atlassed_texture_coord`）⇒ 两者一起缩放/平移。

### 4. 🔴 `brush_decal` = 引擎自带的"程序化圆形笔刷"

`deferred_decal.rsh` 的 `calculate_albedo_deferred_brush_decal`（`:259-299`），
由入口 `brush_decal.rs` 调用（和 `decal.rs` 是**两支并列的 shader**，同一族）：

```hlsl
const float dist = length(my_pos.xy - pixel_pos_in_ws.xy);   // 实体世界XY 到 像素世界XY 的距离
float alpha = saturate(1.0 - dist / side_len);               // 形状 = 算出来的圆，不需要形状贴图
alpha = pow(alpha, max(0.01, 1 - saturate(VA2.y)));          // 羽化曲线可调
alpha *= clamp(saturate(VA2.x) * 0.9 + 0.1, 0.1, 1.0);       // 强度 0.1~1.0
albedo = sample_diffuse(anisotropic_sampler, pixel_pos_in_ws.xy * VA2.z).rgb;   // ← 按世界坐标采样
```

- 🔴 **最值钱的一条**：颜色**按世界坐标采样**（`pixel_pos_in_ws.xy × VA2.z`）⇒
  **相邻/重叠的笔刷落在同一世界坐标上取同一纹素 ⇒ 同类型地表天然连续，没有接缝、没有"一格一格"的重复感。**
- 形状**程序化**（圆形 + 幂函数衰减），不需要形状贴图；`VA2.x` 强度、`VA2.y` 羽化、`VA2.z` 世界平铺尺度、`VA2.w` 模式（>0.75 世界贴图 / >0.25 加遮罩 / >0.10 纯白+遮罩）。
- ⚠️ **它的遮罩分支是坏的**：函数里 `float2 tex_coord = float2(0,0);` 声明后从未更新，
  于是 `sample_diffuse2_texture(1 - tex_coord.xy)` **恒定采样 (1,1) 那个纹素** ⇒ 等于没有遮罩。
  要用它就走 `VA2.w > 0.75` 那条（纯程序化圆形）。
- ⚠️ **缩放语义与 `decal` 不同**（半径 = 半个 X 轴缩放），换 shader 要重新标定尺寸。

### 5. 贴花族里**没有**任何时间项 —— 唯一两处"能动"的地方

| 能动的地方 | 谁提供时间 | 代价 |
|---|---|---|
| `deferred_blood_terrain` 的 `USE_TEXTURE_SWEEP`：`UV += VA2.xy × g_time_var × 0.1` | 引擎 | 只有这一支 shader 读；**纯线性平移**（永远单向、不回头） |
| 任意贴花 shader 的 `VA1`（UV 缩放/偏移），C# 每帧写 `Mesh.SetVectorArgument` | 我们 | 可写**任意函数**（含 sin 来回摆） |

**已逐支核实：`use_animated_texture_coords`（翻页）没有任何贴花 shader 读它** ——
读它的只有 `light_emitter_sprite` / `pbr_standart_vertex_functions` / `show_texture` / `ui_shaders`。
⇒ §七·补 那条结论**成立且现在是源码级证据**。

### 8. 🔴🔴 **每片贴花的"浓淡"入口 = `Mesh.Color`，且只有 RGB 有效、alpha 无效**（2026-09-30 实机五连测定案）

**这条推翻了本文档 §八 里"写 alpha 控制透明度"的假设**，是**驱动贴花浓淡的唯一实测可行手段**。

**证据链**：

| 步骤 | 结果 |
|---|---|
| `Mesh.Color` 到底写的是不是 `g_mesh_factor_color`？ | **是** —— native 桥接里 `SetColor` 与 `FactorColor2/GetFactor2/SetFactor2` 是**同一串相邻的脚本绑定名**；且 `mesh_factor_color` 与**已验可用**的 `mesh_vector_argument`（UV 滚动靠它）在**同一个 `meshf_1_struct`** |
| shader 里它怎么用？ | `albedo_color.rgb *= g_mesh_factor_color.rgb` —— **无条件生效**（`deferred_decal.rsh` 的 `compute_albedo_color_for_decal`） |
| 染红 `tint ff0000` | **变红** ✓ |
| 染绿 `tint 00ff00` | **变绿** ✓ |
| 染蓝 `tint 0000ff` | **变黑消失** ✓（贴图是暖色、蓝分量≈0 ⇒ 蓝×蓝≈0 ⇒ 加法加 0 = 看不见） |
| 只改 alpha（`drive alpha` + `lock 0.2`）| **毫无变化** ✗ |

🔴 **两条结论**：
1. **加法层（`add_alpha`）**：浓淡 = **RGB 乘法**。乘到 0 = 加 0 = 看不见 = **淡出**。
   ⇒ 淡入 / 淡出 / 过渡**全用 RGB 一个旋钮**，不需要 alpha。
2. **压暗层（`modulate`）**：alpha **同样无效**，且 `RGB→小` 是**黑块**不是变淡
   ⇒ **压暗类贴花无法用 factor 淡出**（要淡出只能靠裁剪 —— 见卷首「2026-10-06 定案（续）」的抛物面配方）。

**用法**：每帧 `Mesh.Color = 0xFF000000 | (基色RGB × 浓淡)`，其中浓淡 ∈ [0,1]。
落地件与完整实机记录：[plans/元素地表系统.md](../plans/元素地表系统.md) §十五（交接）。

### 9. 引擎自己留着一行"贴花 alpha 脉动"

`deferred_decal.rsh:271`（笔刷的 alpha 计算行）末尾：

```hlsl
alpha *= clamp(saturate(VA2.x) * 0.9 + 0.1, 0.1, 1.0);
//      *(sin((g_time_var * 5)) * 0.5 + 0.5);      ← 注释掉的脉动
```

⇒ **引擎作者本来的贴花动画思路 = 明暗脉动**（不是位移）。要"燃烧地面忽明忽暗"，照这行做就行（C# 每帧推 alpha）。

### 7. 结论：**火焰的"动"不该由贴花承担**

贴花的平移做不出"来回摆荡/扭曲"（平移是单调的、且整张图一起走）。
**真湍流在粒子那边**：3D Perlin 噪声场（`turbulence_strength`，GPU 粒子专属）+ 每颗粒子的生命内 UV 偏移 + 图集翻转书。
⇒ 正确分工 = **贴花出静止的地面（焦痕/水渍/油面/霜）+ 粒子出会摆的火苗与雾**（原版火焰地面就是这个组合）。
详见 [plans/元素地表系统.md](../plans/元素地表系统.md)（地表系统的唯一文档）。
