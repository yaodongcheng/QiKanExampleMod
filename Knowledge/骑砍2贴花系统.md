# 骑砍2 贴花系统（Decal）—— 引擎能力与实现

> **一句话**：贴花 = 把一张图**投射到已有表面**（地形/物件）上，不需要铺几何体。
>
> 🔴 **要「用自己画的贴图做地面效果」→ 直接跳到 §零 照配方做，全链路已实机验证通过。**
>
> 🟡 **两条路线（这个二分是本文的归纳，不是官方术语；但两套 API 与两条 shader 路径是客观存在的）**：
>
> | | **A. Decal 组件 / 运行期 API** | **B. `decal_mesh` 网格 + decal 材质** |
> |---|---|---|
> | 怎么建 | 空实体 + `Decal` 组件；或 `Decal.CreateDecal()` | 空实体 + MetaMesh(`decal_mesh`) + 一个 **decal shader** 材质 |
> | 贴图从哪来 | **全局图集** `decal_atlas_<组>`，靠**贴图名查表** | **材质自己的贴图** |
> | 能用自己画的图吗 | ❌ **不能**（要塞进图集，无已知手段） | ✅ **能** |
> | alpha 管形状吗 | ✅ 管（形状画在 alpha） | ❌ **不管**（形状必须画在 **RGB**，见 §四） |
> | 实机状态 | ✅ 能出画（限表里注册过的贴图） | ✅ **全链路已验（2026-09-29 实机）** |
>
> 证据来源：**反编译**（TaleWorlds.Engine/Core/MountAndBlade/CampaignSystem + Native 字符串）·
> **shader 源码**（`<游戏根>\Shaders\Sources\`）· **编辑器实拍** · **实机实测**（2026-09-29）。

## 零、快速上手：用自己画的贴图做地面效果（推荐路线 B）

```
① 画图   形状画在【RGB】里，空处填【该 Blend 的空色】（AddAlpha→纯黑 / Modulate→纯白）
         尺寸 1024²，RGBA，只写 IHDR/IDAT/IEND（照抄 Debug/offline/_gen_decal_maps.py）
② 导入   ModKit → Resource Browser → 空白处右键 → Import new asset
         （⚠️ 同名导不进，换个名；编辑器不会自动重读源文件）
③ 材质   照抄 blood_terrain_decal_3：Shader=decal · Blend=AddAlpha · 三个必需 flag ·
         ShaderFlags 那 8 个 · Factor 1 Color=255,255,255,255 · DiffuseMap=你的图
④ 实体   空实体 + MetaMesh(`decal_mesh`) → 材质选它
         Scale X/Y = 地面上的米数；Scale Z = 竖直厚度（原版 0.022）
         scale 必须写在【子节点】上（§2.4）
⑤ 调优   编辑器所见 = 游戏所见 ⇒ 不用重启，编辑器里迭代
⑥ 装机   见 §五（Publish → 改名搬进 AssetPackages → 重启游戏）
```

**想要"又压暗又发光"** ⇒ 两个实体叠两层：`Modulate`+白底图（焦痕）+ `AddAlpha`+黑底图（火光）。
**贴花受场景光照影响**；要"夜里也亮"得靠 `Emission`（VA2.x，未验）或改用粒子。

## 一、路线 A：图集路（Decal 组件 / 运行期 API）

### 1.1 五个图集组，各有一套三件套

| 值 | 组（`DecalAtlasGroup` 枚举） | 表 | 图集贴图资产 |
|---|---|---|---|
| 0 | `All`（Tableau / 角色菜单 / `mono_renderscene`） | `ModuleData/decal_textures_all.xml`（134 条） | `decal_atlas_all` |
| 1 | `Worldmap` | `..._worldmap.xml`（26 条） | `decal_atlas_worldmap` |
| 2 | `Battle` | `..._battle.xml`（39 条） | `decal_atlas_battle` |
| 3 | `Town` | `..._town.xml`（62 条） | `decal_atlas_town` |
| 4 | `Multiplayer` | `..._multiplayer.xml`（59 条） | `decal_atlas_multiplayer` |

- 五张图集都是 **8192×4096**；表里的 `atlas_pos="u,v,w,h"` 就是大图里的矩形。
- 矩形由**构建期打包器**排出（尺寸 16×16 ~ 2048×2048 都有），各组占用率 46%~71%，**都还空着**。
- 路径拼法（native 字符串）：`ModuleData/decal_textures_` + 组名。

### 1.2 谁决定一个场景用哪一组

**不是场景文件自带的**（native 里有 `decal_atlas_group` 这个串，但没有任何场景 XML 用它）。
是建 Mission 时传进去的 —— `MissionInitializerRecord.DecalAtlasGroup`（int，默认 0）：

| 场景 | 代码位置 | 值 |
|---|---|---|
| 战役大地图 | `SandBox.dll`：`Scene.CreateNewScene(false, true, (DecalAtlasGroup)1, "MapScene")` | 1 Worldmap |
| 城镇中心 / 据点 | `SandBox.dll`：`CreateSandBoxMissionInitializerRecord(..., (DecalAtlasGroup)3)` | 3 Town |
| 自定义战斗 / 战役地图上的战斗 | `MountAndBlade.dll` / `CampaignSystem.dll`：`DecalAtlasGroup = 2` | 2 Battle |
| Tableau / 角色菜单 | `Scene.CreateNewScene(..., (DecalAtlasGroup)0, "mono_renderscene")` | 0 All |

### 1.3 🔴 查找键 = **材质引用的贴图名**，不是材质名

引擎拿**材质 `tex[0]` 那张贴图的名字**去当前组的表里查 `atlas_pos`。

**证据（37/37 全中，零例外）** —— 把原版 prefab 里所有 `<decal_component material="X">` 的材质全导出来核对：

| prefab 里写的材质 | 它引用的贴图 | 注册在哪些表 |
|---|---|---|
| `blood_decal_b` | `blood_terrain_decal_9_d` | all **town** battle multiplayer |
| `decal_leaking_d` | `dirt_leaking_a_d` | all **town** battle multiplayer |
| `puddle_decal_a` | `puddles_d` | all **town** |
| `snow_foot_decal` | `decal_snow_footprint_d` | all **town** |
| `decal_city_circle_a` | `decal_map_city_circle` | all **worldmap**（它是大地图图标，正好落在 worldmap） |
| `decal_production_farm_wheat_a` | `decal_production_wheat_farm_d` | all **worldmap** |
| **`fire_damage`** | **`fire_damage`** | all multiplayer ← **没有 town** |

**材质名本身一个都不在表里**（`blood_decal_b` / `puddle_decal_a` …）⇒ 键一定是贴图名。

**反例印证**：`fire_damage` 的贴图不在 town 表 ⇒ 在城镇里召唤它就是**空白**。
（不是 shaderFlags 的锅 —— `decal_city_circle_a` 只有 3 个 flag 照样正常。）

### 1.4 为什么「不在表里 = 空白且不报错」

`gbuffer_functions.rsh` 的贴花主路径：

```hlsl
float2 tc_d = get_atlassed_decal_texture_tc(tc_init, d_atlas_uv_d, atlas_uv);
if (any(tc_d)) { decal_d = decal_atlas_texture.SampleLevel(linear_clamp_sampler, tc_d, 3); }
// 否则 decal_d 保持 0 → alpha 0 → 什么都不画
```

名字查不到 ⇒ `d_atlas_uv_d` 全零 ⇒ `tc_d` 全零 ⇒ 采样被跳过 ⇒ 不可见。
**一个自然、无声、极难排查的失败模式。**

`DecalParams` 结构体（`definitions_shader_structs.rsh:203`）把两级 UV 说死了：

```hlsl
float4 atlas_uv;      // scale_x, scale_y, offset_x, offset_y   ← 这就是 VA1
float4 d_atlas_uv_d;  // diffuse 在大图里的矩形 ← 来自表的 atlas_pos
float4 d_atlas_uv_s;
float4 d_atlas_uv_n;
```

### 1.5 `is_dynamic` 运行时无关

`decal_textures_*.xml` 每条都有 `is_dynamic`。**游戏本体和编辑器的 `TaleWorlds.Native.dll` 里都搜不到这个串**
（运行时要读的话会和 `atlas_pos` 一样留一个字符串）⇒ 它是构建期图集打包工具的记账标记，运行时无关。
实测也印证：`type_a_decal`（false）和 `blood_terrain_decal_9_d`（true）**都能出画**。

## 二、路线 B：网格路（`decal_mesh` + 任意 decal 材质）

### 2.1 `decal_mesh` 是什么

**引擎内置的一个现成立方体网格**（native 内置网格名单里和 `skybox`/`blob_shadow`/`__unit_xz_mesh__` 并列）。
导出的 obj 实证：8 个顶点在 ±1、6 个面 12 个三角形、每面完整 0..1 UV。

- **有效投影体积 = 物体空间 `[-0.5, 0.5]³`**（1×1×1 米 × 实体缩放，中心在实体原点）
- 代理网格是 `[-1,1]³` = **故意放大 2 倍**，保证斜视/斜坡也不缺角

### 2.2 投影怎么工作（**跟网格形状无关**）

`deferred_decal.rsh` 的像素阶段：

```hlsl
// 1. 用屏幕坐标读【场景深度图】
float pixel_depth = sample_texture_level(depth_texture, linear_sampler, tc.xy, 0).x;
// 2. 反算该像素上【真实表面】的世界坐标（不是网格自己的位置）
float4 pixel_pos_in_ws = float4(get_ws_position_at_gbuffer(pixel_depth, tc), 1);
float4 pixel_pos_in_os = mul(g_world_inverse, pixel_pos_in_ws);
// 3. 换到贴花物体空间，落在有效体积外直接丢弃
pixel_pos_in_os.xyz *= 2;
if (any(abs(pixel_pos_in_os.xyz) != saturate(pixel_pos_in_os.xyz))) clip(-1);
// 4. 贴图坐标 = 物体空间的 XY
float2 decal_tex_coord = pixel_pos_in_os.xy * 0.5 + 0.5;
```

人话：**画的是地面，不是网格**。每个像素去问深度图"这里真实表面在哪"，把贴图贴在**那个表面**上。
贴图沿实体**自身的 Z 轴**往下投（第 4 步只取 XY）⇒ **不需要旋转**。

> 官方编辑器文档原话："Their projection geometries are cubes and they are projected in the Z direction."

native 里有专用渲染 pass：**`Forward Decal Meshes`**（紧跟 Alpha Blended Forward Meshes）。

### 2.3 🔴 尺寸与摆位规则

| 项 | 含义 |
|---|---|
| **实体 Position** | 贴花中心。放地上就是把原点放在地面高度 |
| **Scale X/Y** | 贴花在地面上的**实际尺寸（米）** —— `3.0` ⇒ 3×3 米 |
| **Scale Z** | **竖直厚度**。原版 `props_testing.xml` 的 `_decal` 给 **0.022**（2 厘米，薄片，不糊到人/石头上）。地面起伏大就加大 |
| **rotation_euler** | 只转 Z 调朝向即可（Z 轴本来就是竖直的） |
| **VA1（`argument`）** | `1.000, 1.000, 0.000, 0.000` = 整张贴图铺满。它是**贴图内子矩形**，不是大图矩形 |
| **`factor`** | 染色 + 透明度（打包色，ARGB）。原版 `_decal` 用 `4279315788`；不透明白 = `4294967295` |

### 2.4 🔴 prefab 里 scale 必须写在**子节点**上

`GameEntity.Instantiate(scene, name, frame)` 传进去的 frame **会覆盖根节点的 transform**
（根上写 position/scale 一律无效，实测症状 = "召唤了还是原样"）。**子节点不受影响**。
范本：`Modules/Taikou/Prefabs/spell_rasengan.xml`（2026-09-27 实测记下的）。

### 2.5 实机状态（2026-09-29）

- ✅ **投影成立**：`decal_mesh` + decal 材质在城镇石砖地面上**服帖贴合地形**，无几何体、无平面
- ✅ **自绘贴图全程打通**（用户实机验通）：自己画的 PNG → 导入 → decal 材质 → `decal_mesh` →
  **出不规则、有羽化边的地面发光贴花**
- ✅ **贴图规则查明**：形状画在 **RGB**，空处填该 Blend 的**空色**（§四）
- ✅ **ModKit 所见 = 游戏所见**（用户实测）⇒ 调贴花**不用重启游戏**，编辑器里迭代
- ⚠️ **贴花受场景光照影响**（albedo 进 G-buffer 后被场景光照明）——「夜里也亮」要靠 `Emission`（未验）或粒子
- 曾经的"整块硬边矩形"已解释：那是「RGB 没有空色的贴图」，两种 Blend 都会整块染色

## 三、贴花材质怎么配

**照抄 `blood_terrain_decal_3`（Save As 改名 → 只换贴图），别从零新建。**

| 项 | 值 |
|---|---|
| **Shader** | `decal`（GUID `8490623a-1a2b-4f08-9864-de052ab207c2`） |
| **Material Flags** | `no_depth_test` · `no_modify_depth_buffer` · `cull_front_faces` · `dont_optimize_mesh` |
| **Blend** | `modulate` |
| **Alpha Test** | `0` |
| **Shader Flags** | `use_albedo`（必须）· `render_on_terrain` · `render_on_objects` · `render_on_grass` · `use_normalmap` · `use_specular` · `use_ambient_occlusion` · `hardlight_blend` |
| **Factor 1 Color** | `255, 255, 255, 255`（黑的话会一片黑） |

## 四、🔴 贴花贴图怎么画（2026-09-29 用户实测确认的标准）

> **规则（一句话）**：**alpha 空的地方，RGB 也必须是「空色」** —— 否则整个足迹都会被染色。
> **「空色」随 Blend Mode 而变**：`AddAlpha` → **纯黑**；`Modulate` → **纯白**。

| Blend | 公式 | 空色（画成它 = 什么都不发生） | 显形的是 | 只能做 |
|---|---|---|---|---|
| **`AddAlpha`** | 地面 **+** 贴图 RGB × alpha | **纯黑 (0,0,0)** | 比黑亮的 | **提亮**（加法） |
| `Modulate` | 地面 **×** 贴图 RGB | **纯白 (255,255,255)** | 比白暗的 | **压暗**（乘法） |

**贴图结构**（按你要的效果二选一，形状与羽化全部画在 **RGB** 里，羽化 = RGB 渐变到空色）：

| 效果 | Blend | 贴图怎么写 |
|---|---|---|
| **火焰 / 余烬 / 法阵**（在地面上发光） | `AddAlpha` | RGB = **形状本身（亮色）+ 纯黑底**；alpha = 形状 |
| **焦土 / 泥污 / 阴影**（压暗地面） | `Modulate` | RGB = **形状本身（暗色）+ 纯白底**；alpha = 形状 |

### 4.0 实测记录（这几条都是花钱买来的）

| 做法 | 结果 |
|---|---|
| 品红铺满 + 二值 alpha，配 `Modulate` | **整块饱和品红**（形状完全没体现） |
| 同一张，配 `AddAlpha` | **整块淡品红**（Factor Colors 全白也这样） |
| ⇒ 结论 | **两种模式下，贴图 alpha 都对形状不起作用**；形状只能画在 RGB 里 |
| RGB = 形状 + **黑底**、alpha = 形状，配 `AddAlpha` | ✅ **出形状的暖色发光贴花**（2026-09-29 用户实机验通） |
| 原版血材质 `blood_terrain_decal_3` 挂 `decal_mesh` | **一整片红矩形** —— 它的 RGB 全图是同一个红色，没有"空色"概念 |

- ⚠️ **贴花受场景光照影响**（albedo 进 G-buffer 后被场景光照明）—— 想要"夜里也亮"得靠
  `Emission`（Vector Argument 2 的 x 分量，**未验**），或改用**粒子**：
  原版火焰地面就是「粒子出火苗 + 贴花出焦痕」两层
- ⚠️ 贴花足迹是**整个方块**（±0.5 × scale），形状要留在贴图内圈；顶到边缘会被 `clip` 切出硬边
- 想要**真·alpha 抠图**的贴花 ⇒ 只能用**路线 A**（那里 alpha 门控形状），代价是**只能用图集里注册过的贴图**

**规格**：`RGBA` · 只写 `IHDR/IDAT/IEND`（不带 `sRGB/gAMA/cHRM/eXIf/pHYs` 附加块）· 尺寸 1024² 实测可用 ·
**空处必须填对空色**（别留灰色或别的颜色）。
生成器：`Debug/offline/_gen_decal_maps.py`（四种结构一起出 + 剥块 + 回读校验）。

### 4.1 ⚠️ 工具坑：`png_for_editor.py` 会**丢掉 alpha**

[`tools/face-pipeline/scripts/png_for_editor.py`](../tools/face-pipeline/scripts/png_for_editor.py)
是给**不透明贴图**写的，第 15 行注释明写「8bit RGB（丢掉 alpha）」。`AddAlpha` 型贴花靠 alpha 吃饭，
过它 = 形状信息被删（`Modulate` 型不受影响，因为它本来就不看 alpha）。

它要解决的坑是真的（Blender 的 PNG 带 `sRGB/gAMA/cHRM/eXIf/pHYs` 附加块 → 编辑器连源图带产物一起删），
**但该丢的是附加块，不是 alpha**。需要的是「保留 alpha、同样只写 IHDR/IDAT/IEND」。
现成范本：`Debug/offline/_gen_decal_maps.py`（两种贴图一起出 + 剥块 + 回读校验）。

### 4.1b ⚠️ 用 Pillow 缩放带 alpha 的 PNG 会把**透明区的 RGB 抹成黑色**

2026-09-29 实测（Pillow 12.3.0）：

```
原图角落:                RGB=(255,255,255)  A=0    ✓
LANCZOS/BILINEAR/BICUBIC 缩放后: RGB=(0,0,0)      A=0    ✗ RGB 被清零
NEAREST 缩放后:          RGB=(255,255,255)        A=0    ✓
```

**为什么这是坑**：`Modulate` 用的是 **RGB**，透明区的 RGB 一旦变黑 ⇒ 乘 0 ⇒ **整块足迹被压成纯黑方块**
（就是本项目反复撞的那个"矩形"症状）。**做预览图、缩图、拼图时都会中招。**

**规避**：① 要缩放就先把 alpha 合成了再缩（无 alpha 的图不会被清）② 或用 `Image.NEAREST`
③ 或者干脆别缩，用全尺寸。**生成产物本身不受影响** —— 只要别让 Pillow 去 resize 它。

**判据**：读回 PNG 的四角，`RGB` 必须是该模式的**无痕色**（Modulate=255 / AddAlpha=0）。

### 4.2 粒子贴图不能复用来做贴花

粒子那套（`lwn_yinmo_*`、`lwn_prt_*`）是给 `particle_shading` 加法发光做的，天生「RGB 暗、无 alpha」——
直接拿来配 `Modulate` 就是整块压黑，配 `AddAlpha` 只剩亮点。**必须按 §四 的规则重画。**

## 五、装包与进游戏（内容包流程）

### 5.1 三段链路

```
编辑器 Publish  →  Modules/Publish/<模块>/AssetPackages/pack0.tpac
                →  改名拷进  Modules/Taikou/AssetPackages/lwn_taikou_anim.tpac（先备份旧的）
                →  重启游戏
```

🔴 **别把 Publish 目标直接指到 `Taikou\AssetPackages`** —— 那个目录会被 Publish 清空。
🔴 **每次改完都要重搬**，否则游戏读的还是旧的。

**搬运前先核对新包是旧包的超集**（`tpaccli list` 两个包对比资产名，缺失必须为 0）。范本：2026-09-29 那次新包 94 项 / 旧包 93 项 / 缺失 0。

### 5.2 🔴 陷阱：`Assets/` 会把 `AssetPackages/` 整个遮蔽

引擎在模块目录下找资产目录，按**有序清单取第一个存在的**：
`Assets` → `AssetPackages` → `DsAssetPackages` → `EmAssetPackages` → `AssetsBackups` → `AssetSources`。

- 编辑器会重建 `Assets/`（里面是**中间产物**：贴图**只有导入设置没有像素**，`_tex.tpac` 才几百字节）
- 一旦 `Assets/` 存在，刚发布的 `AssetPackages/*.tpac` **一个字节都不会被读**
- 症状：材质读得到（`_mtl.tpac` 是完整的）、**贴图却是空的** —— 极像"材质配错"

**判据（一眼看穿）**：引擎日志里该模块那行 ——
`Loading packages $BASE/Modules/<模块>/AssetPackages...` ✅ 应为这个；
写着 `.../Assets...` ❌ 就是踩了。

**修法**：跑该模块的 `to_game_mode.bat`（`Assets` → `Assets_disabled`）。要回编辑器跑 `to_editor_mode.bat`。
⚠️ ModKit 会重建 `Assets/` ⇒ **此坑会复发**。

### 5.3 prefab 放哪 + 怎么召唤

- prefab XML 放 **`Modules/<模块>/Prefabs/*.xml`**（引擎自动扫描，不需要登记）
- **必须放在游戏 `_MODULES_` 启动列表里的模块**（用 `Taikou`，不是 `TaikouAnim`）
- 召唤：`custom.spawn_prefab <prefab名> [距离米]` —— 放在玩家脚下、面前 N 米
- 🔴 **`custom.decal` 验不了路线 B**：它走 `Decal.CreateDecal()` + `AddDecalInstance` = 路线 A（图集），
  用它验自绘贴图**必然空白**，会让你误判

## 六、常见误判（都踩过）

| 症状 | 真因 |
|---|---|
| 贴花建得出来、不报错、画面空白 | 路线 A：贴图名不在**当前场景组**的表里（§1.4） |
| 用 `custom.decal` 验自绘贴图 → 空白 | 那是图集路，本来就不支持自绘贴图（§5.3） |
| 材质能加载、贴图却是空的 | `Assets/` 遮蔽了 `AssetPackages/`（§5.2） |
| 贴花是一整块硬边方块 | 贴图**没有 alpha 通道**（§四） |
| 实机里看到一个大立方体 | 材质**不是 decal shader**（标准物件 shader 会把 `decal_mesh` 当普通网格画） |
| 召唤了 prefab 但位置/尺寸没生效 | 写在**根节点** transform 上了（§2.4） |
| `Prefab 'X' not found` | prefab 所在模块**不在** `_MODULES_` 启动列表里（§5.3） |
| 编辑器 Material Editor 预览里是「棋盘格 + 黑方块」 | decal shader 要场景深度图 + 专用 pass，材质预览球两样都没有 —— **不以它为判据** |

## 七、已验 / 未验

**✅ 已验（2026-09-29，含实机闭环）**
- 路线 A 的映射规律与失败模式（37/37 中靶 + `fire_damage` 反例）
- 路线 B **能投影到地形**（城镇石砖地面实机，服帖贴合，无几何体、无平面）
- 🔴 **路线 B 全链路打通（实机验证通过）**：自己画的 PNG → 导入 → decal 材质 → `decal_mesh` →
  **不规则、羽化边、位置正确的暖色发光贴花**
- **贴图规则**：形状画在 **RGB**；alpha 空的地方 RGB 必须是**该 Blend 的空色**
  （`AddAlpha`→纯黑 / `Modulate`→纯白）。**两种模式下贴图 alpha 对形状都不起作用**（品红判定图实测）
- 贴图经 Import → Publish → 装包后 **alpha 与 RGB 都存活**（导出比对：分布一致，像素平均差 0.93 = DXT5 压缩噪声）
- **ModKit 所见 = 游戏所见** ⇒ 调贴花不用重启，编辑器里迭代
- `is_dynamic` 运行时无关
- 装包链路：Publish → 改名搬进 `Taikou/AssetPackages` → 重启，实机可见

**⬜ 未验**
- `Emission`（Vector Argument 2 的 x 分量）能否让贴花"夜里也亮" —— **编辑器字段确认存在、材质里能设**，实机没试过
- `Factor` / `add_modulate_combined` 这两个 Blend 模式的行为（`factor` 可能是真 alpha 混合）
- 路线 B 能否换成自己做的网格（投影在 shader 里，理论上可以；官方指定的就是 Decal Mesh，**没理由不用内置的**）
- `Modulate` + 白底图那条（压暗型）**只有数学校验与模拟预览，没实机跑过**
- 一个场景能同时存在几张运行期贴花（怀疑有池子上限）

**❌ 已推翻（别再走回头路）**
- 「`all` 是合并进所有图集的公共底表」—— `all` 是**独立的一组**；跨组要用的贴图是**逐个重复登记**的
- 「`fire_damage` 空白是 shaderFlags 少几个 flag」—— 是**不在 town 表**
- 「贴花贴图必须是特定尺寸」—— 1024² 实测可用
- 「材质必须三张贴图齐全」—— n/s 留空照样出画
- 🔴 **「alpha 通道决定形状」**（本文档曾用一整节这么写）—— **错**。实测两种 Blend 下 alpha 都不影响形状；
  形状只能画在 RGB 里，alpha 只需"和 RGB 同步为空"
- 🔴 **「路线 B 不看 alpha 是铁证」**（本文档曾这么断言）—— 措辞过强：结论本身成立，但当时是从**单个观察**
  归纳的，且与 `deferred_decal.rsh` 里 `early_alpha_value *= diffuse_texture_color.a` 直接冲突。
  正确表述是：**shader 算了 alpha，但 `Modulate`/`AddAlpha` 这两个混合状态都不消费它**

## 八、运行期 API 速查（路线 A）

```csharp
public static Decal CreateDecal(string name = null);
public Decal CreateCopy();                     // 原版 MapScreen 是 1 Create + 4 Copy
public MatrixFrame Frame { get; set; }
public Material GetMaterial();  public void SetMaterial(Material m);
public void SetFactor1(uint packedColor);      // 染色 + 透明度
public void SetVectorArgument (float x, float y, float z, float w);   // VA1：贴图内 UV 矩形
public void SetVectorArgument2(float x, float y, float z, float w);   // VA2：Emission 等
// Scene 侧
public void AddDecalInstance(Decal decal, string decalSetID, bool deletable);
public void ClearDecals();                     // 🔴 全场清光
```

**最小序列**（逐字照抄原版 `SandBox.View` 的 `MapCursor`）：

```csharp
GameEntity entity = GameEntity.CreateEmpty(scene, true);
Decal decal = Decal.CreateDecal(null);
decal.SetMaterial(Material.GetFromResource("blood_terrain_decal_3"));   // 🔴 材质名，不带 _d
entity.AddComponent(decal);
scene.AddDecalInstance(decal, "editor_set", true);    // editor_set = 永久（寿命 999999999999）
MatrixFrame local = new MatrixFrame(Mat3.Identity, Vec3.Zero);
local.Scale(new Vec3(size, size, size));              // 尺寸在帧的缩放假上
decal.SetFrame(local);
entity.SetGlobalFrame(new MatrixFrame(Mat3.Identity, worldPos));
entity.SetVisibilityExcludeParents(true);             // 原版每次显隐都手写这句
```

**`decal_sets.xml`**（`ModuleData/`）管**寿命/池**，不是图集：
`editor_set`（永久）· `default_set`（240/60 秒）· `blood_set`（900/600，每格上限 4）· `steps_set`（40/10，上限 4）。

**手摇 UV 翻页**（贴花唯一的"动画"手段）：
`decal.SetVectorArgument(scaleX, scaleY, offsetX, offsetY)` 每帧改 —— 图集 8×8 ⇒ scale=0.125。
