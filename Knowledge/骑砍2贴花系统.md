# 骑砍2 贴花系统（Decal）—— 引擎能力与实现

> **一句话**：贴花（Decal）是引擎一等公民，能把一张图**投射到已有地形/物件表面上**（不像粒子那样堆透明面片）。
> 它**有运行期 API**（`Decal.CreateDecal` + `Scene.AddDecalInstance`），**能自发光**（`Emission`），
> **UV 由 C# 完全接管**（一个 vec4 就是图集矩形）—— 做"火焰地面 / 焦土 / 血迹 / 水洼"这类
> **大面积地面效果**，比铺粒子便宜得多。
>
> 🔴 **上手前先记住这两条**：
> ① **能做**：复制一个已知能出画的贴花材质（如 `blood_terrain_decal_3`），改贴图，其它别动 —— 运行期召唤得出贴花。
> ② ⚠️ **但"我们自己的贴图能不能出画"还没验**。领先假设：只有 `decal_textures_*.xml` 里
> `is_dynamic="true"` 的动态图集条目的贴图能渲染（§1.1）。**下手做美术之前先跑那个关键实验。**
>
> **证据来源（三层，优先级从高到低）**：
> ① 🔴 **ModKit 编辑器实拍**（2026-09-29 用户在 Material/Shader Inspector 里逐页截图）—— 材质字段与 shader 定义的**权威口径**；
> ② **反编译**（`TaleWorlds.Engine.dll` 的 `Decal` / `Scene`、`SandBox.View.dll` 的 `MapCursor`）；
> ③ **shader 源码**（`<游戏根>\Shaders\Sources\`，844 个文件）。

## 一、先认清：三套名字，别搞混

这是 2026-09-29 实测踩过的坑（我按图集条目名去查材质，全 `[missing]`，白跑两轮）。

| 名字 | 长什么样 | 谁认它 |
|---|---|---|
| **材质 / 资源名** | `blood_terrain_decal_3`（**不带后缀**） | `Material.GetFromResource(name)`；编辑器 Decal 组件的 `Resource File` 下拉 |
| **贴图名** | `blood_terrain_decal_3_d` / `_n` / `_s` | 材质里的 DiffuseMap / NormalMap / SpecularMap 槽 |
| **图集条目名** | 同上（与贴图名同字） | `Modules/Native/ModuleData/decal_textures_*.xml` 的 `name=` |

🔴 **判据**：`Material.GetFromResource("ashes_a_d")` → `null`（那是贴图/图集条目名）；
`Material.GetFromResource("blood_terrain_decal_3")` → 有效材质。

**图集表**（`Modules/Native/ModuleData/`，共 5 张）：

| 文件 | 作用 |
|---|---|
| `decal_textures_all.xml` | 🔴 **公共底表 —— 合并进所有图集**（实测：全表 70 个资源名 100% 都带 `all`） |
| `decal_textures_worldmap.xml` | 战役大地图 |
| `decal_textures_battle.xml` | 野战 / 攻城 |
| `decal_textures_town.xml` | 城镇 / 据点 |
| `decal_textures_multiplayer.xml` | 联机 |

条目形状：`<decal_texture name="blood_terrain_decal_3_d" atlas_pos="u, v, w, h" is_dynamic="false" />`
—— `atlas_pos` 是这张贴图**在共享图集大图里的矩形**；引擎据此给贴花算出 UV 矩形。

### 🔴🔴 1.1 运行期贴花能不能出画 —— 实测事实与**领先假设**

> ⚠️ **本节我犯过两次方向相反的过度结论，都记在下面当教训。**
> 读的时候只看「实测事实」表，推论一律当**待验假设**。

**实测事实（2026-09-29，用户在城镇场景逐条试出来的；材质用 tpaccli dump 反查了贴图 GUID）**：

| 材质 | Diffuse 用的是谁 | 结果 |
|---|---|---|
| `blood_terrain_decal_0` / `_9`（原版材质） | `blood_terrain_decal_9_d`（原版） | ✅ 出画 |
| `lwn_manual_blood_decal_0` = 拿 `blood_terrain_decal_3` **复制一份**、换三张贴图 | `blood_terrain_decal_9_d`（原版） | ✅ 出画 |
| `lwn_manual_blood_decal_1` = 同上，但 **Normal / Specular 槽留空** | `blood_terrain_decal_9_d`（原版） | ✅ 出画 ⇒ **n/s 槽空不空不影响渲染** |
| 同一材质，Diffuse 换成 `fire_damage` 那张 | `fire_damage`（原版） | ❌ 空白 |
| 🔴 **Diffuse 用我们自己导入的贴图**（不在任何图集里） | — | ⬜ **从未做过** |

**✅ 定案的模型（2026-09-29，三条命令 + 日志逐条对上）**：

> 🔴 **运行期贴花能不能渲染，只取决于「这张贴图有没有注册在*当前场景所属图集组*的表里」。**
> 材质完整（8 个 shaderFlags 那套）+ 贴图在该组表里 ⇒ 出画；贴图不在该组表里 ⇒ **建得出来、不报错、画面空白**。

**证据（全部同一材质 `lwn_manual_blood_decal_1`，同一次会话，日志三段完全同构）**：

| 贴图 | 注册在哪个组 | 结果 |
|---|---|---|
| `type_a_decal` | **town** ✓ | ✅ 出画 |
| `blood_terrain_decal_9_d` | **town** ✓ | ✅ 出画 |
| `fire_damage` | all + multiplayer，**没有 town** | ❌ 空白 |
| `boardgames_aserai_d` | 哪儿都没有 | ❌ 空白 |

**推论（同一条规律解释原版行为）**：`MapScreen` 运行期造的攻城器械圈用 `decal_siege_ram/ranged/tower` ——
它们正好在 `decal_textures_worldmap.xml`（大地图那一组）里 ✓。

🔴 **`is_dynamic` 与渲染无关**（`type_a_decal` 是静态条目，照样出画）。它到底管什么，未知。

🔴 **编辑器预览也受同一套限制**：`type_a_decal`（town 注册）能预览，`boardgames_aserai_d`（未注册）不能 —— 两者现象一致。

**各图集组可用的贴图（`_d` 后缀那批，含尺寸正常的图集矩形）**：

| 场景 | 表 | 现成可用的地面类贴图（举几个） |
|---|---|---|
| 城镇 / 据点 | `decal_textures_town.xml` | `ashes_a_d`（**灰烬**）· `mud_a_d`（泥）· `dirt_leaking_a_d` · `ground_straw_b_d` · `puddles_d`（水洼）· `wall_damaged_decal_a_d`（破损）· `type_a/b/c_decal` · `blood_terrain_decal_0..11_d` · `snow_a_s` |
| 野战 / 攻城 | `decal_textures_battle.xml` | 血 12 种 + 少量通用 |
| 大地图 | `decal_textures_worldmap.xml` | `decal_siege_*` · `map_track_arrow` · `gui_map_circle_atlas` · `mainmap_decal_undervillage*` |
| 全部组 | `decal_textures_all.xml` | ⚠️ **不能当"到处都能用"** —— 它是 `DecalAtlasGroup.All` 那一组，城镇场景**看不到**它（`fire_damage` 就是栽在这） |

**❌ 已证伪／被推翻的推论（都记下来，别再走回头路）**：
* ❌ 「只有 `is_dynamic="true"` 的条目能渲染」—— 被 `type_a_decal`（静态）出画推翻
* ❌ 「`all` 表是合并进所有图集的公共底表」—— 被 `fire_damage` 空白推翻
* ❌ 「材质必须三张贴图齐全」—— 被 `lwn_manual_blood_decal_1`（n/s 全空）出画推翻
* ❌ 「从图集表剥 `_d/_n/_s` 后缀能推材质名」—— 见 §1.2

**✅ 运行时能做什么（已验证）**：
* 代码里 `Material.GetFromResource(底材质).CreateCopy()` + `SetTexture(DiffuseMap, 任意贴图)` 是**成功**的
  —— 贴花照建、`liveVisible=True`，**只是不在组表里的贴图不渲染**（探针 `custom.decal tex`，日志三段同构）

**❌ 自定义美术：封死（2026-09-29 定论）**
三条路都试过，都不行：
1. mod 自带 `decal_textures.xml` 放进**编辑器沙箱** → 编辑器预览不出来（表没被读）
2. mod 自带 `decal_textures_town.xml` 放进**游戏加载的模块**（Taikou）→ 游戏里贴花建成功但**空白**
   （若是"表被读、格子被认"会看到该格子原有的图案，什么都没有 ⇒ **表根本没被引擎读**）
3. 运行时 `SetTexture` 塞指针 → 塞得进去，未注册贴图仍不渲染

⇒ **运行期贴花只能用「当前场景所属图集组」的表里注册过的贴图**，且没有已知手段注册新贴图。
做火焰地面时，**美术素材从现成清单里挑**（见上面的分组表），别指望用自己的图。

**`fire_damage` 与能出画材质的其它差异**（共用同一个 `decal` shader，差异如下，哪个是决定性的未验）：

| | `fire_damage`（空白） | `blood_terrain_decal_3`（出画） |
|---|---|---|
| shader | `8490623a-1a2b-4f08-9864-de052ab207c2` | **同一个** |
| shaderFlags | `use_albedo, render_on_terrain, render_on_objects`（3 个） | 8 个（多 `use_normalmap` `use_specular` `use_ambient_occlusion` `hardlight_blend` `render_on_grass`） |
| 贴图 | 只有 tex[0] | tex[0] / tex[2] / tex[4] |
| material flags | 多一个 `render_front_to_back` | 无 |

⚠️ 注意"n/s 槽留空不影响渲染"这条**只证明了槽可以空**，不代表 `fire_damage` 的空白与它无关 ——
`lwn_manual_blood_decal_1` 虽然槽空、但**贴图是动态条目**。

**图集表仍然有用的地方**：查 `atlas_pos`（贴图在图集大图里的矩形）、查 `is_dynamic`（见领先假设）。

⇒ **任务场景里想用现成图案**：`blood_terrain_decal_0..11` 一族（血/伤/焦痕 12 种）—— **确定能出画**。
**想用自己的火焰图**：⚠️ **还没验过**（见上面的"唯一还没做的关键实验"）。别当成已通。

### 🔴 1.2 「剥后缀推材质名」是错的（我在这栽过，记下来）

`decal_textures_*.xml` 里的是**贴图条目**，`name` 去掉 `_d/_n/_s` **不等于**存在同名材质。
2026-09-29 我拿这套机械推导出的 73 个名字当候选发出去，实测绝大部分根本不是材质
（`Material.GetFromResource` 直接返回 invalid）。

**正确姿势**：材质名以 **ModKit 里 Decal 组件 `Resource File` 下拉能选到的东西**为准，
或者直接 `tpaccli dump --filter <名>` 验证它是不是真材质；
图集表只用来查 `atlas_pos` / `is_dynamic`，**不要**拿它推材质名。

## 二、材质怎么配（编辑器实拍口径）

### 2.1 基本

| 字段 | 值 |
|---|---|
| **Shader** | `decal` |
| DiffuseMap (槽 0) | `<资源名>_d` |
| NormalMap (槽 2) | `<资源名>_n` |
| SpecularMap (槽 4) | `<资源名>_s` |
| Heightmap (槽 6) | 一般 None |
| **Transparency → Alpha Blend Mode** | `Modulate`（血贴花就是这个） |
| Alpha Test | 0.000 |
| **Others → Cull Front Faces** | ☑ **必须勾**（否则看不到） |
| **Others → Don't Modify Depth Buffer** | ☑ **必须勾**（否则深度乱） |
| Others → Areamap Amount | 0.650（实拍值） |
| Factor 1 Color / Factor 2 Color | 255,255,255,255 |
| **Texture Settings**（实拍原值，全默认） | Areamap Scale 1.000 · Specular Coef 1.000 · Gloss Coef 1.000 · Ambient Occlusion Coef 1.000 · Normal Depth 1.000 · Detail Normal Scale 1.000 · Parallax Mode `None` · Parallax Amount 0.000 · Parallax Offset 0.500 · Exposure Compensation 1.000 |
| **Vertex Layout**（实拍原值） | Bumpmap ☐ · Skinning ☐ · Skinning Precise ☐ · Double UV ☐ · PostFX ☐ —— **贴花不蒙皮、不吃 Bumpmap** |

### 2.2 Material Shader Flags（材质侧开关，实拍列表）

```
use_albedo               ← 🔴 官方文档明写「is a must」
use_normalmap
use_specular
use_parallax
use_ambient_occlusion
render_on_terrain        ← 贴在地形上
render_on_objects        ← 贴到物件上
render_on_grass          ← 贴到草上
hardlight_blend          ← 硬光混合（图集里有专门一条 blend 路径）
do_not_blend_normals
override_visibility_checks
is_road                  ← 道路样条专用（走 get_uv_for_road）
road_tile_side
```

### 2.3 Shader 侧（`decal` shader 的定义，实拍）

- **Include Files**：`standart.rsh` · `pbr_shading_functions.rsh` · `deferred_decal.rsh`
- **Custom Defines**：`USE_DECAL_RENDERING 1`
- **Vertex Shader** Output Struct = `VS_OUTPUT_DEFERRED_DECAL`，三段计算：
  `calculate_object_space_values_deferred_decal` / `calculate_world_space_values_deferred_decal` / `calculate_render_related_values_deferred_decal`
- **Pixel Shader**：Shading Struct = `pbr_shading_values`，Aux Struct = `decal_auxiliary_values`，
  函数链 = `sample_textures` → `calculate_alpha` → `calculate_normal` → `calculate_albedo` → `calculate_specularity` → `calculate_diffuse_ao_factor`
- **Shader Flags**：`require_albedo` ☑ · `require_gbuffer` ☑ · `uses_decal_rendering` ☑ · `disable_early_depth_stencil` ☑

### 2.4 🔴🔴 Vector Arguments —— 这套东西的全部旋钮都在这

| 槽 | 分量 | 名字（编辑器实拍） | 含义 |
|---|---|---|---|
| **Vector Argument 1** | x | **UV Scale X** | 图集矩形宽 |
| | y | **UV Scale Y** | 图集矩形高 |
| | z | **UV Offset X** | 图集矩形左边界 |
| | w | **UV Offset Y** | 图集矩形上边界 |
| **Vector Argument 2** | x | **Emission** | 🔴 **自发光强度**（`Emission Fade Time` 之外就靠它） |
| | y | **Emission Fade Time** | 自发光衰减 |
| | z | **Heightmap Mask Height** | 高度遮罩 |
| | w | **Reject Threshold Angle** | 🔴 **法线夹角拒绝阈值**（表面越陡越放弃贴，防抹墙） |

**源码佐证**：
- UV：`deferred_decal.rsh:52-56` 直接 `tc * VA1.xy + VA1.zw` —— **`VA1` 就是图集矩形，没有别的解释**
- 自发光：`pbr_shading_functions.rsh:282` `emission_ambient += max(0, decal_d.rgb * decal_params.emission_amount * decal_d.a)`
  → 第 406 行 `final_color.rgb += decal_emission_ambient_term` —— **叠在最终光照上，所以夜里会亮**

### 2.5 材质 flag 庙里还有（存在，但对 decal shader 是否生效**未验**）

`use_animated_texture_coord` · `use_texture_sweep` · `self_illumination` · `use_virtual_texturing` ·
`height_masked` · `do_not_use_alpha` · `use_specular_from_diffuse` · `separate_displacement_map`

⚠️ **别急着勾**：shader 源码里 `use_animated_texture_coords` 只有 `pbr_standart` / `light_emitter_sprite` /
`show_texture` / ui 那几支实现，`decal` 的 include 链（`standart.rsh` + `pbr_shading_functions.rsh` +
`deferred_decal.rsh`）**不含** `pbr_standart_vertex_functions.rsh` ⇒ 推测**对贴花无效**。
而且它和 `self_illumination` 抢**同一个 vec4**（见 `Knowledge/骑砍2网格贴图动画_引擎能力与实现.md`）。
→ 结论：**贴花的 UV 动画走 C# 每帧写 `SetVectorArgument`**，不靠材质 flag。

🔴 **顺带记一个名字陷阱**：flag 庙里那一条实测拼写是 **`use_animated_texture_coord`**（**单数**，无 s），
而 shader 源码里的宏是 `USE_ANIMATED_TEXTURE_COORDS`（复数）。用 `Material.AddMaterialShaderFlag("…")`
按名字加 flag 时**照抄庙里的拼写**，别按源码宏拼。

## 三、运行期 API（`TaleWorlds.Engine.Decal` / `Scene`）

```csharp
// 反编译 TaleWorlds.Engine.dll —— 公开成员全在这
public static Decal CreateDecal(string name = null);
public Decal CreateCopy();                     // 复制一个实例
public MatrixFrame Frame { get; set; }         // 位置 + 朝向 + 缩放
public Material GetMaterial();  public void SetMaterial(Material m);
public void SetFactor1(uint packedColor);      // 染色 + 透明度
public void SetFactor1Linear(uint linearColor);
public uint GetFactor1();
public void SetVectorArgument (float x, float y, float z, float w);   // ← VA1：UV 矩形
public void SetVectorArgument2(float x, float y, float z, float w);   // ← VA2：Emission 等

// Scene 侧
public void AddDecalInstance(Decal decal, string decalSetID, bool deletable);
public void ClearDecals();                     // 🔴 全场清光（血渍也一起没），不是"删这一张"
```

### 3.1 最小可用序列（逐字照抄原版 `SandBox.View` 的 `MapCursor`）

```csharp
Scene scene = /* Mission.Current.Scene 或 (Campaign.Current.MapSceneWrapper as SandBox.MapScene).Scene */;
Material mat = Material.GetFromResource("blood_terrain_decal_3");   // 🔴 材质名，不带 _d

GameEntity entity = GameEntity.CreateEmpty(scene, true);
entity.Name = "myDecal";
Decal decal = Decal.CreateDecal(null);
decal.SetMaterial(mat);
entity.AddComponent(decal);
scene.AddDecalInstance(decal, "editor_set", true);                  // 原版固定用 "editor_set"

MatrixFrame local = new MatrixFrame(Mat3.Identity, Vec3.Zero);
local.Scale(new Vec3(size, size, size));                            // 尺寸在帧的缩放假上
decal.SetFrame(local);
entity.SetGlobalFrame(new MatrixFrame(Mat3.Identity, worldPos));    // 位置在实体全局帧上

entity.SetVisibilityExcludeParents(true);                           // 🔴 原版每次显隐都手写这句，别赌默认值
```

**多张怎么办**：原版 `MapScreen` 是 **CreateDecal 一张 + 其余全部 `CreateCopy()`**
（目标圈大小两档、部队轮廓、据点轮廓、城镇标记 = 1 Create + 4 Copy）—— 照抄它。

### 3.2 手摇 UV 翻页（贴花的"动画"只有这一条路）

```csharp
// 每帧：VA1 = (scaleX, scaleY, offsetX, offsetY)。图集 8×8 ⇒ scale=0.125，offset=(col*0.125, row*0.125)
decal.SetVectorArgument(0.125f, 0.125f, col * 0.125f, row * 0.125f);
```
原版大地图光标就是每帧改 `VA1` 在 6 格图集里跳（`_mapCursorDecal.SetVectorArgument(0.166f, 1f, 0.166f * 帧号, 0f)`）。

### 3.3 自发光

```csharp
decal.SetVectorArgument2(emission, fadeTime, heightMask, rejectAngleDeg);   // VA2.x = Emission
```
🔴 **待实测**：编辑器里这个字段确实叫 `Emission`，但 C# 侧 `SetVectorArgument2` 到 `DecalParams.emission_amount`
的映射**还没实机验过** —— 这是"贴花夜里有不有火光的"关键，验法见 §六。

## 四、两条落地路线

| | **A. 场景实体（编辑器/prefab）** | **B. 运行期 API** |
|---|---|---|
| 怎么放 | 场景/prefab 里放一个空实体 → 加 **Decal 组件** → `Resource File` 选材质 | `Decal.CreateDecal()` + `Scene.AddDecalInstance()` |
| XML 写法 | `<decal_component material="fire_damage"/>` | 代码 |
| 原版用量 | **1500+ 处**（Native 65 / SandBox 189 / Shokuho 160 / YiGu 1054 / StoryMode 5） | 只有 `SandBox.View` 一处（**全是战役大地图**） |
| 脚本控制 | `TaleWorlds.MountAndBlade.ScenePropDecal`（`ScriptComponentBehavior`）：给实体设 Diffuse/Normal/Specular/Mask 四张图 + `TilingSize` / `TilingOffset` / `TextureSweepX/Y` / `UseBaseNormals`，自己 `Material.GetFromResource(MaterialName).CreateCopy()` 建材质 | 完全手写 |
| 适用 | 固定的、随场景走的焦土/血迹/水洼 | 动态生成、要跟着游戏状态变的（燃烧范围、法术残留） |

✅ **路线 B 在任务场景能渲染 —— 已实机验证**（2026-09-29：`blood_terrain_decal_9` / `_0` 在城镇场景里出画）。
前提是材质对应**动态图集条目**，见 §1.1；静态材质建得出来但画面上什么都没有，且不报错。

## 七、做一张自己的火焰贴花（配方 —— ⚠️ 前两步已验证，**第三步"自己的贴图"未验**）

> 2026-09-29 状态：材质复制路线跑通了（`lwn_manual_blood_decal_0` 出画），
> **但那些材质用的都是原版贴图** —— "我们自己的贴图能不能出画"**还没验**（§1.1）。别把已验的部分当全部。

1. **画贴图**：Diffuse（`_d`）+ Normal（`_n`）+ Specular（`_s`）。
   要做翻页动画就画 N×M 格的图集（每格一帧火），动画靠 C# 改 `VA1` 走格（§3.2）。
   💡 n/s 可以先不做（实测槽留空不影响渲染），第一次验证只做 Diffuse 最省事。
2. **贴图进编辑器**：按铁律 4 走 `png_for_editor.py`，用户在 ModKit 里 Import。
3. 🔴 **材质 = 复制一个已知能出画的**（**不要从零新建**）：
   在 Material Inspector 里打开 `blood_terrain_decal_3`（或 `_0`/`_9`）→ **Save As** 新名字 → 换贴图。
   **其它一律别动**：shader(`decal`) / ShaderFlags(那一套 8 个) / Others 的
   **Cull Front Faces** + **Don't Modify Depth Buffer** / Alpha Blend Mode(`Modulate`) 全都保持原样。
   > 为什么别从零建：从零建容易漏 flag 或少贴图槽，做出来就是 `fire_damage` 那种**空白且不报错**的坑（§1.1）。
4. 🔴 **先验"自己的贴图能不能出画"再往下做** —— 拿 §1.1 那个关键实验的结论决定路线：
   出画 → 继续；空白 → 必须先解决"贴图进动态图集"，否则后面全是白工。
5. **Publish 到内容包**：参考 `Knowledge/资产中转沙箱模块工作流.md`
   （Taikou 打不开编辑器 → 用 `TaikouAnim` 沙箱编译 → 产物**改名**拷进 `Taikou/AssetPackages`，
   别覆盖内容包自有的 `pack0.tpac`）。判据 = 装进包里 + `tpaccli list --filter <材质名>` 能查到。
6. **进游戏**：`custom.decal <你的材质名>` → 出画即通。
   之后：每帧改 `VA1` 翻页（§3.2）· `VA2.x` 给自发光（§3.3）· `SetFactor1` 染色/淡入淡出。
7. **配合粒子**：贴花只出"地面那层"，火苗另说 —— 原版就是 `粒子 + 贴花` 两层（§五）。

## 八、与既有轮子的关系

- **网格贴图动画**（`Knowledge/骑砍2网格贴图动画_引擎能力与实现.md`）：那是 `pbr_standart` 网格的两条路（翻页/漂移），**贴花吃不到**（include 链不含）。
  贴花的动画**只有 C# 手摇 VA1** 这一条。两者共用一个坑：`use_animated_texture_coords` / `use_texture_sweep` / `self_illumination` **抢同一个 vec4**。
- **粒子系统**（`Knowledge/骑砍2粒子系统.md`）：粒子的 `decal_material` 字段能让**粒子碰撞时生成贴花**（`create_decal_on_collision` + `decal_min/max_scale` + `permanent_collision_decals`）——
  这条是"被动盖贴花"，不用自己写 API，原版的 `fire_damage` 就是这么用的。
- **资产导入**（铁律 36）：自己画的贴图/材质属**新资产**，必须走 `AssetSources/ImortReady/<名>/` 交用户 Import，Claude 不碰 `Assets/`。
