## 2. 为什么必须走「新 race」

骑砍2 的头网格**不由角色决定，由皮肤（skin）决定**，而 skin 是按 **(race × 性别 × 年龄段)** 三选一的。
全游戏只有一个 `race="human"`，所以**任何"给某个角色换头"都绕不开"给他一个独有 race"**。

| 件 | 作用 | 本工程的值 |
|---|---|---|
| `skins.xml` 的 `<race id="X">` | 皮肤矩阵：里面指定 `face_meta_mesh`（头网格）、`face_textures`（脸池贴图）等 | `lwn_nobunaga` |
| `monsters.xml` 的 `<Monster id="X">` | 物理/骨骼/胶囊（id 必须与 race 同名） | `lwn_nobunaga`（human 的整块副本） |
| NPCCharacter 的 `race="X"` | 把角色挂到该 race 上 | **只有 `lord_tk5_195` 有** |

**别人不受影响的原因**：除信长外没有任何 NPCCharacter 带 `race=` 属性 → 全部继续走 Native 的 `race="human"`。

## 4. 第一步验收（用户做，2 分钟）

1. 开 Taikou 战役（1560 / 1554 / 1568 / 1575 / 1582 都行，**1598 没有信长**）。
2. 找到织田信长（清洲城 / 岐阜城 / 安土城，看年代）。
3. **预期：信长同时出现两个变化**（都是故意留的标记，不是 bug）：

| 标记 | 字段 | 预期表现 | 说明 |
|---|---|---|---|
| ① 变高 | `min_scale` 1.07 → **1.35** | 信长**明显比周围人高一截** | 最直观 |
| ② 换脸 | `face_textures` 4 条全指 **`head_male_d`**（原版是 a/b/c/d 四种脸池） | 信长的**五官比例/肤色与以前不同**了 | 这是换头机制真正消费的字段，比身高更能证明"皮肤换成功" |

**判读**：
- 两个标记都出现 = **race 生效、机制全通** → 直接进第二步。
- 只有变化①或只有②= 部分字段没吃到，要查；
- **完全没变、游戏也没崩** = race 静默回落（`skins.xml` 没被加载），先查 §6 那行；
- 崩了 = **先看崩在哪**：若是**进据点领主大厅刷信长时** NRE（栈顶 `Mission.SpawnAgent`）→ 是 **Monster 后缀变体族缺失**，见 §5 末两行（2026-09-14 实机就是这个，**不是** `soln_skins` 的锅）；若是**启动/加载期**就崩 → 才轮到 §6 回退。
- **其他人（随便找个别的领主看）必须和以前一模一样** —— 这是"隔离成功"的判据。

## 5. 查证过的事实（都是实证，下个 session 别再摸一遍）

| 事实 | 证据 |
|---|---|
| **race 机制**：新 race 要在 `skins.xml` 和 `monsters.xml` 里各定义一份同名节点，NPCCharacter 上写 `race="X"` | 社区文档 `Knowledge/bannerlordmodding_lt/modding/races.md`；织丰的 `euro_monsters.xml` 写了 `<Monster id="european">`，其火枪兵带 `race="european"` |
| ⚠️ **织丰的 `euro_skins.xml` 是死数据** | 织丰 `skins.xml` 里 `grep european` = 0 条，且 SubModule 里**没有**注册 `Skins`，`euro_skins.xml` 也没被任何地方引用 → **不能拿它当"添加 race 已验证"的先例**，本工程是第一次真正落地 |
| **`skins.xml` 靠 `project.mbproj` 的 `type="skin"` 行加载**，不是靠 SubModule 的 XmlNode | Native 自己就是 `<file id="soln_skins" name="ModuleData/skins.xml" type="skin"/>`；TifaHead2 / xxFemaleHead 两个能用的换头 mod 也都是这一行 |
| **没有 `id="Skins"` 的 XmlNode** ——全装模块搜遍无人注册 | 所以 skins 走的是 soln 体系（`project.mbproj`），跟 `Monsters`/`NPCCharacters` 那套 XmlNode 体系**不是一回事** |
| **soln 合并是"追加"不是"覆盖"** | 织丰的 `skins.xslt` 第一件事是 `<xsl:template match="race"/>`（把合并结果里所有 race 删光）再靠自己的 `skins.xml` 重新给 —— 说明合并会**留下**别家的 race，不删就重复 |
| **男头规格 = 3 件（脸/眼/嘴），没有睫毛件** | 原版 `head_male_a` 的 mat_map：`.1`=eye_mat、`.2`=mouth_mat；唯一在售的自定义男头织丰 `sho_head_male_japanese` 也是 3 件 |
| **男 skin 的 `deform_keys` 与女头逐位相同** | 蒂法工程 §21.2：62 条 key_time_point 序列完全一致 → 我们的 FBX 给 `KeyTime_1..59` 直接对齐，**不用改 deform_keys** |
| **男头标定常量** | `TARGET_EYE = (0, 0.1280, 1.6839)`、眼↔嘴竖直距离 `0.0795`、落位验收 `x±0.093 y[-0.071,0.172] z[1.414,1.811]`（已固化进 `build_head.py --gender male`） |
| 🔴🔴 **Monster 必须整族复刻，不能只造基础 id**（2026-09-14 实机崩出来的） | 引擎取 Monster 不止一种问法：除 `Core.AgentData` 构造函数里的 `FaceGen.GetBaseMonsterFromRace(race)`，**据点场景一律按后缀取变体** `FaceGen.GetMonsterWithSuffix(race, "_settlement")`（`LocationCharacter`、`LocationComplex.AddHeroToDecidedLocation`、`Hero` 多处）。Native 给 `human` 定义了**一族 5 个** id：`human` / `human_child` / `human_settlement` / `human_settlement_fast` / `human_settlement_slow`。**后缀用量实测**（1.2.12 全 DLL 反编译计数）：`_settlement` 46 处 · `_child` 12 · `_settlement_slow` 5 · `_settlement_fast` 1 |
| 🔴 **缺变体的崩法：`Mission.SpawnAgent` NRE，且栈里没有下层帧** | 只造 `lwn_nobunaga` 时，要 `lwn_nobunaga_settlement` 取到 **null**（**这条链上无兜底**——`GetBaseMonsterFromRace` 只在 race 本身不存在时回落 human，**变体缺失不回落**）→ `AgentData.AgentMonster = null` → `Mission.SpawnAgent`（`Mission.cs` 第 3860 行）里 `agentBuildData.AgentMonster.Weight` 抛 `NullReferenceException`；C# 从左到右求值，所以 `CreateAgent` 还没进去就在 SpawnAgent 自己体内炸 = **栈顶就是 SpawnAgent、无下层帧**。触发路径天经地义躲不掉：`AddHeroToDecidedLocation` 判 `Occupation == Lord → LordsHall`，紧接着就是 `_settlement` —— 信长是 Lord，**进领主大厅必崩** |

## 6. 唯一有风险的改动：`project.mbproj`（必读）

Taikou 的 `project.mbproj` 在 **2026-09-08 被清空过**：当时 `action_sets.xml` 是 Native 的**逐字拷贝**，
同 soln id 合并出重复定义 → `KeyNotFoundException`（`CreateProcessedActionSetsXMLForNative`，实崩）。
它自己的注释写着「将来需启用某行：先独立实机验证（启用一个为一个）」。

**本次启用的是 `soln_skins`，不重演那次崩**：我们的 `skins.xml` 里**只多一个 `<race id="lwn_nobunaga">`**，
id 与 Native 的 `human` 不同 → 合并是纯追加、不冲突。

**回退**：删掉 `project.mbproj` 里 `soln_skins` 那一行即可（其余改动是纯数据，留删都行）。

> ✅ **2026-09-14 更新：这一行不是那次崩溃的原因。** 首次实机验证的崩是「进据点领主大厅刷信长 → `Mission.SpawnAgent` NRE」，根因是 **Monster 后缀变体族缺失**（§5 末两行），与 soln_skins / race 加载无关——`skins.xml` 其实**正常加载了**（race 生效的证据）。**别一崩就删这行**：先按 §4 的判读分「加载期崩」还是「进场景刷人时崩」。

### 7.3 🔴 编辑器步骤（人做，照 `蒂法换头工程.md` §19.4）

1. 打开 ModKit 编辑器（`bin\Win64_Shipping_wEditor\...Launcher.exe` → SinglePlayer Play → 主菜单 `Ctrl+E`），打开 **Taikou** 工程。
2. 导入 `AssetSources\head_nobunaga_a_ch.fbx`，设置：**Convert to unit = m** ／ **Blend shape import = as_vertex_anim** ／ **不勾 Convert to Z-up** ／ **只勾 Import meshes**。
3. 材质三件套按名字接槽：脸 `head_nobunaga_a`（d/n/s）、眼 `head_nobunaga_a_eye`（`_eye_d`）、嘴 `head_nobunaga_a_mouth`（`_mouth_d`）；Shader 照抄 xxFemale 配方，**Vertex Layout 必须含 skinning**。
4. **Publish —— 目标目录选到模块外面**（`AssetPackages\` 是 Publish 的清空目标，Taikou 里已经有 4 个立绘 tpac，别让它清掉）。
5. 把编译出的 `pack0.tpac`（或含网格的那个包）拷进 `Taikou\AssetPackages\`，然后跑
   `python tools\face-pipeline\scripts\install_pack.py --packdir <模块>\AssetPackages --filter head_nobunaga_a …`（两道补丁 `morphfix` + `skinfix --fullmat`，**漏了 = 白编译**）。

### 7.5 已知风险 / 待实机确认

| 风险 | 说明 |
|---|---|
| **嘴件贴图** | 皮肤会把 `mouth_textures`（原版嘴唇材质）盖到嘴子网格上，用我们的 UV 可能错位。蒂法那边"不动 mouth_textures"且实机通过 → 可能不吃亏；不行就在我们 race 的皮肤里覆盖 `mouth_textures` |
| **头偏大** | 含头发后 `x±0.132 z→1.950`（原版男头 `x±0.093 z→1.811`）；差的就是头发。实机看比例再定要不要缩 |
| **分辨率** | 源图集只有 512×1024，脸区域约 120×150 px → 放大后偏糊。要更清楚只能上 AI 超分（Real-ESRGAN） |

### 7.6 两个可直接复用的坑（本工程实测）

1. **FBX 导入 Blender 后所有形状键默认值 = 1.0** → 直接渲染会得到"拉长的怪物"，看着像几何坏了。预览前必须把 61 个键全部归零。
2. **Blender 5.2 的渲染引擎标识符是 `BLENDER_EEVEE`**（4.x 是 `BLENDER_EEVEE_NEXT`）；写错会**静默回落**到 `BLENDER_WORKBENCH`，而 WORKBENCH 不吃材质 → 渲染出灰模，看着像"贴图丢了"。
