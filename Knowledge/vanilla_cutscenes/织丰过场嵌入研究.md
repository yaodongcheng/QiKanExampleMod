# 织丰 Cutscene 嵌入研究（2026-08-30）

> **结论**：织丰的过场 = **原生 SceneNotification 制式**（没有自建 UI 系统）。
> 复用织丰过场 = 复用它的**场景资源 + 事件类 + 通知触发**。新剧情过场的最小投入 = 写一个继承类换文字，几十行搞定。
> **最终裁定**：不建独立 UI 过场系统，采用织丰嵌入方案（2026-08-30 用户确认）。

## 一、织丰过场的三件套（逐一拆解）

### 1. 事件类（Shokuho.dll，全部 internal）

| 类 | SceneID | 文字 | 旗帜 / 角色 |
|---|---|---|---|
| `MarchOnKyotoSceneNotificationItem` | `scn_cutscene_test`（**织丰自编场景**） | `{=58dSykhX}` 上洛宣言 | 织田王国 banner + 2 个随机兵种（去武器） |
| `FallOfTripleAllianceSceneNotificationItem` | `scn_cutscene_enemykingdom_destroyed`（**复用原生场景**） | `{=fwFVIKuz}` 三同盟破裂 | 武田 banner + 2 随机兵种 |
| `RebellionStartedSceneNotification` | 待查（继承原生同盟类） | 叛变事件 | 双王国 banner（父国+叛国） |
| `ANewShogunateSceneNotificationItem` / `EndofHonjoRebellionSceneNotificationItem` | 继承原生同盟类 | 幕府成立 / 北条之乱 | — |

套路统一：继承 `SceneNotificationData` → override `SceneID` / `TitleText` / `GetBanners()` / `GetSceneNotificationCharacters()`。**文字全部用 `TextObject("{=KEY}...")` 标准本地化**（与项目铁律 13 同机制）。

### 2. 场景资源（Modules/Shokuho/SceneObj/）

- `scn_cutscene_test/` = 织丰自编场景：`scene.xscene`（编辑器文件）+ `atmosphere.xml` + `flora.bin` / `terrain.bin` + `ShaderCache` + `references.txt`。
  **截图里的 2D 战画 = 场景内布景 Mesh + 贴图**（"自定义图片"的唯一原生途径），相机 = 场景内 `PopupSceneCameraPath` 脚本，角色位 = `spawnpoint_player_N` tag。
- 织丰整个 `SceneObj/` 拷贝了全套原生 `scn_*`（婚礼/加冕/出生/死亡/处决等 25+）——**场景文件可自由拷贝进自己模块改造**，这是官方自由度。
- `Prefabs/sho_cutscene.xml` ⚠️ 不是 UI 过场——只是场景物件 prefab（天守阁等建筑组件），**织丰没有独立 UI 层过场**。

### 3. 触发方式（大地图通知条）

`MarchOnKyotoVM : MapNotificationItemBaseVM`（`NotificationIdentifier="kingdomdestroyed"`）：
`_onInspect = delegate { MBInformationManager.ShowSceneNotification(new MarchOnKyotoSceneNotificationItem()); ExecuteRemove(); }`

即：剧情事件 → 挂一条大地图通知 → 玩家点通知条 → 过场播放 + 通知移除。

## 二、复用姿势（新剧情事件三选一）

| 方式 | 代码 | 适用 |
|---|---|---|
| **继承织丰已有类**（推荐） | `class MyItem : MarchOnKyotoSceneNotificationItem { override TitleText => ... }` | 场景/角色/旗帜全继承，只换文字 |
| 仿写新类引用织丰场景 | `class MyItem : SceneNotificationData { SceneID = "scn_cutscene_test"; ... }` | 想换角色/旗帜布局 |
| 自编新场景 | 场景编辑器制作 `scn_xxx` 布景 | 需要新画面图（美术工程） |

触发：剧本引擎直接 `MBInformationManager.ShowSceneNotification(new MyItem())`（公共 API，无需依赖织丰内部）。

## 三、BGM 的事实与坑

- **织丰所有过场均未配 BGM**（日志 `sound=(none)`）——它们是静音过场。
- 剧本引擎已有 BGM 命令 `ChangeBgm`（`Story/SystemCommands.cs`）：`SoundEvent.GetEventIdFromString` + `SoundEvent.CreateEvent(soundIndex, Mission.Current.Scene)` + `Play/Stop`，维持 `StoryEngine.currentBgm`。
- 🔴 **坑（未实测）**：`CreateEvent` 的 scene 参数来自 `Mission.Current.Scene`——**大地图（campaign）无 Mission，直调会崩**。campaign 环境应改用 `SoundEvent.CreateEvent(id, null)`（2D 音乐无需场景）或 `SoundEvent.PlaySound2D(name)`（TaleWorlds.Engine.dll 1.5.2 均有此 API），需实测确认 null scene 合法。

## 四、日志观测（本次实机证据）

`Debug/SceneNotificationLoggerPatch.cs`（本 mod，2026-08-30 落位）在 `StoryEngine_RuntimeLog.txt` 打两个标签：
`[SceneNotification:REQUEST]`（请求入口）→ `[SceneNotification:PLAY]`（真正开播）。
实机记录织丰上洛过场（14:52:30.758/.767，9ms 差）：
`type=MarchOnKyotoSceneNotificationItem scene=scn_cutscene_test context=Any pause=True affirmBtn=hidden negBtn=hidden chars=2 banners=1`。
**REQUEST+PLAY 成对 = 完整播放**；有 REQUEST 无 PLAY = 被门控/排队。

## 五、边界（铁律 3）

LivingWorldNpcs（通用 mod）**禁止引用 Shokuho.dll / 出现织丰字串**。复用链必须落在**织丰剧本层**（Shokuho.dll 侧或剧本工程），LivingWorldNpcs 只提供 `ShowSceneNotification` 等公共 API 调用。
