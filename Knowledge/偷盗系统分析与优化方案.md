# 偷盗系统分析与优化方案

> 对标上古卷轴5、神界原罪2、大侠立志传，分析当前偷盗系统的完整度与乐趣差距，提出上线品质优化路线。

---

## 一、系统全景

### 当前已具备的链路

```
触发（蹲下+背后）→ StealVM UI（盲盒博弈）→ 成功/被发现 → 目击者围观 → 受害者指控 → 谈判系统
```

这是一个**完整的闭环**，从触发到后果都有代码覆盖。

### 核心文件

| 文件 | 职责 |
|------|------|
| `Stealth/StealVM.cs` | 偷窃 UI 的 ViewModel，含风险计算、警惕条、盲盒逻辑 |
| `Stealth/StealManager.cs` | 核心业务：偷取、归还、赃物追踪、目击者检测、装备剥离 |
| `GUI/Prefabs/Steal.xml` | Gauntlet UI 布局（三栏：警惕条 / 盲盒区 / 日志+离开） |
| `Interaction/InteractionMissionView.cs` | 触发入口（蹲下+背后检测 → 打开 StealVM） |
| `AI/NpcSightSystem.cs` | 统一视线引擎（FOV + RayCast），供目击者检测 |
| `AI/AgentBrain.cs` | 犯罪响应行为（WitnessCrime_GatherOnLook / WitnessCrime_StayStare） |
| `AI/AgentAIController.cs` | BroadcastEventInRange 广播犯罪事件 + 触发 GroupStageManager |
| `AI/GroupStageManager.cs` | 围观站位空间分配（多层 NavMesh 站位点生成与分配） |
| `Negotiation/NegotiationSystem.cs` | 冲突解决（ResolveConflict_Apology 赔礼道歉） |

## 二、逐层分析

### 2.1 触发层

**代码位置**：[InteractionMissionView.cs:253-272](../ExampleModVS/ExampleMod/ExampleMod/Interaction/InteractionMissionView.cs#L253-L272)

```
条件：蹲下 (CrouchMode) + 在目标背后 (DotProduct < -0.3) + 距离 < 2.5m → 显示"偷窃 F"
否则 → 显示"对话 F"
```

**已做对的**：
- 蹲下 + 背后 = 符合直觉的偷窃前置条件
- 与"对话"共用 F 键，上下文切换流畅

**不足**：
- 没有环境因子（光线、时间、人群密度）。白天集市中央蹲下也能触发偷窃，违和感强。
- 没有"警觉度预览"——Skyrim 的 Sneak Eye 让玩家在动手前就知道风险等级，我们只在 UI 打开后才知道。

### 2.2 UI 博弈层

**代码位置**：[StealVM.cs](../ExampleModVS/ExampleMod/ExampleMod/Stealth/StealVM.cs) + [Steal.xml](../GUI/Prefabs/Steal.xml)

三栏布局：
- **左侧**：警惕条（0→100%，满则被抓）
- **中间**：盲盒物品区（? → 摸到后显示重量/类型）+ 两个按钮
- **右侧**：日志 + 收手离开

核心循环：
```
摸索（+10 警惕，90%摸到随机槽位）→ 看到重量/类型 → 拿走（+20 警惕）→ 重复或离开
```

**风险计算公式**（`RecalculateState`）：
```
witnessRisk = 目击者数量 × 30%
skillReduction = Roguery技能 × 0.1%

摸索风险 = clamp((当前警惕+10) × 0.4 + 5 - skillReduction + witnessRisk, 0, 100)
拿走风险 = clamp((当前警惕+20) × 0.4 + 10 + 物品重量×2 - skillReduction + witnessRisk, 0, 100)
```

**已做对的**：
- 风险数值显示在按钮上（透明信息）
- 警惕条用物理高度映射百分比（视觉直观）
- 物品重量影响风险（重的更难偷，符合直觉）
- Roguery 技能降风险（有 RPG 成长感）
- 目击者大幅增加风险（30%/人，环境感知）

**不足**：
- **盲盒剥夺决策权**：玩家不知道在冒什么风险偷什么东西。只看到"轻/中/重"和"单手武器/上身着装"，无法判断是否值得。
- **纯 d100 投骰子**：没有玩家操作影响结果的空间，完全是被动等待判定。
- **按钮文案逻辑有冗余**：`RecalculateState` 里对 `IsItemRevealed` 做了两次判断（第 114-131 行）。
- **没有"下一个物品预览"**：当前摸到不满意只能"摸下一个"，但不知道下一个是什么。

### 2.3 结算层

**代码位置**：[StealManager.cs](../ExampleModVS/ExampleMod/ExampleMod/Stealth/StealManager.cs)

**亮点（值得保留和扩展）**：

1. **`_stolenLog` (ConditionalWeakTable)** — 赃物追踪在 Mission 结束后自动 GC，无内存泄漏。
2. **`ReturnStolenItems`** — 完整的对称归还逻辑：玩家背包扣 → 复原 NPC 穿戴外观 → 还回 party 辎重。
3. **`GetStolenValue`** — 按赃物总价值计算赔偿额，不写死数值。
4. **真实扣除** — 偷取从受害者 party 辎重扣实物，不是"假偷"。
5. **装备剥离 + 视觉刷新** — 偷武器后刷新 NPC 战斗属性，偷防具后刷新外观。
6. **尸体安全处理** — `StripAgentEquipment` 对 ragdoll 尸体无条件清空武器槽，避免 AccessViolation。

**不足**：
- 偷窃成功没有 Roguery 经验值反馈。
- 没有"偷窃失败但未被发现的脱身"机制（当前失败 = 必定被抓）。

### 2.4 后果层（围观 + 指控 + 谈判）

**代码位置**：[AgentBrain.cs:160-221](../ExampleModVS/ExampleMod/ExampleMod/AI/AgentBrain.cs#L160-L221)、[AgentAIController.cs:141-260](../ExampleModVS/ExampleMod/ExampleMod/AI/AgentAIController.cs#L141-L260)

```
OnStealFailed → BroadcastEventInRange("WitnessCrime", criminal, victim)
  → GroupStageManager.PrecalculateAllocations（空间站位分配）
  → 目击者走位+围观（MoveToPositionAction + LookAtAction）
  → 受害者 ForceTalkAction → CrimeAccusation → PrepareOpeningAction
  → 进入 NegotiationSystem（ResolveConflict_Apology，severity=70）
```

**亮点**：
- **`CalculateReactionDelay`** 按身份（英雄 / 守卫 / 平民）、距离、视角计算拟人化延迟
- **`GroupStageManager`** 生成多层围观站位（环状布局、NavMesh 验证），目击者按优先级分配到不同圈层
- **`PrepareOpeningAction`** 在犯罪指控场景下预计算 LLM 开场白
- 受害者直接走 `ForceTalkAction` 发起指控，其他目击者围观+注视

**不足**：
- 后果是**本场景限定的**——目击者反应结束后没有跨场景遗留（声望、关系、悬赏）。
- SettlementHonorStore 存在但在偷窃流程中**未被修改**（只有 NPC 冒泡时读取）。
- 只有"赔礼道歉"一种解决路径，没有威胁、抵赖、逃跑等选项。
- 守卫（soldier 类型）没有特殊逮捕行为，和普通平民反应相同。

## 三、与"搜刮"的定位差异

### 3.1 当前状态

| 维度 | 偷窃（活人） | 搜刮（尸体） |
|------|------------|------------|
| 触发条件 | 蹲下+背后 | 任意（尸体状态） |
| 风险 | 警惕条+被发现+谈判 | **零风险** |
| UI | StealVM 盲盒 | InventoryManager 全览 |
| 收益可见性 | 盲盒（重量/类型提示） | **全部可见** |
| 重复性 | 可反复偷（每次风险增加） | 一次性 |
| 后果 | 围观+指控+赔钱/降声望 | 无 |
| 返还机制 | ReturnStolenItems 完整对称 | 不适用 |

### 3.2 核心问题

**搜刮体验实际上优于偷窃**——你看到全部物品后挑选，没有风险。而偷窃在看不到物品的情况下还要冒被抓的风险，这在玩家心理账本上是**负 EV（期望价值）**。

除非偷窃有独占收益（只有偷窃能拿到的特殊物品 / 情报 / 机会），否则玩家没有动机选择偷窃而非直接杀掉搜刮。骑砍2 原版也有这个问题——杀人越货零后果（只要不被看到），偷窃反而更危险。

### 3.3 目标定位

| | 搜刮（Loot） | 偷窃（Steal） |
|---|---|---|
| **核心幻想** | 战后打扫战场，收获战利品 | 神不知鬼不觉从活人身上取走宝物 |
| **风险** | 零 | 中高 |
| **收益** | 标准战利品（装备/钱） | 专属物品 + 情报 + 高价值装备 |
| **玩家技能** | 无（纯选择） | 有（Roguery + 迷你游戏 + 时机判断） |
| **时间压力** | 无 | 有（警惕条持续存在） |
| **后果** | 无 | 声望/关系/谈判/战斗 |
| **独特卖点** | 稳定、大量、安全 | 刺激、独占、高风险高回报 |

**核心设计原则**：搜刮是"收获"，偷窃是"赌博+技巧"。玩家搜刮时感到满足，偷窃时感到心跳加速。两者在情感体验上不重叠。

## 四、对标分析

### 4.1 上古卷轴5 (Skyrim)

| Skyrim 设计 | 我们当前 | 差距 |
|------------|---------|------|
| 物品全可见 + 精确% — 每个物品显示独立偷窃成功率 | 只显示重量/类型，无物品名，无独立概率 | **大** |
| Perk 树 — 额外口袋、偷装备武器、毒苹果等 | Roguery 只降风险，无玩法解锁 | **大** |
| Sneak Eye 指示器 — 实时反馈"被发现"状态 | 只在偷窃 UI 内显示目击者数量，动手前无预警 | **中** |
| 销赃网络 — 盗贼公会 | 无 | **大** |
| 悬赏系统 — 按地区累计悬赏，守卫盘查 | 只有本地目击者反应，无跨场景后果 | **大** |

### 4.2 神界原罪2 (DOS2)

| DOS2 设计 | 我们当前 | 差距 |
|----------|---------|------|
| 偷窃独立技能 + 按重量/价值上限限制（每 NPC 只能偷一次） | 可无限偷（只要不被抓） | **中** |
| 队友分散注意力 — 对话锁定 NPC 朝向，另一人偷 | 单人操作，无配合 | **中** |
| 物品全览 — 看到 NPC 全部物品栏 | 盲盒 | **大** |
| 偷完就跑 — NPC 延时发现失窃并搜查 | 被抓是即时的，无延迟发现 | **中** |

### 4.3 大侠立志传

| 大侠设计 | 我们当前 | 差距 |
|---------|---------|------|
| 迷你游戏 — 偷窃有节奏/时机要素 | 纯数值判定 | **大** |
| 好感度绑定 — 好感高可降难度或解锁特殊选项 | 无好感交互 | **中** |
| 门派/身份后果 — 偷窃影响整个门派声望 | 只有 Settlement 级 honor，且未被偷窃修改 | **中** |

## 五、优化路线图

### P0：核心乐趣 — 让偷窃"有价值且刺激"

#### A. 从盲盒到半透明 — 保留悬念但不剥夺决策权

**当前问题**：玩家不知道在冒什么风险偷什么东西。只看到"轻/中/重"和装备类型，无法做价值判断。

**方案**：摸到物品后展示分级信息：
- 装备类型 + 材质等级暗示（"粗糙的" / "精良的" / "华丽的"）
- 大致价值区间（"大约值 50-200" / "看起来非常昂贵"）
- 高风险物品有特殊标记（"这东西很显眼，拿走可能引起注意"）
- **但不直接显示物品名**——保留"这到底是什么？"的悬念，让玩家在"拿走看看"和"太危险换一个"之间做决策

#### B. 引入玩家技能要素 — 时机迷你游戏

**当前问题**：纯 d100 投骰子，玩家除了计算概率外没有任何操作空间。

**方案选项**：
- **轻量方案**：在警惕条上标记一个"安全区"（随机位置），玩家在安全区内点击"拿走"获得额外成功率加成。这个安全区随 Roguery 技能提高而变宽。
- **中等方案**：类似 KCD2 开锁的简化版——一个往复移动的游标，在绿色区域按下成功，红色区域失败。Roguery 越高绿色区域越宽。
- **不推荐复杂方案**：骑砍2 的 Gauntlet UI 对实时动画支持有限，过度复杂容易卡顿。

#### C. 偷窃专属收益

**当前问题**：偷窃和搜刮拿到的物品类型完全相同，偷窃还有风险，纯亏。

**方案**：
- 某些特殊物品**只能通过偷窃获得**（NPC 身上的独有装备 / 信物），搜刮尸体不掉落
- 偷窃成功可概率获得**情报/秘密**："你从口袋里摸出一封皱巴巴的信…"，触发隐藏任务或对话新选项
- Roguery 高等级解锁专属 Perk："顺手牵羊"（偷窃时概率额外获得一件物品）、"妙手空空"（可偷到 NPC 装备中的武器而不被立即发现）
- 偷窃过程中概率发现 NPC 的**秘密**（弱点、关系网），可用于后续谈判或敲诈

### P1：风险系统深度

#### D. 分层警惕状态（替代当前二元化）

| 警惕值区间 | 状态 | 表现 |
|-----------|------|------|
| 0-30% | 安全 | NPC 正常行为 |
| 30-60% | 不安 | 目标偶尔转头 / 调整站姿（动画），增加 5% 后续风险 |
| 60-90% | 警觉 | 目标可能突然转身触发即时检定；目击者开始注视；按钮开始微微颤抖 |
| 90-100% | 即将暴露 | 屏幕边缘泛红，心跳音效；下一次操作风险 ×1.5 |
| 100% | 被抓 | 进入谈判 / 战斗 |

在 UI 上体现为警惕条颜色渐变（绿→黄→橙→红），不只是固定红色。

#### E. 延迟发现机制（参考 DOS2）

**当前问题**：偷窃失败 = 立刻被抓，没有"偷完快跑"的逃生窗。

**方案**：
- 偷窃成功但警惕值 > 60%：NPC 在 10-30 秒后"发现失窃"→ 开始搜查附近
- 玩家有时间逃离现场（离开一定距离）
- 如果玩家还在附近被找到 → 进入指控流程（severity 比现行犯更高）
- 创造"心跳时刻"：警惕值高了，我是再偷一件还是赶紧走？

#### F. 跨场景声望与悬赏

**当前问题**：SettlementHonorStore 只被读取（NPC 冒泡概率），不被偷窃行为修改。

**方案**：
- 偷窃被抓住 → `SettlementHonorStore.Modify(settlement, -X)`（名誉下降）
- 连续偷窃未被抓 → 增加"惯偷"标签，该据点 NPC 对话中暗示警觉（"最近镇上不太平"），但不直接惩罚
- 偷窃成功不被抓积累"神偷"声望——解锁特殊 NPC 对话（"听说你很擅长'拿'东西…"）和委托任务
- 如果总是偷同一阵营的人 → 该阵营关系下降（跨场景持久）

### P2：沉浸感和制作质量

#### G. UI 打磨

- **警惕条颜色渐变**：绿(0-30)→黄(30-60)→橙(60-90)→红(90-100)，不只是固定 `#8B0000FF`
- **物品剪影**：盲盒状态不用纯"?"，而是根据摸到的重量/类型显示不同的剪影图标（武器轮廓 / 护甲轮廓 / 小物件轮廓）
- **"拿走"按钮重量感**：贵重物品按下后有短暂"犹豫"动画（0.3s delay），暗示玩家"这东西很值钱，确定要拿？"
- **环境音效**：心跳声随警惕值加速（利用 TaleWorlds 的 AudioSystem）

#### H. NPC 反应多样性

**当前状态**：目击者围观系统已经不错（GroupStageManager + 多层站位），但所有 NPC 行为相同。

**方案**：
- **正义感强的 NPC**（Honor 高）→ 主动上前制止，而不是围观
- **胆小的 NPC**（Honor 低 / 平民）→ 跑开或假装没看见
- **同伙/朋友** → 如果玩家在该据点有声望，有概率帮忙望风（降低目击者风险）
- **守卫** → 特殊逮捕流程（不同于普通围观），直接进入"罚款或坐牢"判定
- **受害者后续记忆**：偷窃成功未被抓，下次遇到时 NPC 会说"最近运气不好，老丢东西"（增加沉浸感，不影响 gameplay）

#### I. 偷窃与对话系统的联动

**当前状态**：偷窃失败只有"赔礼道歉"（ResolveConflict_Apology）一条路。

**方案**：谈判时增加多种策略选项：
- **威胁**："你敢声张我就把你贪污的证据抖出去"（需要预先获取情报）
- **抵赖**："我只是不小心碰了一下你的包裹"（Roguery 检定）
- **反咬**："你自己东西没放好，怪我？"（魅力检定）
- **逃跑**：消耗耐力快速脱离，不进入谈判直接跑（但声望损失更大）
- **贿赂**：现场塞钱私了（消耗金钱但避免声望损失）
- **威慑**："你知道我是谁吗？"（需要身份/声望支撑）

## 六、系统架构建议

### 当前架构评审

**做得好的**（保持）：
- `StealManager` 作为纯业务层，`StealVM` 作为纯展示层，职责清晰
- `_stolenLog` 用 ConditionalWeakTable，内存安全
- 资源进出走 `AgentControlHelper.TransferItems`，遵守铁律 4
- 目击者检测走 `NpcSightSystem`，统一视线引擎
- 犯罪广播走 `AgentAIController.BroadcastEventInRange`，不裸调

**需要调整的**：
- `StealVM` 承担了过多责任（UI + 风险计算 + 检测逻辑），建议抽出一个 `StealLogic` 或直接在 `StealManager` 里加纯计算方法
- 风险公式当前硬编码在 `RecalculateState` 里，建议参数化到 Settings 或至少用 const 标注，方便后续平衡调整
- `ExecuteInvestigate` 第 172-178 行对 `IsItemRevealed` 的双重判断有逻辑冗余

### 扩展点

如果后续实现 P0-P2 优化，建议新增以下类/方法：

```
Stealth/
  StealManager.cs        # 已有 — 扩展：AddStealPerks、GetStealableSecrets
  StealVM.cs             # 已有 — 扩展：分层警惕条、迷你游戏绑定
  StealPerks.cs          # 新增 — Roguery Perk 树（顺手牵羊、妙手空空等）
```

## 七、总结

当前偷盗系统**骨架完整**（触发→博弈→结算→后果闭环），**制作质量超出一般 mod 水平**（围观站位分配、对称归还、真实扣除），但**核心乐趣不足**——盲盒设计剥夺决策权、纯数值判定缺乏操作感、与搜刮定位重叠导致玩家动机不足。

优先级排序：**先让偷窃有独特价值（P0）→ 再让风险系统有深度（P1）→ 最后打磨沉浸感（P2）**。

每个优化建议都保持了"骑砍2 能实现"的约束——不依赖外部库、不走复杂实时动画、复用现有轮子（NpcSightSystem / AgentControlHelper / NegotiationSystem）。
