## 管线一句话

`地图图(任意分辨率, 任一素材) → tools/ExportHeightMatMap/make_heightmap.py 一条命令 → 16bit 灰度高度图 PNG + RGBA 材质图 PNG → 场景编辑器 Terrain 面板 Import Heightmap / Import Materialmap；参数 = X/Y/Single Node Size/Single Node Dim 四件套`

```bash
python tools/ExportHeightMatMap/make_heightmap.py                # 主档 4096x2560（hires）
python tools/ExportHeightMatMap/make_heightmap.py 1024 640      # 任意档
python tools/ExportHeightMatMap/make_heightmap.py 1024 640 <src.png> <out_dir>   # 换素材/输出目录
```

## 一、编辑器里没有"PNG 导入"这种单独功能——在 Terrain 面板，参数是四件套

已核实：引擎 DLL 里没有 ImportHeight/TerrainTools 字符串；导入功能藏在场景编辑器 Terrain Properties 面板。

| 面板字段 | 含义 | 换算关系 |
|---|---|---|
| **X** | 横节点数 | 世界宽(m) = X × Size |
| **Y** | 纵节点数 | 世界高(m) = Y × Size |
| **Single Node Size** | 每节点边长(米) | 世界尺寸的真正控制者 |
| **Single Node Dim** | 每节点分辨率 | 总顶点 = X×Dim × Y×Dim；**PNG 必须与之 1:1** |

**三条铁律**：
1. 世界尺寸（米）**只由 X×Size / Y×Size 决定**，与 PNG 分辨率无关
2. **PNG 像素数 ≡ 地形顶点数**（1:1 强制，错像素=错位/形变）
3. 节点数与 Dim 可互换：X=16, Size=128, Dim=256 与 X=32, Size=64, Dim=128 等价（同世界体、同顶点、不同单节点分辨率；原版可参考量≈3000×3000 顶点）

按钮（同一面板，自上而下）：`Import Heightmap` / `Import Materialmap` / `Import Normalmap from Heightmap`（可选）/ `Export Heightmap`（导出核对）。

## 二、Python 管线（2026-09-05 版，替换旧「亮度差分吃整图」）

旧版被废弃的原因：道路黄线/河蓝线被抬成山脊与刻槽、海上航路白点线变成小岛、雪山(灰白/蓝白)混进滩、平原亮度方向搞反。**现管线 = 元素语义分层**：

| 元素 | 判据（源图色域采样） | 高度 |
|---|---|---|
| 海（深浅湾） | blueish & lum≤165 | 0（统一） |
| 湖 | 陆上大块蓝 | 0（=海） |
| 航路/浪花 | 海上低饱和亮色 + 开运算线状/点状 | 归海 → 0 |
| 滩/岩墙/雪 | 粗白 & 距海 d 连续映射（灰白/淡蓝白/淡绿白）| 0.05+d/1200（贴海0.05→岩0.14→雪0.55+雪脊差分，上限0.95） |
| 平原 | 绿区亮度分段低位（Koei 画法：平原亮黄绿、山地暗绿 → 亮度与山高**反向**）| ~0.2 |
| 山地 | 绿区亮度分段高位 + 山影高斯差分（亮度门控增益）| 0.25~0.5+细节 |
| 富士蓝白雪 | 蓝判 + 最大白点簇 → 雪帽；PEAKS 地标锥体豁免海清零 | 0.6-0.88 |
| 道路/河线 | 黄色判/细蓝判 + 开运算线状 | 中值替换底色（不抬山不刻槽） |

**⚠️ 关键裁定（用户亲报 2026-09-05）**：富士山 == 源图坐标 (10500,7000)（山顶白点=格线交点）。
- 富士雪是「蓝白 + 中心白点 + 绿地包围」——**蓝白雪≠水**（与海同色系），曾被三次当湖泊判 0 → 黑斑/蓝湖 bug
- 修复 = 雪帽检测（**最大白点簇**判定：全图最大白点簇=雪顶；浪花/礁石白点都是小簇自动排除）+ **PEAKS 地标区豁免海清零**（高度图、材质图两边同源，禁止分叉）

**材质图四通道**（RGBA 256，与高度图同尺度 1:1）：
- R 草（平原档，h_base<0.30）/ G 林（山地档）/ B 沙土（白系离海≤400）/ A 雪（白系离海>400 且 **hm≥0.42**（高度先决，防海岸白带误判）+ 雪帽 + 地标峰锥）
- 海/湖 = 全 0（引擎自动铺水面）
- ⚠️ 查看器不认 RGBA 四通道（A=雪 被当 alpha → 变半透明黑）；**用 `matpreview_*.png` 人看**

**脚本内部五段**：①语义分类（海陆/白/黄/河 + 雪帽）②高度合成（分层 + 山影）③地标层（`PEAKS` 表 =(cx, cy, 锥半径, 峰高, 山体基底高, 山体半径)）④材质派生 ⑤预览/QA。改素材/改参数 → 重跑一条命令。

## 🔴 三、素材分辨率 × Terrain 四件套：不同分辨率的图适配同一世界的方法论

**问题**：为什么给两张分辨率不同的日本地图（japanmap_hires 15840×10080 / TaikouMap2 704×448），都能生成同一世界尺寸、同一语义内容的地形，精细度如何换算？

**回答（三层）**：

### 第一层：世界尺寸只由四件套决定
```
世界宽(m) = X × Size；世界高(m) = Y × Size    ← 与 PNG 分辨率无关
总顶点    = X×Dim × Y×Dim                      ← PNG 必须 1:1 等于顶点数
```

### 第二层：PNG 分辨率只决定"网格能装多细"，不决定世界有多大
| 管线输出 PNG | X | Y | Size | Dim | 顶点 | 世界尺寸 | 每顶点代表 |
|---|---|---|---|---|---|---|---|
| 4096×2560（hires 主档） | 16 | 10 | 128m | **256** | 4096×2560 | **2048×1280m** | 0.5m |
| 1024×640（小素材推荐档） | 16 | 10 | 128m | **64** | 1024×640 | **2048×1280m** | 2.0m |
| 704×440（Taikou 原生近似） | 16 | 10 | 128m | **44** | 704×440 | 2048×1280m | ≈2.9m |

**规律**：Size 与节点数不动 ⇒ **世界尺寸不变**；Dim × 节点数 = PNG 分辨率；**PNG 越高 ⇒ Dim 可以越大 ⇒ 同世界体网格越细**。

### 第三层：素材分辨率如何换算成"精细度上限"
```
素材有效像素率 = 素材宽 / 世界宽(m)     ← 素材能支撑多少"真细节"
精细度上限 = min(素材像素率, 引擎顶点预算)
```
- japanmap_hires 15840 宽 / 2048m ≈ 7.7 源px/m → 撑得起 4096 顶点网格（0.5m/顶点），细节是真材实料
- TaikouMap2 704 宽 / 2048m ≈ 0.34 源px/m → **只能撑 1024 档（2m/顶点）**；强行 4096 = 顶点全插值 → "假细节"（碎斑振铃），观感反而劣化
- **"同一世界"的保证**：管线输出是**语义图层**（海/陆/山影/雪），语义与分辨率无关；素材经裁剪→语义→按目标顶点重采样，所以两素材输出**图上每个像素映射到世界上同一点**（山脉/海岸/富士同位置），仅网格粗细不同

### 实践规约
1. 正式产出用 **hires 4096 主档**（Dim=256）；小素材（704 级）只配 **1024 档预览**（Dim=64），两档可共用同一场景在世界坐标逐位置对齐
2. **不要**给小素材强行套大 Dim（顶点=插值假纹）
3. 换素材后**四件套只需要改 Dim**（节点数/Size 不动），世界尺寸自动一致
4. 素材原生分辨率不整除不是问题（如 704×448→440）：管线以"世界比例裁切后重采样到目标顶点"输出任意尺寸 PNG

### 直接参数表（照抄用，2026-09-05 实测）

**当前 Output/ 两档现成图 → 参数**：

| 要导入的 PNG（tools/ExportHeightMatMap/Output/） | X | Y | Single Node Size | Single Node Dim | 顶点 = PNG | 世界尺寸 |
|---|---|---|---|---|---|---|
| `hm_japanmap_hires_4096x2560_16bit.png` + `mat_japanmap_hires_4096x2560.png` | 16 | 10 | 128.000 | **256x256** | 4096×2560 ✓ | 2048m × 1280m |
| `hm_TaikouMap2_1024x640_16bit.png` + `mat_TaikouMap2_1024x640.png` | 16 | 10 | 128.000 | **64x64** | 1024×640 ✓ | 2048m × 1280m（同） |

**脚本输出档 → 四件套通用表**：

| 脚本输出的 PNG | 四件套（X / Y / Size / Dim） |
|---|---|
| 4096×2560 | 16 / 10 / 128 / **256x256** |
| 2048×1280 | 16 / 10 / 128 / **128x128** |
| 1024×640 | 16 / 10 / 128 / **64x64** |
| 704×440（Taikou 原生比例） | 16 / 10 / 128 / **44x44** |

**核验公式（防手滑）**：`PNG 宽 = X × Dim 数`，`PNG 高 = Y × Dim 数`；`世界宽(m) = X × Size = 16 × 128 = 2048m`（所有档位一致）。

## 四、ModKit 操作顺序

1. **新建自己的空场景**（不要克隆原版）
2. 右侧 Inspector → **Terrain 面板** → 按上表四件套填（hires 主档：X=16 Y=10 Size=128 Dim=256；或等价 X=32 Y=20 Size=64 Dim=128）
3. `Import Heightmap` → 选 16bit PNG → `Import Materialmap` → 选 RGBA 材质图
4. 若地表整体变色不对 = 通道顺序与引擎材质层不匹配 → **交换 R/G/B/A 重导试 1-2 次**（无需改图）
5. 布局据点 = 场景 `game_entity` 与 settlements.xml 同名即绑定（详见《定居点放置机制》章节）

## 五、定居点放置机制（已验证）

1. **战役层坐标**（玩法/寻路/部队用）= `Modules/<你的mod>/ModuleData/settlements.xml` 的 `posX/posY`（引擎读的值 = 地图场景里同名实体 transform 坐标）
2. **地图图标** = 场景 `game_entity`：`name` = 据点 StringId；`tag` = 类型（town/castle/village/hideout/…）；`transform` x,y = 地图坐标（z 贴地）
3. 让游戏知道这是你的地图 = 模块目录 `SceneObj/` 里场景文件夹与引擎默认名一致（原版 `main_map`；同名覆盖即替换大地图）

## 六、坑点清单（全踩过）

| 坑 | 症状 | 解法 |
|---|---|---|
| 富士蓝白雪被判湖泊 | 高度/材质图上富士=蓝湖/黑斑 | 最大白点簇雪帽检测 + PEAKS 地标豁免（前文§二） |
| 亮度映射方向反 | 平原发白、山地发低（Koei 平原亮/山地暗） | 亮度分段归位 + 山影由 detail 差分驱动 + 亮度门控增益 |
| detail 粒度判断 | 平原路网纹理 detail 比山地大（判不了山） | 弃用细节幅判据；山=uniform 暗绿、平原=细纹密 |
| σ 按输出分辨率等比放大 | 4096 档细节被 σ8 抹平（细节能量 ×2.39 差异） | σ 定值 2.0；基底 σ 按源图尺度 mb 换算 |
| 白判抓平原/城市亮色 | 平原进雪/岩道 | 白判加绿度排除（平原 g−b>10，雪/滩 g≈b） |
| 材质图海岸线白色 | 海岸白带被判雪 | 雪-高度交叉：hm≥0.42 才准当雪，不够高的白系降级沙 |
| 小素材管线失效 | 704 图河/路/滩爆量（river 8.5%/yline 13.8%） | **尺度标定**：小素材先 LANCZOS 放大到 MASTER_W=15840 再走管线（几何阈值按 15840 校准）；色判与分辨率无关 |
| LANCZOS 大倍数放大振铃 | 小素材出"碎斑假细节" | 此为插值伪影非真地；小素材只用于预览档 |
| matpreview 溢出回绕 | 双通道像素 uint8 回绕成品红 | clip 0..255 |
| 查看器不认 RGBA | 材质图黑+绿线 | 引擎版保持 RGBA；人看用 matpreview |
| 导入后地表整色不对 | 引擎材质层通道顺序不匹配 | 换 R/G/B/A 次序重导 1-2 次 |
| 大地图场景编辑器全机卡死 | 实体/植被超量 | 做自己的图别超原版规模；织丰 41,581 实体案例 |
