# 骑砍2 相机系统 — 自定义相机与引擎相机对齐（2026-10-04 实机收官）

> **本文给谁看**：任何**接管/交还相机**的功能（钩索拉拽、玩家飞行、演出取景、未来任何"脚本相机"）。
> 结论先行：**相机 = 5 个参数**（锚点 / 臂长 / pitch / yaw / fov，另加 roll 但不影响机位）。
> **5 个参数全同 ⇒ 画面必然全同。** 所以"切相机时跳一下"永远是这 5 个里有哪个**实际不同**——
> 用本文的公式逐项对，不要靠肉眼猜。
>
> 出处：v1.2.12 客户端 `TaleWorlds.MountAndBlade.View.dll` 的 `MissionScreen`（`UpdateCamera` / `HandleUserInput`），
> 行号是 `ilspycmd` 反编译后的行号。

## 一、引擎第三人称相机的**完整机位公式**（逐字，含行号）

```csharp
// ① 锚点（UpdateCamera 11929 / 12145 / 12178）
num17 = ragdoll(3) || animFlag(0x40000000)          ? 0.5f
      : (CrouchMode || IsSitting())                 ? (Monster.CrouchEyeHeight  + 0.2f) * AgentScale
      : HasMount                                    ? (MountMonster.RiderCameraHeightAdder
                                                       + MountMonster.BodyCapsulePoint1.z
                                                       + MountMonster.BodyCapsuleRadius) * MountAgentScale
                                                      + Monster.CrouchEyeHeight * AgentScale
      : /* 站姿 */                                    (Monster.StandingEyeHeight + 0.2f) * AgentScale;
_cameraTargetAddedHeight += (num17 - _cameraTargetAddedHeight) * dt * 6f * AgentScale;   // ← 6/s 平滑
val23 = Agent.VisualPosition;          // 🔴 **视觉位置**，不是 Position（12240 行）
val23.z += _cameraTargetAddedHeight;

// ② 沿"画面向上"再抬一个量（**12257 行 —— 最容易被漏掉的一项**）
_cameraTarget = val23 + rotation.f * AgentScale
              * (0.7f * pow(cos(1f / ((num30/AgentScale - 0.2f) * 30f + 20f)), 3500f));
//   臂长 1.83、缩放 1 时 = 0.7 × cos(1/68.9)^3500 = 0.484 米  ← "相机比锚点高 0.5 米"的全部来源

// ③ 相机位置（12259 行）
val.origin = _cameraTarget + rotation.u * CameraResultDistanceToTarget;   // u = 后方向
//   rotation = RotateAboutForward(CameraBearing + _cameraSpecialCurrentAddedBearing)
//              → RotateAboutSide(CameraElevation + _cameraSpecialCurrentAddedElevation + _cameraAddedElevation)
```

**人形常量**（`Native/ModuleData/monsters.xml`）：`human` 站姿眼高 1.70 / 蹲 1.10 / 骑乘 0.75；
`human_child` 站姿 1.20（**体型差异靠不同 monster，不靠 AgentScale**；AgentScale 目前只有**马**会被设成非 1）。

> **✅ 我们的实现**：`Camera/SpringArmMath.cs` —— `ResolveEngineEyeHeight`（锚点四支）+ `ComputeEngineLift`（lift 项）
> + `UseEngineEyeHeight` 开关（跟随相机 true；飞行/模板演出 false，行为不变）。

## 二、在我们持有 `CustomCamera` 期间，引擎**哪些状态被冻结**

引擎的整段 `UpdateCamera` 在 `CustomCamera != null` 时被跳过，于是这些量**冻在接管那一刻**、
撒手后**第一帧一次性释放**、再自己慢慢收敛 —— **这就是"切相机时跳一下"的头号来源**：

| 冻结的量 | 释放时的表现 | 对策 |
|---|---|---|
| `_cameraSpecial{Current,Target}{AddedBearing,AddedElevation,PositionToAdd,DistanceToAdd}`（8 项） | 朝向/位置额外偏移 | 撒手前**清零**（`ClearEngineSpecialCameraAdds`，反射；实测常为 0，但清零是保险） |
| `_cameraAddedElevation`（远程武器垂直瞄准修正） | 相机上抬（仰角） | 实测**不是**我们那 0.5 米的来源；如需可同款清零 |
| `_cameraTargetAddedHeight` 的 6/s 平滑 | 锚点高度未收敛 | 锚点公式里已含平滑目标；站立稳态两边相同 |
| `CameraResultDistanceToTarget` 的平滑 | 视距未收敛 | 我们直接抄这个值 ⇒ 天然一致 |

> **✅ 我们的实现**：`SpringArmCameraView.ClearEngineSpecialCameraAdds`（钩索专用开关 `clearSpecialCameraOnReturn`）。

## 三、会**主动改写**引擎相机的引擎事件（踩过的两个）

1. **解冻玩家 ⇒ 引擎重置相机**（2026-10-03 实机 + 反编译全链路）：
   `Agent.Controller = Player` → `Agent.Controller` setter 里 `Mission.MainAgent = this` →
   `OnMainAgentChanged` → `_isPlayerAgentAdded = true` → **下一帧** `HandleUserInput`
   （由 `IMissionSystemHandler.BeforeMissionTick` **每帧**调用、**不受 CustomCamera 挡板保护**）执行：
   ```csharp
   CameraBearing   = MainAgent.MovementDirectionAsAngle;   // 第三人称：角色**移动方向**
   CameraElevation = 0f;                                   // 写死常量 0
   ```
   ⇒ **任何"冻结/解冻玩家（切 Controller）"的功能，解冻后引擎都会把相机重置**。
   **写回角度会被它打掉**；正解 = 归还途中**追引擎的实时值、跟平了才撒手**（见配方 §4）。
   ⚠️ `Agent.Controller` setter **只在切到 `Player` 时**赋值 `Mission.MainAgent` ⇒ **冻结不触发、解冻触发**。

2. **锚点用的是 `VisualPosition`**（12240 行）：被载具搬运 / 视觉插值时，它与逻辑 `Position` 差几十厘米
   （实测 −0.36 米）⇒ 自定义相机必须同样用 `VisualPosition`。

## 四、对齐配方（做任何自定义相机时照抄）

1. **方向/距离/FOV 照抄引擎**：方向从 `Mission.GetCameraFrame()` 的 `−rotation.u` 取；
   距离取 `CameraResultDistanceToTarget`；FOV 取 `CameraViewAngle`。
2. **锚点用引擎公式**（§一①②，含**骑马分支**与 `VisualPosition`）。
3. **别忘记 lift 项**（§一②，1.83 米时 0.484 米）—— 漏了它，交接瞬间相机高度就差这半米。
4. **归还三步**：
   ① 撒手前清 `_cameraSpecial*`（§二）；
   ② 方向在归还滑行期间**追引擎的实时值**（`ChaseEngineLook`：指数平滑 + **yaw 走最短弧**），
      **收敛（差 ≤2°）才撒手**，超时上限兜底；
   ③ **不要写回角度**（`WriteBackLookToEngine` 那套会被 §三-1 的重置打掉 —— 2026-10-03 定稿已弃用于钩索）。
5. **"引擎会重置"的前提才预置俯仰**：只有确定会解冻（⇒ 引擎必然重置成 0 俯仰）的功能才预置；
   不解冻的场景（如 `custom.cam test`）预置反而制造不存在的差（`predictResetOnReturn` 开关）。
6. **骑马/蹲坐/倒地**：锚点分支跟着变 ⇒ 自定义相机也要跟（目前 `ResolveEngineEyeHeight` 已覆盖四支）。

## 五、调试工具（`custom.cam`，2026-10-04 从 grapple 迁到相机自己的模块）

| 命令 | 作用 |
|---|---|
| `custom.cam log <0\|1>` | **诊断日志总开关，默认 0**：`[FollowCam]` 的逐帧 / 交班明细 / 撒手后采样 / 引擎内参。生命周期行（接管/归还/异常）始终打 |
| `custom.cam stat` | 采一行**引擎相机**（机位 / Δ眼 / 角度 / 引擎内参 / 有效锚高 / 是否骑马）。**站着不动敲**；别在接管期间敲（读到的是过期值） |
| `custom.cam info` | 一行**我们的相机**（在跟 / 臂长 / 俯仰 / yaw / 眼高 / 引擎抬升项 / 手动 lift / 日志开关） |
| `custom.cam test [<秒>]` | **原地切换标定台**：不动人，把相机交给我们的相机 N 秒再自动归还 ⇒ 专看"接管/归还那一下有没有突变" |
| `custom.cam lift [<米>]` | 固定高度修正（应急微调；正常 0） |

## 六、排查记事（这些假设都已**证伪**，别再重试）

- ❌「远程武器垂直瞄准修正（`EnableVerticalAimCorrection`）造成 0.5 米」→ 设置关掉后一模一样。
- ❌「`_cameraSpecial*` 冻结值造成」→ 实测那 8 项全是 0。
- ❌「拆木板造成」→ 拆板前后玩家位置与相机坐标零变化。
- ❌「骑马锚点分支」→ 平地测试同样出现。
- ❌「眼高常量 / 视觉位置」→ 分别修正后各只解释了 0.44 / 0.36 的一部分。
- ✅ **真凶 = §一② 的 lift 项（0.484 米）**，此前用 `camlift 0.5` 标定的那半米就是它。
