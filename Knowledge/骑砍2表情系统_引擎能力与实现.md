# 骑砍2 表情系统 —— 引擎能力与实现

> 状态：2026-11-18，反编译 + 资产解包实测（v1.2.12 与 v1.5.7 双端核对，行为一致）。
> 本文是**知识归档**。可执行的东西在别处：
> · 全量名单（机器基线）→ [Scripts/face_animations.csv](../Scripts/face_animations.csv)（生成物）
> · 名单生成器 → [Scripts/gen_face_animations.py](../Scripts/gen_face_animations.py)
> · 运行期唯一出口 → [StoryFaceAnimations.cs](../ExampleModVS/ExampleMod/ExampleMod/Interaction/StoryProbe/StoryFaceAnimations.cs)
> · 对话数据字段 → `Dialogues/*.dialog.json` 的 `Face`

## 一句话结论

原生就有完整的表情系统：**251 条（1.2.12）/ 252 条（1.5.7）有名字的顶点变形片段**，
任意人形 NPC 都能播，和骨骼动作各走各的、可同时进行。

## 一、它是什么

- 表情 = **顶点变形动画（morph）**，驱动头部网格的"变形帧权重"。不是骨骼、不是贴图切换。
- 片段本体在 `Modules/Native/AssetPackages/morph_anims.tpac`（包 GUID `cab5ba7b-…`）。
  每条片段 = 若干个 `(变形帧号, 权重)` 的关键帧序列（`MorphDefinitionData` 实测结构）。
- 登记表在 `Modules/Native/ModuleData/voices.xml`（类型 `face_animation_record`），
  给每个名字挂两个标志：`do_blink`（自动眨眼）、`look_at_player`（看向玩家）。
- 引擎**按名字查资产**，查不到只在引擎日志打一行 `Morph animation could not be found: <名字>`，
  游戏里没有任何提示。

## 二、怎么调用（四种入口）

| 入口 | 签名 | 用在哪 |
|---|---|---|
| Agent | `agent.SetAgentFacialAnimation(Agent.FacialAnimChannel.Mid, "cry", loop: true)` | **活人 NPC / 玩家**（本项目用它） |
| Agent 查询 | `agent.GetAgentFacialAnimation()` | 诊断当前表情 |
| Skeleton | `MBSkeletonExtensions.SetFacialAnimation(skeleton, channel, name, playSound, loop)` | 半身像、过场、场景脚本里的"没有 Agent 的骨架" |
| 原版调试命令 | `mission.set_facial_anim_to_agent <agentIndex> <名字>` | 实机验收表情库是否可用（High 通道 + 循环） |

另有一条**纯数据**入口（原版对话自带，见第四节）。

## 三、三个通道：High / Mid / Low

枚举 `Agent.FacialAnimChannel { High, Mid, Low }`。三层的混合/优先级规则在 native 里，
托管层看不到；以下是**原版自己的用法**（可照抄）：

| 通道 | 原版谁在用 | 结论 |
|---|---|---|
| `High`（0） | 调试命令；**每句对话播完后被清空**（无 `[if:]` 标签时 `SetAgentFacialAnimation(High, "", false)`） | 瞬时/语音类表情。我们的台词没有标签，写进去会被立刻清掉 |
| `Mid`（1） | 对话待机表情、对话反应表情（`MissionConversationLogic`） | **"这一句的脸"该放这里**；会话结束时原版自动清掉 |
| `Low`（2） | 全场默认（`MissionFacialAnimationHandler` 设 `idle_tired`；该方法在两个版本里都是死代码，未接线） | 环境氛围预留位 |

## 四、原版对话的数据入口：台词里的标签

Vanilla 台词文本可以带标签，`MBTextManager.GetConversationAnimations` 解析，`ConversationManager` 在**说话人**身上播放：

```
"... Yield or fight![ib:warrior][if:convo_angry]"
   ib = 待机动作   if = 待机表情
   rb = 反应动作   rf = 反应表情（一次性，播完回到待机）
```

- 显示时自动剥标签（`ConversationManager.CurrentSentenceText`），玩家看不到方括号。
- **本地化条目必须一起带标签**：原版所有语种的 `std_comment_strings_xml-*.xml` 里标签都在文本内；
  我们的 `Languages/CNs` 同理，否则换语言表情就没了。
- `AddDialogLineWithVariation(...)` 那四个 `idleFaceAnimId/reactionFaceAnimId` 形参是**死参数**（构造里丢弃），
  真正生效的只有文本标签。

## 五、版本支持

| 版本 | morph 片段 | 登记表 | 差异 |
|---|---|---|---|
| v1.2.12 | 251 | 245 | — |
| v1.5.7 | 252 | 246 | 多 `sad_face_cutscene`（1.5.7+ 才有） |

- 两版**行为一致**：API 相同、通道相同、`MissionFacialAnimationHandler` 同样是未接线的死代码。
- 名单 CSV 的 `Versions` 列标了可用版本；`sad_face_cutscene` 只能用在 1.5.x。
- 三个**登记表有、资产没有**的名字（调了没反应）：`laugh`、`cutscene_expression_1`、`cutscene_expression_2`。
  要笑用 `hard_laugh`。

### 五类名字各是什么（先分清再用）

- **裸名**（`rage`、`cry`、`happy`、`shocked`…）：**幅度最大、一次性**，像"喊出来 / 哭出来"那一瞬间，适合强表演的台词。
- **`convo_*`**：**对话专用**，幅度小、细腻；原版对话默认就用这一档。**日常台词优先从这里挑**。
- **`idle_*`**：**常驻底色**（站着不动时的神态），适合"这人平时就一脸…"。
- **`talking_*`**：说话时的口型 / 语气（`talking_happy` 等 6 个）。
- **`<反应>_<风格>`**（`trivial_ag`、`negative_co1`…）：原版对话动作配套的反应变体 —— `ag`=强势 `no`=平常 `hi`=带派 `we`=疲惫 `ne`=紧张 `co1`/`co2`=收敛（两档未逐一对证），**一般不用手挑**。

## 七、坑（都会咬人）

1. **用 game object 的 idle 播不出来**：站岗、酒保、弹琴这类"占着物件"的待机，
   表情只出第一帧（社区实证）。绕法：`StopUsingGameObject(true)` + 重设动作，再设表情。
2. **自建头必须有表情变形帧**：自带头的网格要带 `KeyTime_60..100` 那段（说话、眨眼、下颌），
   否则脸完全不动 —— 亨利换头的"没表情"就是这个原因（见
   [wheels.d/assets.md](../plans/rules/wheels.d/assets.md) 自建头 101 条通道）。
3. **名字写错静默失败**，只在引擎日志留一行。所以内容侧必须过离线闸门。
4. **一次性短表情不要当持续表情**：`hit` / `pain` / `scream` / `death` 这类是瞬时动作，
   循环播放会变成抽搐。持续表情用 `convo_*` / `idle_*` 这一类。
5. **动作也可能改表情**：动画资产有 `facial_anim_id` 字段（官方文档：播放该动画时把脸变形成这个表情），
   战斗喊叫的 `face_anim` 也由引擎自动带。我们显式设置后，后续带表情的动作可能把它覆盖 —— 未实测。

## 八、本项目接在哪里

- **数据**：对话节点加 `Face`（一句一个，与 `LineActions` 同级；空 = 回到该角色的原版默认待机脸）。
- **运行期**：[StoryFaceAnimations.Play](../ExampleModVS/ExampleMod/ExampleMod/Interaction/StoryProbe/StoryFaceAnimations.cs)，
  在 `StoryProbeDialogue` 的 `OnShown`（这一句真的展示时）调用，走 **Mid** 通道。
- **离线闸门**：`python Scripts/check_story_probe.py` 的 `faces=` 计数与 `node[...]: 表情 'xxx' 不存在` 报错。
- **实机验收**（**通用命令，不属于剧情探针**）：
  - `custom.face_anim rage` —— 给**准星对着的那个 agent** 设表情（目标走
    `InteractionMissionView.GetAimedAgent()`，项目里"此刻瞄着谁"的唯一入口，禁止自己打相机射线）；
  - `custom.face_anim` —— 报告准星目标的当前表情；
  - `custom.face_anim rage lord_1_1` —— 第二参可弃：指定目标 `Character.StringId`；
  - `custom.face_anim reset` —— 准星目标回到中性脸；
  - 目标解析顺序：显式 id → 准星焦点 → 对话对象 → 主角，回执里会注明落到了谁身上；
  - 原版命令 `mission.set_facial_anim_to_agent <agentIndex> cry` 可以直接验表情库本身。
