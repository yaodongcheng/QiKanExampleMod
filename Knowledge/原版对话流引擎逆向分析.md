## 一、架构总览：Token 状态机

### 核心数据结构

整个对话引擎是**基于字符串 token 的状态机**：

```
ConversationManager
├── ActiveToken: int                  ← 当前状态（token → int 映射）
├── _sentences: List<ConversationSentence>  ← 全局对话句子表（一张大表）
├── GetSentenceOptions()             ← 扫描所有 InputToken == ActiveToken 的句子
└── ProcessSentence(option)          ← 执行后果 → ActiveToken = sentence.OutputToken
```

每句对话（`ConversationSentence`）有：
- `InputToken` / `OutputToken` — 从哪个状态来 / 到哪个状态去
- `Text` — 显示文本（`TextObject`，支持 `{VARIABLE}` 占位符）
- `IsPlayer` — bool，true=玩家选项，false=NPC 说话
- `OnCondition` — `delegate bool()`，条件不满足不显示
- `OnConsequence` — `delegate void()`，选中后执行
- `AgentIndex` / `NextAgentIndex` — 多 NPC 对话时的说话人切换

### 状态转换流程

```
1. 对话开始 → ActiveToken = (int)ConversationToken.Start

2. ProcessPartnerSentence():
   → GetSentenceOptions(onlyPlayer: false)     // 找 NPC 句子
   → 取第一个 → ProcessSentence()
   → ActiveToken = 该句子的 OutputToken
   → RunConsequence()

3. 引擎暂停，UI 展示当前 NPC 台词 + 等玩家输入

4. GetPlayerSentenceOptions():
   → GetSentenceOptions(onlyPlayer: true)      // 找玩家选项
   → 所有 InputToken == ActiveToken ∧ IsPlayer ∧ Condition() 通过的
   → 返回 List<ConversationSentenceOption>

5. 玩家选了第 N 个选项 → ProcessSentence(N):
   → RunConsequence()
   → ActiveToken = 该选项的 OutputToken
   → 回到步骤 2（自动触发下一条 NPC 句子）
```

### Token 生成

```csharp
// ConversationManager.CreateToken() — 反编译确认
internal string CreateToken()
{
    string result = $"atk:{_autoToken}";
    _autoToken++;
    return result;
}
// atk:0, atk:1, atk:2 ... 自增永不重复
```

## 二、DialogFlow — 建造者，不是必需品

### 反编译确认的内部结构

```csharp
public class DialogFlow
{
    internal readonly List<DialogFlowLine> Lines = new List<DialogFlowLine>();
    internal readonly int Priority;
    private string _currentToken;  // 当前正在构建的链的最后一个 OutputToken

    // 每个方法都在追加 Lines 并更新 _currentToken
    public DialogFlow NpcLine(TextObject text, ...) {
        var nextToken = ConversationManager.CreateToken();
        AddLine(text, _currentToken, nextToken, byPlayer: false, ...);
        _currentToken = nextToken;  // ← 链式调用靠这个连接
        return this;
    }

    public DialogFlow PlayerLine(TextObject text, ...) {
        var nextToken = ConversationManager.CreateToken();
        AddLine(text, _currentToken, nextToken, byPlayer: true, ...);
        _currentToken = nextToken;
        return this;
    }
}
```

### AddDialogFlow — 注册时的转换

```csharp
// ConversationManager.AddDialogFlow — 反编译确认
public void AddDialogFlow(DialogFlow dialogFlow, object relatedObject = null)
{
    foreach (DialogFlowLine line in dialogFlow.Lines)
    {
        string id = CreateId();   // "adg:0", "adg:1"...
        uint flags = (line.ByPlayer ? 1u : 0u) | (line.IsRepeatable ? 2u : 0u);
        AddDialogLine(new ConversationSentence(
            id, line.Text,
            line.InputToken,              // ★ 状态机：from
            line.OutputToken,             // ★ 状态机：to
            line.ConditionDelegate,       // 条件
            line.ClickableConditionDelegate,
            line.ConsequenceDelegate,     // 后果
            flags, dialogFlow.Priority,
            0, 0,  // AgentIndex, NextAgentIndex
            relatedObject,                // ★ 归属标记，清理用
            line.HasVariation,
            line.SpeakerDelegate,
            line.ListenerDelegate));
    }
}
```

### 结论

`.NpcLine("text").PlayerLine("text").Condition(...).Consequence(...)` 本质就是往 `_sentences` 列表里追加 `ConversationSentence` 对象。**不用 DialogFlow，直接调 `AddPlayerLine` / `AddDialogLineMultiAgent` 完全等效。**

## 三、PersuasionTask 嵌入机制

### 它不接管引擎，它只是给句子加了个标记

```csharp
public class ConversationSentence
{
    private OnPersuasionOptionDelegate _onPersuasionOption;
    
    // ★ 关键：_onPersuasionOption != null → HasPersuasion = true
    public bool HasPersuasion => _onPersuasionOption != null;
    public PersuasionOptionArgs PersuasionOptionArgs { get; private set; }
}

// delegate 签名
public delegate PersuasionOptionArgs OnPersuasionOptionDelegate();
```

### 完整流程

```
1. DialogFlow.AddPlayerLine 时传入 persuasionOptionDelegate:
   
   DialogFlow.AddPlayerLine(
       id, inputToken, outputToken, text,
       conditionDelegate, consequenceDelegate, relatedObject, priority,
       clickableConditionDelegate: null,
       persuasionOptionDelegate: () => new PersuasionOptionArgs(...),  // ←
       speakerDelegate, listenerDelegate);

2. ConversationManager.GetSentenceOptions():
   - sentence.RunCondition() 通过
   - sentence.HasPersuasion → true   (因为 _onPersuasionOption != null)
   - sentence.PersuationOptionArgs → 非 null
   - → ConversationSentenceOption.HasPersuasion = true

3. 对话 UI 检测到 HasPersuasion → 渲染说服小游戏（技能图标+成功率+特质）

4. ConversationManager.StartPersuasion(goalValue, successValue, ...) 
   → 创建静态 _persuasion 对象 → 引擎进入说服模式
   → 后续 GetSentenceOptions 返回的句子会显示说服进度条

5. 对话结束:
   - GetPersuasionProgressSatisfied() → 说服成功
   - GetPersuasionIsFailure() → 说服失败
   - Quest 根据结果走不同分支
```

### 关键启示

说服选项通过**完全相同的 `AddPlayerLine` 管道**注册，只是多传了 `persuasionOptionDelegate`。**这个模式可以复用到任何"特殊对话节点"——比如 LLM 生成的"自由文本输入"节点、技能检定节点、情报交换节点等。**

## 四、动态化方案：绕过 DialogFlow 直接操作引擎

### 核心 API（全部公开，随时可调）

```csharp
// 加一句 NPC 说话（多 Agent 版本，可指定谁在说）
ConversationManager.AddDialogLineMultiAgent(
    id: "唯一ID",
    inputToken: "当前token",
    outputToken: "下一token",
    text: new TextObject("说话内容"),
    conditionDelegate: () => true/false,
    consequenceDelegate: () => { /* 后果 */ },
    agentIndex: 0,        // 第几个 conversation agent 说话（0=第一个NPC, 1=玩家）
    nextAgentIndex: -1,   // 下一个说话的是谁（-1=不改变）
    priority: 125);

// 加一个玩家选项（自动 IsPlayer=true）
ConversationManager.AddPlayerLine(
    id: "唯一ID",
    inputToken: "当前token",
    outputToken: "选了这个之后跳到哪个token",
    text: "选项文字",
    conditionDelegate: () => true/false,
    consequenceDelegate: () => { /* 后果 */ },
    relatedObject: myQuest,    // ★ 关联到 Quest，清理用
    priority: 125);

// 加说服选项（PlayerLine + 说服参数）
ConversationManager.AddPlayerLine(
    id, inputToken, outputToken, text,
    conditionDelegate, consequenceDelegate, relatedObject, priority,
    clickableConditionDelegate: null,
    persuasionOptionDelegate: () => new PersuasionOptionArgs(...),
    speakerDelegate: null, listenerDelegate: null);

// 创建新 token
ConversationManager.CreateToken();  // → "atk:42"

// 批量清理
ConversationManager.RemoveRelatedLines(myQuest);
```

### 最简封装：DynamicDialogueTurn

```csharp
public class DynamicDialogueTurn
{
    private readonly object _owner;
    private string _currentToken;

    public DynamicDialogueTurn(object owner, string startToken)
    {
        _owner = owner;
        _currentToken = startToken;
    }

    /// <summary>NPC 说一句话 → 自动创建 transition token</summary>
    public DynamicDialogueTurn NpcSays(string text, Action onSaid = null,
        int agentIndex = 0)
    {
        var next = ConversationManager.CreateToken();
        ConversationManager.AddDialogLineMultiAgent(
            Guid.NewGuid().ToString(), _currentToken, next,
            new TextObject(text),
            () => true,
            () => onSaid?.Invoke(),
            agentIndex, -1, 125);
        _currentToken = next;
        return this;
    }

    /// <summary>挂多个玩家选项，每个选项对应一句 NPC 回应</summary>
    public DynamicDialogueTurn PlayerChoices(
        params (string option, string npcResponse, Action onChosen)[] choices)
    {
        foreach (var (opt, response, onChosen) in choices)
        {
            var afterPlayer = ConversationManager.CreateToken();
            var afterNpc = ConversationManager.CreateToken();

            // 玩家选项
            ConversationManager.AddPlayerLine(
                Guid.NewGuid().ToString(), _currentToken, afterPlayer,
                opt, () => true,
                () => onChosen?.Invoke(), _owner, 125);

            // NPC 回应
            ConversationManager.AddDialogLineMultiAgent(
                Guid.NewGuid().ToString(), afterPlayer, afterNpc,
                new TextObject(response),
                () => true, null, 0, -1, 125);
        }
        return this;
    }

    /// <summary>关闭对话</summary>
    public void Close()
    {
        ConversationManager.AddPlayerLine(
            Guid.NewGuid().ToString(), _currentToken, "close_window",
            "", () => true, null, _owner, 125);
    }
}
```

### JSON 驱动的使用方式

```csharp
// LLM 输出这个 JSON
var turns = JsonConvert.DeserializeObject<List<DialogueTurnJson>>(llmJson);

var db = new DynamicDialogueTurn(myQuest, "start");
foreach (var turn in turns)
{
    db.NpcSays(turn.NpcLine, agentIndex: turn.SpeakerIndex);
    db.PlayerChoices(turn.Options
        .Select(o => (
            o.PlayerLine,
            o.NpcResponse,
            (Action)(() => ExecuteConsequence(o.Consequence))
        )).ToArray());
}
db.Close();
```

## 五、与原版对话共存

### 机制

```
ConversationManager._sentences（一张大表，不分来源）
│
├─ InputToken: "hero_main_options"        ← 原版系统保留
├─ InputToken: "issue_classic_quest_start" ← 你的 Quest.OfferDialogFlow
├─ InputToken: "quest_offer"               ← 你的 Quest.DiscussDialogFlow
├─ InputToken: "atk:12345"                 ← ★ 你的动态对话（LLM生成）
├─ InputToken: "atk:12346"                 ← ★ 你的动态对话
└─ ...
```

三个层面保证互不干扰：

| 层面 | 机制 |
|------|------|
| **Token 隔离** | `CreateToken()` 生成 `atk:N`，原版用 `hero_main_options` 等语义化 token，永不碰撞 |
| **Condition 过滤** | 原版选项 `Condition(() => NPC是商人)`，你的 `Condition(() => 一对一对话对象 == QuestGiver)`，同时为 true 就同时显示 |
| **Cleanup** | `RemoveRelatedLines(quest)` 只删 `relatedObject == quest` 的，原版纹丝不动 |

### 玩家看到的效果

```
与 NPC 对话:
┌──────────────────────────────────────┐
│ "有什么我可以帮忙的吗？"                │  ← 原版 issue_offer
│ "关于那个护送任务……"                   │  ← ★ 你的 quest_offer (Quest.DiscussDialogFlow)
│ "我想交易。"                           │  ← 原版 trade
│ "最近有什么传闻？"                     │  ← 原版 gossip
│ "我先走了。"                           │  ← 原版 close_window
└──────────────────────────────────────┘

玩家选 "关于那个护送任务……"
  → ActiveToken = quest_offer
  → 进入你的 token 空间
  → 你的动态对话图开始渲染
```

### Quest 生命周期中的对话注册

```
Quest 构造:
  SetDialogs()
    → OfferDialogFlow 注册 (挂 issue_classic_quest_start)
    → DiscussDialogFlow 注册 (挂 quest_offer)
    → 额外的 LLM 动态节点注册（如果有预生成）

Quest 运行中:
  → 事件触发 → LLM 生成新节点 → DynamicDialogueTurn → AddPlayerLine

Quest 完成:
  → FinalizeQuest() → RemoveRelatedLines(this)
    → 所有 relatedObject == this 的句子被删除
    → 原版对话毫发无伤
```

### 流程图

```
┌─────────────────────────────────────────────────────────────┐
│                    LLM 集成路径                               │
├─────────────────────────────────────────────────────────────┤
│                                                             │
│  游戏事件 (NPC 找你、任务推进、WorldEvent…)                    │
│    ↓                                                        │
│  PromptBuilder 组装上下文:                                    │
│    · NPC 人设 (NPCProfile.GetPersonaPrompt)                  │
│    · 玩家关系 + 信任度                                        │
│    · 当前事件 / Quest 上下文                                  │
│    · 因果链上下文 ({PREVIOUS_QUEST}, {CAUSE_HERO}...)        │
│    · Settings.Instance.WorldDescription                      │
│    ↓                                                        │
│  LLMService.ChatAsync(prompt, needJson: true)                │
│    ↓                                                        │
│  JSON 输出 (按 DialogueTurnJson schema)                      │
│    ↓                                                        │
│  DynamicDialogueTurn 解析 → AddPlayerLine / NpcSays           │
│    ↓                                                        │
│  ConversationManager 自动渲染                                 │
│    ↓                                                        │
│  玩家选择 → ProcessSentence → Consequence 执行                │
│    ↓                                                        │
│  如果需要继续对话 → 上下文回传 LLM → 生成下一段 JSON           │
│                                                             │
└─────────────────────────────────────────────────────────────┘
```

### 三层 Fallback

```
IsLLMReady == true:
  → LLM 生成完整 JSON
  → 解析成功 → 注册到 ConversationManager
  → 解析失败 / 超时 → Fallback 到 CSV 模板

IsLLMReady == false:
  → NarrativeResolver 查 Narrative.csv
  → 命中 → 用 CSV 模板构建 DialogueTurn
  → 未命中 → 用 Quest 原版 TextObject（QuestBase 的静态文本）
```

## 八、实战踩坑 — 模板 NPC 对话注入

> 记录 2026-07-08 一次完整的调试过程：警戒质问（AlertForceConversationAction）注入的
> 对话选项在模板 NPC（农夫、村妇等 `HeroObject==null` 的角色）上完全不出现。

### 坑 0：`ConversationSentence.InputToken / OutputToken` 是 `int` 不是 `string`

文档前面说"基于字符串 token 的状态机"，但 `ConversationSentence` 存储的
`InputToken` / `OutputToken` **不是字符串——是 `int`**，即 `stateMap` 字典的 value。

```csharp
// ConversationSentence 反编译确认（TaleWorlds.CampaignSystem.dll）
public int InputToken { get; private set; }
public int OutputToken { get; private set; }

// 构造时通过 stateMap 把 string → int
InputToken = Campaign.Current.ConversationManager.GetStateIndex(inputToken);
OutputToken = Campaign.Current.ConversationManager.GetStateIndex(outputToken);
```

**后果**：反射拿 `OutputToken` 时 `as string` 会把 boxed int 转成 `null`，代码静默失败。

**正确做法**——反射 + stateMap 反向查找：

```csharp
// 1. 反射拿 int
var otProp = sentence.GetType().GetProperty("OutputToken",
    BindingFlags.Public | BindingFlags.Instance);
int outputTokenInt = (int)otProp.GetValue(sentence);

// 2. 反向查 stateMap：int → string
var cmType = cm.GetType();
var stateMapField = cmType.GetField("stateMap",
    BindingFlags.NonPublic | BindingFlags.Instance);
var stateMap = stateMapField.GetValue(cm) as Dictionary<string, int>;
string outputTokenStr = null;
foreach (var kv in stateMap)
{
    if (kv.Value == outputTokenInt)
    {
        outputTokenStr = kv.Key;
        break;
    }
}
```

### 坑 1：`hero_main_options` 不是通用 token

`hero_main_options` **只存在于有名 Hero 的对话树中**（领主、名人、村长等）。
模板 NPC（农夫、村妇、市民等 `HeroObject==null` 的角色）的对话树结构完全不同。

**SandBox.dll 反编译**（`ConversationMissionLogic` 类的对话注册）：

```
模板 NPC 对话流：
start ─┬─ town_or_village_start (随机闲话) ──→ town_or_village_talk
       │                                            │
       │              ┌─────────────────────────────┤
       │              ├─ town_or_village_talk_children (问候) → town_or_village_player ✅
       │              ├─ town_or_village_talk (童谣) → town_or_village_player_children_post_rhyme
       │              └─ town_or_village_talk_beggar → close_window
       │
       ├─ town_or_village_start_postrumor ──→ town_or_village_player (已传谣后才走)
       ├─ town_or_village_start_postrumor_liege ──→ town_or_village_player
       ├─ town_or_village_start_postrumor_tavern ──→ town_or_village_player
       └─ town_or_village_talk_to_disguised_character ──→ close_window
```

玩家选项 token 对照表：

| NPC 类型 | 对话入口 | 玩家选项 token |
|----------|----------|---------------|
| 有名 Hero（领主、名人） | `start` | **`hero_main_options`** |
| 模板 NPC（农夫、市民） | `start` | **`town_or_village_player`** |
| 童谣儿童 | `start` | `town_or_village_player_children_post_rhyme` |
| 强盗 / 士兵 / 雇佣兵 | `start` | （各自专属分支，待反编译） |

**核心结论：`start` 是所有 NPC 类型的统一对话入口。**

### 坑 2：`Hero.OneToOneConversationHero` 对模板 NPC 返回 null

`ConversationManager.OneToOneConversationHero` 只在对话对象是有名 Hero 时非 null。
模板 NPC 没有 `HeroObject`，此属性返回 **null**。

**连锁反应**：

```
OneToOneConversationHero == null
  → npc.CurrentSettlement == null  （因为 npc 是 null）
  → ActiveEvent == null            （找不到活跃犯罪事件）
  → 所有 INTENT:Threat / INTENT:CharmDefense 等依赖 ActiveEvent 的选项
    Evaluate() 返回 Hide()
  → BuildOptionCondition 把 Hidden 选项从 CurOptions 中过滤掉
  → 玩家看到的选项不完整
```

**修复**（`BuildOptionCondition`）：

```csharp
// 错误写法
var npc = Hero.OneToOneConversationHero;
var settlement = npc?.CurrentSettlement;  // ← 模板 NPC 时 null

// 正确写法：Settlement.CurrentSettlement 在 Mission 场景中会被引擎设置
var settlement = npc?.CurrentSettlement ?? Settlement.CurrentSettlement;
```

### 坑 3：依赖 ActiveEvent 的 Intent 不适用于 Alert 场景

`ThreatIntent.Evaluate()` 原来第一行就：

```csharp
if (ctx.ActiveEvent == null) return Eligibility.Hide();
```

但警戒质问（Alert L3）触发于"玩家蹲下/拔刀/偷窃"，不一定有犯罪事件。
纯行为威慑场景下 ActiveEvent 为 null，导致"挑衅"选项永远不显示。

**修复**：无 ActiveEvent 但 `IsInMission == true`（Alert 场景）→ `Show()` 而非 `Hide()`。
`OnSuccess` / `OnFail` 用 null-guard 区分有无事件的逻辑分支。

### 经验：两种注入模式的选择

| | InjectScript（开场白后塞入） | InjectScriptAsOpening（替换开场白） |
|---|---|---|
| 注入点 | `InjectAtToken`（默认 `hero_main_options`） | `InjectAtToken`（默认 `start`） |
| 对话流 | Token → [PlayerLine 网关] → [NPC 台词] → [选项] | Token → [**NPC 台词 优先级200**] → [选项] |
| NPC 兼容性 | 必须知道目标 token（不同 NPC 类型不同） | **全 NPC 类型通用**（`start` 是统一入口） |
| 适用场景 | 玩家主动找 NPC（犯罪对话，已知 token） | **NPC 主动找玩家**（警戒质问，NPC 类型未知） |

**原则**：不知道 NPC 类型 → `InjectScriptAsOpening` 挂在 `start`。这是唯一不需要
反编译查 token 的通用解法。
