## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 粒子能纯文本写吗？ | ✅ **能**，全 XML，不用开编辑器 |
| 一个 emitter 多大？ | **固定 21 个 flag + 55 个 parameter**（2026-09-21 对原版 6 个已注册文件 **487 个 emitter** 复核：无一例外；唯一例外是 basic 里占位用的 `invalid_particle` 56 参数。死档 `particle_systems2.xml` 是旧格式 17/38，别当模板）→ **必须用生成器写** |

| three.js 能复现吗？ | ✅ 能。粒子用 `Points` + 自定义 shader；混合模式用 `CustomBlending` 对齐 |

## 一、XML 格式

### 1.1 文件结构

```xml
<particle_effects>
  <effect name="lwn_yinmo_charge" guid="{GUID}">
    <emitters>
      <emitter name="core" _index_="0">
        <flags>      …21 个 <flag name= value=/>…      </flags>
        <parameters> …55 个 <parameter …/>…            </parameters>
      </emitter>
    </emitters>
  </effect>
</particle_effects>
```

- 一个文件可放**多个 `<effect>`**（原版 `particle_systems_general.xml` 放了 27 个）
- 一个 effect = **一个发射原点**。多段式技能（蓄力→爆开→飞行）原点不同 → **必须拆成多个 effect**，由代码按时间线依次 Spawn
  - 引擎有 `activation_delay`，但那只延迟**同一原点**的 emitter，跨原点做不到

### 1.2 参数的四种类型（看属性就知道是哪种）

| 类型 | 写法 | 语义 |
|---|---|---|
| **常量** | `<parameter name="gravity" value="0,0,-1" />` | 固定值 |
| **随机** | `<parameter name="particle_life" base="1.3" bias="0.4" />` | 每颗粒子在 `base ± bias` 内随机 |
| **曲线** | `<parameter name="particle_size" base=".25" bias=".25"><curve …/></parameter>` | `base ± bias` **再叠一条生命曲线** |
| **颜色** | `<parameter name="particle_color"><color><keys/></color><alpha><keys/></alpha></parameter>` | 颜色 + 透明度各一条曲线 |

### 1.3 曲线（`<curve>` / `<keys>` / `<key>`）

```xml
<curve name="particle_life" version="1" default="1.000" curve_multiplier="0.300">
  <keys>
    <key time="0.000" value="1.000" tangent="0.193, 0.000" />
    <key time="1.000" value="0.667" tangent="-0.193, 0.000" />
  </keys>
</curve>
```

- `name` = **归一化基准**：`particle_life`（按粒子一生 0→1）或 `emitter_life`（按发射器一生）
- `time` ∈ [0,1]，`value` = 该时刻的输出，`tangent` = 切线（引擎用 Hermite 插值）
- `curve_multiplier` = 曲线输出再乘的系数
- `default` = 曲线缺省时的取值
- 尺寸走加法还是乘法看 `particle_size_curve_op`（`add` 624 处 / `multiply` 188 处）

### 1.4 完整字段表

**21 个 flag**（全部 `name= value="true|false"`）：
`emit_while_moving` / `dont_emit_while_moving` / `emit_at_once` / `local_emit_dir` / `loop_sprite` /
`uses_sprite_animation` / `scale_with_respect_to_emitter_velocity` / `skew_with_respect_to_particle_velocity` /
`spherical_normals` / `emit_on_terrain` / `select_random_sample_mesh` / `fixed_billboard_direction` /
`order_by_distance` / `select_random_sprite` / `create_decal_on_collision` / `create_decal_only_once` /
`randomize_collision_decal_rotation` / `permanent_collision_decals` / `collide_with_objects` /
`use_color_from_terrain` / `enable_collision`

**55 个 parameter**（**顺序即原版顺序，不要重排** —— 保持同序才能让 diff 只显示真正改动的行）。常用的：

| 参数 | 作用 |
|---|---|
| `emission_rate` | 每秒发射数（`emit_at_once=true` 时忽略） |
| `particle_life` / `emitter_life` | 粒子/发射器寿命（秒） |
| `emit_sphere_radius` + `emit_volume_type` | 发射体：球半径 / 盒体积。moduleData 里只出现过 `box`(106) 与 `sphere`，但**引擎还认 `disc`**（`Native/Prefabs/*.xml` 3 处写了 `emit_volume_type="disc"` + `emit_disc_radius`）⇒ 「只有两种」**不成立**（2026-09-22 更正） |
| `emit_velocity_x/y/z` | 初速分量（各向同性就三个填一样） |
| `gravity` | 重力向量 `x,y,z` |
| `damping` / `angular_damping` | 速度/角速度阻尼（每秒衰减） |
| `particle_size` | 尺寸（base±bias + 曲线） |
| `material` | **贴图 + 混合模式**（见 §二） |
| `inherit_emitter_velocity` | 粒子继承发射器速度的比例（**0~1，做尾迹的关键**） |
| `billboard_type` | `3d`(525) / `turn_to_velocity_side`(247) / `2d`(36) / `none`(4) |
| `texture_sprite_count` | 🔴 **图集行列数**（`"2, 2"` = 贴图里 4 个精灵，每颗随机取一格） |
| `max_alive_particle_count` | 上限（**整数**，别写成小数） |
| `particle_color` | 颜色 + 透明度曲线 |
| `emissive_multiplier` / `diffuse_multiplier` | 自发光/漫反射倍率（发光类调高） |
| `emission_turbulence_*` | 发射湍流（抖动） |
| `sample_mesh` + `select_random_sample_mesh` | **从任意网格表面发射** → 做球壳、月牙形粒子带的正解 |

## 二、🔴 材质决定混合模式（最容易翻车的一条）

`material` 不只是贴图 —— **它同时决定这颗粒子怎么和背景合成**。2026-09-18 对 Native 41 个 `prt_shd_*` 材质全量实测：

| blend | 数量 | 代表材质 | 效果 |
|---|---|---|---|
| `add_modulate_combined` | 28 | `prt_shd_smoke_1` | 叠加 + 调制（发光） |
| **`modulate`** | **9** | **`prt_shd_haze_1`**（同为 smoke_d 贴图） | **乘法压暗 → 能出黑烟** |
| `add_alpha` | 4 | `prt_shd_steam_1` | 常规半透明 |

**同一个 `smoke_d` 贴图，换材质名就从「发光」变「黑烟」。** 不用自制材质。

`modulate` 族九个：`prt_shd_dust_1` / `prt_shd_fire_haze_1` / `prt_shd_fire_nm` / `prt_shd_haze_1` /
`prt_shd_rain_mud_1` / `prt_shd_rose_a` / `prt_shd_snow_dust_1` / `prt_shd_waterfall_dust` / `prt_shd_water_wave_1`

## 三、three.js 复现

### 3.1 解析（`preview.template.html`）

`DOMParser` 按 `application/xml` 解析 → 遍历 `particle_effects > effect > emitters > emitter` →
按 §1.2 的四种类型分流成 `num` / `rnd` / `curves` / `color`+`alpha`。

曲线取样用 **smoothstep 近似**（引擎用切线 Hermite，视觉差别很小但不是逐位一致 —— 预览够用）。

### 3.2 模拟（每帧）

```
发射:   acc += emission_rate * dt
        当 acc >= 1 且 存活数 < maxAlive → 生成一颗粒子
生成:   位置 = 原点 + 球/盒体积内随机
        速度 = emit_velocity(±bias) + 发射器速度 × inherit
        寿命 = particle_life(base ± bias)
更新:   v *= exp(-damping*dt);  v += gravity*dt;  p += v*dt;  age += dt
        死亡 → 移除
```

**发射器速度** = 挂点（骨骼/飞行物）每帧的位移差 ÷ dt。`inherit_emitter_velocity` 就是粒子继承它的比例 —— **做尾迹的关键旋钮**（见 §四 坑 5）。

### 3.3 渲染：`THREE.Points` + 自定义 shader

```glsl
// vertex
attribute float aSize; attribute float aAlpha; attribute vec3 aColor;
uniform float uScale;                       // = (画布高/2) / tan(fov/2)
void main(){
  vec4 mv = modelViewMatrix * vec4(position, 1.0);
  gl_PointSize = max(1.0, aSize * uScale / max(0.001, -mv.z));   // aSize 是世界尺寸(米)
  gl_Position = projectionMatrix * mv;
}
// fragment
uniform sampler2D uTex;
void main(){ vec4 t = texture2D(uTex, gl_PointCoord);
  if (t.a < 0.004) discard;
  gl_FragColor = vec4(vColor, t.a * vAlpha); }
```

🔴 `uScale` 必须按画布高度算，否则粒径差 100 倍（踩过）。`aSize` 传**世界米数**，不要再乘系数。

**贴图**：`smoke_d` 是 **2×2 图集**（`texture_sprite_count="2, 2"`）—— 必须按格切，每颗随机取一格。整张当单颗用 = 画出一坨多瓣的灰块（踩过）。

### 3.4 混合模式映射（关键）

| XML 的 blend | three.js |
|---|---|
| `add` | `AdditiveBlending` |
| `alpha` | `NormalBlending` |
| **`modulate`** | `CustomBlending` + `blendSrc: ZERO, blendDst: SRC_COLOR`，片元输出 **`mix(vec3(1.0), color, a)`**（a=0 输出白=乘 1 不变；a=1 输出颜色=压暗） |
| `add_modulate_combined` | 近似 = **常规 alpha 混合 + 一份加法增益**（`region = region*(1-a) + color*a*1.55`） |

🔴 **`add_modulate_combined` 不能当成纯加法做**：纯加法在**亮背景**上几乎不可见（加法只能变亮，亮底已经亮了）——踩过，爆开阶段整段空白。

### 3.5 泛光后处理（决定"像不像游戏"）

three.js r128 的 UMD 包**不含 `EffectComposer`**，自己写三趟：

```
场景渲到离屏 RT
  → 亮部提取（阈值 ~0.86）
  → 三级降采样高斯模糊（1/2、1/4、1/8）
  → 加法合成 + 软性色调映射  c/(c+0.95)*1.22
```

参数经验：**阈值低了整个画面都在发光**（0.62 时地面全白过曝），**强度高了糊成一片**。起步用 `threshold 0.86 / strength 0.30`。

### 3.6 替身网格（XML 表达不了的）

粒子做不出来的几样，用 mesh + shader 代演，**并在文档里标明"实机需要网格/shader"**：

| 元素 | 做法 |
|---|---|
| 体积球壳 | 球体 mesh + 菲涅尔边缘光 + 经线流动 + 3D 噪声 |
| 暗色日冕 | 🔴 **朝向相机的径向渐变贴片**（不是球！球+菲涅尔会变成吞掉本体的灰球） |
| 月牙弧 | 环形扇几何 + 沿弧渐变 + 跨厚度软边 |
| 人形 | 圆柱/球的剪影，**只提供尺度感**（线宽要做投影换算，否则 1.8m 的人只剩 2px） |

## 四、坑点清单（全是本次踩出来的）

| # | 坑 | 症状 | 正解 |
|---|---|---|---|
| 1 | `texture_sprite_count` 是图集 | 多瓣灰块 | 按 `cols×rows` 切格，`select_random_sprite` 每颗随机取一格 |
| 2 | 纯加法在亮背景不可见 | 亮底上特效凭空消失 | 用 `add_modulate_combined` 的语义（alpha + 加法增益），别只做加法 |
| 3 | `modulate` 是乘法**连乘** | 多颗粒子重叠 → 饱和成死黑 | 压暗类 **alpha 峰值压到 0.4 上下**（发光类可到 0.9） |
| 4 | 尺度失控 | 烟团比人还高 | **以人形 1.8m 为基准**定 `particle_size`：核心≈头大(0.35m)、烟团≈半人高(0.7m)、球壳半径≈两人高(3.7m) |
| 5 | `inherit_emitter_velocity` 给太低 | 尾迹跟不上主体，堆成原地一坨 | 尾迹类给 **0.85~1.0** + 低阻尼(0.1~0.3) → 粒子跟着飞再慢慢落后 = 拉出痕迹 |
| 6 | 给剑气加重力/抛物线 | 像块石头飞出去 | **剑气/能量类零重力 + 直线弹道** |
| 7 | 几何体朝向 | 平面月牙侧对镜头 = 一条线 | 躺在 XY 平面的片**不要 `lookAt` 飞行方向**（那会让法线平行于视线）；要`lookAt` 就 `lookAt` 相机 |
| 8 | 相机跟飞行物太紧 | 特效整段飞出画面（投影坐标 1481 而画布才 1100 宽） | **固定取景**（人+特效同框），或大幅缩小飞行距离 |
| 9 | 过曝 | 整幅发白、主体被冲没 | 环境色别用近白；色调映射只压缩不提亮；bloom 阈值抬高 |
| 10 | `max_alive_particle_count` 写成小数 | 引擎按 int 解析可能失败 | 整数参数一律整数字面量 |
| 11 | 参数顺序被重排 | diff 全是噪音 | 生成器**按原版顺序**输出 |

## 五、自检闭环（能自己看图，效率差一个量级）

**没有截图通道时改这种视觉东西等于盲改。** 两条路：

1. **离屏静帧渲染** —— `tools/particle-pipeline/preview/render_still.py`
   用 numpy 重实现同一套规则，渲成 PNG。**不依赖浏览器**，但只画粒子和替身网格（无 shader/泛光）。
   阶段/锚点/相机这些 XML 里没有的演出参数走同名 sidecar（`<xml>.view.json`），没有就自动模式。
2. **浏览器 headless 截图**（推荐）
   ```bash
   chrome --headless=new --user-data-dir=<临时目录> --window-size=1280,720 \
          --hide-scrollbars --screenshot=out.png --virtual-time-budget=2500 \
          "file:///…/preview.html?t=3.4"
   ```
   - `--user-data-dir` 必须独立，否则会去开用户已运行的 Chrome
   - **虚拟时间推得比预期慢** → 页面加了 **`?t=` 参数直跳指定时刻**（加载后快进 + 暂停）

### 8.1 结论速览

| 问题 | 结论 |
|---|---|

| 靠什么解析？ | **UE4.27 编辑器无头跑 Python** → 用 `ObjectExporterT3D` 把资产导成 **T3D 文本** → 自己写解析器 |

### 8.2 四条解析路线的实测对比（选型依据，别再重走）

| 路线 | 实测结果 | 原因 / 证据 |
|---|---|---|
| ① UE Python API 读 Niagara | ❌ **不可行** | 4.27 的 Niagara 运行期类**几乎没有脚本绑定**：`dir(unreal.load_asset("…NS_Fireball"))` 只有 24 个通用 UObject 方法；`get_editor_property("emitter_handles")` 直接报 `Failed to find property 'emitter_handles'`。`unreal` 模块里 Niagara* 有 133 个名字，但都是工厂/枚举/C++ 类型，不是可读句柄 |
| ② UE Python API 读 Cascade | ❌ **不可行** | `ParticleSystem.Emitters` 是 **protected**，Python 报 `Property 'Emitters' … is protected and cannot be read`（能调的只有 `contains_emitter_type()` 这种 helper） |
| ③ 直接读 `.uasset` 的 Names 表（`strings` / 二进制扫描） | ⚠️ **半可用** | 能拿到**模块配方**与材质引用，**但拿不到数值**。例：`/Niagara/Modules/Emitter/SpawnRate`、`/Niagara/Modules/Spawn/Location/V2/SphereLocation`、`ColorFromCurve`、`ENiagara_SpriteRotationMode`、`TilingCurl32`、`DefaultSpriteMaterial`。适合做「这是什么特效」的快速判读，不能做数值复刻 |
| ④ **`ObjectExporterT3D` 导出 T3D 文本** | ✅ **全可用（本方案）** | T3D 是 UE 原生**文本**序列化格式。一次导出同时拿到：节点图（`FunctionScript` / `PinName` / `DefaultValue`）+ **数值常量（含字节流）** + 渲染器（`Material` / `Alignment` / `SubImageSize`）+ **曲线关键帧**（`Time/Value/ArriveTangent/LeaveTangent`）+ Cascade 的全部 `Distribution*` 数值 |

**结论：想解析 UE 粒子，别碰 Python API，直接上 T3D 文本导出。**

### 8.4 T3D 的结构长什么样（解析器要按这个写）

```
Begin Object Class=/Script/Niagara.NiagaraSystem Name="NS_Fireball"
   Begin Object Class=/Script/Niagara.NiagaraEmitter Name="Embers001_10"
      Begin Object Class=/Script/NiagaraEditor.NiagaraScriptSource Name="NiagaraScriptSource_0"
         Begin Object Class=/Script/NiagaraEditor.NiagaraGraph Name="NiagaraGraph_0"
            Begin Object Class=/Script/NiagaraEditor.NiagaraNodeFunctionCall Name="NiagaraNodeFunctionCall_3"
               FunctionScript=NiagaraScript'"/Niagara/Modules/Emitter/SpawnRate.SpawnRate"'
               FunctionDisplayName="SpawnRate"
               CustomProperties Pin (PinId=…,PinName="Use Spawn Probability",…,DefaultValue="false",…)
            End Object
         End Object
      End Object
      Begin Object Class=/Script/Niagara.NiagaraScript Name="EmitterUpdateScript"
         RapidIterationParameters=(SortedParameterOffsets=(…),ParameterData=(0,0,0,0,…),DebugName="…")
      End Object
      Begin Object Class=/Script/Niagara.NiagaraSpriteRendererProperties Name="NiagaraSpriteRendererProperties_0"
         Material=MaterialInstanceConstant'"/Game/FlexibleCombatSystem/VFX/Materials/MI_Embers.MI_Embers"'
         Alignment=VelocityAligned
         SubImageSize=(X=2.000000,Y=2.000000)
      End Object
   End Object
End Object
```

🔴 **T3D 会把同一个对象序列化两次**：第一次是**空壳**（只有 `Begin/End Object`），第二次才带属性。
所以解析时必须**按对象名合并**，不能「取首现」——否则：
- 模块名会变成 `NiagaraNodeFunctionCall_3` 而不是 `SpawnRate`（因为 `FunctionScript` 在第二次出现里）
- Cascade 的 `Modules(0..N)` 全丢

🔴 **数组型属性必须保下标**：`Modules(0)=…` / `Modules(1)=…` 如果只用 `Modules` 当键，后面的会覆盖前面的。
解析时要存成 `Modules(0)`、`Modules(1)`…（键名带下标）。

### 8.5 🔴 数值藏在哪：`RapidIterationParameters` 的字节流解码

Niagara 的**数值字面量**不在图上的 pin 里，而在每个 `NiagaraScript` 的
`RapidIterationParameters` 里 —— 一份「命名常量 + 字节偏移 + 字节流」的表：

```
RapidIterationParameters=(
  SortedParameterOffsets=(
     (Offset=0 ,Name="Constants.Embers001.EmitterState.Loop Delay"   ,TypeDefHandle=(RegisteredTypeIndex=55)),
     (Offset=4 ,Name="Constants.Embers001.EmitterState.Loop Duration",TypeDefHandle=(RegisteredTypeIndex=55)),
     (Offset=8 ,Name="Constants.Embers001.EmitterState.MaxDistance"  ,TypeDefHandle=(RegisteredTypeIndex=55)),
     (Offset=12,Name="Constants.Embers001.EmitterState.MinDistance"  ,TypeDefHandle=(RegisteredTypeIndex=55)),
     (Offset=16,Name="Constants.Embers001.SpawnRate.Spawn Probability",TypeDefHandle=(RegisteredTypeIndex=55)),
     (Offset=20,Name="Constants.Embers001.SpawnRate.SpawnGroup"      ,TypeDefHandle=(RegisteredTypeIndex=57)),
     (Offset=24,Name="Constants.Embers001.SpawnRate.SpawnRate"       ,TypeDefHandle=(RegisteredTypeIndex=55))),
  ParameterData=(0,0,0,0, 0,0,128,63, 0,64,156,69, 0,0,0,0, 0,0,128,63, 0,0,0,0, 0,0,112,65),
  DebugName="NiagaraScript …:EmitterUpdateScript")
```

解码规则（**已验证**）：

1. `ParameterData` 是**十进制字节序列**（0~255），不是十六进制
2. 每项按 `Offset` 切片；**尺寸优先用「下一个 Offset − 当前 Offset」推断**，最后一项用类型表兜底
3. `RegisteredTypeIndex` → 类型：`55=float(4)` / `57=int32(4)` / `59=Vector2D(8)` / `60=Vector3(12)` / `62=LinearColor(16)` / `53,54=half(2)` / `58=bool(1)`
4. 小端 `float32` 解

上面那段的解出来是：`Loop Delay=0.0` / `Loop Duration=1.0` / `MaxDistance=5000` / `MinDistance=0` /
`Spawn Probability=1.0` / `SpawnGroup=0` / **`SpawnRate=15.0`**（`00 00 70 41` → 0x41700000 → 15.0f ✅）。

常量名是**三段式**：`Constants.<Emitter 基名>.<Module>.<Input>`。

🔴 **基名 ≠ 图里的节点名**：图里的 emitter 叫 `Embers001_10`，但常量前缀是 `Constants.Embers001.`。
按节点名拼前缀去匹配会**全部取不到值**（症状：所有参数都退回默认模板）。
正确姿势：**前缀无关匹配** —— 拿 `Constants` 与 emitter 段之后的 `Module.Input` 去比。

### 8.6 参数映射表：UE(Niagara / Cascade) → 骑砍 XML

| 骑砍 XML 参数 | Niagara 来源 | Cascade 来源 | 换算 |
|---|---|---|---|
| `emission_rate` | `SpawnRate.SpawnRate` | `ParticleModuleSpawn.Rate` | 直接（/s） |
| `particle_life` `base`/`bias` | `InitializeParticle.Lifetime Min/Max` | `ParticleModuleLifetime.Lifetime` | `base=min, bias=max-min` |
| `emitter_life` | `EmitterState.Loop Duration` | `ParticleModuleRequired.EmitterDuration` | 秒 |
| `emit_volume_type` + `emit_sphere_radius` | `SphereLocation` 存在 → sphere | `ParticleModuleLocationSphere` | 半径 ÷100 |
| `emit_velocity_x/y/z` | `AddVelocity.Velocity` | `ParticleModuleVelocity.StartVelocity` | ÷100，`bias≈|base|×0.2` |
| `emission_speed_limit` | `SolveForcesAndVelocity.Speed Limit` | — | ÷100 |
| `gravity` | `GravityForce.Gravity` | `ParticleModuleAcceleration.Acceleration` | **×1/980**（UE 惯用 −980 cm/s² ↔ 骑砍默认量级 −1） |
| `damping` | （无，留默认 0.733） | `ParticleModuleAccelerationDrag.DragCoefficient` | 直接 |
| `turbulence_strength` | `CurlNoiseForce.Noise Strength` | — | ÷100，**近似**（骑砍没有 curl noise） |
| `particle_size` / `size_curve` | `ScaleSpriteSize` + `Vector2DFromCurve` 的 `XCurve/YCurve` | `ParticleModuleSize.StartSize` | ÷100 |
| `particle_color`(color/alpha) | `NiagaraDataInterfaceColorCurve` 的 `Red/Green/Blue/AlphaCurve` | `ParticleModuleColor.StartColor` + `ColorOverLife/AlphaOverLife` | 曲线关键帧直接搬 |
| `material` | `NiagaraSpriteRendererProperties.Material` | `ParticleModuleRequired.Material` | 🔴 **必须换名**，见 §8.7 |
| `texture_sprite_count` | `SubImageSize=(X,Y)` | `SubImages_Horizontal/Vertical` | `(X,Y)` → `"X, Y"` |

朝向映射：

| UE | 骑砍 `billboard_type` |
|---|---|
| `VelocityAligned` / `PSA_Velocity` | `turn_to_velocity_side` |
| `ScreenAligned` / `PSA_Square` / `PSA_FacingCameraPosition` | `2d` |
| `Automatic` / `FaceCameraPlane` / `PSA_None` | `3d` |

曲线直接可搬：Niagara 的 `Keys=((InterpMode=RCIM_Cubic,Time=0.200000,Value=1.000000,ArriveTangent=0.625000,LeaveTangent=0.625000),…)`
→ 骑砍的 `<key time= value= tangent="Arrive,Leave"/>`（**切线语义天然对应**，这是最省事的一环）。

### 8.8 三条「不变量」（照抄会翻车）

| # | 不变量 | 症状 | 正解 |
|---|---|---|---|
| 1 | **UE 是 cm，骑砍是 m** | 烟团比人高 100 倍 | 长度/速度/半径 **÷100**；只有加速度类走 `×1/980` |
| 2 | **UE 颜色常是 HDR（>1）** | 闪电 `(0, 47.8, 50)` 直接写进 XML → 饱和成白团 | 取 `max(r,g,b) > 1` 时**除以该 max** 归一，再夹到 [0,1] |
| 3 | **Niagara 的「纯黑」= 颜色交给材质** | 余烬/火星被刷成黑炭 | `Color.Color ≈ (0,0,0)` 且无 `ColorFromCurve` 时**不要覆盖** `particle_color`，沿用默认 |

另外：`select_random_sprite` 是 **flag 不是 parameter**，写进参数区会被生成器直接 `KeyError` 拒绝
（`gen_particle_effect.py` 的 flag 白名单校验，这是它的优点，别绕过）。

## 九、从录像反推特效参数（2026-09-21，`阴魔斩.mp4`）

### 9.1 为什么要立这一条

手上有 UE 工程时可以走 §8 那条路（T3D → parsed → spec → XML）；**没有工程、只有一段录像**时，
录像反而是最可靠的参考源——尤其当它是「同一技能多次释放 + 多机位」的演示片：
多机位能互相补全被遮挡的结构，多次释放能看出哪些是随机、哪些是固定。

### 9.2 三条可复现的方法（别凭肉眼估）

| 方法 | 怎么做 | 本次实测 |
|---|---|---|
| ① **尺子 = 角色** | 挑一帧角色全身清晰、效果也在同框的帧，量「头顶→脚底」像素数，除角色身高（UE5 小白人 ≈ 1.8 m），得到 **px/m**；此后所有尺寸都换算成米 | 12.00s 帧：头顶 252 → 脚底 657 = **405 px = 1.8 m → 225 px/m（1 px = 4.44 mm）** |
| ② **取色 = 掩膜** | 对每帧做「高亮红」「品红」掩膜（如 `R>225 & R-G>60 & R-B>55`），取**最大连通块**的均值与 p95；比肉眼/取色器可靠，也能顺带量出 bbox | 白热核 (246,150,135)/p95 (255,194,185)；绯红亮盘 (241,142,143)；品红飘带 (202,146,185)/p95 (255,181,216) |
| ③ **先粗后密抽帧** | 先 1 fps 抽满全片 → 算**帧差能量曲线**找"动作窗口"→ 再在窗口内按 0.25 s 补密看分解 | 45.1 s 里 **约 10 次施法**（1.2 / 6.5 / 12.4 / 22.0 / 25.0 / 27.4 / 32.2 / 34.0 / 37.0 / 43.0 s），单次循环 ≈ 1.5 s 蓄力 + 0.6~0.9 s 掷出飞行 + 1.5~2.6 s 余韵 |

> 用 `cv2.VideoCapture.set(CAP_PROP_POS_FRAMES, t*fps)` 定点抽帧最省事（不用装 ffmpeg）。
> 合成"九宫格 + 时间戳"的对照图再交给视觉模型，比逐帧单看快一个量级。

### 9.4 🔴 骑砍粒子做不出「月牙」——本次最重要的边界认识

录像里的月牙在 UE 侧是 **Mesh（月牙片）/ Flipbook ribbon**；骑砍没有 mesh 渲染器、也没有 ribbon emitter
（已实证：`bin` 全量 grep 无 `ParticleMesh` / `RibbonRenderer` 命中；`billboard_type` / `sample_mesh`
只在 `TaleWorlds.Native.dll` 里解析）。所以**常规粒子方案**只能做出「弧形冲击波 / 彗尾」，
**读作斩击波，读不出月牙**（已用静帧自检确认：`out/final_*.png` 里残迹段是一团"亮核 + 拖烟 + 余烬"的彗尾）。

> ⚠️ **别把这条说满（README §4.2 已更正）**：发射体除 box / sphere 外**还有第三种 `sample_mesh`**
> ——「从任意网格表面采样发射」，原版自己在用（`prt_pot_pile` 10 处 · `prt_wood_parts2` 9 ·
> 攻城塔残骸 6 · `prt_foam_a` 2 · `generic_particle_3d` 2）。即**结论对、理由错**：
> 做不出来的只是**参考图那种薄、有厚度、边界锐利的立体月牙**，而"**月牙形粒子带**"是能做到的
> ⇒ 路线 C 优先级最高。完整判据表见 **README §4.2**。

三条路线（由易到难，**都没实机验证**）：

| 路线 | 做法 | 代价 / 风险 |
|---|---|---|
| **A 纯粒子近似**（已做） | `crescent_edge`：`billboard_type=turn_to_velocity_side` + `inherit_emitter_velocity≈0.94`，让粒子沿速度铺成 0.3 m 宽的带 | 只能得到"弧形彗尾"，不是月牙；优点是零新增资产、立刻能进内容包 |
| **B 自制月牙贴图 + 单 quad** | 生成一张 256² RGBA 月牙（RGB 恒白 + alpha 载形状，见 §四 坑 2），配 `prt_shd_glow`/自建材质，用 1 个大粒子（`particle_size ≈ 3.6 m`）承担整条月牙，靠 `fixed_billboard_direction` 永远正对相机 | 需要能加材质（`soln_particle_systems` 注册本身就没验证过，见 §8.11）；单 quad 无厚度，侧面看会"翻片" |
| **C `sample_mesh` 撒点成弧** | 引擎有 `sample_mesh` 参数 + `select_random_sample_mesh` flag —— 可以拿一个**月牙 mesh 当发射形状模板**，把粒子撒在月牙面上，得到真正的月牙形粒子阵（mesh 本身不渲染） | 要能给内容包塞 mesh 资产并让粒子系统引用；这条**最接近原效果**，优先级最高去试 |

> 顺带：录像里月牙四周那层**半透明粉紫"面"**同样是 shader/mesh 属性，粒子只能靠
> `prt_shd_steam_1`（add_alpha）大面积低 alpha 近似 —— 本次 13 emitter 里没塞它，需要时再加一个。
