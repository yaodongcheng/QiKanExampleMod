## 0. 第一件甲（2026-09-14）

**源件**：`D:\BrainMaker\战国无双2资产解包分析\export\fbx\L00_yukimura.fbx`
（16 网格 = 3 布料驱动 + 2 武器 + 11 角色件；骨架 124 骨，骨名是无语义的 `bone_N`）

**部位归属**（逐件单显渲染坐实）：兜 / 胴 / 草摺 / 佩楯 / 脛当+靴 / 袖+籠手 / 着物内衬 / 脸 / 皮肤 / 眼

**成品**：`taikou_yukimura_do_a` = 胴 + 草摺 + 佩楯 + 袴 + 脛当 + 靴 + 内衬着物，1089 顶点 / LOD0~5。

### 🔴 两条与 §2.3 原裁定不同的决定（都因"这次素材自带绑定"）

| 项 | 原裁定（§2.3） | 本件做法 | 理由 |
|---|---|---|---|
| **权重来源** | 从原版身体最近点抄 | **用源模型自带的权重重定向，只换骨名** | 源件是绑定过的，权重是美术做的。改从身体抄的话，草摺（甲裙）会被"就近"吸到单侧大腿，走路左右撕扯、硬片被掰弯 |
| **身体参照物** | 原版当基准 | 不变，但**两侧骨骼比例不同**（源件腿长约长 10%、躯干约短 1%） | 用统一径向缩放 `R` 吸收；实测 `R=0.0120` 才不露身体 |

### 新发现的两条硬事实（写代码前必须知道）

1. 🔴 **两个模型的"正面"可能相反**。本例源件正面 = **−Y**（脚趾/面部骨/前垂草摺全在负侧），
   骑砍 = **+Y**（脚趾在脚踝正侧；渲染身体可见胸肌面朝 +Y）。**必须做 Y 轴镜像**，
   不能用 180° 绕 Z 旋转（那会连左右一起翻）。镜像是反射，**做完要反转面绕序**。
2. 🔴 **骑砍 `bone.matrix_local` 的骨轴不沿肢体**（`spine_9` 头 z=1.0064、尾 y=+0.157，指向正前方）。
   拿它当旋转做重定向 → 甲整个转歪。**旋转只能从关节位置推**，且**只给手臂链推**
   （源件 T-pose、骑砍 A-pose，差 33.5°）——给每根骨都推会因垃圾朝向互相打架而切变。

## 2. 参考物裁定：原版当基准，织丰当看样（2026-09-14 实测）

### 2.1 先纠一个错判：两个身体其实一样大

初判是「织丰用自建身体（`body_male_japanese`）、我们用原版身体 → 织丰甲不能当基准」。**实测推翻了**：

| 男体（三件拼装后） | 宽 | 高 | 深 |
|---|---|---|---|
| 原版 `body_male_a` + `feet_male_a` + `hands_male_a` | 1.5996 | 1.5438 | 0.2975 |
| 织丰 `body_male_japanese` + `feet_male_japanese` + `hands_male_japanese` | 1.5973 | 1.5202 | 0.2866 |
| **差** | **−2.3 mm（0.14%）** | **−23.6 mm（1.53%）** | −10.9 mm（3.7%） |

**同尺度。** 织丰身体不是"另一个人种体型"，是拿原版改的。

真正不一样的是**分件切法**：

| | 原版 | 织丰 |
|---|---|---|
| 切法 | `body_male_a` **一件**包住 躯干 + 双臂 + 腿 | 拆**三件**：`body_*`(纯躯干) / `hands_*`(整条手臂) / `feet_*`(小腿) |
| LOD | **6 层**（0..5） | **0 层** |
| 原版各件 bbox | 躯干+臂+腿 `x±0.5990 z[0.381,1.544]`；肩 `body_male_a_sh x±0.2083 z[1.285,1.544]`；脚 `feet_male_a z[0.001,0.399]`；手 `hands_male_a x±0.7998 z[0.967,1.190]` | 躯干 `x±0.2891 z[0.803,1.523]`；肩 `x±0.2891 z[1.180,1.523]`；脚 `z[0.003,0.851]`；臂 `x±0.7986 z[0.969,1.398]` |

> ⚠️ 拿织丰身体做参照时**不能按同名部位直接对 bbox** —— 必须按三件拼装后的整体比。

### 2.3 裁定

| 参考物 | 干什么 | 为什么是它 |
|---|---|---|
| **原版甲** `aserai_cavalry_armor` | **结构模板 + 尺寸基准** | 结构最干净：**1 材质贯穿 6 层 LOD**，顶点量级合理（LOD0 1962），正是"做对"的最简范式 |
| **原版身体** `body_male_a` / `body_female_a` | **权重来源** | 甲贴在身体表面，**身体那个位置的顶点权重就是一手答案**（从另一件甲抄是二手）。已 dump 在 `Debug/offline/core_game/out/body/` |
| **织丰 `sho_okegawa_do_a_1_kimono_a`** | **日式分件看样** | 甲 + 内衬双件、LOD0~5 齐全、被多支兵种装备的标准甲 |
| **素材模型** | **轮廓形状**（唯一真源） | 日式甲长什么样由下载到的模型决定，不从游戏资产抄 |

🔴 **不要拿 `sho_new_maru_do` 当范式** —— 它 **5 件全是 Lod=0、一层 LOD 都没有**，单件 13k 顶点。这是孤例（同包的 `okegawa` LOD 是全的），照抄会直接拖垮千人战性能。

## 3. 盔甲结构规格（引擎认什么）——实测

### 3.1 LOD 层数 = **0 ~ 5，不是 0~6**

社区文档写「LOD0→LOD6，210m+ 剔除」—— **实测原版全系列都是 0..5**。交叉验证 5 个：

```
aserai_cavalry_armor         6 件  0,1,2,3,4,5
empire_plate_armor           6 件  0,1,2,3,4,5
empire_plate_armor_gauntlets 6 件  0,1,2,3,4,5
empire_plate_armor_shoulder  6 件  0,1,2,3,4,5
body_male_a（身体）           6 件  0,1,2,3,4,5
```

LOD 切换距离（社区文档，未实测）：LOD0→1 **15m** / 1→2 **22.5m** / 2→3 **30m** / 3→4 **50m** / 4→5 **70m** / 5→剔除 **130m**。

### 3.2 子网格命名

- 原版方式：`<名字>`（LOD0）+ `<名字>.lod1` … `<名字>.lod5`
- 织丰方式：引擎按材质自动拆成 `.0/.1/.2/.3/.001`（Blender 导出痕迹）

### 3.3 蒙皮三条件（与头通用，见 [蒂法换头工程.md](蒂法换头工程.md) §13.2）

| 条件 | 在哪 | 缺了会怎样 |
|---|---|---|
| **`VertexLayoutFlags` 含 `skinning`** | **材质**上 | 网格钉死在绑定姿势、**完全不跟骨架动** |
| `SkinDataSize > 0` + `BoneIndices`/`BoneWeights` | 网格 + 顶点流 | native 越界（AccessViolation） |
| 绑 `human_skeleton` | FBX 里带骨架 | 编辑器把元数据全算错 |

🔴 第一条最易漏：**它是材质属性，FBX 不携带** → 换新工程 / 重导 FBX 后必须回编辑器重勾。
原版甲 `UnknownInt2` = **20**（网格用到的骨骼数）；织丰甲是 **28**。**别拿织丰的值去刷原版结构。**

### 3.4 男女版：原版**共用一件网格**

实测：`aserai_cavalry_armor` 标了 `has_gender_variations="true"`，但**只有一个网格名**，包里也没有 `aserai_cavalry_armor_fem`。
`core_game.tpac` 里 `_converted`（社区文档说的女性版）、`_slim`（手套瘦版）**命中数均为 0** —— 那两个是**改 mod 的人自己的命名习惯**，不是原版机制。

⇒ **做日式甲不必做男女两版。**

> ⚠️ 未确证的机制：`woman` 皮肤上有 `body_mesh_suffix="_fem"`，该字符串由 **`TaleWorlds.Native.dll`（C++ 层）**消费，反编译看不到。
> 已知边界：包里没有任何 `X_fem` 形式的网格；`body_meta_mesh` 是显式写死的 `body_female_a`。**真实作用待实机验证。**

### 3.5 头盔特有：跟着脸形参数缩放

原版 `deform_key` 条目带 `helmet_scaling_factor_min` / `helmet_scaling_factor_max`，例如：

```xml
<deform_key id="face_width" key_time_point="1" key_min="-0.3" key_max="0.9"
            helmet_scaling_factor_min="-0.1, 0.0, 0.0"
            helmet_scaling_factor_max="0.02, 0.0, 0.0" />
```

⇒ **头盔会随脸宽/脸深等参数被引擎自动缩放**，做头盔时要考虑这条（做身体甲不受影响）。

## 4. 物品注册链

```
FBX ──► [ModKit 编辑器工程] ──► Publish ──► AssetPackages/packN.tpac
                                                  │  mesh= 的扁平名 = 包内资源名
Item XML「id / name / mesh / weight / Type」 ───────┘
   └─► EquipmentRoster  id="Item.<item id>"  ──► NPCCharacter ──► 兵种
```

### 4.1 注册方式 = **目录级，不用改 SubModule.xml**

Taikou 已注册（`SubModule.xml:31-45`）：

```xml
<XmlNode>
    <XmlName id="Items" path="taikou_items"/>
    <IncludedGameTypes> … TaikouCampaign / Campaign / … </IncludedGameTypes>
</XmlNode>
```

`path` 是**目录名**（无 `.xml` 后缀）→ 引擎加载该目录下**全部** XML。**新丢一个 `.xml` 进去即生效。**
（织丰同理：`<XmlName id="Items" path="items"/>`。）

`<AssetPackages>` **不需要声明** —— 全 `Modules/` 下所有 XML grep 零命中，引擎按约定自动扫。

### 4.2 `mesh=` 是扁平字符串

- 不带路径、不带扩展名，**直接就是 tpac 内的资源名**
- 实证：`sho_new_maru_do` 二进制 grep 织丰 7 个包，**只在 pack4 命中**
- **`id` 与 `mesh` 允许不同**：`id="sho_nanban_do_a"` 的 `mesh="sho_nanban_do_1"`
- 下游引用一律用 **item `id`**（`id="Item.sho_bamboo_spear"`），不是 mesh

### 4.3 Item XML 字段（实测归纳）

```xml
<Item id="sho_new_maru_do" name="{=9vQ7nAuu}Maru Do" subtype="body_armor"
      mesh="sho_new_maru_do" weight="15" difficulty="0" appearance="1.6" Type="BodyArmor">
    <ItemComponent>
        <Armor body_armor="33" leg_armor="3" arm_armor="3"
               has_gender_variations="false" covers_body="true"
               modifier_group="plate" material_type="Plate"/>
    </ItemComponent>
    <Flags UseTeamColor="true"/>
</Item>
```

| 位置 | 字段 | 说明 |
|---|---|---|
| 属性·必备 | `id` / `name`（`{=8位ID}`）/ `mesh` / `weight` / `Type` | `Type` 实测：`BodyArmor` `HeadArmor` `HandArmor` `LegArmor` `Cape` |
| 属性·常用 | `subtype` / `difficulty` / `appearance` / `value` / `is_merchandise` | `subtype` 实测：`body_armor` `head_armor`（腿/手/披风常省略） |
| `<Armor>` | `body_armor` `head_armor` `arm_armor` `leg_armor` `covers_body` `covers_legs` `has_gender_variations` `modifier_group` `material_type` `hair_cover_type` | `modifier_group`：`plate`/`chain`/`cloth`/`cloth_unarmored`；`material_type`：`Plate`/`Chainmail`/`Cloth` |
| `<Flags>` | `UseTeamColor` / `Civilian` / `DoesNotHideChest` | 板甲用 `UseTeamColor`，便服用 `Civilian` |

### 4.4 🔴 `culture` 字段：Taikou 与织丰**做派相反**

| | 写法 |
|---|---|
| **织丰** | 5 个盔甲文件里 `culture` **出现 0 次** —— 势力归属完全由「哪个兵种的 EquipmentRoster 引用它」决定 |
| **Taikou** | **写** `culture="Culture.ikoku"`（`taikou_items/body_armors.xml` 现状，v0 拷贝官方物品库带进来的约定） |

**做日式甲时保持 Taikou 现状（写 `culture`）**，别跟着织丰改成不写。

## 5. 管线（源模型 → 引擎）

```
源模型 FBX（任意来源的日式甲）
   │  ① 绑官方骨架 human_skeleton + 逐顶点权重（可从原版身体/原版甲抄）
   │  ② 分 LOD0..5（顶点递减）
   │  ③ 材质：pbr_metallic，槽位 _d / _n / _s
   │     _s 合成公式：R=金属度 / G=255−粗糙度 / B=AO
   ▼  ④ 导出：FBX_SCALE_UNITS + axis_forward='Y' + axis_up='Z' + 场景单位=米
甲 FBX ──[关卡 1] fbx_probe.py ──► ModKit 编辑器（人做：导入 → 勾 Skinning → Model Viewer → Publish）
   │
   │  [验证] tpaccli metaparts / morphinfo 量结构（LOD 层数、骨骼数、bbox）
   ▼  装机 → 写 Item XML → 挂 EquipmentRoster → 进游戏看
```

🔴 **没有"后处理补丁"这一步** —— 换头工程的 `morphfix` / `skinfix --fullmat` 是**脸部专用**（变形帧 + 脸部角色标记），**盔甲不打**。

## 6. 可复用 / 不可复用（换头工程资产）

### 6.1 直接复用

| 资产 | 用途 |
|---|---|
| `tools/face-pipeline/scripts/fbx_probe.py` | **关卡 1**：进编辑器前查 FBX 规格（USF=100 / UpAxis=2 / 网格节点零变换） |
| `tpaccli` 通用命令 | `dump`（导 OBJ/贴图）、`metaparts`（读子网格/LOD）、`morphinfo`（骨骼数/包围盒）、`meshdiff`（逐字段差分）、`assetclone`、`makepack`、`texreplace`、`inspect`、`segs` |
| **硬链接单文件加载**（见 §6.3） | 从 2.8GB / 15GB 的包里读单个资产 |
| **Assets / Assets_disabled 两态 bat** | 编辑器工程不能留给游戏读（见 §7 坑 7） |
| **权威备份 + recipe 脚本**纪律 | 源 FBX 会被 ModKit 删（见 §7 坑 3） |
| **坐标可离线量** | tpac 不存绑定矩阵，静止姿态顶点渲染在自己坐标上 → 写"关卡 2"式离线体检，别烧实机启动 |
| `--weights-from` **思路** | `build_head.py` 里"从原版同类件最近点抄权重" —— 盔甲版改成**从原版身体抄** |

### 6.2 不可复用（脸部专用）

`morphfix` / `skinfix --fullmat` / `transfer_channels.py` / `check_head_space.py` / `build_head.py` 的脸部相关部分
（4 件子网格顺序、59 条变形通道、帧序 Basis→占位→KeyTime —— 盔甲全不需要）

### 6.3 硬链接单文件加载（实测做法）

`AssetManager.Load(dir)` 会把目录下**所有** tpac 载入，所以大包要先隔离：

```powershell
# 建一个只含目标 tpac 硬链接的目录，把它当 --packdir（不额外占盘）
New-Item -ItemType HardLink -Path "...\armor_probe\sho_pack4\pack4.tpac" `
         -Target "...\Modules\Shokuho\AssetPackages\pack4.tpac"
```

实测 **2.3 GB 包加载 0.2 秒**（元数据惰性载入）。

### 6.4 资源定位：先二进制 grep，后开工具

```
grep -c -a "<网格名>" <包>.tpac        # 0 命中 = 肯定不在；≥1 = 在
```

实测：`sho_new_maru_do` → pack4（4 次，其余 6 包 0）；`body_male_japanese` → pack0（12 次，其余 0）。

## 7. 坑点表

| # | 坑 | 症状 / 后果 | 规避 |
|---|---|---|---|
| 1 | **官方骨架 FBX 单位标厘米、数值其实是米** | 头骨落 z≈0.0157 而网格在 z≈1.47 → **差 100 倍** | 绑骨架前把骨架缩放到与网格同空间（换头 §11.3） |
| 2 | **FBX 导出规格** | 节点 scale=100 被烘进顶点 / 绕 X 翻 180°（脸朝后） | `FBX_SCALE_UNITS` + `axis_forward='Y'` + `axis_up='Z'` + 导出前重设场景单位（换头 §13.1） |
| 3 | **ModKit 删资产会连带删源 FBX** | 迭代几轮 `AssetSources/` 就空了 | 权威备份放模块外；生成脚本读备份不读 AssetSources（换头 §13.5b） |
| 4 | **Publish 目标目录不能选模块内** | 得到 `Modules/X/X/` 嵌套（140MB） | 固定发到模块外，再拷 `pack0.tpac` 进来 |
| 5 | **材质手工配置会被 FBX 重导入刷回默认** | shader / flags / **VertexLayout** 全丢 → 网格不跟骨架动 | 导完 FBX 后回看三个材质的 Vertex Layout 还在不在 |
| 6 | **Publish 会清空 `AssetPackages/`** | 放在里面的备份被清掉 | 备份一律放模块外 |
| 7 | **`Assets/` 遮蔽 `AssetPackages/`** | 引擎按 `Assets`→`AssetPackages`→… 取**第一个存在的**；`Assets/` 是编辑器半成品（缺顶点流、贴图无像素）→ 游戏读半成品 | 游戏模式必须让 `Assets` 改名 `Assets_disabled`（bat 化） |
| 8 | **织丰甲顶点量级是原版的 4~12 倍** | 照搬精度拖垮千人战 | 自己控面数，按原版量级（LOD0 约 2000 顶点）设预算 |
| 9 | **`sho_new_maru_do` 无 LOD 是孤例** | 照它做 = 没有 LOD 链 | 参照物选 `sho_okegawa_do_a_1_kimono_a` |
| 10 | **`UnknownInt2` 两家不同**（原版甲 20 / 织丰甲 28） | 拿织丰的值刷原版结构 = 错 | 网格用到的骨骼数由编辑器按 FBX 自己算，**别手工覆盖** |
