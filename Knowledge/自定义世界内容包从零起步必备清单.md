> **总原则（动手前先记住三件事）**：
> 1. **三单元**：逻辑只写 LWN（通用基座），内容包 = 纯数据 + 一个 thin 适配类（`XxxCampaign : LivingWorldCampaign`，3 行）——引擎按战役类名匹配 GameType

> 3. **每改数据必 parse XML + 跑 checker；每改 DLL 必查「LWN 已内置兜底表」（文末）**——很多通用兜底新内容包 0 代码获得

### 1.4b 🔴 用官方场景 = 先扫「场景消费清单」（2026-09-09 两颗雷的总根，雷 40/41）

**规律**：场景文件本身不受 GameType 过滤（官方城市场景直接可用）——**但场景里的 prefab 实例引用原版物品/角色/兵种，那些被过滤**。所以「用官方场景」和「官方物品库进不来」是一对矛盾，矛盾的解法 = 白名单式补齐，**不是**不停等崩修崩。

**排查三步法**（一次补齐，不欠第二颗雷）：
1. `grep -o 'prefab="sp_[a-z]*"' <官方场景>.xscene`（场景用了哪些 spawn prefab）
2. 去 `Modules/Native/Prefabs/editor_spawnpoints.xml`（+ `Modules/SandBox/Prefabs/`）找对应 `<game_entity name="sp_xxx">` 看 `<tags>`——Tags[1] = 被引用的对象 id
3. 对象 id → 查自家物品库/角色库 → **缺失 = 拷官方定义入自家库**（物品/角色同法，culture 洗 ikoku）+ 跑 checker 0 悬空

🔴 **已脚本化（2026-09-10）**：以上三步 = `python Scripts/check_scene_consumables.py` 一键跑（自动读注册表 MB2_PATH 定位官方根；missing≠0 则 exit 1）。**新包/新场景无需手工排查——跑一次脚本即可**；手工三步法保留用于理解原理与脚本查不到时的兜底（已知边界：只查静态 prefab tags）。

**已知消费面**（已实锤，新包直接勾）：黑巷地痞 `gangster_1/2/3`（DefaultAlleyModel 进城消费）· 马 `sp_horse_*`（马物品 6 种）· 动物 5 只（sheep/cow/hog/goose/chicken）。**织丰从不用官方城市场景**（自有 sho_* 场景 + 自有 prefab + 自有物品）→ 天然免疫此族雷——不想补清单就学织丰做自有场景（成本高，v0 建议白名单补齐）。

## v0 边界（什么可以不做——织丰 65 条对照决策表机制）

> 织丰「做派」对照表 = 按 **A（必须做）/ B（织丰做+我们最小集不做，后续数据层）/ C（不做）** 三档裁定，先看织丰证据再定我们的动作。**例子**：路人 40 职业 = B（T4 再做，最小 4 个提前 A）；未成年变体/锦标赛师/舞女/乞丐 = C；日式素材 = 先抄官方值能跑、T5 日化。
