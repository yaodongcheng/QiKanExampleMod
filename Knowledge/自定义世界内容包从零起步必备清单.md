# 自定义世界内容包从零起步必备清单

> 🔴 **再做一个新世界观（新内容包）时，拿这份清单勾。** 全部条目 = Taikou 实机踩过的雷（雷 1~43）+ 织丰 65 条经验交叉对比。
>
> **文档分工（重要）**：本清单 = **导航式索引**（缺什么 → 症状信号 → 修法 → 深坑出处）。每条只留「够行动」的信息；
> 完整的反编译证据/调用链/踩坑过程在各自主档，遇疑先查它们：
> - 排雷全程实录 → `plans/太阁数据加载taikou-campaign-boot-20260907.md`（雷 1~36 全文，含证据行号）
> - 疑难杂症速查 → `plans/rules/pitfalls.md`（每坑：症状/根因/规避）
> - 已造轮子 → `plans/rules/wheels.md` + `wheels.d/`（terrain.md 地图资产 / campaign-mode.md 数据自给）
> - 织丰工程全清单 → `Knowledge/织丰自定义世界观经验.md`（65 条世界工程补丁 + 数据做派方法论）
> - 最小字段交集 → `Knowledge/内容包最小字段交集.md`
>
> 🔴 **维护纪律（CLAUDE.md「自定义世界坑点沉淀纪律」，2026-09-09 用户裁定）**：凡自定义世界相关新坑点/新雷，遇坑即登记——①雷对照总表追加一行（症状一句/根因一句/修法归属）②命中阶段清单 → 补「症状信号/勾选项」，让清单跟着经验升级；细节深挖写各自主档。**已用清单核查新世界时，新坑必须能挂到本清单某一条上——挂不上 = 清单有缺口 = 先补清单再写代码。**
>
> 🔴🔴 **每条检查必须有脚本兜底（2026-09-10 用户裁定，最高优先级）**：本清单里**凡能离线查的条目，都必须有对应的 checker 脚本**——**禁止只有文字没有真实检查内容**。新增条目时**同时**做三件事：①写进清单 ②加/扩 checker ③登记进「清单条目 ↔ 脚本对照表」。写规则前**先拿官方数据跑一遍**（否则会把官方设计当缺陷——2026-09-10 退休据点误判实录）；写完**必须做负面测试**（故意造坏数据，确认脚本真能抓到、exit 1）。确实无法脚本化的（纯代码/设计类）必须在对照表里显式标「非脚本化 + 原因」，不许默默留白。
>
> **总原则（动手前先记住三件事）**：
> 1. **三单元**：逻辑只写 LWN（通用基座），内容包 = 纯数据 + 一个 thin 适配类（`XxxCampaign : LivingWorldCampaign`，3 行）——引擎按战役类名匹配 GameType
> 2. **织丰对照法**：一切「缺 X」先反编译织丰/官方拿证据（做了/不做/怎么做）再动手，禁止凭名字猜
> 3. **每改数据必 parse XML + 跑 checker；每改 DLL 必查「LWN 已内置兜底表」（文末）**——很多通用兜底新内容包 0 代码获得

### 1.4b 🔴 用官方场景 = 先扫「场景消费清单」（2026-09-09 两颗雷的总根，雷 40/41）

## 阶段 2：流程纪律（每次变动必跑）

> 🔴 **数据优先三原则（2026-09-10 全线复盘定案，写代码前先过）**：
> ①**能用 XML 表达的绝不用代码**（场景实体尺寸、物品/角色引用、段注册全是数据活；"运行时自动适配"方案已被用户否决）；
> ②**离线的能查的绝不留给运行期**（缺引用/缺物品/缺段 → 先扩 checker 脚本，别等进游戏崩）；
> ③**运行期的补丁只做兜底，且必须带退役条件**（新增任何 Harmony/加固补丁 → 在下方「LWN 内置兜底」表的台账列登记：治本侧 + 退役条件；每次数据补全后回查，满足即评审退役）。
> 三层防线 = ①数据断言（checker，改动即跑）②启动期加固（反射修补，跨包安全）③运行期兜底（拦截 NRE，带台账）。
> 现状比例（雷 1~43）：约 **7 成纯数据/离线**、1 成「数据治本+代码兜底」双保险、2 成必须代码（其中一半是功能而非补丁）。

- 🔴 **第三方 mod 数据借用纪律（2026-09-10）**：把别的 mod 的数据搬进本包（如 Taikou 的名字池 622 条取自织丰、译文取自 `Shokuho_CNs`）必须**① 在该数据的生成器与语言文件里写明出处 ② 对外发布前标注出处并取得授权 ③ 优先考虑自造替换**（键与值都自持）。借用只会出现在「官方没有、自己又还没造」的字段上——凡借用，记在本清单与 plan 待办里，别让它无声地留在包里
- 实体 ID 一律 StringId（铁律 20）；查找走两轮策略（铁律 5）；名字查 ID 必过别名列（铁律 25）；引用禁用显示名（铁律 20）
- 🔴 **罗马音禁带变音符号（macron / circumflex / acute）——规范原文在 `csv/ReadMe.csv`**（当年给 Excel VBA 写的规则，是权威）：
  ```
  ā/Ā/â/Â/á/Á/ã/Ã → aa      ē/Ē/ê/Ê/é/É → ee      ī/Ī/î/Î/í/Í → ii
  ō/Ō/ô/Ô/ó/Ó/õ/Õ → oo      ū/Ū/û/Û/ú/Ú → uu      ñ/Ñ → n      ç/Ç → c
  ```
  ①**输出一律小写**（`Ā`→`aa`）②**acute 与 macron 同等对待**（`ó`→`oo`，不是"去掉重音"）③🔴 **`ō` 展开成 `oo` 而不是 `ou`**——英雄表的 `EnglishName` 早就用 `oo`（`Katoo`/`Kyoogoku`/`Saitoo`/`Soo`/`Moori`），`check_englishname_clan_prefix.py` 的规范表也是 `oo`；转错了会被该 checker 一次抓出几十条「前缀与家族对不上」④**为什么是双写不是去掉**：库里 `clan_mori_1`（森，短音）与 `clan_mōri_1`（毛利，长音）**同时存在**，去掉会撞成同一个 id ⑤**边界**：上游镜像（`BaseInfo.csv`）跟着改；**别人的原始转储（`shokuho_heroes_full.csv`）不改**（改了会跟源分叉）⑥范本 = `Scripts/convert_taikou_macrons.py`（转换表 + 撞车预检 + 往返校验 + 幂等两跑）
- 🔴 **对账 join 键纪律（2026-09-11）**：跨表对账**按编号 join，禁止按人名**——快照的 `name` 列**自己 README 就标了「勿再引用本行作权威」**（旧路径映射、追加段会错位）；实测按名字 join 会把明智光秀、柴田胜家都算成「芦名家」。人名只在**没有编号可用**时才作最后手段，且必须**多源互证**
