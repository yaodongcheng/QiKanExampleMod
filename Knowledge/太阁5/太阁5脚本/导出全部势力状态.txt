//               支配力 / 城數·武將數（仅武家）/ 造船技术（仅海贼）/ 關係（外交四关系）
//
// 用户口径 ↔ 游戏字段对照（用户说的词不是属性名，先对齐再写）：
//   家主      = 當主（大名家1 / 忍者眾1 / 海賊眾1）
//   势力值    = 支配力（大名家15 / 忍者眾17 / 海賊眾18）← 太阁里就叫支配力
//   战略目标  = 大方針 + 戰略 + 戰略目標 三个字段，两个层次：
//               大方針 = 大战略（武家：分國統一/統一天下/上洛；忍海：里守備/擴大勢力…）
//               戰略   = 当前行动（武家：敵城攻略/大名攻略…；忍海：里增強/他眾攻略/大名支援）
//               戰略目標 = 该行动打哪儿（存对象，类型随戰略变，见下）
//   敌对势力  = 外交感情 ∈ {絕交, 險惡, 敵視}
//   同盟势力  = 外交同盟 == 同盟
//   从属势力  = 外交同盟 == 從屬   ← 「我服从谁」
//   支配势力  = 外交同盟 == 支配   ← 「我支配谁」
//   支持大名家 = 忍者眾18 / 海賊眾19 —— 引擎维护的「主家指针」，**与大名的从属不是一回事**，
//               见文件末尾「支持大名家 vs 從屬」一节的实测结论。
//   ⚠️ 從屬/支配 是同一段关系的两面。本脚本按主体自己的方向输出：
//      「主体的從屬」= 主体的主家，「主体的支配」= 主体的附庸，两列互为镜像、不重复。
//
// 🔴 两条自证设计（都不是冗余，是防「读出假数据」）：
//   ① 每条关系后面挂一个 @外交關係 数字。外交感情/外交同盟 是枚举，没建立过关系的
//      势力对读出来是什么值，离线查不出来（枚举表里 絕交=0 是合法敌对态，但内存
//      默认值也可能正好是 0）。外交關係(200) 是同一段关系的数值形态，一起打出来
//      一眼验伪：若某条「敵:」的 @值 处于中性区间 → 是没初始化过的默认值，不是真敌对。
//   ② 忍者/海贼的 戰略目標 用「自验证解码」：先按推断的类型取，**取到无效对象就退回
//      原始番号**（写成 #数字）。所以看到 #数字 就说明我的类型推断对该条不成立，
//      而不会打出个错名字骗人。武家的解码有官方先例、不打 #。
//
// 属性出处（全部查 E:\TKHACK\database\database_dx.xml 的属性表，非猜测）：
//   大名家屬性：當主1 / 外交同盟5 / 外交感情6 / 戰略11 / 戰略目標12 / 大方針13 /

//               大方針13 / 大方針目標14 / 存在15 / 大型船建造技術16 / 鐵甲船建造技術17 /

// 为什么用「数值番号外循环 + 容器内循环」这种嵌套写法，不能一遍容器跑完：
//   ① 关系是 A×B 的叉积——遍历到一个势力时，必须还能拿到「全体势力」这张表去逐个问

//      外循环一旦用容器，弹完就没了，内循环无从查起。
//      故外循环走数值番号区间，内循环才用容器——两者互不干扰。

//      ⚠️ 忍者與海贼番号区间重叠（都是 50 起）但分属两张表，靠 <類> 列区分。
//   ③ 内循环分四段（武家/商家/忍者/海贼）逐个扫，是因为关系的相手方可能落在任何
//      一类势力上——忍者眾、海賊眾 对大名家的「從屬」正是本表最要紧的一类数据，
//      漏掉就等于附庸名单不全。
//      ⚠️ 曾经想用「勢力」总类型一次扫完（database 确有 type="勢力"），但检索
//         「容器設定:(勢力…」**零先例**，不敢赌，改用四类具体容器。
//
// 🔴 实测教训：容器类名不认异体字，必须逐字照 database 写
//   实机报错：(82): '容器設定:(忍者衆,存在,真)', Unknown container class '忍者衆'
//   —— 工具作者测试脚本里写的是「忍者衆」(U+8846)，会被拒。keywords.xml 里的
//   衆→眾 归一**对容器类名/变量名不生效**（它管游戏数据和显示文本）。本脚本一律用
//   database 正字「忍者眾」「海賊眾」，变量名同理（忍者眾Ａ/海賊眾Ａ）。2026-09-12 实测。
//
// 语法出处（逐条都有先例，非猜测）：
//   代入大名家Ａ:(ｉ) = 数值番号直接当对象用
//       先例：測試用例\測試商家屬性.txt「代入商家Ａ:(ｓ)」（ｓ 为商家番号数值）
//             劇本\測試事件\編譯測試\代入.txt「代入國Ａ:(０)」
//   大名家Ａ.外交感情(勢力Ｂ) / 外交同盟(勢力Ｂ) / 外交關係(勢力Ｂ) = 带参数的属性

//             同文件「代入ｂ:(大名家Ａ.外交關係(勢力Ｂ))」
//   代入勢力Ｂ:(大名家Ｂ) = 把具体势力类型的变量装进 勢力 变量（向上转）
//       先例：測試用例\測試外交關係0-20.txt「代入勢力Ｂ:(織田信長)」「代入勢力Ａ:(武田信玄)」
//   容器設定:(大名家,存在,真) / (商家,存在,真)  本项目 导出全部势力ID.txt（已跑通）
//   容器設定:(忍者眾,存在,真) / (海賊眾,存在,真)
//       先例：劇本\測試事件\編譯測試\容器設定.txt，但**先例写的是异体字「衆」会被拒**，
//             本脚本按 database 正字写（见上方实测教训）
//   容器選擇(先頭) + 容器清理(消去,1) + 條件循環:(容器記錄數)!=(0)  同原势力脚本，已跑通

//       先例：劇本\水落清秋\三好劇情重構.txt；官方解密 tr5_script.txt「代入ａ:(狀況::年)」
//   代入據點Ａ:(大名家Ａ.本城)  先例：本项目 导出全部势力ID.txt（已跑通）
//   空字段判空：代入人物Ａ:(...) + 調查:(人物Ａ)==(無效) + 分歧:(偽){...}
//       ⚠️ 为什么必须判空：空字段不是「空」是「无效对象」，裸插值会打出固定假名
//          （人物槽 → 「门卫」、家族槽 → 「一宫家」；导出全部人物上级.txt 2026-09-11 实测）
//       先例：劇本\測試事件\地圖事件測試.txt「調查:(據點Ａ)==(無效)」
//             分歧:(偽) 先例：劇本\水落清秋\上杉劇情促成.txt
//   文字列設定:(文字列Ａ)[[]] = 清空字符串  先例：劇本\測試事件\功能調用測試.txt
//   文字列設定:(文字列Ａ)[[<文字列Ａ>敵:<勢力Ｂ>@<ｑ>;]] = 自我累加拼串
//       先例：測試用例\測試商家屬性.txt（同名自我累加模式）
//   模塊開始:{ 調查:… 脫出模塊:(偽) … } = 「容量池」写法
//       先例：resources\模板\解决容量限制：模塊+調查+脫出模塊.txt（工具作者自带模板）
//       ⚠️ 條件循環/條件模塊 容量只有 2K，超了运行期出错；模块 16M。
//          循环体内的大段分支必须塞进 模塊開始，循环体本身只留几十字节。
//          自增语句要放在 模塊 外面，否则 脫出模塊 提前跳走会漏自增 → 死循环。
//   ⚠️ 插值 ≠ 赋值：`[[ ]]` 里不能写 `类型::对象变量.属性`（实机报错
//      "Text variable token '城::城Ａ.規模' invalid"）。类型前缀后面只认番号。
//      正解：先 `代入ａ:(城::城Ａ.規模)`，再在 `[[ ]]` 里插 `<ａ>`。
//   日誌:[[...]]  先例：劇本\測試事件\地圖事件測試.txt
//
// 用法：tkhack 事件管理 → 添加事件 → 加载本文件 → 在大地图上移动一格即触发 →
//   去 E:\TKHACK\log\ 抓 "Log: FRC|" 开头的行（日志为简体，字段名会转成 大方针/战略）。
//   ⚠️ 每个年代剧本各跑一次（6 个剧本 = 6 次导出），日志混在一个文件里时靠 <劇本> 和 <年> 区分。

//
// 输出格式（| 分隔，列内多条用 ; 分隔，全程不用半角逗号）：

//      忍者 → 无（本據 不导，见下）

//                           ← 大名侧没写！
//   ⇒ 只读大名家那一侧会**漏掉路径二建立的从属**。所以忍海必须自己也当主体导一遍，
//     两边取并集才完整。
//
// 想加字段（朝廷貢獻度18/大方針目標14/不可侵同盟期間… 属性表里都有）：
//   照抄对应段的 日誌 行，数值字段直接插 `<ａ>` 形式（先 代入ａ:(属性) 再插），
