# 太阁5 数据文件破解笔记（tr5msg 家族 / 字体 / 加密 —— 2026-09-01 探索阶段）

> 状态：**部分破解**。已确定：加密算法、头表结构；未破：正文记录结构（字符编码非标准集，见下）。

## 一、已确认事实（可复用）

### 1. tr5msg00-24.tr5 加密 = 单字节 XOR 0xA5
- 判据：`bytes(b ^ 0xA5)` 后文件头出现**结构化的 u32 表**（解锁后 0000 结尾 4B 对齐、数值域合法），密文里高频的 `a5 a5` / `aa aa` 对即明文 `0x00 0x00` / `0x0F 0x0F`。
- **解密单行 Py**：`open(f,'rb').read()` → `bytes(b ^ 0xA5 for b in d)`。
- 各处文件（tr5msg23 等）同样适用（head 模式一致验证）。
- ⚠️ 这是一层**体外层**：正文记录（0x8E0 起）里的字符/字段值为**第二层编码**（见 §3）。

### 2. 文件布局（tr5msg00 = 物品/人物数据表）
- `0x00-0x03`：文件头 4B（0x08024A12 → 待定）
- `0x04-~0x8E0`：**u32 索引/ID 表**（每项高 16 位=记录 ID 或槽位，如 0x0825、0x082B、0x0B15…；间隔不定 → 是 ID→槽映射而非逐条偏移）
- `0x8E0-文件尾`：**记录区**，反复出现模式：`0x0C 0x02 0x03 XX 0x0C 47 73 <ASCII 字段名> <2B 值/加密码> 0x0F* `——ASCII 字段名（如 `Gspsr`/`G|p`/`G}s`）恒显，是**条目属性键**。

### 3. 文本/字符编码：非标准（关键拦路虎）—— **2026-09-01 已定码表结构**
- **F_FONTT.tr5 码表结构（实锤）**：文件头 5B（`00 5A 00 00 00`）后，`u16 连续区 0xA100 → 0xDFFF`，**共 16128 槽**（= 自建字符码空间 0xA100-0xDFFF，每槽=字形索引）；0x7E04 紧接**第二码段：0xC000 起递增**（小字形/扩展组）。
- 转译途径因此确定：tr5msg 记录中的 2B 码值（例 0xAF47 ∈ 0xA100-0xDFFF ✓）→ 码表索引 → 字形。**「码→字符」字面表尚缺最后一步**（用 JIS 序对照或运行时截图对照），待做。
- 影响：一旦码表映射完成（预期 1 天工作量），tr5msg00-24 全部文本（物品/部队/列传/对话）全部可读。

## 二、下阶段路线（重要：先小后大）

1. **CWTDAT.TR5（391KB，头明文）**——头部无加密，先解结构 → 很可能含**剧目/系统主表**（AI 参数、行动表藏身处），直接可产出。
2. **F_FONTT 码表反推**：0xA100 起递增 u16=字形序 → 与 tr5msg 内部 2B 码对照，建「Koei 字符码 → Unicode」映射表——**映射表一旦建成，所有 tr5msg/TG5 文本全解锁**（高价值轮子）。
3. **tr5msg00 记录区**的完整条目布局 = 属「物品/名」表结构，等映射表到手再解字段。
4. 其余：INIT.TG5（TK5G 头）、SbCdInti/SpCdInit（开局）、taikou5.exe 代码层（AI/主命）→ 按可行性研究文档的 P1/P2。
