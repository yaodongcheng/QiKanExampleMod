## 4. 数据做派（关键结论）

1. **Culture 不填官方全集 70 字段**——织丰 Culture cell（spcultures/shokuho_main_cultures.xml, 19 文化 + neutral_culture）只填运转必需子集：`basic_troop/elite_basic_troop/militia_party_template/encounter_background_mesh/default_battle&civilian_equipment_roster/banner_bearer_replacement_weapons/lord_templates/rebellion_hero_templates` + 各国特色（militia/villager/caravan party 模板）
2. **兵种复用**——`neutral_culture`：`basic_troop=NPCCharacter.guard`、`elite_basic_troop=NPCCharacter.guard`（单兵共享），**不造多兵种树**（无 upgrade 链、类卡拉迪亚 30+ 兵树）
3. **neutral_culture 必须定义**（引擎 fallback 消费点：cs_full 32472/32477/47645 等 4 处 `GetObject<CultureObject>("neutral_culture")`；织丰定义最小 7 字段作模板）
4. **引擎基础层豁免**：Monster/ItemModifier/WeaponDescription/CraftingTemplate/SkeletonScale/SiegeEngine 在 Native SubModule.xml 无 IncludedGameTypes = 所有 GameType 共享——引用它们不算"引用别人"（见 wheels.d/campaign-mode.md 三区块模型）
5. **背包/战利品/装备链**：织丰 items = 自造（不拷官方）；本工程 v0 拷贝官方全量（1233 物品，文化已清洗）——T4 数据层日化时对齐织丰做派

## 8. 参考 mod 双源——衣谷三国（YiGuThreeKingdoms）对照（2026-09-08）

> 用户裁定：衣谷与织丰互相印证。衣谷 = **另一种工程范式**（官方 Campaign 替换式），盘实为第三参考。

### 范式对比（三家）

| | 织丰 | 衣谷（YiGuThreeKingdoms，1.2.12） | 本工程 |
|---|---|---|---|
| 战役形态 | 自定义 GameType（ShokuhoCampaign）+ 自建 GameManager + 原版 CC 全流程（patch 适配） | **原版沙盒战役（Campaign）不换**——数据段挂 Campaign/CampaignStoryMode/CustomGame/EditorGame（全原版 GameType）+ **Yigu.ThreeKingdoms.dll 全 Harmony 修原版** | 自定义 GameType + 自建 GameManager + 自建 CC 3 阶段 |
| 数据姿势 | 自建全量（19 文化/日式物品库/装备集自建） | `sg_` 前缀全包（sg_spcultures/sg_spitems/sg_equipment_sets/sg_dual_wield_weapon/sg_action_sets（自研动作集）/…）——**原版段仍在**（不屏蔽，靠前缀 + 内容替换共存） | v0 占位（拷贝+引用闭包裁剪）→ T4 自建日式（织丰路线）+ taikou_ 前缀 |
| 引擎 fallback | 全自给（neutral_culture/默认装备自己做） | **天然继承官方**（spcultures 未屏蔽 → 官方 Culture/neutral/装备 in 内存） | 全自给（第 5/6 颗雷全程 = 这一条的代价） |
| 同一引擎弱点的处理 | 数据配（不触发） | **Harmony Prefix 过滤**（`CompanionsCampaignBehavior_InitializeCompanionTemplateList_Patch`：剔除文化不在 13 个三国白名单的 N&W 条目） | 数据自给 + CultureTemplateNullFix 加固（双保险） |

### 印证结论

1. **引擎弱点集是公共的**：`CompanionsCampaignBehavior.InitializeCompanionTemplateList`（三个 mod 都撞，三种处理：数据配/补丁过滤/双保险）；`InitializeDefaultEquipments` 引擎硬编码中性装备 roster 同理（织丰/衣谷因数据在而天然躲过；自定义式必须白名单自给）——**"半成品世界"型 NRE = 自定义 GameType 的固有成本，不是做错**。
2. **范式取舍**：替换式（衣谷）= 引擎 fallback 全天然，省大量自给工作；代价 = 世界与官方残余共存（官方文化/物品仍在内存——衣谷还得补丁清杂遗）。纯净式（织丰/我们）= 世界干净，但要自给引擎引用全集（物品 51 + roster 5 + neutral + …）——**我们已把此"引擎自给白名单"做进 prune 脚本常量**（可复用为任何内容包的 checklist）。
3. **工具链**：衣谷同样依赖 Harmony/ButterLib/UIExtender/MBOption（+CsvHelper/Serilog 后台）——现代 1.2.12 内容包标配，LWN 同构 ✓。
4. **数据组织可借**：sg_ 前缀体系（每类一个文件、专属前缀隔离）——我们 taikou_ 前缀同思想 ✓；衣谷自研动作集/双持系统 = 玩法扩展的广度参照（后续可挖）。

## 9. 2026-09-08 排雷全记录通用教训（12 颗雷沉淀）

> 完整排雷链见 `plans/太阁数据加载taikou-campaign-boot-20260907.md`「排雷链记录」。本文只收"可迁移"教训。

1. **枚举字段必须过枚举全集校验**：spnpccharacters 41 模板的 `occupation` 值 12+ 个非引擎枚举（PreacherNotary/ArtisanNotary/Taverngamehost/HorseMerchant…）→ 枚举解析失败 → **NPCCharacters 段静默截断**（只进 24/47 个，后面不加载、不报错）——**造模板前对照枚举全集**（Occupation 33 成员）；探针（CharacterObject.All 计数+GetObject 直查）是唯一能发现它的手段。Culture 的同类枚举：board_game_type 等同样对照。
2. **生成器幂等**：追加式生成器重跑会重复插入；生成物被"重跑覆盖手改"（铁律 22 现场）——生成器必须幂等（追加前检查已存在 id），改内容只改生成器。
3. **引擎白名单三清单**（裁剪"拷贝全家筒"必备）：物品 51（硬编码 GetObject<ItemObject> 41 + DefaultItems 9）+ roster 5（neutral×2/CC 默认/乔装/过场）+ neutral_culture 1 — 都固化在 `Scripts/prune_taikou_items.py` 常量。
4. **文化 N&W 模板池 = 名流生成器原料**：`CreateHeroAtOccupation`（NotablesCampaignBehavior）从 `culture.NotableAndWandererTemplates` 按职业挑模板——**模板池缺职业 = 名流生不出**；官方名流是运行时生成（非 XML 预定义，三连证据）。
5. **时点坑二则**：①Kingdom.InitialHomeLand 引擎在 OnNewGameCreated 洗白（置位必须在 partial-followup 时点）②`MBObjectManager.GetObjectTypeList<T>()` 在 partial-followup 时点**返回 null**（not record 未注册）——此时点一律用 `Campaign.Current.Kingdoms/Clans` 等战役合集。
6. **工坊产线机制**：`GetRandomItemAux(ItemCategory, town)` 从 `_itemsInCategory`（FillItemsInAllCategories 填充，条件 = IsProducable（merchandise 非 NotMerchandise）+ 文化匹配（IsItemPreferredForTown：culture==town 或 null））——**库物品 must 有 merchandise=true + 文化匹配**；工坊 Outputs 的分类必须有物品可产（否则分类表空 → NRE）。
7. **数据自给 checker 闭环 = 唯一根治**（GetPresumedObject 裸桩是 NRE 谱系总根）。
