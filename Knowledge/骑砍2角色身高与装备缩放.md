# 骑砍2 角色身高与装备缩放机制（反编译实证）

> 用途：回答"我们的头/甲/兜拼不回原角色（脖子比甲领口高 9cm），能不能用游戏自身的身高机制表达逐角色身高差"。
> 反编译目标：v1.2.12 客户端（`MB2_PATH` 当前指向）。
> 所有结论标注证据（二进制 grep / 反编译 DLL+类型+方法）。**native 内部实现看不到的，本文一律明写"不可见"**。

---

## 1. 结论先行

### Q1 — 骑砍2 里"身高/体型"怎么表达？

**决定：由 `BodyProperties`（角色的 128 位十六进制脸键）+ 身体甲的 `body_deform_type` 两个来源驱动，最终落到"骨架缩放 + 整体均匀缩放"两件事上，不涉及网格 morph。**

| 要表达的 | 载体 | 最终动作 | 谁做 |
|---|---|---|---|
| **身高** | `FaceGenerationParams.HeightMultiplier`（[0,1] 浮点，建号界面 Body 页"Height"滑块，属性 id `-16`）→ 编码进 `StaticBodyProperties` | **整体均匀缩放**（一个标量） | native：`MBFaceGen::get_scale` |
| **胖瘦 / 体格** | 脸键 `key_time_point=60`(weight) / `61`(build)，取 `DynamicBodyProperties.Weight/Build` | **逐骨、逐轴骨架缩放** | native；范围数据在 `skins.xml` 的 `<bone_scales>` |
| **脸形 → 头盔/头** | 脸键 `1..59` | **头部骨骼缩放矩阵** | `MetaMesh.UseHeadBoneFaceGenScaling(...)` |

- 理由：`FaceGenerationParams.HeightMultiplier` 是唯一的逐角色连续身高量；`skins.xml` 里 `key_time_point="62"` 的 `height` 条目**是空的**（既无 `<bone_scales>` 也无 `helmet_scaling_factor`）——说明身高不走骨骼、不走 XML，由 native 一个标量表达。
- **不是 morph、不是改骨长**：骨长类形变（weight/build）另有其道，身高不在此列。

### Q2 — 这套缩放作不作用于装备？

**决定：作用。装备（身体甲 / 头盔 / 披风）跟着一起缩放；武器不跟（任务里）。**
**⇒ B 方案（不动我们的网格、用游戏自身的缩放表达身高差）可行。**

- 理由一：**所有部件挂在同一个 agent visuals 对象上**。皮肤、身体甲、头盔都通过同一个 `agent.AgentVisuals.AddMultiMesh(...)` / `AddSkinMeshesToAgentEntity(...)` 装配；身高缩放作用在该对象的根 transform（或由 native 在该对象上统一施加），因此构造上"一起变"。
- 理由二（外部实证）：马匹的 `body_length` 通过 `Agent.SetInitialAgentScale(0.01f * BodyLength)` 设的 `AgentScale` 会**连带把骑手整个人放大**（社区文档原文 "a giant rider"，并说明"缩放代码块没有 is-mount 判断"）。骑手是全套装甲带武器的——这条实测证明这套缩放大的是"整个人（含装备）"。
- 唯一的例外是**武器**：由 `AgentVisualsData.UseScaledWeaponsData` 控制，**默认 false**；全 DLL 检索 `UseScaledWeapons(true)` 只出现在 `SandBox.View` 的 3 处（大地图队伍图标路径），**任务内没有任何地方设它** → 任务里武器不跟身高缩放（这也符合直觉：高个子不该配一把按比例放大的剑）。

### Q3 — `ItemObject` / 装备定义侧有没有逐件缩放字段？叠乘还是覆盖？

**决定：有，叫 `ItemObject.ScaleFactor`（XML 属性 `scale_factor`，默认 `1.0`）。但护甲侧没有任何消费点，而且它是"覆盖"不是"叠乘"。**

- 消费点只有四类，全在坐骑和武器：
  1. 坐骑外观：`new AgentVisualsData().Scale(item.ScaleFactor)`（`Mission.SpawnAgentVisuals` 里给马用）
  2. 大地图队伍图标：`.Scale(item.ScaleFactor * 0.3f)`
  3. 武器网格：`weaponData.ScaleFactor = Item.ScaleFactor`
  4. 武器判定长度：`Weapon.CurrentUsageItem.WeaponLength * 0.01f * Weapon.Item.ScaleFactor`
- **覆盖关系**：`_scale = (_data.ScaleData == 0f) ? MBBodyProperties.GetScaleFromKey(...) : _data.ScaleData` —— 一旦给了 `ScaleData`，**由脸键算出的身高缩放被整个绕开**，不是叠乘。大地图图标写死 `.Scale(0.3f)` 就是这个用法。
- 挂载位置：`ItemObject` 级（`<Item>` 元素属性），**不是"装备槽位"属性**；武器另有一套在 `<CraftedItem>/<Piece>` 上（值是百分数，如 `110`）。
- **护甲无逐件缩放通道**（全 DLL 检索 `.ScaleFactor` 的消费者只有上面四类，没有护甲分支）。

### Q4 — 我们自己的自定义网格会不会绕过这套缩放？

**决定：不绕过。走的是同一条装配管线，引擎缩放一样作用到我们的网格上。**

- 我们自建头的装配路径：`skins.xml` 的 `face_meta_mesh` → `Agent.AddSkinMeshes()` → `AgentVisuals.AddSkinMeshes(skinParams, BodyPropertiesValue, ...)` → `AddSkinMeshesToAgentEntity(ptr, skinParams, bodyProperties, ...)`（native）。**`BodyProperties` 是作为参数交给 native 的**，所以 native 有完整的"该缩多少"的输入。
- 我们自建甲的装配路径：`EquipmentElement.GetMultiMesh(...)` → `agent.AgentVisuals.AddMultiMesh(mesh, slot)` —— 和皮肤网格挂在**同一个对象**上。
- **两条注意事项**（不是"绕过"，是"要看住"）：
  1. **头盔/头部**的跟随由 `MetaMesh` 上的 `UsingFacegenScaling` 标志决定 —— 只有该标志为真的网格才会吃到 `UseHeadBoneFaceGenScaling(骨架, 头骨索引, GetFacegenScalingMatrix())`。我们自建的头/兜有没有这个标志，决定头部跟不跟脸形缩放。
  2. 我们的网格是"按源模型尺度绑到骑砍骨架"的。如果绑定时的尺度与骑砍标准尺度不一致，那么**引擎的身高缩放对我们是正确的，错的只是"我们的模型本来就没对齐"** —— 引擎缩放救不了这种错。

### A / B 裁决

**决定：B 可行，且是"逐角色身高差"的正确载体；但 B 替代不了"头/甲/兜共用一个变换"这件事，两者要一起做。**

- B 能解决的：**角色之间的整体大小差**（信长 1.90m vs 宁宁偏矮）。因为引擎缩放是**均匀**的，头、甲、兜、身体一起按同一系数变，构造上不会互相错位。
- B 解决不了的：**内部比例错位**（"脖子比领口高 9cm"）。均匀缩放只能改"整体多大"，改不了"甲领口相对脖子在哪"。这个 9cm 的根因是**三件各自去凑骑砍骨架**（头按眼↔嘴距离归一化、甲用全局径向系数 R=0.0120），不是身高没表达。
- 因此正确组合：**同一角色的头/甲/兜用源模型的同一个变换导出（达成"脖子接领口"构造上成立）→ 角色之间的身高差交给引擎的身高位（B）**。这样两条诉求各归其位，不需要为每个人手调一套缩放参数。
- 附带好处：模板 NPC（普通士兵/村民）的身高由引擎随机生成（见调用链 §2.6），我们什么都不用做就有自然的身高分布。

⇒ **单人模式下范围 [0,1]（多人被夹到 [0.25,0.75]）**。

### 2.2 身高存进脸键的哪个位

`TaleWorlds.Core.dll` → `TaleWorlds.Core.BodyProperties.ClampForMultiplayer()` / `ClampHeightMultiplierFaceKey(in StaticBodyProperties)`：

```csharp
public BodyProperties ClampForMultiplayer() {
    ...
    StaticBodyProperties staticBodyProperties2 = ClampHeightMultiplierFaceKey(in staticBodyProperties);
    return new BodyProperties(dynamicBodyProperties, staticBodyProperties2);
}

private StaticBodyProperties ClampHeightMultiplierFaceKey(in StaticBodyProperties staticBodyProperties) {
    ulong part = staticBodyProperties.KeyPart8;                       // ← 读 KeyPart8
    float num = (float)GetBitsValueFromKey(in part, 19, 6) / 63f;     // ← 第 19 位起 6 位，除以 63
    if (num < 0.25f || num > 0.75f) { num = 0.5f;
        int inewValue = (int)(num * 63f);
        ulong keyPart = SetBits(in part, 19, 6, inewValue);
        return new StaticBodyProperties(..., staticBodyProperties.KeyPart6, keyPart, staticBodyProperties.KeyPart8);
    }
    return staticBodyProperties;
}
```

**IL 已逐条核对**（`ilspycmd -il ... -t TaleWorlds.Core.BodyProperties`）：
- `IL_0009: call get_KeyPart8()` → `IL_0011: ldc.i4.s 19` → `IL_0013: ldc.i4.6` → `IL_0014: GetBitsValueFromKey` → `IL_001a: ldc.r4 63` → `div` —— **读 KeyPart8 + 位 19..24，确凿**。
- 回写侧 IL：`... get_KeyPart5(), get_KeyPart6(), ldloc.s 4 (=改过的 KeyPart8), get_KeyPart8()` —— **改过的值落在第 7 个参数位（KeyPart7 槽），而原始 KeyPart8 原样保留**。

⇒ **字段位置 = 6 bit（取值 0..63，粒度约 1.6%），这 6 位存在哪个 KeyPart 上，读和写自相矛盾**（读 KeyPart8、写 KeyPart7 槽）。这条进"未证实项"，必须实机定。

**实数据旁证（支持"读 KeyPart8"这一侧）**：解码全模块 428 个脸键后发现 —— KeyPart7 的位 19..24 在 417/428 个键里是 **0**（剩下 11 个是同一个模板值的复制，恒 18）；而 KeyPart8 的位 19..24 在 0..63 上**均匀铺开**（均值 28.5），正是"随机身高映射到 6 bit"的样子。

### 2.4 缩放应用到模型上

`TaleWorlds.MountAndBlade.View.dll` → `TaleWorlds.MountAndBlade.View.AgentVisuals.Refresh(...)`（私有，被构造函数与公开 `Refresh` 调用）：

```csharp
_scale = ((_data.ScaleData == 0f)
          ? MBBodyProperties.GetScaleFromKey(_data.RaceData, IsFemale ? 1 : 0, _data.BodyPropertiesData)
          : _data.ScaleData);
((Mat3)(ref frameData.rotation)).ApplyScaleLocal(_scale);
_data.AgentVisuals.SetFrame(ref frameData);
```

⇒ 缩放乘在**整个 agent visuals 的根 transform** 上（`SetFrame`），皮肤、装备一视同仁。构造期 `_scale = (_data.ScaleData <= 1E-05f) ? 1f : _data.ScaleData;`。

**谁触发了这条链（任务内）**：
- 建号/装备界面的**立绘/预览**：`CharacterTableau` 用 `AgentVisualsData().Equipment(...).BodyProperties(...).Race(...)` —— **没有 `.Scale(...)`** → 走 `GetScaleFromKey`。这是"改身高滑块，立绘里连甲一起变"的直接机制。
- 多人 / 大地图队伍图标：另有一套显式 `.Scale(...)`（见 Q3）。
- **任务内的真实 Agent**：不走 `AgentVisuals` 这条 C# 链，走 native —— 见 2.5。

另有第二个缩放入口，作用在**骨架**上：

### 2.6 胖瘦/体格走骨骼，不走整体缩放

`Modules/Native/ModuleData/skins.xml`（`<race id="human">` → `<skin>` → `<deform_keys>`）：

```xml
<deform_key id="weight" key_time_point="60" name="Weight" group_id="0">
    <bone_scales>
        <bone_scale bone_type="biped_abdomen" axis="x" key_min="1"   key_max="1.0" />
        <bone_scale bone_type="biped_abdomen" axis="y" key_min="0.95" key_max="..." />
        ...
    </bone_scales>
</deform_key>
<deform_key id="build"  key_time_point="61" name="Build" group_id="0"> <bone_scales>…</bone_scales> </deform_key>
<deform_key id="height" key_time_point="62" name="Height Multiplier" group_id="0" />   ← 空标签：无 bone_scales
<deform_key id="age"    key_time_point="63" name="Age"   group_id="0" />              ← 空标签
```

⇒ **weight/build 是"逐骨、逐轴"的骨架缩放，范围写在 XML 里**（`bone_type` 用引擎骨枚举），native 施加。
⇒ **height 在 XML 里是空的** —— 佐证身高不走骨骼、不走 XML。

`skin` 上另有一个 `min_scale` 属性（唯一值 `1.07`；同 race 下 10 份 skin 配 `mesh_maturity_type`：adult 1.07/1.06、teenager 0.94/0.93、tween 0.78、child 0.64、toddler 0.52）。**native 消费**（`TaleWorlds.Native.dll` 里有 `min_scale` 字符串，C# 侧无 `Skin` 类），语义本文未定，见"未证实项"。

### 2.7 头部/头盔的另一条缩放（做"兜"必看）

每个**脸形** deform_key 带一对 `helmet_scaling_factor_min/max`（Vec3）：

```xml
<deform_key id="face_width" key_time_point="1" key_min="-0.6" key_max="0.9" …
            helmet_scaling_factor_min="-0.1, 0.0, 0.0"
            helmet_scaling_factor_max="0.015, 0.0, 0.0" />
```

（全文件 142 处 `helmet_scaling_factor_min`；`key_time_point=60..63` 四条身体键**都没有**这对属性。）

链：

```csharp
// TaleWorlds.MountAndBlade.dll → MBAgentVisuals
public MatrixFrame GetFacegenScalingMatrix() {
    MatrixFrame identity = MatrixFrame.Identity;
    Vec3 currentHelmetScalingFactor = MBAPI.IMBAgentVisuals.GetCurrentHelmetScalingFactor(GetPtr());
    identity.rotation.ApplyScaleLocal(currentHelmetScalingFactor);
    return identity;
}

// TaleWorlds.MountAndBlade.View.dll → AgentVisuals.AddArmorMultiMeshesToAgentEntity / MissionScreen 同款代码
if (val3.UsingFacegenScaling) {                       // val3 = MetaMesh
    Skeleton skeleton = _data.AgentVisuals.GetSkeleton();
    val4.UseHeadBoneFaceGenScaling(skeleton, _data.MonsterData.HeadLookDirectionBoneIndex,
                                   _data.AgentVisuals.GetFacegenScalingMatrix());
}
// → TaleWorlds.Engine.dll → MetaMesh.UseHeadBoneFaceGenScaling(skeleton, headLookDirectionBoneIndex, frame)
```

⇒ **只有带 `UsingFacegenScaling` 标志的 MetaMesh 才跟脸形缩放**。这是"头盔会随脸宽/脸深被引擎自动缩放"的实现（工程既有记录见 [骑砍2盔甲资产工程.md](骑砍2盔甲资产工程.md) §3.5）。**我们的头/兜有没有这个标志要落实。**

### 2.8 装备装配点（为什么"一起变"）

`TaleWorlds.MountAndBlade.View.dll` → `AgentVisuals.AddArmorMultiMeshesToAgentEntity(...)`（装备槽 5..9 = 头/身/腿/手/披风）：

```csharp
if ((int)val == 5 || (int)val == 6 || (int)val == 7 || (int)val == 8 || (int)val == 9) {
    ItemObject item = _data.EquipmentData[(int)val].Item;
    ItemObject val3 = _data.EquipmentData[(int)val].CosmeticItem ?? item;   // ← 有 CosmeticItem 就用它
    ...
    val4 = _data.EquipmentData[(int)val].GetMultiMesh(isFemale, hasGloves, needBatchedVersion: true);
    ... _data.AgentVisuals.AddMultiMesh(val4, MBAgentVisuals.GetBodyMeshIndex(val));
}
```

⇒ 护甲网格与皮肤网格进的是**同一个 `AgentVisuals` 对象**。任何作用在该对象根 transform / 骨架上的缩放，对两者同等生效 —— **这就是 Q2 的答案。**
（顺手记一条可用机制：`EquipmentElement.CosmeticItem` 非空时，实际渲染用的是 CosmeticItem 的网格。）

## 4. 未证实项

按"怎么验证"分条列出。**看清的写清了，看不清的不编。**

### 4.1 身高的 6 bit 到底在 KeyPart7 还是 KeyPart8（最需要先定的一条）

- **已知**：C# 里读 `KeyPart8` 的位 19..24（IL 确凿）；同一方法把改过的值写进 **KeyPart7 槽**（IL 确凿）；实数据里 KeyPart7 该字段几乎恒 0、KeyPart8 该字段均匀铺开。
- **不可见**：native `MBFaceGen::get_scale` 读的是哪一个 —— **C++ 实现反编译看不到**。
- **推断**：读 KeyPart8 那侧是对的（数据分布吻合），C# 的 `ClampForMultiplayer` 回写是上游笔误（只影响多人夹取，单人路径不经过它）。
- **验证（30 秒，工具已在手）**：
  1. 取一个英雄的原脸键，把位 19..24 的值分别改在 KeyPart7 / KeyPart8 上（其余 8 个 ulong 一字不动）；
  2. 进场景跑工程已有的 `custom.height`（`CampaignMode/Tools/HeightReportCommands.cs`），看 `AgentScale` 与 `GetEyeGlobalHeight()` 是否跟着变。
  3. 哪一侧让它变，字段就在哪一侧。

### 4.2 人类 `AgentScale` 的数值范围与来源

- **已知**：它是均匀缩放（臂长/体重/眼高同乘）；C# 侧只读。
- **不可见**：native 在什么时候、用什么公式把它算出来（`CreateAgent` 的 `AgentSpawnData` 里只有 Monster 的量纲，**不含 BodyProperties**；BodyProperties 是在后面的 `AddSkinMeshesToAgentEntity` 才交给 native 的）。
- **验证**：`custom.height all` 在同一个场景里同时报我们的角色和原版 NPC，看 `AgentScale` 是否有非 1.0 的值、以及是否与身高滑块方向一致。

### 4.3 `Skin.min_scale` 的语义

- **已知**：`skin` 属性、native 消费（`TaleWorlds.Native.dll` 含该字符串，C# 侧无 `Skin` 类）；与 `mesh_maturity_type` 一一配对，无 `max_scale` 搭档。
- **两种读法**（都自洽，本文不裁定）：① "该 skin 适用角色缩放的**下限**"（成年人 ≥1.07、幼儿 ≥0.52）② "该 skin 自身网格的**缩放倍数**"。
- 支持读法①的旁证：一个 (maturity, 性别) 组合下只有**唯一**一份 skin，所以 `min_scale` 不可能是"在同级 skin 之间挑选"的阈值。
- **注意**：工程现有文档 [战国无双换装工程.md](战国无双换装工程.md) §4 记的"`min_scale` 1.07 → 1.35 会让信长变高一截"标的是**预期**，未记实测结果 —— 引用前先确认。
- **验证**：把某 race 的 adult skin 的 `min_scale` 改成 1.35 与改成 1.07，用 `custom.height` 对比同一角色的 `AgentScale`：变 → 读法①；不变 → 读法②。

### 4.4 我们自建头/兜网格上的 `UsingFacegenScaling` 标志

- **已知**：该标志决定网格跟不跟 `helmet_scaling_factor`。
- **未知**：我们 `head_*.fbx` 编译出的 MetaMesh 上这个标志是什么值（`tpaccli` 能不能读出来还没查）。这条直接决定"兜会不会跟脸形缩放"。
- **验证**：对着原版 `head_male_a` / 织丰自建头 `sho_head_male_japanese` 做同样检查，定出参照值；不一致就补。

### 4.5 native 里的具体施加点

- `IMBAgentVisuals.AddSkinMeshesToAgentEntity` / `UpdateSkeletonScale` / `SetFrame` 都是 native。**"缩放具体乘在根 entity 还是逐骨架"这件事，C# 侧只能从"所有部件都挂同一个对象、且面板预览里整体一起变"反推**。若需要从根上确认，只能靠实机量测（量不同身高下头骨/腹骨的世界系骨长）。

## 5. 落地清单（若采纳 B + 共用变换）

1. **定字段**：按 §4.1 的实验定下身高 6 bit 在哪个 KeyPart（这决定写哪儿）。
2. **写身高位**：`Hero.BodyProperties` → `MBBodyProperties.GetParamsFromKey(ref fgp, bp, false, false)` → 设 `fgp.HeightMultiplier = 目标 [0,1]` → `ProduceNumericKeyWithParams(fgp, false, false, ref np)` → `np.StaticProperties` 写回 `Hero.StaticBodyProperties`（`internal`，需反射；非主角没有官方写入口，见 §3 #23）。**范本已在库**：`ExampleModVS/.../Debug/MyCommands.cs` 2800~2980 行（同一套 API 的既有用法，含"只对主角生效"那条注释）。
3. **换算身高 → 取值**：源模型身高 → `HeightMultiplier` 的映射需要一个标定；工程已有 `HeightReportCommands.cs` 的"眼高 ÷ 0.930 = 总高"做量尺。先取 2~3 个样本（原版最高/最矮的领主）定出 [0,1] ↔ 米 的对应，再排我们的角色。
4. **共用一个变换**：同一角色的头/甲/兜按源模型同一变换导出、落到同一个基准尺度上（解决"脖子接领口"）。
5. **看住两条**：头/兜的 `UsingFacegenScaling`（§4.4）；身体甲的 `body_deform_type` 保持默认（原版从未用过，别引入）。
