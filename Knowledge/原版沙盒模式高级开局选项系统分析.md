# 🔴 原版沙盒模式高级开局选项系统分析（AdvancedStartOptions）

> **版本**：v1.5.1 新增（1.4.8 实测无此机制，三 DLL 对比实证：SandBox.dll / SandBox.View.dll / TaleWorlds.CampaignSystem.dll 的 `AdvancedStartOptions` 与 `unitedempire` 字符串 1.4.8 全部 0 命中）。
> **功能**：沙盒模式（GameType=Campaign）新游戏时，玩家可自定义「世界剧本（时代背景）/ 开局身份 / 全局修改器 / 种子」——即玩家口中的"选择不同时代背景开局"。
> **入口**：新游戏 → 角色创建 → 开局选项面板（`CampaignStartingOptionsVM`，先勾选「启用高级开局选项」总开关）。
> **价值**：官方原生提供**插件式注册扩展点**（`[StartOptionsProvider]` 特性），mod 无需 Harmony 即可往开局面板注入自己的选项，是制作三国/日本战国等**多时代入口剧本**的现成入口。

## 一、功能总览：四个分类（CategoryId）

| CategoryId | 中文意 | 选项 | 说明 |
|---|---|---|---|
| `general` | 通用 | `EnableFastMode`（布尔）/ `Seed`（uint） | 快速模式 / 确定性随机种子 |
| `worldscenarios` | **世界剧本（时代背景）** | `Scenario`（列表）+ 各场景参数 | **核心**：none / unitedempire / LastStand / twofactionwar / InvasionId / alternativecalradia |
| `scenarios` | 开局身份 | `StartType`（列表）/ `KingdomId`（列表） | default / king / vassal / mercenary / trader / outlaw / beggar |
| `globalmodifiers` | 全局修改器 | 4 个布尔开关 | RisenBanditsMultiplier（强盗增多）/ HighRebellion（高叛乱）/ RecruitmentRate（招募率）/ IncreasedGlobalMovementSpeed（移速） |

| 值 | 含义 | 参数选项（条件隐藏） |
|---|---|---|
| `none` | 原版卡拉迪亚 | — |
| `unitedempire` | 统一帝国：三分帝国（empire/empire_w/empire_s）合并为「Calradian Empire」 | `UnitedEmpireUnifierKingdomId`（统一者派系） |
| `LastStand` | 最后防线 | `LastStandKingdomId` |
| `twofactionwar` | 两派战争 | `TwoFactionWarFaction1Id` / `TwoFactionWarFaction2Id` |

| `nordinvasion` | 诺德入侵 | ⚠️ `ApplyWorldScenarios()` switch 里有分支，但 UI 列表**未注册**（隐藏场景，调试/预留） |

## 三、注册机制（mod 扩展点核心）

`AdvancedStartOptionsManager`（SandBox.dll）是 **Attribute 驱动的反射注册表**：

```csharp
public static class AdvancedStartOptionsManager
{
    // 扫描 ModuleHelper.GetActiveGameAssemblies() 全部程序集的全部类型
    // 找带 [StartOptionsProvider] 特性的 static 方法，签名：static void (AdvancedStartOptions)
    public static AdvancedStartOptions CreateCampaignStartOptions() { Initialize(); ... }
}

[AttributeUsage(...)] public class StartOptionsProviderAttribute : Attribute { }
```

**官方 provider 范本**（SandBox.View.dll）：

```csharp
[StartOptionsProvider]
private static void AddStartOptions(SandBox.AdvancedStartOptions.AdvancedStartOptions options)
{
    options.Add(new BooleanAdvancedStartOption("EnableFastMode", "general", null));
    options.Add(new UIntAdvancedStartOption("Seed", "general", 0u, uint.MaxValue, null, (uint)Environment.TickCount));
    options.Add(new ListAdvancedStartOption("Scenario", "worldscenarios",
        new List<(string, ListAdvancedStartOption.ListItemCondition)>
        {
            ("none", GetNeverDisabledItem),
            ("unitedempire", GetNeverDisabledItem),
            ("LastStand", GetNeverDisabledItem),
            ...
        }, null, "none"));   // 默认值 "none"
    options.Add(new ListAdvancedStartOption("KingdomId", "scenarios",
        GetCultureItems(GetStartingKingdomIsDisabled), GetStartingKingdomCondition));   // 隐藏条件
    ...
}
```

**关键语义**：
- **同 StringId 覆盖**：`AdvancedStartOptions.Add` 遇同 StringId 打印 `Overriding start option id:` 并替换 → mod 的 provider 若在官方之后执行，可整体替换官方选项（如改写 Scenario 列表）。
- **条件机制**：`ListItemCondition` = `bool Condition(AdvancedStartOptions o, out TextObject disabledText)`（禁用+原因）；`AdvancedStartOptionCondition` = `bool Condition(AdvancedStartOptions o)`（隐藏）。官方用 `MakeOptionHiddenCondition(optionId, o => GetScenario(o) != "xxx")` 实现场景参数联动隐藏。
- **解锁条件**：`BannerlordConfig.CompletedTraderPlaythrough` / `CompletedKingPlaythrough`（完成过对应身份的通关才解锁该身份开局）。

## 四、生效层：世界剧本如何改变世界

**类**：`AdvancedStartWorldOptionsCampaignBehavior : CampaignBehaviorBase`（TaleWorlds.CampaignSystem.CampaignBehaviors）

```csharp
// RegisterEvents: CampaignEvents.OnNewGameCreatedEvent → OnNewGameCreated → ApplyWorldScenarios()
public static void ApplyWorldScenarios()
{
    switch (Campaign.Current.AdvancedStartData.GetScenario())
    {
    case "LastStand":   OnLastStandScenarioSelected(GetRandomForScenario(WorldScenarioSeed.LastStand)); break;
    case "twofactionwar": OnTwoFactionWarScenarioSelected(GetRandomForScenario(WorldScenarioSeed.TwoFactionWar)); break;
    case "unitedempire": OnUnitedEmpireScenarioSelected(GetRandomForScenario(WorldScenarioSeed.UnitedEmpire)); break;
    case "InvasionId":  OnInvasionScenarioSelected(GetRandomForScenario(WorldScenarioSeed.Invasion)); break;
    case "alternativecalradia": OnAlternativeCalradiaScenarioSelected(GetRandomForScenario(WorldScenarioSeed.AlternativeCalradia)); break;
    case "nordinvasion": OnNordInvasionScenarioSelected(GetRandomForScenario(WorldScenarioSeed.NordInvasion)); break;
    }
}

private static MBFastRandom GetRandomForScenario(WorldScenarioSeed scenarioSeed)
    => new MBFastRandom((uint)((ulong)Campaign.Current.Options.Seed ^ (ulong)scenarioSeed));
// WorldScenarioSeed 私有枚举：LastStand=522134860, TwoFactionWar=335872418, UnitedEmpire=918273645,
//                            Invasion=1517171341, AlternativeCalradia=726028561, NordInvasion=647125983
```

**实现套路**（unitedempire 范本，可复用）：
1. 读参数：`Campaign.Current.AdvancedStartData.GetUnitedEmpireUnifierKingdomId()`
2. `Campaign.Current.KingdomManager.CreateKingdom(...)` 新建王国（文化/旗帜/颜色/头衔从源派系拷贝）
3. 迁移家族：`ChangeKingdomInternal(clan, oldKingdom, newKingdom)`（内部 `ClanLeaveKingdom(giveBackFiefs: true)` + 改归属）
4. 继承政策：`kingdom.AddPolicy(...)`
5. `HandleKingdomCleanup(scenarioRandom)`：清掉空王国（`Kingdom.All` 里 `Clans.Count == 0` 且非玩家所选王国的）
6. `FactionManager.DeclareWar` 重建战争关系

**生效时机**：`OnNewGameCreated`（世界生成完成后）——场景逻辑是**改已有世界**（合并/重置派系关系），不是重建地图。

## 四·五、各剧本的本质差异（🔴 直接回答"每个剧本差什么"）

**结论：全部剧本共享同一套世界定义（SandBox 模块的同一份 cultures/kingdoms/clans/lords/settlements XML），剧本差异 = 运行时对「势力归属关系」的重排。不换文化、不换英雄表、不改英雄年龄/生死、不换地图。**

| 维度 | 是否共享 | 剧本差异 | 代码证据 |
|---|---|---|---|
| 文化 `CultureObject` | ✅ 完全共享（原版 8 文化） | **无差异** | 全部场景代码无任何 Culture 操作 |
| 王国 `Kingdom` | 共享原版 11 王国 | ① unitedempire **运行时新建**「Calradian Empire」（`KingdomManager.CreateKingdom`，唯一新实体，成员全是原版英雄）② alternativecalradia **运行时销毁** 0–5 国（default 0–2 / fractured 碎裂 2–4 / shattered 粉碎 3–5）③ twofactionwar 销毁其余全部只留玩家选的双方 | `OnAlternativeCalradiaScenarioSelected` → `GetAlternativeCalradiaDestroyRange` |
| 家族 `Clan` | ✅ 共享原版家族表 | 差异只在**归属**：`ChangeKingdomInternal` 迁移；LastStand 70% 家族叛逃邻国；DestroyKingdomByDefection 按「邻接最多」逐个叛逃 | `OnLastStandScenarioSelected` / `DestroyKingdomByDefection` |
| 英雄 `Hero` | ✅ **完全共享**（lords.xml 一份英雄表） | **无年龄/生死/出生差异**。没有剧本创建英雄、杀死英雄、改年龄——只有 unitedempire 把统一者派系 `RulingClan` 变成新帝国 ruler | 全类无 Hero 年龄/死亡操作（代码审查） |
| 定居点 `Settlement` | ✅ 地图/城镇/村庄实体不变 | 差异只在**归属**：`GrowKingdomByInvasion` 吞并邻城（Invasion 吞 60–70%、Nord 吞本国+10–14 城、AltCalradia 每国 +20–40%）、`GiveSettlementToClan` 转移 | `OnInvasionScenarioSelected` 等 |
| 战争/和平状态 | 按剧本重置 | LastStand 清空全部战争再单宣一敌；Invasion/Nord 与所有邻国宣战；AltCalradia 邻居间 20% 概率重开战、非邻居停战 | `UpdateWarAndPeaceInTheWorld`（邻居判定 `AreKingdomsNeighbors`） |

**⚠️ 对自制时代剧本的关键启示**：
- 官方剧本机制 = **「同一世界 × 不同势力格局」**，未触及文化表/英雄表/年龄/生死——做「三国 190 年 vs 220 年」这类**人物年龄/生死不同**的时代剧本，官方 ASO 机制不够，需补：①数据层换英雄表（参考织丰之世替换 StoryMode 数据的路子，但那是 1.2.12 方案）②或 `OnNewGameCreated` 后运行时改造（改年龄/生死无官方范本，需自查 `Death` 相关 API）。
- 「只重排势力格局」的剧本（如"蜀汉统一天下"式）可直接复用官方套路。

## 四·六、强行设置已有 Hero 的年龄 / 出生 / 死亡（API 可行性实证，2026-08-24）

**结论：完全可行，官方 API 齐备，且玩家角色创建就是官方范本。** 开新档后遍历 `Hero.All` 逐个设置即可，无需 Harmony。

| 想做的事 | 官方 API | 官方范本调用点 |
|---|---|---|
| 设年龄 | `hero.SetBirthDay(CampaignTime.YearsFromNow(-age))`（public） | 角色创建选年龄：`Hero.MainHero.SetBirthDay(HeroHelper.GetRandomBirthDayForAge(age))`（CampaignSystem 14111 行）；`Age` 是派生值（`_birthDay.ElapsedYearsUntilNow`），无直接 setter，改生日即可 |
| 设为未出生 | `hero.ChangeState(Hero.CharacterStates.NotSpawned)`（public）+ BirthDay 设未来 | 原版 `Hero.Deserialize`：lords.xml 英雄**默认 NotSpawned**，`alive="false"` 属性才标 Dead |
| 设为出生/登场 | `hero.ChangeState(Hero.CharacterStates.Active)` | `HeroSpawnCampaignBehavior.OnNewGameCreatedPartialFollowUp` 开档批量激活；`OnHeroComesOfAge`（成年事件，`AgeModel.HeroComesOfAge`）→ Active + `TeleportHeroAction` 送回老家 |
| 设为死亡 | `KillCharacterAction.Apply(victim, killer, detail, showNotification)`（public static，官方唯一死法入口，带 quest/重复击杀断言）+ `hero.SetDeathDay(CampaignTime)` | 原版 `Deserialize` 的 alive="false" 分支 |
| 建新英雄 | `HeroCreator.CreateSpecialHero(...)` / `HeroCreator.CreateHero(...)` + `InitializeHeroFromCharacterData`（年龄钳制 `HeroComesOfAge`、装备、等级） | `CreateMinorFactionHeroFromTemplate`（197769 行附近） |

**状态机**：`CharacterStates` 枚举 = NotSpawned（未出生）/ Active / Fugitive / Prisoner / Released / Dead / Disabled / Traveling；`HeroState` 属性 private set，**但 `ChangeState()` 方法本身 public**。`ChangeState` 会触发：`CampaignObjectManager.HeroStateChanged` + `OnHeroActivated`（Active）/ `OnHeroGetsBusy`（Traveling）+ Clan 通知——副作用需知晓。

**🔴 四个坑**：
1. **改年龄不联动技能/等级**：`SetBirthDay` 只改生日字段重算 `_defaultAge`；技能值、等级是独立字段——50 岁改 20 岁技能不变。时代剧本需配合清技能/按年龄重算（参考 `HeroCreationModel.GetDefaultSkillsForHero`）。
2. **`OnHeroComesOfAge` 自动激活**：原版成年事件会把到龄英雄自动 Active——设「未出生」必须同时把 BirthDay 设到未来，否则事件会把他拉起来。
3. **状态切换副作用**：`ChangeState(Active)` 触发 `OnHeroActivated` 事件，其他系统会响应（如 `AssignSettlementToHeroOnGameStart` 分配老家）；部队里/战斗中的英雄别乱切。
4. **`KillCharacterAction` 断言**：已死英雄重复击杀 = FailedAssert；有 quest 的 notable 禁止击杀。

## 四·七、按年龄重算技能/等级（官方链，HeroCreator 初始化范本，2026-08-24）

**坑 1 的解法：官方没有「按年龄重算」的单独 API，但有完整范本 —— `HeroCreator.CreateHero` 的初始化链（CampaignSystem 45548 行附近）就是「从 0 按数据重设英雄」的官方流程，直接复用。**

**步骤 1 —— 重设技能**（依赖 `hero.Age`，**必须先 `SetBirthDay` 再调**）：

```csharp
// GetDefaultSkillsForHero（DefaultHeroCreationModel 62324 行）
// - hero.Age < HeroComesOfAge → 返回空列表（未成年无技能）
// - 成年 → 遍历 Skills.All，取 hero.CharacterObject.GetDefaultCharacterSkills()
//          （角色模板的默认技能）+ AddNoiseToSkillValue（加噪声）
foreach (var (skill, value) in Campaign.Current.Models.HeroCreationModel.GetDefaultSkillsForHero(hero))
{
    hero.SetSkillValue(skill, value);   // Hero.SetSkillValue 为 public
}
```

**步骤 2 —— 重算等级/属性（HeroDeveloper.InitializeHeroDeveloper，160314 行）**：

```csharp
hero.HeroDeveloper.InitializeHeroDeveloper();   // 开发序列：
// ① SetInitialLevelFromSkills()：TotalXp = max(1, Σ(2 × skill^2.2) − 2000)  ← 等级从技能反推
// ② CheckLevel()                              ← 按 TotalXp 定 Hero.Level
// ③ SetupDefaultPoints() + SetInitialFocusAndAttributePoints()
// ④ DevelopCharacterStats()（非儿童）→ DistributeUnspentAttributePoints + DistributeUnspentFocusPoints + SelectPerks
```

**时代剧本「重置英雄」完整流程（四·六 + 四·七串起来）**：

```csharp
// 开档后（OnNewGameCreatedEvent，建议在 HeroSpawnCampaignBehavior 激活之后）
foreach (var hero in Hero.All)
{
    // 1. 年龄：按剧本数据表设生日
    hero.SetBirthDay(CampaignTime.YearsFromNow(-dataTable[hero].age));
    // 2. 生死：ChangeState(NotSpawned/Active) + KillCharacterAction.Apply(死)
    // 3. 技能+等级：官方初始化链
    foreach (var (skill, value) in Campaign.Current.Models.HeroCreationModel.GetDefaultSkillsForHero(hero))
        hero.SetSkillValue(skill, value);
    hero.HeroDeveloper.InitializeHeroDeveloper();
    // 4. 阵营归属：ChangeKingdomInternal（官方场景套路）/ clan 迁移
}
```

**🔴 三个坑**：
1. **顺序依赖**：`GetDefaultSkillsForHero` 内部判 `hero.Age` —— 不先设生日，未成年/成年判定错。
2. **`UnspentAttributePoints` 会负**：`SetInitialFocusAndAttributePoints` 是 `UnspentAttributePoints -= attributeValue` 扣减法，官方从新英雄（0 点）开始；对**已有属性点的老英雄**重算可能出现负数 —— 重算前需确认/重置 `UnspentAttributePoints`、`UnspentFocusPoints`。
3. **重算丢已有经验/等级**：`SetInitialLevelFromSkills` 覆盖 TotalXp —— 对「开新档设初始状态」场景无碍；对**存档中**的英雄重算会掉级。时代剧本只在开档做，安全。

## 七、对三国 / 日本战国多时代入口剧本的可复用性评估

**结论：这是 1.5.1 官方给「时代剧本」预留的天然入口，比织丰之世（自定义 GameType `ShokuhoCampaign` + 替换 StoryMode 模块）的方案干净得多。**

### ✅ 现成的注入点
1. **UI 自动出现**：`[StartOptionsProvider]` 静态方法 + `options.Add(new ListAdvancedStartOption("Era", "worldscenarios", ...))` → 开局面板自动多一个「时代」下拉，**零 UI 代码**（VM 按 CategoryId 自动分组渲染）。
2. **数据自动持久化**：`AdvancedStartOptionsData` 走 `SaveableField`，随存档存读；业务层随时 `Campaign.Current.AdvancedStartData.GetOption("Era")` 读取。
3. **条件联动现成**：用隐藏条件（AdvancedStartOptionCondition）做「选了时代 X 才显示时代 X 的参数」。

### ⚠️ 需要自己补的部分
1. **生效逻辑**：官方 `ApplyWorldScenarios()` 的 switch 只认官方 ID——mod 自定义场景需自己监听 `CampaignEvents.OnNewGameCreatedEvent`（注意官方 Behavior 也是这个事件，执行顺序按注册顺序）读选项、改世界（参考 unitedempire 套路：改王国/派系/领地归属）。
2. **世界生成更早介入**：场景逻辑在 `OnNewGameCreated` 是「改世界」不是「建世界」。若三国/战国要**换地图/换文化**，需要更早（`CampaignGameStarter` 阶段）或更彻底的替换——织丰之世用自定义 GameType 的办法依然适用，但 ASO 可以作为「轻量时代剧本」入口（不改地图、只改势力格局/初始状态）。
3. **版本宏**：1.5.1 独有 → mod 代码必须 `#if MB2_GE_150` 包裹（宏体系里已存在，1.5.0+ 定义）；旧版本（≤1.4.8）不能引用这些类型。
4. **类型引用**：框架类型在 `SandBox.dll`（`SandBox.AdvancedStartOptions`），数据/扩展方法在 `TaleWorlds.CampaignSystem.dll`——LivingWorldNpcs 已引用这两个程序集，无新增引用。

### 与现有世界观机制的关系（LivingWorldNpcs 视角）
- 本项目世界观完全自动生成（[worldview.md](../plans/rules/worldview.md)，无静态 flavor），时代剧本 = 数据型入口。
- 自然的落地形态：ASO 的「时代」选项作为**入口剧本选择器**（三国/战国/卡拉迪亚），选中后 mod 读取选项、按时代注入世界观数据与开局事件——**不冲突、复用官方 UI 与存档**。
- 注意铁律：玩家可见文本走 `{=LWN_KEY}` 本地化，注入的选项名/值名也要提供 LWN 翻译条目。
