# 自定义战斗 —— 从自造动画到可玩招式

> 来源：三个实机 mod 逆向（`Stance Combat Overhaul` / `ArtemsCinematicCombat` / `ArtemCore`），2026-09-13；飞行物与光效部分为 2026-09-18 引擎反编译实证。
> 目标问题：**能不能用自己的角色动画做自己的战斗招式？怎么做？** + **能不能发飞行物/剑气特效？怎么做？**
> 配套阅读：[动画导入与UE5重定向_引擎能力与实现路径.md](动画导入与UE5重定向_引擎能力与实现路径.md)（怎么把外部 FBX 变成骑砍能播的动画）、[tpac资源替换打包指南.md](tpac资源替换打包指南.md)（怎么读写 tpac 包）、[§15 飞行物与剑气特效](#15-飞行物与剑气特效月光剑气这类)（怎么甩出一个会飞的特效）。
> 本文补的是这两篇之间的缺口：**动画进了游戏之后，怎么让它变成"招式"**，以及**招式怎么甩出一个会飞的特效**。

## 0. 结论速览

| 问题 | 结论 |
|---|---|
| 能不能做？ | ✅ 能。三个参考 mod 是实机证据 |
| 需要改判定的攻击招式呢？ | ✅ 能，但判定帧耦合，要对齐帧；或者走"动画只当皮、伤害自己结算"的路子 |
| 必须用 Harmony 吗？ | ❌ **不必**。Artem 家族 250 个动作、处决/反击/交击全套，**一行补丁都没打** |
| 最难的一步是什么？ | **造动画本身**。接入是 3 个 XML + 十几行 C# |
| 提交前最容易静默失败的地方？ | `animation=` 名字写错 → 动作解析成 `act_none`，**不报错** |
| 我的 1.2.12 环境能用吗？ | ✅ 机制完整具备（已核实）；三个参考 mod 本身是 1.3.15+/1.4.x，装不了 |
| **判定帧从哪来？** | 引擎**按动画播放百分比**检测武器碰撞，窗口配在 `combat_parameters.xml`，由 clip 的 `combat_parameter_id` 指定（§11） |
| **格挡要自己写吗？** | ❌ 格挡全 native 判。给 clip 设 `combat_parameter_id` 就白送格挡/招架判定（§12） |
| **根运动还是原地？** | **默认原地**。要根运动 = clip 开 `displace_position` flag + 配 displacement 数据；**循环动作绝不能开**（§13） |
| **状态机怎么控？** | 优先级藏在 64 位 flags 的**低 8 位**；channel 0 = 全身、channel 1 = 上半身（§10） |

**一句话**：引擎把「动作」和「动画」分成两层——动作是名字+语义（XML 注册），动画是骨骼数据（tpac 资产）。你要做招式，就是**造动画 → 起个动作名绑上去 → 代码按名字播**。

**第二句话**：判定不用你自己发明——引擎的判定是**按动画进度百分比**触发的连续扫掠，窗口写在配置里、由 clip 指定。**手工打伤害只是三个参考 mod 的选择，不是唯一出路**（详见 §11）。

## 2. 全链路五步

### 第 1 步：造动画（Blender）

**硬规格**：

| 项 | 要求 |
|---|---|
| 骨架 | 绑 `human_skeleton` 的骨名（28 骨）。骨名不匹配 = 通道落空 = T-pose |
| 位移 | 🔴 **原地做，零净位移**（走路/翻滚/挥砍都一样） |
| 例外：要根运动 | 只有明确要角色被动画带着走时，才在 clip 上开 `displace_position` 标志。**循环动作（走/跑）绝不能开** |
| 帧率 | 30fps（优）或 60fps |
| 骨骼上限 | 64 根 |
| 根骨命名 | 名称以 `_notused` 结尾 |
| 导出 | 只导骨骼，不导网格；`bake_anim=True`、`bake_anim_step=1.0`、`bake_anim_simplify_factor=0.0`、`axis_up='Z'`、`axis_forward='-Y'` |

**成对动画**：真正的"招式"是**两段动画一起播**——执行者一段、受害者一段。命名惯例（两个参考 mod 都这么写）：

```
执行者: act_combat_360_killmove_custom          ← 攻击方
受害者: act_combat_360_killmove_death_custom    ← 受击方
反击:   act_onehanded_master_strike_1_affector  ← 攻击方
        act_onehanded_master_strike_1_affected  ← 受击方
```

**空烘焙自检**：健壮的导出是数 MB、耗时数秒。**0.06MB 且瞬间完成 = 一个关键帧都没烘出来**（通常是改名骨骼后 fcurve 路径没跟着改）。

### 第 2 步：导进 ModKit，建 Animation Clip

1. 资源浏览器 → 右键 → `Import new asset` → 选 FBX
2. 导入类型选 **Skeleton Animation**，设 **Owner Skeleton**
3. 建 **Animation Clip**：`Source 1 = 0`、`Source 2 = 末帧`、**Duration 必须 > 0**
4. clip 检视器里设属性（见下表）
5. 发布到本 mod 的 `AssetPackages/*.tpac`

**Clip 属性速查**（这些不在 FBX 里，必须在编辑器补）：

| 属性 | 作用 | 建议值 |
|---|---|---|
| `blend_in_period` | 融合进来的时长 | 攻击类 0.1 左右 |
| `blend_out_period` | 提前进入融合 | 见官方说明，0 = 播完突然停 |
| `priority` | 能否打断别的动作 | 按语义 |
| `flags` | 见下方 flag 表 | **攻击/处决：`enforce_all` 必开** |
| `continue_to_action` | 播完自动接另一个**动作** | 收招接回待机就填这 |
| `voice_code` | 播这个动画时自动配音 | 如 `convo_angry_voice` |
| `step_points` | 脚步音时点 | 不设读作 `-1,-1,-1,-1` |
| `left_hand_pose` / `right_hand_pose` | 手部姿势 | 按需 |

**实测到的 flag 组合**（从两个 mod 的 clip 元数据里解出来的真值）：

```
处决攻击方（8 个）: ignore_all_collisions, client_prediction, disable_hand_ik,
                    use_left_hand_during_attack, lock_movement, enforce_lowerbody,
                    enforce_all, disable_foot_ik
处决受击方（10 个）: 上面 8 个 + keep（播完保持姿势不结束，尸体用）+ displace_position（根运动）
翻滚（3 个）:        disable_hand_ik, enforce_all, disable_foot_ik
```

> 🔴 **2026-09-18 勘误**：旧版本文写「处决受击方 = 上面 + keep」（= 9 个）对不上元数据里的 10 个。逐字节重读 `combat_360_killmove_death_custom.meta` 后确认：第 10 个是 **`displace_position`**，`keep` 排在第 3 位。即**处决受击方那一条 clip 是开了根运动的**。

🔴 **`enforce_all`（全身接管）是攻击/处决类的必备项**——它防止 channel 1 和移动动画同时播导致动作打架。

🔴 **不要在编辑器里改 clip 名**——会损坏（Size 显示 0、拒绝保存、改名文件可能直接消失）。要改就关掉编辑器、改磁盘文件名、重开。

### 第 3 步：注册三件套（**这一步错了会静默失败**）

**文件 A —— `ModuleData/action_types.xml`**：声明动作名存在

```xml
<action_types>
  <action name="act_my_move" />
</action_types>
```

移动/表演类动作**不需要任何属性**。要参与原版战斗系统才需要 `type` / `usage_direction` / `action_stage`（详见 §10）。

**文件 B —— `ModuleData/action_sets.xml`**：动作名绑到动画 clip

```xml
<action_sets>
  <action_set id="as_human_warrior" skeleton="human_skeleton" movement_system="bipedal">
    <action type="act_my_move" animation="my_move_clip" />
  </action_set>
</action_sets>
```

三个要点：

- **同 id 声明 = 增量合并**，不是替换。原版几千个动作不会被你挤掉（三个参考 mod 全都这么干）
- `animation=` 填的是 **Animation Clip 的名字**——不是 FBX 里的 take 名，不是 Skeleton Animation 资源名
- **动作名和 clip 名可以完全不同**（实测：`act_twohanded_dodge_back` → clip `cc_twohanded_dodge_back`）

**文件 C —— `ModuleData/project.mbproj`**：告诉引擎去解析上面两个文件

```xml
<base type="solution">
  <file id="soln_action_sets"  name="ModuleData/action_sets.xml"  type="action_set" />
  <file id="soln_action_types" name="ModuleData/action_types.xml" type="action_type" />
</base>
```

🔴 **`id` 必须用标准名**（`soln_action_sets` / `soln_action_types`）。自定义 id（如 `soln_my_action_sets`）**被静默忽略**——XML 完全正确、文件就在磁盘上、就是死的。

🔴 **同一个 id 不能出现两次**——启动直接 `KeyNotFoundException`。

🔴 **用 `action_sets.xml`，不要用 `action_sets.xslt`**——xslt 路线会触发 human-bullet（角色变折叠人）。

### 第 4 步：代码播动作

```csharp
// ① 解析一次，静态缓存（官方明确要求，别每帧 Create）
private static readonly ActionIndexCache MyMove = ActionIndexCache.Create("act_my_move");

// ② 播。失败会返回 false 且 act_none——必须查
if (!agent.SetActionChannel(0, ref move, ignorePriority: true,
        additionalFlags: 0, blendWithNextActionFactor: 0f, actionSpeed: 1f,
        blendInPeriod: 0.1f, blendOutPeriodToNoAnim: 0.4f, startProgress: 0f,
        useLinearSmoothing: false, blendOutPeriod: -0.2f, actionShift: 0,
        forceFaceMorphRestart: true))
    return;

// ③ 确认真的抢到了通道（可能被更高优先级的动作顶掉）
if (agent.GetCurrentAction(0) != MyMove) return;

// ④ 进度驱动（不需要协程/计时器）
float t = agent.GetCurrentActionProgress(0);
if (t >= 0.4f && !_seen.Contains("hit")) { _seen.Add("hit"); /* 结算 */ }

// ⑤ 收工
agent.SetActionChannel(0, ref ActionIndexCache.act_none, ...);
```

**`SetActionChannel` 参数怎么读**（签名取自 1.2.12 引擎，1.4/1.5 一致）：

| 参数 | 含义 |
|---|---|
| `channelNo` | **0 = 全身接管**；**1 = 上半身叠加**（嘲讽/喊话/挥手用 1） |
| `ignorePriority` | 是否无视优先级强制播 |
| `additionalFlags` | 运行时追加的 `AnimFlags`（位掩码）。**和 clip 自带 flag 是两套**，会叠加 |
| `actionSpeed` | 播放速度倍率 |
| `blendInPeriod` | **负值 = 按动画时长比例；正值 = 绝对秒数** |
| `startProgress` | 从动画的百分之几开始播（**错开一群人的同一动作就靠这个**） |
| `useLinearSmoothing` | 线性插值（慢动作类用） |

**动作类清理**：`agent.SetActionChannel(ch, ref ActionIndexCache.act_none, ...)`

### 第 5 步：表现层（决定"像不像原生游戏"）

这一步不做，功能是通的但观感是业余的。参考 mod 的做法：

| 项 | 做法 |
|---|---|
| **锁血** | 演出期间双方 `SetMortalityState(Invulnerable)`；**致命一击前先切回 `Mortal` 再 `RegisterBlow`**，否则打不死 |
| **围观隔离** | 刷一个隐形物理碰撞体把看客挡开；再把正瞄准这对搭档的 AI 目标改指别人 |
| **相机** | `MissionView` 里自建相机（`SetCameraFrame`），并把挡镜头的其他 Agent 藏起来 |
| **音效** | 自定义 wav 走 `ModuleSounds/` + `module_sounds.xml` 注册；或用 clip 的 `voice_code` |
| **血/粒子** | `Scene.CreateBurstParticle("psys_game_blood_sword_enter", ...)` + `Agent.SetAgentFacialAnimation(0, "cry", true)` |
| **收招** | 用 clip 的 `continue_to_action` 接回对应武器的待机动作。**左右手站姿要分**（`*_left_stance`），否则左撇子穿模 |
| **打断** | 每帧巡检当前动作名，被外力顶掉就立即出账（清状态、恢复 Mortal） |

## 3. 关键技法：进度阈值打点表

这是 ArtemsCinematicCombat 最值得抄的结构。**不用协程、不用计时器、不用状态机**——用动画自身的播放进度当时钟，配一个 HashSet 去重：

```csharp
string name = victim.GetCurrentAction(0).GetName();
float  t    = victim.GetCurrentActionProgress(0);

if (name.Contains("act_combat_360_killmove_death")) {
    if (t >= 0.23f && !seen.Contains("strike-2")) {
        seen.Add("strike-2");
        RegisterBlow(...);                    // 结算伤害
        MakeBladeHitSound(...);               // 音效
        ApplyBlood(...);                      // 血
    }
    if (t >= 0.61f && !seen.Contains("final")) {
        seen.Add("final");
        victim.SetMortalityState(Mortal);     // 先解锁
        blow.InflictedDamage = (int)victim.Health;  // 再必杀
        victim.RegisterBlow(blow, ref acd);
    }
}
```

优点：断帧安全、可序列化、新增动画只加分支不改结构。参考 mod 里 44 个分支、单条动画 2~10 个打点，全靠这个。

**成对动画用字典驱动**，别写 if-else 树：

```csharp
// key = 执行者动作名, value = (受害者动作名, 入场距离)
Dictionary<string, (string victimAction, float teleportDistance)> Killmoves = {
    ["act_combat_360_killmove_oh_custom"] = ("act_combat_360_killmove_death_custom", 1.75f),
    ...
};
```

新增一个处决 = **加一行**，零代码改动。参考 mod 有 45 对。

## 4. 坑点清单

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | `animation=` 名字不是 clip 名 | **静默**，动作解析成 `act_none` | 对着 ModKit 里 clip 的实际名字填；代码里查 `SetActionChannel` 返回值和 `GetCurrentAction` |
| 2 | `project.mbproj` 没登记 | 文件从不解析，动作静默不存在 | 用标准 id 登记，两个文件都要 |
| 3 | 自定义 `soln_*` id | **静默忽略** | 只用 `soln_action_sets` / `soln_action_types` |
| 4 | 两个 `soln_action_sets` 行 | 启动 `KeyNotFoundException` | 一个 id 一行，多个文件用同一个 id 写多行 |
| 5 | 用 xslt 加动作 | 角色变折叠人（human-bullet） | 用 `.xml`，不用 `.xslt` |
| 6 | 编辑器里改 clip 名 | Size=0、拒绝保存、文件消失 | 关编辑器改磁盘文件名再重开 |
| 7 | 走路/循环动画带根位移 | 双倍速 + 滑步 | 循环动作一律原地做 |
| 8 | 攻击 clip 少了 `enforce_all` | 全身动作和上半身动作打架 | 攻击/处决类务必带上 |
| 9 | 独立 `action_set` 不带 `base_set` | 引擎升级后缺动作 → 崩游戏 | 挂 `as_human_warrior` 增量合并 |
| 10 | 拿名字当标识做运行时匹配 | 本地化/改名后失效 | 🔴 引用一律用 StringId（本项目铁律 20） |
| 11 | 以为 flag 是运行时传的 | 根运动/全身接管不生效 | **clip 自带 flag 和运行时 `additionalFlags` 是两套**，要分清 |
| 12 | 演出没锁血 | 招式没放完人就死了 | `SetMortalityState(Invulnerable)`；致命一击前切回 `Mortal` |
| 13 | 演出没清状态就结束 Mission | 留下永久无敌的 Agent | 抄参考 mod 时要补 `OnAgentRemoved` / Mission 结束的清理（**参考 mod 本身漏了**） |

## 5. 两条路线：移动表演类 vs 攻击招式类

### A 档 —— 位移 / 表演类动作（零风险）

翻滚、闪避、突进、处决演出、嘲讽、胜利姿势、登场亮相。

**为什么零风险**：引擎不参与判定，动画想怎么编怎么编。Stance Combat Overhaul 的翻滚就是这一档。

### B 档 —— 真正的攻击招式（有耦合）

原版战斗系统按动作的**分类属性**决定命中时机：

```xml
<action name="act_my_attack"
        type="actt_release_melee"        <!-- 动作大类的语义 -->
        usage_direction="ud_attack_right" <!-- 从哪个方向打 -->
        action_stage="as_attack_release" /> <!-- 处于哪一阶段（起手/释放） -->
```

`type` 常用值：`actt_release_melee`（近战释放）、`actt_ready_melee`（起手）、`actt_defend_*`（防御，按武器分）、`actt_weapon_bash`（盾击）、`actt_blocked_melee`（被格挡）……

**两条子路线**：

| | 做法 | 代价 | 适用 |
|---|---|---|---|
| **B1 稳** | 动画只当"皮"。用**原版**动作的名义播，伤害自己算 | 手感和原版判定脱钩 | 处决、必杀、特殊演出 |
| **B2 险** | 把新动画绑到带分类属性的**新动作**上，让原版系统按它走 | 必须自己对齐判定帧，错位 = 打空/幽灵命中 | 想加进正常连招的招式 |

> 🔴 **2026-09-18 补充**：B2 的"对齐判定帧"现在**有确定的答案**——引擎不是"猜"判定帧，而是**按动画播放百分比开一个碰撞窗口**，窗口配在 `combat_parameters.xml`，由 clip 的 `combat_parameter_id` 指定。**你只要让武器真正打到人的那一刻落在窗口里就行**，不用逐帧调。完整机制见 **§11（判定链路）**，格挡见 **§12**。
>
> 🔴 **重要事实**：**三个参考 mod 全都走 B1（手工 `RegisterBlow`），一个走 B2 的都没有**——它们的 XML 里连一条带 `actt_*` 属性的动作都没注册。所以 B2 是**官方机制支持、社区无人实践**的路，要自己实机验证。

### 伤害怎么注入（B1 路线）

**用公开 API，别学 Stance 反射私有方法**：

```csharp
Blow blow = default;
blow.DamageType      = DamageTypes.Cut;
blow.BoneIndex       = target.Monster.HeadLookDirectionBoneIndex;
blow.GlobalPosition  = target.Position;
blow.BaseMagnitude   = 1f;
blow.InflictedDamage = 1;
blow.SwingDirection  = target.LookDirection;
blow.Direction       = blow.SwingDirection;
blow.BlowFlag        = BlowFlags.KnockBack;
blow.WeaponRecord.FillAsMeleeBlow(item, usage, -1, -1);

AttackCollisionData acd = AttackCollisionData.GetAttackCollisionDataForDebugPurpose(...);
target.RegisterBlow(blow, ref acd);
```

`AttackCollisionData.GetAttackCollisionDataForDebugPurpose(...)` 是**公开的静态工厂**，专门给这种手工命中用。

**护甲吸收公式**（参考 mod 的实现，可直接抄）：

```
absorbed = inflicted × armor / (armor + 100)
最终伤害 = Max(1, inflicted - absorbed)     // 保底 1 点
```

## 6. 架构建议

**优先用引擎扩展点，不要 Harmony。**

| 扩展点 | 用途 |
|---|---|
| `MissionLogic` | 任务级行为（tick + 命中/删除等事件） |
| `MissionView` | UI / 相机 |
| `AgentComponent` | 挂在单个 Agent 上的组件，`agent.GetComponent<T>()` 取 |

Artem 家族 250 个动作全靠这三个，**零 Harmony**。好处是抗版本漂移、不跟别的 mod 抢补丁目标。

**千人战性能三条**：

1. **时间分片**——不是每个 Agent 每帧都跑：
   ```csharp
   if ((agent.Index + (int)(Mission.Current.CurrentTime * 1000f)) % 4 != 0) return;
   ```
2. **`ActionIndexCache` 全部 `static readonly`**，类加载期解析一次，绝不每帧 `Create`
3. 用 `OnTickParallel` 而非 `OnTick`

**跨 mod 互斥**：动作名黑名单（如 `killmove` / `mercy` / `master` / `charge` / `dodge` 子串匹配），动手前先查对方是不是正被别的系统占用。避免两个 mod 同时抢同一个 Agent 的动作通道。

## 10. 战斗动画状态机

> 本节回答：**引擎凭什么决定"这个动作现在能不能播"？我怎么控制？**
> 全部结论来自 1.2.12 反编译（`TaleWorlds.MountAndBlade.dll`）+ 原版 XML 实测（2026-09-18）。

### 10.1 动作 = 一个名字 + 三个分类标签

| 标签 | XML（`action_types.xml`） | C# 枚举（`Agent` 的**内嵌**类型） | 取值 |
|---|---|---|---|
| 大类 | `type` | `Agent.ActionCodeType` | 49 个 `actt_*` |
| 方向 | `usage_direction` | `Agent.UsageDirection` | 9 个 `ud_*` |
| 阶段 | `action_stage` | `Agent.ActionStage` | 7 个 `as_*` |

**官方对这三个属性的全部解释只有一句**：
> These attributes are hardcoded so that the engine can understand certain properties of the action.

**运行时怎么读**（都在 `Agent` 上，参数 = 通道号）：
```csharp
agent.GetCurrentActionType(ch)       // → Agent.ActionCodeType
agent.GetCurrentActionDirection(ch)  // → Agent.UsageDirection
agent.GetCurrentActionStage(ch)      // → Agent.ActionStage
agent.GetCurrentActionPriority(ch)   // → int
agent.GetCurrentActionProgress(ch)   // → float 0~1（就是 §3 的打点时钟）
```

🔴 **`ActionCodeType` 的四个数字区间**（1.2.12 反编译实测，判断"对方在干嘛"全靠它）：
```
StrikeBegin  = 47 (StrikeLight)      StrikeEnd = 51 (MountStrike)
    → agent.IsInBeingStruckAction() 读这个区间 = "正在被打"
DefendAllBegin = 1   DefendAllEnd = 15      → 全部防御动作（fist/shield/2h/1h/staff）
AttackMeleeAllBegin = 19   AttackMeleeAllEnd = 23   → 近战攻防往返
JumpAllBegin = 24    JumpAllEnd = 28
```

> ⚠️ **勘误**：社区文档（`bannerlordmodding_lt/guides/custom_creature_reference.md`）的同名表整体偏移 +1（写 `Rear = 47` / `StrikeBegin = 48` / `MountStrike = 52`），与 1.2.12 反编译不符。**以反编译为准。**

### 10.2 优先级阶梯 —— 决定"能不能抢到通道"

🔴 **`AnimFlags` 是 64 位，低 8 位是"优先级整数"，不是位标志。** 高位才是行为开关。

```
amf_priority_mask = 0xFF      // 取优先级的掩码
```

| 动作 | 值 | | 动作 | 值 |
|---|---|---|---|---|
| idle / 移动（continue） | `0x01` | | equip（换武器） | `0x46` |
| jump / crouch / ride | `0x02` | | rear（马立起） | `0x4A` |
| attack（攻击） | `0x0A` | | upperbody_while_kick | `0x4B` |
| cancel（取消） | `0x0C` | | **striked（受击）** | `0x50` |
| defend（防御） | `0x0E` | | fall_from_horse | `0x51` |
| **defend_parry / throw / blocked / parried** | `0x0F` | | jump_end | `0x52` |
| kick / jump_end | `0x21` | | **die（死亡）** | `0x5F` |
| reload | `0x3C` | | | |
| mount | `0x40` | | | |

🔴 **规则：请求的优先级 ≥ 当前动作的优先级，才能抢到通道。**

**对招式的意义**：想让招式"打不断"，把 clip 的 `priority` 调到对应档位即可。**别随手设高**——设成 `die`（0x5F）等于动作期间免疫一切打断，包括死亡。

### 10.3 两条通道

| 通道 | 语义 | 用途 |
|---|---|---|
| `0` | **全身**（含移动） | 翻滚、处决、倒地、位移动作 |
| `1` | **上半身叠加**（腿仍由移动驱动） | 挥砍、格挡、嘲讽、喊话 |

- ✅ **官方原文**（`enforce_all` 的注释）：**"Valid for channel 0 only."** —— 这是官方对通道语义唯一的直接证据
- ⚠️ **实测坑**：在 channel 0 播一个**未注册**的动作 → index 解析成 `-1` → **腿冻住、人还在滑**（社区原话 "The creature slides with its legs frozen"）。所以 `SetActionChannel` 的返回值和 `GetCurrentAction` 必须查（见 §2 第 4 步）

### 10.4 同组随机、混合、自动接续

| 机制 | 在哪设 | 作用 |
|---|---|---|
| `alternative_group` | `action_sets.xml` 的 `<action>` 属性 | 同组动画随机挑一条播（原版 1330 条带此属性，如 `sit_idle_alt` 下挂 7 条 `act_sit_1..7`） |
| `randomization_weight` | clip flag | 组内被选中的权重，越大越常出 |
| `disable_alternative_randomization` | clip flag | 退出随机池 |
| `blends_with_action` | clip 属性 | 跟**另一条动作**做混合（官方强调：是动作不是动画）——盾牌上/下格挡、平衡/不平衡挥砍就靠它 |
| `continue_to_action` | clip 属性 | 播完自动接**另一条动作**（收招回待机） |
| `synch_with_movement` | clip flag | 不用自己的时长，跟移动进度同步（**防滑步主开关**） |

## 11. 判定链路：一次挥砍从碰撞到掉血

> 本节回答：**伤害是谁算的？判定帧在哪？我怎么让自定义招式打出伤害？**
> 全部来自 1.2.12 反编译 + 原版资产实测。

### 11.1 全链路

```
① Native 碰撞检测（连续扫掠武器胶囊）
     窗口 = 动画播放百分比区间 ← 来自 clip 的 combat_parameter_id 指向的条目
     ↓
② Mission.MeleeHitCallback(ref AttackCollisionData, attacker, victim, realHitEntity,
                            ref momentumRemaining, ref colReaction, crushThroughState,
                            blowDir, swingDir, ref hitParticleResultData, ...)   [C# 回调]
     ↓
③ MissionGameModels.Current.AgentApplyDamageModel.CalculateDamage(...)   ← 🔴 改伤害数值的官方口子
     ↓
④ Mission.RegisterBlow → victim.RegisterBlow(b, in acd) → Agent.HandleBlow
     ↓
⑤ Mission.OnAgentHit(...) → 每个 MissionBehavior.OnAgentHit / OnScoreHit
```

### 11.2 🔴 判定窗口 = "动画百分比"，配在 `combat_parameters.xml`

**这是全场最关键的一张表。** 文件头注释逐字：

```
float collision_check_starting_percent   = 1.0
float collision_damage_starting_percent  = collision_check_starting_percent
float collision_check_ending_percent     = 0.0
```

**语义**：引擎只在动画播到 `[starting, ending]` 这个百分比区间内检测武器碰撞。**不是找某个"判定帧"，是开一个窗口。**

一条完整条目（原版真值）：
```xml
<combat_parameter
    id="hand_shield_bash_params"
    collision_check_starting_percent="0.38"
    collision_check_ending_percent="0.48"
    collision_radius="kick_shieldbash_radius"
    alternative_attack_cooldown_period="hand_shield_bash_cooldown"
    hit_bone_index="19"
    shoulder_hit_bone_index="14"
    vertical_rot_limit_multiplier_up="0.4"
    vertical_rot_limit_multiplier_down="0.4" />
```

**全部字段**：

| 字段 | 含义 |
|---|---|
| `collision_check_starting_percent` / `_ending_percent` | **碰撞检测的动画进度窗口** |
| `collision_damage_starting_percent` | 开始计伤的进度；**必须 ≥ check_starting**，否则引擎报错（`... is smaller than ... for Combat Parameter: %s`） |
| `collision_radius` | 武器碰撞胶囊半径（可引用文件顶部 `<def>` 定义的值） |
| `hit_bone_index` / `shoulder_hit_bone_index` | 碰撞检测用的骨骼索引；**负值 = 引擎按动画自己挑**；肩部为负 = 不检测手臂碰撞 |
| `alternative_attack_cooldown_period` | 副手攻击（盾击/踢）冷却 |
| `weapon_offset` | 武器偏移（如 `guard_spear_offset` = `0,0,-0.7`） |
| `vertical_rot_limit_multiplier_up/down` | 动作仰角上限 |
| `left/right_rider_rot_limit`、`left/right_rider_min_rot_limit` | 骑乘转向限制（**单位是度，不是弧度**） |
| `left/right_ladder_rot_limit` | 爬梯转向限制 |
| `look_slope_blend_factor_up/down_limit`、`look_slope_blend_speed_factor` | 俯仰混合 |
| `<custom_collision_capsule p1 p2 r>` | **子节点**：自定义碰撞胶囊（三段 `weapon_bash_params_*` 各配一条自己的胶囊） |

**原版规模**：1.2.12 共 **155** 条；1.5.2 共 **165** 条，新增 10 条 =
`zero_collision`（**零碰撞——纯表演招式用它是正解**）、`onehanded_backstab`、`dagger_left_leftstance`、`dagger_right_leftstance`、`1h_up_flail`、`1h_left_flail_leftstance`、`1h_right_flail_leftstance`、`onehanded_left_flail`、`onehanded_right_flail`、`crossbow_reload`。

### 11.3 🔴 招式怎么"吃到"判定：clip 的 `combat_parameter_id`

**官方属性表原文**：
> `combat_parameter_id`: This gives an additional set of information to the engine (see combat_parameters.xml)

**实测验证（2026-09-18）**：原版 155 条参数里有 **127 条**在 `Modules/Native/AssetPackages/animation_clips.tpac` 里被逐字引用。clip 记录里这个字段是**按位置存的**（**没有属性名字符串**——所以 `combat_parameter_id` 这个词在 tpac 里 grep 0 命中，但参数值满地都是）：

```
act_defend_shield_left_spear_passive_up_left_stance | shield_defence | client_prediction | blends_accordin...
event:/mission/combat/swing/med | onehanded_right | release_slashright_1h | ...
```

**做法**：在 ModKit 的 Animation Clip 检视器里给自制 clip 指定一条 `combat_parameter_id`。
- **复用原版条目**（如 `onehanded_right`）→ 判定窗口、碰撞半径、骨骼直接照搬，最省事
- **新建条目** → 窗口自己定（合并方式见 §9 未决）

**这意味着**：自定义招式的判定**不需要**自己发明——给 clip 挂一条参数，引擎就会在你要的动画区间里做武器碰撞检测，命中就走完整伤害链，**格挡也白送**。

### 11.4 伤害随动画进度变化 —— `SpeedGraphFunction`

伤害不是恒定的：引擎用**三段折线**把"动画进度"映射成"伤害系数"。

```
进度 0  → zero_progress 值
       ↗ 爬到 FirstMaximumPoint 时 = 1.0（最疼）
       → 保持 1.0
       ↘ 从 SecondMaximumPoint 开始掉
进度 1  → one_progress 值
```

四个控制点来自 `ManagedParametersEnum`：`{Swing|Thrust|OverSwing}CombatSpeedGraph{ZeroProgressValue, FirstMaximumPoint, SecondMaximumPoint, OneProgressValue}`。

**调招式打击感就是调这条曲线**：想让招式在某段最疼、收招段已经卸力，改这四个数。

### 11.5 三条路线（选哪条）

| 路线 | 判定谁做 | 伤害谁算 | 格挡 | 代价 |
|---|---|---|---|---|
| **A 全手工**（三个参考 mod 走的就是这条） | 自己按动画进度打点 | 自己造 `Blow` + `RegisterBlow` | 自己做 | 判定与动画手工对齐；不吃护甲/技能/速度加成（除非自己复刻） |
| **B 引擎判定 + 原版伤害** | 引擎 | 引擎 | **native 白送** | 动画的"打中点"要落在窗口里；要挂 `combat_parameter_id` |
| **C 引擎判定 + 自定义数值** | 引擎 | 自己 | native 白送 | 要替换 `AgentApplyDamageModel`，**无人实践过** |

**建议 C 或 B。** 理由：判定和格挡是 native 最擅长的（连续扫掠 + 胶囊）；伤害数值是官方留了口子的。

### 11.6 C 路的官方口子：`AgentApplyDamageModel`

`TaleWorlds.MountAndBlade.ComponentInterfaces.AgentApplyDamageModel` —— 抽象类，**24 个抽象方法**，全套可重写：

```csharp
public abstract float CalculateDamage(in AttackInformation, in AttackCollisionData, in MissionWeapon, float baseDamage);
public abstract bool  DecideCrushedThrough(...);                  // 破防判定
public abstract void  CalculateDefendedBlowStunMultipliers(...);  // 格挡硬直倍率
public abstract float CalculateStaggerThresholdDamage(...);       // 被打晃动的阈值
public abstract float GetDamageMultiplierForBodyPart(...);        // 部位倍率
public abstract bool  DecideAgentKnockedDownByBlow(...);          // 击倒
public abstract bool  DecideAgentDismountedByBlow(...);           // 打下马
public abstract bool  DecideAgentKnockedBackByBlow(...);          // 击退
// ……共 24 个
```

⚠️ **三个参考 mod 一个都没用它**（全部手工 `RegisterBlow`）。所以这是"官方支持、社区无人实践"的路，**要自己实机验证**（见 §9）。

### 11.8 只读钩子（`MissionBehavior` 可重写）

```csharp
public virtual void OnMeleeHit(Agent attacker, Agent victim, bool isCanceled, AttackCollisionData collisionData);
public virtual void OnRegisterBlow(Agent attacker, Agent victim, GameEntity realHitEntity, Blow b,
                                   ref AttackCollisionData collisionData, in MissionWeapon attackerWeapon);
public virtual void OnAgentHit(Agent affectedAgent, Agent affectorAgent, in MissionWeapon affectorWeapon,
                               in Blow blow, in AttackCollisionData attackCollisionData);
public virtual void OnScoreHit(Agent affectedAgent, Agent affectorAgent, WeaponComponentData attackerWeapon,
                               bool isBlocked, bool isSiegeEngineHit, in Blow blow,
                               in AttackCollisionData collisionData, float damagedHp, float hitDistance, float shotDifficulty);
```

⚠️ **时序陷阱**：`OnRegisterBlow` 虽然是 `ref AttackCollisionData`，但它在 `victim.RegisterBlow(...)`（④）**之后**才触发 —— 在那里改数值**不会**改变这一刀的结果，只能当通知用。**要改数值必须走 ③ 的伤害模型。**

## 12. 格挡与招架

### 12.1 结论

**格挡/招架是 100% native 判的。C# 只能"读结果 + 改硬直/破防"，不能"造一个格挡判定"。**

### 12.2 判定结果

```csharp
public enum CombatCollisionResult { None, StrikeAgent, HitWorld, Blocked, Parried, ChamberBlocked }
//                                   0      1            2         3        4         5
```
（`Blocked` = 被格挡，`Parried` = 被招架，`ChamberBlocked` = 弹反）

### 12.3 回调链与签名

```
Native 判完 → Mission.GetDefendCollisionResults(...)          [MBCallback, internal]
            → MissionCombatMechanicsHelper.GetDefendCollisionResults(...)   ← 真正的算法
```

```csharp
internal static void GetDefendCollisionResults(
    Agent attackerAgent, Agent defenderAgent,
    CombatCollisionResult collisionResult, int attackerWeaponSlotIndex,
    bool isAlternativeAttack, StrikeType strikeType, Agent.UsageDirection attackDirection,
    float collisionDistanceOnWeapon, float attackProgress, bool attackIsParried,
    bool isPassiveUsageHit, bool isHeavyAttack,
    ref float defenderStunPeriod, ref float attackerStunPeriod,
    ref bool crushedThrough, ref bool chamber)
```

- **输入**里值得注意的是 **`attackProgress`**（攻击方动画进度）与 **`collisionDistanceOnWeapon`**（打在武器上的位置）——**两者都参与伤害与硬直计算**
- **输出**（`ref`）：双方硬直 `defenderStunPeriod` / `attackerStunPeriod`、**破防** `crushedThrough`、**弹反** `chamber`

### 12.4 硬直怎么算（可抄）

```
基础 = 10 + 动量（挥砍/刺击各按自己的公式算 base blow magnitude）
defenderStunPeriod = 基础 × StunMomentumTransferFactor
再按防御方武器重量做除数修正：
    盾牌：除数 = 1 + StunDefendWeaponWeightOffsetShield × 盾重
    武器：除数 = 0.9 + StunDefendWeaponWeightMultiplierWeaponWeight × 武器重
                 +（双手/长杆额外加成）
    招架（Parried）：       attackerStunPeriod += Min(0.15, 0.12 × 除数)
    弹反（ChamberBlocked）：attackerStunPeriod += Min(0.25, 0.25 × 除数)，chamber = true
    右手持（非左手）：      除数 += StunDefendWeaponWeightBonusRightStance
最后乘 AgentApplyDamageModel.CalculateDefendedBlowStunMultipliers(...) 的两个倍率，
夹到 StunPeriodMax 上限。
```

**破防**：`crushedThrough = !chamber && AgentApplyDamageModel.DecideCrushedThrough(...)`
→ **想让自定义招式"更容易破防"，重写 `DecideCrushedThrough` 即可，不用 Harmony。**

### 12.5 被格挡后走哪条路

```
Mission.OnAgentHitBlocked(affectedAgent, affectorAgent, ref acd, blowDirection, swingDirection, isMissile)
  → 造一个 cancelDamage: true 的 Blow
  → Mission.OnAgentHit(..., isBlocked: true, damagedHp: 0f)
  → MissionBehavior.OnAgentHit / OnScoreHit(isBlocked: true)
```

即：**被格挡 = 一条 `isBlocked: true` 的 `OnAgentHit`**。想统计"格挡了多少次"，监听 `OnScoreHit` 的 `isBlocked` 即可。

### 12.6 自定义招式怎么接格挡

| 需求 | 做法 |
|---|---|
| 招式能被原版格挡系统接住 | 给 clip 设 `combat_parameter_id`（§11.3），**白送** |
| 招式要"无视格挡"（处决类） | 手工 `RegisterBlow`（A 路），根本不进格挡判定 |
| 招式要"能弹开别人" | 先判对方在不在防御，见下 |

**判"对方正在防御"**（三个参考 mod 里唯一动过格挡的 SCO 就是这么做）：
```csharp
int t = (int)agent.GetCurrentActionType(1);
bool defending = t >= (int)Agent.ActionCodeType.DefendAllBegin    // 1
               && t <= (int)Agent.ActionCodeType.DefendAllEnd;    // 15
```

> **SCO 是三者中唯一碰格挡的**，且**只读不写**：Harmony postfix 挂在 `MissionCombatMechanicsHelper.GetDefendCollisionResults` 上，只把 `CombatCollisionResult == 3/4` 当格挡读出来扣"架势"（盾挡 ×0.5、招架 ×0.75），**不改判定结果**。ACC 与 ArtemCore **完全没有格挡处理**。

## 13. 根运动 vs 原地

### 13.1 结论：默认原地

| | 原地（in place） | 根运动（root motion） |
|---|---|---|
| 怎么开 | **默认**，什么都不用做 | clip 开 `displace_position` flag **+** 配 displacement 数据 |
| 谁负责位移 | 引擎移动系统 / 你的代码 | **动画自己** |
| 适用 | 循环动作（走/跑/待机）、原地挥砍、格挡 | 一次性位移（处决扑击、翻滚、冲锋、倒地） |
| 🔴 禁忌 | — | **循环动作绝对不能开** |

**为什么循环动作不能开**（社区原话）：
> The engine supplies the translation itself, from the movement system. If you bake root motion into a walk, the engine adds its translation to yours and the creature moves at double speed while its feet skate.

即：引擎自己也在推位移，两边相加 = **双倍速 + 滑步**。

### 13.2 三个 flag 别搞混

| flag | 位 | 方向 | 官方语义 |
|---|---|---|---|
| `anf_displace_position` | `0x400000000000` | 动画 → 角色 | "Updates world position of the agent during the animation using the displacement data." |
| `anf_affected_by_movement` | `0x40000000000` | 移动 → 动画 | "Allows movement adder animations to be added on top of this animation"（叠加抖动） |
| `anf_synch_with_movement` | `0x2000000` | 移动 → 动画 | 时长跟真实步速同步（**防滑步主开关**，走/跑/转身必开） |

配套的还有：

| flag | 位 | 作用 |
|---|---|---|
| `anf_enforce_root_rotation` | `0x8000000000` | 朝向跟动画烘的根旋转（转身动画用） |
| `anf_lock_movement` | `0x1000000` | 动画期间钉住角色（不让玩家移动） |
| `anf_lock_camera` | `0x800000` | 动画期间锁镜头 |
| `anf_ignore_scale_on_root_position` | `0x1000000000000` | 根位移不吃体型缩放（体型被放大的角色位移会过冲） |
| `anf_align_with_ground` | `0x100000000000` | 身体贴合地面法线 |

### 13.3 🔴 根位移的"数据"从哪来：`clip_usage_data → displacement_data`

**官方原文**：
> `clip_usage_data` is a common data pointer that may refer to `blend_data`, `displacement_data`, `bipedal_movement_and_ik_data`, and `quadrupedal_movement_data`.

**关键点：根位移不是 FBX 自动带进来的。** 开关在 clip 上（`displace_position`），**位移量在 `displacement_data` 里**，两者都要在 ModKit 的 clip 检视器里配。

**实测旁证**（解出来的二进制 clip 元数据）：
- ACC 的 `combat_360_killmove_death_custom`（处决受击方）：flag 里**有** `displace_position`，尾部**多一条 `displacement` 值记录**（24 字节负载）
- 同目录的 `combat_360_killmove_custom`（处决攻击方）：**没有** `displace_position`
- SCO 的 5 个翻滚 clip：**都没有**

### 13.4 实测：三个参考 mod 全都没用根运动

| mod | 位移怎么做的 |
|---|---|
| **SCO**（翻滚） | **代码逐帧推**：`position.x += dir.x * RollTravelPerSecond * dt` → `TeleportToPosition` → `Scene.GetGroundHeightAtPosition(pos, bodyFlags)` 贴地。默认速率 = `DodgeDistance / 0.5` = **6 米/秒** |
| **ACC**（处决） | `TeleportToPosition(受害者位置 + 受害者朝向 × teleportDistance)` —— 把攻击方**瞬移**到对位点（`teleportDistance` 写在成对字典里，如 `1.75`） |
| **ArtemCore** | 不管位移 |

**工程建议**：**先走"原地动画 + 代码推位移"**。三个实机 mod 都这么干、可控、不用烘数据、没有循环禁忌。根运动是"省代码但要在编辑器里烘数据 + 有循环禁忌 + 出问题难查"的路。

### 13.5 运行时附加 flag —— 与 clip 自带 flag 是**两套**

```csharp
agent.SetActionChannel(ch, ref action, ignorePriority, additionalFlags, ...);
```
`additionalFlags` 是**运行时叠加**的，和 clip 在编辑器里设的 flag **相加**。

**SCO 的实战用法**（这是它代码里唯一出现的非零字面量）：
```csharp
// 25165824 = 0x01800000 = anf_lock_camera(0x800000) | anf_lock_movement(0x1000000)
main.SetActionChannel(0, ref _activeRoll, true, RollAnimFlags(dir), ...);

private static AnimFlags RollAnimFlags(RollDir d)
{
    if (d != RollDir.Back) return (AnimFlags)25165824;  // 前进/左/右翻滚：锁移动 + 锁镜头
    return (AnimFlags)0;                                 // 后翻：不锁
}
```
**读法**：翻滚期间不让玩家自己动、不让转镜头。**这是"运行时按方向给不同 flag"的范式**——比给每条 clip 单独设 flag 灵活。

### 13.6 🔴 运行时读不到 clip 自带的 flag

社区实测（`bannerlordmodding_lt`）：
> You cannot toggle these from a Harmony patch — Only **two** flags are ever bit-tested in managed C#: `anf_synch_with_ladder_movement` and `anf_displace_position`. Every other flag is consumed entirely inside the native engine DLL.

**含义**：想在代码里问"这个 clip 有没有开根运动"——**只有 `displace_position` 和 `synch_with_ladder_movement` 能问**；其余 flag 只能在编辑器里设、在 native 里生效，**C# 看不见也改不了**。

C# 侧读根位移的 API：`Agent.ComputeAnimationDisplacement(float dt)`（native 绑定）。
⚠️ **原版 C# 一处都没调用**（全 DLL grep 只有声明 + 引擎绑定），是纯留给 mod 的口子；用法未验证（见 §9）。

### 15.1 结论速览

### 15.3 运行时代码接口（反编译实证）

```csharp
// ① 凭空发射一枚飞行物（不需要真拿弓、不需要弹药）
public Missile Mission.AddCustomMissile(Agent shooterAgent, MissionWeapon missileWeapon,
    Vec3 position, Vec3 direction, Mat3 orientation,
    float baseSpeed, float speed, bool addRigidBody,
    MissionObject missionObjectToIgnore, int forcedMissileIndex = -1);

// ② 拿到飞行物的实体和逐帧状态（Mission.Missile 是 Mission 的内嵌类）
public class Mission.Missile : MBMissile {
    public GameEntity Entity { get; }          // 🔴 运行时能挂光、挂粒子的实体
    public MissionWeapon Weapon { get; }
    public Agent ShooterAgent { get; }
    public Vec3 GetPosition();                 // 逐帧位置（同步视觉用）
    public Vec3 GetVelocity();                 // 逐帧速度（算朝向用）
}

// ③ 三个回调（MissionLogic 可重写，零 Harmony）
public virtual void OnAgentShootMissile(Agent shooterAgent, EquipmentIndex weaponIndex, Vec3 position,
                                        Vec3 velocity, Mat3 orientation, bool hasRigidBody, int forcedMissileIndex);
public virtual void OnMissileHit(Agent attacker, Agent victim, bool isCanceled, AttackCollisionData collisionData);
public virtual void OnMissileRemoved(int MissileIndex);

// ④ 动态点光（TaleWorlds.Engine.Light，是 GameEntityComponent）
Light light = Light.CreatePointLight(float radius);
light.LightColor = new Vec3(0.4f, 0.7f, 1f);   // 蓝色

light.Radius      = 3f;

light.SetVolumetricProperties(true, 1f);        // 体积光（雾里的光柱）

// ⑤ 自发光材质 / 运行时换材质

```

**引擎自带的材质 flag**（`Material.MBMaterialShaderFlags`，反编译实锤）：
`UseSpecular` / `UseSpecularMap` / `UseEnvironmentMap` / `UseDynamicLight` / `UseSunLight` / `UseSpecularAlpha` / `UseFresnel` / `SunShadowReceiver` / `DynamicShadowReceiver` / **`UseSelfIllumination`（自发光）**。

**自发光怎么配**（官方 Material Editor 文档）：编辑器里给材质打开 **`self_illumination`** flag，自发光纹理放 **Diffuse2** 槽，亮度用 **Vector Arguments** 调。配合矢量参数的运行时读写，就能做"刀身越蓄越亮"。

**发射音 / 命中音**：`SoundEvent.GetEventIdFromString(name)` + `SoundEvent.CreateEvent(id, scene)` + `SetPosition` + `Play()`（项目里 `Combat/FirearmFxLogic.cs` 已经在用这套范式，直接抄）。

**命中结算**：走 §11.7 的 `AttackCollisionData.GetAttackCollisionDataForDebugPurpose(...)` + `RegisterBlow`；或走 §11 的 B/C 路让引擎自己算。

### 15.4 四层做法（引擎给的和要自己造的）

| 层 | 谁做 | 内容 |
|---|---|---|
| **飞行物本体** | 原版引擎 | `AddCustomMissile` 发射；飞行、碰撞、命中、伤害、卡在地上全自动 |
| **视觉外观** | 原版引擎（数据） | 物品 XML 的 `flying_mesh` + `trail_particle_name` + `rotation_speed` —— **零代码** |
| **月牙网格 + 发光材质** | 自己做（一次） | Blender 建月牙薄片 → ModKit 导入 → 材质开 `self_illumination`。之后刀身与剑气**共用同一套材质** |
| **招式与逻辑** | 自己做 | 自定义挥砍 clip（§2 三件套，可选）+ 一个 `MissionLogic`（按键 → 取刀尖 → 发射 → 挂光 → 命中回调 → 清理） |

**建议的代码骨架**（约 150 行，零 Harmony）：

```
按键 / 招式收招
   → 取刀尖位置（武器骨骼）与准星方向
   → Mission.AddCustomMissile(月牙物品, 刀尖, 方向, ...)
   → missile.Entity.AddComponent(Light.CreatePointLight(...))
   → 记进字典：missileIndex → 光
OnMissionTick        → 从 Missile.GetPosition/GetVelocity 刷新光的位置与朝向
OnMissileHit         → 播命中音 + 爆散粒子（Scene.CreateBurstParticle）
OnMissileRemoved     → 从字典移除并销毁光（🔴 必做，否则漏光）
```

### 15.6 坑点（提前知道能省一天）

| # | 坑 | 症状 | 解法 |
|---|---|---|---|
| 1 | 月牙网格朝向没对齐 | 月牙横着飞 / 躺着飞 | 武器网格约定 = 原点握持点 · 长轴 +Z · 刃宽 X · 刃厚 Y；`rotation_speed` 是引擎按这个坐标系转的 |
| 2 | 命中即消失 vs 穿透 | 想"一剑扫一片"但撞第一个目标就停 | 原版导弹撞到即停。要穿透得自己按帧扫附近敌人（`GetNearbyAgents`），工作量翻倍，P5 再决定 |
| 3 | 漏光 | Mission 结束 / 飞行物消失后仍有一盏灯 | `OnMissileRemoved` 必须清（跟参考 mod 漏 `MortalityState` 同一类问题，见 §9） |
| 4 | 拿名字当标识 | 本地化/改名后失效 | 引用一律 StringId（铁律 20） |
| 5 | 无代价按键 | 破坏战斗平衡 | 铁律 12：每个选项必须有代价或检定（冷却/体力/弹药） |
| 6 | 粒子/音效名写错 | **静默不播**，不报错 | 名字先逐个 `ParticleSystemManager.GetRuntimeIdByName` / `SoundEvent.GetEventIdFromString` 验一遍；范本 `Combat/FirearmFxLogic.cs` |
