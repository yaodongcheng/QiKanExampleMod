# 资产中转沙箱模块工作流（把资产编译进内容包的唯一通路）

> 日期：2026-09-19（战国无双铁炮动画实操验证）· 适用：任何 ModKit **打不开**的内容包（Taikou，以及未来的三国包）
> 相关：[CLAUDE.md 铁律 31](../CLAUDE.md)（AssetSources 镜像布局）· [Knowledge/自定义世界内容包从零起步必备清单.md](自定义世界内容包从零起步必备清单.md)（雷 143~146）· [wheels.d/assets.md §十五](../plans/rules/wheels.d/assets.md)

---

## 〇、一句话结论

**ModKit 打不开内容包 ⇒ 用一个小模块当"编译沙箱"：在里面导入/编译/Publish，把产物改名拷进内容包的 `AssetPackages/`。**

**而"抽离资产"的做法是 —— 把编辑器工程里的 `Assets\`（已编译产物）和 `AssetSources\`（源）**两份整块拷过去**，保持 `<类>\<名>\` 层级。这样编辑器一打开，资产已经在工程里，你只需要 Publish。**

---

## 一、什么时候需要它

| 情况 | 走沙箱吗 |
|---|---|
| 资产要进 Taikou（或任何依赖一堆前置 mod 的内容包）| ✅ **必须** —— ModKit 打不开那些包，只能在别处编译再搬 |
| 资产要进一个 ModKit 能直接打开的普通 mod | ❌ 不用，直接在那个模块里做 |
| 想反复迭代某几件资产，不想每次重编一个几百 MB 的包 | ✅ 值得 —— 拆一个小沙箱，改一版只重编小包 |

**为什么不能直接开内容包**：Taikou 依赖 LWN / Shokuhou 等一串前置，编辑器加载不起来。这不是配置问题，是硬限制。

---

## 二、三个概念先分清（混了就白干）

| 概念 | 是什么 | 在哪 | 谁读它 |
|---|---|---|---|
| **沙箱模块** | 一个干净的纯资产模块，只为编译而存在 | `Modules\<沙箱名>\` | **只有编辑器**。运行时**不加载、不要勾选** |
| **编辑器工程** | `Assets\`（编译中间产物）+ `AssetSources\`（源文件）| 沙箱模块内 | **只有 ModKit**。跑游戏时 `Assets\` 必须改名 |
| **交付包** | Publish 产出的 `*.tpac` | 沙箱的 `AssetPackages\` → 改名拷进**内容包**的 `AssetPackages\` | **游戏**（内容包那一份）|

🔴 **关键区分**：`Assets\` 与 `AssetPackages\` 是**两回事** —— 前者是编辑器工程（半成品，游戏读它会崩），后者才是交付物。模块里同时存在两者时，引擎按 `Assets → AssetPackages → …` **取第一个存在的** ⇒ `Assets\` 在 = 整个 `AssetPackages\` 被绕过。**这就是那对 bat 存在的理由。**

## 三、从零建一个中转模块（四步）

### ① 模块目录 + `SubModule.xml`

最简形态（照抄 `TaikouAnim`，纯资产模块连 LWN 都不依赖）：

```xml
<?xml version="1.0" encoding="utf-8"?>
<Module>
	<Name value="TaikouAnim"/>
	<Id value="TaikouAnim"/>
	<Version value="e1.2.12"/>
	<DefaultModule value="false"/>
	<SinglePlayerModule value="true"/>
	<ModuleCategory value="Singleplayer"/>
	<Official value="false"/>
	<DependedModules>
		<DependedModule Id="Native"/>
	</DependedModules>
	<SubModules/>
	<Xmls>
	</Xmls>
</Module>
```

（`<Xmls>` 留空 —— 接线不写这里，见第六节。）

### ② 一对模式切换 bat：`to_editor_mode.bat` / `to_game_mode.bat`

照 `Taikou` 那对抄（管两件事：`Assets`↔`Assets_disabled`、`AssetSources`↔`AssetSources_disabled`）。
🔴 **两个必踩的坑**（写 bat 时）：
- `set "MOD=%~dp0"` —— **引号不能省**。路径含 `&`（Mount **&** Blade）会把整行截断，后续路径全错。
- `echo` 行里的 `>` **必须转义成 `^>`** —— 否则那行字被吞，还在当前目录生成一个以重定向目标命名的垃圾文件。

### ③ junction 进另一个客户端（双端同源）

物理目录放**主目录**，另一个客户端（编辑器跑的那个）建 junction：

```powershell
New-Item -ItemType Junction -Path "<另一客户端>\Modules\<沙箱名>" -Target "<主目录>\Modules\<沙箱名>"
```

与 Taikou / LWN 的做法一致 —— 数据/代码落一处 = 两个客户端同时生效。

### ④ 沙箱**不要**注册任何东西

`soln_*` 行、`<XmlName>` 段都写进**内容包**（见第六节）。沙箱万一被勾选，也不会把接线声明两遍。

## 四、🔴 核心手法：把一个资产从旧模块抽到新模块

**这是本文最重要的一节。** 当时从 `TifaHead2` 把铁炮动画抽进 `TaikouAnim`，做法不是"重新导入一遍"，而是：

### 两条路，选一条

| 路 | 做法 | 什么时候用 |
|---|---|---|
| **A. 整块搬（推荐）** | 把旧模块的 `Assets\<类>\<名>\` + `AssetSources\<类>\<名>\` **两份都拷**到新模块同名位置 | 旧模块里**已经编译好、已实机验证**的资产 |
| **B. 只搬源 + 重新导入** | 只把源文件放进 `AssetSources\`，在编辑器里重新 Import / Compile | 新做的资产；或想借沙箱重新导一遍 |

### 路 A 的精确命令（保持镜像布局）

```powershell
# 源 = 编辑器所在那个客户端的旧模块；目标 = 新沙箱模块
# 🔴 目标路径要写全（含 <类> 这一层），别用「拷到某个父目录」的写法
Copy-Item "<旧模块>\Assets\<类>"        "<新模块>\Assets\<类>"        -Recurse -Force
Copy-Item "<旧模块>\AssetSources\<类>"  "<新模块>\AssetSources\<类>"  -Recurse -Force
# 拷完核对：<新模块>\Assets\<类>\<名>\ 存在，且里面的文件数与源一致
```

🔴 **`Copy-Item` 的两种写法结果完全不同**（当时就是在这里栽的）：
- `Copy-Item <源目录> <目标父目录>\` —— 若**目标父目录不存在**，PowerShell 会把它**当成被拷目录的新名字** ⇒ `Assets\animations` 拷进去变成 `Assets\`，**`animations` 这层没了**，编辑器认不出。
- ✅ `Copy-Item <源目录> <目标路径>`（目标路径 = 含 `<类>` 的完整路径）—— 目标不存在时**按源目录完整复制一份**，层级正确。

🔴 **一个资产往往由多个文件组成**，只拷一半 = 半截：
- 网格类：`.fbx` + `_d` / `_n` / `_s` 三张贴图
- 动画类：`.trf`（源）+ `_geo.tpac`（骨架+网格编译产物）+ `_anm.tpac`（clip 编译产物）

## 五、为什么"编辑器打开就全好了，只需要 Publish"

| 原因 | 说明 |
|---|---|
| **拷的是编辑器工程本身**（`Assets\`），不只是源 | ModKit 打开工程时，资产**已经在工程里注册好了** ⇒ 不需要 `Import new asset`、不需要重编 |
| **镜像布局对齐** | `Assets\<类>\<名>\` 与 `AssetSources\<类>\<名>\` 同目录同名 —— 这是编辑器自动同步的**唯一入口**（铁律 31）|
| **junction 同源** | 编辑器所在客户端能看到这个模块，才有得打开 |

🔴 **为什么不只拷 `AssetSources`**：编辑器是**文件监视**，**只对「ModKit 开着期间」发生的改动生效** —— 开编辑器之前的改动**不会被补拉**。所以只放源文件、再开编辑器 = 很可能什么都不出现。**连 `Assets\` 一起拷，就绕过了这个限制。**

---

## 六、交付：Publish → 改名 → 拷进内容包

```
沙箱模块里 Publish  →  <沙箱>\AssetPackages\pack0.tpac
                    →  改名拷进  <内容包>\AssetPackages\<有意义的名字>.tpac
```

🔴 **三条硬规矩**：

1. **必须改名**：内容包的 `AssetPackages\` 里通常已经有一个 `pack0.tpac`（Taikou 那个 = **299 MB 自有内容**）。同名放进去会把**它**覆盖掉。命名跟既有体例走（`lwnprof_*.tpac` / `taikou_banners.tpac` / 动画 = `lwn_taikou_anim.tpac`）。
2. **接线写在内容包侧，不在沙箱**：`action_types.xml` / `action_sets.xml` / `item_usage_sets.xml` + `project.mbproj` 的 `soln_*` 行 —— 全写 `Taikou\ModuleData\`。沙箱**故意一行都不挂**。
3. **Publish 会清空目标目录** —— 别把备份放在 `AssetPackages\` 里。Taikou 的 `AssetPackages` 还躺着几个 `lwnprof_*.tpac`（立绘包），**直接把 Publish 目标指到它 = 全清**。做法是指到模块外（如 `Modules\Publish\<沙箱名>`），再手工把产物拷回来。

## 七、坑点速查（症状 → 根因 → 解法）

| 症状 | 根因 | 解法 |
|---|---|---|
| 拷完开编辑器，**资产一个都没有** | 只拷了 `AssetSources\`（或拷完才开编辑器）| 连 `Assets\` 一起拷（第五节）|
| 编辑器里**搜不到**某件资产 | 层级少了 `<类>` 那层（`Assets\<名>\`）| 核对目标路径必须是 `Assets\<类>\<名>\` |
| 拷去新模块后**材质白板 / 缩略图打 ⚠** | 材质资源没跟着走（`*_mtl.tpac` 没拷）| 整块拷 `<类>\<名>\` 目录，别只挑网格文件 |
| 跑游戏**崩**或资产不生效 | 模块里 `Assets\` 还在（引擎按 `Assets → AssetPackages` 取第一个存在的，读到半成品）| 跑游戏前执行 `to_game_mode.bat` |
| 内容包那个 299 MB 的 `pack0.tpac` **被覆盖** | 产物同名直接拷进去了 | 必须改名（第六节）|
| 接线被**声明两遍** / 启动报 `KeyNotFoundException` | 沙箱也挂了 `soln_*` 行，且被勾选 | 沙箱不挂任何 soln 行；运行时也不勾选沙箱 |
| bat 报 `'Blade' is not recognized...`，或目录里冒出奇怪文件 | 路径含 `&` 把 `set` 行截断；`echo` 里的 `>` 没转义 | `set "MOD=%~dp0"` 引号不能省；`>` 写 `^>` |

## 八、判据与验收

| 环节 | 判据 |
|---|---|
| 编辑器里资产到位 | 资源浏览器按名字搜得到；编辑器的 `Assets\…\*_geo.tpac` **时间戳刷新** |
| Publish 成功 | `tpaccli list --packdir <模块>\AssetPackages` 里资源数对得上、名字对 |
| **交付完成** | 🔴 **判据是装机包量出来的数字**（`tpaccli dump --packdir <内容包>\AssetPackages …` 量顶点数/包围盒/资源清单）—— **不是"文件已归拢到 AssetSources"**（铁律 31）|
| 两份不打架 | 旧模块里那份**已经删掉**（抽离彻底），否则同名资源两处并存 |
