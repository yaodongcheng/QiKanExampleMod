## §1 实体的"身份证"：GUID 基本没用，用 Pointer + Name

| 手段 | 事实 | 用途 |
|---|---|---|
| `GameEntity.GetGuid()` / `IsGuidValid()` · `Scene.GetEntityWithGuid(guid)` | API 齐全，**但 GUID 只对编辑器/资产实体有效** —— 运行时 `CreateEmpty` 出来的实体多半 `IsGuidValid()==false` ✗ | 编辑器资产反查可用；运行时实体别指望 |
| `GameEntity.Pointer`（`UIntPtr`） | 本会话内唯一，**但会被回收复用**（销毁后再建可能拿到同一地址） | 日志身份（`0x7F…`）：能对上"是不是同一枚"，也能一眼看出**地址被复用**（悬空/双重销毁的 signature） |
| `GameEntity.Name` | 🔴 **可读可写**（`get`/`set` 都有）· `Scene.FindEntityWithName(name)` 可反查存活 | 给运行时实体**自己发编号**（如 `lwn_B_link003`）：一条绳几十上百件时，只有靠它才分得清是哪个 |

**落地范本**：`Combat/GrappleRig.cs` 的 `Ptr()` / `Name()` / `Describe()`（日志一律打 `名字@指针`）。

## §2 帧空间：`SetFrame`=局部 / `SetGlobalFrame`=世界 —— **混用必漂**

```csharp
e.SetFrame(ref f);       // 局部帧（相对父实体）
e.GetFrame();            // 局部帧
e.SetGlobalFrame(in f);  // 世界帧
e.GetGlobalFrame();      // 世界帧 · e.GlobalPosition
```

🔴 **父实体一旦会动，两种口径就不能混**：子件写世界帧后，引擎会在某些时机用「父 × 子局部」重算它的世界位 ⇒ 我们每帧写的世界坐标被顶掉 ⇒ **漂移/跳变**。

**唯一正确姿势（本次采用，风险最小）**：
> **数学照旧全部在世界空间算**，只在**最后写帧那一步**换算成局部 —— 并且**只留一个入口**。

```csharp
// GrappleRig.Place(实体, 世界帧)：
MatrixFrame local = root.GetGlobalFrame().TransformToLocal(world);
e.SetFrame(ref local);
```
配套两条纪律：
1. **每帧先摆 root、再摆子件**（子件换算用到的 root 帧必须是本帧的，否则差一帧 ⇒ 抖）
2. **子件的每一次写帧都必须走这个入口**（本次共 5 处：钩 2 · 环 1 · 绳 2）—— 漏一处就埋一个漂移

## §3 父子结构（`AddChild` / `RemoveChild`）

- `GameEntity.AddChild(child, autoLocalizeFrame)` ✓ 可用；`autoLocalizeFrame: true` = 保持子件当前世界位置不变
- `ChildCount` / `GetChild(i)` / `Parent` ✓ 可读
- 🔴 **`RemoveChild` 全游戏 DLL 里只有定义、零调用**（5 个参数无先例可抄）⇒ **本次决定不用**：
  它的 `keepPhysics` / `keepScenePointer` 参数说明用途是"**把一个还活着的子件摘下来**"，不是"销毁子件"（销毁由引擎自己解链）。
  ⇒ 子件由各自所有者照旧 `Remove(0)`。**故障表征 = 下一次 `AddChild` 崩**（真出现再加显式摘链）。
- 🔴 **别把子件挂到"引擎按骨绑的物品实体"上**（`Agent.GetWeaponEntityFromEquipmentSlot`）：它的寿命由引擎管，换武器/收武器时会被替换或销毁 ⇒ 子件被孤儿化。要"跟着手"就**自己每帧算世界位置**（见 §4）。

## §4 🔴🔴 骨骼挂点：`GetBoneEntitialFrame` 返回的是**角色局部坐标**

**症状**：钩/球一直挂在**盆骨**上、或"看不见"；日志显示我们算的坐标"完全正确"，实体却不在那儿。

**根因（实机取证）**：

```csharp
Vec3 raw = agent.AgentVisuals.GetBoneEntitialFrame(bone, useBoneMapping: false).origin;
// 手垂着时 raw = (0.28, -0.16, 0.85)  ← 这是"右手在角色坐标系里的位置"，不是世界坐标
// 当世界坐标用 ⇒ 离身体 575 米；用 Agent.Frame 转一次世界 ⇒ 离身体 1.4 米 ✓
```

⇒ **双解释判据**（唯一实现 `SpellCastInput.TryReadBoneWorld`）：原始值既按"世界"量一次离身体的距离，也按
`agent.Frame.TransformToParent(raw)` 转世界再量一次，**谁落进合理距离（手 1.5 m / 肩 2 m）就采信谁**。
两种空间自动识别，不要赌原生返回哪一种。

### §4.1 骨索引别按名字找 —— 用 `HumanBone` 语义枚举

```csharp
sbyte bone = agent.AgentVisuals.GetRealBoneIndex(HumanBone.ForearmR);   // 肘
sbyte hand = agent.AgentVisuals.GetRealBoneIndex(HumanBone.HandR);      // 手
```
`HumanBone`（`TaleWorlds.Core`）枚举齐全：`ShoulderR` / `UpperarmR` / `UpperarmTwist1R` / `ForearmR` /
`Forearm1R` / `HandR` / `ItemR` / `Pelvis` / `Spine1/2` / `Thorax` / `Neck` / `Head` / `ThighL` / `CalfL` / `FootL` / `ToeL` 等。

⚠️ **骑砍真实骨名是 `r_foretwist` / `r_upperarm_twist`**（twist 骨当主干用）—— **直觉名 `forearm`/`upperarm` 不存在**，
按名字找必踩空。`Skeleton.GetBoneName(idx)` 可以把索引读回名字**自证**（本次日志：`臂骨=[r_foretwist/r_hand …]`）。

### §4.2 骨骼原点是"起点关节"，不是你以为的那个点

- `HumanBone.HandR` 的原点 = **腕关节**，不是掌心 ⇒ 要"挂手心"，得自己沿**小臂方向**（`ForearmR → HandR` 的连线）外移
- 同一套读法也能做"绕某骨骼轴转"：轴 = 两骨点相减（本次：圆 ⊥ 小臂）
- 🔴 **转向/朝向类需求，先把"以谁为轴、往哪偏"做成运行期旋钮**，别写死 —— 空间判断交给眼睛，符号推理交给代码

### §4.3 🔴🔴 两个"读数可信度闸门"的坑（2026-10-08 日志实锤，症状都是"东西甩到脚底 / 偶尔消失"）

**坑 A —— 距离闸门是从【脚底】量的，不是身体中心。** `Agent.Position` 在**脚底**；人**抬手（瞄准 / 走动摆臂）**时
手骨离脚底**本来就有 1.4~1.5 m**。闸门卡 1.5 ⇒ 每 1.1 秒（= idle 呼吸一个周期）翻过闸门一次 ⇒ 读数被拒 ⇒ 掉兜底。
实测（钩索）：`手源=[bone/local d=1.47]` 与 `[item-entity … d=0.00]` **交替出现，周期 1.83 s**，正是 idle 一个循环。
⇒ **闸门的值要按"脚底到最远关节"量**（抬手 ≈1.5、举过头 ≈2.0）；它真正要挡的是"**坐标空间搞错**"（错空间 = 几百米），
所以放宽到 2.5 完全安全。另一条：**两条解释都能用时取"离身体更近"的那条**（别写"世界优先"—— 角色恰好站在世界原点附近时会收错）。

**坑 B —— `Agent.GetWeaponEntityFromEquipmentSlot(slot)` 对"没绑到骨上"的槽，返回的实体帧在【agent 原点】。**
实测 `d = Distance(实体帧, agent.Position) = 0.00`（刀架在那条兜底上 ⇒ "手"变成**脚底**，钩与绳一起甩到脚踝）。
⇒ 兜底守卫**两头都要卡**：太远（> 闸门）不要，**贴在原点（< 0.35 m）也不要**（那 = 没绑上骨）。
配套纪律：拒掉时要**把原因写进诊断串**（`item Weapon2 d=0.00 not-attached`），否则下次只看到"兜底了"、看不出为什么。

**坑 C（顺带）—— 兜底位本身也会骗人**：读失败就退 `player.Position + 1.25 m`（盆骨）等于"把钩藏进身体"，
而 `pos`/`actual`/`shown` 三个自证**全部正常**。⇒ 读失败应先**顶住"上一次的好手点"**（短窗口 + 按 agent 位移平移），
超时再认输 —— 这才叫"降级"，直接跳盆骨叫"换个地方消失"。

**✅ 三处修法已实机验证通过（2026-10-08 晚）**：闸门 1.5→2.5 · 兜底补下限 0.35（拒"没绑骨"的实体）· 读失败先顶好手点。
实现 = `Combat/SpellCastInput.cs`（`MaxHandDistance` / `MinHandItemDistance` / 优先取更近那条）+ `Combat/GrappleLogic.cs`（`GetHand` 的顶住逻辑）。
查同类问题的命令 = `custom.grapple spinlog 1 5`（边玩边录）+ 「手源换路」自动日志。

## §5 自管绳/链的显示语义（`GrappleRope`）

| 事实 | 后果 |
|---|---|
| **`Show(from,to)` 会把点链重排成一条直线** | 开火瞬间调它 ⇒ 手里甩着的绳"啪"地变直线 ✗（本次实机症状："看不到从右侧飞到目标的曲线"）⇒ 两端已经在那儿时**不要 Show**，接着 `Tick` 才连续 |
| `Tick` 第一行 `if (!_visible) return;` | **调用方判"绳显示着吗"要问绳自己**（`IsVisible`），别只信自己记的"我 Show 过了"标志 —— `Release()`/`Anchor()` 等路径会绕过标志直接 `Hide()` ⇒ 标志卡 true ⇒ **绳永久不出现**（实机踩过） |
| 绳长 = `clamp(跨度 × SlackRatio, MinLength, MaxLength)`，按 `LengthFollowSpeed` 逼近 | **绷直 vs 带弧由这两个数决定**：`SlackRatio=1.0` + `MinLength` 小于跨度 ⇒ 走绷紧解析解 = 直线；`1.05~1.3` ⇒ 带弧 |
| 🔴 **跟随速度追不上目标速度时，绳永远绷直** | 飞行 42 m/s、`LengthFollowSpeed` 只有 8 ⇒ 绳长永远小于跨度 ⇒ **一条直线**（这正是"飞行看着很硬"的原因）；飞行期临时把它拉到 60 才有弧 |
| 每个实体都是独立 `GameEntity` | 建/拆/显隐**要留事件日志**（`[Rope] <标签> 重建/销毁/Show/Hide` + 根子树前后计数）—— 查崩溃时"崩在哪个事件之后"是唯一线索 |

## §6 本次结论一句话

**"跟着骨骼/跟着手"这类需求，正确结构是**：
自建一个**根实体当"这件东西本身"** → 每帧把它摆到挂点（手/载体）→ 所有子件**世界空间算、局部帧写**（唯一入口换算）→
骨点用 `HumanBone` 语义索引 + **双解释**读世界坐标 → 绳/链等自管件的**显隐/长度语义**按 §5 逐条对齐。
