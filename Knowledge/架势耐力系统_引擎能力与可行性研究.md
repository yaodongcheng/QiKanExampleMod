# 架势/耐力系统 — 引擎能力与可行性研究

> 日期: 2026-06-22
> 结论: 可行。骑砍2引擎原生支持破格挡（crushedThrough）+ 防御硬直（defenderStunPeriod），架势系统本质是在这套骨架上加一层资源管理层，触发条件从"武器自带的破格挡概率"变为"架势值归零"。

---

## 一、原始问题

骑砍2原版战斗中，AI 敌人的格挡是**无成本、无上限**的——只要 AIBlockOnDecideAbility 够高，可以无限格挡直到被围殴或体力不支（但原版没有体力概念）。玩家面对高格挡 AI（精英兵/领主）时，单挑变得枯燥：砍→被挡→砍→被挡→循环。需要一套机制确保"格挡一定有尽头"。

## 二、引擎已有什么（不需要从零造）

### 2.1 三个关键原生机制

| 机制 | 接口 | 说明 |
|------|------|------|
| **破格挡** | `GetDefendCollisionResults` → `ref crushedThrough` | 引擎原生！`combat_parameters.xml` 可配武器破格挡概率。C# 层可读写此标志 |
| **防御硬直** | `ref defenderStunPeriod` | 格挡方被破防后的硬直时长（秒），驱动硬直动画 |
| **攻击硬直** | `ref attackerStunPeriod` | 攻击方弹刀后的硬直时长 |

这三个在 `[MBCallback] internal void GetDefendCollisionResults()` 中暴露，是 C++ native 层的攻防结算回调。

### 2.2 AI 格挡相关 DrivenProperties

```csharp
public enum DrivenProperty {
    AIBlockOnDecideAbility,           // AI 每帧决定格挡的概率 (0~1)
    AIParryOnDecideAbility,           // AI 弹反（招架）概率
    AIUseShieldAgainstEnemyMissileProbability,
    AIAttackOnDecideChance,           // AI 攻击意愿
    AiAttackOnParryChance,            // AI 招架后反击概率
    AiAttackOnParryTiming,            // AI 招架后反击时机
    // ... 共 84 个
}
```

通过 `agent.UpdateDrivenProperties(float[84])` 一次性写入 native 层。**这是影响 AI 格挡行为的唯一 C# 入口。**

### 2.3 伤害检测回调

| 回调 | 触发条件 | 用途 |
|------|----------|------|
| `MissionLogic.OnRegisterBlow` | 攻击判定注册（伤害=0 也触发） | **检测格挡**（damage==0 → 被挡了） |
| `MissionLogic.OnAgentHit` | 实际造成伤害（damage>0） | 检测命中 |

已有项目落地案例：[AttackTriggerMissionLogic.cs](../ExampleModVS/ExampleMod/ExampleMod/Combat/AttackTriggerMissionLogic.cs) —— 在 `OnRegisterBlow` 中做攻击意图检测，在 `OnAgentHit` 中做切磋虚拟血量处理。

### 2.4 动画资源

| 动画类型 | 是否存在 | 说明 |
|----------|----------|------|
| 短硬直/踉跄（stun） | ✅ 有 | `defenderStunPeriod` 驱动，几百毫秒到 1.5 秒级别 |
| 持续力竭状态（呼吸急促/武器下垂/弯腰） | ❌ 没有 | 原版无战斗耐力系统，`action_types.xml` 中不存在对应 ActionType |
| 受伤移动 | ✅ 有 | 低血量时移动动画有变化，但这是血量驱动不是耐力驱动 |

**结论**：动画层面只支持"短踉跄"作为表现手段。不要设计"持续疲惫 debuff"——做出来也没有动画支撑。

## 三、方案设计（简化版，核心产出 = 踉跄窗口）

### 3.1 核心数值模型

```
架势值 (0~100)
├── 格挡轻攻击：-8~12 架势（取决于武器重量差）
├── 格挡重攻击：-20~30 架势
├── 格挡踢腿：  -35 架势（踢腿 = 专门破防技）
├── 被破格挡（crushedThrough）：架势直接归零
│
├── 架势恢复速度：每秒 +15~25（取决于 Athletics 技能）
├── 架势恢复延迟：最后一次格挡后 0.8s 才开始恢复
│
├── 架势归零 → 1.2s 踉跄（defenderStunPeriod），期间无法格挡
└── 踉跄结束后架势恢复到 30（不是满的 → 连续施压更快再崩）
```

### 3.2 玩家破防的三条路径

| 路径 | 操作 | 机制 | 适用武器 |
|------|------|------|----------|
| **架势压制** | 连续重击 | 每刀削 20-30 架势，3-5 刀崩防 | 斧、锤、双手剑 |
| **踢腿破防** | 踢腿（E 键） | -35 架势，专门破防 | 任何武器（距离最短，高风险） |
| **绕侧攻击** | 走位打侧面/背面 | 绕开格挡方向，直接命中 | 快武器（匕首、单手剑） |

三条路径各有适用场景——不是只有一种最优解。重武器压制最稳但慢，踢腿最快但距离短，绕侧需要走位技巧。

### 3.3 不对称性（玩家 vs AI）

| 属性 | 玩家 | 精英 AI | 杂兵 AI |
|------|------|---------|---------|
| 架势上限 | 130 | 100 | 50-60 |
| 恢复速度 | 1.5x | 1.0x | 0.8x |
| 恢复延迟 | 0.6s | 0.8s | 1.0s |

玩家有优势但并非无敌——被三个杂兵围攻时还是要走位，不能站桩格挡。

### 3.4 盾牌特殊处理

盾牌已有独立的 HP 系统（原版），盾牌格挡时：
- **不消耗架势**（盾有自己血量）
- 盾烂了才进入架势系统
- 双手武器对盾有额外伤害

## 四、技术实现路径

### 4.1 架构

新增 `PostureCombatMissionLogic : MissionLogic`，与已有的 `AttackTriggerMissionLogic` 平行运行，各自处理不同关注点：

```
PostureCombatMissionLogic
├── Dictionary<int, float> _postureValues        // Agent.Index → 当前架势
├── Dictionary<int, float> _lastBlockTime        // 恢复延迟用
├── Dictionary<int, float> _brokenUntil          // 踉跄硬直结束时间
│
├── OnRegisterBlow()     ← 核心入口
│   ├── damage==0 → 格挡发生 → 扣除架势
│   ├── damage>0  → 命中   → 攻击方架势微耗
│   ├── 架势≤0   → 触发踉跄（crushedThrough + defenderStunPeriod）
│   └── 踢腿检测 → 额外削架势
│
├── OnMissionTick()      ← 恢复 + AI 参数更新
│   ├── 遍历战斗中 Agent
│   ├── 架势恢复（受延迟约束）
│   └── 架势低时更新 DrivenProperties（后半段才降格挡能力）
│
└── OnAgentRemoved()     ← 清理字典
```

### 4.2 架势消耗计算公式

```csharp
float CalculatePostureCost(MissionWeapon atkWpn, MissionWeapon defWpn, Blow blow)
{
    float base = atkWpn.GetWeight() * 10f;          // 攻击方武器重量
    float defense = defWpn.GetWeight() * 3f;         // 防御方武器重量抵消
    float multiplier = blow.IsHeavyBlow ? 1.8f : 1.0f;
    float kickBonus = isKick ? 35f : 0f;             // 踢腿固定削架势

    if (defWpn.IsShield()) return 0;                 // 盾牌不耗架势
    return Math.Max(5f, base - defense) * multiplier + kickBonus;
}
```

### 4.3 关键实现细节

**踉跄触发**（利用引擎原生机制）：
```csharp
void ApplyPostureBreak(Agent defender)
{
    _brokenUntil[defender.Index] = Mission.Current.CurrentTime + 1.2f;
    _postureValues[defender.Index] = 30f; // 恢复不是满的
}
```

**DrivenProperties 更新**：架势低时降 AI 格挡，但只在后半段（<50%）才开始生效——前半段 AI 全力格挡，给玩家"我在真正压制他"的感觉。**注意** `UpdateDrivenProperties` 是只写 API，需要先缓存每个 Agent 的基础值再修改。

## 五、引擎限制与应对

| 限制 | 影响 | 应对 |
|------|------|------|
| 没有持续力竭动画 | 不能做"疲惫 debuff 持续 10 秒" | 只做短踉跄（1.2s），合法且引擎原生支持 |
| `UpdateDrivenProperties` 是只写 API | 不能增量修改，必须传完整 84 个 float | 需要反射读 `HumanAIComponent` 当前值做基线 |
| `OnRegisterBlow` 中 damage==0 不一定是格挡 | 也可能是挥空/打中环境物体 | 需要结合 `AttackCollisionData.CollisionResult` 判断 |
| 盾牌格挡 | 盾有独立 HP，不能双层消耗 | 盾牌格挡不进架势系统 |
| 多版本 DrivenProperty 枚举可能不同 | v1.2.12 vs v1.4.6 枚举值偏移 | 需要在 VersionCompat 中验证和适配 |

## 六、为什么不做成"降低 AI 格挡概率"

一种常见直觉是：架势低了 → 把 `AIBlockOnDecideAbility` 从 0.95 降到 0.3 → AI 开始概率性"放水"。**这是坏设计，不满足铁律 6（KCD2 水准）**：

- 玩家感受不到因果关系——AI 不是"被打崩了所以挡不住"，而是"突然就不挡了"
- 概率性放水让战斗结果变得随机——同一刀有时被挡有时不挡，没有规律
- 沉浸感破坏——玩家会意识到"AI 在让我"，而不是"我技术好"

正确的做法是：AI **始终全力格挡**（AIBlockOnDecideAbility 保持高水平），直到架势归零 → 100% 确定性的踉跄窗口。这样玩家每一刀都在积累可预期的压力，崩防是确定性的回报。

## 九、竞品分析（2026-06-22 调研）

### 9.1 RBM（Realistic Battle Mod）— 最完整的架势系统

目前最接近我们方案的 MOD，已非常成熟。

**架势机制**：
- 攻击**和**格挡都消耗架势（比我们的方案更激进——攻击也耗）
- 架势条 UI 在血条下方，敌方架势显示在屏幕顶部中央
- 完美格挡 → 自己消耗极少架势，**对方掉大量架势**（高风险高回报的反击机制）
- 架势归零 → 踉跄/击退/击倒 + **crush-through 破防真伤**
- 崩防后瞬间恢复 **50%** 架势（不是 30%）

**武器差异化**：

| 武器类型 | 造成的架势伤害 | 格挡时承受的架势消耗 |
|----------|--------------|-------------------|
| 重武器（锤/双手锤） | 高 | 高 |
| 轻武器（剑） | 低 | 低 |
| 双手剑 | — | 🏆 格挡消耗最低，最佳决斗武器 |
| 斧（单手/双手） | 特殊 | **即使对方满架势也能触发踉跄**（不造成伤害但打断动作） |

**盾牌处理**：盾牌格挡参与架势系统，但有格挡角度惩罚（不正确角度格挡 → 额外架势消耗）。

**斧头特殊机制**：RBM 给斧类武器加了一个独特属性——格挡斧头攻击时，即使防御方架势是满的，也会触发短踉跄。不做伤害，但打断动作、露出破绽。这是我们方案没考虑到的设计维度：**武器类型本身可以携带"破防属性"**。

**已知问题**：
- 与 Stamina System（Nexus #7933）同时开启时，AI 获得无限耐力，疲劳后撤永不触发
- 部分玩家反馈强盗头目拿单手斧能无限踉跄玩家，体验不佳（斧头机制可能过强）

**来源**：
- Steam 创意工坊讨论：[RBM 架势系统开发者说明](https://steamcommunity.com/workshop/filedetails/discussion/2859251492/3596716230227652041/)
- 骑砍中文站汉化：[RBM 下载](https://bbs.mountblade.com.cn/plugin.php?id=xlwsq_down&biaoqian=+RBM)
- 国内修改版：[完美格挡使敌人倒地](https://bbs.mountblade.com.cn/download_1796.html)、[架势系统修改探讨](https://bbs.mountblade.com.cn/forum.php?mod=viewthread&action=printable&tid=2112184)

### 9.2 Stamina System（Nexus #7933，Ulfkarl）— 纯耐力向

独立的耐力系统 MOD，不涉及架势/崩防。

**机制**：
- 所有单位 100 基础耐力，Athletics 技能加成
- 攻击和格挡都消耗耐力
- 低耐力惩罚（全局 debuff 路线）：
  - 耐力 < 30 → 移速下降
  - 攻速最高 -60%
  - 伤害最低降至 30%
- AI 低耐力时**后撤几步保持防御姿态**，恢复到 60+ 再战
- 有呼吸音效（breathing sound）

**已知冲突**：与 RBM 架势系统不兼容（同时开启 → AI 无限耐力）。

**来源**：[Nexus Mods](https://www.nexusmods.com/mountandblade2bannerlord/mods/7933) | [中文汉化](https://bbs.mountblade.com.cn/download_2062.html)

| 维度 | RBM | 我们的原方案 |
|------|-----|------------|
| 攻击消耗架势 | ✅ 攻击也耗 | ❌ 只格挡消耗 |
| 完美格挡反击 | ✅ 对方掉大量架势 | ❌ 简化无此机制 |

## 十、结论与决策

**这条路已经被 RBM 走通了。** RBM 证明了架势系统在骑砍 2 里完全可行，引擎的 `crushedThrough` + `defenderStunPeriod` + `OnRegisterBlow` 三件套足够支撑完整的架势/崩防体系，且玩家接受度极高（RBM 是最受欢迎的战斗大修 MOD 之一）。

### 最终决策：直接前置依赖 RBM，不自研架势系统

**理由**：
1. RBM 的架势系统已经做了我们原方案 90% 的事，且更完整（完美格挡反击、武器特有属性、UI）
2. 架势系统本身是**纯战斗层**的功能，跟本项目的差异化领域（NPC AI 行为、叙事、互动）是正交的
3. 不自研可以省下 4-5 天开发 + 持续的平衡调参维护成本
4. RBM 的架势 API（`crushedThrough`、`defenderStunPeriod`、架势值）对我们是透明的——我们仍可以在其之上构建**本项目的差异化价值**

### 本项目在架势之上的差异化空间

依赖 RBM 不意味着什么都不做。RBM 是战斗 MOD，不碰 AI 行为和叙事。本项目可以在 RBM 架势基础上做这些 RBM 不会做的事：

| 能力 | 说明 |
|------|------|
| **架势崩防 → AgentBrain 行为联动** | NPC 架势崩了 → 士气崩溃 → `FightEnemyAction` 中断 → 逃跑/投降意图入队。这是纯战斗 MOD 做不到的——它们只管战斗结算，不管 NPC 后续行为。 |
| **架势崩防 → 叙事演出** | 切磋/决斗中架势崩防 → 触发 Story 引擎 → 胜利台词/求饶/剧情分支。RBM 只管崩防动画，不管崩防后 NPC 说什么。 |
| **架势崩防 → 互动系统** | 战斗中把敌人架势打崩 → 解锁"劝降"互动选项（"你已经无力再战了，投降吧"）。用架势状态作为互动资格条件（`IntentBase.Eligibility`）。 |
| **NPC 性格 × 架势行为** | 胆小的 NPC 架势低时提前退缩；勇猛的 NPC 架势归零也要硬撑。经由 `NPCProfile` + `AgentBrain` 实现——RBM 不会做性格差异化。 |
| **LLM 叙事感知** | NPC 记忆系统记录"上次被 X 打崩了架势"→ 下次相遇对话有怨气/恐惧。RBM 不碰记忆和叙事。 |
