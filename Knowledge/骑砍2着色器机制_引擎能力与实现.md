# 骑砍2着色器机制 — 引擎能力与实现

> 取证：2026-10-03，方法 = 反编译 `Shokuho.dll` + 本机安装目录实测。
> 证据转储：`Debug/offline/_shokuho_dump/Shokuho.decompiled.cs`（离线产物，不进 git，可重生成）。
> 相关：[骑砍2粒子系统.md](骑砍2粒子系统.md)（粒子材质配方）· [骑砍2贴花系统.md](骑砍2贴花系统.md)（decal shader）· [骑砍2网格贴图动画_引擎能力与实现.md](骑砍2网格贴图动画_引擎能力与实现.md)（材质 flag 与 Vector Argument 抢位）· 官方快照 [shaders.md](bannerlord_official_docs/Asset%20Management/Asset%20Types/shaders.md)

## 结论（先看这五条）

1. 骑砍2 里「材质看起来怎样」= **shader 程序 + 材质 flag 组合**；**每个唯一组合是一个独立的待编译单元**（官方口径，见 §1）。
2. 出厂缓存只覆盖原版组合；mod 引入的新组合不在里面 → 要么预编译进模块包，要么运行时现编（现编 = 卡顿、图形异常）。
3. mod 有三条路：**A 自写 shader 源文件**（本机无先例、未验证）/ **B 用原版 shader + flag 组合、ModKit 预编译缓存**（官方推荐；我们自己的 `KCD` 模块已这么做过）/ **C 不预编译，进游戏跑一遍让引擎现编**（织丰走的这条）。
4. 🔴 **织丰没有自制着色器** —— 它主菜单里的 "Compile Shaders" 是路线 C 的自建外壳：跑一场"把所有内容刷一遍"的特制战斗，让引擎把 shader 组合全编译掉。详见 §4。
5. 地形 shader 是**按场景**编译缓存的，单独一套文件（`terrain_shaders_header_data.bin`）——改地形/地表相关内容要盯它。

## 一、基本模型

- Shader = 跑在 GPU 上的渲染程序；材质 flag 改变 shader 代码里的分支（例：开 `USE_PROCEDURAL_WIND_ANIMATION` 材质就随风摆动）。
- 官方文档原话：**Every material defines a new shader flag combination which in turns define a new shader code to be compiled**（每个材质定义一个 shader flag 组合 = 一段要编译的 shader 代码）。
- 引擎自带的缓存包含原版全部组合；新组合要现编。这就是"装了大型内容包第一次进战斗会卡一下/花屏"的根因。
- 引擎侧监控 API（已验签名，`TaleWorlds.Engine.Utilities`）：
  - `static int GetNumberOfShaderCompilationsInProgress()`
  - `static bool CheckShaderCompilation()`
  - `static void SetAssertionAtShaderCompile(bool value)`

## 二、缓存文件都在哪（五个位置，别搞混）

| 位置 | 内容 | 谁写的 |
|---|---|---|
| 游戏根 `Shaders/D3D11/compressed_shader_cache.sack` | 原版全部组合的出厂预编译缓存（游戏版本更新后可能失效/被替换） | 官方 |
| 模块 `Modules/<Mod>/Shaders/D3D11/` | `compressed_shader_cache.sack` + `shader_mapping.bin` | 编辑器 Publish 勾 Compile Shaders（或按路线 A 手编） |
| 用户 `C:\ProgramData\Mount and Blade II Bannerlord\Shaders\CoreShaders\D3D11\` | 运行时现编产物：每个 shader 一个 `*.sacx` + `shader_mapping.bin` | 引擎运行时。本机实测 761 个文件，最新 2026-10-03 = 引擎在游玩过程中持续补编 |
| 用户 `...\Shaders\TerrainShaders\<模块>\<场景>\D3D11\` | 地形 shader 运行时缓存 | 引擎运行时 |
| 场景 `SceneObj/<场景>/ShaderCache/D3D11/` | `terrain_shaders_header_data.bin`（地形 shader 头数据）；原版部分场景还带自己的 `compressed_shader_cache.sack` | 编辑器保存场景时自动生成 |

- shader **源码**位置：`<game>/Shaders/Sources/`（本机 844 个 `.rsh`/`.rs`）+ `Shaders/shader_configuration.h`（编译期总开关）。
- 引擎侧路径串证据（`TaleWorlds.Native.dll`）：`CoreShaders/D3D11/` · `compressed_shader_cache.sack` · `shader_mapping.bin` · `save_shader_combinations` · `save_shader_identifiers` · `rglShader_manager::read_compressed_shader_cache_package`。
- 本机实测：Vanilla 的 `benchmark_battle_11` 等场景两件都有；Taikou `Main_map`、Shokuho 各场景只有 `terrain_shaders_header_data.bin`。

## 三、三条路线

### 路线 A：自写 shader 源文件（未验证）

CSDN 专栏教程（11）口径的步骤：
1. TPAC 资产里创建自己的 Shader，Filename 填 `shader_test`；
2. 往 `<game>/Shaders/Sources/` 新增 `shader_test.rs`（写 `main_vs` / `main_ps`）；
3. ModKit `File → CreatePackage`（勾 compile shader 复选框）→ 模块目录生成 `Shaders/D3D11/*.sack`；
4. 删掉游戏根 `Shaders/D3D11` 的 sack，启动时就会用 mod 的 sack。

⚠️ **本机无先例、未实测**；教程没讲清 mod 分发时用户机是否需要往游戏根 `Shaders/Sources` 放源文件（那等于改游戏安装本体）。要做先开最小验证。
引用：`Knowledge/csdn_column_articles/骑砍Ⅱ霸主MOD开发(11)-可编程渲染管线Shader编程.md`。

### 路线 B：用原版 shader + 材质 flag 组合（官方推荐）

- 做法：不写 shader；在材质上开/关 flag，产出新组合；编辑器 **Publish Module 时勾 "Compile Shaders"**，缓存写进 `Modules/<ModuleName>/Shaders/D3D11`（官方称耗时 30~60 分钟，与多核性能相关）。
- 本机先例：**我们的 `KCD` 模块**有 `Shaders/D3D11/{compressed_shader_cache.sack, shader_mapping.bin}`（2026-09-20），模块内无自写 `.rs` → 就是这条路的产物。
- 运行期还能改 flag（已验签名，`TaleWorlds.Engine`）：

```csharp
// 取 flag 掩码 → 或进现有掩码 → 写回
ulong mask = material.GetShader().GetMaterialShaderFlagMask("use_tableau_blending", true);
material.SetShaderFlags(material.GetShaderFlags() | mask);
// 相关：Material.GetFromResource(string) / Material.CreateCopy() / Shader.GetFromResource(string)
```

### 路线 C：运行时现编 + 用户侧缓存（不预编译）

进游戏把内容渲染一遍让引擎现编，产物落用户目录 `CoreShaders`。**换机器/重装后要再跑一遍**（缓存不进模块包）——织丰选的就是这条，见下。

## 四、织丰案例：不是自定义着色器，是「着色器缓存生成」

**一句话：Shokuho 没有自制 shader（模块里没有任何 `.rsh`/`.rs` 源文件、没有 `Shaders/D3D11` 缓存包）；它做的是一个一次性预编译流程。**

流程链（类名/方法名可在证据转储里全文检索）：

1. 主菜单新增按钮 **"Compile Shaders"** → `InitialStateOption("ShaderCustomSandBoxNewGame")`（在 `ShokuhoSubModule` 里注册，和 "New Game"/"Continue Campaign" 并排）。
2. 弹提示框：要求 Battle Size 拉满 1000、Shader Quality = High；并说图形异常就删 `C:\ProgramData\Mount and Blade II Bannerlord\Shaders` 下的 `CoreShaders` 重启。
3. `CheckForBattleSize()` → `CheckForShaderQuality()` → `CompileShaders()` → `MBGameManager.StartNewGame(new ShokuhoShaderGameManager())`。
4. `ShokuhoShaderGameManager : CustomGameManager` 加载自己的场景 `sho_battle_plain_a`：把**所有文化里每个 soldier/hero 各刷 1 个、每人带全部装备档（≤5 套）**全放上场——目的就是让每种材质上一次屏，逼引擎编译对应的 shader 组合。用的是原版 `CustomBattleHelper` 的私有拷贝（改名 `OpenShaderCompMission`，任务名 `"ShaderCompiler"`）。
5. `ShokuhoShaderCompilerMissionLogic`（MissionLogic）盯 `LoadingWindow.IsLoadingWindowActive`，加载窗一关就 `Mission.Current.EndMission()` + 弹「Shader Generation Complete」。
6. Harmony 补丁 `LoadingWindowPatches.AddShaderCompCount`（`LoadingWindowViewModel.Update` 后置）实时显示「Remaining shaders to compile: N」——数字来自 `Utilities.GetNumberOfShaderCompilationsInProgress()`。
7. 编译产物落**用户侧** `CoreShaders`（ProgramData），不进模块包。

它全模块唯一的"shader 编程"代码 = 运行期给**原版** tableau shader 开一个 flag（`GetMaterialShaderFlagMask("use_tableau_blending", true)` + `SetShaderFlags`）——这是路线 B 的运行期版，不是写 shader。

## 五、对本项目的可用要点

- 要做新视觉效果（地表/法术/贴花类）时的优先级：**原版 shader + flag 组合** → 需要预编译就 ModKit Publish 勾 Compile Shaders（先例 = KCD）→ 运行时兜底才考虑"渲染一遍让它现编"。
- **地形 shader 按场景缓存**：动地形/地表（[plans/元素地表系统.md](../plans/元素地表系统.md) 类工作）要留意 `SceneObj/<场景>/ShaderCache` 与用户侧 `TerrainShaders/<模块>/<场景>`，必要时删掉重生成。
- 排查图形异常（材质变白/花屏/糊）先分两类：
  ① **材质本身没定义/材质名错**（编辑器里就是白板）→ 见铁律 32；
  ② **材质有定义但 shader 组合没编上** → 引擎在后台补编（`GetNumberOfShaderCompilationsInProgress`），急着重编可删 `C:\ProgramData\...\Shaders\CoreShaders` 重启（织丰的官方提示同此）。
- API 速查见本文 §1 与 §3B（均为本机反编译核实的真实签名）。
