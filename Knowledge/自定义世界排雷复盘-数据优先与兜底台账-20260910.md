# 自定义世界排雷复盘：数据优先 vs 运行期兜底（2026-09-10）

> 复盘范围：Taikou 内容包（`Modules/Taikou`）+ LWN 通用基座（`ExampleModVS/…/CampaignMode/Debug`）从零建起到「进城通」的全程（雷 1-42）。
> 读者：审批人。**结论先行、条陈式**——每节第一句就是要拍板的话。

## 一、结论（先说答案）

1. **方向本来就是对的**：42 颗雷里约 **7 成纯数据/离线脚本**解决（XML、SubModule 段、场景实体、生成器+checker），**1 成「数据治本 + 代码兜底」双保险**，剩下是**真必须写代码**的（引擎硬编码拦截、相机功能、存档定义器——这些不是"补丁"，是功能）。
2. **不优雅的地方不在比例，在管理**：兜底补丁**加了就常驻**——没有"治本侧是什么、什么时候能退"的台账；诊断补丁（一堆 *Diag/*Logger）也没有退役动作。这是**永久债风险**，不是当下 bug。
3. **可优化三件事**（按优先级）：①**把"官方场景消费清单"脚本化**——本会话两颗进城雷（地痞/马）本质是同一种离线可查的缺失，靠运行期炸出来才发现；②**建兜底台账 + 退役纪律**（本文第三节即台账，新补丁必须登记一行）；③诊断补丁生命周期管理（排雷结束后归档，别脏补丁常驻）。

## 四、优化清单（可执行，按优先级）

1. **场景消费清单脚本化**（把运行期雷提前成离线断言）——**新脚本**：扫本包 settlers 引用的官方场景 `.xscene` → `prefab="sp_*"` → 读 `Native/Prefabs/editor_spawnpoints.xml` 的 `<tags>` → Tags[1] 的物品/角色 id → 对照本包物品库/角色库 → 缺失即报。落成 `Scripts/check_scene_consumables.py`（与现有 checker 同风格，exit 1 阻断），纳入「数据改动必跑」。
   - **收益**：雷 40（地痞）/41（马）这类"官方场景消费缺失"将来在离线就抓住，不等运行期崩。
2. **兜底退役纪律**（并入清单阶段 2）：新增运行期补丁 → 必须在本文第三节台账加一行（类型/治本侧/退役条件）；**每次数据补全后回查台账**，满足退役条件的评审退役。
3. **诊断补丁生命周期**：`*Diag/*Logger/NavMesh*` 类 = 单次排查用，排查结束**归档**（csproj 注释 + 移 `Debug/_archive/`），保持生产 DLL 干净。本次涉及：ClickDiag/TownEntryDiag/EncounterDiag/PartyVisualCircleDiag/NavMesh×4/各 Logger。
4. **（已落）csproj 显式清单纪律**：新增/删除 .cs 与 csproj 登记行同进同退（plan 雷 40·流程）。
5. **数据侧待办汇总**（从台账导出）：36 兵源来源（T4）、39 Issues 时点（日志确认）、38/39 两补丁恢复或退役（读档二分定案后）。

## 五、给新内容包的启示（一句话）

**能用 XML 表达的绝不用代码；离线的能查的绝不留给运行期；运行期的只做兜底且必须带退役条件。** 三层防线 = ①数据断言（checker/脚本，改动即跑）②启动期加固（反射修补，跨包安全）③运行期兜底（拦截 NRE，带台账）。
