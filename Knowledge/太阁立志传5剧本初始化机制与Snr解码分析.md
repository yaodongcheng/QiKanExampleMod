# 太阁5 剧本初始化机制与 Snr 文件解码分析

> 背景：剧本工程（scenario-campaign-mode / 06-玩家身份与时代重置）需要"不同年代下每个人的归属、每个城池的归属王国、人物出生情况"作为时代初始化数据。本文是太阁立志传5（2004 PC 原版，本文分析的为绿色版 `Taikou5脱壳原版.exe`）年代剧本初始化机制的完整逆向结论，含可复现的解码方法。
>
> **一句话结论**：TK5 的年代初始化 = **每年代一份"世界完整快照"二进制文件**；文件在字节级用**每年代一张 256 字节逐字节替换表（S-box）**混淆；解密表即社区编辑器（剑阁编辑器 / 3DM 综合编辑器 v1.24）附带的 `EnCode.rtg`/`DeCode.rtg`，已用它解出全部 6 个年代的初始状态数据。

## 2. 加载链（脱壳原版 exe 反编译结论，地址均 `Taikou5脱壳原版.exe` 内 VA）

```
[新游戏选剧本] → sprintf("TW\Snr%d_TW.TR5", 剧本号)
 → 打开文件 → 取 size → malloc → 全量 fread → [对象 vtable hook = 解码]
 → 流式读取，offset += 0x10（16 字节记录读取器）
```

关键函数（`_analysis/find_xrefs.py` / `xref.py` / `disasm_func.py` 输出，已确认）：

- `0x54b9a1` / `0x54bcc2` 附近：两个"加载剧本"包装函数，`sprintf("TW\Snr%d_TW.TR5", ...)` 后调用 `0x54b830`
- `0x54b830`：读 8 字节前缀（内层头）、`malloc(count*4+4)`、`0x54b730` 拷贝流数据
- `0x54b670`：打开(size/malloc/fread) + `call dword ptr [eax+4]`（vtable 钩子 = 解码入口；2004 年反调试特性，vtable 为运行时计算，静态搜不到）
- `0x54bad1` 附近：**头部校验函数**——读 16 字节 → `sprintf(%05d)` 比对 `TR5SCENARIO` → `offset += 0x10`

## 3. 加密算法 —— 单层 256 字节 S-box 逐字节替换（已完全破解）

### 3.1 判定过程（为什么不是压缩/异或）

1. 六个文件字节直方图**秩对齐**（最高频字节计数几乎相同：84402/84108/84056…，但**值不同**：0x49/0xC7/0x12/0xD4…）→ 排除固定异或/旋转/仿射（均保序），也非压缩（同一压缩器对近同数据产生近同 token）。
2. 全文件逐字节比对（Snr0 vs Snr1）几乎全不同，但六个文件**大小仅差 ±250 字节**、且 `EnCode` 表第 k 张的首字节恰好 == 第 k 剧本文件最高频字节（见下）→ 断定：**每年代一张字节置换表**，替换后"0x00=空值"频次反而均匀。
3. 十六进制观测细节：文件字节 `0x0F` 后第一区（第 2 层头）六文件完全相同或仅差 1 字节（场景号），证明非流式加密。

### 3.2 表来源与结构

剑阁编辑器（root重来作，3DM《太阁立志传5》综合编辑器 v1.24，下载 `https://dl1.wsyhn.com/tools/3DMGAME_《太阁立志传5》综合编辑器v1.24.rar`，56KB）附三个核心文件：

- `TK5SEditor.exe` —— VB6 编辑器本体
- `EnCode.rtg` / `DeCode.rtg` —— 各 **1536 字节 = 6 × 256 字节置换表**；**每张 256 字节是完整排列（全 256 值唯一），且 `DeCode[k][EnCode[k][x]] == x`（逆关系），即 chunk k = 剧本 k 的编码/解码 S-box 对**

判定铁证：`EnCode[k*256]`（即表 k 的 [] 0x00 项）== 剧本 k 原始文件的最高频字节：

| 剧本 | 文件冲线最高频字节 | EnCode 表 k[0x00] | 备注 |
|---|---|---|---|
| 0 | 0x49 | 0x49 | |
| 1 | 0xC7 | 0xC7 | |
| 2 / 4 | 0x12 | 0x12 | 表 2 ≡ 表 4 |
| 3 / 5 | 0xD4 | 0xD4 | 表 3 ≡ 表 5 |

### 3.3 解码方法（已验证，可复现）

```python
de  = open('DeCode.rtg','rb').read()          # 1536 字节
raw = open('Tw/Snr1_TW.TR5','rb').read()
# 剧本 1（1560）：
plain = bytes(de[1*256:(1+1)*256][b] for b in raw)   # 逐字节查表（注意可变大小文件）
```

验证：解码后最高频字节 = **0x00**（84,124 次）——"空值填充"回归，且文件头区域出现明文：

```
0x00: TR5SCENARIO00001        ← 明文外头（16 字节，未混淆）
0x10: TAI5SNR001 + 00 pad     ← 第 2 层头
0x29: TAI5TAI5SCENARIO1 + pad ← 第 2 层头
0x40+: 数据区（LE 16 位值表格：0x00a6/0x02b6/0x082e/… + 大量 0x00 填充 + SJIS/半角假名字符串）
```

产物已存：`E:\taikou5\Taikou5.Green.Edition-ALI213\Taikou5\_analysis\decoded\Snr0-5.plain`（每个约 153KB，全部 6 代已解码）。

### 3.4 存档无加密（2026-08-31 确认）

`SAVEDATA\SaveDat0.TR5`（399KB）**无 S-box、就是明文**（70% 字节为 0x00=空字段）。头部：`TAIKOU5WIN` 魔数 + [版本4][文件大小][校验][46]。`savedata.tr5`（24KB）与 exe 内嵌 24576 字节模板（VA 0x7018E0）**逐字节 24561/24576 一致**——存档 = 游戏内存状态块快照，模板即字段骨架。

### 3.5 人物记录 36 字节字段映射（三方验证：高亚男截图 × 存档 × Snr 快照）

人物属性表：每剧本一个定长数组，**记录 = 36 字节，基址 = 信长锚点反推**（Snr0=0x951F/Snr1=0x954C/Snr5=0x9540…）+ 36×人物ID；存档基址 0x6D8A。**字段**：

| 偏移 | 字段 | 验证值（1560 信长/秀吉） |
|---|---|---|
| +0x00~04 | 统率/武力/政治/智谋/魅力 | 96,70,97,91,99 / 80,56,88,96,93 |
| **+0x05** | **所属势力 ID**（19=织田；121=无势力/浪人/已死） | 19 / 19（1554 秀吉=121 浪人✓） |
| +0x06 | 直属编码（首领/直臣） | 0x42 信长 / 0xC2 秀吉 |
| +0x07 | 地位阶（随时代变，含义待定） | 0x10 / 0x11 |
| +0x09 | 身份类（实际枚举 ≠ 显示序号） | 信长 08 / 秀吉 02（家老长秀=02 说明更复杂） |
| +0x0A | 上司（1101=无） | ✓ |
| +0x0C | 俸禄（贯） | 0 / 5 ✓ |
| +0x0E | 野心/忠诚 | 100,100 / 98,100 ✓ |
| +0x10 | 家徽 | 39 / 41 ✓ |
| +0x11 | 常量 0x79 | — |
| +0x12-15 | 零 | — |
| +0x16-17 | 生没相关常量（信长0x065F/秀吉0x0649，跨时代不变；编码未破） | — |
| +0x1A-1B | 常量对（05 05 / 05 00…含义待定） | — |

**年龄公式**（游戏情报屏验证）：年龄 = 当前年 − 出生年 + 1（虚岁；信长 1534→1560 年 27 岁✓、秀吉 1536→25✓、长秀 1535→26✓）。

### 3.6 城池记录（城→城主映射，已验证）

## 4. 数据内容语义（社区编辑器字段清单 = 独立第三方佐证）

剑阁编辑器"剧本文件编辑"界面可修改的字段（= 剧本文件的语义内容，社区十多年使用验证）：

- **人物**：姓名、编号、所属势力、上司、直属关系（首领/直臣/陪臣/寄骑/浪人）、身份（大名/城主/家老…足轻/浪人）、所在（城/町）、能力、情义/精神/主义/行为、初始卡
- **城**：大名当主、城主、城士兵数、防御
- **势力/外交**：外交关系、外交情感（停战/开战月数、感情）
- **经济**：商人（第一列=支店长，空则该支店不出现）、据点（其店所在）、御用商人、销售通路、物品所有者
- **其他**：官职及其所有者、武将流派、忍者众/海贼众名、家纹

→ **结论：Snr = 剧本的"世界完整初始快照"，非增量**。人物出生情况不逐代重列，而是通过**初始年龄/身份**随剧本变化实现（同一人物不同年代 = 快照不同）。

## 8. 城并合与映射数据工程（2026-08-31，已落地）

1. **N:1 并合必须过"地理邻接"检查**——同一织丰城承接多个 TK5 城时，各 TK5 城国名必须**同国或直接邻国**，否则报人工（2026-08-31 用户裁定；已验证 23 条 N:1 全部通过，唯一存疑 = 天雾城↔宇和岛城（赞歧↔伊予，织丰 nankai 无伊予实体城的无奈，IsMerge=1 可拆））。

## 6. 对本 mod 剧本工程（LivingWorldNpcs scenario-campaign-mode）的意义

- **机制迁移**：年代初始化 = 每年代一份"快照数据包"（人归属 + 城归属 + 出生/年龄表），开局时整体覆盖运行时。TK5 用 6 独立文件；本 mod 拟用 JSON（每年代一包），引用一律 StringId（铁律 20）。
- **规模参考**：约 900 人物 + 全城归属 + 外交/官职/商人 ≈ 153KB/年代（二进制紧凑态）；JSON 态预计数百 KB/年代，可接受。
- **数据来源**：TK5 数据仅作机制与数量级参照；具体数值应取本工程 战国数据包（织丰主轴，StringId 体系），避免直接拷贝 TK5 数值（它含架空调味与史实偏差）。
