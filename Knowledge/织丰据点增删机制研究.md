# 织丰据点增删机制研究（1.2.12 实测边界 + 1.5.1 路径）

> 2026-09-01 探明。背景：在织丰（Shokuho，日本战国全量素材）基础上为剧本层（ShokuhoTaikouExpansionPack）新增/调整据点。结论先行地记录"能做什么、不能做什么、为什么"。

## 一、结论速览（先看这个）

| 操作 | 1.2.12 环境 | 1.5.1 环境 |
|---|---|---|
| **新增据点**（含大地图模型） | ❌ **不可行**（引擎注册器 NRE，实测多路径全崩） | ✅ 可行（合并管道 + 场景覆盖，本包脚本已就绪） |
| **改/删织丰既有据点**（归属/名字/删除） | ✅ 可行（XSLT 属性级修改，官方标准通道，从未崩过） | ✅ 可行 |
| 调整据点在大地图上的位置 | 改两处：settlements.xml posX/posY + scene.xscene 实体 transform | 同左 |

**1.2.12 剧本层调整据点的正路 = XSLT 改/删**；新据点功能移师 1.5.1 主环境。

## 二、据点三层数据绑定（基础知识，两个版本通用）

| 层 | 文件 | 内容 | 谁决定 |
|---|---|---|---|
| 逻辑层 | `Modules/Shokuho/ModuleData/settlements.xml` | `<Settlement id/name/owner/posX/posY/culture/gate_posX>` + `<Components>`（Town/Castle/Village 组件，含 bound/village_type/menu 背景） | 大地图位置 posX/posY、归属、进村贸易逻辑 |
| 大地图视觉层 | `Modules/Shokuho/SceneObj/Main_map/scene.xscene`（7MB 文本）+ terrain/flora/navmesh bin | `<game_entity name="据点id" prefab="sho_map_*_full">` + `<transform position="x, y, z">` + children（房屋摆放相对坐标） | 大地图上看到的 3D 模型；**实体名 = 据点 StringId（绑定点）** |
| 内部场景层 | Locations 段内的 `scene_name="sho_town_a/sho_village_c/sho_keep_scene/sho_prison_b"…` | 进村/进城/围攻/酒馆/地牢的实际场景（织丰 SceneObj 独立场景） | 复用织丰场景，零新建 |

要点：
- 新增据点/城模型复用 = 克隆现有 `game_entity` 块、改 `name`（=据点 id）+ `transform`（x/y = posX/posY；**z 是贴地高度，先抄邻近村的值再微调**）。
- 织丰坐标域：京都 town_KIN5 = (891.321, 617.074)；邻村距 12~26。坐标与沙盒（0~1000）无关，织丰是独立地图。

## 三、模块加载合并模型（反编译 ObjectSystem 实证，1.2.12 与 1.5.1 同款）

`GetMergedXmlForManaged` → `CreateMergedXmlFile`，按**模块加载顺序**演化一份文档：

```
文档 = 织丰的 settlements.xml（所有之前模块合并结果）
① 先 ApplyXslt(本模块自己的 .xsl/.xslt)   ← 只作用于"之前模块"的数据
② 再 Merge(本模块自己的 .xml)             ← 新元素走这里（官方推荐）
```

- **多源合并被官方支持**：StoryMode 先例——只写 2 条增量 + SandBox 全量并存（1.2.12/1.5.1 都验证）；同 GameType 多文件共存，重复 id 由启动器加载顺序定胜负。
- **注册写法**（照抄织丰）：`<XmlName id="Settlements" path="settlements"/>` + `<IncludedGameTypes><GameType value="ShokuhoCampaign"/></IncludedGameTypes>`（标签是 **IncludedGameTypes**；GameType 必须是织丰自定义的 **ShokuhoCampaign**）。
- **XSLT 规则**：文件名必须与目标 xml 同名（`settlements.xslt`）、放 `ModuleData/` 根目录；`.xsl` 与 `.xslt` 后缀都认（`HandleXsltList` 先试 `.xsl` 再试 `.xslt`）；**无需单独注册**（挂在同名 xml 注册条目上自动生效）；**只对加载在自己之前的模块生效**；**碰不到自己模块的数据**（顺序：xslt 先于自家 xml merge）。
- **XSLT 里写 `{=key}` 必须转义**：`{` 是 XSLT 属性值模板起始符 → `{=LWN...}Lianshui` 写入属性必须写 `{{=LWN...}}Lianshui`（双括号转义还原），否则 `XslLoadException: Unexpected token '='`。
- 引擎 XML 校验（1.2.12 调用方 `skipValidation: false`）：两个环境的 SandBox 均无 `settlements.xsd`，schema 校验未实际生效（排除过这个嫌疑）。

## 四、1.2.12 实测矩阵（本次全部实证）

**判定"不可行"的证据链**：

| 组合 | 结果 |
|---|---|
| 仅注册 + 空根 `<Settlements/>` | ✅ 不崩（织丰原版体验） |
| 注册 + 完整村条目（中文名） | ❌ 崩（角色创建 OnNextStage 空引用，`CharacterCreationOptionsStageVM`） |
| 同上（英文名 fallback） | ❌ 同样崩（**中文洗清，与本地化无关**） |
| 同上（剥掉 text/CommonAreas 装饰字段） | ❌ 崩（场变为注册期 `CreateObjectFromXmlNode` NRE，`node.Attributes["id"].Value` 对无 id 节点） |
| **XSLT 插入**村到织丰文档 | ❌ 同样在注册器 NRE（XSLT 通道本身已通：编译过、节点进文档，死在 ObjectSystem 注册阶段） |

**根因**：1.2.12 的 `ObjectSystem.LoadXml(doc)` 循环：

```csharp
for (XmlNode xmlNode = doc.ChildNodes[i].ChildNodes[0]; ...; xmlNode = xmlNode.NextSibling)
    if (xmlNode.NodeType != XmlNodeType.Comment)
        string value = xmlNode.Attributes["id"].Value;   // ← 无 id 节点 → NRE
```

任何"第二来源"进文档的新节点（合并或 XSLT 插入），在低版本引擎的注册器上都过不了（**注意：这里是"能通过 XSLT 编译+进文档的节点仍有问题"→ 深挖收益极低，判定放弃**）。

**另一条先前的坑（1.2.12 大地图 PartyVisual）**：据点无场景实体时，`PartyVisual.OnStartup` 走 `AddNewEntityToMapScene` 兜底，native 建实体异步不生效 → 二次查找仍 null → 继续解引用崩。→ **1.2.12 缺场景实体不只是观感问题，会崩**（这也是当初"必须补场景覆盖"的起点；场景覆盖方案本身正确，只是被注册器 NRE 挡在更早的地方）。

## 五、1.5.1 推荐路径（下次开工照抄）

1. **增量数据**：本包 `ModuleData/settlements.xml` 只写新增条目（id 全新，Locations 全复用织丰场景）——1.5.1 合并管道已反编译验证成熟；
2. **大地图实体**：本包 `SceneObj/Main_map/` 整目录覆盖织丰（52MB，**必须整套**：terrain/flora/navmesh bin + ShaderCache 是场景的一部分，缺一不可）；由 `gen_map_patch.py`（已写好，位于 ShokuhoTaikouExpansionPack/gen_map_patch.py）生成：拷贝织丰 Main_map → 克隆 Kameoka 实体块（name/transform，坐标从 settlements.xml 读取，单一数据源）→ 自检（实体唯一/坐标一致/标签配对/地形齐全）；
3. **XSLT（改/删织丰数据）**：`ModuleData/settlements.xslt`，属性级写法见 ModuleData/Patches/UpdateSettlementsOwner.xslt（标准范本）；
4. 织丰更新后：重跑 gen_map_patch.py 即可。
