# 换脸管线 —— 踩坑记录与最终结论（2026-08-29 归档）

> 目标：把参考图（织田信长立绘）的脸"贴"到骑砍2 男性角色（原版/织丰 1.2.12）。
> 结果：**暂不可行性结论**。本文记录已验证的事实边界、全链踩坑、不再重走的弯路。
> 配套文档：`Knowledge/tpac资源替换打包指南.md`（机制与工具流程）、
> `Knowledge/脸部系统分析.md`（引擎结构事实）、`tools/face-pipeline/`（工具与 20+ 版本历史材料）。

## 结论（先讲）

1. **"换一张参考图的脸"无法靠"贴图资源替换"做到**——骑砍2 脸 = 多层渲染。
   原生男女头：五官（眼/鼻/嘴/眉）由 FaceGen **按角色 Key 当场合成的"合成脸皮层"**，
   贴图替换（diffuse）只作用于**五官之外的皮肤纹理区**（所以红/黑/绿探针"整脸变色"、
   但把五官画进贴图只会在眼/鼻/嘴/眉周边"漏出"小块）。
2. 织丰头（`sho_head_male_japanese`）情况好转但**仍非单张贴图**：diffuse=皮肤+部分五官纹理，
   但**眼球= 独立子网格 `.eyes` + 独立材质（`eye_mat` → 原生 `eye_a_d` 纹理）**、
   **口腔= 独立子网格 `.mouth`（`mouth_mat`）**、**眉毛= 独立网格+纹理（`sho_male_eyebrows`）**——贴图替换覆盖不了这些层。
3. **理论上唯一正路**：自建"完整脸"头资源（参考织丰 = 新 mesh + 新 diffuse + skin 替换），
   属于 **3D 资产级工程**（需要 3D 建模/UV/法线链 + skin 矩阵与角色引用接线），
   "用脚本把照片炖成资源包"到此为止；本项目暂不做。
4. **愿意继续的后续入口**（若未来投入）：从织丰头的 `.eyes/.mouth` 子网格与材质链直接
   替换眼球/口部纹理（本次已在 1/3 处成功——眼球已换出信长瞳色、眉毛染黑），
   剩余为**皮肤 diffuse 的五官区**仍受织丰头 UV 结构限制（需详测织丰头 UV 布局）。

## 已证实的事实（可复用知识）

- **引擎同名资源覆盖**：`AssetPackages/*.tpac` 同名资源，后加载者生效；无覆盖清单；SubModule 只注册 mod。
- **脸缓存**：NPC 的 `face_mesh_cache="true"` → 旧档脸固化，新档才重新生成；主角每次实时生成。
- **织丰皮肤替换男性头**：`Shokuho/ModuleData/skins.xml`（整文件覆盖，非 xslt），
  将 `human/man` skin 的 `face_meta_mesh` 换成 `sho_head_male_japanese`。
- **资源实测链路**：TpacTool（解码/打包）完整可读写（roundtrip 字节级一致）、
  像素数据（Bannerlord.gts Graphine）内的原版贴图无法解出——**换脸贴图必须全新建**。
- **探针方法学**（对"diffuse 可见区"有效）：全纯色（红/黑/绿）→ 网格数字格 → UV 星图
  （每像素 R=u,G=v）→ 纯色块贴图；**星图是唯一能一次读出引擎真实 uv 的手段**；
  但仅当目标区域在 diffuse 可见层（织丰眼的黑瞳在星图上仍是黑= 独立层，验证了多层结构）。
- **织丰头部子网格材质链**（meshinfo/matinfo 命令可复现）：
  `[0] sho_head_male_japanese`（皮肤）材质 `7b4b0d70…` → `2sho_head_male_japanese_d`（4096 DXT1 13mips）
  `[1] .eyes` 材质 `483bdd43…` → `eye_mat` → `eye_a_d`（512 DXT5）
  `[3] .mouth` 材质 `9dbe88e9…` → `mouth_mat` → `mouth_a_d`（原生族）
  眉毛：`sho_male_eyebrows`（metamesh+2048 DXT5 纹理）

## 打包全链踩坑清单（本次 26+ 包迭代的新增坑）

| # | 坑 | 表现 | 对策 |
|---|---|---|---|
| 1 | 模板纹理选错（FirstOrDefault Width==4096 命中 `_n` BC5） | 捏脸界面崩溃 | makeface 模板选择必须匹配目标格式（DXT1）+ 格式字段以 DDS FOURCC 为准 |
| 2 | DXT5 纹理（眼球/眉毛）被强制 DXT1 | alpha 丢失/色偏/灰 | ParseDds 读 FOURCC：“DXT5”→DXT5；texconv 用 BC3_UNORM |
| 3 | `Source` 字段继承外部路径 | 引擎外链/崩溃 | 置空 |
| 4 | `MipmapCount` ≠ 数据层数 | 越界/崩 | 三处一致（字段/KEY_MIPMAP/target mips） |
| 5 | 打包内 tpac 文件名固定 `face_lwn.tpac` | 多纹理互相覆盖 | makeface 加 `--packname` |
| 6 | Bash 沙箱 vs 宿主视图 | 用户/IDE 看不到产物 | 交付/安装全部走 PowerShell |
| 7 | mod 顺序 | 织丰把我们的包顶回去 | `DependedModuleMetadata order="LoadBeforeThis"` 是无顺序强制锁（注意：实测"顺序已强制但仍在织丰环境未生效时优先怀疑资源名/层，非顺序） |
| 8 | "全红探针生效但真脸包无效" | 观感无变化 | 区分"机制通"与"内容层"——探针红=机制；真脸无变化= 替换内容在引擎不可见层（=核心结论） |
| 9 | 1.2.12 原版 vs 织丰 环境目标不同 | 分析混淆 | 先确认目标环境（原版 male head=head_male_a；织丰=male 头=sho 头） |

## 错路线记录（别再走）

1. **在 diffuse 上画五官区拼脸**（v15-v21/8 个版本全废）——五官层不在 diffuse。
2. **软渲染器 + 导出网格推导 UV 再反推引擎布局**（头回 uv_pick 一套）——软渲与引擎视图不同，
   重复劳动；**唯一有效的是引擎内星图读数**。
3. **在"颜色/位置小偏"上反复调参**（对应 20+ 轮微调）——不少"偏"是**结构层差**，非参数差。
4. **织丰皮肤 diffuse 五官区替换也能成功**的假设（sho v1-v3 三版全偏——被 `.eyes/.mouth/.brow` 覆盖 + 织丰头 UV 竖带环绕结构不同）。
5. 忽略"引擎女性头/原版头/织丰头根本不同布局"→ 锚点跨头复制（每次翻车点）。
6. 借"数字格/颜色块"等方法三番五次读 UV——灯下黑层（diffuse 区域=皮肤纹理可见区，
   越核越远离五官层；**应在确认"五官层在哪"之后再选替换资源**）。
