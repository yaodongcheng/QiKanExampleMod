# 骑砍2「自带骨架武器」机制 —— 投石索 / 连枷 / 镣铐（1.3.0+ 新增）

> **一句话结论**：引擎从 **1.3.0** 起支持一种新武器类型 —— **武器自带一副小骨架**（投石索 9 根骨），
> 引擎在播人体动画的同时，**按名字自动配一条同名 `_weapon` 动画**播在这副骨架上（两条动画时长逐帧对齐）。
> 投石索的"绳子"就是靠这个动的，**不是物理模拟**；弓的"弦"走的是另一套（`HasString` 旗标）。
> **1.2.12 完全没有这套东西** ⇒ 钩索若要用，只能当 1.3+ 的可选增强，不能作为全版本方案。

调查日期：2026-10-13 · 证据版本：1.5.x（Steam 主目录）+ 1.3.15 + 1.2.12 三端对照
· 取证工具：`ilspycmd` + `tools/tpactool` 的 `tpaccli`（`list` / `dump` / `animbones`）

---

## 一、机制总览

引擎里有一族"**武器带自己的骨架**"的物品。全部成员（1.5.x 实查）：

| 家族 | 物品 | 骨架 | `_weapon` 动画 |
|---|---|---|---|
| 投石索 sling | `sling_wool` / `sling_braided` / `sling_reinforced` | `sling_skeleton` | 有 |
| 连枷 flail | `flail_*` ×2 | `flail_skeleton` | 有（`anim_flail_*_weapon`） |
| 镣铐 shackle | `shackle` | `shackle_skeleton` | 有 |

`Modules/Native/ModuleData/CoreGameReferences/skeleton_model.txt` **全文只有两行**：
`human_skeleton` 和 `sling_skeleton` —— 投石索是**唯一被登记进这张参考表的武器骨架**
（连枷/镣铐的骨架只存在于资产包里，没进这张表）。

三个家族都是同一类东西：**手里握着一个"会晃的软物"**（绳子 / 链子 / 铁链）。

## 二、工作方式（三条链，全部实查）

**① 物品声明"我有一副骨架"** —— `SandBoxCore/ModuleData/items/weapons.xml:7112`

```xml
<Item id="sling_reinforced" ... Type="Thrown"
      skeleton_name="sling_skeleton"          <!-- 🔴 关键：自带骨架 -->
      static_animation_name="sling_drop_weapon" <!-- 掉地上时的姿势（也在同一副骨架上） -->
      holster_mesh_with_weapon="sling_holster"
      mesh="sling_a" AmmoOffset="-0.02, 0.0, 0.0">
  <Weapon weapon_class="Sling" ammo_class="SlingStone" item_usage="sling" ...>
    <WeaponFlags RangedWeapon="true" AutoReload="true"
                 UnloadWhenSheathed="true" UseHandAsThrowBase="true" />
```

对照弓：`composite_bow` **没有** `skeleton_name`，但多两个旗标 —— `HasString="true"` +
`StringHeldByHand="true"`。**这就是两者的分水岭**：弓的弦是引擎内建特性，投石索的绳是自骨架动画。

**② 动作表照常挂人体动画** —— `action_sets.xml` 的 `as_human_warrior`（第 6284~6324 行）

```xml
<action type="act_ready_continue_sling" animation="ready_continue_sling" />
```

**③ 引擎再按名字找 `_weapon` 版，播在武器骨架上**

`action_sets.xml`、`item_usage_sets.xml` **从头到尾没有出现过任何 `_weapon` 字样**（`grep` 计数 = 0）。
`_weapon` 动画是引擎在运行时**按"人体动画名 + `_weapon`"自己配的**（这条配对逻辑在 native，托管层看不到）。

### 成对动画实测表（`tpaccli animbones`）

| 人体侧 clip | 源动画（`human_skeleton` 28 骨） | 帧范围 | 时长 | 武器侧 clip（9 骨 `bone_0..bone_8`） | 帧范围 | 时长 |
|---|---|---|---|---|---|---|
| `ready_sling` | `anim_sling_attack_ready` | 1..17 | 0.53s | `ready_sling_weapon` | 1..17 | **0.53s** |
| `ready_continue_sling` | `anim_sling_ready_continue` | 1..11 | 0.45s | `ready_continue_sling_weapon` | 1..11 | **0.45s** |
| `release_sling` | `anim_sling_attack_release` | 14..37 | 0.70s | `release_sling_weapon` | 14..37 | **0.70s** |
| `release_sling_continue` | 同上 | 37..85 | 1.20s | `release_sling_continue_weapon` | 37..85 | **1.20s** |
| `reload_sling` | `anim_sling_reload` | 15..67 | 1.15s | `reload_sling_weapon` | 15..67 | **1.15s** |
| `reload_sling_continue` | 同上 | 55..120 | 1.55s | `reload_sling_continue_weapon` | 55..120 | **1.55s** |

🔴 **左右两列帧范围逐条相同** —— 这是同一段动作捕捉切出来的两条轨（人 + 绳），
所以天然同步，**不需要写任何同步代码**。

绳子上只有 `bone_0` / `bone_1` 在转（`ready_continue_sling_weapon` 的窗口内：`bone_1` 转了 **180°**，
`bone_0` 转 30°），`bone_2..8` 不动、**全部 9 根骨的位移轨道都是 0** ⇒ **纯旋转驱动，没有物理**。

## 三、弓 vs 投石索 —— 全项对照

| 维度 | 弓 | 投石索 |
|---|---|---|
| 武器类 | `WeaponClass.Bow` / `ItemTypeEnum.Bow` | `WeaponClass.Sling` / `ItemTypeEnum.Sling` |
| 弹药类 | `Arrow` / `ItemTypeEnum.Arrows` | `SlingStone` / `ItemTypeEnum.SlingStones` |
| 武器骨架 | 无 | `sling_skeleton`（9 骨） |
| 弦/绳实现 | `HasString` + `StringHeldByHand` 旗标（引擎内建） | 自骨架 + `_weapon` 动画 |
| **动作挂谁身上** | 🔴 **挂在「箭」上** —— `item_usage="arrow_top"` / `"arrow_right"`（左右搭箭位），bow 自己的用法组里**一个 `<usages>` 都没有** | 🔴 **挂在「武器」上** —— `item_usage="sling"`；弹药 `item_usage=""`（空） |
| 弹药插槽 | `1h_throw_stone_left` 类 | `throwing_stone:throwing_stone_2` |
| 弹药附加 | `AttachAmmoToVisual` | 同上 + `ForceAttachOffHandPrimaryBone`（石头挂在**袋兜**那根骨上） |
| 最佳精度等待 | `0.3 + (95.75 − thrustSpeed) × 0.005` ≈ **0.3~0.55 秒** | `2.6 + (89 − thrustSpeed) × 0.12`（羊毛索 105 → **0.68s**；强化索 120 → **负数 = 立刻满精度**） |
| 失稳开始 | `0.6 + 技能×0.01×Lerp(2,4,v)` | `3 + 技能×0.064` |
| 失稳结束 | 开始时 + 2 秒 | 开始时 + **22 秒** |
| 转向精度惩罚 | 0.1 弧度 | **0.2 弧度**（翻倍） |
| 移动精度惩罚倍率 | ×6 | ×5 |
| 技能衰减系数 | `1 − 0.002×技能` | `1 − 0.007×技能`（**技能权重高得多**，钳制下限 0.2） |
| 相关技能 | `DefaultSkills.Bow` | `DefaultSkills.Throwing` |

数值出处（1.5.x `TaleWorlds.MountAndBlade.dll` 反编译，单机与联机两份模型里数值一致）：
`SandboxAgentStatCalculateModel` 约 64272~64420 行 · `MultiplayerAgentStatCalculateModel` 约 65743~65962 行。

🔴 **"蓄力"不在 C# 里，也没有状态机** —— 它就是上面那串 `AgentDrivenProperties`
（`WeaponBestAccuracyWaitTime` / `WeaponUnsteady*`），由引擎每帧读来决定准星收敛。
按住右键期间循环播 `ready_continue_sling`（0.45 秒一圈 = **甩圈**），松手播 `release_sling`。

### 骑马时的投石索（2026-10-13 逐骨实测）

| 事实 | 证据 |
|---|---|
| **只有 2 条骑马专属**：`ready_sling_with_shield_horseback`(0.53s) / `ready_continue_sling_with_shield_horseback`(0.45s) | 资产表 |
| **没有骑马版的 release / reload** —— 直接复用地面版 | `action_types.xml` 里只有那两条带 `_horseback` |
| **和地面版的差别只有左臂**（骨 15~20：左上臂/左前臂/左手）—— 甩圈的右臂、躯干、腿、骨盆**一字不差** | 逐骨四元数 diff（帧 5/9/17，`animrot --all`） |
| 无盾骑马时走地面版 `ready_sling` | 用法组里 `is_mounted="True"` 的裸版那一条 |
| 武器侧（绳子）**骑马也用地面那条** `ready_sling_weapon` | clip → 底层动画对照 |

> 对照实验（证明读数方法有分辨力）：弓的 `anim_bow` vs `anim_bow_horseback` 在同帧
> 逐骨差异**很大**，而投石索的骑马版只差左臂 ⇒ 不是工具读错，是原版真的只改了持盾那只手。
>
> ⇒ **骑马和步行的甩圈是同一套动作**，只有"持盾/持缰那只手"分叉。搬运量因此更小。

## 五、对钩索（Grapple）的可借鉴点

**能借鉴的**

1. **"武器 + 弹药"的用法组分工**：投石索证明了**武器侧可以自己扛全部动作**
   （`reload` / `ready` / `release` / `ready_continue` 四项齐全），弹药侧留空即可。
   我们的钩索现在走的是弓的路子（`Type=Bow` + 动作挂在钩上），多绕了一层。
2. **`ready_continue` 就是"持续状态循环"的官方槽位**：投石索的甩圈、弓的拉满待发都用它。
   钩索若要"举着钩子待发"的循环姿态，这个槽位是现成的。
3. **`AmmoOffset` + 弹药骨挂点**：石头挂在袋兜骨上（`ForceAttachOffHandPrimaryItemBone`），
   这是"弹药在武器上有个固定栖位"的官方写法。

**不能借鉴的**

1. 🔴 **引擎不会替我们模拟绳子** —— 投石索的绳**全靠美术烘动画**（6 条人体动画 = 6 条绳动画）。
   我们的钩索绳有几十种状态（绷直/下垂/甩尾/缠绕/扛人），**没有可能把每种都烘一遍**。
   ⇒ **现有的 verlet 点链方案（`GrappleRope.cs`）继续用**，它天然覆盖所有状态。
2. 🔴 **1.2.12 没有这套机制**（见上表），而钩索要求全版本可玩 ⇒ **不能作为主路径**。
3. 🔴 **自骨架动画的成本**：要新增一副骨架 + 每条要同步的人体动画都配一条 `_weapon`，
   还得过 ModKit 导入。**投入产出比在本工程不成立**。

## 七、把原版投石索动画搬进我们自己的包 —— TRF 路线（2026-10-13 定）

**结论：能，而且不用过 FBX / Blender —— 直接从 tpac 写出 TRF。**

为什么能直读直写（三条都是实查的）：

1. TRF 的**旋转轨语义 = 绝对局部变换**（`tools/anim-retarget/docs/TRF规范.md` §1）。
2. 引擎动画里存的**也是**绝对局部变换（含静止姿势）—— 这正是 `animbones` 说的
   "骨骼里存的是含静止姿势的局部变换，跟首帧比才等于'这段动画动了它多少'"。
3. **源骨架 = 目标骨架**：都是 `human_skeleton`、28 骨、同序。

⇒ **零重定向**，逐骨逐帧抄四元数即可。

**要写的工具**：给 `tpaccli` 加一个 `trfexport` 子命令（约 100 行，照 `AnimRot.cs` / `AnimPos.cs` 写）。
数据接口现成：

```csharp
var data = sa.Definition?.Data;      // SkeletalAnimation 的关键帧
data.BoneAnims[b].RotationFrames;    // 每根骨：帧号 → 四元数（绝对局部变换）
data.RootPositionFrames;             // 根骨专用位移轨（投石索这几条是空的）
```

**输出格式**照 `pipeline/common/fbx_to_trf.py` 的 `write_trf()`：

```
rfver 4
skeleton_anim 1
<名> 1
 28
 <每根骨的旋转帧： 帧号 x y z w>
 <根骨位移帧： 帧号 x y z>          ← 投石索无位移 ⇒ 空轨
end
```

**三条硬纪律**：

1. 🔴 **名字必须 `lwn_*`** —— TRF 里的 `<名>` 就是 clip 名。native 有
   `Unable to register animation clip %s. Another clip with same name already exist`，
   在 1.3+ 上留原名**会和原版撞车**。
2. 🔴 **clip 元数据要一起抄** —— ModKit 导入只管时长；`Blend in period` / `Continue to action` /
   `Priority` / `Param 2` / `loading_type` 要照抄同类原版。现成工具：`clipinfo` 查 ·
   `clipprio` / `clipparams` / `clipflags` / `clipload` 改。
3. ⚠️ **开工前先对骨序** —— TRF **不存骨名、按索引对号**，tpac 的 0..27 骨序必须和 ModKit
   期望的一致（两边都自称是游戏骨架，大概率一致，但**没验过**）。

### 🔴 为什么不能"直接引用原版 clip"了事（2026-10-13 实机，已证伪）

第一反应是"那就不搬了，`action_sets.xml` 的 `animation=` 直接填原版 clip 名" —— **试了，不行**。

| 现象 | 证据 |
|---|---|
| 把 `release` 指向 `release_sling` 之后**开不了火** | 引擎日志（`rgl_log_<pid>.txt`）里 `OnAgentShootMissile` **一次没进**（我们的开火补丁正挂在它上面）⇒ **断在引擎侧** |

**根因**：`animation=` 借的是一个 **AnimationClip**，而 clip **自带一整套为原武器调过的元数据**，
会跟着一起借进来。投石索的 clip 与弓系（= 我们 release clip 的抄写模板）差三样：

| 字段 | 弓 / 我们 | 投石索 |
|---|---|---|
| `ContinueWith` | **空** | `act_release_sling_continue` |
| `Param1` | **0** | `0.924` |
| `enforce_weapon_tip_with_rope_stretched` | 无 | **有**（绳子约束旗标） |

（`ready_sling` 另外还少了我们的 `keep`。）

⇒ **结论：想换画面，必须连"壳"一起自己做。** 这正是要走 TRF 的理由 ——
TRF 给的是**动画数据**，clip 元数据由我们在 ModKit 里按自己那套填（`ContinueWith` 空 / `Param1 = 0` / 不带绳子旗标）。

**顺带说明：搬不了的是武器侧那 6 条 `_weapon`** —— 它们绑 `sling_skeleton`，
而 1.2.12 既没这副骨架、native 也没 `enforce_weapon_tip_with_rope_*`。
⇒ 搬过去的只有"人在甩"，绳子仍归我们自己的 verlet 解法。

## 八、能不能自定义武器类型？

**不能新增枚举值。** 三个入口全是 `Enum.Parse` 硬解，名字对不上**当场抛异常**：

| XML 属性 | 解析（1.5.x `TaleWorlds.Core.dll`） |
|---|---|
| `weapon_class` / `ammo_class` | `(WeaponClass)Enum.Parse(typeof(WeaponClass), …)`（Core 8793 / 8794） |
| `Type` / `item_type` | `Enum.Parse(typeof(ItemObject.ItemTypeEnum), …)`（Core 5316） |
| `WeaponFlags` 子节点 | `Enum.Parse(typeof(WeaponFlags), …)`（Core 11685） |

native 侧用的是同枚举的数值，managed 改不动。

**但"自定义武器类型"本来就不在 `WeaponClass` 那一层。** 引擎真正留的扩展点：

| 扩展点 | 形制 | 作用 |
|---|---|---|
| `item_usage` | **自由字符串** → `<item_usage_set>` | 动作 / 走跑组 / 待机 —— **投石索的全部行为差异都写在这层**，`Sling` 只是个挂靠的枚举名 |
| `action_types` / `action_sets` | 自由命名 | 新动作类型 + 往 `as_human_warrior` 追加（同名 action_set 会被 C# 层追加合并） |
| `WeaponFlags` | 旗标**组合**（不能造新旗标） | native 行为开关（`HasString` / `UseHandAsThrowBase` …） |
| `item_usage_features` | 自由字符串 | ⚠️ 只被**打造系统**消费（`WeaponDescription.ItemUsageFeatures` vs `CraftingPiece.ItemUsageFeaturesToExclude`），**不是通用行为钩子** |

⇒ 现实做法 = **挑一个行为最接近的已有 `weapon_class`**（我们挑了 Bow / Arrow）+ 自己的
`item_usage` + 自己的动作全家 + 自己的旗标组合。这正是钩索现在的做法。

代价：所有 `switch (WeaponClass)` 落 `default`（伤害模型 / AI 判定 / 音效 /
弹药配对 `GetAmmoClassForWeaponClass`）—— 要靠补丁兜（如 `GrappleAmmoOrderPatch`）。

## 九、没解的（下次要碰再挖）

- `_weapon` 的**配对规则**到底写死在 native 的哪一处 —— 托管层零痕迹，
  只知道"按名字 + 后缀"，**是否只认 `ready/release/reload/ready_continue` 这几个槽位、认不认自定义动画名，未验**。
- `anf_enforce_weapon_tip_with_rope_stretched/relaxed` 的实际作用（看名字是"把武器尖端用绳约束拉住"），
  但**没有找到任何官方动画用它**，也没找到它在 ModKit 里怎么设。
- 投石索骨架的**骨数/命名**：动画侧是 `bone_0..bone_8`（9 根），
  但 `sling_skeleton` 资产本身没解析出来（`tpaccli animbones` 显示 `skel = (?)`）——
  骨架资产与动画可能不在同一个包里，工具跨包解析失败。不影响上面的结论。
