## 2. 为什么必须走「新 race」

骑砍2 的头网格**不由角色决定，由皮肤（skin）决定**，而 skin 是按 **(race × 性别 × 年龄段)** 三选一的。
全游戏只有一个 `race="human"`，所以**任何"给某个角色换头"都绕不开"给他一个独有 race"**。

| 件 | 作用 | 本工程的值 |
|---|---|---|
| `skins.xml` 的 `<race id="X">` | 皮肤矩阵：里面指定 `face_meta_mesh`（头网格）、`face_textures`（脸池贴图）等 | `lwn_nobunaga` |
| `monsters.xml` 的 `<Monster id="X">` | 物理/骨骼/胶囊（id 必须与 race 同名） | `lwn_nobunaga`（human 的整块副本） |
| NPCCharacter 的 `race="X"` | 把角色挂到该 race 上 | **只有 `lord_tk5_195` 有** |

**别人不受影响的原因**：除信长外没有任何 NPCCharacter 带 `race=` 属性 → 全部继续走 Native 的 `race="human"`。

## 5. 查证过的事实（都是实证，下个 session 别再摸一遍）

| 事实 | 证据 |
|---|---|
| **race 机制**：新 race 要在 `skins.xml` 和 `monsters.xml` 里各定义一份同名节点，NPCCharacter 上写 `race="X"` | 社区文档 `Knowledge/bannerlordmodding_lt/modding/races.md`；织丰的 `euro_monsters.xml` 写了 `<Monster id="european">`，其火枪兵带 `race="european"` |
| ⚠️ **织丰的 `euro_skins.xml` 是死数据** | 织丰 `skins.xml` 里 `grep european` = 0 条，且 SubModule 里**没有**注册 `Skins`，`euro_skins.xml` 也没被任何地方引用 → **不能拿它当"添加 race 已验证"的先例**，本工程是第一次真正落地 |
| **`skins.xml` 靠 `project.mbproj` 的 `type="skin"` 行加载**，不是靠 SubModule 的 XmlNode | Native 自己就是 `<file id="soln_skins" name="ModuleData/skins.xml" type="skin"/>`；TifaHead2 / xxFemaleHead 两个能用的换头 mod 也都是这一行 |
| **没有 `id="Skins"` 的 XmlNode** ——全装模块搜遍无人注册 | 所以 skins 走的是 soln 体系（`project.mbproj`），跟 `Monsters`/`NPCCharacters` 那套 XmlNode 体系**不是一回事** |
| **soln 合并是"追加"不是"覆盖"** | 织丰的 `skins.xslt` 第一件事是 `<xsl:template match="race"/>`（把合并结果里所有 race 删光）再靠自己的 `skins.xml` 重新给 —— 说明合并会**留下**别家的 race，不删就重复 |
| **男头规格 = 3 件（脸/眼/嘴），没有睫毛件** | 原版 `head_male_a` 的 mat_map：`.1`=eye_mat、`.2`=mouth_mat；唯一在售的自定义男头织丰 `sho_head_male_japanese` 也是 3 件 |
| **男 skin 的 `deform_keys` 与女头逐位相同** | 蒂法工程 §21.2：62 条 key_time_point 序列完全一致 → 我们的 FBX 给 `KeyTime_1..59` 直接对齐，**不用改 deform_keys** |

### 7.10 🔴 眼睛/嘴的真根因 = `MaterialFlags`（2026-09-14 第二轮实机，**已修好**）

**症状**：眼睛看不到、嘴开花、头顶露皮肤（三个一起）。

**真根因**：子网格上带 `face_base_mesh` / `face_eye_mesh` / `face_mouth_mesh` 这类标记时，引擎会**按原版画布布局重新生成一张脸贴图**盖上去。我们的头用的是战无2 原始 UV（挤在贴图左上 1/8），两边布局对不上 → 眼睛采到旁边的像素、嘴采错、**头发那块被当成脸皮涂成肤色**。

**证据（硬对照）**：两个实机通过的自定义头 —— 蒂法（4 件）、萨菲罗斯（3 件）—— 的 `MaterialFlags` **全是空的**；只有信长这三个格有标记。标记是 `install_pack.py` 的 `skinfix --fullmat` 逐格补的（`FaceFlagFor()`，按材质名推断），**蒂法/萨菲罗斯那会儿没跑这一步**，反而躲过了。

**修法（一条命令，不用重编译 tpac）**：

```
tpaccli metaparts --packdir <只含 pack0.tpac 的目录> --filter head_nobunaga_a --out <outdir> --clearflags
```

`--clearflags` 是 2026-09-14 新加到 `MetaParts.cs` 的（照它原有的"改元数据 + `RawMeta=null` + `pkg.Save`"骨架写）。成品包：`Debug/offline/nobu_head_probe/clearflags/pack0.tpac`。

**两个被推翻的假设（别再走）**：

| 假设 | 为什么错 |
|---|---|
| **部件顺序**（"第 2 件=嘴、第 3 件=眼"，要排成 脸→嘴→眼） | 重排成 脸→嘴→眼 后**三个问题一个没好**。而且两个实机通过的头顺序**并不相同**：蒂法 = 脸→嘴→眼→睫、萨菲罗斯 = 脸→眼→嘴 → **顺序不是决定因素**（§16 那条"按顺序分配"的结论只解释得了蒂法当年 6 件超范围的情况） |
| **改 `mouth_textures` 名字** | 改名不换位置。而且**三件 diffuse 本来就是同一张图集**（见下），贴图与 UV 各自都对，改名字无从下手 |

**本轮实测事实（都验过，别再重查）**：

- 三张 diffuse（`head_nobunaga_a_d` / `_eye_d` / `_mouth_d`）**逐像素完全相同**（md5 一致）—— **正常**：战无2 原模型就是"一件模型一张图集"，脸/眼/嘴各取各的区域
- UV 各自指向都对：眼 → 图集里的眼球、嘴 → 嘴部、脸壳 → 脸与头发
- `_n`（法线）**纯色 (127,127,0) = 完全平的**、`_s`（高光）**纯色** → 脸没有凹凸/高光细节，是下一步的观感问题（不影响本轮的三个 bug）
- `face_texture` 的 `lod_material` 我们写的是 **`head_male_a.lod`（原版材质）**，蒂法写的是**自己的名字** —— 已改（见 §7.11）

### 7.11 头顶露皮肤（2026-09-14 **已解决** → 解法见 §7.12）

清掉 `MaterialFlags` 后**眼睛和嘴都好了、头顶照旧** → 说明头顶是**另一条独立原因**，别再往"贴图合成"上想。

本轮排除过程（供以后再遇同类症状时省路）：

| 候选 | 排除依据 |
|---|---|
| 脸贴图合成涂色 | 清 flags 后引擎已不生成贴图，头顶没变 → 不是它 |
| 头顶几何有洞 | 从上方做 z-buffer + 只保留朝上的面：**覆盖完整、没有洞**；且**所有朝上的面采样颜色都是黑的**（头发） |
| 背面剔除 | 头顶那一圈（z 1.84~1.88）确有 20 个面法线朝下，但更低的朝上面把它们接住了 → 从上方看仍有覆盖 |
| `lod_material` | 已从 `head_male_a.lod`（原版）改成自己的名字，头顶照旧 → 不是它（但改了是对的，对齐蒂法写法） |

**结论**：真凶是**引擎挂的原版发型**，见 §7.12。

### 7.12 🔴 头顶露皮肤的真凶 = 引擎挂的原版发型（2026-09-14 实机确认，**已修好**）

**真凶**：角色的 body properties 里带**发型索引**，引擎按它从皮肤 `hair_meshes` 里取一款**原版发型网格**挂到头上。

为什么信长必然被分到发型：他的脸照 `BodyProperty.fighter_empire`（原版模板）生成，模板的 `hair_tags` = empire/sturgia/battania/khuzait；而 skin 的 `hair_meshes` 里 **Bald 那条本身就同时挂着全部文化 tag**（原版就这么写的）→ 他一定落在"有发型可用"的范围里。

我们的头**自带头发**，原版发型（照原版头 z→1.811 做的，最高只到 1.841）和它只会打架 → 从上前方看露出一片浅色（**图 2 那块"秃顶"**）。正面看不出来是因为被我们自己的头发挡住了。

**修法（无风险版）**：把 `hair_meshes` 里每条发型的 **`name` / `cover_type*` 属性摘掉**，保留条目与 `style_tags`：

```xml
<!-- 改前：有网格名 → 引擎会渲染 -->
<hair_mesh name="hair_male_g_a" cover_type1="..." cover_type2="..." cover_type4="...">
<!-- 改后：条目还在、位置不变，但没有网格可渲染 = 光头 -->
<hair_mesh>
    <style_tags><style_tag name="Ponytail" /></style_tags>
</hair_mesh>
```

- **条目数一条不少（29 条）** → 存档里的发型索引**不会越界**
- 这个写法**原版就有先例**：`Bald` 那条本来就是"无 name + 只有 style_tags"
- 生成器开关：`Scripts/gen_taikou_nobunaga_head.py --no-hair`（含断言：摘完不能还剩带 name 的、条目数不能少）

**⚠️ 走过的弯路（别重犯）**：

| 弯路 | 为什么错 |
|---|---|
| **删掉发型条目、只留 Bald** | 列表从 29 条变 1 条，老档里的发型索引（比如 5）取不到 → 崩。这引擎缺定义从不兜底（怪物后缀族是同一个教训）→ **改条数 = 危险，改内容 = 安全** |
| **改 `lod_material`** | 改了（原版写 `head_male_a.lod`，改成自己的名字），头顶照旧 → 不是它。但改了是对的（对齐蒂法/萨菲罗斯的写法） |
| **怀疑几何有洞 / 面朝向反** | 从上方 z-buffer + 只留朝上的面：覆盖完整、没洞；所有朝上面采样颜色**都是黑的**（头发）→ 资产本身没问题 |

**一条通用经验**：自定义头进游戏后**任何"多了/少了一块东西"的症状，先想"引擎是不是往上挂/盖了什么"**——发型、面部合成层（§7.10）都是这一类。自定义头自带头发的，务必把 skin 的发型表摘干净。

### 7.13 角色默认脸的架构（2026-09-14 用户裁定）

**三层**（通用 → 专属）：

| 层 | 谁 | 头 | 实现位置 |
|---|---|---|---|
| **默认男脸** | 全部男性（玩家 + NPC） | **萨菲罗斯** | `Taikou\ModuleData\skins.xslt`（**主配置**）|
| **默认女脸** | 全部女性 | **蒂法** | 同上（同一份文件，男女一体）|
| **特殊人物** | 织田信长等 | **自己的头** | **专属 race**（如 `lwn_nobunaga`）+ NPCCharacter 带 `race=` |

**为什么默认脸走 xslt、特殊人物走专属 race**：
- 默认脸要影响**一整类**（所有男/女）→ 直接改 skin 的属性最省事，一行覆盖一片
- 特殊人物要**只影响一个人** → 骑砍2 没有"按角色换头"的口子，只能给他开专属 race（§2）

**xslt 覆盖 Native skin 的手法（可复用）**：
- 引擎**按文件名自动读** `ModuleData/skins.xslt`，**不需要**在 `SubModule.xml` 注册（TifaHead2 的 `<Xmls>` 就是空的，照样生效）；**删掉该文件 = 完全还原**，无副作用
- 改头网格**必须同时改 `face_textures`**，且**条数 / tag 分布照抄原版**（条数变了引擎按索引取会越界 —— 蒂法工程 §11.2 根因 C）
- `mouth_textures` / `eyebrow_meshes` **照原版不动**；**`deform_keys` 男女都要换成 xxFemale 那套**（幅度必须与位移场同源 —— 见下面第⑥条）

**🔴 坑一：配置必须放在「一定会被加载」的模块里（2026-09-14 实机踩到）**

游戏的模块加载列表由**启动参数**决定：

```
/singleplayer _MODULES_*Bannerlord.Harmony*...*StoryMode*LivingWorldNpcs*Taikou*_MODULES_
```

**启动器里的 `IsSelected` 会被这个参数覆盖**。实测：启动器里 `TifaHead2` 勾着（`IsSelected=true`），但 `_MODULES_` 列表里**没有它** → 它那份 `skins.xslt` **永远不加载** → 女脸改了却"没看到生效"，查了半天。

**所以默认脸的配置放在 `Taikou\ModuleData\skins.xslt`** —— Taikou 一定加载，而且它是**双端 junction 同源**（PowerShell 验过 `LinkType: Junction` → 指向 Steam 侧）→ **改一处，1.2.12 和 1.5.x 两端都生效**。

| 文件 | 状态 |
|---|---|
| **`Taikou\ModuleData\skins.xslt`** | 🔴 **主配置**（男女 + `deform_keys` 全量）→ 一定加载、双端同源 |
| `TifaHead2\ModuleData\skins.xslt` | **不加载**（模块不在 `_MODULES_` 列表）→ 仅作历史留存；⚠️ 它**不是 junction**，是两份独立拷贝，改一边另一边不动 |

⚠️ 若哪天改用启动器启动、或把 TifaHead2 加进 `_MODULES_` → 两模块同时加载会有**同名资产冲突**（Taikou 的 pack0 是后处理版，TifaHead2 那份还是白编译），**先统一再启**。

**配套（资产制作侧）**：FBX / 皮肤表的规格见 [蒂法换头工程.md](蒂法换头工程.md) §13.7 ——

- **第⑤条「材质名必须与贴图名对应」**：`head_xxx_a`（材质）↔ `head_xxx_a_d`（贴图）↔ 皮肤表里的名字基，**三者同源**，
  对不上就挂不上贴图（实机表现是"用了别人的贴图/纯色/发黑"，而编辑器里常常看不出来）。
- **第⑥条「`deform_keys` 的 `key_min/key_max` 必须与位移场来源同源，男女都要换」**：
  位移场是从 xxFemale 移植来的 → 幅度就得用 xxFemale 那套。**原版男女两套 63 条里 56 条不同** ——
  只给女脸换、不给男脸换 → **男脸被拉坏 / 动画不对**（2026-09-14 接上默认男脸后实机发现，已修）。

**🔴 关键坑：xslt 的匹配范围必须锚定到 `race[@id='human']`**（2026-09-14 实测踩到）

TifaHead2 原来的写法是 `match="skin[@name='man']"` —— 它匹配**所有 race** 里叫 `man` 的皮肤，
于是把信长专属 race（`lwn_nobunaga`）的皮肤也一起改成了萨菲罗斯 → **"特殊人物用自己的脸"当场失效**。
已收窄为 `match="race[@id='human']/skin[@name='man']"`（6 处模板全改：男女的 `face_meta_mesh` / `face_textures` + 女的 `deform_keys` / `constraints`）。

**规律**：`skin[@name=...]` 这种"按名字匹配"的写法，在**全模块合并后是跨 race 的**。
只要还要加专属 race（第二步批量做 28 个武将时一定会加），任何"做默认脸"的覆盖都必须先锚定 race，
否则每加一个专属 race 都会被默认脸覆盖掉。

**已验证的组合**（用 `lxml` 把 Native + Taikou 的 skins 合成"引擎视角的合并文档"再跑 xslt，2026-09-14 **用户实机验证通过**）：

| race | 性别 | 结果 |
|---|---|---|
| `human` | 男 | `head_sephiroth_a` |
| `human` | 女 | `head_tifa_a` |
| `lwn_nobunaga`（信长） | 男 | `head_nobunaga_a`（**专属 race 不被默认脸影响**）|

> 这份回归可以用同样的办法复跑：读 Native 的 `skins.xml` + 追加 Taikou 的 race 节点 → 依次套各模块的 `skins.xslt` → 打印结果。加新专属 race 后建议跑一遍。

**已知未收敛**：蒂法那头还有"领口几何/颜色"的问题没过（见 [蒂法换头工程.md](蒂法换头工程.md) §22.8 的 TODO #1 领口重建）。

### 7.14 🔴 自定义头的后处理链：`install_pack.py` 是终点，**白编译 ≠ 可用**（2026-09-14 补）

**这次的教训**：蒂法和萨菲罗斯两个头**从来没跑过后处理**，一直是"白编译"状态就被拿去用了。
表面能跑（蒂法早期实机确实过了），但**男脸接上默认脸后萨菲罗斯的脸形崩了**（动画不对）—— 根因就在这。

**正确的完整链**（源头 = ModKit 工程 `Modules\artest3\TifaHead2`，**不是**游戏模块目录）：

```
Modules\artest3\TifaHead2\AssetPackages\pack0.tpac     ← 人在 ModKit 里 publish 的产物
   │
   │  python tools/face-pipeline/scripts/install_pack.py \
   │      --module "Modules\artest3\TifaHead2" --filter head_ --clients "Modules\Taikou"
   ▼
   ① morphfix              补 morph 帧 60 → **101** + 同步 VertexKeyCount
   ② skinfix --fullmat     四角色材质配方 + MaterialFlags
   ③ 关卡 2（check_head_space）  编译产物落点检查，不过不装机
   ④ 装机 + md5 校验
   ▼
Modules\Taikou\AssetPackages\pack0.tpac     （35 MB → **52 MB**，多出来的就是补的帧）
```

**🔴 但三个头的 flags 要分开处理**（`install_pack` 会把 flags 全设上）：

| 头 | UV 布局 | flags | 处理 |
|---|---|---|---|
| 蒂法 / 萨菲罗斯 | 铺满 [0,1]²、**对齐原版画布真值表** | ✅ **要有** | install_pack 设上即可 |
| **织田信长** | **战无2 原始布局**（挤在贴图左上 1/8） | ❌ **必须空** | 跑完 install_pack 后**再单独清掉** |

清信长的 flags：
```
tpaccli metaparts --packdir <只含 pack0.tpac 的目录> --filter head_nobunaga_a --out <out> --clearflags
```
（**为什么信长特殊**：带 flags 时引擎会按**原版画布布局**重新生成脸贴图，而他的 UV 是源模型自己的布局 → 两边错位 → 眼睛/嘴/头发全糊。见 §7.10）

**判定「有没有跑过后处理」的两条硬指标**（各一条命令）：

- `tpaccli morphinfo`：`VertexKeyCount` 应为 **101**（白编译 = 60）
- `tpaccli metaparts`：`flags` 应带 `face_base_mesh` 等（白编译 = 空）

⚠️ **改完还要确认改对了客户端**：`Taikou` 是 junction 同源（改一处两端都对）；
**`TifaHead2` 不是** —— 它是两份独立拷贝，改了 Steam 侧 1.2.12 侧不动（这次就在这里绕了圈）。

## 25.1 判据速查（先用哪一条）

|---|---|---|

## 25.2 🔴 三条铁律（本轮血泪）

1. **凡是连在主网格上的几何，一律只改 UV，不删顶点。**
   颏带的"下巴条"看着是配件，实际**就是下颌的皮面**（美术把带子纹理画在下颌上）。删 ⇒ 镂空。
   更阴的是**耳侧那几块**：它们看着像"飘在表面外的独立碎片"，但**也是脸颊皮面的一部分** ——
   删了脸上会开洞、露出头壳内表面（那部分 UV 落在图集占位区 = 一块棋盘格）。
   **判据：先用 `_jit_inside.py` 把它单独渲出来，看它离开之后脸还完整不完整。**

2. **整片一个 UV = 一块死板色块。** 要**逐 loop 取最近**（肤色）顶点的 UV，纹理才会跟着邻居过渡。
   而且候选点要**限制在近邻半径内**（≈3 源单位）—— 取"全脸最近"会跨 UV 缝挑到后脑/头顶，
   那些地方的 UV 是图集占位区（棋盘格）。

3. **改判据之前先对账顶点数**：头删掉的 = 兜加上的（本轮 32/51/40/26/22 逐个相等）。
   对不上就是没搬对，或者两边走的判据不是同一条。

## 25.3 脚本接线（照这张图找代码）

```
parts_table.py  ──►  build_heads.py  ──►  build_head.py        （头）
      │                                      ▲
      └────────────►  build_helmets.py ──► build_armor.py      （兜：颏带并回来）
```

| 环节 | 文件 | 本轮新增 |
|---|---|---|
| 数据 | `tools/sw2-pipeline/parts_table.py` | 字段 `hard`（头发走硬判据）/ `seal`（封底）/ `strap`（颏带种子点）/ `strap_bone`（只能改 UV 的那部分）|
| 头 | `tools/face-pipeline/scripts/build_head.py` | 1.3c `--strap-seed` 摘独立碎片；1.3d `--strap-bone` 只改 UV；1.4b 硬判据白名单**只认头骨**；1.4c 头发并进脸壳（在 1.3/1.4b **之后**）；1.6 `--seal-bottom` 封发块底口 |
| 批头 | `tools/sw2-pipeline/build_heads.py` | 🔴 挑件串的唯一来源 = `build_head_args()`（原来另有一份 `pick_of()` 重复拷贝，**改一份不生效**，已删）|
| 兜 | `tools/armor-pipeline/scripts/build_armor.py` | `--strap-from <脸壳子网格> --strap-seed "…"`：把脸壳件里的颏带碎片并进兜 |
| 批兜 | `tools/sw2-pipeline/build_helmets.py` | 自动读 parts_table 的 `strap` 传参，不用手传 |

**已知未决**：兜的贴图步骤（`build_textures.py`）会报 `甲的 UV 超出了源件范围` ——
因为颏带的 UV 在**脸壳**的图集区、不在兜件的范围里。图仍能出（UV 是通的），
但**要人工确认带子在兜上的颜色**。若不对 → 把 UV 范围改成「兜件 ∪ 脸壳件」。
