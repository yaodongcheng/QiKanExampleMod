# BannerlordTalk v1.0.3

独立的大地图人物闲聊 MOD。核心不依赖 AnimusForge；临阵统帅（LC）战后档案只是可选的公开事实来源。

## 选择正确的正式包

| 正式包 | 精确目标 | MCM | 可选 LC 边界 |
| --- | --- | --- | --- |
| `BannerlordTalk-v1.0.3-BL1.4.8` | Bannerlord `1.4.8` | `5.12.2` | `1.6.5` |
| `BannerlordTalk-v1.0.3-BL1.3.15` | Bannerlord `1.3.15` | `5.11.3` | `1.6.4` |

两个包的 DLL 与 `SubModule.xml` 不同，不能混装，也不能把其中一个改名后当成“全 1.3.x / 全 1.4.x 通用包”。压缩包内的 `BannerlordTalk` 文件夹才是要复制到游戏 `Modules` 的模块；`KnowledgeLibraries` 中三份 TXT 是游戏外编辑、游戏内整库粘贴导入的可选常识库，不会自动安装或混合。

两个包的根目录还会附带 `通用主聊天提示词.txt`、`安装与使用教程.txt` 和 `模组功能说明.txt`。通用提示词不含指定角色设定，可在管理面板的主聊天提示词页按纯文本导入；教程同时说明版本选择、常识库三选一、API 与可选 Fish TTS 配置。正式包不会覆盖玩家现有的 MCM、API、提示词、Fish 音色或存档配置。

1.3.15 包所对应的 LC 1.6.4 尚无 1.6.5 才加入的战后 `BattleArchiveFeed`；不安装 LC 或使用 LC 1.6.4 都不影响闲聊主体，但不会得到 LC 战后档案注入。不要把 LC 1.6.5 的 1.4.x DLL 混入 1.3.15 环境。

## v1.0.3 重点

- 公共常识主页不再把整库正文或正文抽样装入游戏文本控件，只显示规则数、字符数和全文复制说明。常识页使用固定尺寸的只读摘要，正文编辑控件在该页隐藏，避免停留页面时持续处理长文本。
- 管理器响应式布局只有在计算后的尺寸真正变化时才通知 Gauntlet；分辨率和 UI 缩放未变时不再每帧重复触发布局刷新。
- 导入确认仍提供有界的统计、诊断和短预览；解析、确认替换、战役保存及“复制当前整库”继续使用完整文本，不因界面省略正文而截断。

## v1.0.2 重点

- 修复完整常识库粘贴预览和点击“替换整库”后可能卡住游戏界面的错误。管理器现在只把最多约 6000 字的有界抽样交给 Gauntlet 排版，不再把 6–9 万字整库全文绑定到 RichTextWidget 或多行编辑控件。
- 截断只影响游戏内显示：解析、校验、原子替换、战役存储和“复制当前整库”仍使用完整文本。提示词导入预览也加上相同的最终显示上限，避免同类长文本卡顿。
- 新增长文本回归，覆盖超过 9 万字的常识、确认路径仍持有完整剪贴板内容，以及 UTF-16 代理对边界不会被截坏。

## v1.0.1 重点

- 新增 Google 官方 OpenAI 兼容端点的 `gemini-3.7-flash` 精确请求配置：仅在端点为 `generativelanguage.googleapis.com` 且模型名精确为 `gemini-3.7-flash` 时，不发送温度与多候选数，避免这两个字段导致请求被拒绝。
- MCM 主模型页新增 Gemini 3.7 “低 / 中 / 高”思考等级，对应 Google 兼容接口的 `reasoning_effort`；默认低档面向高频实时闲聊。
- Gemini 3.7 适配是严格限定的供应商分支；Gemini 3.1 Pro、DeepSeek 与其他 OpenAI-compatible 模型保留既有请求字段与行为。

## v1.0.0 重点

- 在 v0.14 城镇识别、和平聚落放行和窗口显隐实测基础上，进一步把聚落变化作为会话上下文边界，避免已经进入城镇后仍被上一段“赶路”话题带偏。
- 同一条刚生成的台词不再同时以当前话题、普通记忆和近期公开台词三份重复注入；可见心声只以极少量、仅本人可见的措辞参考参与防重复，不会被当成私密思绪或公开记忆。
- 最终不可覆盖约束明确：实时地点高于旧旅途记忆；旧台词只能作为过去发生过的内容；没有实时存档事实或本轮近期已验证战役事件依据时不得编造当前追兵、伏击或迫近威胁；语言优先采用世界内自然表达。
- 正式交付分为精确的 Bannerlord 1.4.8 与 1.3.15 两包，并各附卡拉迪亚、战锤旧世界、权游三套可复制粘贴的完整常识库。

## v0.14 重点

- 修复城镇、城堡和村庄菜单中的原生 `PlayerEncounter` 被误判成战斗，导致自动闲聊长期阻断的问题。只有已解析到聚落且菜单使用 Bannerlord 三种原生聚落 overlay 时才按和平聚落放行；真实战斗、竞技场、MapEvent、事件锁以及未验证的 Encounter/None 菜单仍然安全阻断。
- 当前聚落解析新增同一战役内的一项内存缓存，并由主队进入/离开聚落事件维护。缓存只允许在原生聚落 overlay 下兜底，不写入存档，也不会用菜单文字、距离或名称猜测地点。
- 请求接受时固定聚落身份；生成期间若地点身份变化，立即以 `location_context_changed` 取消并短重试，不提交迟到台词、不推进发言人，也不累计网络失败。
- Probe 默认 metadata-only 现可记录有限地点元数据和战斗分类结果：聚落 ID、来源、菜单 ID、overlay、聚落菜单验证状态、缓存兜底状态、战斗门状态/原因以及是否存在有效战斗。它不因此记录提示词、人物私密内容、Endpoint、密钥或认证头。

## v0.13 重点

- 地点判定改为单一、一致的聚落解析路径：优先使用 Bannerlord 当前聚落上下文，覆盖城镇/城堡菜单只有 `PlayerEncounter.EncounterSettlement` 、主队直接驻留聚落、被俘玩家所在聚落以及真正旅途。提示词地点、常识检索、事件聚落标识、生成门和进城自动隐藏现在共用同一结果，不再把黑城堡菜单误写成「大地图旅途中」。
- 本版不改心声与私密思绪的选择、显示、注入或生成逻辑；模型仍可合法返回纯对白。

## v0.12 重点

- 闲聊窗标题栏新增“收起/展开”。收起后只保留 68 逻辑像素标题条，正文、滚动条和鼠标命中区域会一起缩小，不是单纯变透明。
- 新增窗口显隐快捷键，默认 `Ctrl+H`；它只改变本次游戏会话的窗口显示，不关闭自动生成、记忆或 TTS。进入城镇菜单默认整窗自动隐藏：不渲染、不命中、不捕获输入；离开城镇后恢复进入前的会话显隐及手动收起/展开状态。自 v0.14 起，城镇自动隐藏期间可按 `Ctrl+H` 临时完整显示，再按一次重新隐藏；离开城镇仍恢复进入前的会话状态。
- 透明度仍只控制外观，不能让鼠标穿透。需要操作被遮挡的原生菜单时，应收起窗口或使用显隐快捷键。
- 主模型现在先选择内部 `presentation`：日常纯对白、对白加动作、对白加心声或罕见的完整演出。合法选择具有权威性，禁止的多余字段会被丢弃；若模型漏写或写错选择，则安全降级为纯正文，不会因此触发长时间失败退避。它不再把动作、正文、心声当成每轮固定三件套，也不会增加第二次主请求。
- 最近公开历史只回送正文，不再把上一轮动作或可见心声作为固定格式范例。私密思绪仍只进入本人记忆，与可见心声完全分离。
- 瞬时网络错误采用短重试：以当前生成间隔为基准指数退避，最高不超过失败退避上限；HTTP 400 与解析错误等非瞬时失败仍走完整失败退避。发言人游标和剩余轮数只在台词成功提交时推进，传输失败、取消和战斗中止不会跳过角色。

## v0.10 剪贴板与整库修复

- 修复中文多行剪贴板导入：提示词和常识改走 Windows `CF_UNICODETEXT`，逐字保留 LF / CRLF 和中文，不再依赖会压平换行或产生乱码的游戏剪贴板读取。
- 如果 Windows 剪贴板暂时被占用，TaleWorlds 回退只允许可逐字回读的单行 ASCII；中文或多行内容会直接报错并要求重试，不会冒险保存损坏文本。
- 提示词和常识发现 Unicode 替换字符 U+FFFD 时硬拒绝，不允许把已经损坏的文本保存进配置或战役存档。
- 五段式常识如果在同一物理行发现多个规则头，会拒绝整次替换并提示补回真实换行；失败预览不会改变旧常识库。

- 只保留自动闲聊。系统按当前合格角色数自动选择单人、两人或多人会话，每次请求只生成当前一名发言者的一次自然发言。
- 默认正文上限 160 字，通常引导为 60–160 字、1–3 个相互连贯的短句；`action` 和可见 `inner_voice` 都是可选字段，不再用三字段完整样例强迫模型机械输出。
- 私密“思绪”与可见心声完全分开。每名角色累计达到可配置的成功台词数后（默认 4 句）才异步结算一次思绪；思绪只进入本人私密记忆，之后按规则召回给本人主模型，不显示、不播报，也不照搬成心声。
- 主模型的日常事实改为自然描述，不再直接注入“士气 48”“技能 210”“生命 128/151”一类游戏面板数值；人格智能生成也只允许人格、说话风格、长期目标、价值与禁忌五项自然语言字段。
- 闲聊窗按分辨率和 UI 缩放自适应，固定在左上角或右上角；标题栏 `－/＋` 可缩放。已移除实机不可靠的拖动定位。
- 公共常识只保留一份战役内整库。游戏内不再逐条编辑：从 Word、记事本或聊天中复制完整多行常识库，读取剪贴板、预览条数和错误后一次性整体替换；失败或取消不会改旧库。
- 提示词粘贴分为“纯文本”和“完整预设 JSON”两条明确路径，按钮始终读取系统剪贴板，经预览确认后才保存，不会再误读当前短编辑框。
- 新增可选 Fish Audio TTS。正文、动作、可见心声可分别开关；隐藏思绪永不播报。队列异步、有限容量，语音失败不影响聊天、记忆或调度。

## 聊天与模型

- 独立 OpenAI-compatible Chat Completions：API 地址、API Key、模型、温度、最大 Token、超时和按服务兼容的思考开关。
- 公网只允许 HTTPS；回环地址可用 HTTP；拒绝 URL 凭据、查询参数、片段和重定向。
- 战斗、任务场景和战后稳定期有硬门；进入战斗会取消聊天、思绪、总结与人格生成请求，迟到结果不会写入。
- 玩家默认可以作为 AI 发言者；可在 MCM 关闭。AI 台词只作展示和记忆，不会执行交易、任务、命令或任何游戏状态操作。

## 人格、记忆与思绪

- 玩家和当前主队英雄同伴各有独立人格卡，可手工编辑，也可调用主聊天模型生成草稿；草稿必须由玩家采用并保存，不会自动覆盖。
- 个人记忆分为 Recent、Situational、EventLog、Archive；私密思绪分为 Mid、Long、Belief。
- 成功提交的公开台词、手工记录、已验证战后事实和成功生成的思绪才会入库；失败、取消、迟到输出不入库。
- 记忆和思绪有独立注入预算；思绪只对本人可见。主动旧记忆最多一条，且只有台词提交后才更新召回状态。
- 记忆总结可关闭、沿用聊天模型，或使用独立便宜模型；总结失败不删除原始记忆。

## 公共常识格式

每个物理行是一条：

`[标签|重要性|Any/All|可提取|可匹配]正文`

例如：

`[临冬城,史塔克|0.80|Any|False|True]临冬城是史塔克家族在北境的重要城堡。`

标签支持中英文逗号、顿号和分号。导入会先完整解析；只有无错误并由玩家确认后，才原子替换当前战役的公共常识。导出会把完整多行常识库复制到剪贴板。本版没有知识包、主包、补充包或向量设置。

## Fish TTS

- 通用设置：Endpoint、API Key、Fish 合成模型、Temperature、Top-P、语速、音量和请求起点间隔。
- 首次应用相关默认设置时，如果本机存在 LC 的 Fish 配置，会安全复制这些通用参数；不会打印或写入日志。十个角色音色槽不会从 LC 的阵营音色自动复制。
- 十个角色槽按当前存档的 `Hero.StringId` 精确绑定，界面同时显示当前本地化名字。名字只供识别，不参与匹配；同名角色不会串音。
- 每槽填写 Fish 音色 `reference_id`。它与全局 Fish 合成模型不是同一个字段。
- 默认只播正文；动作和可见心声可分别开启。没有精确角色音色映射时安全跳过，不按名字猜测。

API Key 会明文保存在本机 MCM JSON；不会进入战役存档、Probe、常识库、提示词导出或发布包。请像保管其他本机 MOD 配置一样保护该文件。

## 管理面板

MCM 快捷键（默认 Ctrl+J）或闲聊窗“管理”按钮打开：

- 人格卡：玩家与同伴的人格草稿、话痨度和自动发起设置。
- 资料库 / 角色记忆：查看、新增、编辑、删除、置顶四层个人记忆。
- 思绪：查看、新增、编辑、删除、置顶 Mid / Long / Belief 私密思绪。
- 资料库 / 公共常识：查看整库统计、读取剪贴板、确认整体替换、复制完整整库；主页不加载正文。
- 提示词：主聊天、独立思绪、记忆总结模板的纯文本或完整 JSON 剪贴板导入、预览、确认和恢复默认。

## Probe 与证据边界

`BannerlordTalkAuditProbe` 是可选诊断 MOD。默认只记录阶段、模型、状态、耗时、Token、召回计数和原因码；只有 Probe 自己开启正文审计时才记录 system/user、原始响应和最终解析内容。任何模式都不记录密钥或 Authorization。

编译、离线验证和安装只能证明文件与静态契约；真实 MCM、Gauntlet、剪贴板、Fish 播放、模型质量、战斗切换、存读档和长档稳定性仍需进游戏测试。
